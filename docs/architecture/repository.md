# 仓库与发布架构

## 分层

Lawyeah 使用一个公开源码仓库管理 22 个法律业务领域包。领域包是安装、版本和评测单元；领域内部的流程、场景知识和组合方案不作为跨领域依赖发布。

```text
catalog → 领域与渠道目录
packs → 自包含领域包
schemas → 可执行契约
templates → 研发脚手架
tooling/tests → 源码质量与发布边界
static release archive → 用户实际安装内容
```

私有研究、原始检索结果和内部证据链保存在公开仓库之外。公开 Skill 只包含已经完成蒸馏、能够直接指导任务的方法与资源。

## 领域包运行结构

每个领域包只注册一个顶层 `SKILL.md`。顶层文件完成用户身份、代理立场、业务阶段、任务目标和程序状态识别，并直接链接当前任务所需的工作流、场景知识、组合方案及质量标准。

引用文件不得要求模型经过多层索引才能找到任务正文。详细知识按需加载，模板只在生成对应成果时读取，确定性脚本只在任务确有需要时执行。

## MCP 边界

Skill 声明抽象能力和 `required`、`recommended`、`optional` 依赖级别，不保存服务端点、用户 ID、密钥或令牌。授权与凭证保存由 AI 宿主和 Lawyeah 授权服务负责。

MCP 不可用时，Skill 继续完成不依赖外部依据的事实整理和工作框架。受影响的判断节点不得声称已经完成法规、案例或专业知识验证。

## 安装与更新

构建发生在 Lawyeah 的 CI 或发布环境。不同平台接收静态目录或静态插件包，客户电脑不安装更新器、守护进程或后台程序。

更新通过重新安装完成，同名官方领域目录整体替换，不进行逐文件合并。用户自定义内容不应写入官方包目录。

## 版本

- 领域包使用独立语义化版本；
- 目录使用 `YYYY.MM` 版本；
- MCP 能力契约独立版本化；
- 组合包记录所选择的领域范围，不复制专业内容。

## 发布边界

`release-manifest.json` 是用户安装包的白名单。每个包只允许包含顶层入口、Pack 清单、UI 元数据、引用资料、确定性脚本和输出资源。仓库测试、构建工具、模板、CI、实施计划及任何凭证不进入用户安装包。
