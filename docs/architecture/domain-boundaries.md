# 法律业务领域一级边界

本文说明 Lawyeah **22 个法律业务领域**的一级归属规则，不是 GitHub 上的安装目录清单。

公开仓库的安装单位是 **32 个中文包**：21 个办案包在 [`领域/`](../../领域/)，11 个合同包在 [`合同/`](../../合同/)。下表中的「合同审查与起草」在 GitHub 上按合同类型拆成 11 个独立包；其余 21 个领域各对应一个办案包。机器可读的历史领域目录仍在 [`catalog/domains.json`](../../catalog/domains.json)，律师请以中文目录为准。本文不替代各包内的入口技能。

## 归属原则

1. 按用户主要目标和最终专业成果确定领域，不按出现的法律名称、案由或关键词归类。
2. 一个原子 Skill 只有一个主要领域。相似 Skill 可以在不同领域独立发展，但不共享运行时方法、知识文件、模板或版本。
3. 跨领域任务可以同时使用多个已安装 Skill，但必须识别主要成果归属，不预设固定组合方案。
4. 专项行业规则足以改变事实分析、证据结构、程序或成果标准时，优先归专项领域。
5. 全库关系只用于说明 `related-to` 或 `excludes` 边界，不构成固定前后顺序。

## 跨领域处理

当一个用户任务同时涉及多个领域时：

1. 先识别用户要求的主要专业成果；
2. 由拥有该成果的领域承担主要归属；
3. 其他领域只处理其独立专业成果；
4. 不复制同一原子 Skill，也不建立固定调用链；
5. 某个领域包未安装时，不声称已经完成依赖该专业领域的判断。

一级边界只解决归属。具体原子技能、触发和停止条件以各中文包内入口技能和原子技能为准。
