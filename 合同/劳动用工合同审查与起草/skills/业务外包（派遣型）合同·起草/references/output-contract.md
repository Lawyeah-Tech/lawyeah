# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的单价、业务量、保额；把已失效《合同法》及其解释或 2007 年劳动合同法第五十七条五十万旧文写入结论；输出劳动仲裁请求、工伤索赔策略或胜率；把本约改成派遣协议、个人承揽或平台协议正文；把三性、10%、派遣许可证写成**本类型**放行条件；把面试权、人头费、越级指挥写成可放行惯例。

## 1. 触发、单方立场与成果状态

立场（发包方或承包方）、授权、签署状态、主要目标。负触发写路由，不启动本类型起草。写明中文成果名称是「业务外包（派遣型）合同·起草」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2007 年第五十七条五十万旧文时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `劳动关系类合同`，子级 `业务外包（派遣型）合同`。定性理由、易混切开结果（尤其与 `劳务派遣协议·审查` 劳务派遣、`承揽合同（个人劳务）·审查` 个人承揽、`平台用工相关协议·审查` 平台用工的切开）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。假外包写明留本任务并点名，不转成 `劳务派遣协议·审查` 实体审查，除非用户改口要派遣文本。

## 4. 主体、授权、资质与文本版本

主体表：发包方签约名、承包方签约名（须为组织）、付款名、发票名、现场管理人员、授权签字人。版本表：正文、SLA/考核标准、人员名单及社保证明（仅备案）、安全生产协议、业务指令单样本、聊天确认；冲突并列。口头“我们按外包算”不得写成已满足管理权隔离。特许业务许可未见则该签署能力字段停止。

## 5. 管理权、标的独立性与结算闭环

用工指挥权归属；现场管理人员；标的是否可独立核算；SLA/KPI；计费是成果/业务量还是人头；发票品名；进场与验收。缺口标 `G#`。不输出工伤待遇或连带金额终值。

## 6. 假外包、强制规范与责任隔离

面试/考勤/奖惩/调岗/加班/请假；人头费；无现场管理人员；无证特许业务；把无证派遣改成外包；本约争议写成劳动仲裁；“发包方不承担任何劳动法义务”写成已免责；真外包误用第一千一百九十一条第二款切断发包方一切责任。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和删除句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得输出派遣三性/10% 放行句；不得把本约改写成派遣、个人承揽或平台条款。

## 9. 谈判与签署提醒

谈判顺序：先红线（假外包拒改、人头费拒改、无证特许、无证派遣改外包、争议条款走劳动仲裁），再必须改（管理权沉默、无现场管理人员、无 SLA、发票品名、工伤与雇主责任险、安全生产协议），最后可优化。签署提醒：SLA、人员名单及社保证明（仅备案）、安全生产管理协议、现场管理人员任命书作为附件；双方盖公章。不指导倒签、补假考勤隔离或伪造指令单痕迹。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本技能交付可编辑草稿、未决项、自审风险表和自审后修改句。草稿必须覆盖本类型起草必写、附件必附与禁止出现。待签评改转 `业务外包（派遣型）合同·审查`。不是履约交底、派遣协议审查、个人承揽审查、平台用工审查、劳动仲裁或工伤文书、效力保证。

## 起草模式交付

正触发时先交可编辑草稿和未决项，再交自审风险表与自审后修改句。三闸未落入正文或附件的，不得宣称起草完成。
