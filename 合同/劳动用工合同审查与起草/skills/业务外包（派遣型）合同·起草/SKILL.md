# 业务外包（派遣型）合同·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。引用劳动合同法第五十七、六十六、九十二条时，使用 2012 年修正、2013-07-01 施行文本；2007 年第五十七条“注册资本五十万元”不得写入结论。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **劳动关系类合同 / 业务外包（派遣型）合同**，输出可编辑草稿、未决项，并用本类型硬闸自审后给出风险表和修改句。签署方为发包单位与承包单位两个组织。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。显示名为「业务外包（派遣型）合同·起草」。待签评改转 `业务外包（派遣型）合同·审查`。

`depends-on` 为空。不要求先跑导航。

不交付：劳务派遣协议起草或审查、个人承揽起草或审查、平台用工起草或审查、个人劳务承包起草或审查、劳动者劳动合同起草或审查、他类型起草、待签文本签前审查、履约交底、劳动仲裁或工伤索赔策略、解除补偿终值、有效性保证、把假外包或无证派遣改写成可履行规避结构。

## 本类型硬闸

1. **真外包 vs 假派遣**：本约以事为标的。承包方自主招聘、培训、考勤、考核、奖惩并交付可独立核算的业务成果或服务。发包方不得直接面试、考勤、奖惩、调岗、安排加班或批准请假承包方员工。文本或事实按人头供人、由发包方直接指挥监督的，点名假外包红旗；《劳务派遣暂行规定》第二十七条：以承揽、外包等名义按劳务派遣用工形式使用劳动者的，按照该规定处理。禁止只改标题。
2. **用工管理权防火墙**：甲方行使合同管理权（看结果、看 SLA）；乙方行使用工指挥权（看过程）。发包方指令只能通过《业务指令单》下达给承包方现场管理人员（领班/项目经理）。无现场管理人员、发包方主管直接给外包员工开会派活：必须改或红线。
3. **去人头化结算**：按业务量、质量、工作包或成果计价。严禁以“人数×单价”或“工资+五险一金+管理费”作为唯一计费依据。发票开“服务费/外包费”，不得开“人头费/劳务费”或个人抬头。
4. **与个人承揽 `承揽合同（个人劳务）·审查` 切开**：承包方必须是独立法人或组织。自然人按件/按项目交付、自备工具的个人承揽 → 负触发 `承揽合同（个人劳务）·审查`。禁止把本约改成个人承揽正文，禁止抄个人承揽验收主路径。
5. **与平台用工 `平台用工相关协议·审查` 切开**：平台与从业人员接单、自主决定是否接单、无固定组织指挥 → 负触发 `平台用工相关协议·审查`。禁止把本约改成网约/平台协议。
6. **与劳务派遣 `劳务派遣协议·审查` 切开**：真实派遣（持《劳务派遣经营许可证》、用工单位指挥、按人头）→ 负触发 `劳务派遣协议·审查`。假外包：留本任务点名红旗；用户改口要按派遣合规 → 整段交接 `劳务派遣协议·审查`。禁止把无证派遣改写成外包以规避许可。禁止把三性、10%、派遣许可证写成**本类型**放行条件。
7. **资质与责任隔离**：特许业务（保安、危化装卸、特种设备、医疗废物等）承包方无相应许可：红线，不改成可履行无证外包。真外包不要求《劳务派遣经营许可证》；《人力资源服务许可证》非签署前置。人员只与承包方建立劳动关系。本约两组织之间的争议走民事诉讼，严禁写成劳动仲裁。合同写“发包方不承担任何劳动法义务”只能作内部追偿，不得写成已切断法定责任。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。禁止把面试权、人头费、越级指挥写成行业惯例可放行。

## 工作边界

正触发：本类型条件已谈妥、要出己方稿；尚未签署，尚未成争；核心给付是承包单位承包一项可独立核算的业务并自主管理劳动者、按成果或业务量交付；用户要一份可签署草稿。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 有完整待签文本要评改 → `业务外包（派遣型）合同·审查`；
- 核心给付是劳务派遣单位派人、用工单位指挥监督 → `劳务派遣协议·审查` / `劳务派遣协议·起草`；
- 自然人承揽人按件/按项目交付 → `承揽合同（个人劳务）·审查` / `承揽合同（个人劳务）·起草`；
- 平台与从业人员接单协议 → `平台用工相关协议·审查` / `平台用工相关协议·起草`；专业版未装则 `unavailable`；
- 个人劳务承包、包工头式自然人承包组织劳动力 → `个人劳务承包合同·审查` / `个人劳务承包合同·起草`；专业版未装则 `unavailable`；
- 用人单位与劳动者两方劳动合同 → `劳动合同·审查` / `劳动合同·起草`；
- 平等主体个人劳务 → `个人劳务（雇佣）合同·审查` / `个人劳务（雇佣）合同·起草`；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问进场、验收日、付款日履约 → 本套导航的履约步骤；
- 已申请劳动仲裁、工伤索赔、立案、开庭 → 劳动领域或 `已成争的普通合同路径`，不审仲裁或工伤策略。

标题外包但人完全服从发包方指挥、按人头结算：留本任务，点名假外包红旗，按硬闸改管理权、结算和防火墙；用户改口要一份派遣协议 → 交接 `劳务派遣协议·审查`，本任务不写三性/10% 放行路径。

无证经营派遣、把无证派遣改成外包规避许可、转包给无用工主体资格的组织或自然人仍要放行：只出告知与红线，不改写成可履行规避结构。

## 建立起草坐标

确认：使用者与授权；单方立场（发包方或承包方择一）；相对方；已谈妥的外包业务、SLA、结算口径、现场管理人员、行业许可；不可接受事项；法域与拟签署日。缺立场不启动。条件未谈妥的商业数字用 `【待填】`，不编造。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的单价、业务量、保额用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验暂行规定第二十七条、2012 年劳动合同法第五十七/六十六/九十二条、民法典第七百七十条与第一千一百九十一条至第一千一百九十三条、侵权责任编解释（一）第十八条、安全生产法第四十九条、行业许可；`search_practiced` 只补审查反例，不写办案策略；`search_template` 只借组织对组织业务外包/服务外包栏目，不得粘贴劳务派遣协议或建设工程劳务分包范本当本约。不虚构案件系统。

## 起草模式

本原子只承担本类型起草。有完整待签文本要评改时，转 `业务外包（派遣型）合同·审查`。本类型条件已谈妥、要出己方稿时，留在本任务按三闸落稿并自审。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。按下文明示清单把本类型硬闸写成正文必写、附件必附或禁止出现。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

### 起草必写

- 标题用「业务外包协议」或「服务外包合同」；签署方是发包单位与承包单位两个组织。
- 标的是可独立核算的业务成果或服务，写清交付标准、响应时间、合格率等 SLA。
- 承包方自主招聘、培训、考勤、考核、奖惩；发包方指令只能通过《业务指令单》下达给承包方现场管理人员。
- 按业务量、质量、工作包或成果计价；发票开「服务费」或「外包费」。
- 人员只与承包方建立劳动关系。
- 本约两组织之间的争议走民事诉讼，不得写成劳动仲裁。
- 「发包方不承担任何劳动法义务」只能作内部追偿，不得写成已切断法定责任。
- 特许业务写明承包方相应许可；未见许可不得出可履行稿。

### 附件必附

- 《业务质量考核标准（SLA）》。
- 《业务指令单》范本。
- 承包方现场管理人员指定文件。
- 《外包人员名单及社保证明（仅供备案）》。
- 《安全生产管理协议》。

### 禁止出现

- 「派遣」「人头费」「劳务派遣人员」等按人头供人用语作为可履行结构。
- 以「人数×单价」或「工资+五险一金+管理费」作为唯一计费依据。
- 发包方直接面试、考勤、奖惩、调岗、安排加班或批准请假承包方员工。
- 把无证派遣改写成外包以规避许可。
- 把三性、百分之十、派遣许可证写成**本类型**放行条件。
- 把本约改成个人承揽或平台协议；把自然人承包改成可履行组织外包。

### 0. 签署状态与成果分流

本类型条件已谈妥、要出己方稿 → 留本任务按三闸落稿并自审；有完整待签文本要评改 → `业务外包（派遣型）合同·审查`；已签履约 → 本套导航的履约步骤；已成争 → 劳动领域。

### 1. 类型锁死与邻类切开

标题、签署方与核心给付一致才继续。派遣、个人承揽、平台用工、个人劳务承包、劳动合同负触发。假外包留本任务并点名。

### 2. 主体与行业资质

签约名、履行名、付款名、发票名分列。承包方须为组织。特许业务未见许可：字段停止或红线。

### 3. 真外包 vs 假派遣（管理权）

面试、考勤、奖惩、调岗、加班、请假权归属。指挥链是否混同。

### 4. 标的独立性与 SLA

是否可独立核算的业务或工段。有无交付标准、响应时间、合格率。

### 5. 去人头化结算与发票

计费依据、费用结构、发票品名。

### 6. 工伤、第三人损害与追偿

真外包走第一千一百九十三条；被穿透才走第一千一百九十一条第二款。内部追偿不得对抗劳动者或第三人。

### 7. 安全生产、数据与争议条款

进场安全协议；本约争议走民事诉讼。不审劳动仲裁策略。

### 8. 按框架六步落稿并自审

必须先出草稿，再出自我审查的风险表和修改句。不得只交白稿。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；条件未谈妥仍要编造数字出可签署终稿；用户坚持保留面试/考勤/人头费仍按真外包放行、把无证派遣改成外包、把自然人承包改成可履行组织外包、保证有效、倒签或补假 SLA/考勤隔离痕迹。
- `字段停止`：法域、行业许可真伪、业务是否可独立核算、现场管理人员是否真实委派未核验。
- `目标停止`：主目标已变为待签评改、履约交底、派遣协议审查、个人承揽审查、平台用工审查、劳动仲裁或工伤策略。
