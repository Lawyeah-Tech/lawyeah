# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的年龄、金额、期限、保额；把已失效《合同法》及其解释或解释（一）第三十二条第一款写入结论；输出劳动仲裁请求、工伤或人身损害索赔策略或胜率；把本协议改成劳动合同正文；把未退休人员改写成返聘；把“一定是劳务”“一定不是工伤”写成法律结论。

## 1. 触发、单方立场与成果状态

立场（聘用单位或受聘人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「退休返聘合同·审查」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、解释（一）第三十二条第一款当作现行有效、或把 2012 年未改动的第四十四条标成失效时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `劳动关系类合同`，子级 `退休返聘合同`。定性理由、易混切开结果（尤其与 `劳动合同·审查` 劳动合同、`个人劳务（雇佣）合同·审查` 个人劳务的切开）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、身份凭证与文本版本

主体表：聘用单位签约名、受聘人姓名、付款名、发票名、授权签字人。身份闸：出生日期、性别与原法定退休口径、现行延迟退休年龄是否已达、是否见到退休证或养老金领取记录。版本表：正文、岗位说明、退休/养老凭证、体检报告、保险方案、原劳动合同终止材料；冲突并列。未见身份凭证：签署能力字段停止，不得写“已经是劳务”。

## 5. 劳务内容、报酬、伤害与解除

劳务内容是否任务导向；报酬是否称劳务费及个税税目；是否夹带工资/试用/经济补偿；商业意外或雇主责任险是否附加超龄条款；解除通知期；体检附件。缺口标 `G#`。不输出赔偿终值。

## 6. 强制规范与不得排除的责任

去劳动化是否完成；养老金不得从劳务费扣除；民法典第一千一百九十二条过错责任不得以“概不负责”排除；工伤认定权不得由合同预先消灭。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和删除句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架“受伤不认定为工伤”“保险限额内不再承担额外责任”写成可放行免责；不得把本协议改写成劳动合同条款。

## 9. 谈判与签署提醒

谈判顺序：先红线（未达身份闸仍要返聘、劳动合同标题加试用期拒改、概不负责、养老金扣除），再必须改（去劳动化用语、劳务费与个税、商业险附加超龄、退休/养老凭证和体检入附件），最后可优化。签署提醒：退休证与最近一期养老金领取记录、体检报告或身体健康告知书、保险单或投保安排、双方盖章及受聘人亲笔签名。不指导倒签、补假退休证或补假体检。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本技能只出审查意见和修改句，不出整份起草终稿；出稿转 `退休返聘合同·起草`。不是履约交底、劳动合同审查、劳动仲裁或工伤/人身损害文书、关系定性保证。
