# 审查方法（锁定 劳动关系类合同 / 平台用工相关协议）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止把劳动合同审查或职业中介审查的 method 拼贴后换标题当作本文件。禁止套用试用期分档、违约金白名单、介绍费、跳单或人服许可正文。

本文件的主线是 **平台与从业人员之间的关系定性 + 算法治理 + 与运输平台合同切开**。三道硬闸必须走完：三分法、算法管理、运输平台切开。缺一闸不得宣称审查完成。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受，或“已经排除劳动关系”。

`search_law` 返回已失效《合同法》及其解释、劳动合同法 2007 文本、2006 年劳动争议解释（二）时记为噪声，不得写入 `L#`。把“注册个体户即排除劳动关系”“点击同意即已提示说明”“不完全符合等于平台免责”写成已核验规则的，同样记噪声。人社部发〔2021〕56 号是经国务院同意的部门联合指导意见，不是法律或行政法规；运行时用官方文本核验，不得升格。

示范文本只参考结构。人社部 2023 年新就业形态劳动者书面协议参考文本可借栏目（任务推送、报酬、休息、职业保障、申诉），不得把参考文本写成已经排除劳动关系。众包或信息技术服务范本若含“不享有工伤、不得兼职、保证金、点击即全部同意”，当反例，不得照抄。

知识库纠正（不回写双文件）：

- `基本面.md` “通常定性为中介服务、技术服务或合作经营协议”：禁止作为默认。先按指导意见第（二）项做三分法。标题或鉴于写“平等民事主体”只是 `C#`，不是结论。
- `基本面.md` “引导从业人员注册为个体工商户……弱化人身依附性”：禁止建议。指导意见要求依法合规用工；实务口径明确不得以注册个体户规避劳动法。已注册个体户仍按履行事实认定。
- `基本面.md` “去劳动化合规”若仅指识别穿透风险：可作红旗。若被理解成把实质劳动管理改成可履行民事：禁止。
- `框架.md` “严禁出现用工、聘用”“使用违约金、服务评分、降级替换入职、辞退、罚款、考勤”：只改用词不改管理，不能改变定性。本任务盯管理事实，不提供去劳动化话术。
- `框架.md` “明确约定乙方不享有工伤保险待遇”：符合劳动关系的，依法参加工伤保险，不得放弃。不完全符合的，审查职业伤害保障或商业意外／第三者责任，不得写成平台已无伤害责任。民事关系也不得用格式条款预先免除因故意或重大过失造成的人身损害。
- `框架.md` 适用场景把外卖、网约车、即时货运一并列进本类型：仅当文本是平台与从业人员的注册／合作／灵工协议。托运人运单、承运人责任、运费发票主轴 → 运输平台原子。

## 节点 1　类型识别与单目录加载

### 1.1 定性（本类型灵魂闸之一：不是运输，也不是劳动本约）

用标题、核心给付和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

必须同时满足才正触发：

1. **一方是组织接单或提供接单工具的互联网平台（或其合作商）**，另一方是提供配送、出行、即时货运、跑腿、在线服务等劳动或劳务的自然人／个体经营者。
2. **对价绑在完成平台任务或使用平台技术**，而不是促成第三人订立劳动合同，也不是把货物运达托运人指定地点作为本约标的。
3. **文本处理的是平台与从业人员之间的关系**，不是托运人与承运人之间的运单。

缺第 1 项或第 3 项：不是本类型。禁止用邻类知识把缺项补成“完整平台用工”后宣称审完。

## 节点 2　三分法（硬闸）

支持依据（当次核验写入 `L#`）：劳动合同法 2012 修正第七条（用工之日起建立劳动关系）、第十条（应当订立书面劳动合同）；劳动法 2018 修正第二条、第四条；指导意见第（二）项三分法、第（三）项合作用工、第（十八）项根据用工事实认定关系。从属判断的事实清单参考劳社部发〔2005〕12 号的三项外观（主体资格、劳动管理＋有报酬劳动、劳动是业务组成部分），该通知 MCP 常未精确命中时标官方来源，不把记忆条号写成已核验。关联单位交替或同时用工：劳动争议司法解释（二）第三条。

### 2.1 事实清单（先摘录，再归类）

每一项必须回链 `C#`／`D#`／`S#`。材料未提不得写成“不存在”，只能写 `依据不足`。

| 观察点 | 偏劳动关系 | 偏不完全符合 | 偏民事 |
| --- | --- | --- | --- |
| 是否接单 | 不能拒单或拒单即处罚、限权、封号 | 可拒单但拒单降低权重或限时 | 可自由选择时间、地点、频率，拒单无不利后果 |
| 工时与在线 | 固定班次、强制在线时长、实时考勤打卡 | 建议在线或高峰激励，无固定工时 | 明确无需考勤、无需在平台场所办公 |
| 过程控制 | 路线、话术、着装、巡检、即时调度 | 平台定服务标准，过程有抽检 | 只验收结果，不管过程 |
| 生产工具 | 平台提供车辆、账号、工服并禁止他用 | 自备工具但必须用平台包装／标识 | 自备主要生产工具 |
| 报酬 | 底薪＋考核，按月发，像工资 | 按单计酬，平台定单价和抽成 | 客户付费、平台仅技术通道，抽成透明 |
| 多平台 | 禁止或多平台即违约 | 不禁止但算法惩罚 | 明确保留多平台执业 |
| 组织外观 | 工牌、入职培训、服从规章制度、辞退 | 规则＋评分＋封号 | 平等合作、可随时注销 |

### 2.2 归类动作

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 多项偏劳动关系，尤其强制排班、实时考勤、不能拒单、禁止多平台 | **符合劳动关系**。红线：不得按民事或“不完全符合”放行。修改句要求依法订立劳动合同；其余劳动本约条款转 `劳动合同·审查`，本任务不审试用期分档或加班费精算 | 改几个用词就能去劳动化；已经是合作关系 |
| 有劳动管理（派单规则、评分奖惩、抽成）但接单时间地点有真实自由 | **不完全符合**。必须书面协议；审查算法、报酬支付、休息、职业伤害、申诉；平台不能免责 | 不完全符合＝无需保障；可以不写书面协议 |
| 自主接单、自备工具、可多平台、无过程控制、无拒单惩罚 | **民事**。仍审格式条款、算法若存在、伤害分担、数据与退出；不得预先免除故意或重大过失责任 | 民事＝可以收押金、可以强制独家、可以不公示规则 |
| 标题民事、附件考勤排班、用户口述“按对我有利的理解就是合作” | 多源并列，按履行规则定性，不选有利版 | 已经排除劳动关系 |
| 依据不足，清单多项空白 | 字段停止。列必须见到的规则页面、排班记录口径、拒单后果句 | 出具“可以按民事签” |

符合劳动关系而用户（平台侧）仍要“改成合作协议继续管人”：整体停止。符合劳动关系而用户（从业人员侧）要评估仲裁请求：目标停止，转劳动争议专项。

不完全符合不是第三种独立“法定合同类型”，是指导意见下的管理＋保障口径。修改句写“双方不完全符合确立劳动关系情形，但甲方对乙方进行劳动管理的，应按书面协议履行报酬、休息、职业伤害和算法公示义务”，不得写成新的有名合同已经成立。

## 节点 3　算法管理（硬闸）

支持依据：算法推荐管理规定第二十条（向劳动者提供工作调度服务的，应保护劳动报酬、休息休假等合法权益，建立完善订单分配、报酬构成及支付、工作时间、奖惩等相关算法）、第七条（公开算法推荐服务相关规则）、第八条（不得设置诱导沉迷等违法或违背伦理的算法模型）；指导意见第（十）项（制定修订进入退出、订单分配、计件单价、抽成、报酬、工时、奖惩等规则和算法，听取工会或劳动者代表意见，公示告知，建立申诉机制）；民法典第四百九十六条、合同编通则解释第十条（电子合同仅勾选弹窗不足以证明已提示说明）。

### 3.1 必须显化的规则

缺一项则算法字段不得写成已闭环：

1. 订单分配规则（指派／抢单、权重因子、是否可拒）。
2. 计件单价与抽成比例，调整程序和生效时点。
3. 报酬构成、结算周期、扣减项目与异议期。
4. 工作时间、在线时长、休息规则。
5. 奖惩、降权、封号的触发条件和救济。

上述规则应作为附件或可核验链接，并约定变更须再次提示。材料未见规则页面：标 `G#`，不得写“平台已依法公示”。

### 3.2 禁止的算法结构

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| 强制接单、连续拒单即封号或限制接单 | **红线删除或改为无不利后果的拒单权** | 改成“建议接单”却保留同等处罚 |
| 未写在协议里的隐形排班、强制在线 | 必须改：排班／在线规则公示，否则不得实施 | 系统需要所以合法 |
| 以罚代管：差评即高额违约金、保证金罚没 | 删除罚没；可改为降低权重并允许申诉 | 改个名字叫服务分即可留罚款 |
| 最严时效、诱导超时、超时即重罚 | 红线。指导意见第（七）项：不得制定损害安全健康的考核指标 | 时效内送到才算完成，安全自负 |
| 最终解释权归平台、算法保密不得告知 | 必须改。规则须公示告知；商业秘密不能对抗报酬和工时知情 | 算法是商业秘密所以可以不公开 |
| 无申诉或申诉后仍立即永久封号且结算清零 | 必须改：申诉通道、处理时限、申诉期间限制扩大损失 | 内部客服已读即处理完毕 |

平台侧修改句：补公示、听取意见、申诉和变更通知。从业人员侧修改句：要求附件化规则、拒单无罚、时效取中值或合理区间、封号前书面通知和已完单结算。

## 节点 5　报酬、休息、职业伤害、禁止收费

支持依据：指导意见第（四）项不得收取保证金、押金或其他财物，不得违法限制多平台就业；第（五）项不完全符合纳入最低工资保障口径、按时足额支付；第（六）项合理休息，法定节假日支付合理报酬；第（九）项出行、外卖、即时配送、同城货运等职业伤害保障试点，平台应按规定参加，并鼓励商业保险。劳动合同法第九条（用人单位不得扣证、要求担保或收取财物）在被认定为用人单位时并行适用。

| 事项 | 文本要求 | 不得写成 |
| --- | --- | --- |
| 报酬名称 | 三分法未定时不要把“服务报酬”直接改成“工资”，也不要默认“不是工资”。先定性再选词 | 改成技术服务费就排除工资属性 |
| 支付 | 周期、路径、扣减清单、对账单和异议期。抽成数字缺则 `【待填】` | 平台可随时单方调价且立即生效、不得异议 |
| 休息 | 不完全符合或劳动管理：休息办法和超强度限制要落句 | 接单自由所以无需休息条款 |
| 职业伤害 | 试点行业写明是否参加及扣费用途；非试点写商业意外／第三者责任的投保人、保额、受益口径 | 一律约定不享有工伤且平台免责 |
| 押金／保证金／装备押金 | **红线删除**。指导意见第（四）项 | 少收一点合法；履约保证金可留 |
| 多平台 | 默认允许。独家须有对价和期限，否则删除禁业 | 为防飞单必须独家 |

报酬是否低于当地最低工资：无履行地和工时数据则字段停止，不编造金额。

## 节点 6　程序、电子签署、格式条款

平台用工多为电子点击。审查：

1. 核心条款（关系定性、抽成、限责、管辖、单方变更、伤害分担）是否单独加黑、弹窗或确认页。
2. 合同编通则解释第十条：仅勾选、弹窗，不得认定已尽提示或说明，除非另证明显著标识和可理解说明。
3. 隐私政策：位置、生物识别、行程轨迹须最小必要、目的明示、保存期限；不得与主协议偷偷并入且不可单独查阅。
4. 账号注册成功或首单点击的生效时点要写清；规则更新的通知和拒绝更新时的退出结算要写清。

用户要求“点一下就算全部同意、以后改规则不用再通知”：必须改。

## 节点 7　解除、争议改写、运输切开复核

### 7.1 退出

从业人员可注销退出；平台因严重违规或丧失资质可限制接单。必须写：已完单报酬结算、在途保险责任、个人数据删除或匿名化、申诉期间不得扩大封号后果。不得把“单方永久封号且全部收益归平台”写成可接受。

### 7.2 争议解决：改写法，不审策略

或裁或诉、机构不明：标待核，改成单一仲裁机构或单一法院连结点。若三分法指向劳动关系，商事仲裁条款必须改，劳动争议走法定仲裁前置；本技能不写仲裁请求或时效计算。用户追问确认劳动关系怎么赢：目标停止。

### 7.3 运输切开复核（硬闸收口）

在出修改句前再核一次：用户真正要审的是不是运单、承运责任、货损、运费发票。是则负触发 `合作文本。托运人与网络货运经营者之间以承运人身份揽货并收运费开运输票的，负触发` 或 `仅为货源／运力信息撮合不承运不收运费的运输中介文本，负触发`，撤回已写的用工修改句中与承运责任冲突的部分。司机注册协议里夹带“平台对货主承担承运人责任／不承担承运人责任”的，只标与运输原子的交接，不在本任务改承运条款。

## 节点 8　按框架六步出修改句

本节点是成果闸。没有修改句或红线，不得宣称审查完成。禁止只打红黄绿。三分法句、算法公示／禁止强制接单句、运输切开句（或“已确认非运输合同”的回链）都缺，不得宣称本类型审查完成。

打开已加载的 `框架.md`，按六步逐段对照正文。`基本面.md` 用于校验类型、主体、算法和红旗，不代替本节点出句。框架与硬闸冲突的，以本文件为准。

| 步 | 动作 | 必须产出 |
| --- | --- | --- |
| 首部 | 标题可用平台服务／注册用户／新就业形态书面协议；禁止假装已经排除劳动关系。主体列平台、合作商、从业人员。鉴于写明按用工事实定性，不把民事声明写成已核验结论 | 标题或主体修改句 |
| 交易条款 | 接单自主性的正说与反说；派单／抢单规则；报酬与抽成；工具归属；考勤是否存在 | 闭环修改句；缺数字用 `【待填】` |
| 配套 | 算法公示与申诉；职业伤害或商业保险；删除押金；多平台；封号与结算；数据；争议改单一连结点 | 删除句或可执行后果句 |
| 尾部 | 电子签署提示痕迹；规则附件；隐私政策；许可证或试点参保凭证作为附件 | 生效与附件修改句 |
| 语言 | 盯死工资／服务报酬、考勤／在线、罚款／降权、工伤／职业伤害。不提供去劳动化同义替换表 | 替换空词或删除规避词的句子 |
| 常见问题 | 用词去劳动化但管理仍在；个体户夹层；强制接单；运输合同误入；点击即同意 | 结构级改法或红线 |

每条修改句固定格式：

`定位（条／款／附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

示范三分法句（不完全符合）：

`定位首部／关系条款｜原文：双方为平等民事主体，不建立任何劳动关系，乙方放弃一切劳动保障｜建议改为：双方根据用工事实确定权利义务。若甲方对乙方进行劳动管理但乙方对是否及何时接单有真实自由，双方按书面协议履行报酬支付、休息安排、职业伤害保障和算法规则公示义务，甲方不得以本条排除前述义务。若履行中出现强制排班、实时考勤或不能拒单，任何一方有权要求依法改订劳动合同。｜理由：L# 指导意见第（二）项；劳动合同法第七条｜可退让点：民事外观可保留，但必须加履行中穿透改订句｜不接受时的红线：坚持“已排除劳动关系且平台无保障义务”仍要放行`

示范算法句：

`定位规则／奖惩条款｜原文：乙方必须服从系统派单，连续拒单三次永久封号，算法规则属商业秘密不予披露｜建议改为：甲方应向乙方公示订单分配、计件单价、抽成比例、报酬支付、工作时间和奖惩算法的规则文本（附件【待填】）。乙方有权拒绝派单，拒单不作为封号或扣减已完单报酬的理由。规则变更应于生效前【待填】日提示；乙方不接受的，可注销并结算已完单报酬。乙方对降权或限制接单有权在【待填】日内申诉，申诉处理前不得扩大限制。｜理由：L# 算法推荐管理规定第二十条、第七条；指导意见第（十）项｜可退让点：可约定恶意刷单、安全违规的限制接单，但须列明情形和申诉｜不接受时的红线：保留强制接单或秘密算法仍要放行`

示范个体户删除句：

`定位主体／准入条款｜原文：乙方须注册个体工商户后与甲方签署本合作协议，否则不得接单｜建议改为：甲方不得诱导或强迫乙方注册个体工商户、个人独资企业或其他商事主体作为接单条件。乙方是否登记为市场主体，不改变按用工事实认定双方关系。｜理由：I# 指导意见第（二）项＋实务反例：注册个体户不当然排除劳动关系｜可退让点：无｜不接受时的红线：把注册个体户当作去劳动化前提仍要放行`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（实质劳动却坚持民事放行、强制接单或诱导超时、个体户规避、押金、童工／强迫劳动、运输合同误审）；
- `必须改`：可谈但签署前要落句（算法未公示、无申诉、职业伤害未写、仅勾选、禁多平台无对价、合作商夹层未显化）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级抽成或保证金且用户拒绝升级：停止“可以签署”建议。

## 起草模式与自审

本任务是起草。有完整待签文本要评改时转 `平台用工相关协议·审查`。
按框架六步落稿，必须写入下列三闸。出稿后按上文审查节点自审自己的稿，未过不得宣称完成。

### 起草必写

- 先按用工事实做三分法，再落稿：符合确立劳动关系的，不得起草去劳动化民事稿，应转 `劳动合同·审查` 或停止。
- 不完全符合确立劳动关系但企业进行劳动管理的，必须落书面协议，并写报酬、休息、职业伤害保障、算法公示与申诉；不得写成平台已无保障义务。
- 民事关系须有真实自主接单、自备主要生产工具、可多平台执业；仅改用词不改管理，不得升格为民事。
- 订单分配、计件单价、抽成比例、报酬构成及支付、工作时间、奖惩等规则和算法须公示并告知，并建立可执行申诉通道。
- 费率、限责、管辖、单方调价、最终解释权须有足以引起注意的提示；仅网络勾选不得写成已尽提示说明。
- 除非独家且有对价，保留多平台执业；封号、注销、规则变更的通知与结算清理要落句。
- 职业伤害试点或商业意外／第三者责任必须有安排；不得向从业人员收保证金、押金。

### 附件必附

- 算法规则或规则页面版本。
- 隐私政策。
- 职业伤害或商业保险凭证。
- 电子签署提示说明痕迹。
- 合作商或站点协议（存在夹层时）。

### 禁止出现

- 「标题写合作就一定不是劳动关系」；「注册个体户就排除劳动法」。
- 换掉「入职／罚款／考勤」就可以去劳动化；「不完全符合等于平台免责」。
- 「点击同意即已尽提示说明」。
- 强制接单、隐形排班、以罚代管、诱导超时或把最严时效写成考核默认。
- 诱导或强迫注册个体工商户以规避用人单位义务。
- 把司机／骑手注册协议按运输合同审完，或把运单／承运条款按本类型改残。
- 把实质劳动关系改写成可履行的民事合作。
