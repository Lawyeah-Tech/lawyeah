# 平台用工相关协议·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。引用劳动合同法第七条、第十条时，使用 2012 年修正、2013-07-01 施行文本；2012 年修正未改这些条文文字的，不得把 2007 文本标成失效。不得把《关于维护新就业形态劳动者劳动保障权益的指导意见》写成法律或行政法规。不得把标题或“去劳动化”用词写成已经排除劳动关系。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **劳动关系类合同 / 平台用工相关协议**，输出可编辑草稿、未决项，并用本类型硬闸自审后给出风险表和修改句。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。显示名为「平台用工相关协议·起草」。待签评改转 `平台用工相关协议·审查`。专业版未装本原子时输出 `unavailable`，提示，不得用邻类硬套。

`depends-on` 为空。不要求先跑导航。

不交付：他类型起草；待签文本签前审查；履约交底；争议文书或劳动仲裁策略；有效性保证；把实质劳动关系改写成可履行的民事合作；把诱导或强迫注册个体工商户写成去劳动化最佳实践；把网络货运或信息中介运输合同按本类型写完。

## 本类型硬闸

1. **三分法先定性**。按用工事实，而不是按标题或“平等民事主体”声明，分成三类：符合确立劳动关系情形、不完全符合确立劳动关系情形但企业对劳动者进行劳动管理、个人依托平台自主开展经营活动的民事关系。符合劳动关系的，不得改写成民事或“不完全符合”后放行，应转 `劳动合同·审查` 或停止可履行的去劳动化结构。不完全符合的，必须落书面协议，并审查报酬、休息、职业伤害保障、算法公示与申诉；不得写成平台已无保障义务。民事关系须有真实自主接单、自备主要生产工具、可多平台执业；仅改用词不改管理，不得升格为民事。
2. **算法管理**。订单分配、计件单价、抽成比例、报酬构成及支付、工作时间、奖惩等规则和算法须公示并告知从业人员，建立申诉通道。禁止强制接单、隐形排班、以罚代管、诱导超时或把最严时效写成考核默认。仅有网络勾选不得写成已尽提示说明。
3. **与运输平台切开**。本类型审的是平台与从业人员之间的用工／合作文本。托运人与网络货运经营者之间、以承运人身份揽货并收运费开运输票的，负触发 `合作文本。托运人与网络货运经营者之间以承运人身份揽货并收运费开运输票的，负触发`。仅为货源／运力信息撮合、不承运、不收运费的运输中介文本，负触发 `仅为货源／运力信息撮合不承运不收运费的运输中介文本，负触发`。禁止把司机／骑手注册协议按运输合同审完，也禁止把运单／承运条款按本类型改残。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

禁止表述：标题写合作就一定不是劳动关系；注册个体户就排除劳动法；换掉“入职／罚款／考勤”就可以去劳动化；不完全符合等于平台免责；点击同意即已尽提示说明；合同一定有效或全部无效；先签再改。

## 工作边界

正触发：本类型条件已谈妥、要出己方稿；尚未签署，尚未成争；核心给付是互联网平台与从业人员之间的信息匹配、任务分发或技术支持，从业人员按单或按任务提供服务；用户要一份可签署草稿。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 有完整待签文本要评改 → `平台用工相关协议·审查`；
- 已是全日制书面劳动合同，工时工资社保岗位齐全、无平台派单主轴 → `劳动合同·审查` / `劳动合同·起草`；
- 按人头派驻、三方派遣、需要《劳务派遣经营许可证》作为主给付 → `劳务派遣协议·审查` / `劳务派遣协议·起草`；
- 职业介绍／猎头撮合双方建立劳动关系，中介自己不派单 → `职业介绍／猎头撮合双方建立劳动关系，中介自己不派单→`（P1 未装则 `unavailable`）；
- 假外包真派遣、人员接受发包方直接管理 → `业务外包（派遣型）合同·审查` / `业务外包（派遣型）合同·起草`（P1 未装则 `unavailable`）；
- 个人劳务承包、个人劳务雇佣、个人承揽，无平台算法派单 → `个人劳务承包合同·审查` / `个人劳务承包合同·起草`／`个人劳务（雇佣）合同·审查` / `个人劳务（雇佣）合同·起草`／`承揽合同（个人劳务）·审查` / `承揽合同（个人劳务）·起草`；
- 托运人与网络货运平台之间的货物运输、平台以承运人身份收运费开运输票 → `合作文本。托运人与网络货运经营者之间以承运人身份揽货并收运费开运输票的，负触发`（P1 未装则 `unavailable`）；
- 货源／运力信息撮合、平台不承运不收运费的运输中介 → `仅为货源／运力信息撮合不承运不收运费的运输中介文本，负触发`（P1 未装则 `unavailable`）；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问履约节点、结算日历或职业伤害申报节点 → 本套导航的履约步骤；
- 已催告、索赔、立案、开庭、仲裁，或主问怎么确认劳动关系、怎么打劳动仲裁 → `已成争的普通合同路径` 或劳动争议专项。

强迫劳动、使用未满 16 周岁未成年人、诱导或强迫注册个体工商户以规避用人单位义务、把最严时效或诱导超时写成可履行考核：只出告知，不改写成可履行结构。用户坚持“改到能规避劳动法”：整体停止。

## 建立起草坐标

确认：使用者与授权；单方立场（从业人员／平台企业／合作商或站点择一）；相对方；已谈妥的派单与算法规则、报酬与抽成、职业伤害或保险、是否强制注册个体户；不可接受事项；法域与拟签署日。缺立场不启动。条件未谈妥的商业数字用 `【待填】`，不编造。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的抽成、时效、保额用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验劳动合同法第七条／第十条（2012 修正）、算法推荐管理规定第二十条、民法典第四百九十六条至第四百九十八条、合同编通则解释第十条、劳动争议司法解释（二）第三条；`search_practiced` 只补审查反例，不写办案策略；`search_template` 只借栏目结构。人社部发〔2021〕56 号指导意见及职业伤害试点细则，MCP 未精确命中时用官方公开文本核验，不得把指导意见升格为法律。不虚构案件系统。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》或其解释、劳动合同法 2007 文本、2006 年劳动争议解释（二）时记为噪声，不得写入 `L#`。把“注册个体户即排除劳动关系”或“点击同意即已提示说明”写入结论的，同样不得写入 `L#`。


## 起草模式

本原子只承担本类型起草。有完整待签文本要评改时，转 `平台用工相关协议·审查`。本类型条件已谈妥、要出己方稿时，留在本任务按三闸落稿并自审。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。按下文明示清单把本类型硬闸写成正文必写、附件必附或禁止出现。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

### 起草必写

- 先按用工事实做三分法，再落稿：符合确立劳动关系的，不得起草去劳动化民事稿，应转 `劳动合同·审查` 或停止。
- 不完全符合确立劳动关系但企业进行劳动管理的，必须落书面协议，并写报酬、休息、职业伤害保障、算法公示与申诉；不得写成平台已无保障义务。
- 民事关系须有真实自主接单、自备主要生产工具、可多平台执业；仅改用词不改管理，不得升格为民事。
- 订单分配、计件单价、抽成比例、报酬构成及支付、工作时间、奖惩等规则和算法须公示并告知，并建立可执行申诉通道。
- 费率、限责、管辖、单方调价、最终解释权须有足以引起注意的提示；仅网络勾选不得写成已尽提示说明。
- 除非独家且有对价，保留多平台执业；封号、注销、规则变更的通知与结算清理要落句。
- 职业伤害试点或商业意外／第三者责任必须有安排；不得向从业人员收保证金、押金。

### 附件必附

- 算法规则或规则页面版本。
- 隐私政策。
- 职业伤害或商业保险凭证。
- 电子签署提示说明痕迹。
- 合作商或站点协议（存在夹层时）。

### 禁止出现

- 「标题写合作就一定不是劳动关系」；「注册个体户就排除劳动法」。
- 换掉「入职／罚款／考勤」就可以去劳动化；「不完全符合等于平台免责」。
- 「点击同意即已尽提示说明」。
- 强制接单、隐形排班、以罚代管、诱导超时或把最严时效写成考核默认。
- 诱导或强迫注册个体工商户以规避用人单位义务。
- 把司机／骑手注册协议按运输合同审完，或把运单／承运条款按本类型改残。
- 把实质劳动关系改写成可履行的民事合作。

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)

禁止打开其他类型目录。`基本面.md` 把本类型默认写成中介／技术服务／合作经营、把引导注册个体户写成去从属结构：按 method 纠正，不回写知识库。`框架.md` 要求删除“用工／聘用”、约定不享有工伤、用商事术语替换考勤罚款：按 method 当作风险信号或禁止建议，不当作放行改法。

### 0. 签署状态与成果分流

本类型条件已谈妥、要出己方稿 → 留本任务按三闸落稿并自审；有完整待签文本要评改 → `平台用工相关协议·审查`；已签履约 → 本套导航的履约步骤；已成争 → 劳动或争议专项。

### 1. 类型锁死（用工协议 ≠ 运输合同 ≠ 劳动合同本约）

标题、核心给付与“平台对从业人员派单或提供接单工具”一致才继续。托运人运输、信息中介运力撮合、全日制劳动本约、职业介绍、派遣、外包派人负触发。

### 2. 三分法

按从属事实归入劳动关系／不完全符合／民事。名实不符写入 `C#`。符合劳动关系不得在本任务改成民事。

### 3. 算法与规则公示

派单、定价、抽成、工时、奖惩是否公示；有无强制接单、隐形排班、以罚代管、诱导超时；申诉通道是否可执行。

### 4. 主体与个体户夹层

平台、合作商／站点、从业人员、个体户登记是否同一履行关系。关联单位交替用工按解释（二）第三条标风险。诱导或强迫注册个体户：红线。

### 5. 报酬、休息、职业伤害、禁止收费

报酬性质与支付节点；不完全符合不得低于提供正常劳动的当地最低工资口径（运行时核验）；职业伤害试点或商业意外／第三者责任；不得向从业人员收保证金、押金。

### 6. 格式条款与电子签署

费率、限责、管辖、单方调价、最终解释权须有足以引起注意的提示；仅勾选或弹窗不够。

### 7. 多平台执业与退出

除非独家且有对价，保留多平台执业。封号、注销、规则变更的通知与结算清理要落句。

### 8. 按框架六步落稿并自审

必须先出草稿，再出自我审查的风险表和修改句。不得只交白稿。三分法句、算法公示／禁止强制接单句、运输平台切开句不得省略。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；条件未谈妥仍要编造数字出可签署终稿；用户坚持倒签、把实质劳动关系改成可履行民事、诱导或强迫注册个体户以规避劳动法、把强制接单或诱导超时改成可履行考核、使用童工或强迫劳动、保证有效。
- `字段停止`：法域、动态规则、行业许可、职业伤害试点范围、算法规则页面未核验。
- `目标停止`：主目标已变为待签评改、履约交底、争议文书，或把本合同改成运输合同／劳动合同本约／职业中介。

从业人员生存级报酬被抽成或保证金卡住且用户拒绝升级：停止放行建议，只列风险与转介。
