# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、保证排除劳动关系、对方接受或必然可执行；编造未给出的抽成、时效、保额、许可证号；把已失效《合同法》及其解释写入结论；把实质劳动管理改成可履行民事；把注册个体户写成已经排除劳动法。

## 1. 触发、单方立场与成果状态

立场（从业人员／平台企业／合作商或站点择一）、授权、签署状态、主要目标。负触发写完整 Skill ID 路由，不启动实体审查。P1 未装写 `unavailable`。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、劳动合同法 2007 文本、2006 年劳动争议解释（二）时记噪声，不得写入 `L#`。指导意见 56 号注明官方文本核验状态，不得标为法律。

## 3. 类型与加载路径

父级劳动关系类合同、子级平台用工相关协议、定性理由、与劳动合同／职业中介／劳务派遣／业务外包／网络货运运输／运输信息中介的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。强迫劳动、童工、个体户规避写停笔告知，不填可履行结构。

## 4. 主体、许可、授权与文本版本

主体表：平台、合作商／站点、从业人员、个体户字号（如有）、签约名、付款名、实际管理人。许可表：增值电信／网约车等行业许可是否被提及，职业伤害试点是否参加。版本表：正文、规则页面、隐私政策、合作商协议、个体户登记、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

三分法结论（劳动关系／不完全符合／民事／依据不足）；接单自主性；算法规则是否公示；报酬与抽成；休息；职业伤害或商业保险；多平台；退出结算。缺口标 `G#`，不补商业数字。批准、许可、试点参保写成生效条件或期限，不写成已经完成。

## 6. 强制规范与格式条款

强制接单、隐形排班、以罚代管、诱导超时、押金、个体户准入是否出现。是否构成格式条款；提示说明痕迹；异常条款。强制规范只区分行政管理后果与是否导致民事行为无效。无 `search_law` 或官方文本引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。三分法、算法管理、运输平台切开三类至少各有一行可回链，除非该事实确定不存在并写明依据。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。三分法句、算法公示／禁止强制接单句不得用“建议注意合规”代替。不得输出去劳动化同义替换表。

## 9. 谈判与签署提醒

谈判顺序：先红线（实质劳动却坚持民事、强制接单或诱导超时、个体户规避、运输误审），再必须改，最后可优化。签署提醒：规则附件、隐私政策、合作商协议、职业伤害或保险凭证、电子签署提示痕迹、日期真实。不指导倒签或补假个体户。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本技能只出审查意见和修改句，不出整份起草终稿；出稿转 `平台用工相关协议·起草`。不是履约交底、争议文书、劳动仲裁策略、运输合同审查或效力保证。
