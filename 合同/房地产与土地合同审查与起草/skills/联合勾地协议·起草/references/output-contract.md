# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、一定竞得或必然可执行；编造未给出的份额、限价、价款；把已失效《合同法》及其解释、《物权法》、1986 年土地管理法旧义写入结论；把《招标投标法》自动写成土拍准据法；保证备案或登记一定办成；把单方勾地、已挂牌联合拿地或合作开发文本当成已完成的本类型审查；写“确保拿地可履行”；写“未备案则本约未生效”。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查联合勾地协议（土地使用权）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《物权法》、1986 年土地管理法或 1990 年联营解答时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `土地使用权`，子级 `联合勾地协议`。定性理由、易混切开结果（预申请 / 单方勾地 / 出让合同 / 已挂牌联合拿地 / 股权拿地 / 合作开发 / 代建）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。挂靠、围标、商业贿赂写停笔告知，不填可履行结构。

## 4. 主体、竞买身份、份额与文本版本

主体表：签约名、竞买申请名、保证金付款名、出让金付款名、拍后股东名、授权举牌人、保证人。份额表：保证金、出让金（含溢价）、拍后股权或权益、沉没成本。版本表：正文、授权委托书、章程草案、预签股权文件、产业监管协议、聊天确认；冲突并列。

## 5. 给付闭环

目标地块是否特定到规划指标；竞买身份是否三者择一；举牌人与最高限价；资金监管；三极端退出；拍后退出路径（不得写成开发经营）。缺口标 `G#`。批准、登记、公告、国资决议写成生效条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。确保拿地、陪标、商业贿赂不得写成可放行。强制规范只按第一百五十三条、第一百五十四条区分是否导致民事行为无效，不用失效口诀，不自动套《招标投标法》。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把合作开发条款直接改成“联合勾地已闭环”而不问是否应转 `房地产合作开发类合同·审查`。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为单方勾地或合作开发、份额真空、无限额举牌、确保拿地或陪标、无监管打款），再必须改（授权委托书、三极端退出、溢价分担、国资决议、产业监管附件），最后可优化。签署提醒：有权公章、举牌授权书与正文一致、份额附件、监管账户开户文件、实际控制人保证。不指导倒签或把未备案写成合同无效。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是单方勾地、出让合同、已挂牌联合拿地或合作开发安排。
