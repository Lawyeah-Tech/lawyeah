# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然中选或必然可执行；编造未给出的保证金、面积、工期；把已失效《合同法》及其解释写入结论；把意向写成已锁定实施权；打开或摘抄 `城市更新项目前期服务合同·审查`／`城更合作（村集体与企业）·审查` 的主路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。成果名称必须写「审查城市更新项目意向合作协议（房地产合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释或担保法解释时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级、子级、定性理由、易混切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型，且未打开 `城市更新项目前期服务合同·审查` 或 `城更合作（村集体与企业）·审查` method。跳过招商锁定实施权、个人账户、阴阳协议写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、履行名、付款名、收款名、授权签字人。村集体侧是否为登记合作社或依法代行的村民委员会；有无匹配事项的表决决议；企业是否子公司签约。版本表：正文、红线图、表决材料、监管账户文件、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

约束力分层表（有约束力模块／预约模块／无强制订立本约模块）；排他对象、禁止行为、节点与最长期限；前期配合清单；保证金性质、账户、计息、退还与转化；“不代表最终开发权”声明。缺口标 `G#`，不补商业数字。招商、批复、选聘写成条件或期限，不写成已经完成，也不写成已锁定实施权。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款。强制规范只区分是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。锁定实施权、个人账户、无上限排他先改句或停笔，不先宣告整约无效。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。禁止补写正式开发的利益分配表或分户补偿标准。

## 9. 谈判与签署提醒

谈判顺序：先红线（锁定实施权、无上限排他、个人账户、假表决），再必须改（约束力分层、退还触发、表决附件），最后可优化。签署提醒：合作社或村集体公章而非个人章；决议、红线图、退还指引作附件；保证金到监管账户再生效；拒绝倒签表决日。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、正式合作审查或效力保证。
