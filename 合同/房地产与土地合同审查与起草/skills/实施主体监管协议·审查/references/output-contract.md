# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证协议有效、资格不被撤销、预售一定办成或对方接受；编造未给出的面积、文号、保证金、税收指标；把已失效《合同法》、1989 年行政诉讼法第十二条旧义、法释〔2015〕9 号写入结论；把本约改成民事合作或更新合作；把商事仲裁写成可放行；把公建挂钩删掉以便先卖；把未确认主体写成可以报批。

## 1. 触发、单方立场与成果状态

立场（实施主体／项目公司、监管机关、拟提供连带保证的母公司）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在监管机关与已确认实施主体，以及公共贡献是否为核心理由。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》、1989 年行政诉讼法第十二条旧义、法释〔2015〕9 号时记噪声，不得写入 `L#`。行政协议定性、仲裁条款、单方变更解除补偿、预售条件、地方更新办法无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `实施主体监管协议`。定性理由必须同时满足：监管机关；已确认或明文以确认为前提的实施主体；公共贡献监管为主给付。易混切开：更新合作五类、土地出让、资金监管专户、拆迁补偿、合作开发／联建。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开更新合作或合作开发 method。伪造确认、规避限购、先卖后建或假移交写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：监管方、实施主体、保证母公司、接收单位。法人写名称与统一社会信用代码；机关写全称与是否区级以上更新主管部门或是否载明委托。

版本表：监管协议正文、公共设施清单、质量标准、资金监管细则、安置面积统计、范围坐标图、保函／保证金凭证、实施主体确认文件、专项规划批复、容积率计算表、建设用地规划许可证、聊天确认。冲突并列，不选对用户有利的一版。口头“已经确认了”“局里同意了”不得写成已确认。

## 5. 公共贡献与监管给付闭环

分列并回链文本位置：

- 项目：单元名称、确认文号、专项规划批复号、用地红线及面积。
- 性质：是否锁定行政监管、是否误写成合作开发。
- 空间移交：无偿移交用地类型、面积、时限。
- 实物配建：保障房、产业用房、幼儿园等面积、装修标准、地下车位是否一并移交。
- 安置：回迁总面积、过渡费义务、与安置协议的引用。
- 规划一致性：清单是否与规划许可、容积率表一致。
- 资金监管：总额、是否另签专户协议、节点拨付。
- 三同步与挂钩：公建与融资区进度关系；预售／验收／首次登记前提。
- 保函或保证金：金额、是否可替换为不可撤销保函、阶梯调减。
- 移交定义：是否完成登记并交证；移交前风险；是否禁止抵押。
- 接收标准：是否锁定签订时标准；事后加码如何处理。
- 股权锁定与母公司保证。
- 资格撤销程序与补偿接口。
- 税收／入驻考核及缺额后果。
- 分期隔离。

缺口标 `G#`，不补商业数字、文号或已确认事实。批准、许可、移交写成条件或期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

机关制式文本预先拟定且未协商的，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：是否构成行政协议；仲裁条款；单方变更解除；规划条件不得擅自改变；预售法定条件；配套幼儿园同步移交；伪造确认。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“标题是监管协议所以必然是有效行政协议”或“整份协议因仲裁条款而全部无效”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：误写成民事合作或更新合作；实施主体未确认或名实不符；仲裁或或裁或诉；公建未达标仍可预售；资格撤销无程序或被改成民事协商消灭监管权；移交定义不是登记交证；接收标准可被事后加码；规划指标与清单冲突；应移交资产设抵押；无保函或保函不可调减；税收兜底无上限；不可抗力含经营不善；缺地下车位移交；多期未隔离。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、文号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：鉴于锁定监管而非合作；删除商事仲裁；公建挂钩预售／验收／首次登记；资格撤销保留行政属性并补程序与补偿接口；移交＝登记交证且无抵押。

## 9. 谈判与签署提醒

谈判顺序：先红线（改成民事合作或仲裁、删挂钩先卖、伪造确认、应移交资产设抵押），再必须改（确认文件一致、规划对齐、移交标准、三同步、保函阶梯、非归责顺延、分期隔离），最后可优化（保函替代现金、动态考核）。

签署提醒：监管机关公章与法定代表人签；确认文件、批复、清单、保函作附件；日期真实。不指导倒签或补假确认。

实施主体立场必须提示：签字后面临资格撤销、报批停摆和保证金扣划；前期投入可能无法收回。监管机关立场可坚持挂钩和保函，但须提示违法变更解除可能引发补偿或赔偿，不得保证处置一定成立。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、复议或诉讼文书、保证金精算终局或效力保证。
