# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然中选或必然可执行；编造未给出的服务费、面积、容积率；把已失效《合同法》及其解释或 1993 年反不正当竞争法第七条旧义写入结论；保证批文或中选一定办成；把前期服务、股权合作、村集体本约或合作开发文本当成已完成的本类型审查；写“包办批文可履行”；写“咨询费空转可以过关”。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查城市更新项目合作合同（开发商与前期服务公司）（房地产合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1993 年反不正当竞争法第七条旧义或失效技术合同法实施条例时，记噪声，不得写入 `L#`。MCP 效力字段与官方施行日冲突时，以施行日为准。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `城市更新项目合作合同（开发商与前期服务公司）`。定性理由、易混切开结果（前期服务 / 股权合作 / 意向协议 / 村集体本约 / 合作开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、筹码、授权与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。筹码表：村集体协议、表决／成员大会、政府备案或立项、核心执行人。版本表：正文、红线图、村集体协议复印件、进度确认单、廉洁协议、资金监管协议、聊天确认；冲突并列。

## 5. 成功标准、对价阶梯、跳单排他与结算分流

成功标准是否锁在正式签约成为合作企业；服务范围是否节点化；费用是否阶梯且未一次预付；共管安排；规划指标调整；二次收费是否闭合；跳单与排他；非中选／政策／后续补偿金归属；资料所有权与保密。缺口标 `G#`。不输出股权对赌或利润分成主路径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。包办批文、空转咨询费、向影响力主体输送利益、伪造表决不得写成可放行。强制规范只按第一百五十三条及合同编通则解释第十六条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把利润分成或股权条款直接改成“服务费类型”而不问是否已是他类。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为前期服务或股权合作、包办批文、空转贿赂、一次预付、筹码未闭合仍要全额预付），再必须改（成功标准、阶梯支付、跳单排他、非中选结算、资料归属、规划指标调整），最后可优化。签署提醒：项目组授权决策人、红线图、村集体协议复印件、表决文件、进度确认单、廉洁协议、共管协议。不指导倒签或补假表决／假备案。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是前期服务、股权合作、村集体本约或合作开发安排。
