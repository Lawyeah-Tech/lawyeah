# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同有效、已经取得典型物权、必然直接确权、必然对抗执行或对方接受；编造未给出的面积、份额、出资额、证号、税额；把已失效《合同法》《物权法》及其解释写入结论；把 2005 年解释已删除第 16 条当现行划拨无效专条；把合作建房暂免土地增值税写成已经适用；把双方都必须有资质写成民事效力唯一条件；把单名义隐名或二次过户留在本技能改完；把全部联建子类型写进一份意见。

## 1. 触发、单方立场与成果状态

立场（土地提供方 / 投资联建方）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在双名义报建和直接初始登记主结构，以及当地联建政策是否已核。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《物权法》及其解释、2005 年解释已删除第 16 条、失效划拨联建视同转让专条时记噪声，不得写入 `L#`。合作开发定义与资质效力、固定回报定性、合同效力与登记分离、预告登记、开发资质、25% 转让条件、预告登记执行异议无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `联建模式联建合同`。定性理由必须同时满足：共同开发；双名义报建；直接初始登记。易混切开：参建隐名、出资结构型联建、风险分担型联建、操盘型联建、委托代建、项目公司股权、土地使用权转让、宅基地合作。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `隐名参建联建·审查` 或其他联建子类型 method。挂靠、违法分包、规避限购或未达投资额变相转让写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：土地提供方、投资联建方、共同项目管理机构、授权签字人、国资/集体/上市公司决议机关。自然人写姓名与证件号是否与文本一致；法人写名称与统一社会信用代码。分列民事资质（一方即可）与行政双资质（报建可行性）。

版本表：联建正文、报建授权、分房位置图/拟分配明细、土地红线图、权属证书、资质证书、政策咨询纪要、内部决议、聊天确认。冲突并列，不选对用户有利的一版。口头“已经备案了”“土地没查封”不得写成已批准或已洁净。

## 5. 联建给付闭环

分列并回链文本位置：

- 地块：坐落、面积、证号、用途、出让或划拨。
- 双名义：立项、规划许可、施工许可、竣工验收备案是否均记载双方。
- 共同发包：对外工程合同是否双方共同发包人。
- 土地权利：是否办理使用权共有登记；份额。
- 出资与管理：资金由谁投入；是否共同项目部。
- 确权：直接初始登记还是二次过户；部位是否特定。
- 语言：初始登记/直接登记 vs 过户登记。
- 税务：合作建房申请、失败分担、发票开具对象。
- 风险：是否共担亏损、超支、处罚。
- 对抗执行：预告登记、购建房款凭证；不得写成必然排除执行。
- 政策断档：转项目公司或免责解除。
- 违约：拒不盖章、查封致无法确权。

缺口标 `G#`，不补商业数字、证号或已批准事实。批准、登记、备案写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

一方预先拟定且未协商的异常条款，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：双方均无开发资质；划拨/集体土地未批；未达投资额变相转让；挂靠借用资质；规避限购。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“联建手续已经是物权”或“双方必须都有资质否则合同一律无效”写成已核验结论。不得把无规划许可仍请求分配项目利益写成可放行。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：名不副实单名义；二次过户主路径；初始登记写成过户；分房部位不特定；土地不洁净；民事/行政资质未分账；不共担风险；税务失败无预案；发票单开；对抗执行保证；政策断档无备选；拒不盖章无后果。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、证号、部位用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：双名义四证核验；直接初始登记；与 `隐名参建联建·审查` 切开；不把全部联建写进一句；民事与行政资质分账；税务失败分担与发票双开；对抗执行不得保证。

## 9. 谈判与签署提醒

谈判顺序：先红线（单名义硬留、二次过户主路径、查封地硬上、保证对抗执行、假批文、规避限购或未达投资额转让），再必须改（双名义闭环、直接登记用语、分房特定化、税务预案、发票、政策备选），最后可优化。

签署提醒：双方法人公章与法定代表人签；资质证书、土地证、红线图、分配明细、政策咨询纪要作附件；先核当地是否仍受理双名义；日期真实。不指导倒签或补假受理。

投资方立场可建议预告登记、印章托管、每证双名称核验，但必须同时写明：未完成登记不得当成已取得所有权；联建手续不保证排除执行。出地方立场必须提示：拒不盖章会锁死报建，查封责任可能按市场价赔偿。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、确权或执行异议文书、税额精算终局或效力保证。
