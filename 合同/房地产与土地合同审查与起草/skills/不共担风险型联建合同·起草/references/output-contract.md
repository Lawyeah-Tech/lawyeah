# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、不被穿透、对方接受或必然过户；编造未给出的价格、利率、面积、税额、证号；把已失效《合同法》、1990 年联营解释“企业间借贷一律无效”、2005 年土地使用权解释旧条号写入结论；按共担风险联建改完。

## 1. 触发、单方立场与成果状态

立场（出地方或出资方/操盘方）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。真共担转 `共担风险型联建合同·审查`。已成争转争议。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1990 年联营解释无效论、或 2005 年解释旧第 24–27 条号时记噪声，不得写入 `L#`。现行穿透条号必须是 2020 年修正后的第 21–24 条。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `不共担风险型联建合同`。定性理由必须写清：哪一方不承担经营风险、固定利益形态、为何不是共担风险联建。

易混切开结果必须点名是否排除：`共担风险型联建合同·审查`、无联建外观的纯转让/纯借款/纯买卖、出资或操盘维度原子。

**穿透表（必填）**：

| 不担风险方 | 固定利益形态 | 条文（运行时复核） | 真实性质 | 不得再按联建处理的事项 |
| --- | --- | --- | --- | --- |
| 出地方 / 出资方 / 依据不足 | 固定货币 / 固定房屋 / 固定利益 / 使用权 / 未写清 | 第 21 / 22 / 23 / 24 条 | 土地使用权转让 / 房屋买卖 / 借款 / 房屋租赁 | 开发资质、利润分成、共担亏损空话 |

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库“加共担条款即可合规”不得执行。挂靠、规避转让/预售/金融特许写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、土地使用权人、出资方、收款/还款名、发票名、授权签字人、担保人或让与担保权利人。名称不一致不自动合并。

穿透后二次核验：

- 转让：出地方是否有处分权；国资/集体是否决议和评估。
- 借款：资金来源；是否疑似职业放贷或转贷。
- 买卖：开发/销售主体与预售证主体是否同一。
- 租赁：出租人是否有权处分房屋。

版本表：正文、补充协议、保底确认函、股东会决议、土地/房屋清单、沟通记录。冲突并列，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定回答，缺项标 `G#`，不补商业数字：

- 不担风险方与固定利益是否锁定到可执行（金额/面积或套数/位置/租期）
- 土地：出让或划拨、证号或 `G#`、四至、用途、终止日期
- 抵押、查封、在建工程抵押：已披露 / 未披露 / 依据不足
- 投资是否达到开发投资总额 25%（仅作出让地转让过户条件，不写成效力定论）
- 分房时：预售许可是否覆盖拟分房屋
- 借款时：本金、期限、利率或保底、还款账户、是否预扣利息
- 税款：谁承担因定性改变可能发生的土增税、契税、增值税、所得税；有无预提安排
- 对外：内部风险转移是否声明不对抗第三人
- 批准、登记、过户、预售许可写成生效条件或期限，不写成已经完成

## 6. 格式条款与强制规范

是否构成格式条款；联建空话 + 保底附件是否提示说明。强制规范只区分是否导致民事行为无效。未达 25%、未办过户、未备案：原则上走行政/履行障碍，不一律无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型默认应出现（有事实则单列，无事实则在缺口节说明未检出）：固定回报未穿透、与共担条款互相冲突、25%/划拨过户障碍、权利负担、利率或职业放贷、无证分房、税负承担空白、内部免责对抗第三人。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`，不编造。

修改句必须服务于**已穿透的真实性质**。禁止建议句写成：按比例分担亏损、设立联合管委会共签、取消保底改为分红——除非用户已确认改类型并已转出本任务。

## 9. 谈判与签署提醒

谈判顺序：先红线（规避监管、无证分房、职业放贷、隐匿抵押/查封），再必须改（穿透落句、固定利益可执行、税款、25%/批准条件、利率上限），最后可优化。

签署提醒：土地/房屋权属与负担查询；国资决议和评估；固定利益数字与支付时点书面锁定；不倒签；不指导先付款后补批准或补预售证。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、效力保证，也不是共担风险型联建文本。
