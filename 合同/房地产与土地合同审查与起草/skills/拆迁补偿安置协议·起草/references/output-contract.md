# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证协议有效、对方接受、必然可执行或唯一必得补偿额；编造未给出的面积、单价、文号、搬迁日；把已失效《合同法》及其解释、2001 年《城市房屋拆迁管理条例》写入结论；把“复合型承揽”“项目公司当然是征收主体”“一律民事故可仲裁”写成已核验；把拆迁委托、一级开发、村企合作或商品房买卖留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（征收／补偿方或被征收／被拆迁人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明土地性质（国有／集体／未知）以及是否夹带委托实施或商品房买卖条款。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2001 年拆迁条例、1991 年实施条例同号旧义、已废止征收土地公告办法、1989 年行政诉讼法第十二条不受理清单时记噪声，不得写入 `L#`。征收主体、补偿项目、先补偿后搬迁、禁止逼迁、行政协议与仲裁无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `拆迁补偿安置协议`。定性理由必须同时满足：对价是腾退换补偿安置；相对方是权属人或公房承租人；不是实施单位委托本约。易混切开：拆迁委托、一级开发、村企合作、商品房买卖、资金监管、实施主体监管。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `意向合作）。禁止打开上述method当本类型主路径。禁止抄` method。挂靠、伪造征收决定、逼迁或建设单位参与搬迁写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：征收部门或组织实施的政府、实施单位或项目公司、被补偿人、公房承租人、共有人、见证村集体、付款名、授权签字人。名称与证件不一致不自动合并。

版本表：正文、测绘报告、补偿明细表、选房确认单、征收决定或补偿方案、家庭成员声明、授权委托、聊天确认。冲突并列，不选对用户有利的一版。口头“指挥部同意了”不得写成已授权。

## 5. 补偿安置给付闭环

分列并回链文本位置：

- 标的：坐落、结构、合法／现状／补偿计算面积、附属物。
- 主体：征收部门或书面委托、权属与共有。
- 方式：货币或产权调换／安置房；选择权是否被单方取消。
- 项目：国有三项加补助奖励，或集体土地法定项目；支付期限；评估时点。
- 安置：回迁地块或就近地段、户型、面积、差价、交付标准。
- 搬迁：期限；先补偿后搬迁；临迁费起止（至实际交付）。
- 负担：抵押、查封、租赁清退。
- 生效：签字成立 vs 征收决定／方案／签约率成就后生效。

缺口标 `G#`，不补商业数字、文号或已批准事实。批准、评估、登记写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

补偿方预先拟定且未协商的免责、取消选择权、单方解释权、管辖或仲裁，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：无权主体冒充征收机关；先搬后补；停水电或建设单位参与搬迁；自行强制拆除；一口价吞掉法定项目；虚假征收决定。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“未附征收决定一律整约无效”或“拆迁补偿安置协议当然是／当然不是行政协议”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：征收主体或书面委托未闭合；补偿项目缺项或一口价；面积混用；回迁地块真空；先搬后补；逼迁或建设单位搬迁；共有人未签；方案背离；仲裁条款与行政协议路径冲突；签约率失效无清理。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、文号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：征收部门或书面委托作附件且主体不适格不生效；补偿项目分列；删除一口价吞项；先补偿后搬迁；删除逼迁；行政协议路径下改仲裁；共有人本人签。

## 9. 谈判与签署提醒

谈判顺序：先红线（无权主体、假征收决定、先搬后补、停水电、建设单位搬迁、一口价吞法定项目），再必须改（项目分列、回迁地块、临迁费至交付、共有人签署、争议路径），最后可优化（监管账户、先签先选房、进度通报、首次登记税费）。

签署提醒：征收部门或持书面委托的签字人签；被补偿人及共有人亲笔签字并按指印；测绘、明细、选房单、方案作附件；日期真实。不指导倒签或补假批准。

征收／补偿方立场可坚持方案统一和签约率条件，但必须保留法定补偿项目和先补偿后搬迁。被征收人立场必须提示：主体或方案未闭合时签字可能难以请求法定项目外承诺；构成行政协议时，合法变更解除的补偿也可能低于民事预期。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、行政复议或行政诉讼文书、补偿精算终局或效力保证。
