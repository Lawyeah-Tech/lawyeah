# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然过户或必然排除执行；编造未给出的出资、面积、税费；把已失效《合同法》《物权法》或《联营解答》写入结论；把投资方写成共有物权人、准物权人或预售出卖人；把双名义显名联建或固定回报借款当成已完成的本类型审查；写“先卖后补预售许可”或“借款合同作为资金输出名义”的可履行路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查参建模式联建合同（隐名开发模式）（房地产合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《物权法》或其解释、已失效《联营解答》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `参建模式联建合同（隐名开发模式）`。定性理由、易混切开结果（显名联建 / 不共担风险 / 借款 / 委托代建 / 土地使用权转让 / 商品房买卖 / 隐名合伙）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、单一名义、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。单一名义表：立项、施工许可、预售许可、对外销售的名义人。资质与权证：出地方土地使用权、开发资质、出让合同限制。版本表：正文、二次过户方案、模拟成本、抵押/质押、共管账户、聊天确认；冲突并列。

## 5. 物权定位、销售资格、二次确权与资金

投资方是合同债权人还是被误写成物权人；销售资格是否只在出地方；二次确权步骤是否完整；税费分担；共担亏损还是固定回报；共管账户。缺口标 `G#`。不输出显名联建双名义口径，不输出投资方对外卖房口径。

## 6. 格式条款、强制规范与对抗第三人

是否构成格式条款。内部协议不得写成已对抗出地方债权人。抵押/预告登记是否具备登记条件。强制规范只按第 153 条和解释第 16 条区分。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把投资方写成首次登记权利人。

## 9. 谈判与签署提醒

谈判顺序：先红线（双名义却要本技能放行、投资方对外卖房或首次登记、固定回报、保证排除执行、未达条件变相转地），再必须改（单一名义、亏损分担、二次确权与税费、共管账户、拟登记担保），最后可优化。签署提醒：授权、对外印章共管、日期、附件清单、出地方权证与资质复印件。不指导倒签或先卖后补证。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是显名联建、借款或商品房买卖本约审查。
