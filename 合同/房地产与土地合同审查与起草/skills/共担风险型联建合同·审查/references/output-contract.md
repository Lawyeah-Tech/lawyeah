# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的出资额、面积、地价、分成；把已失效《合同法》、1990 年联营解答、2005 年解释旧条号、已删除的解释原第十六条写入结论；把固定回报化妆成共担；把不共担、代建或合作开发文本当成已完成的本类型审查；把特定化部位写成必然对抗执行。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查共担风险型联建合同（房地产合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1990 年联营解答、2005 年解释旧第十二条或旧第十六条、1992 年划拨办法时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `共担风险型联建合同`。定性理由、易混切开结果（不共担风险型联建 / 固定回报穿透 / 代建 / 土地使用权合作开发 / 出资结构或操盘子型 / 转让 / 买卖 / 租赁）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `不共担风险型联建合同·审查` 或其他邻类 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、土地、资质、组织模式与文本版本

主体表：签约名、履行名、土地权利人、项目公司名（如有）、销售/报建主体、付款名、发票名、授权签字人。土地表：宗地号、用途、容积率、出让/划拨、抵押查封、闲置与欠缴出让金。资质表：哪一方或项目公司持有房地产开发经营资质。组织模式：契约制联建或公司制。版本表：正文、成本预算书、分房/收益分配明细、土地红线图、资金监管协议、聊天确认；冲突并列。

## 5. 亏损共担、固定回报切开与分配清算

超支追加比例；最终审计亏损分担；过错额外支出除外；有无固定回报、保底、无论盈亏必付；分房附图或分钱成本口径；使用权年限是否超过二十年；联管会或双签；共管账户与土增税保证金。缺口标 `G#`。命中固定回报或不担亏损的，写清转出原子，不在本节写成已审完的共担风险型联建。

## 6. 程序、格式条款与强制规范

内部决议或村民代表大会决议、划拨转出让、报建名义、预售许可、开竣工与闲置。是否构成格式条款；提示说明痕迹。限额与除外（人身损害、故意或重大过失不得排除）。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“固定回报 / 保底利润 / 无论盈亏”改成可履行假共担，不得把特定化部位写成必然对抗执行。

## 9. 谈判与签署提醒

谈判顺序：先红线（固定回报假共担、不共担/代建整案误入、无亏损分担、挂靠或规避限购、倒签），再必须改（亏损共担落句、资质与土地程序、超支追加、分配与税务保证金、联管会双签、共管账户、使用权年限），最后可优化。签署提醒：授权、用印、日期、成本预算书/分房明细/土地红线图作为附件、审批是否作为生效条件。不指导倒签或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是不共担风险型联建、代建或借款安排。
