# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、保证中选实施主体或必然可执行；编造未给出的金额、期限、通过率；把已失效《合同法》《加工承揽合同条例》或《城市房屋拆迁管理条例》写入结论；输出诉讼请求或胜率；把本约改成可履行的实施主体锁定或招商操纵；把服务费改成投资款后放行。

## 1. 触发、单方立场与成果状态

立场（村集体或前期服务公司）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查城市更新项目前期服务合同（房地产合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《加工承揽合同条例》《城市房屋拆迁管理条例》《民法通则》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `城市更新项目前期服务合同`。定性理由、易混切开结果（尤其与 `城更合作（开发商与前期服务）·审查` 开发商合作、`城更股权合作·审查` 股权合作、`城更合作（村集体与企业）·审查` 村企合作、`意向合作）。禁止打开上述method当本类型主路径。禁止抄` 拆迁委托、`拆迁委托）或` 咨询的切开）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、资格与文本版本

主体表：村集体签约名、登记或代行依据、理事长/社长、服务公司名称、付款名、收款名。资格闸：成员大会或成员代表大会决议、会议记录、街道/镇备案、服务商地方准入是否见到。版本表：正文、项目范围图、服务清单、表决决议、聊天确认；冲突并列，集体同意以决议书为准。

## 5. 给付闭环与风险负担

服务四项：意愿征集、摸底测绘、方案编制、招商组织。对价：阶段服务费，不得写成投资款。支付：后续中选企业承接 + 落空安排。保证金：共管账户与退还节点。退出：政策关闸 / 招商失败两列。缺口标 `G#`。

## 6. 强制规范与规避结构

当然实施主体、保证中选、干预投标、伪造表决、阴阳合同、服务费伪装投资、保证金进个人账户、核心工作转包、违法处理村民个人信息。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和删除句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架“终止后成果一律归村”改成已付款前后不分；不得把保证中选改成排他招商门槛。

## 9. 谈判与签署提醒

谈判顺序：先红线（当然实施主体、保证中选、投资款伪装、伪造表决、阴阳合同、保证金个人账户、干预投标），再必须改（决议附件、服务四项、服务费落空、排他期、转包、个人信息、成本上限），最后可优化。签署提醒：决议书、会议记录、范围图、服务清单、共管账户。不指导倒签、补假决议或买票。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、合作/股权审查、拆迁委托审查、咨询审查、诉讼或仲裁文书、效力保证。
