# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、比例、工期；把已失效《合同法》及其解释、民法通则联营条文或 1990 联营解答写入结论；保证必然过规划或预售；把一方操盘、不共担风险或隐名参建当成已完成的本类型审查；写“起诉前补资质所以现在可以签”；写“可诉请解散公司即已解决僵局”。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查联合操盘型联建合同（房地产合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、民法通则联营条文或 1990 联营解答时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `房地产合同`，子级 `联合操盘型联建合同`。定性理由、易混切开结果（一方操盘 / 不共担风险 / 笼统共担 / 联建模式 / 隐名参建）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `一方操盘型联建合同·审查` 的 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、资质、项目公司与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、项目公司。资质表：哪一方或项目公司持有开发资质、等级与有效期是否被材料提及。版本表：正文、股东协议、权责清单、财务／印章制度、品牌协议、聊天确认；冲突并列。

## 5. 联席、双签、僵局与给付闭环

联管会组成与表决；重大事项清单；资金双签与共管账户；印章交叉共管；僵局时限、升级与退出；同比例出资；分配与共担；RACI／首问责任；联合验收。缺口标 `G#`。不输出单方最终决定权口径，不输出“解散公司即退出”。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。挂靠、违法分包、规避限购不得写成可放行。强制规范只按第 153 条和合同编通则解释第 16 条区分，不用失效口诀。双方均无资质：效力字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。必须盯死：共同管理权 vs 监督权；双签 vs 单方用印；僵局退出 vs 只写协商。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为一方操盘或固定回报、无双签且单方管章管钱、一致决无退出、挂靠／无资质报建），再必须改（联管会、重大事项清单、双签时限、RACI、不配合签字违约、擅自行动责任），最后可优化。签署提醒：授权、联管会成员委托书、预留印鉴、首期共管到账、附件清单。不指导倒签或先交章后补决议。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是一方操盘、不共担风险或隐名参建安排。
