# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然过户或必然取得规划许可；编造未给出的投资额、分成、期限、面积；把已失效《合同法》《物权法》《房屋登记办法》、1986／2004 年土地管理法旧条、1991 年实施条例写入结论；把合作方写成已取得宅基地使用权；把买卖、租赁、房地产合作开发或集体建设用地合作开发当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查宅基地合作开发合同（土地使用权）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、物权法、房屋登记办法、1986／2004 年土地管理法旧条、1991 年实施条例、2007 年未修正城乡规划法单独文本时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `土地使用权`，子级 `宅基地合作开发合同`。定性理由、易混切开结果（内部买卖 / 对外买断 / 租赁或委托运营 / 房地产合作开发 / 集体建设用地合作开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、成员资格、共有人与文本版本

主体表：签约名、出地方／证载权利人、户内共有人、合作方、付款名、发票名、集体组织或村委会（参与方或监管方）。成员资格：成员名册、户籍、权利义务关系是否闭合。版本表：正文、权属证书、家庭成员同意书、集体书面意见、设计图纸、投资概算、规划许可或翻建申请、聊天确认；冲突并列。

## 5. 给付闭环：共建、经营权、期限、征收

地块是否宅基地；是否约定过户或永久使用；出资与建设分工；报建是否以农户名义；规划许可／乡镇审批写成条件还是已完成；合作期限与期满残值；经营收益或分层使用如何分；征收补偿如何切；户口迁出或身份丧失如何承接。缺口标 `G#`。不输出“签字即过户”，不输出对外买断可履行路径，不把整约改写成租赁或国有出让地分房。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。对外买断、占永久基本农田、无证超建、施工资质挂靠不得写成可放行。强制规范只按第一百五十三条和合同编通则解释第十六、十八条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“另行协商”留在过户、永久使用或征收切分上。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为买卖或租赁、对外过户或永久买断、占永久基本农田、无证超建、拒写成员资格或共有人同意），再必须改（报建主体、规划许可条件、集体书面意见、征收与身份丧失、期满残值），最后可优化。签署提醒：户内共有人到场或书面同意、集体书面意见作为附件、权属证书与图纸一致、日期与许可申请不倒签。不指导伪造成员名册或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是买卖、租赁、房地产合作开发或集体建设用地合作开发安排。
