# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的份额、金额、期限；把已失效《婚姻法》及其解释、《合同法》《物权法》、1989 年同居意见写入结论；把同居写成视同夫妻共同财产；把签字日写成已经取得物权；把未登记写成可对抗善意第三人；把分手费写成必然可强制执行；把赠与过户前写成已经不可撤销；把夫妻财产约定、分手协议或赠与当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标、双方婚姻状况。负触发写路由，不启动实体审查。写明中文成果名称是「审查同居财产约定（婚姻家庭）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《婚姻法》及其解释、《合同法》《物权法》、1989 年同居意见时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `婚姻家庭`，子级 `同居财产约定`。定性理由、易混切开结果（夫妻财产约定、分手协议、赠与、离婚协议、分居协议、分家析产）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、婚姻状况与文本版本

主体表：签字人、身份证号痕迹、经常居住地、是否主张无配偶。资格表：完全民事行为能力痕迹。版本表：正文、初始财产清单、购房或转账凭证、产证、聊天确认；冲突并列。婚姻状况未核：对外效力和公序良俗字段停止。

## 5. 给付闭环：归属、开支、债务、登记

核心给付是否仅为同居存续期归属与开支分担；是否夹带分手结算或无偿给予；各自所得 / 共同出资 / 共同经营是否切开；钱款性质（资助 / 借款 / 赠与 / 共同投资）；登记现状与加名义务；合同生效与物权变动是否拆开；个人债务防火墙。缺口标 `G#`。不输出夫妻共同财产推定、离婚经济补偿或第 1065 条对外效力主路径。

## 6. 公序良俗、格式条款与强制规范

是否一方有配偶；补偿或分手费是否背离家庭伦理；是否排除诉权。是否构成格式条款。强制规范只按第 153 条、合同编通则解释第 16、17 条区分。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的数字用 `【待填】`。不得把框架里的“自动转化成夫妻财产约定即有对外效力”或“分手费必然可执行”写成建议句。

## 9. 谈判与签署提醒

谈判顺序：先红线（婚姻财产制错位、分手协议/赠与主轴、婚外补偿、签字即对抗第三人），再必须改（财产分层、钱款性质、登记期限、债务个人承担、解除认定标准、结婚后是否另签），最后可优化。签署提醒：双方亲笔签名按指印；建议无利害关系见证人或律师见证；初始财产清单、出资凭证、共同账户规则入附件。不指导倒签或补假无配偶声明。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是夫妻财产约定、分手协议或赠与审查。
