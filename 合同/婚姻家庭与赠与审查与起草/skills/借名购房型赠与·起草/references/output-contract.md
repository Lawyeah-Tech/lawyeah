# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然更名；编造未给出的房价、税负、日期；把已失效《合同法》《物权法》写入结论；把支付首付写成房屋权利已转移；把未公证的“不可撤销”写成已经关闭第 658 条；把商品房买卖本约或让与担保当成已完成的本类型审查；把撤销赠与写成开发商或银行必须改名；把规避限购改成可履行路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查“以他人名称购房并支付房款” 型赠与合同（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《物权法》、或把商品房买卖解释／担保制度解释当作本类型主规则时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `“以他人名称购房并支付房款” 型赠与合同`。定性理由、易混切开结果（商品房买卖 / 让与担保 / 房屋借名 / 一般赠与 / 公益赠与 / 婚家赠与 / 无对价财产转移 / 借款）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、付款、资格与文本版本

主体表：出资人（赠与人）、名义购房人（受赠人）、开发商／卖方（知情非当事人）、贷款银行（知情非当事人）、配偶。付款表：首付、节点款、月供、装修、契税的支付人与附言。资格表：名义人限购或信贷资质。版本表：确认书正文、购房合同、网签、贷款合同、付款回单、聊天确认、配偶同意、公证申请；冲突并列。

## 5. 给付闭环：借名外观认定、房屋／金钱分轨、658、贷款分离

三选一是否写死；借名外观是否被误写成已成立房屋赠与；房屋权益盯登记、金钱盯到账是否拆开；各笔资金是否分项；658 窗口是否被付款或无公证条款虚假关闭；公证对象是否为本确认书；撤销后更名／退房是否只写成努力义务并配金钱清算。缺口标 `G#`。不输出“付款即给房”，不输出“撤销后开发商必须改名”。

## 6. 格式条款、强制规范、538 与限购

是否构成格式条款；提示说明痕迹。538 逃债、规避限购或信贷不得写成可放行。强制规范只按第 153 条区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把对开发商或银行的内部安排写成命令。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为买卖本约、让与担保或借名留房、代持／赠与混写、付款即给房、规避限购、撤销写成第三人必须改名），再必须改（三选一、资金分项、登记／到账节点、658 窗口、配偶加签、贷款清算），最后可优化。签署提醒：出资人与名义人双方到场、配偶视财产属性加签、确认书日期覆盖已发生付款或写追认、附件含购房合同和付款回单、公证申请如要关闭 658。不指导倒签或先网签后补定性。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是商品房买卖、让与担保或借名留房安排。
