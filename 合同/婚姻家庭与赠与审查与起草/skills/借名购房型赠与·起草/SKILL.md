# 借名购房型赠与·起草

## 任务目标

在单一立场下，只按已谈妥条件起草 **赠与合同 / “以他人名称购房并支付房款” 型赠与合同**，输出可编辑草稿、未决项，并在出稿后用本类型硬闸自审。借名买房只告知，不改成可履行规避。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。中文名必须是「审查“以他人名称购房并支付房款” 型赠与合同（赠与合同）」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证必然更名或任意撤销必然消灭。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **借名购房出资外观下的赠与认定**：本类型的外观就是“我出钱、写他的名去买房”。同一份文件必须三选一写死——赠与房屋权益、赠与已付资金、借名代持。选择赠与才留本技能。出现“房屋实际归出资人”“先用你的名、以后转回”：负触发，转 本套导航的类型切开步骤 重新定性，不按第 658 条改完。没有书面三选一时，判断写 `依据不足`，不得推定房屋赠与已经成立。
2. **限购规避只告知**：用他人名义购房规避限购、信贷或购房资格：只告知名实不符和行政风险，民事返还与行政违法拆开，不改写成可履行借名或假赠与。用户坚持“改到能签且仍规避”：整体停止。
3. **不得按商品房买卖或让与担保改完**：要审开发商预售／现售本约 → 负触发 `真实房屋买卖，买受人取得所有权`。文本写到期还本、回购、担保债权、流质或“先过户再还钱把房拿回” → 负触发 `文本写到期还本回购担保债权流质或“先过户再还钱把房拿回”→负触发`。本任务只审出资人与名义购房人之间的内部确认。撤销赠与不等于自动改网签。禁止打开或复制 `真实房屋买卖，买受人取得所有权`、`文本写到期还本回购担保债权流质或“先过户再还钱把房拿回”→负触发` method。
4. **必须出修改句**：每个风险回链文本位置，并给出可回给对方的修改句或明确停笔口径。

## 工作边界

正触发：已有可读待签出资赠与确认书或同等文本，尚未签署，尚未成争，核心给付是以他人名义购房并付款且拟确认无偿给予名义人房屋权益或已付资金，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 开发商／卖方买卖本约、认购书要按商品房审 → `真实房屋买卖，买受人取得所有权`；
- 名买卖实担保、回购还本、流质 → `文本写到期还本回购担保债权流质或“先过户再还钱把房拿回”→负触发`；
- 存量房买卖、卖方是原登记权利人且有房价 → `或`；
- 约定房屋实际归出资人、登记人仅出名 → 转引擎重新定性（房屋借名），不按本类型赠与改完；
- 标的是现金或动产，与名购房结构无关 → `一般赠与合同·审查`；
- 救灾、扶贫、助残等公益、道德义务是主线 → `公益道德义务性质的赠与合同·审查`；
- 近亲属或家庭内部，主线是赡养、只赠一方、婚内加名 → `婚姻家庭中的赠与合同·审查` 或 `亲属间房屋赠与合同·审查`；
- 不直接支付对价的其他财产转移，不是“以他人名称购房并付款” → `无对价财产转移赠与·审查`；
- 出资人已有房屋再过户给对方 → `房产赠与合同·审查`；
- 出资人只要还钱、不主张房屋 → `或` 或 `或`；
- 死后生效 → `生前类赠与协议·审查`；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁 → `已催告解除索赔诉讼或仲裁→` 或对应专项。

挂靠、违法分包、规避限购、规避信贷资质：只出告知，不改写成可履行结构。

禁止打开 `真实房屋买卖，买受人取得所有权`、`文本写到期还本回购担保债权流质或“先过户再还钱把房拿回”→负触发`、`一般赠与合同·审查`、`公益道德义务性质的赠与合同·审查`、`婚姻家庭中的赠与合同·审查`、`无对价财产转移赠与·审查` 的 method。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及购房合同／网签／贷款／付款回单／聊天确认版本；三选一定性；标的是房屋权益还是金钱；网签与登记状态；首付、月供、装修、契税各笔性质；是否公证及公证对象；是否存在回购、还本或担保外观；出资是否共同财产及配偶是否签署；名义人购房资格与限购信号；赠与人负债；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

## 起草模式

本原子只承担本类型起草。待签评改转 `借名购房型赠与·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务起草并自审。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。商业数字未给用 `【待填】`，不编造。出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。他类型出稿、已签履约、已成争：仍负触发。

借名买房只告知，不改成可履行规避。出现“房屋实际归出资人”“先用你的名、以后转回”：负触发重新定性，不按第 658 条改完。规避限购、信贷或购房资格：只告知名实不符和行政风险，不起可履行借名或假赠与稿。

### 起草必写

- 同一份文件必须三选一写死——赠与房屋权益、赠与已付资金、借名代持。选择赠与才留本技能。没有书面三选一时，判断写 `依据不足`，不得推定房屋赠与已经成立。
- 写清项目、房号、买卖合同编号、已付未付。房屋权益盯登记，金钱盯到账。首付、月供、装修、契税分项。
- 关闭任意撤销须公证**本赠与确认**，仅公证购房合同不够。
- 银行未同意前不得承诺必然更名。撤销后更名是努力义务，不能更名则金钱清算。撤销赠与不等于自动改网签。

### 附件必附

- 书面三选一定性。无此书面选择不得出房屋赠与已成立稿。
- 购房合同与付款回单用于标的和资金分项，不按商品房买卖本约改完。缺金额、期限、税负用 `【待填】`。

### 禁止出现

- “房屋实际归出资人”“先用你的名、以后转回”仍按本类型赠与出可履行稿。
- 把规避限购、信贷或购房资格改成可履行借名或假赠与。
- 按商品房买卖或让与担保改完本确认书。
- “支付首付即房屋赠与完成”。
- 把撤销写成开发商或银行必须改名。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → 本任务起草模式；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有本类型确认书，才进入本任务。

### 1. 借名外观下的赠与认定

标题、核心给付与三选一定性一致才继续。买卖本约、让与担保、借名留房、一般赠与、公益赠与、婚家赠与、无对价财产转移负触发。

### 2. 限购规避停笔

只告知，不改可履行。

### 3. 主体与共同财产

出资人、名义购房人双方必须签。开发商、银行可列为知情方，不是赠与当事人。用夫妻共同财产须配偶签署。

### 4. 标的分轨与付款分项

写清项目、房号、买卖合同编号、已付未付。房屋权益／预售权益／金钱三选一。首付、月供、装修、契税分项。禁止“支付首付即房屋赠与完成”。

### 5. 登记节点、658 与公证对象

房屋权益盯登记；金钱盯到账。关闭任意撤销须公证**本赠与确认**，仅公证购房合同不够。

### 6. 贷款分离与撤销落地

银行未同意前不得承诺必然更名。撤销后更名是努力义务，不能更名则金钱清算。

### 7. 538、法定撤销与穷困

538 只告知。666 针对尚未支付的后续房款或未完成金钱赠与。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把付款写成房屋权利已转移、把代持与赠与混写放行、把规避限购改成可履行、未公证却保证 658 消灭、把撤销写成开发商必须改名、按商品房买卖或让与担保改完。
- `字段停止`：法域、动态规则、限购细则、税负精确额、银行／开发商是否同意、共同财产未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
