# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然过户或必然免税；编造未给出的期限、份额、税额；把已失效《合同法》赠与章或《房屋登记办法》写入结论；把交钥匙写成已经赠与完成；把亲属身份写成当然消灭第 658 条；把未核共有写成可以过户；把无偿受赠人写成善意取得；把假买卖/避债改成可履行结构；把一般赠与、非亲属房产赠与或买卖当成已完成的本类型审查；把商品房五证清单做成主路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查亲属间房屋赠与合同（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》赠与章或其解释、已失效《物权法》、已失效《房屋登记办法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `亲属间房屋赠与合同`。定性理由、易混切开结果（一般赠与、房产赠与、商品房买卖、二手房买卖、析产、遗赠）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、共有人与文本版本

主体表：赠与人（登记权利人）、受赠人、配偶、其他共有人、代签人。资格表：亲属关系证明痕迹、意思能力核实痕迹。版本表：正文、权属证、配偶同意书、居住权稿、聊天确认；冲突并列。未核共有或登记簿：该签署能力字段停止。

## 5. 房屋、过户、公证与无偿性

房屋是否特定到可登记；权利负担是否书面披露；过户责任方、期限与材料；占有交付是否与登记切开；是否公证；658 表述是否把亲属身份当成道德义务；是否夹带价款。缺口标 `G#`。不输出商品房五证或买卖网签主路径。

## 6. 撤销、居住权、税费、格式条款与强制规范

任意撤销、法定撤销、继承人撤销、穷困抗辩分列。唯一住房是否设居住权。契税承担与第 6 条免税范围（夫妻变更、法定继承，不含父母赠子女）。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分。假买卖/避债/限购只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的期限、份额用 `【待填】`。不得把亲属身份写成当然道德义务，不得把“其他子女不得有异议”写成已约束未签字人。

## 9. 谈判与签署提醒

谈判顺序：先红线（共有人未签、假买卖/避债、交钥匙即完成拒改、唯一住房无居住权），再必须改（过户期限、658/公证、权属披露、税费），最后可优化。签署提醒：全体共有人签字按手印；高龄人建议公证处核实身份；权属证、亲属关系证明、配偶同意书、居住权合同、银行书面意见入附件；签署日与递件日分开。不指导倒签或补假同意。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是一般赠与、非亲属房产赠与或买卖本约审查。
