# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然过户；编造未给出的面积、税负、日期；把已失效《合同法》《物权法》及失效契税暂行条例写入结论；把交钥匙写成已经取得物权；把未公证的“不可撤销”写成已经关闭第 658 条；把亲属房屋或买卖文本当成已完成的本类型审查；写“过户完成后本合同生效”；把逃债或规避限购改成可履行路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查房产赠与合同（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《物权法》、已失效契税暂行条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `房产赠与合同`。定性理由、易混切开结果（亲属间房屋赠与 / 买卖 / 一般赠与 / 附义务赠与 / 夫妻财产约定 / 分家析产 / 遗赠）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属、资格与文本版本

主体表：签约名、登记簿权利人、受赠人证件、授权签字人、共有人或机关决议。权属表：坐落、单元号、面积、用途、土地使用权、抵押查封租赁居住权。资格表：限购、境外个人、农村房屋或经适房封闭期。版本表：正文、权属证、共有人同意、决议、租赁、居住权、完税安排、聊天确认；冲突并列。

## 5. 给付闭环：无偿、登记、占有、税费

无偿性是否被对价句击穿；申请登记的责任方、期限、材料；交付占有与物权变动是否拆开；658 窗口是否被无公证条款虚假关闭；税种承担表；资格不成就的解除。缺口标 `G#`。不输出“交房即完成”，不输出“未公证也不可撤销”。

## 6. 格式条款、强制规范、538 与限购

是否构成格式条款；提示说明痕迹。538 逃债、规避限购或封闭期不得写成可放行。强制规范只按第 153 条和合同编通则解释第 16 条区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把占有交付直接写成所有权转移。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为买卖或亲属房屋、交房即完成、未公证排除 658、逃债或规避限购、共有人未签仍递件），再必须改（房屋特定化、登记期限、税费表、资格先决、居住权、户口），最后可优化。签署提醒：全体权利人到场或授权原件、权属证、完税安排、公证或当日递件、签署日/交付日/申请登记日三列。不指导倒签或先过户后补税。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是亲属房屋赠与、买卖或遗赠安排。
