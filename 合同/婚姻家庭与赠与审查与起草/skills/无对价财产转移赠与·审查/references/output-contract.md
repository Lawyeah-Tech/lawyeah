# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、保证必然不是赠与、对方接受或必然可执行；编造未给出的价格、投入额、本金、利率、数量；把已失效《合同法》及其解释写入结论；把空否认句写成已关闭第 658 条；把第 538 条改成可排除；把流质改成赠与完成；把名赠与实借贷或让与担保整案留在本技能按赠与改完。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。成果名称写「审查“不直接支付对价的财产转移” 型赠与合同（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《物权法》、已失效《担保法》及其解释时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级、子级、定性理由、易混切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `一般赠与合同·审查`、`公益道德义务性质的赠与合同·审查`、`零对价股权赠与·审查`、`借名购房型赠与·审查`、`文本写到期还本回购担保债权流质或“先过户再还钱把房拿回”→负触发` 或 `的method。` method。逃债、国资违规无偿、规避限购、流质改赠与写停笔告知，不填可履行结构。

## 4. 主体、授权、原因关系人与文本版本

主体表：签约名、履行名、登记 / 占有名、原因关系中的债权人、投资人或出借人、授权签字人、共有人或担保人。版本表：正文、结算单、代偿 / 出资凭证、借条、回购确认、清单、决议、聊天确认；冲突并列，不选对用户有利的一版。赠与页与借条页并行必须点名。

## 5. 给付闭环与无偿定性

标的清单、数量质量、权利负担、交付 / 验收 / 登记（分列）、对价或零元、隐性对价、原因证据编号、资金流向、回购 / 占用费 / 流质有无、已交 / 未交拆分。缺口标 `G#`，不补商业数字。批准、登记写成条件或期限，不写成已经完成。定性结论只能是：现有依据支持非赠与 / 现有依据支持潜在赠与 / 现有依据支持名赠与实借贷或让与担保（此时应已负触发） / 依据不足，无法形成结论。禁止输出“必然不是赠与”。

## 6. 格式条款、538 与强制规范

是否构成格式条款；提示说明痕迹；异常条款。第 538 条不得排除；第 539 条仅在有价款时点名。流押 / 流质不得改成终局赠与。强制规范只区分是否导致民事行为无效，禁止用已失效“效力性 / 管理性”口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔 / 转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。整案已切到借贷或让与担保的，本节不写赠与改法。

## 9. 谈判与签署提醒

谈判顺序：先红线（赠与定性二选一、名赠与实借贷切开、538、流质），再必须改（原因证据、清单、交付定义），最后可优化。签署提醒：授权、用印、日期、结算与决议附件、条件成就凭证。不指导倒签、补假原因或补假借条。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证。
