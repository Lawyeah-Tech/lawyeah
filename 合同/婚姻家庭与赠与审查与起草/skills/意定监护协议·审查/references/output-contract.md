# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证协议有效、法院必然指定、公证后窗口必然配合或对方接受；编造未给出的报酬、资产范围、日期；把已失效《合同法》《民法总则》《继承法》写入结论；把未公证写成无效；把口头写成已成立意定监护；把医院诊断写成已经完成行为能力宣告；把死后财产归监护人或资格人会签留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（设立人/被监护人、拟任监护人、拟任监督人、拟任后备监护人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在：自己预选监护人、书面文本、以丧失或部分丧失民事行为能力为职责触发。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《民法总则》《继承法》、2002 年《公证程序规则》、已被修改的 2018 年《妇女权益保障法》条文时记噪声，不得写入 `L#`。书面形式、公证是否强制、监护职责与财产处分、失能触发与解除无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `婚姻家庭`，子级 `意定监护协议`。定性理由必须同时满足：设立人是为自己预选监护人的完全行为能力成年人；书面；失能触发职责。易混切开：遗赠扶养、监护权协议、遗嘱、普通委托。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `遗赠扶养协议·审查` 或 `监护权协议·审查` method。胁迫、代签、伪造能力或公证、预先过户规避继承写停笔告知，不填可履行结构。

## 4. 主体、授权、能力与文本版本

主体表：设立人、拟任监护人、监督人、后备监护人。自然人写姓名与证件号是否与文本一致；组织写名称与统一社会信用代码，并标关系（亲友、同事、社会组织）。

版本表：正文、监督确认、医疗预嘱、近半年病历或体检、公证意向、聊天确认。冲突并列，不选对用户有利的一版。口头“已经公证了”“医院已经宣告失能了”“子女都同意了”不得写成已公证、已宣告或已同意。

## 5. 意定监护给付闭环

分列并回链文本位置：

- 书面：合同书还是仅口头/聊天；是否亲笔签名。
- 公证：是否拟办公证；文本是否把公证写成生效要件或“视为已公证”。
- 成立与触发：协议何时成立；职责何时开始；二者是否混成签字即履行。
- 能力认定：医院诊断、鉴定、法院特别程序如何分工；是否允许监护人自行认定。
- 职责：生活照料、医疗决策、财产管理是否分列。
- 财产：日常开支与重大处分是否切开；重大处分是否为被监护人利益并受监督。
- 意愿：是否写明最大程度尊重真实意愿、不干涉有能力独立处理的事务。
- 监督与后备：有无监督人、报告周期、后备顺位。
- 报酬：无偿或有偿；支付来源与复核。
- 解除与撤销：失能前双方可解除；失能后监护人无正当理由不得解除；设立人有完全能力时可书面撤销。
- 死后事务：若出现丧葬代理，是否误写成财产归监护人。

缺口标 `G#`，不补能力、不补已公证、不补监督人已同意。公证、能力宣告写成条件或双方义务，不写成已经完成。

## 6. 强制规范与本类型效力红旗

强制规范与效力红旗只在核验后落法律结论：非书面；签署时无完全行为能力；胁迫、欺诈、恶意串通；监护人除为被监护人利益外处分财产；监护人不履职或侵害权益可被撤销。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“未公证一律无效”或“意定监护具有最高顺位、法院不得再指定他人”写成已核验结论。有效且监护人愿意并能履职时，意定安排优先于法定顺序，但仍受撤销监护和签约时能力审查约束。

机构提供的重复使用文本，可提示格式条款的说明义务，但不把定金、验收节点塞进本类型。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：非书面；公证被写成法定生效或视为已完成；职责未分列或授权过宽；监护人自行认定失能；医院诊断当成能力宣告；重大财产无监督可自由处分；死后财产归监护人；与遗赠扶养或监护权协议混同；无解除/撤销分层；签署时能力无痕迹。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的报酬、资产范围用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：书面亲签；公证建议但不写成生效要件；职责分列；成立与触发分列；能力认定不得自行宣告；重大财产限制与监督；删除死后财产归监护人。

## 9. 谈判与签署提醒

谈判顺序：先红线（非书面、代签、自行认定失能、自由卖房、死后财产归监护人、伪造能力），再必须改（职责分列、触发与认定、监督、解除分层、公证安排），最后可优化（后备、医疗预嘱、报告周期）。

签署提醒：设立人与监护人本人签；建议按指印并同步录音录像或公证；签署日期真实；近半年病历或体检作附件但不代替能力结论；监督人本人确认。不指导倒签、代签或补假公证。

设立人立场必须提示：签字后，一旦失能，监护人将取得人身与财产控制权，无监督则道德风险高。监护人立场必须提示：失能后无正当理由不得解除；侵害权益可被撤销并承担责任；窗口可能仍要求公证或法院指定文书。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、能力宣告申请、公证代办、遗赠扶养或监护权协议整案、效力或指定结果保证。
