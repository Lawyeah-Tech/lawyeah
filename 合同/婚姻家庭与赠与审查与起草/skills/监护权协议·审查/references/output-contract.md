# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、保证居委会／民政／法院必然指定或必然可执行；编造未给出的费用、日期、账户、文号；把已失效民法通则意见、婚姻法解释或合同法写入结论；把第三十三条意定监护或第一千零八十四条直接抚养写成默认路径。

## 1. 触发、单方立场与成果状态

立场必须是拟任监护人、其他资格人、或为被监护人利益行事的近亲属，择一。写授权、签署状态、主要目标。负触发写完整 Skill ID 路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效民法通则及其意见、婚姻法解释、合同法或 2012 年预防未成年人犯罪法同条号时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级：婚姻家庭。子级：监护权协议。定性理由须写清：依法具有监护资格的人之间确定谁担任监护人，而不是本人预授、不是直接抚养安排、不是委托照护伪装转移。易混切开结果必须点名意定监护、抚养权变更、扶养／抚养、离婚协议是否已排除。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。挂靠、违法分包、定金比例与本类型无关，不得写入本节充数。

## 4. 主体、资格顺位、被监护人与文本版本

主体表：各协议人（资格人）姓名与关系、拟任监护人、候补监护人、被监护人、费用分担人。不得把未成年人写成金钱给付义务人或违约金债务人。

资格表：所依据的第二十七条或第二十八条顺位；父母是否死亡、丧失监护能力或仍有能力；是否已被撤销监护资格。父母能力不明则该字段停止。

版本表：正文、附件、意愿谈话或视听记录、户口／诊断材料、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环（监护职责分配）

标的是监护职责，不是财产买卖。写：确定的监护人人选、起止与终止条件、人身照料、教育医疗、财产代管与重大处分核准、费用来源与劳务补偿、定期报告与查阅、候补人选、备案或公证义务。缺口标 `G#`，不补家事数字。备案、公证、认定行为能力、法院确认写成待完成条件或双方义务，不写成已经完成。

## 6. 格式条款与强制规范

亲属个案协议通常不是经营者格式条款；打印店或网上下载的重复使用监护模板仍可能构成格式条款。强制规范审查：免除有能力父母的监护、监护买卖、自由处分被监护人不动产、捆绑继承。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

至少覆盖已出现的硬闸：法定监护不得放弃、儿童利益、与意定监护切开、确定与委托、被监护人意愿、财产与继承捆绑、资格人参与与对外效力。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的金额、日期、账户、文号用 `【待填】`，不编造。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线（父母放弃监护、监护买卖、自由卖房、继承捆绑、伪造意愿），再必须改（意愿痕迹、财产核准、费用来源、候补、资格人列全、对外路径），最后可优化（基层见证、公证、定期报告频率）。

签署提醒：全体参与协商的资格人亲签捺印；八周岁以上或可表达的被监护人签署同意文句，但不因此成为债务人；签署日期与职责起算；附件清单（关系证明、意愿记录、财产清单、费用表）。不要指导倒签或补假意愿。提示：签字不等于指定已经完成，不等于户籍、学籍、银行、医院对外已经变更完毕，不等于已有执行名义。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、意定监护草稿、抚养安排或效力保证。不得承诺法院、民政或基层组织必然指定或确认。
