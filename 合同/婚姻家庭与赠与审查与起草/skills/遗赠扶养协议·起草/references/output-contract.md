# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证协议有效、房屋必然过户或对方接受；编造未给出的证号、金额、探视次数、医疗分担；把已失效《合同法》《继承法》及其意见写入结论；把第 658 条任意撤销写成可适用于本协议；把“另立公证遗嘱即可推翻协议”写成现行规则；把“未经公证无效”写成现行规则；把签约即过户改成可履行；把第一顺序继承人留在本技能改成可履行本类型；把 `附义务的赠与合同·审查` 或 `生前类赠与协议·审查` 整案留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（遗赠人、扶养人个人、扶养组织、拟签字共有人或配偶）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在生养死葬和死后转移，以及扶养人与遗赠人的亲属关系。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《继承法》及其意见、1996／2009 年老年人法同条号旧义、民法通则时记噪声，不得写入 `L#`。主体适格、死后转移、优先效力、解除分侧、共有先析无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `婚姻家庭`，子级 `遗赠扶养协议`。定性理由必须同时满足：双方法律行为；生养死葬；死后转移。易混切开：生前赠与／附义务赠与、遗嘱、遗赠、赡养、机构服务合同。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `附义务的赠与合同·审查` 或 `生前类赠与协议·审查` method。伪造能力、代签、第一顺序规避赡养或即时过户写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：遗赠人、扶养人、配偶／共有人、已知法定继承人、见证人、监督人。自然人写姓名与证件号是否与文本一致；组织写名称与统一社会信用代码。明确双方有无血缘或姻亲，以及是否可能落入第一或第二顺序。

版本表：协议正文、财产清单、扶养标准附件、既有遗嘱、其他扶养协议、权属证明、能力材料、见证／公证草稿、聊天确认。冲突并列，不选对用户有利的一版。口头“老人同意了”“已经过户了”不得写成已同意或已转移。

## 5. 生养死葬与死后财产给付闭环

分列并回链文本位置：

- 对价：鉴于是否锁定生养死葬换死后财产、互为对价、不适用赠与任意撤销。
- 生养：居住、饮食、衣物、医疗分担、护理、探视／精神慰藉的可执行标准。
- 死葬：仪式、地点、费用、安葬方式。
- 遗赠财产：清单、证号、是否个人所有或仅份额、负担。
- 转移时点：是否写明去世后转移；有无“签订即过户”。
- 居住与生前处分：终身居住；不得擅自出售抵押赠与。
- 优先效力：与遗嘱、遗赠、法定继承的关系。
- 解除：事由、程序、分侧费用后果。
- 留痕与监察：凭证保存、第三人监督。

缺口标 `G#`，不补商业数字、证号或已过户事实。公证、登记写成建议或双方义务，不写成已经完成或效力前提。

## 6. 格式条款、强制规范与本类型效力红旗

养老机构或组织预先拟定且未协商的，按格式条款审查提示说明。自然人偶发协商通常不是格式条款。

强制规范与效力红旗只在核验后落法律结论：无民事行为能力；胁迫或危困显失公平；处分他人财产超出份额；第一顺序主体错用；即时转移滑向赠与。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“未经公证无效”或“整份协议因未量化照料而当然无效”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：对价未锁定或义务虚权利实；签订即过户；按赠与任意撤销；与遗嘱混写可随时撤回；第一顺序作扶养人；财产未特定或超份额；无居住保留；无解除分侧；无履行留痕；多份协议冲突。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、证号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：鉴于锁定生养死葬换死后财产；删除即时过户和任意撤销；写入死后转移和协议优先；量化扶养；解除分侧；共有先析。

## 9. 谈判与签署提醒

谈判顺序：先红线（即时过户、第一顺序规避赡养、伪造能力／代签、任意撤销），再必须改（量化扶养、死后转移、优先效力、解除分侧、财产清单），最后可优化。

签署提醒：遗赠人本人签并按指印；能力存疑则医学评估和全程录像；共有人本人签；公证或两名以上无利害关系人见证；日期真实。不指导倒签、代签或补假鉴定。

遗赠人立场必须提示：签字后非经约定或法定事由不得当赠与撤销；子女可能起诉能力或未尽责。扶养人立场必须提示：义务在先、权利在后；遗产可能被生前消耗或超份额无效；未尽责可能既得不到财产也要不回费用。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、确认协议有效诉讼文书、过户申请或效力保证。
