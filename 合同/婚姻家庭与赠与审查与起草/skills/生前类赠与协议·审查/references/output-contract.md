# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或死后必然过户；编造未给出的份额、日期、税负；把已失效《合同法》《继承法》《物权法》写入结论；把签字或交钥匙写成已经取得物权；把赠与公证写成已经关闭第 1142 条撤回；把生前赠与、遗赠扶养或标准遗嘱文本当成已完成的本类型审查；写“签字即生效并办理过户”；把逃债或规避限购改成可履行路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查遗赠协议（生前约定死后过户财产的 “类赠与” 情形）（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《继承法》及其意见、已失效《物权法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `遗赠协议（生前约定死后过户财产的 “类赠与” 情形）`。定性理由、易混切开结果（生前赠与 / 遗赠扶养 / 遗嘱继承 / 分家析产）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开邻类 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、遗产范围、形式与文本版本

主体表：遗嘱人、受遗赠人、是否法定继承人、见证人、执行人或遗产管理人。遗产表：财产特定化、个人份额、负担、是否已做生前赠与。形式表：所选遗嘱形式、签名日期、见证人人数与利害关系。版本表：正文、旧遗嘱、遗赠扶养协议、权属证、聊天确认；冲突并列。

## 5. 给付闭环：死后生效、撤回、六十日、登记原因

生存期间不得请求过户或占有；签字不是物权变动；撤回走第 1142 条而非第 658 条；知道受遗赠后六十日内书面接受；登记原因是继承/受遗赠。缺口标 `G#`。不输出“签字即过户”，不输出“公证后不可撤回”，不输出“签字视为已经接受”。

## 6. 必留份、债务、扶养协议优先与强制规范

必留份、税款债务、与遗赠扶养协议抵触时协议优先。无偿逃债、规避限购不得写成可放行。强制规范只按第 153 条和合同编通则解释第 16 条区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的数字用 `【待填】`。不得把占有交付直接写成所有权转移，不得写入赠与章工具。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为生前赠与或扶养、签字即过户、无遗嘱形式、套用 658、逃债先过户），再必须改（死后生效声明、个人份额、六十日通知、执行人、替补指定），最后可优化。签署提醒：按所选形式完成签名与日期、见证人无利害关系、存放处、不要双方当合同盖章。不指导倒签或人还在先过户。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是生前赠与、遗赠扶养或标准遗嘱继承安排。
