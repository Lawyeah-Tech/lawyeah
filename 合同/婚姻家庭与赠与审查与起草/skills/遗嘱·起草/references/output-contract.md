# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、法院必然认定或必然可执行；编造未给出的份额、日期、财产识别信息；把已失效《继承法》及其意见写入结论；把公证遗嘱写成效力最高；把必留份法定上限写成应继份二分之一；把打印未逐页签名写成可以设立；把遗赠扶养协议或生前赠与当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、设立状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查遗嘱（婚姻家庭）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《继承法》及其意见、《婚姻法》《物权法》《合同法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `婚姻家庭`，子级 `遗嘱`。定性理由、易混切开结果（遗赠扶养、生前赠与、双边死后过户类赠与、分家析产、离婚）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、见证人与文本版本

主体表：遗嘱人、继承人、受遗赠人、见证人、执行人、监护代理。资格表：立遗嘱时行为能力痕迹、见证人与继承人/受遗赠人有无利害关系。版本表：正文、财产清单、在先遗嘱、遗赠扶养协议、产证、聊天确认；冲突并列。形式未闭合或见证人不适格：该设立字段停止。

## 5. 形式、财产范围与继承 / 遗赠分流

拟采用的法定形式及缺口；是否只处分个人财产；配偶或共有份额是否切开；抵押查封是否误写成处分无效；给法定继承人用“继承”、给其他人用“受遗赠”并写六十日。缺口标 `G#`。不输出赠与任意撤销、遗赠扶养生养死葬对价或分家共有分割主路径。

## 6. 必留份与强制规范

是否存在可能双缺的继承人；判断时点是否写成遗嘱生效时；未保留时是预留必要份额而非整份无效。强制规范只按第 153 条区分。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的数字用 `【待填】`。不得把框架里的“代书也须逐页签名”或“抵押即处分无效”写成建议句。

## 9. 谈判与签署提醒

谈判顺序：先红线（形式未闭合、不适格见证人、已能支持的双缺零保留、遗赠扶养/赠与错位），再必须改（废止前嘱、配偶份额、继承/受遗赠用语、执行人），最后可优化。签署提醒：按所锁形式亲笔或逐页签；见证人当场声明无利害关系；完整年月日；建议同步录像或公证，但不写成必然有效或公证后不得撤回。不指导倒签或补假见证人。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是遗赠扶养协议、生前赠与或双边死后过户类赠与审查。
