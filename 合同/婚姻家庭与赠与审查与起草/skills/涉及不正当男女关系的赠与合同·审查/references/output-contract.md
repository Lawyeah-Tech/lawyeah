# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同当然有效或当然全部无效或必然全额返还；编造未给出的金额、证号、日期；把已失效《合同法》《婚姻法》及其解释写入结论；把包养改成可履行；把公证或已过户写成必然有效；把分手协议或一般赠与留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（赠与人、受赠人、赠与人配偶）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明赠与人是否有配偶、给付是否以维持不正当关系为对价、是否已交付。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《婚姻法》及其解释时记噪声，不得写入 `L#`。第 153 条、解释（二）第七条、第 157 条、通则解释第 17 条无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `涉及不正当男女关系的赠与合同`。定性理由必须同时满足：无偿给予；相对方是不正当关系第三人或其死亡后的近亲属。易混切开：分手协议、一般赠与、附义务赠与、股权零元转让、存续同居约定、离婚协议、忠诚协议、真实借贷或劳动报酬。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `公益道德义务性质的赠与合同·审查`、`婚姻家庭中的赠与合同·审查`、`一般赠与合同·审查`、`附义务的赠与合同·审查`、`零对价股权赠与·审查`、`夫妻忠诚协议·审查` method。包养、限制结婚、不得报警或逃债过户写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：赠与人、受赠人、赠与人配偶、非婚生子女、代收或代持人、受赠人控制账户或公司、已知债权人。自然人写姓名与证件号是否与文本一致。

版本表：正文、转账或权属草稿、婚姻状况材料、财产约定、子女出生材料、死亡或丧葬材料、聊天确认。冲突并列，不选对用户有利的一版。口头“配偶同意了”不得写成已同意。

## 5. 给付闭环

分列并回链文本位置：

- 给付目的：是维持或巩固不正当关系，还是损害填补、子女抚养、死亡后道义。
- 人身或关系对价：是否存在包养、保持同居、限制结婚、不得举报。
- 财产性质：个人财产还是夫妻共同财产；有无配偶同意。
- 标的：金额、账户、房屋坐落与拟登记权利人；是否概括给指定人。
- 子女：抚养是否单列，权利人是否子女。
- 交付与登记：已付与未付；房屋是否拟过户。
- 撤销条款：是否误用第 658 条处理无效问题。
- 保密：是否封死向配偶或司法机关陈述。
- 生效：是否写成关系存续期间有效。
- 分层归属：该单元落入 L1／L2／L3／L4 中的哪一层。

缺口标 `G#`，不补商业数字、证号或已过户事实。批准、登记写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

自然人偶发赠与通常不是格式条款。一方事先打印、对方只能签字的，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：第 153 条公序良俗；通则解释第 17 条分层因素；解释（二）第七条；第 157 条返还；第 1042 条禁止有配偶者与他人同居；第 311 条无偿不构成善意取得；第 538 条逃债。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“整份合同因有第三者二字当然全部无效”或“双方自愿就当然有效”写成已核验结论。不得把“改成生活补助即可履行”写成已核验放行。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：给付目的违背公序良俗；包养或按月同居对价；限制结婚或不得报警；用第 658 条处理无效；共同财产写成个人财产或配偶不得追索；子女财产与给本人混写；空写不可撤销或公证对抗配偶；整份写成当然无效或当然有效；与 `分手协议·审查` 边界不清。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、证号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：删除关系对价且不改成可履行包养；效力分层先于第 658 条；与分手协议切开后的转出口径（若已切开则本节不填实体句）。

对包养条款，“建议改为”只允许删除或停笔告知，禁止输出可履行付款节点。

## 9. 谈判与签署提醒

谈判顺序：先红线（包养对价、限制结婚或报警、伪造同意、逃债过户），再必须改（财产性质披露、子女拆分、无效返还清算、删除空文不可撤销），最后可优化。

签署提醒：本人签；代收方签；日期真实。建议核对婚姻状况和资金来源。不指导倒签或补假同意。公证不能使违背公序良俗变成有效。

赠与人立场必须提示：无效案件不要先发撤销通知；配偶可能追索；空写不可撤销挡不住第 153 条；不得因有第三者就假设整份当然无效。受赠人立场必须提示：已过户不等于已经终局取得；青春损失费名目可能不受保护；不得把“配偶无权主张”当成盾；双方自愿不等于当然有效。配偶立场必须提示：可评估确认无效与返还，不在本任务出具起诉状；返还范围可能存在全额与份额分歧。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、确认无效诉讼文书、返还精算终局或效力保证。
