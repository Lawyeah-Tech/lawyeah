# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的金额、天数、期限；把已失效《合同法》赠与章写入结论；把“附义务”写成已经关闭第 658 条；把空义务写成已可稳妥启动第 663 条第 3 项；把不履行写成合同当然无效；把无负担赠与当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查附义务的赠与合同（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》赠与章或其解释、《物权法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `附义务的赠与合同`。定性理由、易混切开结果（一般赠与、公益赠与、遗赠扶养、房产/亲属房屋赠与、有偿合同、分家析产）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `一般赠与合同·审查` 的 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、处分权与文本版本

主体表：赠与人、受赠人、义务受益人、监督人、需一并签字的配偶或共有人。资格表：处分权痕迹、受赠人履约能力、未成年人利益说明。版本表：正文、财产清单、义务清单、权属件、公证意向、聊天确认；冲突并列。共有财产未经配偶同意：该处分字段停止。

## 5. 财产、义务与撤销窗口

核心给付是否为无偿给予+可强制或可撤销之负担；义务是否量化到可启动第 663 条第 3 项；权利是否已转移；第 658 条窗口是否仍打开；是否具备公证或公益、道德义务例外；履行顺序；居住权是否单独登记。缺口标 `G#`。不输出一般赠与无负担主路径、遗赠扶养死后过户主路径或买卖价款主路径。

## 6. 瑕疵担保、强制规范与违法义务

第 662 条是否被“无偿免责”掏空。是否构成格式条款。强制规范只按第 153 条和合同编通则解释第 18 条区分。以维持不正当关系、限制人身自由为义务：停笔，不改成可履行。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的数字用 `【待填】`。不得把“附义务即不可撤销”或“不履行当然无效”写成建议句。

## 9. 谈判与签署提醒

谈判顺序：先红线（无负担错位、空喊不可撤销、违法义务、唯一住房先过户拒留居住），再必须改（义务量化、催告+第 663 条第 3 项+返还、公证条款、第 662 条限度内担保、阶段交付），最后可优化。签署提醒：赠与人、受赠人亲笔签名；受赠人确认义务清单；财产清单与义务清单入附件；建议公证但不写成未办公证已关闭第 658 条。不指导倒签或补假公证。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、撤销权诉讼策略或效力保证，也不是一般赠与、公益赠与或遗赠扶养审查。
