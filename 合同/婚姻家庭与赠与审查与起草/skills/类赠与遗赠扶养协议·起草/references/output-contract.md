# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或死后必然过户；编造未给出的金额、天数、丧葬标准；把已失效《合同法》《继承法》《物权法》《民法总则》及失效《养老机构设立许可办法》写入结论；把本协议写成可以按第 658 条任意撤销；把签字或交钥匙写成已经取得物权；把先过户再养老改成可履行赠与；把子女协议当成已完成的本类型审查；把婚家货架同名文本换标题交差。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查遗赠扶养协议（与赠与合同有区别的 “类赠与” 协议）（赠与合同）」。入口句必须回答：有没有生养死葬对价、能不能按赠与任意撤销。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《继承法》、已失效《物权法》、已失效《民法总则》、已失效《养老机构设立许可办法》、2013《养老机构管理办法》时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `遗赠扶养协议（与赠与合同有区别的 “类赠与” 协议）`。定性理由、易混切开结果（婚家遗赠扶养 / 附义务赠与 / 一般赠与 / 遗赠 / 遗嘱 / 赡养 / 意定监护 / 养老服务）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `遗赠扶养协议·审查` method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、继承人范围、能力与文本版本

主体表：遗赠人、扶养人（个人或组织）、授权签字人、见证人。身份表：扶养人是否落在第 1127 条继承人以外；组织登记与备案。能力表：行为能力痕迹、录像或见证。权属表：财产清单、个人份额、抵押查封租赁居住权。版本表：正文、附件、权属证、告知子女证据、聊天确认；冲突并列。

## 5. 给付闭环：生养死葬、死后转移、删除赠与工具

生养（住所、饮食、护理频次、费用来源）与死葬是否可检验；财产是否特定化且限于个人份额；转移时点是否死亡并清算后；合同是否签字立即生效；有无第 658、660、661、666 条或“赠与人/受赠人”；居住是否保留至去世；费用账册。缺口标 `G#`。不输出“可以按赠与撤销”，不输出“先过户再养老可放行”。

## 6. 格式条款、强制规范、协议优先与清算

是否构成格式条款；提示说明痕迹。解释（一）第 3 条优先于抵触遗嘱。第 1159、1162 条只标清算红旗，不做必留份精算。逃债或规避限购不得写成可放行。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把赠与章条款改成“可接受”。

## 9. 谈判与签署提醒

谈判顺序：先红线（婚家误入、法定继承人作扶养人、无照料只给房、保留第 658 条、先过户再养老、死亡后协议才生效），再必须改（义务清单、财产特定化、死后转移、解除结算、居住、账册、协议优先、删除赠与人称谓），最后可优化。签署提醒：双方到场、建议非继承人见证和录像、财产清单、能力说明、组织登记备案、已告知子女证据。不指导倒签或补假能力证明。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是婚家 `遗赠扶养协议·审查`、附义务赠与或遗嘱安排。
