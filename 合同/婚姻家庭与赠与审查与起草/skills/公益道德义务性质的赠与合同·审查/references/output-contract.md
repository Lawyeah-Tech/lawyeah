# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、税前扣除必然办成或必然可强制交付；编造未给出的金额、账户、期限；把已失效《合同法》及其解释、2016 年《慈善法》已被修改条号、2016 年公开募捐管理办法或 2007 年实施条例第 51 条旧义写入结论；把未达门槛的文本写成第 658 条第 2 款已经打开；把看护供养改成公益外壳；按遗赠改完；把“资金到账后生效”写成可放行；把任意撤销关闭写成法定撤销一并消灭。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查公益、道德义务性质的赠与合同（赠与合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2016 年《慈善法》已被修改文本、2016 年《慈善组织公开募捐管理办法》、2007 年实施条例第 51 条旧义时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `赠与合同`，子级 `公益、道德义务性质的赠与合同`。定性理由、易混切开结果（一般赠与、附义务赠与、商业赞助、房产/亲属房屋赠与、婚内赠与、股权赠与、遗赠）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `一般赠与合同·审查` 或 `附义务的赠与合同·审查` 的 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、资格与文本版本

主体表：赠与人、受赠人、实际受益人、对公账户名、授权签字人、内部决议机关。资格表：慈善组织登记、公开募捐资格、免税资格是否被材料提及。版本表：正文、公开承诺、物资清单、项目方案、账户证明、内部决议、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环：三轨、用途、对公交付、票据

分轨写清：第 658 条第 2 款事实是否具备；第 660 条与慈善法第 41 条是否写清；第 663 条和第 666 条（含向县级以上人民政府民政部门报告并公开说明）是否保留。用途是否特定到可监督；对公账户与批次；质量标准；捐赠票据。缺口标 `G#`。不输出“空喊公益即不得撤销”，不输出“到账后生效”，不输出一般赠与任意撤销主路径、附义务看护主路径或遗赠死因处分主路径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；单方改用途、排除查阅权、无偿免除产品质量责任。虚假公益、关联输送、擅自公开募捐、指定利害关系人为受益人不得写成可放行。强制规范只按第 153、154 条区分。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止用普通赠与任意撤销句或遗赠条替换本类型三轨句。

## 9. 谈判与签署提醒

谈判顺序：先红线（未达门槛却关闭任意撤销、看护供养当公益、按遗赠改、个人账户收款、商业对价、虚假公益、到账生效、删掉第 663/666 条、无资格公募），再必须改（用途、对公账户、票据、请求交付、监督、剩余财产、公开承诺附件），最后可优化。签署提醒：组织用印、决议附件、账户证明、承诺文本、物资清单。不指导倒签认捐日或补假决议。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是一般赠与、附义务赠与、商业赞助或遗赠安排。
