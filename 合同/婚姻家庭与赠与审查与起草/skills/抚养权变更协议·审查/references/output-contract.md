# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、保证法院确认或必然可执行；编造未给出的抚养费、日期、账户、文书号；把已失效婚姻法解释或 1993 年子女抚养意见（含十周岁口径）写入结论。

## 1. 触发、单方立场与成果状态

立场必须是现直接抚养一方或拟接收直接抚养一方，择一。写授权、签署状态、主要目标。负触发写完整 Skill ID 路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效婚姻法解释、1993 年子女抚养意见或已失效合同法时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级：婚姻家庭。子级：抚养权变更协议。定性理由须写清：原已有直接抚养安排，本文件只变更直接抚养人并配套抚养费与探望。易混切开结果必须点名离婚协议、分居协议、只改抚养费、监护处分是否已排除。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。挂靠、违法分包与本类型无关，不得写入本节充数。

## 4. 主体、原依据、子女身份与文本版本

主体表：父方、母方、子女、原直接抚养人、拟直接抚养人、抚养费付款名与收款账户名。不得把未成年人列为当事人。

原依据表：离婚协议/民政登记/判决书/调解书名称、文号、日期、原直接抚养安排原文摘录。未附原件则该字段停止。

版本表：正文、附件、原家事文书、聊天确认、子女意愿记录；冲突并列，不选对用户有利的一版。

## 5. 给付闭环（直接抚养安排）

标的是直接抚养安排，不是财产买卖。写：变更时点、经常居住地、主要照料人、就学、户口与学籍配合、证件交接、抚养费构成与节点、探望频率与接送、重大事项协商。缺口标 `G#`，不补商业或家事数字。批准、登记、调解书、司法确认写成待完成条件或双方义务，不写成已经完成。

## 6. 格式条款与强制规范

父母个案协议通常不是经营者格式条款；异常剥夺探望或监护时仍审查提示说明。强制规范只区分管理性与是否导致民事行为无效。监护不得私下放弃或转让。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

至少覆盖已出现的硬闸：子女利益、监护处分、离婚协议切开、八周岁意愿、费探挂钩、对外效力、原依据。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的金额、日期、账户、文号用 `【待填】`，不编造。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线（监护处分、费探挂钩、买卖抚养、对外强制执行伪称），再必须改（原依据、意愿痕迹、居住就学、对外路径），最后可优化。

签署提醒：父母双方亲签捺印；签署日期与交接日起算；附件清单（原文书、意愿记录、账户）；不要指导倒签或补假意愿。提示：签字不等于户籍学籍已改，不等于已有执行名义。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、离婚财产方案或效力保证。不得承诺法院必然出具调解书或确认裁定。
