# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证协议有效、保证民政必然登记或身份已经消灭；编造未给出的证号、日期、补偿额、迁入地；把已失效《收养法》《合同法》写入结论；把第一千一百一十七条写成登记条文；把公证或签字写成可以替代解除登记；把成立收养要件当作本类型主线；把未成年人写成补偿或违约金债务人。

## 1. 触发、单方立场与成果状态

立场必须是收养人、送养人或成年被收养人，择一。夫妻共同收养须写清是否双方都签。写授权、签署状态、主要目标。负触发写完整 Skill ID 路由，不启动实体审查。写明被收养人是否未成年、是否已满八周岁，以及原收养是否已有登记证。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《收养法》、1992 年旧登记规定或已失效《合同法》时记噪声，不得写入 `L#`。解除条件、登记、未成年利益、身份后果、补偿请求权无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `婚姻家庭`，子级 `解除收养协议`。定性理由必须同时满足：已有依法成立的收养关系；本文件以协议终止该关系。易混切开：成立收养、抚养权变更、监护协议、遗赠扶养、继父母退出、寄养、涉外。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `收养协议·审查` method。买卖未成年人、逃债、胁迫、无证补办再解除写停笔告知，不填可履行结构。

## 4. 主体、原登记与文本版本

主体表按分轨填写：

- 未成年：收养人（夫妻共同收养列双方）、送养人、已满八周岁的被收养人（意见栏，不是合同义务人）。
- 成年：收养人与成年被收养人；送养人不是必要主体。

原登记表：原《收养登记证》编号、登记机关、登记日期、被收养人常住户口所在地。未附原件或证号与主体不一致：该字段停止。

版本表：解除协议正文、原收养登记证复印件、八周岁以上本人声明、补偿清单、聊天确认。冲突并列，不选对用户有利的一版。口头“孩子同意了”“证丢了但肯定登过”不得写成已同意或已登记。

## 5. 解除条件、登记与后果闭环

分列并回链文本位置：

- 解除条件：未成年双方协议或成年关系恶化、无法共同生活；一方不同意是否被写成可强制。
- 八周岁以上本人同意痕迹；是否把未成年人写成债务人。
- 监护回归：接收人、交接时点、居住就学安全；生父母不能接收时的处理。
- 登记：共同到被收养人常住户口所在地县级民政；材料清单；三十日审查；收回登记证、发给解除证明。
- 身份效力时点：身份关系自办理解除登记之日起终止，还是写成签字即解除。
- 身份后果：与养方消除；未成年与生父母自行恢复；成年是否恢复已协商。
- 补偿：生活费与抚养费分列；请求权基础；支付时间、账户、担保；是否用“再无义务”抹掉法定生活费。
- 姓氏与户口：是否恢复原姓；谁在取得解除证明后几日内配合迁户；不得写成签字即已迁户。
- 共同财产：清单与分割或折价；不得与身份解除捆绑成逃债结构。

缺口标 `G#`，不补证号、补偿额或已完成登记。批准、登记、迁户写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

亲属个案协议通常不是经营者格式条款。一方事先印好、排除对方法定补偿或强制未成年人放弃意愿的，仍审查提示说明。

强制规范与效力红旗只在核验后落法律结论：协议解除条件是否具备；未登记不得消灭身份；最有利于被收养人；禁止买卖未成年人；第一千一百一十八条生活费不得约定免除（在具备法定条件时）；胁迫、欺诈、恶意串通逃债。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“公证后即解除”或“签字即消灭继承和赡养”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：解除条件未分轨或一方不同意仍放行；签字/公证代替登记；登记条文错挂第一千一百一十七条；八周岁意愿缺失或把未成年人写成债务人；监护回归落空；与养方写“中止”而非“消除”；成年与生父母恢复未协商却写死；用“再无经济义务”抹掉生活费；无证事实收养写成可登记解除；成立收养要件混入主线。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的证号、日期、金额用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：条件分轨；身份关系自解除登记之日起终止；共同登记材料与管辖；八周岁本人同意栏；监护回归；消除/恢复用语；生活费与抚养费分列。

## 9. 谈判与签署提醒

谈判顺序：先红线（一方不同意硬写解除、签字即解除、买卖未成年人、逃债、胁迫意愿、无接收监护），再必须改（登记时点、材料管辖、身份后果分轨、补偿分轨、户口配合），最后可优化。

签署提醒：收养人夫妻双方、送养人或成年被收养人本人签；已满八周岁在意见栏亲签“本人同意解除收养关系”；原登记证原件核对；签署日真实，通常在共同前往民政当日或之前；不要指导倒签或补假同意。提示：签字不等于身份已断，不等于户口已迁，不等于已有执行名义。

收养人立场必须提示：未登记则养子女仍可能主张继承或身份利益；补偿无担保可能“身份断了钱拿不到”。送养人或未成年利益一侧必须提示：解除后谁接收监护、就学与安全是否可落地。成年被收养人立场必须提示：具备法定条件时生活费义务不因一纸“互不往来”而当然消灭。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、起诉解除文书或效力保证。不得承诺民政必然办成登记，不得承诺法院必然准予解除。
