# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证协议有效、民政必然登记或拟制血亲已经成立；编造未给出的年龄、日期、费用、证号；把已失效《收养法》《合同法》、1992 年登记规定、1984 年事实收养口径写入结论；把签字或公证写成收养关系成立；把未登记写成已产生养父母子女权利义务；把不符合法定送养或收养条件改成可履行；把解除已成立收养留在本技能改完；把买卖或非法送养改成可登记结构。

## 1. 触发、单方立场与成果状态

立场（拟收养人、拟送养人、儿童福利机构、拟签字配偶或有抚养义务的人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否拟建立收养关系、是否已有收养登记证、是否夹带解除或监护转让。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《收养法》《合同法》、1992 年登记规定、1984 年事实收养口径时记噪声，不得写入 `L#`。登记成立、送养与收养条件、八周岁同意、禁止买卖无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `婚姻家庭`，子级 `收养协议`。定性理由必须是拟依法成立养父母与养子女关系。易混切开：解除收养、监护协议、意定监护、抚养权变更、扶养_抚养、亲属朋友抚养、寄养、离婚协议、涉外收养程序。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `解除收养协议·审查` method。买卖、伪造材料、规避公告或不符合法定准入写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：收养人及配偶、送养人、被收养人、有抚养义务的人、其他监护人。自然人写姓名与证件号是否与文本一致；机构写名称。标明被收养人出生日期是否已满八周岁、收养人是否已满三十周岁、有无配偶。

版本表：协议正文、身份与户口材料、出生医学证明、无力抚养或孤儿材料、体检、相关违法犯罪记录证明、评估或公告草稿、聊天确认。冲突并列，不选对用户有利的一版。口头“已经同意”“已经评估”不得写成已同意或已完成。

## 5. 成立收养给付闭环

分列并回链文本位置：

- 被收养人是否落入第 1093 条三类。
- 送养人是否落入第 1094 条三类或第 1095 条特别情形。
- 共同送养或单方送养法定事由。
- 监护人送养是否取得有抚养义务的人同意。
- 收养人五项条件、子女人数、夫妻共同收养、无配偶者收养异性年龄差。
- 法定例外是否有事实支持。
- 八周岁本人同意。
- 登记机关、申请期限、未登记前不得对外以养父母子女名义行事。
- 评估与公告配合义务，是否被协议拟制完成。
- 公证是否被误写成成立时点。
- 交接与证件移交是否早于或替代登记。
- 费用是否必要合理或构成对价。
- 身份效果是否错误提前到签字日。
- 预埋解除是否写成私下终止。

缺口标 `G#`，不补年龄、费用或已登记事实。登记、评估、公告写成条件或双方义务，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

民政示范文本或机构预先拟定且未协商的，按格式条款审查提示说明。自然人偶发协商通常不是格式条款。

强制规范与效力红旗只在核验后落法律结论：禁止买卖未成年人；违反收养章规定无效；未登记不成立；不符合主体准入。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“长期共同生活即事实收养”或“整组协议因未公证而全部无效”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：签字或公证即成立；未写民政登记成立；送养或被收养类型不成立；未共同送养；收养人条件被协议放宽；配偶未共同收养；八周岁无本人同意；对价或感谢费买卖外观；拟制评估或公告完成；交接替代登记；预埋私下解除；与 `解除收养协议·审查` 主文件混淆。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的年龄、日期、费用、证号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：登记成立时点；送养与共同送养；删除或停笔非法对价；收养人条件与夫妻共同收养；八周岁本人同意；评估公告配合而非拟制完成。

## 9. 谈判与签署提醒

谈判顺序：先红线（买卖或非法送养、不符合法定准入、公证替代登记、伪造材料、倒签），再必须改（登记成立句、共同送养、配偶共签、八周岁签署、评估公告配合），最后可优化（探视、姓氏、随访）。

签署提醒：收养人夫妻、送养人、已满八周岁的被收养人本人签；相关证明作附件；共同到县级民政部门申请登记；日期真实。不指导倒签、补假评估或假同意。

收养人立场可建议尽快配合评估与登记，但必须同时写明：未登记不得当成已成立。送养人立场必须提示：登记成立后与生父母权利义务消除，不是可以随时收回的保管约定。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是登记代办、解除收养整案、监护转让、涉外认证链、刑事辩护或效力保证。
