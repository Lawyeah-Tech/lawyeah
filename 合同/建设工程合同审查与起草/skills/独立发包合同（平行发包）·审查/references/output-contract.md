# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价格、工期、配合费比例、证号；把已失效《合同法》及其解释、法释〔2004〕14 号、法释〔2018〕20 号、1997 年建筑法未修正文本、2000 年质量管理条例未修订文本写入结论；把肢解发包写成民事合同必然无效；把无资质或挂靠改成可进场；把主体结构改成可履行平行发包；把本约按甲指或 EPC 改完。

## 1. 触发、单方立场与成果状态

立场（发包人或独立承包人）、授权、签署状态、主要目标、专项工程名称。负触发写路由，不启动实体审查。甲指（总包签约/转付）、EPC、施工总承包本约、把主体结构当平行发包必须在本节写明负触发或停笔，不得进入第 5–8 节充当可履行修改。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2004/2018 建工解释、1997 年建筑法未修正文本或 2000 年质量管理条例未修订文本时记噪声，不得写入 `L#`。建筑法与 2019 修正冲突时以 2019 修正为准。肢解发包、资质、必须招标无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `建设工程`，子级 `独立发包合同（平行发包）`。定性理由必须同时满足：发包人与专项承包人直接签约；价款由发包人直接支付；标的是非主体、可独立完成的专项工程。易混切开：甲指分包、EPC、施工总承包本约、专业分包、劳务分包、挂靠。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `建设工程施工合同·审查` / `指定分包合同（甲指分包）·审查` / `工程总承包合同·审查` 的 method。挂靠、肢解发包或无资质写停笔告知，不填可履行结构。

## 4. 主体、授权、专项资质与文本版本

主体表：发包人、独立承包人、现场施工总承包人（非本约主体）、其他平行承包人、监理、付款账户名、发票名、现场负责人、授权签字人。独立承包人专业承包资质与特种许可是否被材料提及。版本表：正文、界面划分清单、交叉施工配合协议、总包合同中预留平行发包权利的条款、配合费约定、招标投标文件、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

分列并回链文本位置：

- 专项范围：工程名称、部位、是否触及主体结构或单位工程整体。
- 界面：物理界面、时间界面、交接验收、成品保护。
- 施工条件：水电、垂直运输、脚手架、场地交付条件。
- 配合费：金额或计取方式、包含范围、承担主体、是否总包代收。
- 价款：发包人直付路径、计价方式、节点、发票。
- 工期：是否嵌入总体总进度计划；总包滞后的窝工补偿；本约延误的交叉索赔。
- 验收：独立报验、总包见证、专项验收、参加整体竣工验收。
- 保险：统保或分保，有无真空。

缺口标 `G#`，不补商业数字、证号或配合费比例。批准、招标、许可写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。强制规范只区分管理性与是否导致民事行为无效。本节点必须单独回答：是否肢解发包或主体结构被拆出；专项资质是否对应；是否必须招标未招；签约和付款是否仍走总包（甲指信号）；是否挂靠。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“肢解发包即合同必然无效”或“分包管理办法第 7 条禁止一切直接发包”写成已核验结论。第 7 条禁止的是建设单位直接**指定分包人**，不是禁止发包人就专项工程直接发包。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

本类型风险表至少覆盖（有文本才填，无对应条款标缺口）：

- 直接签约 + 直接支付是否被总包转付/代结算污染；
- 界面划分清单、时间界面、成品保护是否缺失；
- 配合费包含范围、承担主体、代收定性；
- 多总包或准总包并存、主体结构是否被平行发包；
- 专项资质与特种许可；
- 必须招标事实；
- 总包合同是否预留平行发包权利、是否书面告知总包；
- 工期连锁与交叉损坏；
- 三方配合协议与发包人裁决义务；
- 挂靠、无资质、农民工工资穿透。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

停笔项（肢解发包、主体结构平行发包、挂靠、无资质、必须招标未招）只给告知句，不给“改完就能进场”的可履行句。

## 9. 谈判与签署提醒

谈判顺序：先红线（肢解/主体结构、挂靠、无资质、必须招标未招、甲指或 EPC 误留），再必须改（界面清单、配合费、直付路径、工期连锁、三方协议），最后可优化。签署提醒：发包人与独立承包人直接盖章；禁止只盖项目部章充任承包人；附件装订界面划分表、配合协议、总包知情确认；日期不得伪造早于实际协商日。不指导倒签进场或补假资质。

发包人立场必须提示：平行发包越多，总协调和交叉索赔压力越大，无项目管理班子不得写成风险已转移。独立承包人立场必须提示：与总包无合同关系不等于可以拒绝安全调度；未锁定施工条件可能被总包断水电卡进场。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本技能只出审查意见和修改句，不出整份起草终稿；出稿转 `独立发包合同（平行发包）·起草`。不是履约交底、争议文书或效力保证。肢解/挂靠/无资质已停笔的，本节重复告知一次。
