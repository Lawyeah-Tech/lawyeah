# 边界与路由

本技能只审查 **建设工程 / 独立发包合同（平行发包）**。

必须同时读出发包人与专项承包人**直接签约**，以及价款由发包人**直接支付**。现场可另有施工总承包人，但本约承包人与总包之间不得形成分包合同关系。标题叫“独立发包”“平行发包”“专项施工”但付款走总包、总包盖章或设计施工一体总责的，不得留在本技能做实体结论。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或标题独立发包、核心给付明显不是发包人直接发包专项工程 | 本套导航的类型切开步骤 |
| 施工总承包人与分包人签约；价款经总包转付、总包开票、总包结算；发包人只行使指定权 | `指定分包合同（甲指分包）·审查`。禁止打开其 method，禁止按指定权+总包签约改完 |
| 设计+采购+施工或设计+施工一体，承包人对质量、安全、工期、造价负总责 | `工程总承包合同·审查`。禁止打开其 method |
| 本约就是业主与施工总承包人的按图施工本约 | `建设工程施工合同·审查`。禁止抄黑白合同/先定后招/解释二固定价主路径完成本任务 |
| 总包经发包人同意把专业工程分包出去，总包与专业分包人签约 | `专业分包合同·审查` |
| 只出人工，不含主材、大型机械和技术管理 | `劳务分包合同·审查` |
| 出借资质、只收管理费、无真实隶属 | `挂靠合同（借用资质合同）·审查`；本任务停笔告知，不改成可履行 |
| 企业内部经营层或项目经理内部承包 | `内部承包合同·审查` |
| 联合体成员之间的内部分工、损益或退出 | `联合体协议·审查` |
| 勘察 / 设计 / 监理 / 咨询本约 | `建设工程勘察合同·审查` / `建设工程设计合同·审查` / `建设工程监理合同·审查` / `建设工程咨询服务合同·审查` |
| 无文本、本类型条件已谈妥、要出己方稿 | `独立发包合同（平行发包）·起草` |
| 已签未争、问进场、配合费、验收节点 | 本套导航的履约步骤 |
| 已成争 | `或` 或 `或` |
| C 端大众快检 | 只分流，不回改 |

同一文本既写“发包人直接付款”又写“总包与承包人另行签订分包合同”：按核心签约主体切开。发包人—独立承包人直接盖章且直付 → 留本技能，删除总包签约句。总包—分包人盖章且转付 → 负触发 `指定分包合同（甲指分包）·审查`。两可且无法判断：负触发引擎，不灌两套知识。

把应当由一个承包人完成的单位工程或主体结构拆给数家“总包”：留在本技能只出肢解发包告知并停笔，不转去“改成可履行多家总包稿”。

专业版未收录的 P1 场景不会安装对应原子。若用户拿这些文本来找专业版：输出 `unavailable`，提示或回引擎，不得用本独立发包原子硬套。

禁止在正文写半截 Skill ID。转出时必须写完整 ID，例如 `指定分包合同（甲指分包）·审查`、`工程总承包合同·审查`、`建设工程施工合同·审查`。
