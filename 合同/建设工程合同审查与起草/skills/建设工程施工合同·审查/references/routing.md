# 边界与路由

本技能只审查 **建设工程 / 建设工程施工合同**。

| 主要目标 | 路由 |
| --- | --- |
| 类型未定或名实明显不符 | 本套导航的类型切开步骤 |
| 核心给付是勘察 | `建设工程勘察合同·审查` |
| 核心给付是设计 | `建设工程设计合同·审查` |
| 设计采购施工一体 / EPC | `工程总承包合同·审查` |
| 经发包人同意的专业工程分包 | `专业分包合同·审查` |
| 纯劳务分包（只出人工） | `劳务分包合同·审查` |
| 农村低层自建、私人室内装修等承揽 | 引擎重新定性，或项目承揽原子 |
| 无文本、本类型条件已谈妥、要出己方稿 | `建设工程施工合同·起草` |
| 已签未争、履约节点 | 本套导航的履约步骤 |
| 已成争（效力、价款、优先受偿、索赔） | `或` 或 `或` |
| C 端大众快检 | 只分流，不回改 |

挂靠、违法分包、先定后招、黑白合同：留在本技能只出告知并停笔，不转去“改成可履行稿”，也不转争议原子充作签前修改。

专业版未收录的 P1 场景（BT、内部承包、挂靠合同文本、甲指分包、平行发包）不会安装对应原子。若用户拿这些文本来找专业版：输出 `unavailable`，提示或回引擎，不得用本施工合同原子硬套。
