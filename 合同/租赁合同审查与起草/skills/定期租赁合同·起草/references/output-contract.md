# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的租期、租金、占用费；把已失效《合同法》租赁章写入结论；把超过二十年写成整份无效或整份有效；把续订写成累计不超过二十年；把未书面一律写成不定期；把届满继续使用写成按原期限再续一期；把随时解除留在定期里仍称已锁定；把不定期或房产专论当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查定期租赁合同（租赁合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》租赁章或其解释、已失效《城市房屋租赁管理办法》时，记噪声，不得写入 `L#`。实务“续订总期限不得超过二十年”“未书面即不定期”记噪声。

## 3. 类型与加载路径

父级 `租赁合同`，子级 `定期租赁合同`。定性理由、易混切开结果（不定期、房产/不动产/动产/建筑设备/临时建筑、融资租赁）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、授权与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、共有人或有权锁定该期限的人。版本表：正文、附件、交付确认书、聊天确认；冲突并列。共有/国资/集体未闭合：该签署能力字段停止。

## 5. 给付闭环：期限、租金与标的寿命

起算点与届满点或可确定期间；是否超过二十年；是否书面且满六个月；标的剩余寿命是否覆盖租期；租金支付周期是否长于剩余租期；免租期是否计入租期；迟延交付租期是否顺延。缺口标 `G#`。批准、登记、备案写成义务或对抗安排，不写成已经完成，也不写成未备案即合同无效。

## 6. 续订、默示更新、格式条款与强制规范

续订是否重新合意、是否自续订日起截断二十年；届满继续使用是否被误写成按原期限再续一期；随时解除是否消解定期。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。倒签/查封只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“自动续期”写成法定按原期限续期。

## 9. 谈判与签署提醒

谈判顺序：先红线（期限不能确定、超二十年拒改、随时解除拒改、倒签/查封对抗），再必须改（起算绑定交付、续订重新合意、默示更新排除、标的寿命截断），最后可优化。签署提醒：签署日与起租日分开；交付确认书入附件；期限变更书面补充。不指导倒签或补假交付。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务先出草稿，再按本类型硬闸自审；不得只交白稿。不是履约交底、争议文书或效力保证，也不是不定期或房产租赁专论审查。
