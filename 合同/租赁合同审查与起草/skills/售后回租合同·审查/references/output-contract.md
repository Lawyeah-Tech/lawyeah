# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证构成本质上的融资租赁、保证是借贷、保证有效或必然可取回／对抗；编造未给出的评估值、价款、利率、登记机关；把已失效《合同法》融资租赁章、2014 年解释未修正文本、24%／36%／旧四倍写入结论；把直租、普通租赁、真实买卖或让与担保留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（出租人／买受人、承租人／出卖人或保证人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否先卖后租、付款对象是否为承租人，以及是否夹带直租、普通租赁或“所有权仅作担保”条款。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其融资租赁章、2014 年融资租赁解释未修正文本、《物权法》《担保法》及其解释、1991 旧四倍、2015 年 24%／36% 时记噪声，不得写入 `L#`。先卖后租定性、虚构租赁物、登记对抗、占有改定、取回清算、让与担保自我定性、利率上限无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `租赁合同`，子级 `售后回租合同`。定性理由必须同时满足：卖方＝承租人、买方＝出租人；转让价款付给承租人；租回占有使用。易混切开：直租融资租赁、普通动产／房产租赁、住房卖后租住、让与担保／抵押、产权式商铺。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `融资租赁合同·审查` method。无物、查封物、禁止流通物、伪造评估写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：承租人／出卖人、出租人／买受人、担保人、登记权利人、实际占有人、评估机构、付款名、授权签字人。名称与证件不一致不自动合并。通道方“过一手”的，并列谁真正出资、谁记资产。

版本表：转让合同、融资租赁合同、还租表、评估报告、清单、权属证、决议／批准、抵押权人同意、保证合同、保险、聊天确认。冲突并列，不选对用户有利的一版。口头“已经过户了”不得写成已登记。

## 5. 先卖后租给付闭环

分列并回链文本位置：

- 标的：名称、编号、存放地、权属来源、评估值、账面净值。
- 主体重合：首部括号；付款对象是承租人。
- 转让：价款、支付日、所有权转移时点、占有改定、瑕疵担保（有权处分、物真实存在）。
- 回租：起租日、租期、还租表、利率、保证金、手续费；本金与转让价款勾稽。
- 登记／过户：不动产产权证号；中登网或统一登记；特殊动产；完成前是否放款。
- 回购：名义价款或公式、回转登记时限、税费。
- 保险与风险：占有期间灭失不当然免除租金；保险金优先清偿出租人。
- 两合同关系：一份无效时返还价款、恢复登记。

缺口标 `G#`，不补商业数字或已过户、已登记事实。过户、登记、评估写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

出租人预先拟定且未协商的全额加速、单方解释权、放弃抗辩、管辖，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：虚构租赁物；低值高买且无合理解释；“本买卖不真实／所有权仅作担保”；无物或禁止流通物；倒签登记。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“主体重合当然不构成融资租赁”或“未登记即整约无效／未登记即已可对抗”写成已核验结论。真回租可以适用全部租金加速或解除取回的择一，但须先通过名实闸。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：身份重合未标注；付款对象不是承租人；无占有改定；无评估或低值高买；还租表与转让价款对不上；不动产不过户；登记完成前即放款；“所有权仅作担保”；保证未覆盖改判借贷；回购无回转时限；取回无清算；一物多融。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、评估值用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：身份重合；占有改定；登记或过户完成作为放款条件；删除“不转移所有权／仅作担保／买卖不真实”；还租表勾稽；保证覆盖融资租赁或借款；回购回转时限；取回多退少补。

## 9. 谈判与签署提醒

谈判顺序：先红线（无物、查封物、禁止流通、伪造评估、流质归己、不过户的不动产仍要当回租放款），再必须改（占有改定、登记条件、价款勾稽、保证覆盖、回购回转），最后可优化（保险第一受益人、现场盘点照片、编号拓印、资金用途监管）。

签署提醒：有权签字人与公司决议；共有人或抵押权人同意；评估、清单、还租表、权属证作附件；日期真实。不指导倒签过户或补假评估。

出租人立场可坚持登记完成再放款和禁止再抵押再回租，但必须保留清算。承租人立场必须提示：未过户未登记时出租人取回权可能失败；被改判借贷后租金加速和留购结构可能被拆成还本付息。保证人立场必须提示：主合同被识别为借贷后，未覆盖的保证可能脱保。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务只出审查意见和修改句，不出整份起草终稿。出稿转 `售后回租合同·起草`。不是履约交底、诉讼文书、利息精算终局或效力保证。
