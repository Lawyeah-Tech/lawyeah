# 不定期租赁合同·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》租赁章（含原第 215、232、236 条）、已失效《城市房屋租赁管理办法》、已失效《经济合同法》当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **不定期租赁合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「不定期租赁合同·审查」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、把定期租赁/融资租赁/售后回租/房产或动产全套物的审查改完。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **随时解除须通知**：不定期租赁当事人可以随时解除合同，但应当在合理期限之前通知对方（第 730 条）。解除意思须到达（第 565 条）。修改句必须同时写下：双方均可解除、通知形式、送达地址、通知期内权利义务不变、通知期满日＝应返还日。只写“随时收回/随时搬走”而无通知：必须改。当日清场、删除通知义务、解除后仍须付满固定年限租金：红线。通知期满终止不是违约。
2. **未采用书面超六个月视为不定期**：租赁期限六个月以上应当采用书面形式；未采用书面形式且**无法确定租赁期限**的，视为不定期（第 707 条）。书面形式含合同书、信件和可调取查用的数据电文（第 469 条）。微信、邮件已写清起止日的，期限可以确定，不得一律改写成不定期。不得把“口头超六个月合同无效”写成结论。

配套必须改：先标明三种入口（成立时无期限 / 第 707 条拟制 / 第 734 条默示更新）；能补成定期则优先补起止日；禁止“永久承租、任何一方不得解除”；融资租赁、售后回租不得套双方随时解除。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签租赁正文或可核对的口头/微信履行记录，尚未按定期结构锁定签署，尚未成争，核心给付是占有使用换租金，期限未约定或约定不明且依第 510 条仍不能确定，或第 707 条拟制，或第 734 条默示更新；用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 正文或数据电文已写清起止日，期限可以确定 → `定期租赁合同·审查`；不得删掉届满日后继续当不定期审；
- 出租人依承租人指定向出卖人购买、融资+融物、租金覆盖购价 → `融资租赁合同·审查`（P1；专业版未装则 `unavailable`）；
- 承租人先卖后租回同一物 → `售后回租合同·审查`（P1；未装则 `unavailable`）；
- 用户主轴是房屋备案、一房数租、优先购买整章，而不是期限形态 → `房产租赁合同·审查`；不动产占有使用整章 → `不动产租赁合同·审查`；动产点验/编号整章 → `动产租赁合同·审查`；工地湿租 → `建筑设备租赁合同·审查`；
- 无文本、本类型条件已谈妥、要出己方稿 → `不定期租赁合同·起草`；
- 已签只问收租日、腾退日、通知留痕 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼或仲裁 → `或对应专项领域。` 或对应专项领域。

规避限购、伪造占有、租赁物不存在或不交付只走资金：只出告知，不改写成可履行租赁。

房屋或动产上的不定期文本可以留在本任务，但只评改任意解除、通知期、默示更新后的结算。不得把本任务写成房产或动产的全套物审查。

## 建立审查坐标

确认：使用者与授权；单方立场（出租人侧或承租人侧择一）；相对方；全文及微信/收据/原定期合同版本；三种入口哪一种；数据电文是否已写清起止日；拟通知期与通知形式；租金按日或按月；押金与装修；是否融资或售后回租；不可接受事项；法域与拟签署日。缺立场或无可读文本（含无可核对的履行记录）则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的租金、通知天数、押金用 `【待填】`，不编造。不得把框架里的住房 30 日、厂房 60 日、设备 7 日写成法定期限。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验第 730、707、734、469、510、565、703、722、725、726 条，以及融资租赁切开、格式条款、定金上限、强制规范；`search_practiced` 只补审查反例；`search_template` 只借栏目结构。不虚构案件系统。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》租赁章、《城市房屋租赁管理办法》、《经济合同法》时记为噪声，不得写入 `L#`。实务书把“口头超六个月即不定期”写成不看“无法确定期限”的，记为不完整口径，不得当作第 707 条全文。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)
- [框架](references/框架.md)

禁止打开其他类型目录。`基本面.md` 尽调清单“610 条”按第 510 条理解。`框架.md` 把住房 30 日、厂房 60 日、设备 7 日列为数字化示例，不得写成法定固定天数。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `不定期租赁合同·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有不定期租赁文本，才进入本任务。

### 1. 类型锁死与三种入口

标题、核心给付与期限形态一致才继续。已写清起止日、融资租赁、售后回租负触发。留下本类型的，必须标明入口。

### 2. 主体与送达

签约名、履行名、收款名、发票名、解除通知接收人分列。送达地址未写：必须改。口头“发给中介就行”不得写成已到达。

### 3. 硬闸：随时解除须通知

补双方任意解除、合理通知期、到达规则、通知期内照常履行、期满返还。禁止当日清场和禁止解除。

### 4. 硬闸：未采用书面超六个月视为不定期

同时检验“应书面”“未采用书面”“期限无法确定”。数据电文已写清起止日：切开到定期或补成定期，不维持假不定期。

### 5. 租金、押金、装修与调价

按月/按日明确。单方随时调价必须改。押金绑腾退验收，不绑谁先提出解除。不定期项下固定装修须有残值公式。

### 6. 格式条款、强制规范与买卖不破租赁

只点出卖通知与解除通知不要混用。受让人承继的仍是不定期，仍须合理通知。无核验引文则法律结论字段停止。

### 7. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本且无履行记录仍要实体意见；用户坚持倒签、保证有效、无需通知当场清场、永久不得解除、把融资或售后回租改成双方随时终止、把口头超六个月写成合同无效仍要放行。
- `字段停止`：法域、动态规则、合理期限是否足够搬离、数据电文是否构成书面、受让人是否知悉、地方备案窗口未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。

生存级押金、预付租金或个人无限连带且用户拒绝升级：停止“可以签署”建议。
