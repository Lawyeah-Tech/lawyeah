# 独立保函·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、已失效《担保法》及其解释当作现行规则。不得把独立保函套用民法典一般保证或连带保证规定。不得把知识库“通常五个营业日”或“非金融机构开立一律连带”写成已核验法条。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **保证合同 / 独立保函**，输出可编辑草稿、未决项、自审风险表与自审后修改句。有完整待签或待开立文本要评改时，转 `独立保函·审查`。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。中文显示名为「独立保函·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类合同审查或起草；待签文本评改；履约交底；争议文书、止付申请或拒付策略；有效性保证；把非金融机构文本改成可履行独立保函；把从属保证或安慰函按本类型放行。

## 本类型硬闸

1. **独立保函 ≠ 普通保证 ≠ 安慰函**。正触发必须同时看见：银行或非银行金融机构开立；书面；载明据以付款的单据和最高金额；并且具备见索即付、载明适用国际商会《见索即付保函统一规则》等独立保函交易示范规则、或文本显示开立人仅承担相符交单付款责任三者之一。付款义务绑在基础交易违约事实、损失核定或法律裁判结果上 → `一般保证合同·审查` / `连带责任保证合同·审查`。仅知晓、关注、督促、尽合理努力、无单据无最高金额 → `安慰函·审查`。禁止打开或复制 `一般保证合同·审查` / `连带责任保证合同·审查` 的 method。
2. **开立人资格**。中国境内独立保函开立人限于银行或非银行金融机构。普通企业或自然人出具的“独立保函／见索即付”：不按本类型放行，不改写成可履行独立保函。独立性约定按担保制度解释第二条处理。剩余保证方式不得写成“一律连带”。
3. **独立性**。开立人的付款义务独立于基础交易关系和保函申请法律关系。开立人不得以基础交易或申请关系抗辩，独立保函规定第十二条欺诈情形除外。仅记载对应基础交易，不得据此改写成一般保证或连带保证。当事人主张独立保函适用民法典关于一般保证或连带保证规定的，现有依据不支持。国内交易约定独立保函，不得以无涉外因素否定独立性。
4. **单据表面相符**。标的是符合保函要求的单据，不是基础交易损失。必须写清单据名称、格式、签署人和提交路径。开立人只做表面审查。单据与保函条款之间、单据与单据之间表面上不完全一致，但不导致相互之间产生歧义的，仍可认定表面相符；不得写成必须逐字相符。知识库“通常五个营业日”不是法释〔2020〕18 号固定审单日；未并入示范规则前不得写成已核验法定期限。
5. **欺诈例外**。独立性不是绝对无例外。仅第十二条所列情形构成独立保函欺诈。人民法院裁定止付必须同时具备第十四条三项条件。以受益人在基础交易中违约为由请求止付，现有依据不支持。本任务只把例外写进文本风险和修改句，不代做止付申请、证据组织和胜率判断。
6. **语言不得混用**。统一使用“开立人义务／付款承诺”。严禁保留“连带责任保证”“根据主合同违约情况”“在债务人不能履行时”作为付款条件。核心已是相符交单的，不得仅因夹带“保证”二字整案降级；付款取决于裁判或损失核定的，不得仅因写了“独立／见索即付”按本类型放行。
7. **最高金额、有效期、转让与管辖必须特定**。缺最高金额或单据：当事人主张独立保函性质，现有依据不支持。未载明可撤销的，开立后原则上不可撤销。转让须同时载明可转让和据以确定新受益人的单据。管辖按独立保函关系确定，不得直接套基础交易争议条款。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

禁止表述：独立保函就是连带保证；基础交易违约即可止付；五个营业日已是法定期限；非金融机构开立一律连带；未写 URDG 也当然适用 URDG；独立保函适用一般保证期间或先诉抗辩；保证一定有效或相符交单一定获付。

## 工作边界

正触发：本类型条件已谈妥、要出己方保函稿，尚未开立／尚未签署，尚未成争，核心给付是金融机构开立人凭符合保函要求的单据向受益人付款；用户要己方草稿。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 已特定主债，先诉抗辩或“不能履行”为主线，无相符交单 → `一般保证合同·审查`；
- 已特定主债，明确连带责任保证，债权人可直接请求，无单据化付款 → `连带责任保证合同·审查`；
- 最高债权额 + 一定期间连续发生 → `最高额保证合同·审查`；
- 安慰函、维好协议、意愿书；仅知晓、关注、督促、尽合理努力 → `安慰函·审查`；
- 差额补足、流动性支持、回购承诺等增信主轴 → `增信措施类保证合同·审查`；
- 同一文本是单笔借款加保证，主从一体 → `保证借款合同·审查`；
- 普通企业或自然人出具“独立保函／见索即付” → 不按本类型放行；告知解释 2 后转 `一般保证合同·审查` / `连带责任保证合同·审查` 或标明 `unavailable`；
- 有完整待签文本要评改 → `独立保函·审查`；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已开立只问交单日、减额台账或失效日 → 本套导航的履约步骤；
- 已索赔、已拒付、已申请止付、已立案或开庭，或主问能不能止付／怎么拒付 → `或` 或 `或`。

伪造授权、倒签开立日，或把非金融机构文本改成可履行独立保函：只出告知，不改写成可履行规避结构。

## 建立审查坐标

确认：使用者与授权；单方立场（开立人／申请人／受益人择一）；相对方；全文及开立申请／反担保／基础合同引用版本；开立人是否金融机构及分支授权；单据清单原句；最高金额及币种；独立性／见索即付／URDG 原句；有效期或失效事件；转让与提交路径；不可接受事项；法域与拟开立日。缺立场或本类型条件未谈妥则不启动起草。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的金额、单据、日期用 `【待填】`，不编造。

## 起草模式

本原子只承担本类型起草。待签评改转 `独立保函·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务起草并自审。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。本类型硬闸改成正文必写、附件必附或禁止出现。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

### 起草必写

- 开立人为银行或非银行金融机构；书面；载明据以付款的单据和最高金额。
- 具备见索即付、载明适用国际商会《见索即付保函统一规则》等独立保函交易示范规则、或文本显示开立人仅承担相符交单付款责任三者之一。
- 统一使用“开立人义务／付款承诺”。
- 单据名称、格式、签署人和提交路径；开立人只做表面审查。
- 最高金额、有效期特定；未载明可撤销的，开立后原则上不可撤销。
- 转让须同时载明可转让和据以确定新受益人的单据。
- 管辖按独立保函关系确定，不得直接套基础交易争议条款。
- 欺诈例外仅按第十二条所列情形写入文本风险，不以基础交易违约为由止付。

### 附件必附

- 据以付款的单据名称、格式或样本。
- 开立人金融机构资格材料。
- 无对应事实不编造附件，缺项写入未决项。

### 禁止出现

- 普通企业或自然人出具的“独立保函／见索即付”改写成可履行独立保函。
- “连带责任保证”“根据主合同违约情况”“在债务人不能履行时”作为付款条件。
- 独立保函就是连带保证；适用一般保证期间或先诉抗辩。
- 基础交易违约即可止付。
- 五个营业日已是法定期限（未并入示范规则前）；未写 URDG 也当然适用 URDG。
- 保证一定有效或相符交单一定获付；非金融机构开立一律连带。
- 国内交易约定独立保函以无涉外因素否定独立性。
- 仅记载对应基础交易即改写成一般保证或连带保证。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)
- [框架](references/框架.md)

禁止打开其他类型目录。`基本面.md` 把“非金融机构开立一律认定为连带责任保证”、把“通常五个营业日”写成法定期限：按 method 纠正，不回写知识库。`框架.md` 把“根据主合同履行情况支付”或混用“连带责任保证”当可保留结构：按 method 当作必须清理的冲突句。

### 0. 签署状态与成果分流

无书面文本、条件已谈妥 → 留本任务起草；已开立只问交单或失效日 → 本套导航履约步骤；已索赔／已止付／已立案 → 争议或 `或`。有完整待签或待开立文本要评改时转 `独立保函·审查`。本类型条件已谈妥、要出己方稿，才进入本任务。

### 1. 类型锁死（独立性三件套）

标题、核心给付与独立保函三件套一致才继续。普通保证、最高额保证、安慰函、增信、保证借款、非金融机构文本负触发。

### 2. 开立人资格与主体

开立人是否银行或非银行金融机构；分支机构是否有书面授权。受益人、申请人名称与交单路径必须特定。

### 3. 独立性条款与混用语言

必须有独立性或见索即付或已并入示范规则。清理从属混用。仅记载基础交易背景不当然降级。

### 4. 单据表面相符

单据名称、格式、签署人、提交地址或 SWIFT。写明只审表面。不得要求开立人核实基础违约。

### 5. 最高金额、币种与减额

最高赔付金额及币种必须定量。预付款保函可约定随履行自动减额。区分保函金额与基础债务余额。

### 6. 有效期、失效与展期或付款

固定失效日或失效事件。盯死自动展期和“要么延期要么付款”。未载明可撤销则按不可撤销处理。

### 7. 欺诈例外披露、转让与管辖

欺诈例外按第十二条列明，不得写成基础违约即可拒付或止付。转让与管辖按独立保函关系写，不套基础合同。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。独立性句、单据清单句和最高金额句不得省略。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；条件未谈妥仍要出可签署终稿；用户坚持倒签、伪造授权、把非金融机构文本改成可履行独立保函、把从属保证或安慰函按本类型放行、把无单据或无最高金额文本按本类型放行、把基础交易违约写成已经可以止付、保证有效或保证相符交单一定获付。
- `字段停止`：法域、动态规则、开立人牌照、分支授权、URDG 是否并入、单据格式未核验。
- `目标停止`：主目标已变为待签评改、履约交底、争议文书、止付或拒付策略，或把本合同改成普通保证／安慰函。

生存级金额或跨境转开且用户拒绝升级：停止放行建议，只列风险与转介。
