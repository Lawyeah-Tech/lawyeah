# 审查方法（锁定 保证合同 / 独立保函）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止把 `一般保证合同·审查` 或 `连带责任保证合同·审查` 的 method 拼贴后换标题当作本文件。禁止套用先诉抗辩、保证期间起算或“约定不明按一般保证”作为本类型主路径。

本文件的主线是 **独立性 + 单据表面相符 + 欺诈例外**。缺一闸不得宣称审查完成。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受、相符交单一定获付、基础违约即可止付，或唯一必得金额。

`search_law` 返回已失效《合同法》及其解释、已失效《担保法》及其解释、法释〔2002〕38 号时记为噪声，不得写入 `L#`。把“五个营业日已是法定审单日”“非金融机构开立一律连带”“基础交易违约即可止付”写成现行规则的，同样记噪声。

示范文本只参考结构。检索到的保函范本同时存在“独立保函”和“非独立保函／连带责任保证”两类，不得把非独立保函栏目或保证期间句照抄当本约建议句。

知识库纠正（不回写双文件）：

- `基本面.md` 写非金融机构开立“会被依法认定为连带责任保证”：2026-08-18 `search_law` **未命中**“非金融机构开立独立保函＝连带责任保证”的现行条文。支持依据是独立保函规定第一条（开立人限于银行或非银行金融机构）＋担保制度解释第二条（普通担保中的独立性约定无效，金融机构独立保函另走独立保函规定）。剩余保证方式按核验后的文本意思分层，解释第二十五条只处理“不能履行／不履行／无条件”等保证合同用语，不得写成“一律连带”。
- `基本面.md` “通常为 5 个营业日”：法释〔2020〕18 号第六、七条未规定固定审单日。五日是知识库实务口径；只有保函载明，或第五条情形下示范规则被并入，才能写成约定期限。
- `基本面.md` “必须载明见索即付、独立于基础交易或明确适用 URDG”：第三条是**三选一**，并受“未载明单据和最高金额除外”但书约束，不是三项同时具备。
- `基本面.md` 把“独立”同时绑基础违约事实或法律裁判结果即降为普通保证：与第三条第二款区分。仅记载对应基础交易，现有依据不支持改写成一般或连带保证。付款义务本身取决于裁判结果、损失核定或“主合同履行情况”的，才不是本类型。
- `框架.md` “开立人仅需对单据进行表面相符审查”采用；“必须逐字相符”不得写成法定。第七条：表面上不完全一致但不产生歧义的，仍应认定表面相符。
- 国内交易可以约定独立保函。第二十三条：不得以无涉外因素否定独立性。

## 节点 1　独立性三件套识别与单目录加载

### 1.1 定性（本类型灵魂闸）

用标题、核心给付和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

必须同时满足才正触发：

1. **开立人是银行或非银行金融机构**（材料能回链牌照、名称或用户承认）。
2. **书面**，且载明**据以付款的单据**和**最高金额**。
3. **独立性外观三者之一**：载明见索即付；载明适用《见索即付保函统一规则》等独立保函交易示范规则；或文本显示开立人的付款义务独立于基础交易及申请关系，仅承担相符交单的付款责任。

缺第 1 项：不是本类型。缺第 2 项：当事人主张独立保函性质，现有依据不支持。缺第 3 项且付款取决于基础履行或裁判：按普通保证切开。

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 银行或保险公司开立；见索即付；书面索赔通知＋约定单据；最高金额确定 | 本类型 | 正触发；独立性、表面相符、欺诈例外都审 |
| 标题普通保函，正文却是相符交单、独立于基础交易 | 本类型 | 正触发；标题必须改正 |
| 仅记载对应基础交易名称，付款仍只取决于单据 | 本类型 | 正触发；不得仅因记载基础交易降级 |
| 已特定主合同；“不能履行”或先诉抗辩；无单据化付款 | 一般保证 | 负触发 `一般保证合同·审查` |
| 已特定主合同；明确连带责任保证；直接请求；无相符交单 | 连带责任保证 | 负触发 `连带责任保证合同·审查` |
| 最高限额 + 连续发生期间 | 最高额保证 | 负触发 `最高额保证合同·审查` |
| 知晓、关注、督促、尽合理努力；无单据无最高金额 | 安慰函 | 负触发 `安慰函·审查` |
| 差额补足、流动性支持、回购承诺为主给付 | 增信措施 | 负触发 `增信措施类保证合同·审查` |
| 同一文本是一笔借款加保证人签章 | 保证借款 | 负触发 `保证借款合同·审查` |
| 普通企业或自然人出具“独立保函／见索即付” | 非本类型 | 不放行。告知解释 2。不改成可履行独立保函 |
| 付款“根据主合同违约事实和法院判决确定” | 从属保证 | 负触发 `一般保证合同·审查` / `连带责任保证合同·审查` |

支持依据（运行时核验）：独立保函规定第一条、第三条；担保制度解释第二条。

### 1.2 加载协议（硬闸）

本技能已锁定 **保证合同 / 独立保函**。只打开 `references/基本面.md` 与 `框架.md`。禁止读其他类型目录，禁止为对照再开第二类。禁止打开 `一般保证合同·审查` / `连带责任保证合同·审查` 的 method。

### 1.3 规避结构停笔

加载后或定性中出现：伪造或补假开立授权；倒签开立日；把普通企业改成“视同金融机构”；把从属保证或安慰函外壳改成见索即付以规避从属性；把无单据、无最高金额文本包装成独立保函却拒补两项。

动作：

1. 交付告知：该结构不符合独立保函规定第一条、第三条或担保制度解释第二条，不得改写成可履行规避文本。
2. 不写假授权模板、倒签步骤、非金融机构独立保函路径。
3. 风险表只保留识别依据和删除／改正句。
4. 用户坚持“改到能开且仍规避”：整体停止。

## 节点 2　开立人资格与主体

### 2.1 主体表

建表：开立人、申请人、受益人、指示人／通知行（如有）、签约名、授权签字人。名称不一致不自动合并。交单地址、联系人、电传或 SWIFT 路径分列；缺失标 `G#`。

支持依据：独立保函规定第一条、第三条、第四条。

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 开立人为银行、保险公司、证券公司等金融机构，材料能回链 | 继续 | 已经具备一切开立资质 |
| 开立人为普通公司、自然人、政府机关 | 红线。不按本类型放行 | 改成可履行独立保函；一律连带 |
| 金融机构分支机构开立，未见总行或有权机构书面授权 | 必须改：授权作为附件；未获授权不对外发出 | 盖了分行保函章就可以 |
| 受益人或申请人名称与基础合同封面不一致 | 并列冲突；必须改到一致 | 按常用简称合并 |
| 口头“总行同意了” | 不得写成已授权 | 已经有权开立 |

申请人与开立人之间的开立协议、保证金或反担保：只审对保函正文放行的影响，不在本任务展开反担保整案。材料没有反担保不得写成“额度充足”或“已全额覆盖”。

### 2.2 开立、生效与不可撤销

支持依据：独立保函规定第四条。

- 开立时间为开立人发出独立保函的时间。
- 一经开立即生效，但保函载明生效日期或事件的除外。修改句把生效日／生效事件写清，并与开立日拆开。
- 未载明可撤销的，当事人主张开立后不可撤销，现有依据支持。用户要写成可撤销：必须显化撤销权人、通知方式和撤销前已交单的处理。

## 节点 3　独立性条款与混用语言

支持依据：独立保函规定第三条、第五条、第六条、第二十三条；担保制度解释第二条。

### 3.1 独立性必须可回链

审查清单，缺一项则不得写成独立性已锁定：

1. 见索即付，或已载明适用 URDG 等示范规则，或有“付款义务独立于基础交易及申请关系、仅承担相符交单付款责任”的等价句。
2. 排除“根据主合同履行情况支付”“引用主合同违约判定标准”“以法院或仲裁认定的损失为准”。
3. 基础交易只作背景识别，不引入实质性履行抗辩。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| “本保函项下开立人的义务独立于基础交易合同或申请关系；开立人的付款义务不因申请人对基础合同的任何异议而受影响” | 可接受；继续审单据 | 已经有效 |
| 载明适用 URDG758 或 ISP98 | 可接受。第五条：载明或一审辩论终结前一致援引，示范规则才构成条款 | 未载明也当然适用 URDG |
| 只写“独立、无条件、不可撤销”，无单据无最高金额 | 红线。第三条但书 | 已经是独立保函 |
| 写了见索即付，又写“根据主合同违约和判决支付” | 核心给付已从属。负触发普通保证，或红线删除从属付款条件 | 留“独立”二字即可放行 |
| 夹带“连带责任保证／保证人承担保证责任”，但付款仍只取决于书面索赔通知和约定单据 | 必须改：删除保证内涵词汇，统一为开立人付款承诺 | 仅因“保证”二字整案降级；或假装没有冲突 |
| 当事人以记载了基础交易为由主张一般或连带保证 | 现有依据不支持该主张 | 记载基础交易＝已经是普通保证 |
| 主张适用民法典一般保证或连带保证规定 | 现有依据不支持 | 套用 686／687／692 |
| 国内交易，一方以无涉外因素主张独立性无效 | 现有依据不支持 | 国内不能开独立保函 |

开立人立场：修改句锁死“仅审核单据表面，不对基础交易作实质性调查”。申请人立场：同一句必须保留，并提示一旦相符交单将先行扣款。受益人立场：不得接受开立人保留“有权审查基础违约是否成立”。

### 3.2 示范规则并入

未载明、双方也未一致援引：不得把 URDG 审单日、交单地细则写成已经并入。修改句给出选项：显化并入 URDG758／ISP98，或在保函正文写尽单据、审单标准和提交路径。

## 节点 4　单据表面相符

本节点是本类型的标的闸。标的是**符合条件的单据**，不是基础交易损失。

支持依据：独立保函规定第一条第二款、第三条但书、第六条、第七条。

### 4.1 单据必须特定到可执行

单据包括：付款请求书、违约声明、第三方签发的文件、法院判决、仲裁裁决、汇票、发票等表明发生付款到期事件的书面文件。出现“法院判决／仲裁裁决”作为单据时，必须写成**受益人应提交的文件**，不得写成开立人有权等到裁判结果再决定是否付款。

审查清单，缺一项则标必须改：

1. 书面索赔通知或付款请求书的名称、份数、语言。
2. 附加单据名称（监理确认书、违约声明、发票等）、出具人和签章要求。
3. 提交地点、联系人、可接受的电传／SWIFT／纸质路径。
4. 有效期内提交；逾期提交的后果。
5. 审单标准：仅表面相符；单据之间不产生歧义即可。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| “受益人提交书面索赔通知及【待填】即可请求付款；开立人仅审核单据表面是否相符” | 可接受或可优化 | 已经没有不符点风险 |
| “提交相关证明材料”“适当文件” | 必须改到具体名称和签署人 | 已经可执行 |
| “开立人有权调查基础交易是否违约后再付款” | 红线删除。与第六条冲突 | 更审慎所以可留 |
| “单据必须逐字相符，任何差异均可拒付” | 必须改。第七条：不产生歧义仍构成表面相符 | 已经是法定审单标准 |
| “开立人应在五个营业日内审单” | 可作约定句。未并入 URDG 时不得写成法定 | 法释〔2020〕18 号已规定五日 |
| 未写单据，也未写最高金额 | 红线。不按本类型放行 | 独立二字已够 |

受益人侧：单据格式越具体，索赔越可执行，也越容易因细微差异被拒。修改句在可执行与防拒付之间显化，不替用户选唯一格式。开立人侧：模糊单据会失去表面审查抓手。申请人侧：模糊单据等于扩大现金敞口。

### 4.2 开立人不得把基础关系当抗辩

第六条：单据表面相符的，受益人请求付款应予支持。开立人以基础交易关系或申请关系抗辩的，不予支持，但第十二条除外。

禁止建议句：“如申请人证明受益人在基础合同项下构成违约，开立人有权拒付”。允许风险句：提示申请人关注第十二条欺诈例外和第十四条止付条件，并写明基础违约本身不够。

## 节点 5　最高金额、币种与减额

支持依据：独立保函规定第一条、第三条但书。

1. 最高赔付金额须有阿拉伯数字和大写，并写明币种。
2. 区分**保函金额**与**基础债务余额**。保函语言围绕单据提交，不写成“以基础合同未付余额为准，但最高不超过”。
3. 预付款或分期履行类保函，可约定随交付、进度或已返还预付款自动按比例减额，并写明减额凭证和生效时点。
4. 空白、另议、以实际损失为准且无上限：红线。不按本类型放行。

超出最高金额的部分，现有依据不支持开立人付款。本任务不计算已减额余额，只要求文本写清减额机制。

## 节点 6　有效期、失效与展期或付款

支持依据：独立保函规定第四条。有效期是权利存续期间，不是民法典保证期间。禁止套用第六百九十二条、第六百九十三条或“还清为止视为六个月”。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| 明确失效日期，或明确失效事件（如退回原件、收到书面免责声明、货款结清且提交约定单据） | 可接受 | 已经不会发生逾期索赔 |
| 未写失效日也未写失效事件 | 必须改，避免永续 | 开立人可随时注销 |
| “保函原件退回是唯一注销条件” | 必须改：原件退回不是唯一失效条件 | 受益人持有原件＝永久有效已是法定 |
| 自动展期，或“要么延期要么付款”（Extend or Pay） | 红线或必须改。申请人侧提示现金敞口被拉长；受益人侧若保留须写清通知时点、展期次数和上限 | 银行惯例所以当然可留 |
| 用户要本任务认定有效期是否已经届满 | 目标停止，转履约或争议 | 已经失效／尚未失效 |

## 节点 7　欺诈例外披露、转让与管辖

### 7.1 欺诈例外：写进文本，不写策略

支持依据：独立保函规定第十二条、第十四条、第十八条。

第十二条应当认定构成独立保函欺诈的情形：

1. 受益人与申请人或其他人串通，虚构基础交易；
2. 受益人提交的第三方单据系伪造或内容虚假；
3. 法院判决或仲裁裁决认定基础交易债务人没有付款或赔偿责任；
4. 受益人确认基础交易债务已得到完全履行，或确认保函载明的付款到期事件并未发生；
5. 受益人明知其没有付款请求权仍滥用该权利的其他情形。

第十四条：裁定中止支付必须同时具备：止付申请人提交的证据证明第十二条情形存在具有**高度可能性**；情况紧急，不立即止付将造成难以弥补的损害；止付申请人提供了足以弥补被申请人因止付可能遭受损失的担保。

硬闸：

- 止付申请人以受益人在基础交易中违约为由请求止付的，人民法院不予支持。
- 开立人在依指示开立的独立保函项下已经善意付款的，对保障该开立人追偿权的独立保函，不得裁定止付。
- 知识库“恶意索赔、基础交易已完全履行或因受益人原因无法履行”只是第十二条的概括，修改句应回链具体项，不得另造第六项。
- 本任务可以：在保函中明确单据格式、虚假索赔的违约或赔偿责任说明、欺诈例外不改变表面审单义务。
- 本任务不可以：判断本案是否已构成欺诈；撰写止付申请；评估高度可能性；指导伪造紧急情况。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| “除独立保函规定的欺诈情形外，开立人不得以基础交易抗辩” | 可接受 | 已经没有欺诈风险 |
| “受益人在基础合同项下违约的，开立人有权拒付或申请人有权申请止付” | 红线删除 | 第十四条第二款的反面已经是法定权利 |
| 用户要“写到法院一定止付” | 拒绝保证；目标停止 | 欺诈例外很容易成立 |

第九条：开立人依据独立保函付款后向申请人追偿，应予支持，但单据存在不符点的除外。签署提醒可写：开立人审单留痕；申请人关注不符点。不在本任务展开追偿诉讼。

### 7.2 转让

支持依据：独立保函规定第十条。

未同时载明可转让和据以确定新受益人的单据，开立人主张受益人付款请求权的转让对其不发生效力，现有依据支持。通常约定不得转让，或经开立人书面同意后转让。用户要可转让：必须补确定新受益人的单据。

### 7.3 管辖与适用法

支持依据：独立保函规定第二十一条。

- 受益人与开立人因独立保函产生的纠纷：开立人住所地或被告住所地法院管辖，保函载明其他法院或仲裁的除外。
- 当事人主张根据基础交易合同争议解决条款确定管辖或仲裁：现有依据不支持。
- 欺诈纠纷：被请求止付的独立保函开立人住所地或被告住所地管辖，书面协议另定除外；不得改套基础合同或保函中的普通付款管辖条款来争夺欺诈管辖。

或裁或诉、机构不明：标待核，改成单一仲裁机构或单一法院连结点。出现仲裁条款：不得改写成“应向某法院起诉”并假装已选定诉讼。框架建议“开立人所在地法院”可作为谈判句，不是法定唯一解。

通知送达：写明物理地址和电传／SWIFT。不得把微信已读写成已经送达的唯一充分条件。

示范修改句（独立性＋单据）：

`定位付款条件｜原文：本保函为见索即付，开立人承担连带保证责任，并根据主合同违约情况和法院判决支付｜建议改为：本保函为不可撤销的见索即付独立保函。开立人在受益人于有效期内向【待填地址／SWIFT】提交下列单据且单据表面相符时，在最高金额【待填】内付款：（1）书面付款请求书；（2）【待填第三方单据名称及签署人】。开立人的付款义务独立于基础交易及保函申请关系，不对基础交易作实质性审查。开立人不是保证人，不适用民法典关于一般保证或连带保证的规定。｜理由：L# 独立保函规定第一条、第三条、第六条｜可退让点：可谈判增加一项具体单据，不得改回按判决付款｜不接受时的红线：拒删“根据主合同和判决支付”仍要按独立保函放行`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或不发出（非金融机构开立、无单据或无最高金额、付款绑裁判或损失核定、基础违约即可止付、倒签或假授权、把安慰函或普通保证按本类型放行）；
- `必须改`：可谈但开立前要落句（混用保证词汇、单据名称不具体、未写表面相符、有效期空白、转让或管辖套基础合同、五日被写成法定）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级金额或跨境转开且用户拒绝升级：停止“可以开立／可以接受”建议。
