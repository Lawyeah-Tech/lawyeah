# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的差额、利率、回购价；把已失效《合同法》《担保法》及其解释写入结论；写“标题不叫保证就不是保证”；写“增信当然连带”；写“增信没有保证期间”；写“改名即可免决议”；写“脱钩条款必然有效”；写“无效一律只赔二分之一”；把安慰函、独立保函、单笔保证或最高额文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查增信措施类保证合同（保证合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》或其解释、已失效《担保法》或其解释、1993 年公司法旧第十五条时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `保证合同`，子级 `增信措施类保证合同`。定性理由、易混切开结果（安慰函／独立保函／一般保证／连带责任保证／最高额保证／保证借款）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。解释第三十六条落入哪一层必须写明。

## 4. 主体、决议、禁止主体与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。决议表：是否覆盖本增信事项、对象、额度、期限；是否关联担保；上市公司是否披露。禁止主体：机关、政府及其所属部门、公益法人。版本表：正文、基础合同或计划说明书、核算口径、决议、签收页、聊天确认；冲突并列。

## 5. 产品分型、给付闭环与期间／方式

差额补足／流动性支持／回购是否分清；付给谁；触发；公式；通知与时限；限额。落入保证时：方式是否显化、期间是否具备、范围是否与差额基数一致。落入债务加入或第四款时：写明不适用保证期间或不得按保证请求。缺口标 `G#`。不输出独立保函相符交单口径，不输出最高额两套期间口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。政府隐性债务、机关／公益增信、假决议不得写成可放行。强制规范只按第一百五十三条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把弱意愿词直接写成“保证类型”而不问是否有代偿意思。不得把对债务人输血直接写成向债权人付款。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为安慰函或独立保函、政府／机关／公益主体、无决议拒补、公式不能算、假决议／倒签、脱钩条款拒删），再必须改（四层显化、付给谁、触发与公式、期间与方式、决议附件、范围列举），最后可优化。签署提醒：针对该增信事项的决议原件或盖章件、法定代表人或授权代表签字、骑缝、基础合同与核算口径附件、债权人签收页（单方函时）。不指导倒签或把未决议写成已经有效。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务只出审查意见与修改句，不出整份起草终稿。无文本出稿转配对起草原子。不是履约交底、争议文书或效力保证，也不是安慰函、独立保函、单笔保证或最高额安排。
