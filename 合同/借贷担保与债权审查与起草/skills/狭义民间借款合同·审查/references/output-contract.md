# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的本金、利率、期限、账户；把已失效《合同法》及其解释写入结论；把 24%、36% 或银行利率旧四倍写成现行上限；把整类写成未放款即未成立；把有企业参与的利息约定不明写成必然无息；把职业放贷写成可履行放贷；把狭义和广义写成同一套方法。

## 1. 触发、单方立场与成果状态

立场（出借人、借款人、拟签字的企业负责人或配偶）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明主体组合（自然人/企业）以及有无平台、小贷或持牌外观。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1991 年借贷意见、2015 年 24%/36% 条文或已被删除的旧第 10 条成立规则时记噪声，不得写入 `L#`。成立分岔、670、第 24/25/28/29 条、第 13 条无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `借款合同`，子级 `狭义民间借款合同`。定性理由必须同时满足：出借人是一般企业或自然人；非持牌、非准金融、非平台撮合；核心给付为临时性货币融通。

易混切开必须写明结果：广义平台/小贷 → `广义民间借款合同·审查`；双方自然人生活互借 → `自然人之间的借款合同·审查`；双方企业经营性拆借 → `企业间借款合同·审查`；持牌机构 → `金融机构借款合同·审查`；担保主文件 → 对应原子。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。职业放贷、转贷或违法用途写停笔告知，不填可履行放贷结构。

## 4. 主体、授权、资质与文本版本

主体表：出借人、借款人、指定收款账户名、引用中的担保人或配偶。自然人写身份信息是否被文本载明；法人写名称与统一社会信用代码是否被提及。企业出借人单列“是否呈现经常性、营利性放贷外观”，不得写成已经构成或已经不构成职业放贷。

版本表：正文、借据、收款收据、账户页、聊天确认。冲突并列，不选对用户有利的一版。口头“我们不是职业放贷”“配偶已经同意”不得写成已核验。

## 5. 借贷给付闭环

分列并回链文本位置：

- 本金：阿拉伯数字与大写、币种。
- 到账：面额、预扣利息/咨询费/保证金、实际收款人是否就是借款人。
- 成立与生效：是否写成签字成立，或写成未放款即未成立。必须标出主体组合后再选 679 或诺成路径。
- 利息：有约定 / 未约定 / 约定不明，三者不得混写；有企业参与时约定不明不得写成无息。
- 利率与费用：年利率或月利率、起息日、复利是否另约、逾期利息、违约金、律师费；是否可能突破合同成立时一年期 LPR 四倍。
- 期限与还款：起算绑实际放款日还是签约日；一次性或分期；还款顺序；提前还款。
- 用途与资金来源：合法具体用途；出借资金是否被文本或材料指向自有资金。
- 担保与配偶引用：合同名称编号是否指向本债；空白保证方式不得写成已连带。

缺口标 `G#`，不补商业数字。批准、登记、内部决议写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

企业出借人预先拟定且未协商的文本，按格式条款审查提示说明。加速到期、单方认定违约、送达拟制未显著提示的，标必须改。

强制规范与效力红旗只在核验后落法律结论：职业放贷；套取信贷转贷；非法资金来源转贷；明知违法用途；套路贷外观。不得用“两年 10 人”代替法释第 13 条第 3 项三要件。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：是否误入广义平台路径；主体组合与成立条款是否匹配；砍头息或面额与到账不一致；利率或息费总和是否可能超四倍；利息约定不明是否被误写成无息或误写成有息；用途或资金来源红旗；无理由加速到期；担保或配偶引用未闭环。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：标题不用投资/平台贷款；成立与放款按主体组合分列；到账本金；明确年利率或月利率并锁四倍总和；用途正反说；加速到期绑定违约事件与催告；担保和配偶只补引用闭环。

## 9. 谈判与签署提醒

谈判顺序：先红线（职业放贷外观、转贷、违法用途、倒签、超四倍、无理由随时收回），再必须改（成立分岔、砍头息、利息写清、用途与账户、格式提示），最后可优化。

签署提醒：自然人亲笔签名并按指印；企业公章加法定代表人或授权人；日期真实；附件含身份证或证照复印件、指定账户、拟作为附件的转账回单或收据、被引用的担保或配偶文件。打款备注写明“借款”并打到借款人本人账户。不指导倒签或补假资金来源。

出借人立场可建议转账交付、收据确认到账、用途监督，但混主体或企业侧合同不得写成“未放款即未成立”。借款人立场必须提示：面额大于到账时按到账抗辩；息费总和可能被调减到四倍；签字后若主体组合走诺成，可能产生请求放款或迟延放款责任。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务只出审查意见与修改句，不出整份起草终稿。无文本出稿转配对起草原子。不是履约交底、争议文书、利息精算终局或效力保证。
