# 边界与路由

本技能只审查 **保证合同 / 安慰函** 的待签文本。中文展示名是「审查安慰函（保证合同）」。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符 | 本套导航的类型切开步骤 |
| 已具备完整保证结构；先诉抗辩或“不能履行”为主线；无安慰／维好姿态 | `一般保证合同·审查` |
| 明确连带责任保证；债权人可直接请求；完整保证合同结构 | `连带责任保证合同·审查` |
| 最高额保证；一定期间连续发生；最高债权额限度 | `最高额保证合同·审查` |
| 独立保函；见索即付；URDG／ISP98；金融机构相符交单付款 | `独立保函·审查`；专业版未装则 `unavailable`，提示，不得用本技能硬套 |
| 差额补足、流动性支持、回购承诺等增信**主文件**（双边、有金额／触发／付款日） | `增信措施类保证合同·审查`；专业版未装则 `unavailable` |
| 同一文本是单笔借款主文加保证从债 | `保证借款合同·审查` |
| 主文件是金融机构借款、民间借贷等，函件只是名称混用 | 对应借款场景原子；本任务不审利率或放款条件整案 |
| 有完整待签文本要评改 | `安慰函·审查` |
| 无文本、本类型条件已谈妥、要出己方稿 | 留本任务起草并自审 |
| 已签未争、只问主张日、送达或履约节点 | 本套导航的履约步骤 |
| 已催告、索赔、立案、开庭，或主问这封函能不能追、责任是否消灭、怎么起诉 | `或` 或 `或` |
| 企业融资整包、对赌或结构化增信要放行意见 | `企业融资整包对赌或结构化增信要放行意见`；本任务不放行融资结构 |
| 配偶是否共同债务 | 只标缺口；整案 `配偶是否共同债务` |
| 追股东或法人格 | `追股东或法人格` |
| C 端大众快检 | 只分流，不回改 |

安慰函里夹带一句“见索即付／效力独立于主合同”：不在本类型改成独立保函。删除或改正该句后，若其余仍是支持／维好姿态则继续审；用户坚持改成见索即付独立保函：`目标停止`，转 `独立保函·审查` 或标明 `unavailable`。

安慰函里夹带一句“将提供流动性支持／维持净资产”：留在本任务，按解释第三十六条审意思。用户交出的是已写明差额、触发日和付款日的《流动性支持协议》或《差额补足协议》：负触发 `增信措施类保证合同·审查`。

用户坚持把软安慰改成“代为清偿／本文件构成保证担保”并仍要本技能出具可签署意见：`目标停止`，转 `一般保证合同·审查` 或 `连带责任保证合同·审查`。不得在本技能把安慰函写成保证后宣称审查完成。

标题写“安慰函”、正文已是完整保证条款：按核心给付负触发对应保证原子，不留在本任务做软。
