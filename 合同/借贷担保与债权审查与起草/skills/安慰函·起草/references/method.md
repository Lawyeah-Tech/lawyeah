# 审查方法（锁定 保证合同 / 安慰函）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止把 `一般保证合同·审查`、`连带责任保证合同·审查`、`最高额保证合同·审查` 或 `保证借款合同·审查` 的 method 拼贴后换标题当作本文件。禁止套用买卖验收、定金比例、保证期间或先诉抗辩主路径。

本文件的主线是 **是否具备保证意思**，以及 **道义支持与保证分开**。见索即付独立保函和差额补足等增信主文件必须在加载前切开。缺一闸不得宣称审查完成。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、必然是保证、必然只是道义、对方必然接受，或唯一必得金额。

`search_law` 返回已失效《合同法》及其解释、已失效《担保法》及其解释、法发〔1994〕8 号时记为噪声，不得写入 `L#`。把解释第八条写成“是否具有担保意思”的，同样记噪声。

示范文本只参考结构。检索到的承诺函若是保密函或资管份额流动性支持，不得照抄当本约建议句。

知识库纠正（不回写双文件）：

- `基本面.md` 写“根据《民法典担保制度司法解释》第8条，判断关键在于是否具有提供担保的意思表示”：2026-08-18 `search_law` 核验，解释**第八条**是公司未作对外担保决议时仍可能承担责任的**例外**（金融机构保函、全资子公司、三分之二表决权股东签字；上市公司不适用后两项）。**不是**担保意思条文。承诺文件定性走解释**第三十六条**，定义走第六百八十一条。
- `基本面.md`／`框架.md` 债权人“做硬”：把“负责督促”改成“负责清偿”、增加“见索即付”或“放弃一切抗辩”、写“本文件构成保证担保”。这是把安慰函写成保证或独立保函，**禁止作为本技能建议句**。债权人要真正保证 → 转 `一般保证合同·审查`／`连带责任保证合同·审查`；要见索即付 → 转 `独立保函·审查`。
- `基本面.md` “政府出具的安慰函若涉及行政增信通常无效”：须先完成意思分层。仅道义姿态不是保证，不走“保证无效”。硬词可能被解释为保证时，才适用第六百八十三条和解释第五条；仍不得改成可履行机关保证。
- `基本面.md` “缺失决议可能导致安慰函对公司不产生约束力”：仅在可能被定性为担保或债务加入时适用解释第七、八、九、十二条。软安慰不得假装已经需要担保决议才成立。
- `框架.md` “若构成保证则审查保证期间”：本任务不展开保证期间、方式和先诉抗辩主路径。提示“一旦被认定为保证，期间和方式将另受保证规则约束”，需要评改保证结构则转出。
- `基本面.md` 追偿权空白：只有构成保证或债务加入后才讨论追偿。保证追偿不在本任务展开；债务加入追偿可点名合同编通则解释第五十一条，不代替修改句。软函谈不上保证追偿。
- 公司决议条号：2023 年修订公司法第十五条（2024-07-01 施行）。知识库未写条号或旧第十六条，运行时并列说明。
- 本任务审查的是拟在民法典施行后签署或出具的新文本。不得给待签稿套用失效担保法。

## 节点 1　类型识别与单目录加载

### 1.1 定性（本类型灵魂闸之一）

用标题、核心给付和用户陈述定性，**不用标题单独定性**。名实不符时按核心给付归类，标题冲突写入 `C#`。

必须同时满足才正触发：

1. **第三人姿态**：出具人不是主债务人本人，而是母公司、关联方、机关或其他第三方向债权人表态。
2. **支持／维好／意愿／知晓**：核心是对债务人清偿能力、持股、经营或履约的关注、督促、维好或类似姿态，而不是一份已经写完保证方式、保证期间和主债权清单的保证合同。
3. **不是独立保函，也不是增信主文件**：无见索即付／URDG／相符交单结构；也不是以差额、触发日、付款日为给付闭环的双边增信协议。

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 《安慰函》《支持函》《知晓函》《意愿书》《维好协议》；知悉、督促、合理努力、保持控股、维持清偿能力 | 本类型 | 正触发；进入意思分层 |
| 标题安慰函，正文出现代为清偿、负责解决欠款、不使债权人受损 | 本类型（硬安慰） | 正触发；标担保意思；**不改写成保证合同** |
| 标题担保函，正文仅知晓、督促、合理努力 | 本类型 | 正触发；标题必须改正；不得因标题写成已经是保证 |
| 《一般保证合同》／《连带责任保证合同》，含方式、期间、主债权 | 单笔保证 | 负触发 `一般保证合同·审查` 或 `连带责任保证合同·审查` |
| 最高限额 + 连续发生期间 | 最高额保证 | 负触发 `最高额保证合同·审查` |

| 同一文本是一笔借款加保证人签章 | 保证借款 | 负触发 `保证借款合同·审查` |
| 单独的股权回购承诺／EAL 作为主给付 | 增信措施 | 负触发 `增信措施类保证合同·审查`。Keepwell 正文仍可留本类型 |

## 节点 2　保证意思分层（本类型灵魂闸）

支持依据（当次 `search_law` 写入 `L#`）：担保制度解释第三十六条；民法典第六百八十一条。运行时必须核验。核验失败则效力字段停止，摘录和修改句草稿继续。

规则形状：

1. 第三人向债权人提供差额补足、流动性支持等**类似承诺文件**作为增信措施，**具有提供担保的意思表示**，债权人请求承担保证责任的，依照保证的有关规定处理。
2. 承诺文件具有加入债务或与债务人共同承担债务等意思表示的，认定为第五百五十二条债务加入。
3. 前两款难以确定是保证还是债务加入的，认定为保证。
4. 不符合前三款的，债权人请求承担保证责任或连带责任，人民法院不予支持；但不影响依据承诺文件请求履行约定的义务或承担相应的民事责任。
5. 第六百八十一条用于核对“不履行或约定情形时履行债务或承担责任”是否出现。

### 2.1 软词（道义或经营支持）

| 文本迹象 | 判断形状 | 本任务动作 |
| --- | --- | --- |
| 知悉、知晓、关注、了解该笔融资 | 现有依据不支持按保证或连带责任请求 | 必须改出口径：保持软词；出具人侧加反说“不构成保证或法律担保义务”；债权人侧提示纸面安慰风险，**不得在本类型改成代为清偿** |
| 督促、促使、协助、尽商业上合理努力 | 同上 | 同上。不得把“努力”解释成已经承诺代偿 |
| 保持股权比例、维持控股、不撤资（无代偿） | 通常为经营承诺 | 说明一般仅具债权效力，不当然对抗第三人；不写成保证 |
| 维持债务人正常经营／清偿能力，无付款机制 | 依据不足，无法写成保证 | 分层说明；债权人若要可执行担保必须转出 |

出具人侧示范修改句（做软，允许）：

`定位承诺条款｜原文：本公司将督促子公司履行还款义务，并在必要时提供支持｜建议改为：本公司知悉该项融资。本公司将在商业上合理的范围内促使债务人保持正常经营。本函仅表达经营关注与意愿，不构成民法典第六百八十一条项下的保证，也不构成第五百五十二条项下的债务加入。债权人不得依据本函请求本公司承担保证责任或连带责任。｜理由：L# 解释第三十六条第四款、第六百八十一条｜可退让点：可保留“督促还款”但不加付款后果｜不接受时的红线：对方坚持写入代为清偿或见索即付仍要本类型放行`

### 2.2 硬词（具有担保意思）

| 文本迹象 | 判断形状 | 本任务动作 |
| --- | --- | --- |
| 代为清偿、承担保证责任、承担连带责任 | 现有依据支持认定具有担保意思 | 红线或必须改。出具人侧删除硬词并改回软词＋反说。债权人侧：要真正保证则转 `一般保证合同·审查`／`连带责任保证合同·审查`，**本任务不改写成保证合同** |
| 负责解决欠款、不使债权人受损、承担兜底责任 | 极易被认定为代偿意思 | 同上。必须把原句摘入风险表 |
| 债务人未能如期支付则由本方在收到通知后 X 日内代为清偿 | 保证型表述 | 不得按框架做硬保留。转出或删除 |

禁止建议句：“若债务人未能如期支付，由本方在收到通知后【待填】日内代为清偿”“本文件构成民法典项下的保证担保”“见索即付／放弃一切抗辩权”。

### 2.3 债务加入与难分

| 文本迹象 | 判断形状 | 本任务动作 |
| --- | --- | --- |
| 加入该笔债务、与债务人共同承担、本公司亦为债务人 | 现有依据支持按 552 审查 | 标债务加入。提示解释第十二条：以公司名义加入可参照对外担保规则。本任务不把函改成债务加入协议整稿 |
| 既像代偿又像共同承担，无法择一 | 解释 36 第三款：认定为保证 | 写明“难以区分时依法按保证认定”的**风险**，仍不改写成保证合同 |
| 用户要求本任务在保证与加入之间选定对用户有利的一种并放行 | 现有依据不支持自行选取 | 并列；难分按保证认定风险提示 |

### 2.4 第四款残余义务

软函被排除保证和连带责任后，解释第三十六条第四款仍可能支持“依据承诺文件请求履行约定的义务或承担相应的民事责任”。不得写成“软函 = 废纸 = 零义务”。修改句把约定义务（如保持持股、通知、合理努力）写到可核验、可停止的程度，同时保留“不构成保证”反说。

## 节点 3　主体、禁入与决议

### 3.1 主体表

建表：债权人、债务人、出具人、签约名、授权签字人。名称不一致不自动合并。记录出具人与债务人是母子公司、实际控制还是机关隶属。材料没有则标 `G#`，不得写成“资产充足”或“当然有权代表集团”。

口头“我们老板同意了”不得写成已授权。

### 3.2 机关与公益（硬闸）

支持依据：第六百八十三条；解释第五条、第六条。

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 出具人为机关法人，函内仅知晓、关注 | 可保留软姿态；必须写明不构成保证；提示行政协调不等于民事担保 | 已经是有效机关保证；已经整函无效 |
| 出具人为机关法人，函内有代偿、负责解决、不使受损 | **红线**。只出告知：若被解释为保证则因主体不适格而不能成立保证责任。不改成可履行机关保证 | 加个决议就能签；改成融资平台盖章即可 |
| 公益性学校、医院、养老机构出具硬函 | 红线。解释第六条例外不在本任务展开成可签保证 | 学校医院“改个名称就能保证” |
| 登记为营利法人的民办学校／医院 | 不得仅以名称否定担保资格；仍核意思分层和决议 | 当然无效或当然有效 |
| 用户称国务院已批准转贷 | 须见材料，否则 `G#` | 口头批准即除外 |

### 3.3 可能构成担保或加入时的决议与披露

支持依据：2023 年修订公司法第十五条；解释第七、八、九、十二条。

先完成节点 2。**软安慰且无硬词、无加入词：不强制按担保决议放行，但债权人若要把函当作担保使用，必须提示一旦被认定则决议和披露仍可能被追问。**

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 硬词或加入词已出现，公司出具，未见章程指定的董事会或股东会决议 | 必须改：删除硬词，或转保证／加入路径并补决议；未闭合前不放行 | 法定代表人签字即对公司发生担保效力 |
| 为股东或实际控制人的债务出具硬函 | 须股东会决议且关联股东回避 | 董事会决议即可 |
| 出具人为上市公司或已披露的控股子公司 | 解释第九条：未按公开披露的已决议信息订约，公司可主张不发生效力且不承担担保或赔偿责任 | 未披露也一定有效 |
| 相对人主张解释第八条例外 | 材料能回链才标可能例外；上市公司不适用第八条第二、三项 | 无决议一律放过或一律无效 |
| 仅软词，用户要求“按担保决议走一遍才踏实” | 可作债权人优化：把决议当形式审查附件，但不把软函写成已经是担保 | 已经构成担保所以必须有决议 |

自然人出具硬函：记录配偶是否签署。未签不得写成“一定不是共同债务”。生存级个人兜底措辞且用户拒绝升级：停止“可以签署”建议。

## 节点 4　单方函、接收与基础关系

支持依据：第六百八十五条；第四百九十条。

1. 安慰函通常是单方文件。修改句要求载明致送对象、主债权或授信合同名称和编号、出具日。
2. **仅当节点 2 已认定具有保证意思**，才适用第六百八十五条第二款：债权人接收且未提出异议的，保证合同成立。软函不得写成“接收即保证成立”。
3. 债权人侧可要求书面签收或回函确认**收到**该函，并写明确认范围（知悉／不视为接受保证／或已转保证原子后的接受）。出具人侧可要求回函不得被解释为接受保证。
4. 不得写成口头一律无效；也不得保证微信一句即成立且已构成保证。
5. 函件是否作为主协议附件：写清冲突时以哪一份为准。主协议写“保证人见附件安慰函”而函内只有软词：并列冲突，不选有利版。

用户要求倒签出具日或“先盖章后补决议”：整体停止。

## 节点 5　支持方式、从属性提示与夹带句

本节点只处理函内姿态，不把函升级为增信主文件。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| 资金不足时注入资金、提供流动性，无金额无付款日 | 留本类型；按节点 2 审是否滑向担保意思 | 已经是可执行流动性支持协议 |
| 已写明差额、触发日、五个工作日付款 | 核是否应负触发 `增信措施类保证合同·审查` | 按安慰函做软，删掉付款机制后宣称审完 |
| 债务清偿前不转让股权、维持净资产不低于【待填】 | 经营承诺；说明通常仅债权效力 | 已经具有对抗第三人的物权效力 |
| 不抵押承诺（Negative Pledge） | 标债权效力；不写成已设立担保物权 | 已经优先于后设抵押 |
| “本函独立于主合同／见索即付／放弃一切抗辩” | 必须改。普通担保独立性约定按解释第二条无效；见索即付结构转 `独立保函·审查` | 改成可履行独立保函仍按本类型放行 |
| 跨境 Keepwell + 另页 EAL | Keepwell 留本类型；EAL 主文件转 `增信措施类保证合同·审查`。域外法字段停止 | 输出域外法下 Keepwell 必然可执行 |

若节点 2 已标担保意思：提示从属性（第六百八十二条）——一旦被认定为保证，主债无效则保证无效（法律另有规定除外）。修改句删除独立性用语。不在本任务计算保证期间或填写一般／连带方式。

追偿：软函不写保证追偿。出具人侧若保留任何可能被执行的支付承诺，可另约向债务人追偿；不把法定保证追偿写成已经发生。

## 节点 7　格式条款、争议解决与语言

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

- 格式条款、提示说明：仅在函件由一方反复使用时点名。无核验引文不写无效结论。
- 争议解决：或裁或诉、机构不明则改成单一连结点。出现仲裁条款不得改写成已选定诉讼。用户追问胜率：目标停止，转争议或评估原子。
- 准据法：默认中国大陆。约定域外法且用户要直接给域外 Comfort Letter 结论：字段停止，建议缓签，不编造域外法。
- 通知送达：可约定邮寄至载明地址第 X 日视为送达。不得把微信已读写成已经送达的唯一充分条件。

语言闸（对应框架第五步）：

- 盯死：负责解决／督促、支持／清偿、关注／担保、尽力／必须。
- 正说须有反说：出具人侧“维持正常经营”必须配“不构成保证或债务加入”。
- “如果……则代为清偿”结构一旦出现，回到节点 2.2，不得当优化句保留。
