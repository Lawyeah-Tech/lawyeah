# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的本金、利率、期限、账户；把已失效《合同法》及其解释写入结论；把法释〔2020〕17 号第 25 条四倍、年利率 24% 或 36%、银行利率旧四倍写成银行贷款上限；把未放款写成合同依法未成立；把职业放贷写成金融机构；把无催告无违约事件的随时收回放行。

## 1. 触发、单方立场与成果状态

立场（贷款人/分支机构、借款人、拟签字担保人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明出借人是否持牌、经营范围是否含贷款。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1991 年借贷意见或 2015 年 24%/36% 条文时记噪声，不得写入 `L#`。持牌、诺成、670、利率监管口径、用途、格式条款无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `借款合同`，子级 `金融机构借款合同`。定性理由必须同时满足：出借人持牌且经营范围含贷款；核心给付为资金借贷。易混切开：自然人互借、民间/职业放贷、企业间拆借、抵押/保证/质押主文件、让与担保、名为投资实为借贷。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。无证放贷、转贷或违法用途写停笔告知，不填可履行放贷结构。

## 4. 主体、授权、资质与文本版本

主体表：贷款人（总行/分行/支行）、借款人、指定收款人或受托支付对象、引用中的担保人。金融机构写名称与许可证/机构编码是否被文本或材料提及；法人写统一社会信用代码。分支机构授权单独一列。

版本表：正文、借款凭证、提款申请、利率确认页、账户页、聊天确认。冲突并列，不选对用户有利的一版。口头“已经持牌”“总行批了”不得写成已核验。

## 5. 借贷给付闭环

分列并回链文本位置：

- 本金：阿拉伯数字与大写、币种、授信额度是否循环。
- 到账：面额、预扣利息/保证金/咨询费、实际划付对象（借款人账户或受托支付对手）。
- 成立与生效：是否写成签字成立，或写成未放款即未成立。默认按诺成审查；另有约定须点名，不得引用 679 当法定默认。
- 先决条件与提款：条件清单、提款期、未提部分处理。
- 用途：具体用途与禁止流入证券、期货、违规房地产、转贷。
- 支付方式：受托支付或自主支付及例外。
- 利息与费用：LPR 期限品种、加减点、重定价、年化披露、罚息、复利、其他费用。
- 期限与还款：起息、结息、还款计划、提前还款补偿、展期。
- 担保引用：合同名称编号是否指向本债；未落实能否放款。

缺口标 `G#`，不补商业数字。批准、登记、内部审批写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

金融机构预先拟定且未协商的，按格式条款审查提示说明。加速到期、交叉违约、单方调价、账户扣划未显著提示的，标必须改。

强制规范与效力红旗只在核验后落法律结论：无证经营贷款；套取贷款转贷；用途违法；职业放贷包装。监管办法未遵守不当然写成民事合同无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：出借人是否持牌；把未放款写成未成立；砍头息或面额与到账不一致；把法释第 25 条四倍或 24%/36% 写成银行上限；利率公式不明；用途空白或指向证券/转贷；支付方式空白；无理由加速到期；交叉违约过宽；单方调价；账户扣划未提示；担保引用未闭环。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：持牌主体；成立与放款分列；到账本金；监管利率公式而非民间四倍；用途正反说与支付方式；加速到期绑定违约事件与催告；担保引用闭环。

## 9. 谈判与签署提醒

谈判顺序：先红线（无证包装、转贷、违法用途、倒签、无理由随时收回），再必须改（诺成与先决条件、砍头息、利率公式与年化披露、用途与支付、格式提示），最后可优化。

签署提醒：有权签字人与合同专用章；分支机构授权作附件；日期真实；附件含提款申请、还款计划、利率确认、担保合同清单；打款备注写明贷款/受托支付对象。不指导倒签或补假许可证、假放款。

贷款人立场可建议先决条件与受托支付作为风控，但必须同时写明：合同仍按诺成成立，未放款不等于未成立。借款人立场必须提示：签字后可能产生付息、承诺费或未提款承诺责任；加速到期与账户扣划会扩张现金流风险。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务交付可编辑草稿、未决项、自审风险表与自审后修改句。草稿必须覆盖本类型起草必写、附件必附与禁止出现。有完整待签文本要评改时转配对审查原子。不是履约交底、争议文书、利息精算终局或效力保证。
