# 边界与路由

本技能只审查 **保证合同 / 独立保函** 的待签或待开立文本。中文展示名是「审查独立保函（保证合同）」。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符 | 本套导航的类型切开步骤 |
| 已特定单笔主债；先诉抗辩或“不能履行”为主线；无相符交单 | `一般保证合同·审查` |
| 已特定单笔主债；明确连带责任保证；债权人可直接请求；无单据化付款 | `连带责任保证合同·审查` |
| 最高债权额 + 一定期间连续发生的债权 | `最高额保证合同·审查` |
| 安慰函、维好、意愿书；仅知晓、关注、督促、尽合理努力；无单据无最高金额 | `安慰函·审查` |
| 差额补足、流动性支持、回购承诺等增信主文件 | `增信措施类保证合同·审查` |
| 同一文本是单笔借款主文加保证从债 | `保证借款合同·审查` |
| 普通企业或自然人出具“独立保函／见索即付／效力独立” | 不按本类型放行。告知担保制度解释第二条后转 `一般保证合同·审查` / `连带责任保证合同·审查`；方式不明不得写成一律连带 |
| 主文件是工程、买卖或借款，保函只是名称混用且付款取决于裁判或损失核定 | 对应基础合同场景或 `一般保证合同·审查` / `连带责任保证合同·审查`；本任务不审基础合同整案 |
| 备用信用证、跟单信用证为主结构 | 不按本类型硬套；转引擎重新定性 |
| 无文本、本类型条件已谈妥、要出己方稿 | `独立保函·起草` |
| 已开立未争、只问交单日、减额或失效日 | 本套导航的履约步骤 |
| 已索赔、已拒付、已申请止付、已立案或开庭，或主问能不能止付、怎么拒付、怎么追偿 | `或` 或 `或` |
| 企业融资整包、对赌或结构化增信要放行意见 | `企业融资整包对赌或结构化增信要放行意见`；本任务不放行融资结构 |
| C 端大众快检 | 只分流，不回改 |

专业版未收录的 P1 场景不会安装本原子。若用户拿本类型文本来找专业版：输出 `unavailable`，提示，不得用邻类硬套。

独立保函里夹带一句“连带责任保证”或“保证人”：不立即整案转普通保证；先判断付款是否仍只取决于相符交单。核心已是单据付款的，删除或改正混用词后继续审。付款取决于基础违约事实、损失核定或法律裁判的：`目标停止`，转 `一般保证合同·审查` / `连带责任保证合同·审查`。

普通保证或最高额保证里夹带一句“本合同独立于主合同”：不整案按本类型放行；那是从属性保证中的无效独立性约款，留在对应保证原子处理。

用户坚持把非金融机构文本改成见索即付独立保函：`整体停止`。不得提供可履行的规避结构。
