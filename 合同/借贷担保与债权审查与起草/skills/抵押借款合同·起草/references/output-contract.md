# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同有效、抵押权已经设立、必然优先受偿或对方接受；编造未给出的本金、坐落、权证号、利率、期限；把已失效《合同法》《担保法》《物权法》及其解释写入结论；把银行利率旧四倍、年利率 24% 或 36% 写成现行保护上限；把抵押合同写成自登记之日起才生效；把未登记写成已取得优先受偿权；把流押写成可以过户；把抵押人写成保证人；把让与担保买卖留在本技能改成可履行买卖。

## 1. 触发、单方立场与成果状态

立场（出借人/抵押权人、借款人、第三人抵押人、拟签字共有人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在抵押主结构。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《担保法》《物权法》及其解释、1991 年借贷意见或 2015 年 24%/36% 条文时记噪声，不得写入 `L#`。流押、从属、登记与合同效力分离、担保范围、处分规则、利率上限无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `借款合同`，子级 `抵押借款合同`。定性理由必须同时满足：资金借贷；抵押为主结构。易混切开：让与担保/买卖过户担保、纯保证、无抵押自然人/民间借款、质押、金融机构监管条款主审、企业拆借。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。职业放贷、转贷、禁止抵押财产包装或流押过户写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：出借人/抵押权人、借款人、抵押人、共有人、保证人（如有）、指定收款人。自然人写姓名与证件号是否与文本一致；法人写名称与统一社会信用代码。抵押人与借款人是否同一人必须写明。

版本表：正文、抵押物清单、权属证明、内部决议、账户页、聊天确认。冲突并列，不选对用户有利的一版。口头“配偶同意了”“已经能登记”不得写成已同意或已登记。

## 5. 主债与抵押给付闭环

分列并回链文本位置：

- 主债权：合同名称与编号、本金大小写、币种、履行期限。
- 从属：是否写明抵押合同从属于该主债；有无独立性约款。
- 抵押财产：名称、坐落或规格、权证号、数量、权属、是否禁止抵押、房地是否一并写入。
- 登记：不动产/在建工程登记义务主体与期限；动产是否登记对抗；预告登记是否被写成现实抵押权。
- 合同效力与物权：是否把登记写成合同生效条件。
- 担保范围：合同列举是否覆盖法定项目；是否与拟登记内容一致。
- 处分：抵押期间转让、出租是否按“可以转让 + 另有约定 + 通知”而不是旧同意生效。
- 实现：折价/拍卖/变卖优先受偿，还是流押过户。
- 利息与费用：有无书面利率；是否民间借贷路径；费用是否并入上限审查。
- 放款条件：不动产未登记是否仍允许放款。

缺口标 `G#`，不补商业数字、证号或已登记事实。批准、登记写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

银行或职业放贷人预先拟定且未协商的，按格式条款审查提示说明。自然人偶发互借通常不是格式条款。

强制规范与效力红旗只在核验后落法律结论：流押；禁止抵押财产；独立性约款；套取金融机构贷款转贷；未取得放贷资格而向不特定对象放贷；出借人事先知道或应当知道用于违法犯罪仍提供借款；公司对外担保未审查决议。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：流押或放弃清算；抵押财产未特定；禁止抵押财产；把登记写成合同生效或把未登记写成已设立；担保范围空白或与登记簿冲突；独立性约款；旧“同意才能转让否则无效”；利率/费用未核验或疑似超过保护上限；共有人未签；公司决议未附；借新还旧沿用旧登记；预告登记当现实抵押权。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、证号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：删除或改写流押；财产特定化与登记义务；合同生效与抵押权设立分列；担保范围列举并与登记一致；从属主债、删除独立性约款；处分按通知/另有约定而不是旧同意无效；利率上限待核表述。

## 9. 谈判与签署提醒

谈判顺序：先红线（流押过户、禁止抵押财产、伪造登记/决议、违法放贷），再必须改（特定化、登记义务、从属、担保范围、处分口径、利率核验），最后可优化。

签署提醒：抵押人与共有人本人签；公司决议作附件；权属证书原件核对；不动产约定先登记后放款；日期真实；附件含抵押物清单、权属证明、决议。不指导倒签、补假登记或假同意。

出借人立场可建议共有人签署和办理登记作为增信，但必须同时写明：未登记不得当成已有优先受偿权。抵押人或借款人立场必须提示：签字、配合登记和扩大担保范围会扩张责任财产风险。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务交付可编辑草稿、未决项、自审风险表与自审后修改句。草稿必须覆盖本类型起草必写、附件必附与禁止出现。有完整待签文本要评改时转配对审查原子。不是履约交底、实现抵押权文书、利息精算终局或效力保证。
