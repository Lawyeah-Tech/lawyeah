# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同有效、必然按借贷或必然按投资裁判、固定回报必然可执行或对方接受；编造未给出的本金、回报率、期限、费用；把已失效《合同法》《担保法》《物权法》及其解释写入结论；把银行利率旧四倍、年利率 24% 或 36% 写成现行保护上限；把拆分服务费写成已经绕开上限；把阳合同改成可强制过户或可强制入股；把让与担保借款或房屋买卖担保留在本技能改完；把普通借款换标题审完。

## 1. 触发、单方立场与成果状态

立场（资金方/名义投资人，或融资方/标的公司）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明伪装形态（名股实债、名合实贷、名租实贷、名买卖实拆借、拆分费用）以及是否同时存在过户或让与担保夹带。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《担保法》《物权法》及其解释、1991 年借贷意见、2015 年 24%/36% 条文或法复〔1996〕2 号时记噪声，不得写入 `L#`。穿透依据、利率上限、砍头息、职业放贷/转贷、虚构租赁物无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `借款合同`，子级 `“名为其他合同，实为借贷” 的合同`。定性理由必须同时满足：外观不是借款；实质是提供资金、到期还本、固定或保底回报、不承担经营风险。易混切开：让与担保借款、房屋买卖担保、真实买卖、真投资/真合伙、已标明借款的普通民间/自然人/企业间/金融机构借款、保证/抵押/质押借款。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。职业放贷、转贷、虚构租赁物、流质过户或假放款写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：资金方、融资方、回购义务人、保证人（如有）、指定收款人。自然人写姓名与证件号是否与文本一致；法人写名称与统一社会信用代码。资金方是否持牌、是否出现职业放贷红旗必须写明。

版本表：正文（阳合同）、补充协议、回购/对赌、服务或咨询合同、转账或付款指示、发票约定、内部决议、聊天确认。冲突并列，不选对用户有利的一版。口头“已经当股东了”“服务费是另回事”不得写成已是股权投资或费用已隔离。

## 5. 伪装给付闭环

分列并回链文本位置：

- 资金：谁向谁的账户支付、金额大小写、是否预扣、实际到账（已知则写，未知标 `G#`）。
- 名义标的：股权/份额/租赁物/货物是否真实存在；是否仅作通道。
- 经营与风险：是否约定不参与经营、不承担亏损；有无派驻或表决安排。
- 回报：固定收益、保底、租金、溢价、咨询费、服务费、管理费各自金额或比例。
- 还本：回购、退出、份额转让的条件是否无条件、价格是否固定。
- 期限：投资期/合作期/租赁期；回购日/退出日。
- 阴阳合同：文件清单是否齐；冲突条款。
- 利息折算：是否已合并年化；上限核验状态。
- 夹带担保：是否出现过户、不清算归己；若为主结构应已在节点 1 转出。

缺口标 `G#`，不补商业数字或已放款、已过户、已入股事实。批准、登记、工商变更写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

资金方预先拟定且未协商的投资/咨询模板，按格式条款审查提示说明。偶发、双方协商的文本通常不是格式条款。

强制规范与效力红旗只在核验后落法律结论：虚假意思表示；职业放贷；转贷；虚构租赁物；超利率上限（超出部分）；以合法形式掩盖非法目的；公司对外担保决议错位。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：标题与给付名实；保底或固定回报；无条件回购；不承担经营风险；拆分服务费/咨询费；砍头息；费用未并入上限；阴阳合同冲突；流质或过户夹带；职业放贷或转贷红旗；决议按投资作出但实质是借贷或担保。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：穿透后还原借贷给付；回报与费用并入上限待核表述；删除或改写预扣；删除流质过户或转出让与担保原子；不得把阳合同改成可强制履行的真实投资或真实买卖。

## 9. 谈判与签署提醒

谈判顺序：先红线（职业放贷/转贷/虚构租赁物、流质过户、把阳合同当真实买卖或真实投资起诉、伪造放款），再必须改（穿透表述、费用合并、砍头息、回购改还款、决议按实际性质补），最后可优化。

签署提醒：全套阴阳合同齐签；实际到账与合同本金核对；日期真实；附件含回购/服务合同、付款指示、对应决议。不指导倒签、补假发款、补假入股或假过户。

资金方立场可建议改为明示借款并压缩费用，但必须同时写明：伪装不能提高受保护利率。融资方立场必须提示：接收资金并同意无条件回购，可能按借贷加计息处理。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务只出审查意见与修改句，不出整份起草终稿。无文本出稿转配对起草原子。不是履约交底、争议文书、利息精算终局或效力保证。
