# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、必然收到债款、对方必然接受；编造未给出的价款、未偿额、清单；把已失效《合同法》第七十九条至第八十三条写入结论；把未通知写成转让合同无效；把转让后债务人不得抗辩写成可放行效果；把债务转移、代付款或保理硬套本类型。

## 1. 触发、单方立场与成果状态

立场（转让人／受让人）、授权、签署状态、主要目标。债务转移、代付款、保理、股权／资产、已成争或其他负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》第七十九条至第八十三条或其解释时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `债权转让合同`，子级 `债权转让合同`。写定性理由和与债务转移、代付款、保理、股权转让、资产买卖的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。虚构债权或规避国资进场写停笔告知，不填可履行规避结构。

## 4. 主体、授权、债权权属人与文本版本

主体表：转让人（名义债权人／实际权利人）、受让人、债务人（非必为签约方）、保证人、抵押人、质权人、授权签字人。版本表：正文、债权清单、通知书、基础合同、担保登记查询、聊天确认；金额或清单冲突并列，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定检查并回链文本：

- 标的：基础合同名称编号、债务人、未偿本金／利息／违约金、全部或部分、基准日；
- 可转让性：性质、法律禁止、基础合同禁止转让特约及金钱／非金钱分层；
- 真实性：履行凭证、催收、时效、是否已清偿或部分清偿、是否已出质或查封；
- 通知：谁发出、书面内容、送达方式、回证、共同通知；不得写成未通知则本合同无效；
- 从权利：保证／抵押／质押／利息是否随同、专属除外、变更登记、是否通知保证人；
- 单一真实价款；付款与通知送达、材料移交、登记递件的顺序及未完成后果；
- 抗辩与抵销披露：质量异议、同时履行、已过时效、互负债务。

缺口标 `G#`，不补商业数字。通知、登记写成义务或条件，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款（含示范文本或资产包填充版）；提示说明痕迹。强制规范只区分是否导致民事行为无效与是否仅造成对债务人不生效、不能对抗、进场未履行。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。硬闸七项若文本或事实触及或沉默，必须各有至少一行，不得用色块代替。

## 8. 修改句

按框架六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止输出“未通知则本合同无效”或“转让后债务人不得抗辩”充当修改句。

## 9. 谈判与签署提醒

谈判顺序：先红线（人身性／法律禁止转让、虚构或已过时效未披露、无清单一揽子、国资未进场、先全款后通知、转让后不得抗辩），再必须改（通知先决、从权利登记、抗辩抵销披露、真实性回购／降价），最后可优化。签署提醒：基础合同与禁止转让条款、清单与凭证、书面通知及送达、担保变更登记、日期不得倒签、附件清单。不指导倒签或补假通知回证。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务只出审查意见与修改句，不出整份起草终稿。无文本出稿转配对起草原子。不是履约催收交底、争议追索文书、代办登记或效力保证。
