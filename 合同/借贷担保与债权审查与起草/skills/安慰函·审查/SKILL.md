# 安慰函·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、已失效《担保法》及其解释当作现行规则。不得把担保制度解释第八条写成“是否具有担保意思”的条文。不得把安慰函改写成保证合同或独立保函后按本类型放行。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **保证合同 / 安慰函** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。中文名必须是「审查安慰函（保证合同）」。

`depends-on` 为空。不要求先跑导航。

不交付：他类合同审查；从零起草；履约交底；争议文书或行权策略；有效性保证；把安慰函改成保证合同、独立保函或差额补足主协议后按本类型放行；套用一般保证／连带保证的期间、先诉抗辩或方式推定主路径。

## 本类型硬闸

1. **是否具备保证意思**。看正文是否符合民法典第六百八十一条：债务人不履行到期债务或发生约定情形时，由出具人履行债务或者承担责任。分层走担保制度解释第三十六条，不看标题。解释第八条是公司决议例外，**不是**担保意思条文。
2. **道义支持 ≠ 保证**。仅知晓、关注、督促、促使、尽商业上合理努力、保持股权比例：现有依据不支持按保证或连带责任请求，但不等于“一定无任何民事责任”。出现代为清偿、承担保证责任、不使债权人受损、负责解决欠款、兜底：标为具有担保意思，按保证有关规定**提示后果**，**不把本函改成保证合同**。加入债务或共同承担：按第五百五十二条标出。保证与债务加入难以区分：解释第三十六条第三款认定为保证，仍不改写成保证合同。
3. **安慰函 ≠ 独立保函 ≠ 增信主文件**。见索即付、URDG／ISP98、相符交单、付款独立于基础交易 → `独立保函·审查`。差额补足、流动性支持、回购承诺作为双边主文件且有金额、触发和付款机制 → `增信措施类保证合同·审查`。函内一句“将提供流动性支持”仍留本类型，按解释第三十六条审意思。
4. **禁止把安慰函写成保证**。禁止打开或复制 `一般保证合同·审查`、`连带责任保证合同·审查`、`最高额保证合同·审查` 的 method。禁止把框架“做硬：改成代为清偿／见索即付／本文件构成保证担保”当作本技能最佳实践。债权人要真正保证 → `目标停止`，转对应保证原子。
5. **标题不决定性质**。标题担保函而内容仅知晓督促，或标题安慰函而内容含代偿，按核心给付归类，标题冲突写入 `C#`。
6. **机关／公益不得被改成可履行保证人**。第六百八十三条；解释第五条、第六条。政府或公益主体出具硬函：只出告知。用户坚持改到能签：停止。
7. **可能被定性为担保或债务加入时才走决议闸**。2023 年修订公司法第十五条；解释第七、八、九、十二条。软安慰不得假装已经需要担保决议才成立；硬词未删时不得宣称“无决议也一定对公司发生效力”。上市公司硬函还须核解释第九条披露。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

禁止表述：必然是保证／必然只是道义；一定能执行／一定无约束力；先改成代为清偿再按本类型放行；未登记则函件未生效；争议怎么赢。

## 工作边界

正触发：已有可读待签安慰函、维好协议、意愿书、支持函或知晓函，尚未签署或尚未出具，尚未成争，核心给付是第三方向债权人表达对债务人履约的知晓、支持、维好或类似姿态；用户问这封函有没有担保力、能不能签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 已具备完整保证结构（保证人、主债权、保证方式、保证期间）→ `一般保证合同·审查` 或 `连带责任保证合同·审查`；有最高限额和连续发生 → `最高额保证合同·审查`；
- 独立保函、见索即付、URDG／ISP98、相符交单 → `独立保函·审查`（专业版未装则 `unavailable`，提示，不得用本技能硬套）；
- 差额补足、流动性支持、回购承诺作为主给付且有金额、触发、付款日 → `增信措施类保证合同·审查`（未装则 `unavailable`）；
- 同一文本是单笔借款加保证，主从一体 → `保证借款合同·审查`；
- 无文本、本类型条件已谈妥、要出己方稿 → `安慰函·起草`；
- 已签只问何时主张、如何送达或履约节点 → 本套导航的履约步骤；
- 已催告、索赔、立案、开庭、仲裁，或主问这封函能不能追、责任是否消灭、怎么起诉 → `或` 或 `或`。

机关法人、公益性主体违规保证，或伪造决议、倒签：只出告知，不改写成可履行规避结构。

## 建立审查坐标

确认：使用者与授权；单方立场（债权人／出具人／债务人择一）；相对方；全文及附件版本；标题原句；硬词／软词原句；出具人与债务人关系；出具人是否机关、公益或上市公司；债权人是否拟签收或回函；是否另有保证或抵押；用户是要保持道义还是做成可执行担保；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

### 0. 签署状态与成果分流

无书面文本 → `安慰函·起草`；已签履约 → 本套导航履约步骤；已成争或主问能否追函件出具人／起诉策略 → 争议或 `或`。未签且目标是评改已有安慰函，才进入本任务。

### 1. 类型锁死

标题、核心给付与安慰函姿态一致才继续。完整保证合同、独立保函、增信主文件、保证借款同文本负触发。

### 2. 保证意思分层（本类型灵魂闸）

按解释第三十六条和第六百八十一条做硬词／软词／加入／难分四层。不把本函改成保证合同。

### 3. 主体、禁入与决议

出具人是否机关或公益；若可能被定性为担保或债务加入，决议和上市披露是否闭合。

### 4. 单方函与债权人接收

书面出具；若已构成保证意思，685 第二款看债权人是否接收且未异议。软函不得写成“接收即保证成立”。

### 5. 支持方式与从属性提示

流动性、持股、净资产、不抵押承诺只审函内表述。若被定性为保证，独立性约款删除，不改成独立保函。

### 6. 禁止做硬

用户要改成保证、见索即付或差额补足主协议：目标停止并转出，不在本类型出具放行意见。

### 7. 按框架六步出修改句

必须有可回给对方的修改句或红线。做软句可用；做硬句禁止。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、伪造决议、把机关或公益主体改成可履行保证人、把本函改成保证或独立保函仍按本类型放行、保证有效或保证一定无担保力。
- `字段停止`：法域、动态规则、决议真伪、披露是否完成、域外准据法未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书、保证责任评估，或把本函改成保证合同／独立保函／增信主文件。

生存级金额或自然人兜底措辞且用户拒绝升级：停止放行建议，只列风险与转介。
