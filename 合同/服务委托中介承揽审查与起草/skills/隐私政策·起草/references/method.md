# 审查方法（锁定 互联网相关合同 / 隐私政策）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止把服务合同或广告审查方法抄进本任务。禁止把 `最终用户协议·审查` 的许可、账号、UGC 或责任限额正文当作本类型主路径。

定性校验：标题、核心给付与本类型一致才继续；最终用户协议、用户服务协议、无文本起草或已成争明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受、必然不被处罚或唯一罚款金额。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准。

示范文本只参考隐私政策栏目。工商总局示范或企业站点政策不证明本约条款已被接受。命中用户协议、EULA 或特定公司隐私权政策正文不得粘贴充作本约。

知识库纠正（不回写双文件）：

- `基本面.md` “必须通过主动勾选……默认勾选或仅告知即视为同意不具备法律效力”：基于同意处理时，第十四条要求充分知情下自愿、明确同意，默认勾选不构成明确同意。第十三条第二至七项可以不经同意。不得写成“一切处理都必须勾选才合法”，也不得把合同履行所必需写成仍须另签一张总同意。
- `基本面.md` “出境需通过安全评估、认证或订立标准合同”：第三十八条是条件之一，加上条约和其他法定条件。《促进和规范数据跨境流动规定》第五条存在免予申报评估、订立标准合同、通过认证的情形。豁免不等于可以不告知、不取得单独同意、不开展影响评估（该规定第十条）。
- `基本面.md` / `框架.md` 要求另立《儿童个人信息保护规则》：第三十一条和《网络数据安全管理条例》第二十一条要求专门处理规则，可为独立文件或政策内专章，不得把“必须另立一份带该标题的独立文件”写成唯一合法形式。
- `框架.md` “注销时限通常不得超过 15 个工作日”：本次未核到法律条文级期限，作监管实务口径，标 `G#`，不得写成个保法期限。
- 隐私政策同时是个人信息处理规则和可能的格式条款。不得只按民法典合同效力审查而跳过个保法告知义务。

本技能已锁定 **互联网相关合同 / 隐私政策**。只打开 `references/基本面.md` 与 `框架.md`。禁止读其他子目录，禁止为对照再开第二类，禁止打开 `最终用户协议·审查` 的许可或免责节点。

### 1.3 规避结构停笔

加载后或定性中出现：伪造或倒签同意日志；把一次出境拆成多笔以落入“不满十万人”口径；把身份证号、人脸、精准定位改称“非敏感”仍要一次总授权放行；要求指导如何绕过安全评估。

3. 风险表只保留识别依据和红线/改正句。

## 节点 2　告知同意（硬闸）

支持依据：个保法第十三条、第十四条、第十五条、第十六条、第十七条；《网络数据安全管理条例》第二十一条、第二十二条。

### 2.1 独立、公开、可保存

处理规则须公开、便于查阅和保存，集中展示、易于访问。仅在用户协议第×条写“我们重视隐私”：必须改，要求独立成文并在注册/登录/设置入口放置链接。

### 2.2 告知事项

处理前告知：处理者名称或姓名和联系方式；目的、方式、种类、保存期限；行权方式和程序。保存期限难以确定的，写确定方法。清单化列明收集项和提供给其他处理者的项。

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 告知事项齐全，入口可回链 | 继续；可优化摘要或图表 | 实际收集必然与文本一致 |
| 缺失处理者法定名称、联系方式、保存期限或行权路径 | **必须改** | 有客服邮箱即可不写处理者 |
| “我们将收集您使用服务过程中产生的全部信息” | **红线**：删除概括授权 | 范围大一点没关系 |
| 默认勾选“我已阅读并同意” | **红线**：改为未勾选，由用户主动勾选 | 行业惯例可放行 |
| 不授权通讯录/精准定位就不能浏览或下单等基本功能 | **必须改或红线**：拆基本功能与扩展功能 | 不授权就不让用是处理者权利 |

基于第十三条第二至七项处理的，文本须点名对应合法性基础，不得假装已取得同意。基于同意的部分仍须满足第十四条。

修改句（默认勾选 + 概括授权）：

`定位（同意条款 / 注册页说明）｜原文：打开本应用即视为同意我们收集您所有可能产生的信息；同意框已默认勾选｜建议改为：我们仅在您充分知情后，通过未预先勾选的同意框就《隐私政策》列明的处理目的、方式和种类取得您的同意。拒绝扩展功能（如个性化推荐、通讯录匹配）不影响基本功能（如【待填：浏览/下单】）。｜理由：个保法第十四条、第十六条；网络数据安全管理条例第二十二条｜可退让点：可用摘要+全文链接，但全文须可保存｜不接受时的红线：保留默认勾选或概括授权则建议不公示、不签署`

## 节点 3　敏感个人信息（硬闸）

支持依据：个保法第二十八条至第三十一条；《网络数据安全管理条例》第二十二条第二项。

敏感个人信息包括生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等，以及不满十四周岁未成年人的个人信息。须有特定目的和充分必要性，采取严格保护措施；须单独同意；还须告知必要性与对个人权益的影响。

| 文本写法 | 动作 |
| --- | --- |
| 人脸/身份证号/银行卡/持续定位与注册同意捆在同一勾选 | **必须改**：拆出单独同意弹窗或独立确认 |
| 把身份证号、人脸写成“普通个人信息” | **红线**：按敏感处理 |
| 收集通讯录、相册却不说明对应功能，或与手电筒、记账等基本功能捆绑 | **必须改或红线** |
| 处理不满十四周岁信息但无专门规则、无监护人同意 | **必须改**（见节点 6） |

单独同意不是“同一页多几个加粗词”。须能识别为独立的意思表示。

修改句：

`定位（敏感信息条款）｜原文：注册即同意我们收集身份证号、人脸识别信息和持续地理位置｜建议改为：为实现【待填：实名认证 / 支付核验 / 导航】，我们处理您的【待填：身份证件号码 / 人脸信息 / 精准位置】。该等信息属于敏感个人信息。我们已说明必要性及对您的影响。请在本弹窗单独确认；拒绝该处理的，您仍可使用【待填：基本功能】，但无法使用【待填：对应扩展功能】。｜理由：个保法第二十八、二十九、三十条｜可退让点：可按功能分次申请，不得并入注册总同意｜不接受时的红线：继续与注册一次性勾选捆绑则建议不公示`

## 节点 4　出境（硬闸）

支持依据：个保法第三十八条、第三十九条；《促进和规范数据跨境流动规定》第五条、第十条；《网络数据安全管理条例》第三十五条；《个人信息出境标准合同办法》第五条、第六条。

### 4.1 告知与单独同意

向境外提供的，须告知境外接收方名称或姓名、联系方式、处理目的、方式、个人信息种类，以及个人向境外接收方行权的方式和程序，并取得单独同意。写“可能传输至全球服务器”而不点名接收方：必须改。

### 4.2 机制或豁免

文本须在下列之一中可核验，缺材料则字段停止，不写成“已经合规”：

- 国家网信部门组织的安全评估；
- 专业机构个人信息保护认证；
- 与境外接收方订立标准合同（生效后方可出境）；
- 法律、行政法规或国家网信部门规定的其他条件；
- 2024 年第五条免予申报评估、订立标准合同、通过认证的情形（合同履行所必需、跨境人力资源管理、紧急保护、非关键信息基础设施运营者当年累计向境外提供不满十万人个人信息且不含敏感个人信息、不含重要数据）。

豁免仍须履行告知、单独同意和影响评估等义务。不得把第五条写成可以静默出境。

关键信息基础设施运营者、重要数据、达到评估阈值：不得指导拆分人数规避。规模未给出：标 `G#`。

修改句：

`定位（跨境传输条款）｜原文：您的信息可能被传输并存储于全球任何国家，无需另行同意｜建议改为：如向中华人民共和国境外提供您的个人信息，我们将向您告知境外接收方的名称、联系方式、处理目的、处理方式、个人信息种类以及您向该接收方行使权利的方式和程序，并取得您的单独同意。在通过安全评估、保护认证、订立标准合同或符合国家网信部门规定的其他条件（包括依法免予申报、订立或认证但仍履行告知和单独同意）之前，不向境外提供。｜理由：个保法第三十八、三十九条；跨境流动规定第五、十条｜可退让点：接收方名称可用清单附件，须可核验｜不接受时的红线：保留“全球自由传输、无需告知或同意”则建议不公示`

不得保证“已通过安全评估”。评估、认证、备案状态未附凭证：字段停止。

## 节点 5　共享、SDK、权利与注销

### 5.1 向其他处理者提供

支持依据：个保法第二十三条。须告知接收方名称或姓名、联系方式、目的、方式、种类，并取得单独同意。SDK / 插件按实际接收方列入《第三方信息共享清单》，字段与目的一一对应。委托处理走第二十一条，约定目的、期限、方式和监督，不冒充已取得单独同意，也不把受托人写成可以自行再提供。

### 5.2 权利路径

支持依据：个保法第十五条、第四十四至第四十七条；《网络数据安全管理条例》第二十一条、第二十四条。须提供查阅、复制、更正、补充、删除、撤回同意、注销账号的便捷路径。撤回难度不得高于同意。注销后除法定期限内须留存者外，删除或匿名化；技术上难以删除的，停止除存储和必要安全保护外的处理。

不得把“须本人到公司提交书面申请并等待六十日”写成便捷注销。十五个工作日不作法律结论，可写为处理时限建议并标实务口径。

修改句（无法注销）：

`定位（用户权利条款）｜原文：注销须本人持身份证原件到公司办理，且注销后已购虚拟权益不予处理说明｜建议改为：您可通过【待填：设置-账号与安全-注销】在线申请注销。我们将在核实身份后删除您的个人信息或作匿名化处理；法律、行政法规规定的保存期限未届满或技术上难以删除的，我们停止除存储和必要安全保护之外的处理。注销路径的操作步骤不得难于注册。｜理由：个保法第十五条、第四十七条；网络数据安全管理条例第二十一条、第二十四条｜可退让点：可核验身份，但不得要求不合理线下到场｜不接受时的红线：无在线注销或撤回难于同意则建议不公示`

## 节点 6　儿童与重大变更

支持依据：个保法第三十一条；未成年人保护法第七十二条；《未成年人网络保护条例》第三十二条；《网络数据安全管理条例》第二十一条第二款。

处理不满十四周岁未成年人个人信息：取得父母或其他监护人同意；制定专门处理规则（独立文件或专章均可）。不得因监护人拒绝非必要处理而拒绝未成年人使用基本功能。产品面向儿童或可合理预见大量儿童使用却完全沉默：必须改。

重大变更（处理目的、方式、种类或共享/出境范围变化）：须将变更部分告知并以显著方式再次征求同意。不得仅网站静默换文即对存量用户生效。

## 节点 7　争议条款：改写法，不审策略

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不公示或不签署（默认勾选、概括授权、强迫授权、敏感/出境无单独同意、拒不独立成文、指导规避评估）；
- `必须改`：可谈但生效前要落句（告知事项残缺、无清单、无撤回注销、儿童规则缺失、重大变更静默生效）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。坚持默认勾选、概括授权或拒绝单独同意：停止“可以公示/签署”建议。
