# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或点击后必然全部受约束；编造未给出的费用、限额、期限；把已失效《合同法》、1993 年消保法第二十六条旧义或已失效网交规章写入结论；把勾选或弹窗写成已尽提示说明；把封号写成可没收全部已付对价且不得救济；把隐私政策或软件许可本约当成已完成的本类型审查；写“提前五日”为已核验法定续费期间。

## 1. 触发、单方立场与成果状态

立场、授权、签署或上线状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查最终用户协议（互联网相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1993 年消保法第二十六条旧义或已失效网交规章时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `互联网相关合同`，子级 `最终用户协议`。定性理由、易混切开结果（隐私政策 / 软件自用许可 / 软件分发许可 / 软件著作权转让 / 起草 / 履约 / 已成争）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、运营公示、权源与文本版本

主体表：公示名、履行名、收款名、客服与投诉渠道。权源：软著或分发授权是否被材料提及。版本表：正文、点击页／勾选截图、会员规则、虚拟财产规则、隐私政策链接、聊天确认；冲突并列。

## 5. 点击生效、账号与虚拟财产、给付闭环

是否主动勾选；重大利害条款提示痕迹；账号权属与注销路径；封号程序与虚拟财产清算；许可范围（非独占、不可转让、可撤销）；自营／撮合；UGC 授权；通知删除；自动续费三件套；未成年人限制。缺口标 `G#`。不输出席位／CPU 计量，不输出单独同意或出境清单。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；最终解释权、概括免责、剥夺投诉起诉、平台责任一概转嫁是否出现。强制规范只按第一百五十三条、第四百九十七条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把隐私处理规则或席位许可直接写成“本类型已审完”。

## 9. 谈判与签署提醒

谈判顺序：先红线（最终解释权、概括免责、封号没收且剥夺救济、邻类整案、无许可上线），再必须改（点击生效、提示痕迹、注销与虚拟财产、UGC、通知删除、续费、未成年人、自营／入驻），最后可优化。签署／上线提醒：运营主体公示、点击页与正文一致、隐私政策独立链接、会员与虚拟财产规则作为附件、投诉渠道。不指导倒签或补假点击记录。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是隐私政策、软件自用许可、软件分发许可或软件著作权转让安排。
