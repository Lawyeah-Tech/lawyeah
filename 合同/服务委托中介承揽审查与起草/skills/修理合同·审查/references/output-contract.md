# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、保证修好或对方接受；编造未给出的价金、工期、零件编号；把已失效《合同法》承揽章或《加工承揽合同条例》写入结论；把定作/加工/买卖当本类型审完；把 787 写成无偿解除或已放弃；把旧件归属写成“法律默认归修理厂”；把留置权写成当然优先于查封。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查修理合同（承揽合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》承揽章、《加工承揽合同条例》或《经济合同法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `承揽合同`，子级 `修理合同`。定性理由须写清：修复哪一件既有物、与定作/加工/买卖如何切开。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。挂靠、无资质承修特种设备、承修报废车或拼装：只保留识别与停笔。

## 4. 主体、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、设备所有权人或保管授权人。资质表：特种设备修理许可、电梯制造单位委托、机动车维修经营痕迹。版本表：正文、报修清单、进场确认单、零件价目、验收/结算单、聊天确认；冲突并列。未核资质：该签署能力字段停止。

## 5. 给付闭环

既有物身份与进场损坏现状；修复目标（恢复原状 / 恢复特定功能 / 达到安全运行）；谁供新件、旧件归属、775 禁换范围；拆解报价与增项书面确认；工时费与材料费、支付节点、检测费在停修时是否仍付；试运行验收与质保同一故障。缺口标 `G#`。不输出定作新物规格书、加工来料定额或买卖货交承运人主路径。

## 6. 787、格式条款与强制规范

是否保留完成工作前的随时解除及损失赔偿；放弃 787 或无偿解除如何改。是否构成格式条款；免责、留置、管辖是否加黑提示。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“旧件通常归定作人”写成法条；不得把“只结算工时和已拆封材料”写成已穷尽 787 损失。

## 9. 谈判与签署提醒

谈判顺序：先红线（邻类错位、排除 787、无资质承修特种设备、报废拼装、旧件强制归厂且拒改），再必须改（进场确认、材料归属与 775、拆解后停修、试运行与质保、留置催告期限），最后可优化。签署提醒：进场确认单、报修清单、零件价目、验收结算单入附件；签字人与设备权属一致；涉及保险理赔的日期不得倒签。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是定作、加工、买卖或施工审查。
