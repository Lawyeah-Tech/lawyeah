示范文本只参考结构。民法典第 470 条允许参照示范文本，不证明本约条款已被接受，也不等于已经完成技术合同认定登记或已经享受税收优惠。

知识库纠正（不回写双文件）：

- `基本面.md` 写“三新”时漏“新品种”：现行第 851 条是新技术、新产品、新工艺、**新品种**或者新材料及其系统。
- `基本面.md` 把“双方均有使用的权利”写成笼统默认：那只覆盖技术秘密第 861 条；**专利申请权默认归研究开发人**，不得混写。
- `基本面.md` “通常约定软件著作权归委托人”：这是谈判方向，不是无约定法定默认。无约定不得写成已经归委托人。
- `框架.md` 把“归双方所有”当常见写法：共有是陷阱，不是可履行默认。须一方所有另一方获许可，或补收益分成与单独实施/许可规则。
- `框架.md` 把科技部《技术开发（委托）合同》示范文本写成“确保行政合规”：只借栏目，不证明本约已被接受，不写成已经免税。
- 知识强调“委托性”：不得因此引入第 933 条任意解除作为本类型默认主路径。本类型走技术合同章。

支持切开的规范（法律结论须运行时复核）：

- 第 851 条：技术开发合同包括委托开发合同和合作开发合同，应当采用书面形式。
- 解释第 19 条第二款：一方仅提供资金、设备、材料等物质条件或者承担辅助协作事项，另一方进行研究开发工作的，属于委托开发合同。
- 第 855 条及解释第 19 条第一款：分工参与研究开发工作＝合作开发。
- 合同编通则解释第 15 条：不拘泥名称，按内容、结构和履行行为认定。
- 第 919 条：委托是处理委托人事务——只用于负向切开一般委托，不把第 933 条写进本类型。

## 节点 2　主体、资质、联系人与文本版本

### 2.1 主体表

建表：签约名、履行名、付款名、发票名、授权签字人。名称不一致不自动合并。课题组、工作室等无民事主体资格的科研组织签约：字段停止，修改句要求由法人或非法人组织作为乙方，或补授权。口头“我们老板同意了”不得写成已授权。

### 2.2 特殊行业资质

医药研发（CRO）、军工、出口管制或高精尖管控技术，文本与材料均未见相应许可：该履行字段停止。只有营业执照不等于已具备该研发准入。用户仍要无证承接：按节点 1.4 停笔告知，不改成可履行无证研发。

### 2.3 项目联系人与核心人员

技术研发具动态性。联系人在职责范围内签署的确认书、需求变更单应对所属方有约束力。核心主研人员更换须对方书面同意。

修改句：

「双方各指定一名项目联系人，姓名、职务、邮箱和权限范围列入附件。联系人在权限内签署的需求变更单、阶段成果确认书对本方有约束力。超出权限或涉及经费增减、验收结论、知识产权归属的，必须由双方法定代表人或另行授权代表书面确认。乙方更换附件所列核心研究人员，应提前【待填】日书面通知甲方并取得甲方书面同意；未经同意更换，甲方有权中止付款并要求限期恢复。」

## 节点 3　标的、任务书与验收闭环（硬闸）

1. 项目名称、目标、技术路线、可量化性能指标、验收方法和评价方法必须进入附件《技术任务书》。只有“达到行业领先”“国际先进”视为必须改。
2. 交付与验收分列。受托人提交是交付，委托人按指标确认是验收。签收、付款、试用不当然等于验收，除非合同有可回链约定且已提示。
3. 建议约定交付后【待填】日试运行，作为最终验收前提。验收期限届满未书面提出不符合项的，可以视为合格，但必须写期限和书面提出方式。
4. 建立“技术指标—验收结论—尾款支付”闭环。未验收不得主张尾款到期。

修改句：

「研究开发标的以附件《技术任务书》为准，包括项目名称、技术路线、量化性能指标、测试方法和合格判据。乙方按附件《进度计划》向甲方交付阶段成果和最终成果，交付不等于验收。甲方应在收到完整交付物后【待填】日内按任务书指标完成验收并出具书面结论；逾期未提出具体不符合项的，该阶段视为验收合格。最终验收合格是支付尾款人民币【待填】元的前提。试运行期为交付后【待填】个月，试运行期内出现任务书列明的致命缺陷的，验收结论可撤销。」

最强反方：委托方主张“我已经签收资料就是验收”。现有依据不支持在无清晰视为验收条款时把签收写成验收合格。

## 节点 4　开发归属默认（硬闸）

运行时核验第 859、861、875 条后再落法律结论。核验失败：摘录条款继续，效力字段停止，修改句草稿仍按下列方向写。

### 4.1 专利申请权

默认规则（有核验引文才写成 `L#`）：除法律另有规定或当事人另有约定外，申请专利的权利属于研究开发人。研究开发人取得专利权的，委托人可以依法实施该专利。研究开发人转让专利申请权的，委托人享有以同等条件优先受让的权利。

| 文本写法 | 动作 |
| --- | --- |
| 未写归属，或写“按法律规定” | 必须改：明示适用默认，并写委托人免费实施、优先受让；或改成约定归委托人并写清受托人是否保留实施权 |
| “知识产权归甲方（委托人）”但未写专利申请权、技术秘密、软件著作权、实施权 | 必须改：分项写死，避免只拿走专利却漏源码或反向 |
| “归双方所有/共同所有”且无收益比例、单独申请、单独许可规则 | **必须改或红线**。共有极难行使 |
| “无约定视为归委托人，乙方不得实施” | **红线**。与第 859 条默认冲突；若要改归委托人，须明确约定，并评估是否同时剥夺法定实施权 |
| 软件/源码未单列 | 必须改：著作权、源码、目标码、开发文档分列；无约定不得写成已经归委托人 |

修改句（明示默认）：

「除双方另行书面约定外，因履行本合同完成的发明创造，申请专利的权利属于乙方。乙方取得专利权的，甲方可以在约定业务范围内免费实施该专利，但不得许可第三人实施，法律另有规定的除外。乙方转让该专利申请权的，应提前书面通知甲方，甲方在同等条件下有权优先受让。双方不得以“未约定即归甲方”或“当然共有”解释本条。」

修改句（约定归委托人，须当事人真要改默认）：

「双方约定：因履行本合同完成的发明创造，申请专利的权利属于甲方。乙方应当配合办理申请、答复审查意见和权利转移所需文件。在专利权有效期内，乙方【有权 / 无权】为非商业验证目的实施；未经甲方书面同意，乙方不得向第三人转让或许可。」

### 4.2 技术秘密

无约定或约定不明，依第 510 条仍不能确定的：在相同技术方案被授予专利权前，双方均有使用和转让的权利；但研究开发人在向委托人交付前，不得将成果转让第三人。自己使用或普通许可可以；独占、排他许可或转让须对方同意或追认。

修改句：

「不申请专利的技术秘密成果，其使用权、转让权和收益分配按附件约定。交付前，乙方不得向第三人转让或披露。交付后，【仅甲方有权使用和对外普通许可 / 双方均可自己使用并以普通许可方式许可他人使用】；任何一方以独占、排他许可或转让方式处分的，须事先取得另一方书面同意。」

### 4.3 后续改进

无约定或约定不明且依第 510 条仍不能确定的：一方后续改进的技术成果，其他各方无权分享。可补互利的优先受让或普通许可，但不得写成无偿独占对方改进——后者落入解释第 10 条。

修改句：

「任何一方在本合同标的技术基础上后续改进形成的技术成果，归改进方所有。改进方应在合理期限内书面通知另一方。另一方有权在【待填】日内按公平市场价格优先受让或取得普通许可。任何一方不得要求对方将自行改进的技术无偿提供、无偿独占或非互惠转让。」

最强反方：委托方主张“我出了钱，没写就应该归我”。现有依据不支持把第 859 条默认翻转成归委托人；要归委托人必须另有约定。

## 节点 5　经费、报酬、变更与止损（硬闸）

1. **经费与报酬分列**。经费用于耗材、设备、外协；报酬是受托人智力对价。混写成一个“开发费”且节点不明：必须改。
2. **分期**：签约款 + 节点进度款 + 验收款 +【质保/维护费】。未给出数字用 `【待填】`。
3. **超额与结余**：经费不足时甲方追加还是乙方自担；结余归受托人还是返还，必须写死。
4. **变更**：需求蔓延是高频争议。变更请求—技术评估—费用确认—联系人或补充协议书面确认，未完成不得纳入原范围。
5. **中期止损**：中期验收发现指标严重不达标，委托人有权停止后续投入并解除未履行部分。这是约定解除，不是第 933 条任意解除。
6. 禁止把“双方可随时解除，已付经费不予返还/全部返还”写成默认。若当事人坚持随时退出，须单独谈判退出结算，并提示与技术合同章及已发生研发成本的关系；不得写成“因本合同是委托所以当然适用随时解除”。

修改句（价款与止损）：

「本合同对价分为研究开发经费人民币【待填】元和报酬人民币【待填】元，分列核算。支付节点：本合同签署后【待填】日内支付【待填】元；完成中期里程碑并经书面确认后【待填】日内支付【待填】元；最终验收合格后【待填】日内支付尾款【待填】元。经费结余【归乙方 / 返还甲方】。经费不足时，因甲方变更需求导致的，由甲方追加；因乙方方案选择导致的，由乙方自担。中期验收结论为关键指标偏差超过附件允许范围的，甲方有权书面通知解除此后未履行部分，已合格阶段按确认书结算，未使用经费应在【待填】日内返还，已完成工作对应的报酬不予追回。」

## 节点 6　技术风险、非法垄断、格式条款与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 技术风险（硬闸）

第 858 条：因出现无法克服的技术困难，致使研究开发失败或部分失败的，风险由当事人约定；没有约定或者约定不明确，依据第 510 条仍不能确定的，风险由当事人合理分担。发现可能失败情形应及时通知并采取适当措施减损；未及时通知或减损的，就扩大损失承担责任。

| 文本写法 | 动作 |
| --- | --- |
| 未定义技术风险，只写“完不成视为违约，全额退费” | **红线或必须改** |
| 有“技术风险”四字，无判定程序 | 必须改：第三方专家或双方认可机构判定 |
| 风险发生后费用、劳务、已购设备如何分担未写 | 必须改：通常甲方承担已发生经费损失，乙方承担已投入劳务，或按约定比例 |
| 把未尽责、挪用经费、关键人员擅自撤离也写成技术风险 | 必须改：排除过错和违约 |

修改句：

「技术风险指：乙方已按约定制定并实施研究开发计划、合理使用经费、及时告知阶段结果，仍因现有科学技术水平无法克服的困难，导致研究开发失败或部分失败。是否构成技术风险，由双方共同指定的【待填】机构或【待填】名专家在【待填】日内出具书面意见；不能共同指定的，任一方有权申请有鉴定资质的机构鉴定。构成技术风险的，已发生且经凭证确认的经费损失由甲方承担，乙方已投入的研究开发劳务由乙方自行承担，双方互不支付额外违约金；未使用经费应返还甲方。不构成技术风险的，按违约条款处理。任何一方发现可能导致失败的情形，应在【待填】日内书面通知对方并采取减损措施。」

### 6.2 非法垄断技术（硬闸）

第 850 条：非法垄断技术或者侵害他人技术成果的技术合同无效。解释第 10 条六种情形，本类型最常见的是：限制在标的技术基础上进行新的研究开发或限制使用改进技术；不对等交换改进（无偿提供、非互惠转让、无偿独占或共享改进知识产权）；限制从其他来源获得类似或竞争技术。

| 文本写法 | 动作 |
| --- | --- |
| “乙方不得在本合同技术基础上自行改进” | **红线**。删除 |
| “甲方后续改进无偿归乙方独占”或反向 | **红线**。改为互利优先受让或普通许可 |
| “合作期间及此后【待填】年，甲方不得从第三方获得类似技术” | **红线**。删除或改为不披露对方秘密 |
| 禁止对标的技术知识产权有效性提出异议 | **红线**。删除 |

本任务删除或改写该结构，不在签前意见里宣告整份合同已经无效。用户坚持保留可履行垄断结构：整体停止该部分。

修改句（删除垄断）：

「删除“任何一方不得在本合同标的技术基础上自行研究开发或改进”“不得从其他渠道获得类似技术”“改进成果无偿归对方独占”等表述。任何一方有权在本合同技术基础上继续研究开发并使用其改进技术。一方要求分享对方后续改进的，仅可约定互利的优先受让或普通许可，对价为【待填】或届时公平市场价格。」

### 6.3 权利担保与开源污染

受托人应保证交付成果不侵犯第三人专利权、技术秘密或软件著作权。使用开源组件须列清单并说明许可证义务（尤其是强传染性协议）。委托方被诉时的抗辩、应诉配合、替换方案和赔偿上限要可执行。不得把“甲方验收即视为无侵权”写成受托人免责。

### 6.4 格式条款

为重复使用而预先拟定、订立时未与对方协商。研究机构或甲方采购制式文本均可构成格式条款。审查：成果当然归己方、失败全额退费且不得调整、最终解释权、单方无限保密、管辖是否有显著提示。仅电子勾选不足。

### 6.5 强制规范

违反法律、行政法规强制性规定不一律无效。禁止用已失效“效力性/管理性”口诀。非法垄断走第 850 条，不用第 153 条口诀替代。技术合同未登记多为管理或税收程序：不得写成“未登记则开发合同当然无效”，也不得写成“登记后必然免税”。

## 节点 7　配套、尾部与登记

1. **保密**：范围、期限（可至公开日或约定年数）、归还销毁。不得用无限保密去限制对方合法后续研发。
2. **禁止互挖核心人员**：可写约定期限内不得招揽对方附件所列人员；不得写成行业禁业。
3. **违约**：逾期交付、逾期付款、资料不实、泄露秘密、权利瑕疵分别有可执行后果。只有“依法承担违约责任”视为必须改。违约金须可调整。
4. **技术合同登记**：约定由【甲方 / 乙方】在签署后【待填】日内办理认定登记，另一方配合。登记是税收优惠的常见程序条件，不是合同生效或已经免税的证明。
5. **附件最低清单**：《技术任务书》《研发预算表》《阶段性成果确认清单》；软件项目另附源码交付清单和开源组件清单。冲突适用顺序写死。
6. **通知送达**：指定邮箱。微信已读不写成已经到达，除非合同把该渠道写成送达且用户要保留。

修改句（登记与附件）：

「本合同自双方法定代表人或授权代表签字并加盖公章之日起成立。双方指定【甲方 / 乙方】在签署后【待填】日内向有权机关申请技术合同认定登记，另一方应在【待填】日内提供所需材料。未完成登记的，任何一方不得主张已享受税收优惠，也不因此当然导致本合同不成立。附件《技术任务书》《研发预算表》《阶段性成果确认清单》【及《开源组件清单》】与正文冲突时，技术指标以任务书为准，价款以预算表为准，阶段完成以确认清单为准。」
