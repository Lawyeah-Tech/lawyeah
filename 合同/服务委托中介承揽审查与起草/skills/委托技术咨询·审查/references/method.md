# 审查方法（锁定 委托合同 / 技术咨询合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止复制 `或`（技术类技术咨询）、`咨询服务合同·审查`（咨询服务）的 method，禁止复制开发验收/成果归属主路径、设计出图节点或施工挂靠主路径。

定性校验：标题、核心给付与本类型一致才继续；技术类目录、商务咨询、技术服务、委托开发、出图、一般委托明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受、意见必然正确或投资必然不亏。

`search_law` 返回已失效《合同法》技术咨询章（第 356–359 条）及其解释、已失效《技术合同法》及其实施条例、已失效《技术合同管理暂行规定》时记为噪声，不得写入 `L#`。2004 年技术合同司法解释未修正文本指向合同法条号的，改走 2020 修正本。

示范文本只参考结构。民法典第 470 条允许参照示范文本，不证明本约条款已被接受。科技部 2001 版技术咨询示范文本处技术合同法/合同法时代，只借栏目。技术开发、工程设计、建设工程咨询、咨询服务范本只证明是另一类型。

知识库纠正（不回写双文件）：

- `基本面.md` “版权通常归委托人”：咨询报告作为作品，委托作品无约定时著作权不当然归委托人。第 885 条只覆盖履行过程中**新的技术成果**，不得与报告著作权混写。
- `基本面.md` / `框架.md` “决策损失由委托人承担”：第 881 条第 3 款的前提是报告和意见**符合约定要求**。报告逾期、不符约定、数据造假或违反科学常识，现有依据不支持套用自负。
- `基本面.md` “费用由受托人负担”：第 886 条针对“没有约定或者约定不明确”。与第 921 条一般委托“委托人预付费用”相反。计划外异地考察要报销，必须书面逐项。
- `框架.md` “签字盖章即生效”且把技术合同登记写成必经生效：登记服务于税收优惠，现有依据不支持把未登记写成合同不成立或不生效。
- 任意解除：委托父级可能被主张第 933 条。有偿技术咨询不得写成委托人可无偿随时解除；已交付且符合约定的报告应付相应报酬；解除应赔偿直接损失和合同履行后可以获得的利益。

## 节点 1　类型识别与单目录加载

### 1.1 定性

用标题、核心给付、对价方式和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。标题写“委托协议”“顾问协议”的，先看是否就**特定技术项目**出具论证、预测、调查或评价报告。

必须切开后再加载，禁止两可时灌入两套知识：

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 委托人/受托人（或委托方/顾问方），就特定技术项目出可行性论证、技术预测、专题技术调查、分析评价报告，报酬是咨询费 | 本类型 | 正触发 |
| 用户或文本明确落在技术类合同目录，主张按四技合同技术咨询原子审 | 技术类技术咨询 | 负触发 `或` |
| 无特定技术项目；管理、战略、财务、人力、品牌等商务意见 | 咨询服务 | 负触发 `咨询服务合同·审查` |
| 维修、测绘、检测、调试、现场解决特定技术问题 | 技术服务 | 负触发 `委托技术服务·审查` |
| 研究开发新技术、新产品、新工艺并交付开发成果 | 委托技术开发 | 负触发 `委托技术开发合同·审查`；技术类开发主轴 `只审委托合同目录下的委托技术开发。用户或材料按技术类合同进入《技术开发合同》→` |
| 施工图、初步设计、出图盖章、可据以施工的图纸 | 设计 | 负触发 `委托他人设计的服务合同·审查` 或 `单独设计发包，无现场简易施工成果` |
| 建设工程咨询、估算概算、全过程工程咨询 | 建设工程咨询 | 负触发 `只出可行性造价或管理咨询意见不交付测绘测试成果→` |
| 以委托人名义对外签约、开委托人抬头发票、概括处理事务 | 一般委托 | 负触发 `一般委托合同·审查` |

支持切开的规范（法律结论须运行时复核）：

- 第 878 条第 1 款：技术咨询是以技术知识就**特定技术项目**提供可行性论证、技术预测、专题技术调查、分析评价报告等。
- 技术合同司法解释（2020 修正）第 30 条：“特定技术项目”包括软科学研究项目，以及运用科学知识和技术手段进行调查、分析、论证、评价、预测的专业性技术项目。
- 第 878 条第 2 款：技术服务是解决特定技术问题，不包括承揽和建设工程合同。
- 第 851 条：技术开发是就新技术、新产品、新工艺、新品种或者新材料及其系统研究开发。
- 第 919 条：委托是处理委托人事务——对外代理、概括处理事务走一般委托，不是本类型。
- 第 843 条：技术合同包括开发、转让、许可、咨询或者服务。本技能吃的是**委托父级**下的咨询意见给付，不是技术类目录原子。

本技能已锁定 **委托合同 / 技术咨询合同**。只打开 `references/基本面.md` 与 `框架.md`。禁止读其他子目录，禁止为对照再开第二类，禁止打开 `或` 或 `咨询服务合同·审查` 的 method。

### 1.3 委托父级技术咨询（硬闸）

| 文本写法 | 本任务动作 | 修改句方向 |
| --- | --- | --- |
| 委托人聘请受托人就某工艺/某装置/某技术路线出具论证或评价报告，并付咨询费 | 正触发，留下本类型 | 首部写明“委托技术咨询，给付是意见不是实施或出图” |
| 用户声明按技术类四技合同审、不要委托父级 | 负触发 `或` | 不填本类型十节实体结论 |
| 咨询内容是品牌定位、股权架构、薪酬方案，无技术项目 | 负触发 `咨询服务合同·审查` | 不得套用第 881 条第 3 款 |
| 授权受托人以委托人名义对外签约或采购设备 | 负触发 `一般委托合同·审查`，或必须改：删除对外代理 | 「乙方仅就附件所列技术问题出具咨询报告，无权以甲方名义签署对外合同。」 |
| 交付源代码、工艺包或样机并验收开发成果 | 负触发开发原子 | 不得按咨询意见减责 |

修改句（正触发首部）：

「本合同为委托合同项下的技术咨询合同。甲方委托乙方以技术知识，就附件《技术咨询大纲》列明的特定技术项目，提供可行性论证 / 技术预测 / 专题技术调查 / 分析评价报告。乙方交付的是咨询意见和报告，不是研究开发成果，不是可据以施工的图纸，也不是现场实施或维修。乙方不是甲方的对外代理人。」

最强反方：相对方主张已构成技术开发、技术服务或设计，从而主张对实施结果或图纸负责。修改句必须收回开发成果、实施责任和出图措辞。用户坚持保留出图、开发或商务咨询主轴：负触发，不填本类型十节实体结论。

| 文本或附件信号 | 本任务动作 |

用户坚持“咨询合同里把施工图改到能签”：目标停止，转设计原子。

### 1.5 虚假咨询 / 套现停笔

加载后或定性中出现：合同无问题清单、无论证章节、无数据来源；以技术咨询为名走账、套取现金或输送利益；双方承认没有实质技术工作。

动作：

1. 交付告知：无实质性技术论证的“咨询”可能面临审计、税务和公序良俗审查。不得改写成可履行的套现结构。
2. 不写可履行的空章节伪装、假专家名单或体外资金路径。
3. 风险表只保留识别依据和删除/转出口径。
4. 用户坚持“改到能签且仍这样走账”：整体停止。

## 节点 2　主体、专家、资质与文本版本

### 2.1 主体表

建表：签约名、履行名、付款名、发票名、授权签字人、核心专家。名称不一致不自动合并。口头“我们专家组都定了”不得写成已锁定专家。

共同受托：对委托人的责任写清连带或按份，不得默认按份。转委托须书面同意；禁止把整单外包给未列名人员后仍声称本所履行。

### 2.2 专家名单与资质

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 工程咨询、安全评价、环境影响评价等依法需资质，文本未附有效资质查询页 | 字段停止；修改句要求作为附件 | 已具备全部咨询资质；可以出具法定评价 |
| 只有营业执照或高新技术企业称号 | 执照不等于该咨询资格 | 已具备法定评价资格 |
| 核心专家未列名，或允许任意更换 | 必须改：列名单；更换须书面同意 | 机构接单即可，人员无所谓 |

修改句：

「乙方指定附件《核心专家名单》所列人员主持本次咨询。更换须事先取得甲方书面同意。涉及【工程咨询 / 安全评价 / 环境影响评价】的，乙方应在签署前出示并作为附件提交现行有效资质查询页；未核验前，不得主张已具备出具该类法定评价的条件。」

部门规章或资质管理规范不当然导致民事合同无效。本任务只停止“可以出具法定评价”表述。建设工程咨询主轴按节点 1.1 转 `只出可行性造价或管理咨询意见不交付测绘测试成果→`。

## 节点 3　意见给付与任务书（硬闸）

支持依据：第 878 条第 1 款、第 845 条、第 879 条、第 880 条。

1. 标的必须确定到可履行：项目名称、咨询问题清单、报告名称、载体、份数、汇报次数。只有“提供某项目技术咨询”视为必须改。
2. 技术任务书/咨询大纲作为合同组成部分。任务书应列章节、核心参数、对标标准或对比案例数量。
3. 区分“技术可行性”与“经济可行性”。未写清的，修改句要求分章，禁止用一句“可行性”涵盖投资回报。
4. 技术预测应写明基于现有科技水平和已提供资料的逻辑推演，不是对未来必然发生的保证。

修改句：

「咨询事项以附件《技术咨询大纲》为准，至少包括：【待填】个具体问题；报告应覆盖【待填】等章节；引用的外部数据须注明来源和时点；对比案例不少于【待填】个。大纲与正文冲突时，以双方签章的大纲为准，但不得把施工图、开发成果或现场实施塞进大纲而不变更合同类型。」

禁止编造章节名或案例数量。未给出的用 `【待填】`。

## 节点 4　决策损失与报告符合约定（硬闸）

支持依据：第 881 条。

条文要点：委托人未按约提供必要资料影响进度质量、或不接受/逾期接受成果的，已付报酬不得追回，未付应当支付。受托人未按期提出报告或报告不符合约定的，减收或免收报酬等。委托人按照受托人**符合约定要求**的咨询报告和意见作出决策所造成的损失，由委托人承担，但是当事人另有约定的除外。

| 文本写法 | 动作 |
| --- | --- |
| “保证投产成功 / 保证获利 / 保证年降本” | 红线删除担保结果，改为论证建议 |
| “甲方按本报告决策的一切损失由乙方赔偿”，不问报告是否符合约定 | 必须改。符合约定时默认委托人自负；不符约定才走减酬或赔偿 |
| “即使报告不符合约定，决策损失仍由甲方自负” | 红线。现有依据不支持用格式条款掏空第 881 条第 2 款 |
| 沉默 | 必须改：补 881 结构——符合约定则委托人自负；不符约定则减酬/返还/赔偿 |

修改句（默认路径）：

「乙方应在【待填】日前交付符合附件《技术咨询大纲》和《验收评价表》的咨询报告。报告逾期或经约定评审不符合约定要求的，乙方应在【待填】日内免费修正；仍不符合的，甲方可减收或免收相应报酬，已付部分应退还。甲方根据乙方**符合本合同约定要求**的咨询报告和意见作出决策所造成的损失，由甲方自行承担。双方另有书面约定由乙方分担决策损失的，该约定须加黑并由甲方单独签认，且不得免除乙方对不符约定报告的减酬和赔偿责任。」

修改句（受托人侧可退让，须加黑）：

「在报告符合约定要求的前提下，双方可以书面约定乙方对甲方依据该报告作出的投资决策承担不超过咨询费【待填】倍的有限责任。该条属于重大利害关系条款，须加黑提示。禁止约定保证获利或保证投产。」

最强反方：委托人主张“咨询就是要包结果”，或受托人主张“只要交了纸就是符合约定”。现有依据支持另有约定改变自负，但现有依据不支持把保证获利或“交卷即合格”写成已闭合。用户坚持保证获利或报告不符仍自负：整体停止。

## 节点 5　费用默认受托人负担与报酬（硬闸）

支持依据：第 886 条。对照第 921 条（负向）。

### 5.1 费用

| 文本写法 | 动作 |
| --- | --- |
| 费用沉默，或只写“实报实销”“按委托惯例”“按第 921 条预付” | 必须改。沉默时现有依据支持由受托人负担；现有依据不支持按第 921 条要求委托人预付或偿还正常工作费用 |
| 要由委托人承担计划外异地考察、外请专家、特殊检测 | 必须书面逐项列举项目、计算方式和上限；未列项目不得另收 |
| 咨询费未写是否含税包干 | 必须改：写含税包干或列出可另报项目 |

修改句：

「除本合同附件《费用清单》逐项列明并由双方签章确认的【计划外异地考察 / 外请专家 / 特殊检测】外，乙方正常开展咨询工作所需的调研、资料、试验测定和差旅费用由乙方自行负担，已包含在咨询费中，不得事后向甲方报销。未列入该附件的项目，不适用委托合同关于委托人预付或偿还费用的规则。」

### 5.2 报酬

分期建议：启动费 + 中期稿 + 终稿验收。部分完成应付相应报酬。禁止编造金额。定金必须使用“定金”二字；超过主合同标的额百分之二十的部分不产生定金效力。

修改句：

「咨询费为含税包干价人民币【待填】元。甲方于本合同生效后【待填】日内支付【待填】%；收到符合约定的中期稿后【待填】日内支付【待填】%；终稿验收通过后【待填】日内支付剩余【待填】%。乙方未完成的部分不得请求该部分报酬。甲方未按约定提供必要资料影响进度和质量，或不接受、逾期接受符合约定的工作成果的，已支付报酬不得追回，未支付的应当支付。」

## 节点 6　资料协作、新成果、格式条款与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 资料提供与明显错误通知

支持依据：第 879、881 条第 1 款。失效实施条例关于“发现明显错误应通知”不得写入 `L#`；作为审查提醒写入修改句。

| 文本写法 | 动作 |
| --- | --- |
| 未列甲方应提供的资料清单和截止日 | 必须改 |
| 资料失实导致结论错误，却由乙方承担全部决策损失 | 必须改：基于甲方虚假或错误资料的结论，乙方不承担决策损失；乙方发现明显错误应及时通知 |
| 乙方对甲方资料“一律免责核查” | 可接受须加：明显错误或与公开作废标准冲突的，仍应在【待填】日内书面通知 |

修改句：

「甲方应按附件《甲方提供资料清单》在【待填】日前提供技术背景材料、原始数据和现场条件，并保证所供资料真实、完整。因甲方资料虚假、错误或不完整导致报告结论偏差的，由甲方承担相应后果，已付咨询费不予退还。乙方发现甲方资料存在明显错误、缺陷或引用已作废标准的，应在发现后【待填】日内书面通知甲方补正；甲方未在合理期限内补正的，乙方可中止相应部分工作。乙方未通知而继续使用明显错误资料的，不得主张该部分已尽专业注意。」

### 6.2 新成果与报告著作权

支持依据：第 885 条；司法解释（2020 修正）第 31 条（未约定保密时引用、发表不当然违约，但侵害对方合法权益仍应担责）。

| 文本写法 | 动作 |
| --- | --- |
| “履行中一切成果、报告著作权和新发明一律归甲方” | 必须改：分列。新的技术成果无约定时，受托人利用甲方资料完成的归受托人，委托人利用报告完成的归委托人；报告著作权另行约定 |
| 保密沉默，又允许任意发表对方数据 | 必须改：技术参数、投资规模和未公开数据须保密；回交或销毁程序写死 |
| 咨询事项涉及后续招标，未写回避 | 必须改：乙方及其关联单位不得参与后续设备供应或施工投标 |

修改句：

「咨询报告的著作权由双方书面约定；未约定的，不得写成当然归甲方。履行本合同过程中，乙方利用甲方提供的技术资料和工作条件完成的新的技术成果，属于乙方；甲方利用乙方工作成果完成的新的技术成果，属于甲方。另有约定的，按书面约定。甲方提供的技术参数、未公开数据和投资信息，乙方及专家在【待填】年内不得向第三人披露，项目结束后应按清单回交或销毁。若咨询事项涉及后续设备采购或施工招标，乙方及其关联单位不得参与该等投标。」

### 6.3 格式条款与强制规范

为重复使用而预先拟定、订立时未与对方协商。依据示范文本制作，不当然排除格式条款。

审查：决策自负、保证获利、费用实报实销、无偿任意解除、管辖/仲裁等异常条款是否有足以引起注意的标识，以及是否按要求说明（第 496 条；解释第 10 条）。仅有网络勾选或弹窗，不得写成已尽提示或说明义务。

违反法律、行政法规强制性规定不一律无效（第 153 条；解释第 16 条）。禁止用已失效“效力性/管理性”口诀。非法垄断技术或侵害他人技术成果：第 850 条及司法解释第 10 条，不改写成有效垄断结构。跨境传输敏感技术数据未评估：字段停止，不指导规避出境评估。

## 节点 7　验收、登记、违约与退出

### 7.1 验收看任务书（硬闸）

验收重点：逻辑是否按任务书展开、数据来源是否可核对、论证深度是否达到约定章节，而不是市场事后成败。经济效益或成本预测，除非另有约定，不得视为验收标准。

修改句：

「甲方应在收到终稿后【待填】日内，按附件《验收评价表》组织评审或核对。评审只评价报告是否符合《技术咨询大纲》的章节、数据来源、论证深度和约定指标，不评价甲方后续投资是否盈利。甲方逾期未书面提出修改意见的，视为通过验收。正式提交前，乙方应向甲方现场汇报一次，并根据甲方一次书面反馈作免费修正。」

### 7.2 技术合同登记

登记服务于税收优惠。修改句可约定双方配合办理认定登记，但不得把未登记写成合同不生效，不得保证必然免税。

修改句：

「双方同意在本合同生效后【待填】日内配合办理技术合同认定登记，所需材料由各方按登记机关当时要求提供。未完成登记不影响本合同效力，也不构成任何一方保证必然享受税收优惠。」

### 7.3 违约、解除与争议

逾期交稿、报告不符、资料不实、逾期付款必须分别有可执行后果。只有“依法承担违约责任”视为必须改。构成违约不等于当然解除。

有偿技术咨询不得写成委托人可无偿随时解除。解除应结算已完成且符合约定的部分报酬，并赔偿对方直接损失和合同履行后可以获得的利益，但不可归责事由除外。

争议解决：出现仲裁条款，不得改写成“应向某法院起诉”并假装已选定诉讼。或裁或诉、机构不明：标待核。

## 节点 8　按框架六步出修改句

本节点是成果闸。没有修改句或红线，不得宣称审查完成。禁止只打红黄绿。

打开已加载的 `框架.md`，按六步逐段对照正文。`基本面.md` 用于校验类型、主体、标的、费用、决策风险和红旗，不代替本节点出句。

| 步 | 动作 | 必须产出 |
| --- | --- | --- |
| 首部 | 标题用技术咨询/委托技术咨询；主体全称与专家；鉴于只写决策背景，不写保证获利或出图义务 | 标题或主体修改句 |
| 交易条款 | 特定技术项目；任务书章节；报告名称与载体；费用包干或逐项；报酬节点；881 自负与不符约定后果 | 闭环修改句；缺数字用 `【待填】` |
| 配套 | 资料清单与明显错误通知；保密与回交；新成果与报告著作权分列；回避后续招标；报告不符的减酬 | 可执行后果句或删除句 |
| 尾部 | 双方公章；任务书/资料清单/验收表/专家名单入合同；登记配合义务；附件清单 | 生效与附件修改句 |
| 语言 | 正说加反说；盯死论证建议 vs 担保结果、技术可行性 vs 经济可行性、意见 vs 施工图、费用包干 vs 实报实销 | 替换空词的句子 |
| 常见问题 | 咨询内容宽泛；费用按委托报销；报告不符仍自负；把出图或开发塞进咨询 | 结构级改法或红线 |

每条修改句固定格式：

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（技术类/商务咨询/出图/开发主轴、保证获利、报告不符仍自负、无实质论证套现、倒签、假资质）；
- `必须改`：可谈但签署前要落句（任务书章节、费用逐项或包干、881 结构、资料清单、专家名单、新成果与著作权分列、验收异议期）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级预付无阶段验收且用户拒绝升级：停止“可以签署”建议。
