# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的咨询费、工期、份数；把已失效《合同法》技术咨询章、《技术合同法》及其实施条例写入结论；把第 881 条第 3 款套到商务咨询；把施工图写成已验收的咨询意见。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。写明中文成果名称是「审查技术咨询合同（委托合同）」。负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》技术咨询章、《技术合同法》及其实施条例时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级必须写成 **委托合同**，子级 **技术咨询合同**。定性理由须同时回答：为何不是技术类目录下的技术咨询、为何不是咨询服务、为何交付物不是施工图。易混切开结果写全 ID。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。无实质论证或套现写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、核心专家。版本表：正文、技术任务书、资料清单、验收评价表、聊天确认；冲突并列，不选对用户有利的一版。工程咨询/安评/环评等资质未核：字段停止。

## 5. 给付闭环

标的须落到特定技术项目与意见给付：问题清单、报告名称、载体与份数、任务书章节。费用（默认受托人负担或书面逐项）、报酬节点、发票、资料提供、答疑修正、决策损失条款、新成果与报告著作权分列。缺口标 `G#`，不补商业数字。批准、登记写成配合义务或期限，不写成已经完成，不写成生效要件。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款（保证获利、报告不符仍自负、任意解除无偿、费用实报实销）。强制规范只区分管理性与是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线，再必须改，最后可优化。签署提醒：授权、用印、日期、任务书/资料清单/验收表/专家名单附件、条件成就凭证。不指导倒签或补假资质。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证。
