# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的费用、轮次、尺寸；把已失效《合同法》及其解释或 1994 年《广告法》写入结论；把未约定著作权写成归广告主；把“买断”当成已完成权属转移；把设计验收写成可以发布；把制作或发布文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查广告设计合同（服务合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1994 年《广告法》、1990 年《著作权法》继承条款或已失效广告审查员办法时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `服务合同`，子级 `广告设计合同`。定性理由、易混切开结果（制作 / 发布 / 广义混包 / 功能性委托设计 / 委托创作）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、资格、确认人与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、样稿确认人。资格表：设计方是否表面具备广告设计经营范围——无材料不得写成“已具备合法资格”。版本表：正文、任务书、报价、素材清单、聊天确认；冲突并列。

## 5. 成果、权属、对价与验收

交付物是否仅为设计成果；媒介尺寸与源文件格式；著作权是未约定、许可还是转让；许可/转让是否写明种类、媒介、地域、期限；源文件是否与尾款交换；修改轮次；验收是否被写成可以发布。缺口标 `G#`。不输出制作工期或媒介排期。

## 6. 格式条款、强制规范与广告合规提示

是否构成格式条款；提示说明痕迹。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。违法用语、代言人、须审广告只作设计阶段提示，不代替发布审查。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“买断”留在建议句里充作权属安排。

## 9. 谈判与签署提醒

谈判顺序：先红线（权属空词、制作/发布未切开、违法广告结构、倒签），再必须改（许可/转让清单、源文件绑尾款、修改轮次、验收≠发布、确认人），最后可优化。签署提醒：授权、用印、日期、任务书与素材清单、确认邮箱、预付款到账是否作为生效条件。不指导倒签或补假授权。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是广告制作、媒介发布或投放执行安排。
