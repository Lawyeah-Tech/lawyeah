# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的时长、单价、色差、交片日；把已失效《合同法》承揽章或《加工承揽合同条例》写入结论；把货物到场写成安装合格；把母带寄出写成审片合格；把 CPT/CPM 或曝光结算写成制作对价；把无确认脚本开机写成可放行；把全部媒介空置损失写成必然必得；把集资或违禁制作改成可履行结构；把设计或发布当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查广告制作合同（服务合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》承揽章或其解释、已失效《加工承揽合同条例》、已失效《经济合同法》、已失效《互联网广告管理暂行办法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `服务合同`，子级 `广告制作合同`。定性理由、易混切开结果（广告设计、广告发布、广告代理、代言、互联网广告、印刷、定作、施工、委托设计/创作）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、变更单签字人。资格表：广告制作经营资格、影视制作能力、户外安装施工或特种作业、代言许可覆盖。版本表：正文、确认脚本、设计终稿、色样、配乐清单、报价、聊天确认；冲突并列。未核资质：该交片或安装能力字段停止。

## 5. 成片 / 物料给付、变更、验收与对价

核心给付是否按确认稿加工并交付成片或物料；是否夹带设计主轴或 CPT/CPM；开工条件是否含确认稿和预付款；变更单是否当场闭合；粗剪/精剪/成片或到货/安装是否分列；价款是否按件；档期损失是否可预见且有凭证上限。缺口标 `G#`。不输出设计改稿轮次或发布监测主路径。

## 6. 广告合规、格式条款与强制规范

是否禁止擅自加减功效断言或删除忠告语；是否构成格式条款；无限档期转嫁、到货即合格、扣留素材等异常条款是否加黑提示。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。集资/违禁/挂靠只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的实务量级写成法定期限。

## 9. 谈判与签署提醒

谈判顺序：先红线（类型错位、无确认脚本开机、CPT/CPM、无限档期转嫁、功效保证或违禁制作、扣留素材、挂靠施工），再必须改（成品特定化、变更单、审片顺延、权属清单、留置范围、资质附件），最后可优化。签署提醒：双方公章；确认脚本、设计终稿、封样、报价、保险、分包名单、变更单授权人入附件。不指导倒签或补假批文。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是广告设计、广告发布、代言或施工审查。
