# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的单价、数量、工期；把已失效《合同法》承揽章或《加工承揽合同条例》写入结论；把未确认订单写成已经成立；把“24 小时未异议”写成法定承诺；把买卖检验两段期间、所有权保留或货交承运人风险当成已完成的本类型审查；把单笔承揽或建设工程当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查“合同 + 订单” 模式承揽合同（承揽合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》承揽章、《加工承揽合同条例》、《经济合同法》时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `承揽合同`，子级 `“合同 + 订单” 模式承揽合同`。定性理由、易混切开结果（买卖框架订单 `通用型号现货卖方组织生产买方不控制过程→`、单笔加工/定作/修理/复制/印刷/OEM、项目承揽、建设工程）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。挂靠或违法分包写停笔告知。

## 4. 主体、授权名册与文本版本

主体表：签约名、下单名、履行名、付款名、发票名、授权签字人、是否连带。授权表：有权签发/接收订单的经办人、预留印鉴或系统账号、人员变更通知。版本表：框架正文、订单样张、技术标准库、对账单样张、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

框架与订单分层；订单确认通道；图纸/样品/技术标准库；材料由谁提供；批次工作成果验收（签收 ≠ 验收）；价金与对账节点；最低承诺或预估量；调价触发。缺口标 `G#`，不补商业数字。批准、许可写成生效条件或期限，不写成已经完成。

## 6. 格式条款、787 解除与强制规范

是否构成格式条款；沉默视为承诺、单方调价、管辖是否加黑提示。第 787 条解除是否被写成已抛弃；预警期与呆滞料赔偿。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“24 小时未异议”写成法定期限。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线（买卖错位、未确认即成立、挂靠/倒签），再必须改（确认通道、授权名册、图纸验收、对账、787 预警与呆滞料），最后可优化。签署提醒：法定代表人或授权代表签章；授权名册、订单样张、技术标准库、对账单样张入附件；框架期限与新旧订单衔接。不指导倒签或补假授权。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是买卖框架订单或建设工程审查。
