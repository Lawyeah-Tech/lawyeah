# 框架加订单承揽·审查

## 任务目标

在单一立场下，只审查 **承揽合同 / “合同 + 订单” 模式承揽合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文名必须是「审查“合同 + 订单” 模式承揽合同（承揽合同）」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、把买卖框架订单/单笔承揽/建设工程整案改完、把未确认订单写成已经成立。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **承揽框架 ≠ 买卖框架订单**：核心是按定作人图纸、样品或技术参数完成工作并交付工作成果，对价是报酬。库存 SKU 调用、转移通用物所有权换价款 → 负触发 `通用型号现货卖方组织生产买方不控制过程→`。禁止把买卖检验两段期间、所有权保留百分之七十五、货交承运人风险主路径抄进本任务。
2. **订单确认才成立**：框架只锁定通用规则。各笔承揽本约自订单确认（签章、指定邮箱回执或约定系统回执）时成立。未确认订单不得写成已经成立。沉默视为承诺须有第 140 条书面约定；无约定不得把“未异议即接受”写成法定。口头订单须限期书面补正，否则承揽人有权拒绝投产。
3. **框架 ≠ 预约**：框架不是“将来再订合同”。订单确认后即受框架规制，构成该笔本约。不得把框架改成预约，也不得把未确认订单写成已锁定全部未来数量。
4. **授权名册与主体一致**：签约名、下单名、开票名、付款名分列。集团签约、分支或子公司下单须写清授权及是否连带。附件列有权签发和接收订单的经办人及预留印鉴/账号；人员变更须书面通知后生效。
5. **图纸/技术标准库 + 批次工作成果验收**：框架固定通用技术标准与验收规范；订单锁定本次品名、规格、图纸或样品。签收送货单不等于工作成果验收。不得套用买卖第 620–623 条作为本类型默认法。
6. **定作人解除 + 呆滞料预警**：第 787 条随时解除不得写成已经抛弃。可约定书面预警期与呆滞料、已投入工时材料的赔偿。不得把“放弃任意解除”写成已经消灭法定解除权的必然有效条款。
7. **对账闭环与最低/预估量**：定期对账；对账单效力；口头变更须书面变更单。最低采购承诺有强制力，预估量仅供备产。产能超额拒绝是否免责须可执行。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签框架承揽或承揽采购框架正文，并带订单/任务单机制，尚未签署，尚未成争，核心给付是按定作人要求完成工作、交付工作成果、支付报酬，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 库存商品、通用 SKU 调用、转移标的物所有权换价款、无定制工作过程 → `通用型号现货卖方组织生产买方不控制过程→`；不得删掉买卖条款后继续当承揽审，也不得把本类型改成买卖框架订单；
- 无 1+N 结构的单笔加工 → `加工合同·审查`；单笔定作 → `定作合同·审查`；修理 → `修理合同·审查`；复制 → `复制合同·审查`；印刷 → `印刷合同·审查`；定牌加工（OEM）主轴是商标授权代工而非框架订单分层 → `定牌加工（OEM）合同·审查`；单一项目包干无滚动订单 → `项目承揽合同·审查`；
- 建设工程勘察、设计、施工，或建设用地上的建筑安装 → `工地建筑活动承包资质竣工验收→` 或对应建设工程原子；
- 无文本、本类型条件已谈妥、要出己方稿 → `框架加订单承揽·起草`；
- 已签只问下单、交货、对账留痕 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼或仲裁 → `或对应专项领域。` 或对应专项领域。

挂靠、违法分包、禁止流通定制、通谋虚假价款、倒签：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（定作人侧或承揽人侧择一）；相对方；全文及订单样张/授权名册/技术标准库/对账单版本；核心给付是定制工作成果还是库存物所有权；订单确认通道与是否沉默视为承诺；下单主体是否与签约主体同一；图纸或样品如何锁定；对账日与对账单效力；最低承诺还是预估量；解除预警与呆滞料；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的单价、数量、期限用 `【待填】`，不编造。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)
- [框架](references/框架.md)

禁止打开其他类型目录。`框架.md` 中“24 小时未异议视为接受”不是法定承诺，须有第 140 条书面约定才可保留。`基本面.md` 中“订单作为特殊约定优于框架”须落成冲突适用句，不得假定已经优先。不得把 VMI/安全库存写成默认结构。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `框架加订单承揽·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有框架承揽 + 订单文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。买卖框架订单、单笔承揽、项目承揽、建设工程负触发。

### 2. 主体与授权名册

签约名、下单名、付款名、发票名分列。授权名册未附：该下单约束力字段停止。

### 3. 订单成立硬闸

确认通道写死。未确认不成立。沉默视为承诺无法定依据则必须改。

### 4. 图纸、材料、批次验收

框架标准库 + 订单图纸/样品。签收 ≠ 工作成果验收。材料提供与检验按第 774、775 条分列。

### 5. 对账、调价、最低/预估量

定期对账。最低承诺与预估量不得混写。

### 6. 787 解除、呆滞料、格式条款与强制规范

书面预警期与赔偿。放弃任意解除不得写成必然消灭 787。无核验引文则法律结论字段停止。

### 7. 违约、转包与争议

逾期交付、逾期付款、质量不符分列后果。主要工作转第三人须书面同意。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把未确认订单写成已经成立、把库存买卖错位或挂靠/违法分包改成可履行结构。
- `字段停止`：法域、动态规则、授权名册、订单确认通道、许可文号、调价阈值未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类（含 `通用型号现货卖方组织生产买方不控制过程→`）。

生存级预付款或个人无限连带且用户拒绝升级：停止“可以签署”建议。
