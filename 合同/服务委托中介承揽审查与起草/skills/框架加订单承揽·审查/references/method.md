# 审查方法（锁定 承揽合同 / “合同 + 订单” 模式承揽合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止复制买卖框架订单（`通用型号现货卖方组织生产买方不控制过程→`）的检验两段期间、所有权保留、货交承运人风险、特殊动产登记主路径。禁止复制单笔加工/定作 method 或施工挂靠可履行改写。

定性校验：标题、核心给付与本类型一致才继续；库存买卖、单笔承揽、项目承揽或建设工程明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、未确认订单已经成立、对方必然接受或唯一必得金额。

`search_law` 返回已失效《合同法》承揽章及其解释、《加工承揽合同条例》、《经济合同法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突。

示范文本只参考结构。民法典第 470 条允许参照示范文本，不证明本约条款已被接受。买卖框架订单或施工合同范本只证明是另一类型。

知识库纠正（不回写双文件）：

- `框架.md` “承揽人 24 小时内未异议视为接受”：不是法定承诺。第 480 条承诺原则上以通知作出；第 140 条沉默只有法律规定、当事人约定或交易习惯时才视为意思表示。无书面约定不得写成法定。硬闸是**订单确认才成立**。
- `框架.md` “订单优先，但基本法理和违约责任以框架为准”：冲突规则须落成可执行句，不得假定已经优先。
- `基本面.md` “订单作为特殊约定优于框架”：同上，必须写明哪些事项以订单为准、哪些以框架为准。
- `框架.md` VMI/安全库存：可选商业结构，文本未约定不得编造成默认路径。
- `框架.md` “定作人虽有随时解除权，应约定较长书面预警期”：第 787 条可约定通知程序和赔偿范围；不得把“放弃任意解除”写成已经消灭该条的必然有效条款。
- 不得把买卖第 620–623 条检验异议、第 641–643 条所有权保留、第 604 条货交承运人风险补进本类型默认法。

### 1.1 定性

支持切开的规范（法律结论须运行时复核）：

- 第 770 条：承揽是按照定作人要求完成工作、交付工作成果、支付报酬。

- 解释第 6 条：认购书等约定将来订立合同的是预约；已就标的、数量、报酬达成合意且未约定将来另订，或已履行并接受的，可认定本约。框架 + 已确认订单是本约分层，不是预约。

## 节点 3　订单确认才成立（硬闸）

本闸改变各笔承揽本约是否成立。支持依据：第 471、472、480、483、488、491 条；第 140 条；解释第 3、6 条。

### 3.1 框架与订单分层

框架生效只锁定通用条款、技术标准库、对账规则、违约与解除程序。**各笔完成工作、交付成果、支付报酬的债权，自该笔订单确认时成立。** 禁止下列写法：

| 文本写法 | 动作 |
| --- | --- |
| “本框架签字后，定作人发出的任何订单自动生效” | 红线。改为确认后成立 |
| “承揽人收到订单后必须生产，不得拒绝”且无确认程序 | 必须改。超量或无法排产应有拒绝或协商窗口 |
| “框架有效期内的预估量视为已下单” | 红线。预估量不是订单 |
| 要求签订确认书，却写发出即成立 | 必须改。第 491 条第 1 款：要求确认书的，签订确认书时成立 |

修改句（定作人侧可谈确认时限，承揽人侧坚持确认才投产）：

`第【待填】条｜原文“甲方下达订单后本合同项下该批次自动成立”｜建议改为“框架协议仅约定通用规则。每一笔承揽本约自乙方在【待填】小时内通过【指定邮箱回执 / 约定 OA 或 ERP 确认 / 签章回传】确认该订单时成立。逾期未确认的，该订单不成立，甲方不得主张乙方已受约束。乙方确认前不得投产，投产风险自负”｜理由：硬闸 2；第 483、491 条｜可退让：确认时限可谈【待填】小时｜不接受：发出即成立或预估量视为已下单，红线`

### 3.2 沉默不视为法定承诺

第 480 条：承诺应当以通知方式作出，交易习惯或要约表明可以行为承诺的除外。第 140 条：沉默须有法律规定、当事人约定或交易习惯。

| 文本写法 | 动作 |
| --- | --- |
| “24 小时未书面异议视为接受”且加黑、双方协商 | 可保留为第 140 条“当事人约定”，须写通道、起算点和异议方式 |
| 同上但夹在附件小字，或只有“未回复即同意” | 必须改：改为明示确认；或加黑单独签署确认页 |
| 无任何确认或沉默条款，审查意见写成“行业习惯 24 小时默认成交” | 禁止。现有依据不支持把记忆中的行业习惯写成已核验 |

最强反方：定作人主张未异议即承诺，且已实际收货。履行治愈（一方履行主要义务且对方接受）可影响**事后**成立判断，签前不得依赖该路径放行“未确认即成立”。本任务不把已收货写成已经成立——那是履约或争议问题。

### 3.3 实质性变更是新要约

订单回传改了标的、数量、质量、报酬、履行期限地点方式、违约或争议解决：第 488 条为新要约，原订单不因此成立。修改句要求回传文件标注“变更项”，并经对方再确认。

### 3.4 口头订单

合作久、电话微信下单：必须改。所有口头指令应在【待填】日内由发起方补发书面确认件，否则承揽人有权拒绝生产；已生产的，按第 777 条变更赔偿争点另核，不得写成口头已经成立。

## 节点 4　图纸、材料、批次工作成果验收（硬闸）

支持依据：第 771、774、775、779、780、781、784、785 条。

1. **动态标的**：框架写技术标准库或操作规程；订单写本次品名、规格、数量、图纸编号或样品封存号。只有“按甲方通知加工”：标必须改。
2. **材料**：承揽人供料按第 774 条选用并接受定作人检验；定作人供料按第 775 条及时检验，不得擅自更换。混料须分列风险和灭失责任（第 784 条保管）。
3. **验收**：第 780 条定作人应当验收工作成果。批次独立验收期，逾期未书面异议可约定视为该批次合格，但须保留隐蔽瑕疵和承揽人明知不符的例外。
4. **签收 ≠ 验收**：送货单、仓门签收只确认件数与外观，不视为工作成果符合图纸或样品。禁止把买卖第 623 条签收推定直接写成法定。
5. **质量不符**：第 781 条修理、重作、减少报酬、赔偿。只有“依法承担违约责任”视为必须改。
6. **保密与复制品**：第 785 条未经许可不得留存复制品或技术资料。长期合作的工艺改进归属须在框架统一约定，不编造已经归一方。

修改句：

`第【待填】条｜原文“货到签收即验收合格”｜建议改为“每批次工作成果按该订单所附图纸/样品及框架《技术标准库》验收。签收送货单仅确认件数与运输外观，不视为质量合格。定作人应在收货后【待填】日内完成该批次验收；逾期未书面提出不符的，该批次外观视为合格，但不消灭隐蔽瑕疵及承揽人知道或应当知道不符时的责任。不符的，定作人可合理选择修理、重作、减少报酬或赔偿损失”｜理由：硬闸 5；第 780、781 条｜可退让：外观期可短于性能期｜不接受：一次签收消灭全部质量请求`

不得输出买卖“二年补充期间”“所有权保留登记”作为本类型默认句。

## 节点 5　对账、调价、最低承诺与预估量（硬闸）

1. **定期对账**：写对账日、对账单出具人、盖章或财务章、异议期。可约定“收到对账单后【待填】日未书面异议视为确认”，须加黑。对账单是结算依据，但不得写成“无对账单则已交货也不得主张报酬”——与第 782 条及送货/验收证据冲突时必须改。
2. **支付**：按月结算、月结【待填】日。报酬期限不明时，第 782 条指向交付时支付；部分交付相应支付。不编造账期。
3. **调价**：原材料波动触发条件和公式须可执行。只有“随行就市”：必须改。单方调价是异常条款，须提示说明。
4. **最低采购承诺 vs 预估采购量**：前者不达标可约定差额补偿；后者仅供备产，不得写成违约。混用一词：必须改。
5. **产能超额**：定作人突然下达超出【待填】的订单，承揽人可在确认期内拒绝且不构成违约；未约定则承揽人确认后受约束。
6. **定金**：必须使用“定金”二字才讨论罚则。超过主合同标的额百分之二十的部分不产生定金效力（第 586 条）。框架保证金池不是定金，除非写明定金性质。无核验引文不得把 20% 写成已核验结论。

修改句：

`第【待填】条｜原文“年采购量约 10 万件，乙方须保证供货”｜建议改为“附件所列【待填】件为预估量，仅供乙方备产，不构成甲方下单义务。最低采购承诺为每【自然年/季度】【待填】件；甲方确认订单累计不足该数量的，应在该期间届满后【待填】日内按差额×【待填】元向乙方支付补偿，该补偿可调整。超出乙方书面确认产能上限的订单，乙方有权在确认期内拒绝”｜理由：硬闸 7；框架语言｜可退让：补偿改为下一期配额调整｜不接受：预估量当作已下单或必须接单`

## 节点 6　787 解除、呆滞料、格式条款与强制规范

### 6.1 定作人解除 + 呆滞料（硬闸）

第 787 条：定作人在承揽人完成工作前可以随时解除合同，造成承揽人损失的应当赔偿。框架模式下建议拆成：解除**框架**与解除**已确认订单**。

| 文本写法 | 动作 |
| --- | --- |
| “双方同意定作人放弃随时解除权，解除无效” | 必须改。不得写成已经消灭 787 的必然有效条款。可约定书面通知、预警期和赔偿范围 |
| “定作人可随时解除且无需赔偿” | 红线。与 787 赔偿句冲突 |
| 无预警期、无呆滞料 | 必须改：解除框架提前【待填】日书面通知；已确认未完工订单的处理（继续履行或赔偿已投入材料、工时、合理利润）；专为履行框架备置且无法转售的原材料按约定补偿 |
| 框架到期自动消灭未完订单 | 必须改：已确认订单继续履行完毕，除非另书面解除并赔偿 |

修改句：

`第【待填】条｜原文“甲方可随时终止本协议，已备料由乙方自行消化”｜建议改为“甲方解除本框架的，应提前【待填】日书面通知，框架终止不影响已确认且未完工订单，该等订单应继续履行完毕。甲方解除某一已确认订单的，应书面通知乙方，并在【待填】日内赔偿乙方为该订单已投入且无法转作他用的材料费、已完工部分报酬及双方书面确认的其他合理损失。专为履行本框架备置、且甲方连续【待填】日未下单的呆滞料，按双方确认清单由甲方回购或补偿”｜理由：硬闸 6；第 787、777 条｜可退让：预警天数｜不接受：随时终止且备料自负，或约定放弃 787 并写成已经无效`

最强反方：定作人主张 787 无需理由、通知到达即解除。签前仍须把通知形式、已投入损失和呆滞料写成可执行句。本任务不认定已经解除。

### 6.2 格式条款

框架和订单背面条款均可构成格式条款（第 496 条）。审查：沉默视为承诺、单方调价、最终解释权、放弃 787、管辖/仲裁是否有足以引起注意的标识（解释第 10 条）。仅电子勾选不足。未提示的后果是相对方可主张不成为合同内容，不是本任务直接改判无效。

### 6.3 强制规范

违反法律、行政法规强制性规定不一律无效（第 153 条；解释第 16 条）。禁止用已失效“效力性/管理性”口诀。挂靠、违法分包、禁止流通定制：不改写成有效履行。

## 节点 7　违约、转包、争议解决

1. 逾期交付按**该笔订单**总额按日计违约金；逾期付款、质量不符须分别有后果。只有“依法承担违约责任”视为必须改。
2. 第 772 条：主要工作须自己完成，另有约定除外；未经同意将主要工作交第三人，定作人可以解除。辅助工作交第三人，承揽人仍就成果负责（第 773 条）。修改句区分主要/辅助，禁止概括“可任意转包”。
3. 构成违约不等于当然解除。法定解除只点名催告或目的不能实现，不在本任务作出已解除结论。
4. 违约金避免“不得调整”或“按框架总价百分之三十必得”（解释第 64 条：仅以约定不得调整为由主张不予调整的，不予支持）。
5. 争议解决：已有仲裁条款，不得改成“应向某法院起诉”并假装已选定诉讼。或裁或诉、机构不明：改成单一仲裁机构或单一法院连结点。
6. 微信已读不写成已经送达，除非合同把该渠道定为送达。
7. 新旧框架衔接：新框架对存续中旧订单有无追溯力必须写明，默认不追溯，已确认旧订单继续适用旧框架。

## 节点 8　按框架六步出修改句

本节点是成果闸。没有修改句或红线，不得宣称审查完成。禁止只打红黄绿。

对照已加载框架级文件和本方法硬闸，按六步逐段出句。

| 步 | 本类型必须盯的点 | 必须产出 |
| --- | --- | --- |
| 首部 | 标题用框架承揽/承揽采购框架，不用购销/买卖框架；主体与授权；鉴于不写“全部订单已经成立” | 标题或主体修改句 |
| 交易条款 | 订单确认才成立；图纸/标准库；材料；批次验收；对账与报酬；最低承诺≠预估量 | 闭环修改句；缺数字用 `【待填】` |
| 配套 | 逾期交付/付款/质量分列；787 预警与呆滞料；主要工作转包同意；保密与工艺归属 | 可执行后果句 |
| 尾部 | 公章＋授权签字；授权名册、订单样张、标准库、对账单入附件；框架期限与旧订单衔接 | 生效与附件修改句 |
| 语言 | 正说加反说；确认 vs 收到；签收 vs 验收；最低承诺 vs 预估；定金 vs 保证金 | 替换空词的句子 |
| 常见问题 | 未确认即成立；口头订单；无对账；买卖错位；放弃 787；新框架追溯旧订单 | 结构级改法或红线 |

每条修改句固定格式：

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（买卖错位、未确认即成立、预估量视为已下单、挂靠/倒签、随时终止且备料自负拒改）；
- `必须改`：可谈但签署前要落句（确认通道、授权名册、图纸验收、对账、787 预警）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级预付款或个人无限连带且用户拒绝升级：停止“可以签署”建议。
