# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的佣金、提成基数、期限；把已失效《合同法》居间章或《技术合同法》写入结论；把 965 写成中介必胜；把口头说权属没问题写成已尽调；把未核资质写成可以展业；保证技术产生经济效益；把未许可出境、非法垄断或假转让改成可履行结构；把技术转让本约或 `技术类合同项下技术中介本约→` 当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术转让中介合同（中介合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》居间章或其解释、已失效《技术合同法》或其实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `中介合同`，子级 `技术转让中介合同`。定性理由、易混切开结果（`技术类合同项下技术中介本约→`、技术转让/专利权/申请权/技术秘密转让本约、技术许可、咨询/服务/开发、其他中介、委托、行纪）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属附件与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、拟让与方/拟受让方。资格表：职务发明单位授权、共有人书面同意、在先许可披露、技术经纪资质痕迹。版本表：正文、技术清单、成熟度说明、保密承诺、目标方名单、聊天确认；冲突并列。未核权属或共有：该促成/签署能力字段停止。

## 5. 中介事务、报酬、保密与如实报告

核心给付是否仅报告机会或媒介；是否夹带自己让与或对履行提供专门服务；独家或非独家；报酬构成、促成时点、未成费用、提成基数；NDA 与分级披露；书面权属/成熟度/瑕疵报告。缺口标 `G#`。不输出技术转让本约的资料交接、培训或登记操作主路径。

## 6. 跳单、格式条款与强制规范

965 范围与自行获知例外；防跳单是否加黑提示。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。850/进出口/涉密/假转让只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的「1–2 年」写成法定期限。

## 9. 谈判与签署提醒

谈判顺序：先红线（自己让与/履行专门服务错位、签字即全额无论本约成立、无 NDA 披露、850/出境/假转让、保证经济效益），再必须改（报酬节点、965 例外、书面尽调、分级披露、权属附件），最后可优化。签署提醒：双方法定代表人或授权人签字盖章；技术清单、成熟度说明、保密承诺、目标方名单、权属确认入附件；限制出口或涉密许可作为生效前提。不指导倒签或补假许可。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、跳单诉讼策略或效力保证，也不是技术转让本约或技术类合同技术中介审查。
