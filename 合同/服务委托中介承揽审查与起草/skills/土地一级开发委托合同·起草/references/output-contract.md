# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同有效、必然回款、必然摘牌或对方接受；编造未给出的面积、金额、期限、文号；把已失效《合同法》及其解释、1989 年行政诉讼法第十二条不受理清单写入结论；把“注册资本不低于一百万元”写成现行门槛；把一律行政协议或一律民事合同写成已核验；把未招标写成必然整约无效；把名开发实借贷、名开发实施工或一二级联动留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（委托方／政府侧或受托开发企业）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在真实一级委托实施和核定成本回收，以及是否夹带固定回报或二级拿地安排。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1989 年行政诉讼法第十二条不受理清单、2001 年拆迁条例时记噪声，不得写入 `L#`。行政协议识别、仲裁条款、垫资禁令、招拍挂强制、名实切开无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `委托合同`，子级 `土地一级开发委托合同`。定性理由必须同时满足：政府或其授权机构委托实施一级开发；企业真实筹措资金并组织规划、征拆、市政；对价是核定成本加利润或财政开发补偿；本约不绑定二级摘牌。易混切开：名开发实借贷、名开发实施工、一二级联动、拆迁委托、政府代建、一般委托。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `“一二级联动”相关合同·审查`、`名为一级开发实为借贷·审查` 或 `名为一级开发实为施工·审查` method。挂靠、违法分包、伪造授权、定向出让或施工单位垫资写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：委托方机关或储备机构、受托开发企业、项目公司、付款名、发票名、授权签字人、担保人或城投。名称与统一社会信用代码不一致不自动合并。

版本表：正文、红线图、开发方案、成本预估、授权文件、储备计划或会议纪要、选定程序文件、聊天确认。冲突并列，不选对用户有利的一版。口头“已经批准了”“领导同意了”不得写成已授权或已纳入计划。

## 5. 一级开发委托给付闭环

分列并回链文本位置：

- 委托事务：红线范围、面积、开发内容（资金、规划、征拆、市政）。
- 权限与计划：授权文件、土地储备开发计划或等效批准是否覆盖红线。
- 资金：成本构成、按实核定或包干、审计主体、利润计算、支付节点、预算或国库路径。
- 角色：委托实施单位／投资实施主体，而非承建单位垫资。
- 净地与出让：净地标准；未完成不得进入出让。
- 期限：前期手续、征拆、市政竣工。
- 转委托：是否须书面同意。
- 优益权：规划调整解除时的补偿范围。
- 生效：签字成立 vs 批准／预算到位后生效。

缺口标 `G#`，不补商业数字、文号或已批准事实。批准、招投标、预算写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

机关或城投预先拟定且未协商的免责、限责、排除主要权利、单方解除互不补偿、管辖或仲裁，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：施工单位垫资；经营性用地未招拍挂或内定底价；出让金直接返还／先征后返；虚假意思表示掩盖借贷；无行政主体资格且无委托；挂靠或规避必须招标。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“未招标一律整约无效”或“土地一级开发委托当然是／当然不是行政协议”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：委托权限或储备计划未闭合；资金路径或成本核定缺失；固定回报／年化；承建垫资或 BT；内定底价或保证摘牌；出让金直接返还；毛地出让；仲裁条款与行政协议路径冲突；转委托真空；优益权解除互不补偿。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、文号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：授权与储备计划作附件且未批准不生效；成本核定与财政支付路径；删除固定回报或转出借贷原子；删除承建垫资或转出施工原子；删除摘牌优先或转出联动原子；受托方定位为委托实施单位；行政协议路径下改仲裁为行政诉讼。

## 9. 谈判与签署提醒

谈判顺序：先红线（无权委托、假计划、固定还本付息、施工单位垫资、定向出让、毛地出让），再必须改（授权附件、成本核定、预算支付、优益权补偿、争议解决），最后可优化。

签署提醒：有权机关或持书面授权的签字人签；授权文件、储备计划、红线图、成本明细、选定文件作附件；日期真实。不指导倒签或补假批准。

政府侧立场可坚持预算约束和审计核定，但必须写明逾期支付后果。企业侧立场必须提示：授权或预算未闭合时投入资金可能无法回收；即使构成行政协议，合法变更解除的补偿也可能低于民事预期。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、行政诉讼或民事诉讼文书、回款精算终局或效力保证。
