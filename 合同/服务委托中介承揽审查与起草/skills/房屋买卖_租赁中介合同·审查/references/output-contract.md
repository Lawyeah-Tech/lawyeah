# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的佣金、账户、期限；把已失效《合同法》居间章写入结论；把 965 写成中介必胜；把口头说没事写成已产调；把未核备案写成可以展业；把房款改入中介私户；把阴阳/套贷改成可履行结构；把委托/行纪/本约当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查房屋买卖_租赁中介合同（中介合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》居间章或其解释、已失效《城市房地产中介服务管理规定》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `中介合同`，子级 `房屋买卖_租赁中介合同`。定性理由、易混切开结果（职业/婚姻/技术转让中介、一般委托、行纪、销售代理、二手房本约、房产租赁本约）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、备案、人员与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、共有委托人。资格表：经纪机构备案痕迹、承办经纪人/协理签名。版本表：正文、带看确认单、房源清单、告知书、聊天确认；冲突并列。未核备案或人员：该签署能力字段停止。

## 5. 中介事务、报酬、成交款与产调

核心给付是否仅报告机会或媒介；是否夹带代签或以自己名义成交；独家或非独家；报酬比例、促成时点、未成退费；成交款账户是否监管户/出卖人户/专用存款账户；书面产调与房屋状况告知书。缺口标 `G#`。不输出买卖过户或租赁本约的户口/租期主路径。

## 6. 跳单、格式条款与强制规范

965 范围与自行获知例外；防跳单是否加黑提示。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。阴阳/套贷/限购只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“6–12 个月”写成法定期限。

## 9. 谈判与签署提醒

谈判顺序：先红线（代签/行纪错位、房款进私户、阴阳/套贷、签约即全额无论过户），再必须改（报酬节点、965 例外、书面产调、备案人员附件），最后可优化。签署提醒：机构印章 + 一名经纪人（或两名协理）签名；带看确认单、房源清单、书面告知书入附件；成交款账户与佣金账户分列。不指导倒签或补假备案。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、跳单诉讼策略或效力保证，也不是买卖/租赁本约审查。
