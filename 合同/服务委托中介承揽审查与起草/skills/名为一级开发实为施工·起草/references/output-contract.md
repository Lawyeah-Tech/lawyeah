# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的造价、工期、工程量；把已失效《合同法》及其解释、2004 年施工解释、2002 年优先受偿批复、计委令第 3 号写入结论；输出工程款或优先受偿诉讼策略；把本约改成真委托、标准施工合同或投资借贷正文；把施工资质矩阵或“当然优先受偿”写成**本类型**放行条件；把应招未招或政府垫资改成可履行规避结构。

## 1. 触发、单方立场与成果状态

立场（政府/平台发包侧或名义开发商/施工企业侧）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查名为土地一级开发，实为建设工程施工类合同（委托合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2004 年施工解释、2002 年优先受偿批复、计委令第 3 号时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `委托合同`，子级 `名为土地一级开发，实为建设工程施工类合同`。定性理由、易混切开结果（尤其与 `土地一级开发委托合同·审查` 真委托、`名为一级开发实为借贷·审查` 投资借贷、`工地建筑活动承包资质竣工验收→` 标准施工的切开）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。施工内核写明留本任务并点名，不转成 `工地建筑活动承包资质竣工验收→` 实体审查，除非用户改口要标准施工文本。

## 4. 主体、授权、资质与文本版本

主体表：甲方签约名、乙方签约名、付款名、发票名、授权签字人。版本表：正文、工程量清单/施工图、招标或直接发包说明、立项或预算批复、资质复印件、聊天确认；冲突并列。口头“按一级开发算”不得写成已排除施工内核。施工资质未见则该签署能力字段停止，不得因委托标题写成不需要资质，也不得输出 `工地建筑活动承包资质竣工验收→` 全套资质放行表。

## 5. 给付闭环

工程内容与红线；竣工验收 vs 净地验收；进度款/审定决算 vs 回购款/分成；财审时限；权属与风险转移。缺口标 `G#`。不输出优先受偿可执行金额或财审周期终值。批准、招标、立项写成生效条件或期限，不写成已经完成。

## 6. 误套、强制规范与规避结构

施工资质是否被误套或反向豁免；优先受偿是否被写成当然享有；应招未招；政府投资垫资或 BT 回购；挂靠转包；结算语言冲突。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和删除句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得输出施工示范文本整稿；不得把本约改写成真委托分成或借贷回购条款。

## 9. 谈判与签署提醒

谈判顺序：先红线（应招未招拒改、政府垫资/BT 拒改、挂靠转包、当然优先受偿、保证有效），再必须改（名实标题、验收标准、进度款闭环、仅有开发资质、财审时限），最后可优化。签署提醒：工程量清单、技术规范、资质复印件、资金落实说明作为附件；双方盖公章或有权机关印章。不指导倒签、补假招标或伪造立项痕迹。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、真委托审查、标准施工审查、投资借贷审查、工程款或优先受偿文书、效力保证。
