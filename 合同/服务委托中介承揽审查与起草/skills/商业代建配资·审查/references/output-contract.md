# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同有效、已经放款、已经设立抵押权或对方接受；编造未给出的本金、费率、证号、期限；把已失效《合同法》《担保法》《物权法》及其解释写入结论；把银行利率旧四倍、年利率 24% 或 36% 写成现行保护上限；把协助融资写成必须放款；把未登记写成已有优先受偿；把流质写成可以接管项目公司；把纯商业代建、政府/资本/股权代建或无代建的拆借留在本技能改完。

## 1. 触发、单方立场与成果状态

立场（委托方/借款人、代建方/出借人或引资人、第三方资方、保证人、项目公司）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否同时存在代建管理主给付和配资支持，以及配资角色是直接出借、协助引资还是承诺到位。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《担保法》《物权法》及其解释、1991 年借贷意见、2015 年 24%/36% 条文时记噪声，不得写入 `L#`。配资效力、利率上限、流押流质、公司决议无 `verified-result` 时，对应法律结论字段停止。

## 3. 类型与加载路径

父级 `委托合同`，子级 `“商业代建 + 贷款配资” 合同`。定性理由必须同时满足：商业代建管理；配资支持构成对价。易混切开：纯商业代建、政府代建、资本代建、股权代建、合作开发、施工、企业间借款、抵押/质押/保证借款。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `商业代建合同·审查` 或 `资本代建合同·审查` method。职业放贷、转贷、禁止抵押财产包装、流质接管或假放款写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：委托方/借款人、代建方、出借人或引资人、第三方资方、项目公司、土地使用权人、保证人、抵押权人、质权人。自然人写姓名与证件号是否与文本一致；法人写名称与统一社会信用代码。

版本表：代建正文、借款或引资协议、担保协议、权属/四证、内部决议、现金流预测、提款条件、聊天确认。冲突并列，不选对用户有利的一版。口头“已经放款了”“抵押已经办了”不得写成已放款或已公示。

## 5. 代建与配资给付闭环

分列并回链文本位置：

- 代建：范围（报建/营造组织/营销）、是否可核验、管理费计价。
- 配资角色：直接出借 / 协助引资 / 承诺到位。
- 主债权：合同名称与编号、本金大小写、币种、履行期限、放款方式、提款前提。
- 名实：鉴于是否锁定融资需求与代建能力；多份文本是否交叉引用；是否明代建实借贷。
- 费用分列：代建费、利息、顾问费、通道费是否并表。
- 资金闭环：共管账户、支付范围、回款顺序、一票否决对象。
- 担保：财产、权利人是否与债权人一致、登记义务、实现方式是否清算型。
- 交叉违约：代建延误与配资展期；配资逾期与停工/撤品牌；提前还款是否解除代建。
- 任意解除：第 933 条路径是否被文本废除而不写赔偿。

缺口标 `G#`，不补商业数字、证号或已放款事实。批准、登记、放款写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

职业放贷人或机构预先拟定且未协商的，按格式条款审查提示说明。

强制规范与效力红旗只在核验后落法律结论：未取得放贷资格而向不特定对象放贷；套取金融机构贷款转贷；流押/流质/暴力清算；以禁止抵押财产设定抵押；公司对外担保未审查决议；抽逃出资外观。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“企业间借贷一律无效”或“违反三道红线所以整约无效”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型至少检查：配资角色不明或协助写成承诺；明代建实借贷未锁定；代建费/顾问费未并入利率；超保护上限或未核验；抵押权人与出借人不一致；未登记当优先受偿；暴力清算或 1 元收购；保证方式不明却写成连带；公司决议未附；回款顺序冲突；提前还款自动解除代建；任意解除被空白废除。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、证号用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：配资角色写入鉴于；费用分列并待核上限；删除或改写暴力清算；担保权利人一致；与纯代建切开的负触发不得在本节能改完。

## 9. 谈判与签署提醒

谈判顺序：先红线（职业放贷/转贷、暴力清算、禁止抵押财产、伪造放款/决议、保证必然放款），再必须改（配资定性、费用并表、权利人一致、回款顺序、交叉违约宽限期），最后可优化。

签署提醒：委托方、代建方、真实出借人、保证人本人签；公司决议、担保合同作附件；权属证书原件核对；约定先完成约定登记后放款；日期真实。不指导倒签、补假放款或假同意。

委托方/借款人立场必须提示：签字后可能同时承担高成本资金和高强度管理干预；停工权和共管一票否决会影响销售和施工。代建方/出借人立场可建议完成抵押或股权出质登记作为增信，但必须同时写明：未完成登记不得当成已有优先受偿权；即使已登记也不得期前归己所有。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、停工或还款诉讼文书、利息精算终局或效力保证。
