# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的劳务费、户数、工期；把已失效《合同法》《城市房屋拆迁管理条例》写入结论；打开或摘抄 `的method，禁止把本约改成对被征收人的补偿安置文本。` 的补偿测算口径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。成果名称必须写「审查拆迁委托协议（委托合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释或 2001 年《城市房屋拆迁管理条例》时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级、子级、定性理由、易混切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型，且未打开 `的method，禁止把本约改成对被征收人的补偿安置文本。` method。挂靠、违法分包、非法强拆写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。委托人是否为市、县级人民政府确定的房屋征收部门；实施单位是否被写成营利公司或开发商关联方；有无指挥部、项目部印章。版本表：正文、授权委托书、征收决定或批准文号、红线、实施方案、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

受托具体工作清单；保留给政府或征收部门的职权清单；补偿协议署名与征收专用章；劳务费构成与支付节点；补偿款专户与代付／垫付切开；验收（签约率、平稳度、档案、清场）与“拆净”工程验收切开。缺口标 `G#`，不补商业数字。征收决定、补偿决定、强制执行申请写成保留职权或协助义务，不写成已经完成，也不写成已外包。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款。强制规范只区分管理性与是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。抽成、包干、超权、代签、逼迁先改句或停笔，不先宣告整约无效。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。禁止补写对被征收人的补偿标准表。

## 9. 谈判与签署提醒

谈判顺序：先红线（超权、代签、抽成包干、逼迁），再必须改，最后可优化。签署提醒：征收部门公章而非指挥部章；授权委托书作为附件；实施方案、红线、选聘文件；拒绝倒签授权日或征收决定日。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、补偿安置审查或效力保证。
