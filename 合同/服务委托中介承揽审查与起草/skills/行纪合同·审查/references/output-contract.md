# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的限价、报酬、账户、期限；把已失效《合同法》行纪章写入结论；把费用沉默写成可按委托报销；把无市价写成已有介入权；把“一律由委托人向第三人主张、行纪人免责”且无追索路径写成已闭合；把货款视为行纪人所有；把违禁品或无证特许改成可履行结构；把中介/委托/经销当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查行纪合同（服务合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》行纪章或其解释、已失效《关于对外贸易代理制的暂行规定》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `服务合同`，子级 `行纪合同`。定性理由、易混切开结果（一般委托、中介、经销买卖、广告发布、诉讼代理、纯劳务）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、共同行纪人。资格表：进出口或特许许可痕迹。版本表：正文、商品清单、限价表、价格指示函、寄售单、聊天确认；冲突并列。未核贸易资质：该成交能力字段停止。

## 5. 贸易给付、价格、费用、第三人责任与货权

核心给付是否自己名义从事贸易并付酬；是否夹带代签、只撮合或买断；指定价/限价与补差；溢价归属；费用是否书面逐项；第三人违约是先赔还是排除且追索路径闭合；介入权是否具备市价且未被反对；货款账户是否专户；寄售货权是否仍归委托人。缺口标 `G#`。不输出中介跳单或经销价保主路径。

## 6. 介入权、格式条款与强制规范

介入权勾选或禁止；是否构成格式条款；先赔排除、任意定价等异常条款是否加黑提示。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。违禁品/无证特许/资金盘只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的实务量级写成法定期限。

## 9. 谈判与签署提醒

谈判顺序：先红线（类型错位、免责无追索、任意吃差价、无市价自买自卖、货款视为行纪人所有或进私户、货物空过户、违禁品），再必须改（价格指示与补差、费用逐项、专户、留置范围、介入权勾选、资质附件），最后可优化。签署提醒：双方公章；寄售单、限价表、价格指示函、费用清单、专户信息入附件。不指导倒签或补假许可。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是中介、一般委托或经销审查。
