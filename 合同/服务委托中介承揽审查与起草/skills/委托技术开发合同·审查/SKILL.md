# 委托技术开发合同·审查

## 任务目标

在单一立场下，只审查 **委托合同 / 委托技术开发合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文名必须是「审查委托技术开发合同（委托合同）」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、把技术类同名合同整案改完、把无约定改写成成果当然归委托人或当然共有、把非法垄断技术写成可履行结构。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **委托父级切开（同名不同父级必须负触发）**：只审委托合同目录下的委托技术开发。用户或材料按技术类合同进入《技术开发合同》→ `只审委托合同目录下的委托技术开发。用户或材料按技术类合同进入《技术开发合同》→`；进入《委托开发合同》→ `的method。`。禁止把技术类同名合同当本原子审完。
2. **开发归属默认**：无约定时，专利申请权属于研究开发人（受托方）；委托人可以依法实施；受托人转让申请权时委托人同等条件优先受让。禁止写“无约定视为归委托人”或“当然双方共有”。必须把归属写死，或明示适用该默认并写明免费实施与优先受让。
3. **三新 / 非现有技术**：标的须是订立时尚未掌握的新技术、新产品、新工艺、新品种或新材料及其系统。现成转让、无创新改型验证、单纯买卖或劳务负触发。假开发红线。
4. **书面任务书与验收闭环**：无书面不启动实体审查。指标须可量化并入任务书。交付不是验收。尾款挂钩验收结论。
5. **技术风险 ≠ 违约失败**：定义技术风险、通知减损、第三方判定。失败不得一律全额退费。未约定则合理分担，不是受托人独担。
6. **非法垄断技术**：限制后续改良、阻碍吸收类似技术、无偿独占改进成果 → 红线删除，不改成可履行垄断结构。
7. **经费报酬、联系人、止损**：经费与报酬分列；超额/结余分摊；项目联系人权限；书面变更；中期止损；核心人员更换须书面同意。禁止把委托任意解除写成默认主路径。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签委托技术开发正文，尚未签署，尚未成争，用户或材料按**委托合同**父级进入，核心给付是一方出资、另一方以自己技术力量完成三新研究开发，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 用户、封面或材料目录指向「技术类合同 / 技术开发合同」→ `只审委托合同目录下的委托技术开发。用户或材料按技术类合同进入《技术开发合同》→`；
- 用户、封面或材料目录指向「技术类合同 / 委托开发合同」→ `的method。`；
- 双方按约定计划和分工共同或分别承担设计、工艺、试验、试制 → `双方按约定计划和分工共同或分别承担设计工艺试验试制→`；
- 用户或材料锁定「技术类合同 / 软件委托开发合同」→ `可运行软件或系统交付→`。委托合同父级下的软件/系统定制开发仍可留在本任务，不自动转出；
- 只解决特定技术问题、验证或调试既有方案，不产出新方案 → `委托技术服务·审查` 或 `或`；
- 只提供可行性、方案比选等意见，不交付研发成果 → `委托技术咨询·审查` 或 `或`；
- 处理一般事务、核心是任意解除或对外代理 → `一般委托合同·审查`；
- 现成技术转让或许可 → `或对应许可原子；` 或对应许可原子；
- 无文本、本类型条件已谈妥、要出己方稿 → `委托技术开发合同·起草`；
- 已签只问节点、验收留痕、经费拨付 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁 → `或对应专项领域。` 或对应专项领域。

假开发、非法垄断、倒签规避登记：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（委托方侧或受托研发方侧择一）；相对方；全文及任务书/预算/阶段清单版本；进入的是委托合同父级还是技术类父级；是否只有一方做研发；标的是否订立时尚未掌握；专利申请权、技术秘密、软件著作权有无约定；技术风险定义；经费与报酬是否分列；验收是否挂钩尾款；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的经费、报酬、日期、指标用 `【待填】`，不编造。

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)

禁止打开其他类型目录。`基本面.md` 的“三新”按第 851 条补入“新品种”；专利申请权与技术秘密分条，不得把“双方均有使用”套到专利默认。`框架.md` 不得把“归双方所有”当可履行默认，不得把科技部示范文本写成已经享受税收优惠。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `委托技术开发合同·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有委托技术开发文本，才进入本任务。

### 1. 类型锁死与父级切开

标题、核心给付、对价方式和**父级目录**一致才继续。技术类同名、合作开发、技术服务/咨询、一般委托、技术转让负触发。

### 2. 主体、资质、联系人

签约名、履行名、付款名、发票名分列。医药/军工未见许可：字段停止。项目联系人权限和核心人员锁定必须可执行。

### 3. 三新与任务书

指标可量化。交付与验收分列。

### 4. 开发归属默认

无约定按研究开发人享有申请权，并补委托人实施与优先受让。共有须补收益和单独实施/许可规则。

### 5. 经费、报酬、变更、止损

分列。书面变更。中期验收不达标可止损解除。

### 6. 技术风险、非法垄断、格式条款

风险可判定。垄断条款删除。无核验引文则法律结论字段停止。

### 7. 验收、权利担保、登记

指标—验收—尾款。权利担保。技术合同登记写成一方义务，不写成已经免税。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把现有技术改成可履行假开发、把限制后续改良写成可履行、把无约定改成“当然归委托人且受托人不得实施”。
- `字段停止`：法域、动态规则、资质文号、登记能否免税、技术可行性、默示共有如何行使未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类（含技术类同名）。

生存级预付款或个人无限连带且用户拒绝升级：停止“可以签署”建议。
