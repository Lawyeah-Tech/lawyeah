# 网络货运平台模式下的运输合同·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、1999 年《汽车货物运输规则》、1997 年《道路货物运单使用和管理办法》当作现行规则。不得把 2019 年《网络平台道路货物运输经营管理暂行办法》写成唯一现行依据。交运规〔2026〕1 号《网络货运承运平台经营管理办法》是部门行政规范性文件，不是法律或行政法规；MCP 未收录时用交通运输部官网核验，不得升格为法律。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **运输合同 / 网络货运平台模式下的运输合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他类型。场景分层为 **P1**。中文名必须是「网络货运平台模式下的运输合同·审查」。专业版未装本原子时输出 `unavailable`，提示，不得用邻类硬套。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证限额一定成立、把信息中介或货代改成可履行承运结构、把一对一道路货运或劳务派遣按本类型改残。

## 本类型硬闸

1. **名实三件套锁定承运平台，切开信息中介。** 同时看身份声明、运费/发票资金流、派单或在途监控。正像是经营者依托互联网整合运力，以承运人身份与托运人订立运输合同，委托实际承运人完成道路货物运输，承担承运人责任。只发货源运力、不统一承运、不收运费、不开运输发票、不调度车辆 → `一般信息中介平台模式下的合同·审查`。标题写撮合但三件套指向承运的，留本任务，必须改身份句。
2. **不得按普通道路运输或劳务派遣改完。** 无平台整合、一对一公路、主路径是车辆营运证或治超 → `道路货物运输合同·审查` 或 `道路运输合同·审查`。司机注册、抽成、封号或长期驻场用工外观 → `或` 或 `类派遣长期运输·审查`。禁止打开邻类 method 后换标题。禁止把实际承运人改写成派遣工来逃避承运人责任。
3. **许可—合同—发票—保险四统一。** 许可证经营范围须覆盖“网络货运承运平台经营”（历史证件写“网络货运”的，标换证待核）。托运人向平台付运费，平台开运输发票。4.5 吨豁免只适用于实际承运车辆及相应驾驶员，不得写成平台自身可不办网络货运许可。承运人责任险鼓励投保，不替代第八百三十二条。
4. **对外单一责任面。** 托运人只面对平台。改派、拆单不中断对托运人的责任期间。实际承运人可在运单显示，但不是对托运人的免责主体。平台向实际承运人追偿另章约定。禁止“仅技术服务”“司机独立对托运人负责”“仅在司机无力赔偿时补充赔偿”。
5. **货损按第八百三十二、八百三十三条；第八百三十一条只是初步证据；删除失效汽车货规。** 道路普通货运无法定单位限额。格式限额须合理并显著提示，高价值货须提供保价。保险免赔和限额不能自动成为对托运人的合同限额。
6. **轨迹与本票承运信息对托运人披露。** 争议后合理期限内披露本票轨迹、实际承运人信息和交接记录。不得以商业秘密拒绝。保存期限不得短于三年而不作提示。
7. **危货／禁运／超载超限／虚构交易／挂靠。** 只告知，不改成可履行。系统拦截＋合同禁止；不得先运后审。指使或强令超载超限、相互委托虚构运输：红线或停笔。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。身份句、发票／资金流句、货损指向平台句不得整表缺席。

禁止表述：仅技术服务已经切开承运责任；司机自负可对抗托运人；补充赔偿等于已承担承运人责任；4.5 吨豁免覆盖平台自身许可；点击同意即已提示；已保险即免责；合同一定有效或全部无效；先签再改；实际承运人是劳务派遣所以平台无承运责任。

## 工作边界

正触发：已有可读待签正文，尚未签署，尚未成争，核心给付是网络货运承运平台以承运人身份将货物运达并收取运费，用户问能否签、哪里必须改、怎么回对方。标题写成“信息撮合／会员协议”但收取运费并承诺送达的，按本类型审。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 只发布货源和运力、不统一承运、不收运费、不开运输发票、不调度车辆 → `一般信息中介平台模式下的合同·审查`；
- 只撮合订舱报关、不以自己名义承运揽货 → `货运代理合同·审查`；
- 无平台整合运力，一对一公路承运且道路运政许可／车辆营运证／治超为主路径 → `道路货物运输合同·审查` 或 `道路运输合同·审查`；
- 通篇只走民法典货运节、无网络货运外观 → `货运合同·审查`；
- 平台与司机／骑手的注册、抽成、封号协议，无托运人运单主轴 → `或`；
- 长期驻场司机、用工或劳务派遣外观主导 → `类派遣长期运输·审查`；
- 两种以上不同运输方式全程责任 → `多式联运合同·审查`；
- 客运 → `客运合同·审查` 或对应乘客原子；
- 保管、仓单为主给付 → `普通货物仓储合同·审查`；
- 铁路／航空／水路／海上货物单式本约 → 对应单式原子；
- 无文本、本类型条件已谈妥、要出己方稿 → `网络货运平台模式下的运输合同·起草`；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁或货损已立案 → `或对应专项领域。` 或争议专项。

以运输为名运送依法禁止流通物、走私或无相应资质的危险货物：只出告知，不改写成可履行路径。挂靠出借许可证、虚构互委运输、指使超载超限：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（托运人／网络货运承运平台择一）；相对方；全文及用户协议隐藏页、电子运单样张、禁运清单、价目或保价页版本；平台是否声明承运人身份；运费付给谁、谁开何种发票；许可证经营范围痕迹；是否调度派单与在途监控；货损索赔对象；限额或保价；轨迹披露；货类是否危货或禁运；是否把司机写成派遣工或自有员工；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》、汽车货规、1997 年运单管理办法时记为噪声，不得写入 `L#`。把“仅技术服务已切开承运责任”“4.5 吨豁免覆盖平台许可”或“司机是派遣工所以平台无承运责任”写入结论的，同样不得写入 `L#`。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `网络货运平台模式下的运输合同·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议或货运专项。未签且目标是评改已有网络货运承运平台对托运人文本，才进入本任务。

### 1. 名实三件套与类型锁死

身份声明、运费发票、派单监控三者对照。信息中介、货代只撮合、一对一道路货运、一般货运、司机注册、劳务派遣、客运、仓储负触发。标题撮合但收运费、开运输票、承诺送达的，留本任务。

### 2. 平台承运人身份

办法第二条意义上的身份声明；删除仅技术服务、司机自负、补充赔偿、派遣免责。

### 3. 许可、发票、保险四统一

许可证经营范围；运费付给平台；运输发票；承运人责任险鼓励但不替代法定责任。4.5 吨不扩平台。

### 4. 电子运单、改派、交付

每票运单记载实际承运人、车牌、驾驶员、起讫地、费用；改派不中断责任期间；货损通知直接向平台提出即有效。

### 5. 货损、限额、保价

第八百三十二、八百三十三条；第八百三十一条只是初步证据；删除汽车货规；高价值货保价。

### 6. 格式条款与强制规范

无核验引文则法律结论字段停止。仅勾选不够。禁运、超载、虚构交易不得改成可履行。

### 7. 数据披露、解除与争议论坛

轨迹与本票承运信息；许可证失效与系统性不能派单；不要把所有纠纷指定到平台所在地并排除货物所在地保全。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。身份句、发票句、货损指向平台句不得省略。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、仅技术服务／司机自负／补充赔偿／派遣免责并放行、把走私或禁运危货改成可运、把挂靠或虚构互委或强令超载改成可履行。
- `字段停止`：法域、动态规则、许可换证、发票种类、保价费率、精确限额未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
