# 审查方法（锁定 运输合同 / 网络货运平台模式下的运输合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止打开 `一般信息中介平台模式下的合同·审查`、`货运代理合同·审查`、`道路运输合同·审查`、`类派遣长期运输·审查`、`客运合同·审查`、`货运合同·审查` 的 method。禁止把一对一公路的车辆营运证、治超许可窗口做成第一主路径。禁止把平台与司机的关系改写成劳务派遣后宣称承运责任已经切开。

本文件的主线是 **名实三件套（身份 × 运费发票 × 派单监控）+ 平台对托运人的承运人地位 + 与撮合平台切开**。七道硬闸必须走完。缺承运人身份闸或中介切开闸，不得宣称审查完成。不得按普通道路运输或劳务派遣改完。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受或唯一必得金额。

`search_law` 返回已失效《合同法》及其解释、1999 年《汽车货物运输规则》、1988 年汽车货规、1997 年《道路货物运单使用和管理办法》时记为噪声，不得写入 `L#`。把“仅技术服务已切开承运责任”“司机自负可对抗托运人”“4.5 吨豁免覆盖平台自身许可”“司机是派遣工所以平台无承运责任”写成已核验规则的，同样记噪声。交运规〔2026〕1 号《网络货运承运平台经营管理办法》是部门行政规范性文件，不是法律或行政法规；MCP 未收录时用交通运输部官网核验，不得升格。交通运输部解读载明：该办法是对 2019 年《网络平台道路货物运输经营管理暂行办法》的修订，撮合平台另行规定，取消施行期限。2019 年暂行办法不得写成唯一现行依据。

示范文本只参考结构。道路货运本约、货物托运单、配货三方委托、水水联运运单不得当本约。范本若引用失效汽车货规、预置“平台仅撮合”或把司机写成派遣工，当反例。

知识库纠正（不回写双文件）：

- `基本面.md` 经营范围写“网络货运”：现行交运规〔2026〕1 号第六条核发表述为“网络货运承运平台经营”。审查时许可证经营范围须覆盖该表述；历史证件仍写“网络货运”的，标换证待核，不得直接写成已不合规或已合规。
- `基本面.md` 把本类型称为道路货物运输合同：民事给付仍是货物运达，但本任务主路径是平台承运人身份、电子运单、运费发票和对外单一责任面，不是一对一公路的车辆营运证／治超整案。
- 4.5 吨豁免：办法第十条括号例外与站场规定（2023）第十五条只适用于实际承运的普通货运车辆及相应驾驶员。不得写成平台经营者自己可以不办网络货运许可。
- `框架.md` “汽车货物运输规则”：失效，删除，不得当货损依据。
- 办法第十五条“鼓励承运人责任保险”：鼓励不等于已经免除第八百三十二条责任。
- 站场规定（2023）第二十条：MCP 命中的是 2005 年车辆年审旧条，条号已变。本任务不以该旧条作现行默认。挂靠、转让出租证件改引办法第九条、站场规定（2023）第二十三条。
- 办法第二十二条是最小必要保密和依法向主管机关提供，不是平台对托运人拒绝披露本票轨迹的依据。

## 节点 1　名实三件套与类型锁死

### 1.1 灵魂闸：承运平台，不是撮合中介，也不是公路本约或派遣

用标题、核心给付、资金流／发票和对价方式定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

同时核对三件套：

1. **身份件**：文本是否以承运人身份与托运人订约，或虽自称撮合但承诺运达。
2. **对价件**：对价是否是运费（或等价运达对价），托运人是否向平台付款，平台是否开运输发票。不是单纯信息服务费、会员费、货代佣金或派遣管理费。
3. **控制件**：平台是否确认承运、派单、改派或在途监控。核心给付是货物运达，不是促成第三人自行订约，也不是只处理订舱报关，更不是向货主派遣司机。

必须同时满足才正触发：一方是依托互联网整合运力的平台经营者，另一方是托运人；对价是运费或同等运达对价；平台以自己名义确认承运、派单或在途管理。

缺第 2 项且平台不调度、不开运输票：不是本类型。禁止用邻类知识把缺项补成“完整网络货运”后宣称审完。

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 《网络货运运输合同》《电子货运运单》，平台收运费、开运输票、承诺送达 | 本类型 | 正触发；七道硬闸都审 |
| 标题信息撮合／会员协议，正文统一定价、派单、向平台付运费、承诺运到 | 本类型 | 正触发；标题冲突写入 `C#` |
| 只发布货源／运力，运费由货主与司机结算，平台只收信息服务费或会员费，不调度 | 网络货运撮合平台／信息中介 | 负触发 `一般信息中介平台模式下的合同·审查`。办法第三十一条：撮合另行规定 |
| 只订舱、报关、仓储、短驳，报酬是代理费，不以承运人身份揽货 | 货运代理 | 负触发 `货运代理合同·审查` |
| 货代以自己名义签发道路运单或承诺运到并收运费差价 | 可能跃迁为承运 | **不按货代放行后假装已切开**。有平台整合与网络货运外观则留本任务；无平台外观转 `货运合同·审查`／`道路货物运输合同·审查` |
| 一对一公路承运，无平台整合，主路径是车辆营运证、治超、道路危货资质 | 道路货物运输 | 负触发 `道路货物运输合同·审查` 或 `道路运输合同·审查`。禁止把治超七闸抄进本任务 |
| 通篇货运节，无网络货运许可或平台派单外观 | 一般货运 | 负触发 `货运合同·审查` |
| 司机／骑手注册、抽成、封号，无托运人运单 | 平台用工 | 负触发 `或` |
| 长期驻场司机、接受货主管人、正文主给付是派遣劳动力 | 派遣／长期运输易混 | 负触发 `类派遣长期运输·审查`。禁止按劳务派遣改完承运责任 |
| 两种以上不同运输方式全程负责 | 多式联运 | 负触发 `多式联运合同·审查` |

同一平台可能同时存在“对货主的运单”和“对司机的注册／合作协议”。只审用户提交的那一份；两份都在且主给付不同，拆开路由，不在本任务合并审用工或派遣。

### 1.2 加载协议（硬闸）

本技能已锁定 **运输合同 / 网络货运平台模式下的运输合同**。只打开 `references/基本面.md` 与 `框架.md`。禁止读其他类型目录，禁止为对照再开第二类。禁止打开 `一般信息中介平台模式下的合同·审查`、`货运代理合同·审查`、`道路运输合同·审查`、`类派遣长期运输·审查`、`客运合同·审查`、`货运合同·审查` 的 method。

### 1.3 违法或规避结构停笔

加载后或定性中出现：倒签接单日或运单日；挂靠或出借道路运输经营许可证；无相应资质承运危险货物或禁运物；指使或强令超载超限；虚构运输交易相互委托；把走私或依法禁止流通物改成可运。

动作：

1. 交付告知：该结构违反道路运输条例、办法第九／十一／十三条、第二十五条或民法典第一百五十三条指向的强制规范，不得改写成可履行文本。
2. 不写假许可模板、倒签步骤、可履行的超载或互委路径、可履行的危货普运结构、可履行的派遣避责结构。
3. 风险表只保留识别依据和删除／转出口径。
4. 用户坚持“改到能运”：整体停止。

合规改道（真实取得网络货运许可、真实危货资质、真实拒绝禁运）只点名，不在本任务起草。

## 节点 2　平台承运人身份（硬闸）

支持依据（当次核验写入 `L#`）：交运规〔2026〕1 号第二条（以承运人身份与托运人签订运输合同，委托实际承运人完成道路货物运输，承担承运人责任）；第三十一条（信息交易撮合另行规定）；民法典第八百零九条（运输合同定义）、第八百十一条（安全运到约定地点）、第八百三十二条（掌管期间货损）。

### 2.1 必须出现的身份句

合同或运单须能回链到相当于下列意思的句子：**平台作为承运人与托运人订立本合同，对货物运输承担承运人责任。** 承运人责任不得只写在用户协议隐藏页。

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 缺身份句，或写成“仅提供技术服务／信息匹配／交易撮合” | **必须改**。补承运人身份；删除相反意思 | 标题写网络货运就已是承运人；技术服务已切开 |
| “司机／实际承运人独立对托运人承担责任，平台不承担” | **红线删除**。实际承运人可在运单显示，但不是对托运人的免责主体 | 列了车牌就算已切开平台责任 |
| “平台仅在司机无法赔偿时补充赔偿／视情况垫付／酌情补偿” | **红线改为**平台依法承担承运人责任，再向实际承运人追偿 | 补充赔偿＝已经负责；先行赔付当噱头可留 |
| “司机为劳务派遣工／灵活用工，平台不承担运输责任” | **红线删除**。用工安排不能对抗托运人的承运请求 | 写成派遣就已切开；按 `类派遣长期运输·审查` 改完本约 |
| 改派、拆单后“原运单责任终止，由新司机负责” | **必须改**：改派不中断对托运人的责任期间 | 算法改派所以平台不知情 |
| 持有网络货运许可，合同却按中介免责 | 名实不符。按承运人义务认定并改条款 | 有许可但合同可继续当中介 |
| 无许可却以承运人揽货收款 | 行政违法红旗；民事合同不当然无效；更难主张中介免责。经营能力字段停止 | 无证所以一定无效；无证所以一定是中介 |

### 2.2 最强反方

相对方主张：标题是会员协议；实际运输由司机完成；平台没有自有车辆；点击同意了免责页；司机是外包或派遣。回应：办法第二条看的是以承运人身份订约并承担承运人责任，不是自有车辆；无车正是本模式；隐藏页免责和派遣标签不能对抗身份与资金流。依据不足时字段停止，不写成“已经是中介”或“已经是承运人且免责有效”。

## 节点 3　许可、发票、保险四统一（硬闸）

### 3.1 主体表

建表：网络货运承运平台签约名、履行名（含分支机构）、付款名、运输发票开具名、托运人、收货人、运单记载的实际承运人／车牌／驾驶员、授权点击账号。名称不一致不自动合并。

### 3.2 许可证

办法第六条：需要申领的，向所在地县级交通运输主管部门申请，《道路运输经营许可证》经营范围为网络货运承运平台经营。第七条：经营性互联网信息服务要求与线上服务能力。第九条：在许可范围内经营。

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 未见许可或经营范围 | 标 `G#`；经营能力字段停止；修改句要求作为附件 | 可以先签后办证；4.5 吨所以平台不用许可 |
| 经营范围是普通货运／货运站，不是网络货运承运平台经营 | 红旗。修改句要求范围覆盖或停止以该身份揽货 | 有任何道路运输证即可 |
| 历史证件写“网络货运” | 标换证待核，不直接宣布失效或有效 | 旧证一律作废；旧证一律等同新证 |
| 实际承运车辆总质量可能 ≤4500 千克且普通货运 | 该车／该驾驶员可豁免两证；平台自身许可不豁免 | 平台也豁免 |

### 3.3 运费与发票

托运人向平台支付运费；平台开具运输费用发票。平台再与实际承运人结算（办法第十二条：按约定及时向实际承运人结算）。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| 司机直接向货主收款，平台只抽佣且不开运输发票 | 模式已滑向中介。改定性或改资金流；不能两头落空 | 抽佣就是运费；开普票也算运输票 |
| 签约主体与开票主体不一致 | **必须改**：谁签约收款，谁开运输发票 | 第三方代开即可放行 |
| 价目只写会员费／技术服务费，另收运费差价 | 必须拆清运费与平台服务费；运费仍应付给承运身份的平台 | 改个名字就不审运费 |
| 数字未给 | 写 `【待填】`，不编造单价 | 按行业惯例补一个价 |

### 3.4 保险

鼓励平台投保承运人责任险（办法第十五条）；实际承运人投保交强险和相应商业险。保险免赔和限额不能自动成为对托运人的合同限额。已保险不免平台责任。

## 节点 4　货物、电子运单、改派、交付

### 4.1 货物与禁止事项

品名、包装、重量、体积、是否危货。办法第九条：不得运输法律法规规章禁止运输的货物。第十条：审查实际承运车辆及驾驶员资质；线上线下一致；委托不得超越实际承运人经营范围。超出许可范围的自动拒绝，不得“先运后审”。站场规定（2023）第二十九条：不得运输法律、行政法规禁止运输的货物；限运、凭证运输须查验手续。

危货、超限大件超出平台许可或实际承运人资质：红线禁止承揽。匿报危货：托运人承担费用和事故责任；平台明知故派的分担，不得改成平台无责。

### 4.2 电子运单

每票运单是合同组成部分，记载实际承运人、车牌、驾驶员、起讫地、费用。禁止“运单仅供内部”。框架协议与运单冲突：并列，修改句选定以运单记载的履行事实为准或删除冲突句。不得以“未签纸质合同”否认电子下单。成立时点按支付或平台确认接单。站场规定（2023）第三十一条鼓励电子合同、电子运单，不把未采用电子运单写成合同未成立。

1997 年运单管理办法已失效，不得引用。

### 4.3 改派与在途

平台可更换实际承运人，但不中断对托运人的责任期间。监控轨迹、异常停留、偏离的权力越大，越不能主张“不知情的信息方”（办法第十八条：对运输、交易全过程实时监控和动态管理）。

### 4.4 交付与异议

签收方式、异常破损拍照、等待超时。货损通知直接向平台提出即有效。第八百三十一条：约定期限或合理期限未提出异议的，视为按运输单证记载交付的**初步证据**，不是不可推翻的完好交付。电子签收过短异议期应改为外观当场、隐蔽损害合理期限。

收货人不明或无正当理由拒领：第八百三十七条提存，不得擅自变卖。交付前变更到达地或收货人：第八百二十九条，须写费用。

## 节点 5　货损、限额、保价（硬闸）

支持依据：第八百三十二条（承运人对运输过程中毁损、灭失赔偿；不可抗力、货物自身性质或合理损耗、托运人／收货人过错为免责且承运人举证）；第八百三十三条（有约定从约定；否则按交付或应当交付时到达地市场价格；法律、行政法规另有限额的除外）；第八百三十五条（不可抗力灭失，未收运费不得请求，已收的可返还）。

道路普通货运没有法律、行政法规规定的单位责任限额。当事人约定限额属于格式限责，须公平、显著提示，并提供保价选项。高价值货不能默认按运费若干倍。部门规范性文件不得冒充第八百三十三条的“法律、行政法规另有限额”。

| 文本写法 | 动作 | 不得写成 |
| --- | --- | --- |
| 货损按《汽车货物运输规则》或失效货规 | **删除**。改引第八百三十二、八百三十三条 | 行业惯例所以可引用失效规则 |
| 实际承运人过错即平台免责 | **红线删除**。平台先赔再追偿 | 履行辅助人过错等于不可抗力 |
| 未保价一律按运费 2／3／10 倍 | 必须改：合理限额＋显著提示＋保价；高价值货默认保价或按到达地市价 | 倍数就是法定限额 |
| 保险限额自动等于合同限额 | 必须拆开 | 已投保即免责 |
| “签收即视为完好，逾期不得索赔”且期限过短 | 改为第八百三十一条初步证据＋外观／隐蔽分列 | 电子签名＝不可推翻验收 |

不可抗力免责不得扩到平台未审核资质、明知无资质仍派单、系统可拦截而未拦截。第八百三十二条三项免责之外的“平台已尽审核即无责”不得放行。

## 节点 6　格式条款与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 是否格式条款

平台用户协议、点击确认页、运单背面多为重复使用、未协商。不得仅以“这次没用过第二次”否认。

### 6.2 提示说明

民法典第四百九十六条；合同编通则解释第十条：电子合同仅勾选、弹窗，不得认定已尽提示或说明，除非另证明显著标识和可理解说明。身份相反意思、货损限额、管辖、单方改规则、视为完好交付、派遣免责，须单独加黑或确认页。

第四百九十七条、第五百零六条：不合理免责、排除主要权利、故意或重大过失财产损失免责，无效。第四百九十八条：争议时不利解释。只在核验后作为修改理由，不代替修改句。

用户协议更新对未完成运单原则上不得溯及加重责任。

### 6.3 强制规范

第一百五十三条；解释第十六条。未取得网络货运许可从事经营，通常先产生行政责任，不当然导致民事合同无效。履行必然导致运输禁运物、超载超限或虚构交易的，不改成可履行。禁止用已失效“效力性／管理性”口诀代替解释第十六条。

办法第十一条不得虚构运输交易相互委托；第十三条不得指使或强令超载超限；第十七条不得利用数据和算法、技术、平台规则收取不合理费用。站场规定（2023）第二十三条：《道路运输证》不得转让、出租、涂改、伪造。

## 节点 7　数据披露、解除、争议论坛

### 7.1 数据与个人信息

办法第十八条：记录用户注册、身份认证、服务与交易信息；交易信息包括订单日志、结算、含时间和地理位置的实时行驶轨迹；保存自交易完成之日起不少于三年，涉税资料十年。第二十二条：最小必要使用驾驶员、收货人信息；未经同意不得泄露、出售或挪作他用；主管机关依法调取的，如实提供。

争议发生后，平台应在合理期限（修改句用 `【待填】` 日，建议不超过十五日）向托运人披露本票轨迹、实际承运人信息和交接记录，作为货损区段的初步证据。**不得以商业秘密拒绝披露本票承运信息。** 第二十二条不能写成对托运人的拒披露权。可对无关第三方脱敏。

### 7.2 解除与停运

托运人匿报危货：平台可拒绝或就地停运。平台许可证失效、系统性不能派单：须写未完成运单的移交和赔偿安排。不得只写“双方协商解除”而无通知和清理。

### 7.3 留置与运费

第八百三十六条：留置限于相应运输货物，不得扩到托运人任何财产。不可抗力灭失：第八百三十五条返还已收运费。禁止“运费概不退还”一刀切。

### 7.4 争议解决

诉讼或仲裁须单一连结点。不要把所有纠纷指定到平台所在地并排除货物所在地保全。或裁或诉、机构不明：标待核。出现仲裁条款：不得改写成“应向某法院起诉”并假装已选定诉讼。本任务不写起诉状或时效精算。用户追问货损怎么赢：目标停止。
