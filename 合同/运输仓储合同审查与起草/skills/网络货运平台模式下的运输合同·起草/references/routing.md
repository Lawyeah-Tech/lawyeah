# 边界与路由

本技能只审查 **运输合同 / 网络货运平台模式下的运输合同** 的待签文本。中文展示名是「审查网络货运平台模式下的运输合同（运输合同）」。场景分层为 P1：专业版未装则 `unavailable`，提示，不得用邻类硬套。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。禁止打开邻类 method 后换标题交差。禁止按普通道路运输或劳务派遣改完本类型。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符且无法判断资金流／派单 | 本套导航的类型切开步骤 |
| 只发布货源／运力，不统一承运，不收运费，不开运输发票，不调度车辆 | `一般信息中介平台模式下的合同·审查`。P1：未装则 `unavailable` |
| 只订舱、报关、仓储、短驳，报酬是代理费，不以承运人身份揽货 | `货运代理合同·审查`。P1：未装则 `unavailable` |
| 一对一公路承运，无平台整合，主路径是车辆营运证、治超、道路危货资质 | `道路货物运输合同·审查` 或 `道路运输合同·审查` |
| 通篇货运节，无网络货运许可或平台派单外观 | `货运合同·审查` |
| 司机／骑手注册、抽成、封号，无托运人运单主轴 | `或`。P1：未装则 `unavailable` |
| 长期驻场司机、接受货主管人、劳务派遣外观主导 | `类派遣长期运输·审查`。P1：未装则 `unavailable` |
| 两种以上不同运输方式全程负责 | `多式联运合同·审查`。P1：未装则 `unavailable` |
| 客运 | `客运合同·审查` 或对应乘客原子 |
| 保管、仓单为主给付 | `普通货物仓储合同·审查` |
| 铁路／航空／水路／海上货物单式 | 对应单式原子 |
| 有完整待签文本要评改 | `网络货运平台模式下的运输合同·审查` |
| 无文本、本类型条件已谈妥、要出己方稿 | 本任务起草并自审 |
| 已签未争、只问在途节点、回单或开票日历 | 本套导航的履约步骤 |
| 已催告、索赔、立案、开庭，或主问货损怎么告平台 | `或对应专项领域。` 或货运争议专项 |
| C 端大众快检 | 只分流，不回改 |

标题写“信息撮合”“会员协议”“技术服务”，正文却向平台付运费、开运输票、统一定价派单、承诺送达：留在本任务，按承运人身份闸审查，不转 `一般信息中介平台模式下的合同·审查`。

标题写“网络货运”，正文却只撮合、运费司机与货主直接结算、平台不开运输票、不调度：负触发 `一般信息中介平台模式下的合同·审查`，不得按本类型改完后假装已切开。

货代以自己名义签发道路运单或承诺运到并收运费差价：不得因标题写“代理”而转出后假装已切开承运责任。有平台整合与网络货运外观则留本任务；无平台外观转 `货运合同·审查` 或 `道路货物运输合同·审查`。

一对一《道路货物运输合同》没有平台整合、没有电子运单系统：不在本任务补“网络货运”三字后放行。负触发道路货运或一般货运原子。不得把车辆营运证、治超窗口做成第一主路径。

正文把实际承运司机写成劳务派遣工、平台“仅作为用工单位/信息方”：不得按派遣协议改完。有托运人运单和运费外观则留本任务，红线删除派遣免责；无运单主轴转 `或` 或 `类派遣长期运输·审查`。

仅缺许可文号、保价费率或保额，但给付仍是平台对托运人承运：留在本任务，必须出显化句，相关字段停止。

用户要把“仅技术服务／司机自负／补充赔偿／派遣免责”留在可履行结构：不按本类型放行。
