# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的运费、限额、保额；把已失效《合同法》及其解释、汽车货规写入结论；把 2019 年暂行办法写成唯一现行依据；把本案改成普通道路运输或劳务派遣审查。

成果名称必须含「审查网络货运平台模式下的运输合同（运输合同）」。

## 1. 触发、单方立场与成果状态

立场（托运人／网络货运承运平台）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、汽车货规、1997 年运单管理办法时记噪声，不得写入 `L#`。交运规〔2026〕1 号用官方公开文本核验的，在本表记来源和日期。

## 3. 类型与加载路径

父级 `运输合同`，子级 `网络货运平台模式下的运输合同`。定性理由必须同时交代名实三件套：平台是否整合运力并以承运人身份对托运人订约；运费是否付给平台或存在同等运达对价；是否调度派单或在途监控。易混切开结果（信息中介 / 货代 / 道路货运 / 一般货运 / 平台用工 / 劳务派遣 / 多式联运 / 客运 / 仓储）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。禁止打开 `一般信息中介平台模式下的合同·审查`、`货运代理合同·审查`、`道路运输合同·审查`、`类派遣长期运输·审查`、`客运合同·审查`、`货运合同·审查` 的 method。挂靠、虚构互委、禁运或强令超载写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：平台签约名、履行名、付款名、运输发票名、托运人、收货人、运单记载的实际承运人、点击确认账号。许可表：道路运输经营许可证经营范围是否覆盖“网络货运承运平台经营”或历史“网络货运”换证待核。版本表：正文、用户协议隐藏页、电子运单、价目／保价页、聊天确认；冲突并列，不选对用户有利的一版。司机注册协议或派遣协议若一并提交，只记录“另件，不在本任务合并审用工”。

## 5. 给付闭环

身份声明是否以承运人订约；货物与禁运拦截；电子运单记载；运费资金流与运输发票；改派是否中断责任期间；交付与货损通知是否可直接向平台提出；保价或限额；轨迹披露时限。缺口标 `G#`，不补商业数字。许可、换证写成条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款（身份相反意思、限额、视为完好、管辖、单方改规则、派遣免责）；网络勾选／弹窗是否足够。强制规范只区分是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。交运规〔2026〕1 号不得写成法律或行政法规。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。承运人身份、发票资金流、货损指向平台三类风险不得整表缺席（正触发且文本涉及该事项时）。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。身份句、发票句、货损指向平台句不得省略。

## 9. 谈判与签署提醒

谈判顺序：先红线，再必须改，最后可优化。签署提醒：授权与点击确认痕迹、许可证和保险单附件、运单样张、禁运清单、保价单独确认、用户协议版本不溯及未完成运单。不指导倒签或补假许可。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只起草并自审，不评改对方来稿。待签评改转配对 ·审查 原子。草稿必须落入本类型三闸。不是履约交底、争议文书或效力保证。
