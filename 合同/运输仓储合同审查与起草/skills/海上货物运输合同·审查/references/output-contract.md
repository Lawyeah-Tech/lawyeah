# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或限额必然成立；编造未给出的运费、件数、申报价值；把已失效《合同法》、《国内水路货物运输规则》写入结论；把水路货运、客运或父级海上文本当成已完成的本类型审查；写“沿海内贸当然适用航海过失免责和第五十六条”；写“无单放货保函可以对抗正本持有人”；写“卸入堆场即已交付”；写“放弃索赔”可放行。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查海上货物运输合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《国内水路货物运输规则》、GF—97—0404 或法发〔1992〕37 号中的《经济合同法》口径时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `运输合同`，子级 `海上货物运输合同`。定性理由、易混切开结果（水路货运 / 海上客运 / 父级海上 / 货运代理 / 多式联运 / 航次租船）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开邻类 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、签单身份、航区与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。身份表：承运人／实际承运人／无船承运人／货代是否 as carrier。航区表：装港、卸港、中途港、是否两端中国港口、第四章是否适用。版本表：正文、提单样张、费率表、危规申报、电放指示、聊天确认；冲突并列。

## 5. 提单、责任期间、单位责任限制

提单或海运单种类、正本份数、电放、凭单放货；责任期间是否短于第四十六条强制期间；集装箱与非集装箱是否分开；“视为已交付”是否提前结束掌管；甲板货、危险品是否记载；单位责任限制是按件还是按公斤，有无申报价值程序；沿海是否被误套第四章限额或旅客限额。缺口标 `G#`。不输出水路货规保价主路径，不输出旅客伤亡限额。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。适航、管货概括取消，责任期间短于强制期间，无单放货操作化，两套正本，预借倒签，不得写成可放行。强制规范按第四十四条区分条款无效还是整约问题，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把内河运单直接写成“海运提单类型”而不问航区。责任期间修改句必须写清集装箱接收至交付、非集装箱装船至卸船，或明确书面延长。

## 9. 谈判与签署提醒

谈判顺序：先红线（航区错套第四章、责任期间短于强制期间、无单放货操作化、两套正本、预借倒签、只赔运费、货代签单却否认承运人），再必须改（提单栏位、交付定义、申报价值、电放书面流程、实际承运人连带、管辖可识别），最后可优化。签署提醒：提单由承运人或具名代理签发并注明被代理人；样张背面与框架协议的解释顺序；到付须在提单显示。不指导倒签、预借或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书或效力保证，也不是水路货运、海上客运或货运代理安排。
