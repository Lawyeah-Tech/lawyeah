# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的运费、限额、滞箱费率；把已失效《合同法》、1997 年《国际集装箱多式联运管理规则》、水路货规或汽车货规写入结论；无海运写成可适用海商法单位责任限制；把货方证明损坏区段写成索赔受理条件；把一般货运、道路货运、单式运输或货代只撮合当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查多式联运合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1997 年多式联运管理规则、水路货规、汽车货规时，记噪声，不得写入 `L#`。海商法整部被标“已被修改”但第一百零二至一百零六条文字仍命中的，记录冲突，按条文文字适用，不得写成专节废止。

## 3. 类型与加载路径

父级 `运输合同`，子级 `多式联运合同`。定性理由、易混切开结果（一般货运 / 道路货运 / 同一方式联运 / 铁路 / 航空 / 海商 / 水路 / 货代 / 网络货运 / 客运 / 仓储）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。禁止打开 `货运合同·审查`、`道路货物运输合同·审查` 的 method。

## 4. 主体、签单身份与文本版本

主体表：经营人签约名、签单章／提单抬头、履行名、付款名、发票名、授权签字人；托运人、收货人、通知方分列；区段承运人只作附件名录。货代以自己名义签多式联运单据的，经营人身份按已锁定处理。版本表：正文、单据样张、背面条款、区段名录、箱封记录、保险、聊天确认；冲突并列。

## 5. 方式组合、单据、区段责任与给付

运输方式是否≥两种且互不相同；是否含海上运输（决定民法典专节还是海商法第四章）；是否在接收货物时签发多式联运单据及可转让性、正本份数、电放条件；责任期间是否自接管至交付；第八百三十九条是否被下沉；第八百四十二条网状规则是否被改成就低或“货方证明区段”；区段不能确定时走运输章还是（仅含海运时）海商法第一百零六条；全程运费与目的地费用、留置范围。缺口标 `G#`。不输出单式运政许可精算，不输出海商法第五十六条必得限额。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。就低限额、区段义务下沉、无单放货、无海运套海商法限额不得写成可放行。强制规范只按第一百五十三条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把单式运单栏目或货代委托直接写成“多式联运类型”而不问方式组合和签单。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为单式或货代、无海运套海商法限额、货方证明区段才受理、全程义务下沉、正本在外电放、走私或禁运），再必须改（单据签发与可转让性、网状责任原文、接管至交付、第八百四十一条、运费与留置、一个争议论坛），最后可优化。签署提醒：经营人名称与签单章／提单抬头一致、单据样张与背面冲突规则、区段名录、箱封记录、保险。不指导倒签接管日或无单放货。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书或效力保证，也不是一般货运、道路货运、单式运输或货代安排。
