# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、人身必赔或必然可营运；编造未给出的票价、限额、船名；把已失效《合同法》及其解释、第四章货物免责、货物一年时效、民用航空法旅客条文或《水路旅客运输规则》写入经海路旅客结论。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。成果名称写「审查海上乘客运输合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》、失效水路货规、第四章货物规则、民用航空法旅客条文当作旅客依据时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级、子级、定性理由、易混切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。渔船货船载客或无证营运写停笔告知，不填可营运结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、履行名、收款名、发票名、授权签字人、实际承运人、船舶所有人。版本表：正文、客票背面、邮轮旅游条款、团体名单、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

航线是否经海路、沿海或国际、船名与舱位、客票效力、行李与车辆分轨、票款拆分、退改安置、保险。缺口标 `G#`，不补商业数字。许可、客船证书写成生效或发航条件，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；客票背面提示说明痕迹。强制规范只区分管理性与是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。货物章免责、票价封顶、风浪自负、视为过失被改必须落入风险表。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线，再必须改，最后可优化。签署提醒：授权、用印、出票或电子支付、旅客名单附件、客船证书摘要、条件成就凭证。不指导倒签或补假证书。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只起草并自审，不评改对方来稿。待签评改转配对 ·审查 原子。草稿必须落入本类型三闸。不是履约交底、争议文书或效力保证。
