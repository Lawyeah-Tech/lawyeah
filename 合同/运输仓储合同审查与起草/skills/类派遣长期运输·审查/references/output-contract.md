# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的运价、运次、人数；把已失效《合同法》及其解释写入结论；把三性 / 10% 写成运输合同放行条件；把供人结构改成可履行规避用工。

成果名称必须含「审查与劳务派遣合同易混淆的长期运输服务合同（运输合同）」。

## 1. 触发、单方立场与成果状态

立场（委托方／承运人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2007 年劳动合同法第五十七条五十万旧文、2004 年道路运输条例第二十一条旧文本时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `运输合同`，子级 `与劳务派遣合同易混淆的长期运输服务合同`。定性理由必须同时满足：较长时期内持续提供车辆、驾驶员和运输组织；给付目标是旅客或货物位移；常带驻场 / 包车 / 年度框架 + 运单，或标题写成派遣 / 外包但给付仍是运输。易混切开结果（道路运输总类 / 客运 / 货运 / 培训服务期 / 真实派遣 / 劳动合同 / 业务外包 / 平台用工）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `道路运输合同·审查`、`与培训服务期及派遣劳动原子切开：专项培训服务期→负触发`、`客运合同·审查`、`货运合同·审查` 或劳务派遣相关劳动原子的 method。知识库与硬闸冲突时，以 method 硬闸为准。挂靠、无证经营、无证派遣改运输写停笔告知，不填可履行规避用工结构。

## 4. 主体、授权、资质与文本版本

主体表：委托方、承运人、驾驶员（不得列为与委托方的劳动合同主体）、付款名、发票名、授权签字人。版本表：正文、附件、运单 / 派车单样张、聊天确认；冲突并列，不选对用户有利的一版。许可字段未核则停止，不写“可以营运”。

## 5. 给付闭环

运输对象（货或旅客）、线路或区域、人车油是否捆绑、调度与指挥、计价、运单、替换权、发票品目。缺口标 `G#`，不补商业数字。许可写成条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；“工伤自负”“与甲方无关”“货损由司机个人赔”等异常条款。强制规范只区分是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔 / 转出口径。禁止输出无修改句的色块表。运输 vs 派遣、人员管理、人车油三类风险不得整表缺席（正触发且文本涉及该事项时）。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`，不编造。禁止只给原则、不给句子。运输 vs 派遣句、人员管理句、人车油句不得省略。

## 9. 谈判与签署提醒

谈判顺序：先红线，再必须改，最后可优化。签署提醒：授权、用印、日期、车辆清单、驾驶员名单（注明系承运人员工）、许可证、保险、运单样张。不指导倒签或补假授权。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书或效力保证。
