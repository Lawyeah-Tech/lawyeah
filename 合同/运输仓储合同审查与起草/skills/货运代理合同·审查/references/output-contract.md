# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的费率、时限、限额；把已失效《合同法》、汽货规、水路货规、国际海运条例 2001 年第 7 条写入结论；把标题“代理”写成已切开承运责任；把无船承运或自己名义签单改回“货损概不负责”仍放行；把网络货运改名后按纯代理放行；把口头指示写成已授权倒签或预借；把未核备案写成可以签单展业。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查货运代理合同（运输合同）」。签单混写或无船承运外观须声明：未假装已切开。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、汽货规、水路货规、1997 年运单办法、2012 年海上货代规定未修正本或国际海运条例 2001 年第 7 条时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `运输合同`，子级 `货运代理合同`。定性理由必须同时交代：核心给付是处理运输事务；法律性质是委托而非承运、亦非纯信息中介。易混切开结果（承运本约 / 无船承运 / 网络货运 / 信息中介 / 多式联运 / 仓储）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未抄承运 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、备案、签单抬头与文本版本

主体表：签约名、履行名、付款名、发票名、签单抬头、授权签字人。资格表：国际货代备案痕迹、无船承运备案、是否同时持有网络货运牌照。版本表：正文、委托书、签单样本、费率、报关委托书、聊天确认；冲突并列。未核备案或签单授权：该签署/签单能力字段停止。

## 5. 委托事项、名义、费用与单证

核心给付是否仅处理运输事务；是否夹带运达承诺或自己调度运力；签单身份 as carrier / as agent；是否无船承运外观；代理费、代垫、包干是否分列；实际承运人是否披露；转委托权限；运输单证可否扣留。缺口标 `G#`。不输出承运保价、单位限额或道路许可主路径。

## 6. 身份转换、格式条款与强制规范

硬闸 1–2 的结论；签单外观与无船承运定性；包干差价是否逼出承运人责任。是否构成格式条款。“一切损失概不负责”不得写成已可执行。强制规范只按第 153 条和解释第 16 条区分。走私/骗税/夹藏只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。身份条款必须二选一，禁止含糊。

## 9. 谈判与签署提醒

谈判顺序：先红线（签单同时货损概不负责、无船承运却主张过错、网络货运改名、走私骗税、扣运输单证、倒签预借），再必须改（身份二选一、包干披露、转委托、时效协助、备案与签单样本），最后可优化。签署提醒：合同抬头与签单抬头一致；委托书、签单样本、费率、报关委托书入附件；每票勾选身份。不指导倒签、预借或补假承运人授权。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书、货损索赔策略或效力保证，也不是承运合同或网络货运平台审查。
