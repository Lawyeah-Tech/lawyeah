# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的港口、运费、班期；把已失效《合同法》及其解释或已废止《国内水路货物运输规则》写入结论；把内河或国内沿海写成适用海商法第四章；把客货混装一张免责放行；把海上、多式联运或道路文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查水路运输合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已废止《国内水路货物运输规则》、1987 年水路运输管理条例或 2008 年经营资质规定时，记噪声，不得写入 `L#`。MCP 效力字段与官方施行日冲突时，以施行日为准。

## 3. 类型与加载路径

父级 `运输合同`，子级 `水路运输合同`。定性理由、航区识别（内河／国内沿海／经海路）、客货分流、易混切开结果（水路乘客／水路货物／海上三原子／多式联运／道路）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、许可、船舶与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、收货人或购票人。许可表：国内水路运输经营许可证号、经营范围是否覆盖航区与客货种类、船舶识别号与航区等级。版本表：正文、附件、客票或运单样张、航线图、危货说明、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

航区与客货识别表、起讫港、是否过闸或进入感潮河段／海域、是否江海直达及分段、是否夹带其他运输方式、单据种类、票款或运费及预付／到付、停航标准与退改、许可与保险是否覆盖该航区。缺口标 `G#`，不补商业数字。批准、许可写成生效条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。一律适用海商法、失效货规、人身免责、货船载客、超载自愿不得写成可放行。强制规范只按第一百五十三条及合同编通则解释第十六条区分是否导致民事行为无效，不用失效口诀。无许可不当然无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把海上、多式联运或道路条款直接改成“国内水路类型”而不问是否已是他类。

## 9. 谈判与签署提醒

谈判顺序：先红线（航区误挂海商、客货混责、失效货规、货船载客、倒签或假许可、多式联运拒转），再必须改（分流表、许可与航区等级、单据、江海直达分段、停航标准），最后可优化。签署提醒：许可复印件、船舶证书、航线图、客票或运单样张、危货说明、船长或代理人授权。不指导倒签或补假许可／假航区。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书或效力保证，也不是水路乘客、水路货物、海上运输或多式联运的专项审查。对象确定后应交接对应子类型，不在本任务替代人身或货损整案。
