# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的运费、限额、船名；把已失效《合同法》、已失效《国内水路货物运输规则》写入结论；把中国港口间货运写成适用第四章；把内河或完整货／客本约当成已完成的本类型审查；写“一律适用海商法”；写“视为国际运输所以可以航海过失免责”；写“国内沿海货运适用普通三年时效”而不核验法释〔2001〕18 号；写“客票可引用货物免责”；把货／客专章精算写进本成果。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查海上运输合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《国内水路货物运输规则》（2000）、法发〔1992〕37 号时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `运输合同`，子级 `海上运输合同`。定性理由、易混切开结果（海上货物 / 海上旅客 / 水路 / 一般货运或客运 / 多式联运 / 租船 / 货代）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、航区识别与文本版本

主体表：承运人、实际承运人、托运人／旅客或包船人、收货人；签约名、履行名、签单名、授权签字人。识别表：对象、装港、卸港、是否中国大陆港口之间、是否经海路、单据类型。版本表：正文、航线清单、提单样张、运单、客票运输条件、船舶证书、聊天确认；冲突并列。

## 5. 适用法分轨、单据与责任条款

适用法是否按第四章／第五章／民法典货运节拆开；中国港口间货运是否偷运第四章免责或第五十六条单位限制；单据是否与航区匹配；客货是否混用免责；喜马拉雅是否扩张；海事赔偿责任限制是否与合同单位限制混写。缺口标 `G#`。不输出水路运输内河规则主路径，不输出货物本约无单放货精算或旅客限额精算。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。走私禁运、排除海商法强制责任、降低旅客法定限额不得写成可放行。强制规范只按第一百五十三条和已核验的第四十四条、第一百二十六条区分是否导致条款无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。对应事实存在时，识别表句、三轨适用法句、沿海货运删除第四章减责句、客票不得并入货物免责句不得省略。不得把水路运输、货物专章或旅客专章主路径直接写成“本类型已审完”。

## 9. 谈判与签署提醒

谈判顺序：先红线（内河冒充海上、完整货／客本约硬留本技能、中国港口间货运第四章减责、客票引用货物免责、走私禁运），再必须改（识别表、适用法分轨、单据匹配、客货分项、船舶替换与许可），最后可优化。签署提醒：承运承诺是否写清、签单授权、航线清单与正文识别条款一致、保险航区覆盖、海事管辖或仲裁单一连结点。不指导倒签或先签再补许可。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书或效力保证，也不是海上货物、海上旅客、水路运输、多式联运或租约安排。
