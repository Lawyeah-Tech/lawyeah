# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、人身必赔或必然可执行；编造未给出的票价、人数、期限；把已失效《合同法》运输章、《汽车旅客运输规则》、2012 年客规限额条写入结论；把无道路客运许可写成可以营运；把超载自愿或人身票价封顶写成可履行；把一般客运或网约车整案当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查道路乘客运输合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》运输章、《汽车旅客运输规则》、2012/2016 客规或 2004 年道路运输条例旧文本时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `运输合同`，子级 `道路乘客运输合同`。定性理由、易混切开结果（一般客运、网约车/巡游出租、道路货运、带驾租赁、道路运输总类、铁路/航空/水路乘客）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。知识稿中的出租与网约车不在本任务展开。

## 4. 主体、许可与文本版本

主体表：旅客或包车人、缔约承运人（客运企业）、挂靠车主或实际承运人、付款名、发票名、授权签字人。许可表：道路运输经营许可证号及经营范围、班线许可或包车客运标志牌、车辆道路运输证、驾驶员从业资格、承运人责任险痕迹。版本表：正文、客票或电子客票规则、包车任务书、线路批文、保险单、旅客名单、聊天确认；冲突并列。未核许可：该经营能力字段停止。

## 5. 形态、定额、票款、人身与迟延

班线/包车/旅游是否写准；线路、站点、班次或行程表是否锁定；核定载客人数；票款或包车价、儿童票、取消与退改；823/822 人身与救助；820 迟延改乘退票；甩客与移交他人运输；824 行李分轨。缺口标 `G#`。不输出网约车三证核验或货运留置主路径。

## 6. 格式条款与强制规范

是否构成格式条款。人身免责、超载自愿、管辖单方所在地是否有显著提示。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。无许可经营多为管理规范：合同可能仍成立，但不写“可以营运”，也不改成可履行无证发班。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。框架“网约车身份摇摆”一步：不在本任务出可履行网约车句，写转出口径。

## 9. 谈判与签署提醒

谈判顺序：先红线（类型错位、无许可或超范围、超载自愿、人身自负或票价封顶、移交无资质车辆、非营运车经营性载客），再必须改（许可文号与线路匹配、核定人数、820 改退、824 分轨、挂靠对外身份），最后可优化。签署提醒：客运企业公章；电子客票规则与数据保存期限；线路批文或包车任务书、保险单、旅客名单、车辆例检记录入附件。不指导倒签或补假许可。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只起草并自审，不评改对方来稿。待签评改转 `道路乘客运输合同·审查`。草稿必须落入本类型三闸。不是履约交底、争议文书或效力保证，也不是一般客运、网约车或货运专项审查。
