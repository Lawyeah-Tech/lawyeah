# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的运费、货量、滞期费率；把已失效《合同法》、《国内水路货物运输规则》、《水路货物运输合同实施细则》或《汽车货物运输规则》写入结论；保证货必无损或限额必然有效；把海上货运或道路货运当成已完成的本类型审查；写“运单仅供结算”；写“适用海商法及国际惯例”作为纯内河当然规则；写“已保险即承运人免责”；写“货损只赔运费”；把国内水路运单写成可背书转让的提单。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查水路货物运输合同（运输合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《国内水路货物运输规则》、《水路货物运输合同实施细则》、《汽车货物运输规则》或 2012 年条例／2014 年规定“已被修改”同号旧义时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `运输合同`，子级 `水路货物运输合同`。定性理由、航区识别、易混切开结果（海上货物／道路货物／水路乘客／水路总类／货代／一般货运／多式联运／仓储）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `水路运输合同·审查`、`水路乘客运输合同·审查`、`海上货物运输合同·审查`、`多式联运合同·审查`、`客运合同·审查`、`货运合同·审查` method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、许可、船舶与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、收货人。许可表：水路运输经营许可证范围、船舶营运证、实际承运船舶。版本表：正文、运单样张、货物清单、危货说明、保险单、运价表、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

货物特定化、甲板货书面同意、危货书面说明、运单效力与解释顺序（运单≠提单）、装港卸港是否过闸或经海路、运到期限起算、运费预付或到付、待闸滞期、交付凭证、831 检验异议、835／836／837／829。缺口标 `G#`，不补商业数字。批准、许可写成生效条件或双方义务期限，不写成已经完成。不输出海商法第四章免责作为本约当然规则，不输出道路运政主路径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。海商法免责搬家、失效货规、货损只赔运费、已保险即免责、运单仅供结算、国内运单按提单流通不得写成可放行。强制规范只按第一百五十三条和解释第十六条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把海上货运或道路货运直接改成“内河类型”而不问航区和核心给付。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为海上货运或道路货运、海商法免责搬家、失效货规、运单仅供结算、国内运单按提单流通、货损只赔运费、匿报危货），再必须改（运单解释顺序、甲板货书面、滞期起算、831 检验异议、835／836／837／829、收货人可识别），最后可优化。签署提醒：许可与船舶营运证附件、运单样张、船长或代理人签收授权、危货说明、保险单、解释顺序。不指导倒签或无单放货。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只起草并自审，不评改对方来稿。待签评改转配对 ·审查 原子。草稿必须落入本类型三闸。不是履约交底、争议文书或效力保证，也不是海上货物运输、道路货物运输、水路乘客运输或货代安排。
