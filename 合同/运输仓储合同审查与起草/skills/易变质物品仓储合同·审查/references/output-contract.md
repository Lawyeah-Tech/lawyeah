# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、货必不腐、对方接受或必然可执行；编造未给出的温度、保质期、损耗率、电费；把已失效《合同法》仓储章或《仓储保管合同实施细则》写入结论；把知识稿“紧急处置=第 906 条”或“食品冷链一律须食品经营许可”写成已核验规则。

## 1. 触发、单方立场与成果状态

立场（存货人或保管人择一）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《仓储保管合同实施细则》、担保法解释时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级仓储合同、子级易变质物品仓储合同、定性理由、与普通仓／危险品仓／租仓／保管／冷链运输的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型。危化主给付写停笔转出，不填可履行危化结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、冷库经营人名、存货人名、付款名、发票名、授权签字人、应急联络人、授权提货人。资质表：仓储经营范围；食品是自身经营许可还是非食品生产经营者贮存备案；疫苗／血液／药品监管痕迹。版本表：正文、温控要求清单、应急联络名单、仓单／入库单样张、聊天确认；冲突并列，不选对用户有利的一版。

## 5. 给付闭环

必须分列且回链文本：货种与保质期；书面温湿度区间与允许波动；入库中心温度与感官／包装验收；24 小时监测与数据调取；备用电源与启动时限；先进先出；自然损耗率 vs 非正常变质；变质通知与紧急处置；串味／混放禁令；仓位费与电费／温控费／预冷费；赔偿计价基准（入库申报单价或同期批发价，进口货才写报关单价）。缺口标 `G#`，不补 ℃ 或损耗率。许可、备案、消防写成义务和期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；停电免责、货损概不负责、全权销毁、最终解释权是否有显著提示。强制规范只区分管理性与是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。不得用已失效“效力性／管理性”口诀。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。四项硬闸（温控／保质期、变质风险分担、验收与通知、危险品切开）在原文沉默时仍须点名存货人必要项。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字和温度用 `【待填】`，不编造。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线（危化误入、无备用电源却把停电当不可抗力、超期／已霉变入库、概不负责），再必须改（温控量化、入库测温、通知时限、监测记录、FIFO、串味），最后可优化。签署提醒：授权、用印、日期、温控清单与应急联络名单作为附件、条件成就凭证。不指导倒签或补假许可／假温控曲线。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只审查，不交付整份起草终稿。出己方稿转配对 ·起草 原子。不是履约交底、争议文书或效力保证。
