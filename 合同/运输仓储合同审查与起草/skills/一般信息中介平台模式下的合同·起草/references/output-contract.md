# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证合同有效、必然无效、中介身份不会被改定性或对方接受；编造未给出的费率、清分时限、核验周期、保存期限；把已失效《合同法》及其解释、《汽车货物运输规则》、《公路运输管理暂行条例》写入结论；把标题“信息平台”写成已排除承运；把代收运费写成与身份无关；把概括免责写成有效；把网约车、网络货运或货代留在本技能按中介改完。

## 1. 触发、单方立场与成果状态

立场（平台运营者、托运人端用户、承运人端用户）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明是否只撮合信息不承运，以及资金、发票、运单、调度四外观是否已切净。写明未按网货实际承运人或货代改完。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《汽车货物运输规则》、《公路运输管理暂行条例》、合同法解释（二）第十四条时记噪声，不得写入 `L#`。中介报酬、如实报告、运输合同定义、第 506 条、格式条款、电商保存与核验、网约车承运人责任切开无 `verified-result` 时，对应法律结论字段停止。网络货运部门规章未核验原文时，不得写暂行办法条号。

## 3. 类型与加载路径

父级 `运输合同`，子级 `一般信息中介平台模式下的合同`。定性理由必须同时满足：标的是信息与撮合；运输合同拟在托运人与实际承运人之间成立；平台不以自己名义承运。易混切开：网络货运、货运代理、客运／网约车／定制客运、一般货运、道路货物、道路运输总类、技术转让中介、职业中介、房屋中介、平台用工、长期运输／派遣、动产租赁。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`（本场景已锁定）。写明只读这一对、未通读其他类型、未打开 `网络货运平台模式下的运输合同·审查`、`货运代理合同·审查`、`技术转让中介专利权或技术秘密让与媒介→`、`道路运输合同·审查`、`客运合同·审查` 或 `货运合同·审查` 的 method。违法撮合、无许可实质承运写停笔告知，不填可履行结构。

## 4. 主体、授权、资质与文本版本

主体表：平台运营者、托运人端、承运人端、支付机构、保险人、授权签字人。自然人写姓名与证件号是否与文本一致；法人写名称与统一社会信用代码。平台是否被写成承运人或见证人兼改派人，分列。

版本表：用户协议正文、收费标准、核验规则、运输合同模板、宣传页或应用商店简介、支付协议、聊天确认。冲突并列，不选对用户有利的一版。口头“我们只做信息匹配”不得写成已排除承运外观。

## 5. 撮合给付闭环

分列并回链文本位置：

- 服务内容：发布、检索、沟通、模板、评价；是否写入不以自己名义订运输合同、不签发运单、不收运费、不开运输发票、不承担承运人货损。
- 运输合同关系：签约方是否仅为托运人与实际承运人；模板是否预留双方签章；平台有无改派、定价、签收确认权。
- 报酬：中介费或会员费计取时点是否绑促成；未促成是否仍收费；发票种类是否为信息服务。
- 资金流：点对点还是代收；清分时限；是否占用；是否开运输票。
- 核验：证件类型、复审周期、虚假信息下架和通知。
- 责任：故意、重大过失是否保留；是否存在“任何情况下均不承担责任”。
- 数据：沟通和成交记录保存期限是否短于三年底线；争议时是否协助提供。
- 管辖：信息服务纠纷与运输纠纷是否分开。
- 宣传：广告是否写平台承运或丢货必赔。
- 三份文件：用户协议、运输合同模板、支付协议是否隔离。

缺口标 `G#`，不补费率、许可或已核验事实。清分、核验、保存写成条件或双方义务期限，不写成已经完成。

## 6. 格式条款、强制规范与本类型效力红旗

平台预先拟定且未协商的免责、限额、管辖、单方改规则：按格式条款审查提示说明。仅勾选弹窗不得写成已尽提示。

强制规范与效力红旗只在核验后落法律结论：明知非法营运或违禁品仍撮合；无许可却以自己名义揽货收款；故意或重大过失免责；消费者端把平台法定责任一概转给承运人。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

不得把“中介声明即排除承运责任”或“无证撮合合同必然无效”写成已核验结论。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型至少检查：承运外观未切净；与 `网络货运平台模式下的运输合同·审查`、`货运代理合同·审查` 或客运未切开；运输合同模板把平台写成当事人或赋予改派权；按运费差价结算却主张技术服务费；未促成仍收报酬；概括免责；零审核；代收运费却主张资金无关；宣传与条款打架；用户纠纷一律不协助；信息服务与运输纠纷未分管辖。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字、期限用 `【待填】`，不编造。禁止只给原则、不给句子。框架与硬闸冲突时按硬闸出句。

建议句必须覆盖本类型硬闸：只撮合信息不承运；切开网络货运与货代；运输合同仅在承托双方之间；报酬绑促成且开信息服务发票；保留故意、重大过失责任；宣传与条款统一。

## 9. 谈判与签署提醒

谈判顺序：先红线（承运外观拒改、货代事务拒改、无许可揽货收款、明知违法仍撮合、概括免责、宣传承运条款中介），再必须改（四外观切净、模板去改派、核验标准、促成计酬、数据保存、分管辖），最后可优化。

签署提醒：点击同意须能定位规则版本；收费标准、核验规则、运输合同模板作附件；模板中平台不是当事人；日期真实。不指导倒签办证日或补假核验。

平台立场可建议先统一身份再上线，但必须同时写明：中介声明不能对抗承运外观。用户立场必须提示：平台收运费、开运输票或承诺运达的，即使条款写中介，仍可能被按承运人或依法应取得网络货运许可的经营者追责。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本原子只起草并自审，不评改对方来稿。待签评改转配对 ·审查 原子。草稿必须落入本类型三闸。不是履约交底、货损诉讼文书、有效性保证，也不是 `网络货运平台模式下的运输合同·审查`、`货运代理合同·审查`、`道路乘客运输合同·审查` 或 `技术转让中介专利权或技术秘密让与媒介→` 的专项成果。切到承运、货代或客运后如需继续审，写明交接字段，不代做。
