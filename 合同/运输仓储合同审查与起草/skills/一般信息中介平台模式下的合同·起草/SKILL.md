# 一般信息中介平台模式下的合同·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、审查反例和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、合同法解释（二）第十四条“效力性强制性规定”口诀、《汽车货物运输规则》、《公路运输管理暂行条例》、《道路货物运单使用和管理办法》当作现行规则。不得把网约车平台承运人责任、货运代理签单路径或网络货运经营者义务写成中介免责依据。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **运输合同 / 一般信息中介平台模式下的合同**：平台为托运人与实际承运人提供货源／运力信息匹配和交易撮合，促成双方自行订立运输合同。民事性质是中介或信息服务，不是运输合同。输出可编辑草稿和未决项，并用本类型硬闸自审后给出风险表和修改句。待签评改转 `一般信息中介平台模式下的合同·审查`。

本技能类型锁死。不扫描其他类型。场景分层为 **P1**。中文名必须是「一般信息中介平台模式下的合同·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类审查、从零起草、履约交底、争议文书、合同有效性或必然无效保证、网络货运整案、货运代理整案、客运／网约车整案、道路货物或道路运输总类承运整案、技术转让中介整案、职业或房屋中介整案、把中介改写成可履行承运或把无许可网络货运改成可履行。

## 本类型硬闸

未完成下列切开和落句，不得宣称审查完成。每一闸必须给出修改句或明确转出口径，禁止只打红黄绿。禁止打开或复制 `网络货运平台模式下的运输合同·审查`、`货运代理合同·审查`、`技术转让中介专利权或技术秘密让与媒介→`、`道路运输合同·审查`、`客运合同·审查`、`货运合同·审查` 的 method。

1. **只撮合信息不承运**。核心给付是促成托运人与实际承运人自行订约。必须逐项排除：不以自己名义签订运输合同、不签发运单、不向托运人收取运费、不开具运费发票、不作为承运人承担货损。出现任一项承运外观且用户拒绝改回撮合：负触发，不在本技能改成“名义中介、实质承运”。
2. **不得按网货实际承运人改完**。网络货运必须以承运人身份与托运人订运输合同、收运费、开运输发票、对货损承担承运人责任。标题写“信息平台”不等于中介。资金流、发票、运单、调度四者有一项做成承运而用户要按中介放行：负触发 `网络货运平台模式下的运输合同·审查`，不灌两套知识，不打开其 method。
3. **不得按货代改完**。代为订舱、报关、以自己名义签运单或处理具体运输事务：负触发 `货运代理合同·审查`，不打开其 method，不把本约改写成对外订运输合同。
4. **必须出修改句**。禁止只打红黄绿。每个风险回链文本位置。

附加必落句（有事实则单列，无事实在缺口节说明）：

- **三份文件隔离**：平台用户协议（中介）+ 托运人与承运人运输合同（货运）+ 如有支付协议。运输合同仅存在于托运人与实际承运人之间；模板须预留双方签章，平台不是签约方，不得有改派、统一定价、签收确认权。
- **报酬与发票**：中介费或会员费的计取时点绑促成；发票种类为信息服务。按运费比例抽成或按运费差价结算：评估是否构成变相承运。未促成不得请求报酬，必要费用须另约。
- **核验与故意、重大过失**：证件类型、复审周期、虚假信息下架和通知。删除“任何情况下平台均不承担责任”。故意或重大过失（虚假认证、明知无资质仍置顶、明知违法仍撮合）不得预先免除。
- **资金流**：运费点对点最优。必须代收的，写成定向清分、不占用、不开运输票，并评估被改认定为承运人的风险。禁止“代收运费却主张资金与平台无关”。
- **宣传与条款统一**：广告写“平台承运、丢货必赔”而条款写中介免责：必须改到同一身份，不能统一则换许可、换合同，转 `网络货运平台模式下的运输合同·审查`。
- **合规升级开关**：出现统一定价、承运承诺、运输开票时，停止中介表述，不得在本技能里改成可履行承运。
- **争议管辖分列**：平台与用户的信息服务纠纷，与货主和司机之间的运输纠纷分开管辖。至少应提供沟通和成交记录，不得写“用户之间纠纷一律不协助”。

禁止套用买卖验收、定金百分之二十、建设工程挂靠、职业中介许可、房屋中介佣金或技术转让中介节点。

## 工作边界

正触发：已有可读待签文本要评改（审查模式），或本类型条件已谈妥要出己方稿（起草模式）；尚未签署，尚未成争；核心给付是货源／运力信息发布、检索、沟通、模板撮合；平台不以自己名义承运、不签发运单、原则上不向托运人收取运费、不开具运费发票。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 深度调度、统一定价、以自己名义承运收款、开运输发票、签发运单、承诺运达或包赔货损 → `网络货运平台模式下的运输合同·审查`；禁止打开或复制其 method；
- 代为订舱、报关、以自己名义签运单或处理具体运输事务 → `货运代理合同·审查`；禁止打开或复制其 method；
- 班线、包车、旅游、出租、网约载客、定制客运网络平台，或正文主给付是运送旅客 → `道路乘客运输合同·审查`；未锁定公路机动车的客运 → `客运合同·审查`；禁止打开 `客运合同·审查` method；禁止用本技能审客运或网约车承运主路径；
- 公路机动运输且客货未拆或已排他道路货物／道路运输总类，平台自己承运 → `道路运输合同·审查`／`道路货物运输合同·审查`／`货运合同·审查`；禁止打开 `道路运输合同·审查`、`货运合同·审查` method；
- 技术转让中介、专利权或技术秘密让与媒介 → `技术转让中介专利权或技术秘密让与媒介→`；禁止打开其 method；
- 职业介绍、人力资源服务许可、岗位撮合 → `职业介绍人力资源服务许可岗位撮合→`；房屋买卖或租赁中介 → `房屋买卖或租赁中介→`；
- 平台与骑手／司机的用工、众包、算法管理文本 → `或`；
- 长期驻场司机、用工外观主导 → `类派遣长期运输·审查`；
- 出租人提供车辆甚至司机，承租人决定线路并承担运输对象风险 → `承租人决定线路并自负运输对象风险的带驾租赁→`；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问撮合记录、清分日、下架节点 → 本套导航的履约步骤；
- 已成争（货损告平台、运费挪用、催告解除、立案仲裁）→ 合同争议或对应专项领域。

明知非法营运、运输违禁品仍撮合，或要求把无许可网络货运、假核验、倒签办证日改成可履行：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（平台运营者、托运人端用户、承运人端用户，择一）；相对方；全文及收费标准、核验规则、运输合同模板、宣传页版本；资金是否代收、发票种类、是否派单改价；不可接受事项；法域与签署时限。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

## 使用 Lawyeah MCP

宿主可调用时：

- `search_law`（法律结论 required）：核验中介合同定义与报酬、如实报告、运输合同定义、格式条款与故意重大过失免责、电商平台核验与保存、网约车平台承运人责任（仅作客运切开）。
- `search_practiced`（optional）：补“自称信息平台、按承运外观被改定性”的审查反例。返回“标题写中介即不是承运人”“任何情况下平台免责有效”“按汽货规赔”或无船承运人／提单识别时记噪声。
- `search_template`（optional）：只借栏目结构。范本把平台写成承运人、见证人兼改派人或按运费差价结算的，不得当规则。运单范本不得当本约。

不虚构案件系统。`search_law` 返回已失效《合同法》及其解释、《汽车货物运输规则》、《公路运输管理暂行条例》、合同法解释（二）第十四条时记为噪声，不得写入 `L#`。网络货运部门规章全文本次未稳定命中的，不得凭记忆写条号。


## 起草模式

本原子只承担本类型起草。待签评改转 `一般信息中介平台模式下的合同·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务起草并自审。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。本约只撮合货源／运力信息，不承运，不代办订舱报关，不改成可履行网络货运。

1. 先按框架六步落稿：首部锁中介身份与三份文件隔离；交易条款写促成计酬、信息服务发票、资金点对点或定向清分；配套写核验、故意重大过失不得预免；尾部写信息服务纠纷与运输纠纷分管辖；正说反说后按下述必写与禁忌落句。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿。自审至少核对：不以自己名义订运输合同、不签发运单、不收运费、不开运输发票、不承担承运人货损是否写全；宣传与条款是否同一身份。输出风险表和修改句。不得只交白稿。
3. 网络货运承运、货代事务、客运／网约车、道路承运出稿、已签履约、已成争：仍负触发。

**起草必写**：核心给付是促成托运人与实际承运人自行订约。必须逐项排除：不以自己名义签订运输合同、不签发运单、不向托运人收取运费、不开具运费发票、不作为承运人承担货损。三份文件隔离：平台用户协议（中介）＋托运人与承运人运输合同（货运）＋如有支付协议；运输合同仅存在于托运人与实际承运人之间，模板预留双方签章，平台不是签约方，不得有改派、统一定价、签收确认权。中介费或会员费的计取时点绑促成，发票种类为信息服务；未促成不得请求报酬，必要费用须另约。证件类型、复审周期、虚假信息下架和通知。运费点对点最优；必须代收的，写成定向清分、不占用、不开运输票，并评估被改认定为承运人的风险。平台与用户的信息服务纠纷，与货主和司机之间的运输纠纷分开管辖；至少应提供沟通和成交记录。

**附件必附**：平台用户协议；托运人与实际承运人运输合同模板（平台不是签约方）；支付协议（如有代收）。

**禁止出现**：任何情况下平台均不承担责任；故意或重大过失（虚假认证、明知无资质仍置顶、明知违法仍撮合）预先免除；代收运费却主张资金与平台无关；广告写“平台承运、丢货必赔”而条款写中介免责；统一定价、承运承诺、运输开票仍写中介；用户之间纠纷一律不协助。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口，不代替节点。

4. 四外观：资金、发票、运单、调度

6. 核验、如实报告与故意重大过失
7. 格式条款、宣传冲突、数据与管辖
8. 违法撮合与合规升级开关
9. 按框架六步出修改句

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无可读文本仍要实体意见；用户坚持伪造许可或倒签办证日、把无许可网络货运改成可履行中介、把明知非法营运或违禁品撮合改成可履行、保证中介身份不会被改定性或保证合同有效、要求按失效汽货规出货损结论、要求按网货实际承运人或货代改完。
- `字段停止`：法域未核验；资金流、发票种类无法判断且用户拒绝对话；承运外观与中介声明冲突且用户拒绝选择一条路径。
- `目标停止`：主目标已变为待签评改、履约交底、货损诉讼文书，或用户要把本约改成网络货运／货代／客运／技术转让中介却拒绝转出。

货主生存级货损被“平台一律免责”打发且用户拒绝升级：停止“可以签署”建议。
