# 计算机软件著作权转让合同·起草

## 任务目标

在单一立场下，只按已谈妥条件起草 **计算机软件著作权转让合同** 己方稿，出稿后用本类型硬闸自审。交付草稿、未决项、自审风险表和自审后修改句。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。中文显示名为「计算机软件著作权转让合同·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证登记一定办成或保证无第三方主张。

## 本类型硬闸

1. **技术合同节参照 ≠ 知产父级路径**：正像是父级落在技术类合同、核心给付为已固定软件著作财产权让与。规范主轴是民法典第 876 条参照适用技术转让／许可节；著作权法、计算机软件保护条例另有规定的从其规定。封面或用户指定「知识产权相关合同 / 软件著作权转让合同」→ `软件著作权转让合同·审查`。禁止打开或复制 `软件著作权转让合同·审查` method。
2. **转让 ≠ 许可**：让与人停用该版本或仅保留书面自用，不得再向第三人许可或再转让。仅授权使用、期限届满收回、让与人继续对外复制发行或再许可 → `计算机软件著作权许可合同·审查`。禁止打开 `计算机软件著作权许可合同·审查` method。
3. **登记对抗 ≠ 专利登记生效**：软件著作权自开发完成产生。登记证明是登记事项的初步证明。合同自依法成立时生效。禁止写成“未向中国版权保护中心登记则合同无效／未生效”。不得套用专利法第十条“转让自登记之日起生效”。
4. **权随码走**：主给付是约定财产权让与加上与版本一致的可编译源码、文档、构建脚本和密钥。只交登记证或安装包视为黑盒。验收只写可完整交付、可编译、与版本一致，不得写成功能开发验收。
5. **人身权不转**：发表权、署名权、修改权不得写成可买卖标的。`基本面.md` 把发表权与复制权并列成可转财产权时，以 method 纠正为准。
6. **与开发切开**：软件须已完成并已固定。对价绑“谁来写代码、验收什么功能” → `软件委托开发合同·审查`。
7. **850、开源与进出口**：禁研、禁他源、不对等无偿回授、禁止质疑必须改。笼统“实质性相似产品开发禁令”须收窄到让与人不得再利用本合同交付源码／核心逻辑。隐瞒强互惠开源或未批向境外交付源码：只告知，不改成可履行。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签计算机软件著作权转让正文，父级为技术类合同，尚未签署，尚未成争，核心给付是现有特定软件著作财产权的让与，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 封面成册或用户指定走知产父级软件著作权转让 → `软件著作权转让合同·审查`；
- 仅授权使用、让与人可再许可或期限届满收回 → `计算机软件著作权许可合同·审查`；知产父级分发／自用许可 → `软件许可合同（分发许可模式）·审查`／`软件许可合同（自用许可模式）·审查`；
- 订立时尚待开发、对价绑功能验收或里程碑 → `软件委托开发合同·审查`；
- 一般文字、美术、视听作品财产权让与、无软件版本与源程序 → `著作权转让合同·审查`；
- 现有未公开技术秘密买断、无软件著作财产权让与 → `技术秘密转让合同·审查`；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁或软著权属／侵权已立案 → `或知产争议专项。` 或知产／争议专项。

以转让为名转移国家秘密、未批限制进出口技术，或把明知无权处分／隐瞒 GPL 传染改成可履行买断：只出告知，不改写成可履行路径。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及附件／版本清单／源码交接单版本；父级是否技术类；标的是否已完成并已固定；是买断还是许可；源码是否当场编译校验；登记权利人是否与签约名一致；在先许可、出质、开源、职务或合作开发；进出口或数据出境；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。意见中不得复述用户材料里的源码、密钥或用户数据，只引用版本号、清单编号或哈希。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的价款、期限用 `【待填】`，不编造。

## 起草模式

本原子只承担本类型起草。待签评改转 `计算机软件著作权转让合同·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务，不转 `计算机软件著作权转让合同·起草`。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。下表把本类型硬闸改成正文必写、附件必附或禁止出现。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

### 起草必写

- 主给付是已固定软件著作财产权让与；走技术类合同、民法典第 876 条参照技术转让／许可节。
- 让与人停用该版本或仅保留书面自用，不得再向第三人许可或再转让。
- 合同自依法成立时生效；登记证明只作登记事项的初步证明。
- 财产权让与须配与版本一致的可编译源码、文档、构建脚本和密钥。
- 验收只写可完整交付、可编译、与版本一致。
- 人身权（发表权、署名权、修改权）不转。

### 附件必附

- 版本清单与源码／文档／构建脚本／密钥交接单。
- 在先许可、出质或开源披露清单（有事实则附）。

### 禁止出现

- 打开或复制知产父级软件著作权转让 method。
- 仅授权使用、期限届满收回、让与人继续对外复制发行或再许可。
- “未向中国版权保护中心登记则合同无效／未生效”。
- 套用专利法第十条“转让自登记之日起生效”。
- 只交登记证或安装包的黑盒；功能开发验收或对价绑“谁来写代码”。
- 发表权、署名权、修改权写成可买卖标的。
- 禁研、禁他源、不对等无偿回授、禁止质疑。
- 笼统“实质性相似产品开发禁令”。
- 隐瞒强互惠开源或未批向境外交付源码写成可履行。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → 本任务起草并自审；已签履约 → 本套导航履约步骤；已成争 → 合同争议或知产。未签且目标是评改已有技术类软著转让文本，才进入本任务。

### 1. 类型锁死

标题、父级目录、核心给付与对价方式一致才继续。知产父级成册、许可、开发、一般作品、技术秘密买断负触发。

### 2. 主体、权属与在先负担

签约名、履行名、付款名、发票名分列。合法拥有、职务／合作／委托开发、已有许可或出质必须闭合或字段停止。

### 3. 财产权范围与人身权

列明复制、发行、出租、信息网络传播、翻译等财产权。人身权不转。未列明权利不得行使。

### 4. 源码交付与编译验证

清单、哈希、编译环境、与版本一致。禁止黑盒。签收不等于验收。

### 5. 登记对抗与生效切开

成立生效。版权中心登记是对抗和举证枢纽，不是生效要件。禁止专利登记生效话术。

### 6. 对价、850、开源、改进、进出口

节点与源码校验／登记证明挂钩。禁研／回授必须改。开源清单。向境外交付源码未批则履行字段停止。

### 7. 格式条款与强制规范

无核验引文则法律结论字段停止。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把许可改成买断外壳、把未完成开发改成转让、把明知无权处分或未批进出口或隐瞒强互惠开源改成可履行、坚持只转证书不交源码、坚持打开 `软件著作权转让合同·审查` method。
- `字段停止`：法域、动态规则、进出口目录、权属或在先许可／开源未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
