# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、版本号、登记号；把已失效《合同法》《技术合同法》及其实施条例、1991 年软件保护条例写入结论；保证登记一定办成或保证无第三方主张；把许可、开发、一般作品或知产父级文本当成已完成的本类型审查；写“未向版权中心登记则本合同未生效”；写“先交源码后补进出口许可证”；在意见中复述源码、密钥或用户数据；打开 `软件著作权转让合同·审查` 或 `计算机软件著作权许可合同·审查` 的 method。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查计算机软件著作权转让合同（技术类合同）」。写明父级是技术类合同，不是知识产权相关合同。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、1991 年软件保护条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `计算机软件著作权转让合同`。定性理由、易混切开结果（知产父级转让 / 技术类许可 / 开发 / 一般作品 / 技术秘密）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `软件著作权转让合同·审查` method。知识库与硬闸冲突时，以 method 硬闸为准。规范主轴写清：第 876 条参照技术转让节；著作权法／软件条例另有规定的从其规定。

## 4. 主体、权属、在先负担与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。权属表：登记证权利人、开发者署名、职务／合作／委托开发、共有、已向第三人许可或出质。版本表：正文、版本／模块清单、源码交接单、登记证、开源清单、聊天确认；冲突并列。意见只引用版本号、清单编号或哈希，不摘录源码。

## 5. 财产权、源码交付、登记与验收

转让的财产权种类是否列明；人身权是否被误写成可转；源码、文档、构建脚本是否可编译校验；买断后让与人是否停用及不得再处分该版本；价款与节点；编译验证与签收是否分列；登记是对抗还是被写成生效。缺口标 `G#`。不输出专利登记生效口径，不输出许可续期口径，不输出功能开发验收口径。

## 6. 格式条款、强制规范、850、开源与进出口

是否构成格式条款；提示说明痕迹。850 过宽禁研／不对等回授不得写成可放行。开源／第三方组件未披露标必须改或红线。向外国人转让未批：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。原文摘录不得含源码正文、密钥或用户数据。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、登记与权利担保、配套、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把独占／排他／普通许可方式直接写成“转让类型”而不问是否买断。不得把发表权写成可转财产权。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为许可或开发、知产父级误入、只转证书不交源码、登记生效误用、人身权当财产权卖、明知无权处分、未批进出口、隐瞒强互惠开源），再必须改（版本锁定、源码清单与编译验证、权属与在先负担、850／回授收窄、开源清单、登记配合），最后可优化。签署提醒：授权、用印、日期、版本清单与源码交接单、编译验证记录、首笔价款到账后再交完整源码。不指导倒签或先交源码后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是知产父级转让、许可、开发或技术秘密买断安排。
