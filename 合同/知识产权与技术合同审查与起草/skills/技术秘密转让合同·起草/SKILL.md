# 技术秘密转让合同·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、已失效《技术合同法》及其实施条例当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **技术秘密转让合同** 己方稿，出稿后用本类型硬闸自审。交付草稿、未决项、自审风险表和自审后修改句。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「技术秘密转让合同·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证秘密永远不被反向工程或永远具有竞争优势。

## 本类型硬闸

1. **转让 ≠ 许可 ≠ 专利转让**：正像是把**已经存在、尚未公开、以保密维持**的技术秘密相关权利**让与**对方。让与人停用或仅保留约定自用，不得再向第三人许可或再转让（除非合同明示且与买断一致）。仅授权使用、期限届满收回、让与人可继续自用并再许可他人 → `技术秘密使用许可合同·审查`。出现专利号/申请号、公开换保护、登记之日起权利变动 → `专利权转让合同·审查` / `专利申请权转让合同·审查`。标题笼统“技术转让”、标的未锁定秘密载体 → `技术转让合同·审查`。尚待研究开发 → `技术开发合同·审查`。只协助操作、不交核心配方/源码 → `知产技术服务·审查`。
2. **秘密性维持（生命线）**：保护随保密状态存续。须约定双方对未公开部分承担保密义务，期限写“直至该信息进入公知领域止”或与之等价的持续保密，不得写成固定两年到期自动解密。泄密使标的价值归零，须有可执行违约后果，但不得写成“惩罚性且不得调整”的必得金额。劳动合同法上的竞业限制期限上限只约束竞业，不缩短本合同保密期。买断后禁止让与人再就同一秘密申请专利，除非申请权书面归受让人。
3. **披露范围**：主文不得详述配方、关键参数或完整源码。用密级目录、载体描述、哈希或编号界定范围。分阶段披露：先框架与接收规则，对价节点到达后再交核心。接触人员、复制份数、存储位置必须可核验。禁止黑盒（只交结果、不交足以独立实施的参数）。禁止在正文、聊天或未加密附件中无控制地全文粘贴秘密。
4. **权属、在先许可与明知侵权**：让与人须保证合法拥有、完整无误有效、能够达到约定目标，并披露已向第三人作出的许可或共有。职务成果、离职人员带走的技术未闭合则权属字段停止。用户或材料显示明知盗取他人商业秘密仍要受让：只出告知，不改成可履行买断。
5. **可复现验收与指导**：验收以受让人凭交付资料和约定指导能否生产合格产品或实现指标为准。须有技术还原性测试和验证期。让与人负有交付资料和现场指导义务。第三方合法反向工程导致公开的，约定后续价款减免或清理，不得写成让与人当然免责或当然继续全额收款。
6. **非法垄断与后续改进**：限制继续研发、限制他源技术、不对等无偿回授、禁止质疑：必须改或删除。后续改进无约定则改进方享有，他方无权分享；要对等互惠才写回授。
7. **成立生效 ≠ 专利登记**：本合同不以向专利行政部门登记为权利变动要件。科技部门技术合同认定登记只服务税收优惠，不得写成未登记则转让未生效。跨境限制进出口技术未批：履行字段停止，禁止“先交核心后补许可证”。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签技术秘密转让正文，尚未签署，尚未成争，核心给付是现有特定技术秘密的权利让与，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 仅授权使用、让与人可再许可或期限届满收回 → `技术秘密使用许可合同·审查`；
- 已授权专利的权利让与、须向国务院专利行政部门登记才发生权利变动 → `专利权转让合同·审查`；
- 专利申请权让与 → `专利申请权转让合同·审查`；
- 笼统技术转让、标的同时含专利/申请权且未拆成秘密专章 → `技术转让合同·审查`；
- 订立时尚不存在、须研究开发 → `技术开发合同·审查`；委托开发 / 合作开发细分主文件 → `委托开发合同·审查` / `合作开发合同·审查`；
- 已有技术的概括许可主文件 → `技术许可合同·审查`；专利实施许可 → `专利实施许可合同·审查`；
- 以技术知识解决特定问题、不交核心秘密 → `知产技术服务·审查`；可行性或 FTO 意见 → `知产技术咨询·审查`；
- 计算机软件著作权让与为主给付 → `计算机软件著作权转让合同·审查` 或 `软件著作权转让合同·审查`；源码秘密点可在本技能专章评改，不代审著作权本约；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁或商业秘密侵权/权属已立案 → `或知产争议专项。` 或知产/争议专项。

以转让为名买卖国家秘密、未批限制进出口技术，或把明知侵权的受让改成可履行买断：只出告知，不改写成可履行路径。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及附件/密级目录/交接清单版本；标的是否已有且未公开；是买断还是许可；披露是否分阶段；保密期限与接触名单；在先许可或职务成果；验收与指导；进出口或国家秘密；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。意见中不得复述用户材料里的具体配方、参数或源码，只引用载体编号。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的价款、指标、期限用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验 850 与解释第 10、12 条，862–864、868–875，解释第 1、22、25、28、34 条，专利法第十条（负向切开），反不正当竞争法商业秘密定义，商业秘密司法解释第 14 条，进出口条例；`search_practiced` 只补审查反例；`search_template` 只借栏目结构。不虚构案件系统。

## 起草模式

本原子只承担本类型起草。待签评改转 `技术秘密转让合同·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务，不转 `技术秘密转让合同·起草`。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。下表把本类型硬闸改成正文必写、附件必附或禁止出现。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

### 起草必写

- 主给付是已经存在、尚未公开、以保密维持的技术秘密权利让与。
- 让与人停用或仅保留约定自用，不得再向第三人许可或再转让（除非合同明示且与买断一致）。
- 双方对未公开部分持续保密，期限写成“直至该信息进入公知领域止”或等价持续保密。
- 泄密须有可执行违约后果；买断后禁止让与人再就同一秘密申请专利，除非申请权书面归受让人。
- 用密级目录、载体描述、哈希或编号界定范围；分阶段披露；接触人员、复制份数、存储位置可核验。
- 让与人保证合法拥有、完整无误有效、能够达到约定目标，并披露已有许可或共有。
- 验收以受让人凭交付资料和约定指导能否复现指标为准；须有还原性测试、验证期和现场指导。
- 第三方合法反向工程导致公开的，约定后续价款减免或清理。

### 附件必附

- 密级目录与载体／哈希／编号清单。
- 接触人员名单与复制份数、存储位置安排。

### 禁止出现

- 仅授权使用、期限届满收回、让与人可继续自用并再许可。
- 专利号／申请号、公开换保护、登记之日起权利变动。
- 主文详述配方、关键参数或完整源码；未加密全文粘贴秘密。
- 固定两年到期自动解密；“惩罚性且不得调整”的必得金额。
- 黑盒交付（只交结果、不交足以独立实施的参数）。
- 明知盗取他人商业秘密仍写可履行买断。
- 限制继续研发、限制他源技术、不对等无偿回授、禁止质疑。
- 把专利登记或科技部门认定登记写成权利变动要件。
- “先交核心后补许可证”。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → 本任务起草并自审；已签履约 → 本套导航履约步骤；已成争 → 合同争议或知产。未签且目标是评改已有技术秘密转让文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。许可、专利转让、申请权转让、开发、服务、软件著作权本约负触发。

### 2. 主体、权属与在先许可

签约名、履行名、付款名、发票名分列。合法拥有、职务成果、已有许可必须闭合或字段停止。

### 3. 秘密性维持与披露范围

保密期限、接触名单、分阶段披露、载体目录。禁止固定短期限自动解密，禁止主文泄密，禁止黑盒。

### 4. 买断效力与登记切开

让与人停用/再处分；不得按专利法第十条写登记生效。认定登记只服务税。

### 5. 验收、指导、公知与反向工程

还原性测试、验证期、指导人天数。第三方合法反向与受让人违约反向分列。

### 6. 对价、850、后续改进

节点与交付/试产挂钩。禁研/回授必须改。改进成果默认归改进方。

### 7. 格式条款与强制规范

无核验引文则法律结论字段停止。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把许可改成买断外壳、把明知侵权受让或未批进出口/国家秘密改成可履行、坚持在主文全文公开秘密。
- `字段停止`：法域、动态规则、进出口目录、国家秘密审批、权属或在先许可未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
