# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、流片量、保护期；把已失效《合同法》及其解释写入结论；保证备案或保护期一定办成／存续；把转让、专利实施许可、技术秘密许可文本当成已完成的本类型审查；写“未备案则本合同未生效”；写“专有权已随许可移转”；把专利年费或《专利实施许可合同备案办法》写成布图许可生效规则。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查集成电路布图设计专有权许可合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、把《专利实施许可合同备案办法》当作本类型生效规则时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `集成电路布图设计专有权许可合同`。定性理由、易混切开结果（转让 / 专利实施许可 / 概括技术许可 / 技术秘密许可 / 开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。未打开 `集成电路布图设计专有权转让合同·审查` 或 `专利实施许可合同·审查` 的 method。

## 4. 主体、证书、共有人与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。权源表：登记证书权利人／转授权链条；共有人是否同意独占或排他许可；在先许可。版本表：正文、证书、交付清单、NDA、首次商业利用承诺、聊天确认；冲突并列。

## 5. 许可范围、保护期、给付与书面／备案

许可方式是否落成独占／排他／普通；复制与商业利用（含进口）是否写清；Foundry／型号／工艺节点；许可期限是否超过剩余保护期；首次商业利用日是否书面承诺；书面是否具备；备案／转让登记是否被误写成生效要件；价款是否与 GDSII 交付／DRC／LVS／流片节点挂钩。缺口标 `G#`。不输出转让登记生效口径，不输出专利年费维持口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。无偿独占回授、禁止质疑有效性、未批进出口先交 GDSII、无证书硬授权不得写成可放行。强制规范只按第一百五十三条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把转让登记或专利备案直接写成“许可生效条件”。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为转让或专利许可、无证书、未批进出口仍交 GDSII、850 回授、未备案无效），再必须改（保护期、许可方式、进口权、交付清单、备案配合、首次商用承诺、流片失败分责），最后可优化。签署提醒：证书与签约名一致、共有人同意书、授权书须含“许可布图设计专有权”、交付清单、NDA、首次商业利用书面承诺。不指导倒签或把未备案写成合同无效。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是转让、专利实施许可或技术秘密许可安排。
