# 技术中介合同·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、已失效《技术合同法》及其实施条例当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **技术类合同 / 技术中介合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P1**。中文显示名为「技术中介合同·审查」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证第三人投产或固定收益。

## 本类型硬闸

1. **中介报酬**：报酬请求以促成委托人与第三人订立**具备履行条件的正式技术合同**为前提。禁止放行「本协议签字当日支付全额佣金，无论技术合同是否签署或生效」。报酬、活动经费、未促成时的必要费用必须分列。经费无约定由中介人承担；未促成不得请求报酬，但可按约定请求必要费用；仅在本约写中介条款且报酬不明的，由委托人与第三人平均负担。
2. **与技术转让中介切开**：正像是以知识、技术、经验和信息为另一方与第三人订立技术合同进行联系、介绍，**并对履行该合同提供专门服务**。仅报告技术转让订约机会、媒介签约、不对履行提供专门服务 → `撮合专利许可只收中介费不自己实施也不自己许可→`。中介人自己让与专利权或技术秘密 → `技术转让合同·审查`。禁止打开或复制 `撮合专利许可只收中介费不自己实施也不自己许可→` 的 method。
3. **与技术服务切开**：对履行提供专门服务是联络、交付监督、验收协调、沟通障碍排除，不是中介人自己动手解决特定技术问题。调试、改进、排除故障、操作指导、交付工作成果作为主给付 → `知产技术服务·审查`。禁止打开或复制技术服务 method，不得套用第 882、883 条工作成果主路径。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签技术中介正文，尚未签署，尚未成争，核心给付是联系介绍并对第三人技术合同履行提供专门服务，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 仅报告技术转让订约机会、媒介签约，不对履行提供专门服务，或用户把父级锁在中介合同货架 → `撮合专利许可只收中介费不自己实施也不自己许可→`；
- 中介人自己让与专利权、专利申请权或技术秘密，或主文件是本约 → `技术转让合同·审查`；已有技术的实施或使用许可本约 → `技术许可合同·审查`；
- 动手调试、改进工艺、排除故障、操作指导、交付达标工艺包或工作成果 → `知产技术服务·审查`；狭义技术服务 → `技术服务合同（狭义）·审查`；技术培训 → `技术培训合同·审查`；
- 就特定技术项目只出可行性或技术方案意见、不促成第三人签约 → `知产技术咨询·审查`；
- 尚待研究开发作为主给付 → `技术开发合同·审查`；
- 房屋买卖或租赁中介 → `房屋买卖或租赁中介→`；职业介绍或猎头 → `职业介绍或猎头→`；婚姻中介 → `婚姻中介→`；建设工程招投标中介 → `建设工程招投标中介→`；
- 一般委托代签本约 → `一般委托代签本约→`；以自己名义受让再转出 → `以自己名义受让再转出→`；
- 无文本、本类型条件已谈妥、要出己方稿 → `技术中介合同·起草`；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁或跳单诉讼策略 → `或知产争议专项。` 或对应专项。

以中介为名买卖国家秘密、未批限制进出口技术，或要求把虚假技术参数改成可履行保证：只出告知，不改写成可履行路径。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及受保护名单/费用表版本；是否对履行提供专门服务；拟促成的是开发、许可还是转让；报酬是否绑本约成立；经费与必要费用是否分列；跳单范围与自行获知例外；是否书面如实报告权属与资信；是否保证第三人经济效益；进出口或国家秘密；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的报酬、期限、费用用 `【待填】`，不编造。

宿主可调用时：`search_law` 核验第 887、962–965 条，解释第 38–42 条，以及 878/882 切开、850、506 除外；`search_practiced` 只补审查反例；`search_template` 只借栏目结构。不虚构案件系统。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `技术中介合同·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有技术中介文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。仅报告技术转让机会、动手做技术、本约让与、咨询意见、其他中介负触发。

### 2. 主体与专业能力披露

签约名、履行名、付款名、发票名分列。可要求披露专业领域与利益冲突，不编造「无技术经纪人证合同无效」。

### 3. 标的：联系介绍 + 履行专门服务

写明拟促成的技术合同类型、受保护名单、专门服务内容与期限。促成=签署具备履行条件的正式技术合同，不是 MOU。

### 4. 中介报酬（硬闸）

分列报酬、活动经费、必要费用。删除签字即全额。经费无约定不得写成委托人依法负担。

### 5. 如实报告、跳单与保密

书面报告权属、许可负担、资信与技术风险。965 写范围与自行获知例外，不得写交易当然无效。接触技术秘密须保密，未签保密安排不得放行核心 Know-how。

### 6. 格式条款与强制规范

无核验引文则法律结论字段停止。850、进出口、涉密停笔。

### 7. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把虚假技术参数或未批进出口改成可履行结构、坚持保留签字即全额或第三人收益保证。
- `字段停止`：法域、动态规则、进出口目录、国家秘密审批、地方备案未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
