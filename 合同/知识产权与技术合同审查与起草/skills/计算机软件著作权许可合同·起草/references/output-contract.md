# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或不侵权；编造未给出的许可费、席位、版本；把已失效《合同法》或其解释、《技术合同法》及其实施条例、1991 年软件保护条例、1992 年登记办法写入结论；写“许可就是买断”；写未办许可登记则合同未生效或当然不能对抗第三人；把知产分发／自用或转让主文件当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查计算机软件著作权许可合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、《技术合同法》及其实施条例、1991 年软件保护条例、1992 年登记办法时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `计算机软件著作权许可合同`。定性理由、易混切开结果（知产分发许可、知产自用许可、软件著作权转让、委托开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准：许可不是转让；登记不是生效或物权对抗；向境外许可须进出口手续。未明确权利全授、未批境外交付写停笔告知，不填可履行结构。

## 4. 主体、授权、许可定性与文本版本

主体表：许可人、被许可人、转许可权来源、共有人或职务作品权利人、授权签字人。许可定性：保留权属的使用许可，还是买断过户（后者应已负触发）。版本表：正文、技术规格、开源清单、维保／EULA 附件、聊天确认；冲突并列。未见共有人或职务作品权属闭合而作独占许可：签署能力字段停止。

## 5. 给付闭环

软件名称版本登记号、点名权利项、独占／排他／普通、地域期限、安装限额、目标码／源码与文档、许可费与维保费、开源声明、验收与 SLA、期满卸载销毁、停用保障。缺口标 `G#`，不补商业数字，不补源码原文。许可登记、进出口许可证写成义务或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；自动续费、单方限责、管辖等异常条款。强制规范只按民法典第一百五十三条和合同编通则解释第十六条区分，不用失效“效力性／管理性”口诀。第八百五十条、第八百七十六条、软件保护条例第十八条／第十九条、进出口许可只作为修改理由，不代替修改句。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止写出“许可人将软件著作权全部转让”或“未点名的权利视为已全部授予”。

## 9. 谈判与签署提醒

谈判顺序：先红线（许可／转让定性、未明确权利全授、开源传染、未批出境、850 回授），再必须改（权利项、许可方式、安装限额、交付物、SLA 与退场、停用保障），最后可优化（登记举证、审计频率、关联公司授权）。签署提醒：版本与登记号、开源清单、授权签字、日期与附件清单。不指导倒签或先出境后补证。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、效力保证，也不是知产分发／自用许可或软件著作权转让审查。
