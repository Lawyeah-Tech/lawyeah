### 首部 要素审查

* **合同标题**：提取的标准命名方式为“**计算机软件著作权许可使用合同**”。应明确许可类型，如“**独占许可**”、“**排他许可**”或“**普通许可**”。
* **合同主体**：
* **许可方**：必须是软件著作权人或经合法授权的转许可人。需核实《计算机软件著作权登记证书》。
* **被许可方**：审查其技术环境及使用规模（如安装终端数、并发用户数）。


* **鉴于条款**：重点载明软件的**名称、简称、版本号、软件登记号**。明确许可方拥有该软件完整的、排他的（或有权分许可的）权利。

---

### 交易条款 审查

* **许可范围（核心要素）**：
1. **权利项授权**：明确许可的是哪些权利，如：**复制权、发行权、信息网络传播权**。是否包含**修改权**（关系到是否交付源代码进行二次开发）。
2. **性质界定**：
* **独占许可**：被许可方在约定范围内唯一使用，许可方也不得使用。
* **排他许可**：仅许可方与被许可方在约定范围内使用。
* **普通许可**（最常见）：可同时授权给多个第三方。


3. **地域与期限**：约定授权的地理范围及时间长度。保护期通常为法人作品发表后 **50 年**。


* **费用与支付方式**：
* **授权费（License Fee）**：一次性支付或按年/月订阅。
* **计费模式**：按 CPU 核数、按用户量（User License）、按站点（Site License）或按流量计费。


* **交付物清单**：
* **二进制文件**：安装包、授权码/秘钥、相关驱动。
* **源代码（可选）**：若涉及定制开发或深度集成，需明确是否交付源码。
* **文档**：用户手册、接口 API 文档、安装指南。



---

### 权利担保与维权（重点）

* **著作权登记义务**：
* **法律效力**：合同成立即生效。向**中国版权保护中心**办理许可合同登记虽非强制，但可有效对抗第三人，也是享受软件退税政策的依据。


* **权利瑕疵担保**：
* 许可方保证软件不侵犯任何第三方的知识产权（重点审查**开源协议合规性**，防止被“传染”）。


* **维权约定**：
* 明确发生盗版或第三方侵权时，由哪一方主导法律程序，费用及赔偿款如何分担。



---

### 配套条款 审查

* **违约责任条款（核心）**：
* **超授权范围使用**：被许可方擅自增加终端数、擅自拆解/反编译、擅自转许可的惩罚性赔偿。
* **服务违约**：许可方未按约提供补丁升级、系统崩溃响应迟延的赔偿。


* **后续升级与维护（SLA）**：
* 约定是否包含免费升级服务、重大漏洞补丁的响应时限。


* **反向工程限制**：
* 除非为了实现兼容性所必需，否则通常禁止被许可方对软件进行反汇编、反编译或解码。



---

### 常见问题与最佳实践

* **结构性缺陷**：缺失对**分许可（Sub-license）**的约定。
* **最佳实践**：明确约定被许可方的关联公司（母/子公司）是否自动获得使用权。


* **条款设计陷阱**：
* **“自动续费”陷阱**：未约定合同到期后的处理。应明确到期后是自动终止、自动续期还是需要重新谈判。


* **登记提示**：
* 建议被许可方在获得“独占许可”后，务必办理**软件著作权许可合同备案**，以防许可方再次将权利售予他人。



---

### 审查 Checklist

| 要素 | 审查要点 |
| --- | --- |
| **许可项** | 是否明确包含“复制”、“运行”、“发行”等具体动词 |
| **安装限额** | 是否约定了具体的服务器、终端或 IP 限制 |
| **交付物** | 是否包含 API 文档及环境部署手册 |
| **退场机制** | 合同终止后，被许可方必须在几天内卸载软件并销毁副本 |
