# 软件著作权转让合同·起草

## 任务目标

在单一立场下，只按已谈妥条件起草 **软件著作权转让合同** 己方稿，出稿后用本类型硬闸自审。交付草稿、未决项、自审风险表和自审后修改句。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「软件著作权转让合同·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证登记一定办成或软件永远不被第三方主张。

## 本类型硬闸

1. **软件登记对抗**：计算机软件著作权因开发完成或发表而自动产生，不以登记为生效条件。登记证明文件是登记事项的**初步证明**；转让合同可以另办合同登记或权利人变更，便于对外维权、再许可、出质、海关备案和行政查处，但**不得写成“未登记则合同无效/未生效”**。变更完成前，对外公示的权利人仍是登记名义人。出让人拒不配合提交变更材料、补正或领取新证，构成根本违约。禁止把专利法上“登记之日起权利变动”套到本类型。
2. **源码交付**：主给付是约定著作财产权让与，加上与**锁定版本**一致的全部源代码、目标程序、文档、构建脚本、密钥与第三方库清单的可校验交割。只交安装包、目标程序或登记证复印件，视为未完成主给付。禁止“需要时再提供”“原则上含源码”。验收标准限于可完整交付、哈希一致、可编译、与版本及登记记载一致，**禁止写成功能开发验收或上线里程碑**。
3. **与开发 / 许可切开**：正像是把**已经存在**的特定版本软件的约定财产权让与对方，出让人丧失这些权利，不得再自行复制发行或许可他人（已披露且由受让人承继的在先许可除外）。仅授权使用、出让人继续向市场供应该软件、期限届满收回 → `软件许可合同（分发许可模式）·审查` 或 `软件许可合同（自用许可模式）·审查`。对价绑“谁来写代码、验收什么功能”、订立时模块尚不存在 → `软件委托开发合同·审查`。一般文字、美术、音乐、视听作品财产权让与、无软件全称/版本/源程序 → `著作权转让合同·审查`。夹带未完成模块的，未完成部分拆出，已完成版本才留在本任务。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签软件著作权转让正文，尚未签署，尚未成争，核心给付是已完成特定版本软件的著作财产权让与，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 对价绑研究开发过程、功能清单、上线验收、里程碑付款，订立时软件尚未完成 → `软件委托开发合同·审查`；
- 分发、OEM、SaaS 转授权，出让人保留著作权并继续供货 → `软件许可合同（分发许可模式）·审查`；
- 仅授权受让人自己使用、不得再分发，权属不移转 → `软件许可合同（自用许可模式）·审查`；
- 一般作品著作权让与，标的不是计算机软件或只有作品名称没有源程序/版本 → `著作权转让合同·审查`；
- 著作权许可使用主文件 → `著作权许可使用合同·审查`；委托创作 / 合作创作主文件 → `知产委托创作·审查` / `合作创作合同·审查`；
- 技术类目录下以「计算机软件著作权转让合同」成册的主文件 → `计算机软件著作权转让合同·审查`；专业版未装该原子则 `unavailable`，不得用邻类知识硬套；
- 主给付是未公开技术秘密买断，软著登记只是附带一句 → `技术秘密转让合同·审查`；源码秘密点可点名另审，不代审秘密买断本约；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁或软著权属/侵权已立案 → `或知产争议专项。` 或知产/争议专项。

以转让为名买卖禁止传播内容、未批限制出口技术，或把明知无权处分、隐瞒 GPL 等强互惠开源改成可履行买断：只出告知，不改写成可履行路径。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及附件/版本模块清单/源码交接单版本；软件是否已完成；是买断还是许可或开发；全称、版本号、平台、登记号；源码是否当场校验；登记权利人是否与签约主体一致；在先许可、出质、开源；进出口；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。意见中不得复述用户材料里的完整源码或密钥，只引用版本号、模块名、哈希或交接单编号。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的价款、版本、期限用 `【待填】`，不编造。

## 起草模式

本原子只承担本类型起草。待签评改转 `软件著作权转让合同·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务，不转 `软件著作权转让合同·起草`。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

起草必写：标的是已经存在的特定版本软件的约定财产权让与；计算机软件著作权因开发完成或发表自动产生，登记是登记事项的初步证明，不得写成未登记则合同无效／未生效；变更完成前对外公示的权利人仍是登记名义人；出让人拒不配合提交变更材料、补正或领取新证构成根本违约；主给付加上与锁定版本一致的全部源代码、目标程序、文档、构建脚本、密钥与第三方库清单的可校验交割；验收限于可完整交付、哈希一致、可编译、与版本及登记记载一致。
附件必附：软件全称、版本号、模块、平台、登记号清单；源码哈希／交接单；第三方库清单。
禁止出现：专利法上登记之日起权利变动套到本类型；只交安装包、目标程序或登记证复印件视为完成主给付；需要时再提供、原则上含源码；写成功能开发验收或上线里程碑；仅授权使用、出让人继续向市场供应该软件、期限届满收回（属许可）；对价绑谁来写代码、验收什么功能、订立时模块尚不存在（属委托开发）。职务／合作／委托开发权源未闭合不得写成买断。隐瞒 GPL 等强互惠开源、未批限制出口、明知无权处分：只告知，不起可履行稿。

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → 本任务起草并自审；已签履约 → 本套导航履约步骤；已成争 → 合同争议或知产。未签且目标是评改已有软件著作权转让文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。许可、开发、一般作品著作权转让、技术秘密买断负触发。

### 2. 主体、权属链与在先负担

签约名与登记权利人、职务/合作/委托开发权属、出质、在先许可必须闭合或字段停止。

### 3. 标的特定化与源码交付

全称、版本号、模块、平台、登记号；源码哈希/托管；可编译校验。禁止无版本、禁止源码真空。

### 4. 权利种类、第 29 条与登记对抗

按第 10 条 / 条例第 8 条列举财产权；未列明不得行使；人身权不转移。登记是对抗与举证，不是生效。

### 5. 对价、开源、进出口

价款与源码校验/登记变更挂钩。开源清单作为交割条件。未批限制出口不得先交源码。

### 6. 格式条款与强制规范

无核验引文则法律结论字段停止。

### 7. 违约、解除、争议

拒交源码、拒不登记、重复转让必须分别有可执行后果。权属诉讼与合同仲裁不要互相排斥维权。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把许可或开发改成买断外壳、把明知无权处分或未批出口改成可履行、坚持只转证书不交源码。
- `字段停止`：法域、动态规则、进出口目录、权属或在先许可/出质未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
