# 审查方法（锁定 知识产权相关合同 / 软件著作权转让合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止打开或复制 `著作权转让合同·审查`（一般作品著作权转让）method，禁止打开或复制 `软件委托开发合同·审查`（软件委托开发）method。不把功能验收、开发里程碑、作品名称即可特定当成主路径。

定性校验：标题、核心给付与本类型一致才继续；许可、开发、一般作品转让或他类明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受、保证登记一定办成或唯一必得金额。

`search_law` 返回已失效《合同法》及其解释、1991 年《计算机软件保护条例》、1992 年《计算机软件著作权登记办法》时记为噪声，不得写入 `L#`。1992 年办法第 16 条“不备案不能对抗第三者”已失效，不得当现行法源。

示范文本只参考结构。科学技术部《技术转让（软件著作权）合同》示范文本常按“技术资料提交、转让价款”组栏目，且可能仍引用已失效《合同法》：只借栏目，不得当作源码已交付或登记对抗已被示范文本确认。民法典第 470 条允许参照示范文本，不证明本约条款已被接受。

意见和修改句不得复述完整源码、私钥或生产密钥。只引用软件全称、版本号、模块名、哈希或“附件【待填】第【待填】项”。

知识库纠正（不回写双文件）：

- `基本面.md` / `框架.md` 把登记定位为对抗、举证和变更义务：采用。禁止改写成“未登记合同无效”。当事人另行约定以变更登记为生效条件的，按约定审，但须写清谁主办、几日内、未完成的解除或中止，不得空喊“登记后生效”。
- `框架.md` 验收“可完整交付、可编译、与版本一致”：采用。写成功能测试、用户验收、上线合格的，按开发切开或必须改。
- `框架.md` “登记排队、开源合规整改、编译环境缺失不是不可抗力”：采用。
- 第 27 条书面合同的六项是主要内容清单，不是缺一项整约当然不成立。缺项标必须改，成立问题走著作权民事纠纷解释第 22 条与民法典第 490 条，本任务不宣告已成立或未成立。
- 2013 年《计算机软件保护条例》第 20、21 条全文本次若未核验，书面与登记义务分别回链著作权法第二十七条、条例第七条和著作权法实施条例第二十五条；不把未核验条号写入 `L#`。

## 节点 1　类型识别与单目录加载

### 1.1 定性

用标题、核心给付、对价方式和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

支持切开的规范（法律结论须运行时复核）：

- 著作权法第十条：财产权可以全部或部分转让；人身权（发表、署名、修改、保护作品完整）不在可转让清单。
- 著作权法第二十七条：转让第十条第一款第五项至第十七项规定的权利，应当订立书面合同，并列明作品名称、权利种类与地域、价金、支付、违约等。
- 著作权法第二十九条：许可使用合同和转让合同中著作权人未明确许可、转让的权利，未经著作权人同意，另一方当事人不得行使。
- 《计算机软件保护条例》第八条：软件著作权人可以全部或部分转让软件著作权；权利清单含发表、署名、修改、复制、发行、出租、信息网络传播、翻译等。
- 条例第六条：保护不延及思想、处理过程、操作方法或数学概念。算法本身不是本类型标的。
- 民法典第八百七十六条：计算机软件著作权的转让和许可，参照适用技术转让、许可节。参照不是把本约改成技术秘密或专利转让。
- 技术合同解释第四十六条：计算机软件开发等合同争议，著作权法及其他法律、行政法规另有规定的，依照其规定。开发主文件不在本任务改。

必须切开后再加载，禁止两可时灌入两套知识：

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 已完成特定版本软件；对价换约定财产权让与；出让人停止复制发行和再许可 | 本类型 | 正触发 |
| 分发、渠道、OEM、SaaS 转授权；出让人继续供货 | 软件许可（分发） | 负触发 `软件许可合同（分发许可模式）·审查` |
| 仅自用、不得再分发，权属不移转 | 软件许可（自用） | 负触发 `软件许可合同（自用许可模式）·审查` |
| 功能尚未写完，付款绑开发周期或上线 | 软件委托开发 | 负触发 `软件委托开发合同·审查` |
| 小说、字体、摄影、影视等，无源程序和软件版本 | 著作权转让 | 负触发 `著作权转让合同·审查` |
| 技术类目录下计算机软件著作权转让成册 | 技术类软著转让 | 负触发 `计算机软件著作权转让合同·审查` |
| 主给付是未公开工艺/配方买断 | 技术秘密转让 | 负触发 `技术秘密转让合同·审查` |

标题写“转让”、正文全是许可范围、使用费和届满交回：负触发许可，不删许可句后硬套本技能。标题写“转让”、正文是开发里程碑：负触发开发。

### 1.2 加载协议（硬闸）

本技能已锁定 **知识产权相关合同 / 软件著作权转让合同**。只打开 `references/基本面.md` 与 `references/框架.md`。禁止读其他子目录，禁止为对照再开第二类。禁止打开 `著作权转让合同·审查`、`软件委托开发合同·审查` 的 method。

### 1.3 违法结构停笔

加载后或定性中出现：标的含违法内容或禁止出版传播的软件；未批限制出口技术却约定立即向境外交付源码；用户或材料显示明知登记权利人不是出让人、职务/合作软件个人盗卖，或故意隐瞒 GPL 等强互惠条款，仍要完成买断。

动作：

1. 交付告知：不得改写成可履行买断。职务软件财产权常属单位（条例第十三条；著作权法十八条第二款第一项）。合作开发不能分割使用的，任何一方不得单独转让（条例第十条；著作权法第十四条）。出质后转让须质权人同意（民法典第四百四十四条）。
2. 不写“先受让后补权属”“知情但合同免责”“先交源码后补出口许可证”。
3. 风险表只保留识别依据和转出/删除提示。
4. 用户坚持“改到能签且仍做这些事”：整体停止。

## 节点 2　主体、权属链与在先负担

### 2.1 主体表

建表：签约名、履行名、付款名、发票名、授权签字人、登记权利人。名称不一致不自动合并。口头“我们老板同意了”不得写成已授权。国资评估、上市公司重大无形资产、高校职务软件内部决议未附：该签署能力字段停止。

授权书须含“转让软件著作权”。合作开发须全体出让人签署。

### 2.2 权属链（硬闸）

出让人须为登记权利人或依法的开发者、继受人。登记权利人与签约主体不一致：必须先变更再转让，或取得登记名义人共同签署；不得写成“合同一签权属自然干净”。

| 来源 | 规则要点 | 本任务动作 |
| --- | --- | --- |
| 职务开发 | 条例第十三条；著作权法十八条第二款第一项：计算机软件等职务作品，作者享有署名权，其他权利由单位享有（符合法定情形） | 个人开发者单独签署：字段停止或红线补单位主体 |
| 合作开发 | 条例第十条：不能分割使用的，协商一致行使；任何一方不得阻止他方行使**除转让权以外**的其他权利 | 转让须全体一致；一方签字处分整体：红线 |
| 委托开发 | 条例第十一条：无书面约定则著作权归受托人 | 出让人是委托人但无权属约定：权属字段停止 |
| 外包/开源贡献 | 权属链高频断裂点 | 附件列开发合同、贡献者许可；材料不足不写清洁 |

民法典第八百七十条经第八百七十六条参照：让与人应当保证自己是合法拥有者，并保证完整、无误、有效，能够达到约定目标。未核验材料不得写成权属清洁。

### 2.3 在先许可、出质与重复处分

已发放的分发许可、OEM、SaaS 授权不因转让当然消灭。出质期间不得擅自转让（民法典第四百四十四条）。

| 文本写法 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 未披露是否已许可第三人 | 必须改：附件列在先许可的相对方类型、范围、期限、可否终止或由受让人承继 | 未提及就是没有 |
| 已有分发许可仍声称全部权利干净让与 | 红线：列清单，由受让人决定承继或终止；冲突许可未清理则不签买断 | 转让后许可自动消灭 |
| 已出质未取得质权人书面同意 | 红线：取得同意或先涤除质权 | 出质不影响转让 |
| 出让人保留向全市场继续供应该软件 | 按许可重新定性，负触发 `软件许可合同（分发许可模式）·审查` | 普通转让所以可以继续卖 |

## 节点 3　标的特定化与源码交付

### 3.1 版本锁定

标的必须写到：**软件全称、版本号、平台（客户端/服务端/嵌入式）、开发语言、登记号（如有）**。附件列模块清单。禁止只写“某系统全部软件著作权”。后续小版本、补丁、分支是否纳入必须明示；未纳入的走补充协议。

登记证书按版本记载。合同版本、商用版本、登记版本三套皮：必须改到同一版本号，或明确各版本分别作价。

### 3.2 源码交付（硬闸）

交付物最低清单：目标程序、**全部源代码**、设计/使用说明、编译与构建环境说明、密钥与证书（可托管）、第三方库与开源清单。

交割动作必须可核验：

1. 交割当日按文件级或仓库级哈希校验，记录于《源码文档交接单》。
2. 受让人指定环境当场或约定期限内完成编译，生成物与约定版本一致。
3. 价款未清或登记未完成时，可采用第三方托管或双控仓库，条件成就后释放。
4. 签收只证明载体件数，不视为验收通过。

| 文本写法 | 动作 |
| --- | --- |
| “需要时提供源码”“原则上含源码”“尽快交付相关技术” | 红线删除。改为：签约后【待填】日内交付与 V【待填】登记版本一致的全部源代码和文档，当场哈希校验；无法编译或与版本不符的，受让人有权拒付尾款并解除 |
| 只交目标程序或安装盘 | 必须改：补源码，或显著区分残缺对价并放弃修改/再开发控制利益——后者须用户明示接受 |
| 只交登记证复印件 | 红线：交证不等于财产权转移，更不等于源码交付 |
| 验收写成功能测试、用户验收、上线合格 | 必须改或负触发开发：本类型验收只问可交付、可编译、与版本一致 |
| 技术支持写成开发里程碑、缺陷修复无限期 | 必须改：有限期安装/编译协助，天数上限【待填】，性质为附随义务 |

有限期协助可以保留，防止合同滑向技术开发。协助逾期不是不可抗力。

## 节点 4　权利种类、第 29 条与登记对抗

### 4.1 权利清单与反说

按著作权法第十条和条例第八条逐项点名拟转让的财产权：复制、发行、出租、信息网络传播、翻译，以及是否含再许可、再转让。地域必须写明。

正说：交付并满足约定条件后，上列财产权归受让人。

反说（必须同时落句）：

- 未明确转让的权利，受让人不得行使（第二十九条）。
- 署名权、修改权、保护作品完整权不转移。
- 思想、算法、处理过程不受软件著作权保护（条例第六条）；专利或开源互惠义务可能独立限制行使。
- 未交与版本一致的源码，视为未完成主给付。

“全部软件及相关技术”“含全部技术方案和专利”只写在鉴于里：必须改到交易条款，专利另拆或负触发。

### 4.2 登记对抗（硬闸）

| 文本写法 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 本合同自软件登记机构变更登记之日起生效，未登记未生效 | 必须改：删除登记生效。合同自依法成立时生效；变更登记是出让人协助义务和受让人对抗、举证枢纽。当事人确需以变更登记为生效条件的，写清主办方、【待填】日补正期限、逾期解除或中止 | 和专利转让一样要登记才生效 |
| 未办理转让合同登记则合同无效 | 必须改：合同登记、权利人变更均非生效要件；登记证明是初步证明（条例第七条）；专有许可或转让合同可以向著作权行政管理部门备案（实施条例第二十五条） | 未登记未生效 |
| 只约定“协助办理登记”，无期限、无拒不配合后果 | 必须改：出让人于源码校验通过后【待填】日内共同提交变更申请；逾期不配合视为根本违约，受让人可主张过户不能的损害赔偿并中止尾款 | 协助二字已足够 |
| 变更完成前未约定谁维权、谁收许可费 | 必须改：过渡期内对外公示权利人仍是登记名义人；许可费归属、开源合规责任写清 | 未约定视为受让人已能对外维权 |

最强反方：出让人主张“著作权自动产生，不必登记”。回应：自动产生解决的是**有没有权利**，不解决**对外对抗和举证**。受让人付的是可对外主张的控制权，拒不变更登记会使买断目的落空。

## 节点 5　对价、开源、进出口

### 5.1 对价

固定价款建议与源码校验、登记变更挂钩：首期对交接、中期对编译通过、尾款对变更后证书。未给出的数字写 `【待填】`。禁止编造评估值。

定金：必须使用“定金”二字才讨论罚则。民法典第五百八十六条：不得超过主合同标的额百分之二十，超过部分不产生定金效力。担保交源码和配合登记用“定金”；预付款用“首期转让价款”。

权属被追夺、版本不符、开源传染导致不能按约定闭源分发的：返还已付款并赔偿，不得只写“依法承担责任”。

### 5.2 开源与第三方

开源组件清单和许可证意见作为交割条件。隐瞒 GPL 等强互惠条款构成权属瑕疵。思想不受保护，不妨碍互惠许可证独立限制闭源销售。

修改句：出让人保证附件《开源及第三方清单》完整；若因签约前未披露的强互惠条款导致受让人不能按约定方式分发，受让人有权降价、解除或要求替换不侵权实现。

### 5.3 进出口

条例第二十二条：向外国人许可或转让软件著作权，应当遵守《技术进出口管理条例》。限制出口技术未经许可不得出口；技术出口合同自许可证颁发之日起生效（条例第三十条、第三十五条）。自由出口技术合同自依法成立时生效，不以登记为生效条件（第三十六条）。

限制出口“先交源码，许可证后补”：整体停止或履行字段停止。批准作为生效或交付源码的前提。

## 节点 6　格式条款、免责与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 免责

可约定除权属追夺、拒交源码、拒不登记、故意或重大过失外的赔偿上限。下列不得排除（第五百零六条及本类型主给付）：

- 造成对方人身损害；
- 因故意或者重大过失造成对方财产损失；
- 无权处分或重复转让；
- 拒交源码或拒不配合变更登记。

“出让人对能否登记、源码能否编译不承担任何责任”：必须改。

### 6.2 格式条款

民法典第四百九十六条、第四百九十七条；合同编通则解释第九、十条。依据示范文本制作，不当然排除格式条款。仅网络勾选或弹窗：不得写成已尽提示义务。

### 6.3 强制规范

违反法律、行政法规强制性规定不一律无效。禁止用已失效“效力性/管理性”口诀。买卖禁止传播内容、未批限制出口仍交付源码、明知无权处分或隐瞒强互惠开源：不改写成有效履行结构。

## 节点 7　违约、解除、争议

拒交源码、版本不符无法编译、拒不配合登记、重复转让、隐瞒开源传染，必须分别有可执行后果。只有“依法承担违约责任”视为必须改。构成违约不等于当然解除。违约金不是必得金额；禁止写“不得调整”。

权属诉讼与合同仲裁不要互相排斥：修改句保留受让人对第三人提起侵权或权属确认的权利，不因本合同仲裁条款放弃。

争议解决：出现仲裁条款，不得改写成“应向某法院起诉”。或裁或诉、机构不明：标待核，改成单一机构或单一法院连结点。

通知送达：微信已读不写成已经到达，除非合同把该渠道写成送达且用户要保留。源码不得经未加密即时通讯传送。

## 节点 8　按框架六步出修改句

| 步 | 动作 | 必须产出 |

| 首部 | 标题用软件著作权转让或计算机软件著作财产权转让，不用开发/许可/一般作品转让混称；主体与登记权利人一致；鉴于只写开发完成、版本与登记事实，不写保证通过登记或含全部专利 | 标题或主体修改句 |

每条修改句固定格式：

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（实为许可或开发、源码真空拒补、只转证书、未登记未生效拒改、明知无权处分、未批出口仍要交源码、合作开发一方擅自转让）；
- `必须改`：可谈但签署前要落句（版本号、权利清单与第 29 条反说、登记配合期限、在先许可、开源清单、价款节点、有限期协助）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级金额或个人无限连带且用户拒绝升级：停止“可以签署”建议。
