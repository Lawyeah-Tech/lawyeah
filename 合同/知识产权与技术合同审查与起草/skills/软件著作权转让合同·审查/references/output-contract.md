# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、版本、工期；把已失效《合同法》、1991 年《计算机软件保护条例》、1992 年《计算机软件著作权登记办法》写入结论；保证登记一定办成；把许可或开发文本当成已完成的本类型审查；写“未登记则本合同未生效”；写“先向境外交源码后补出口许可证”；在意见中复述完整源码或密钥。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查软件著作权转让合同（知识产权相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》、1991 年条例、1992 年登记办法时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `知识产权相关合同`，子级 `软件著作权转让合同`。定性理由、易混切开结果（分发许可 / 自用许可 / 软件委托开发 / 一般著作权转让 / 技术类软著转让 / 技术秘密）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属链、在先负担与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、登记权利人。权属表：取得方式（原始/继受/职务/合作/委托）、共有人、出质、已向第三人许可的范围与可否买断。版本表：正文、版本模块清单、源码交接单、登记证、开源清单、聊天确认；冲突并列。意见只引用版本号与哈希，不摘录源码。

## 5. 给付闭环

软件全称与版本号；权利种类与地域；第 29 条未列明权利；源码/文档/构建环境交付与哈希；验收是否误写成开发验收；价款与校验/变更节点；登记对抗而非登记生效；开源与进出口。缺口标 `G#`。不输出“未登记未生效”，不输出功能上线保证。

## 6. 格式条款、强制规范与进出口

是否构成格式条款；提示说明痕迹。强制规范只按第 153 条和合同编通则解释区分，不用失效口诀。技术进出口未批准：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。原文摘录不得含完整源码或密钥。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。必须出现可回给对方的完整句子，禁止只给原则。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为许可或开发、源码真空、只转证书、登记生效误用、明知无权处分、未批出口），再必须改（版本号、权利清单与第 29 条反说、登记配合期限、在先许可、开源清单、价款节点），最后可优化。签署提醒：授权须含“转让软件著作权”、合作开发全体用印、日期、版本模块清单、哈希交接单、开源清单、登记申请草本。不指导倒签或先交源码后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是软件委托开发、软件许可或一般作品著作权转让安排。
