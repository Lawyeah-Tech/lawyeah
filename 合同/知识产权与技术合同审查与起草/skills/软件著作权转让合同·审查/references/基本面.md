## **第一步：合同类型（法律性质）分析**

* **法律定性**：软件著作权转让合同是软件著作权人将其软件上的**著作财产权**（复制、发行、出租、信息网络传播、翻译等）让与受让人、受让人支付价款的合同。核心给付是**已存在软件的权属变更**，不是委托开发、也不是技术秘密“交底”。适用《著作权法》（2020修正）第27条、第29条，《计算机软件保护条例》，《计算机软件著作权登记办法》，《民法典》第876条（软件著作权转让、许可参照技术转让、许可节）。涉及跨境的，同时审《技术进出口管理条例》。
* **易混淆辨析**：
* **软件著作权转让 vs 一般作品著作权转让**：规则同源，但软件必须锁定**软件全称、版本号、源程序与文档**；登记证书（如有）按版本记载，漏版本等于漏标的。
* **转让 vs 许可**：转让后出让人丧失约定财产权，不得再自行复制发行或许可他人。合同保留出让人无限期复制分发权的，实为许可。
* **转让 vs 软件开发/委托开发**：开发合同解决“谁来写代码、验收什么功能”；本类型假定软件已完成，交易的是权属。夹带未完成模块的，把未完成部分拆成委托创作/开发，已完成版本按转让审。
* **转让 vs 技术秘密转让**：源码可同时构成商业秘密。著作权转让不自动等于技术秘密转让；未约定保密和秘密点的，受让人拿到源码仍可能被出让人就“秘密”主张权利，或相反——出让人泄密损害受让人。
* **效力认定**：
* **财产权转让应书面**，列明软件名称（含版本）、权利种类、地域、价金、支付、违约（《著作权法》第27条）。**未明确转让的权利，受让人不得行使**（第29条）。
* 软件著作权登记、转让合同登记均非生效要件，但是权属对抗、海关备案、融资出质、行政查处中的关键证据。登记权利人与出让人不一致的，须先变更再转让。
* 人身权中的署名权、修改权不因转让消灭。禁止出版传播或含违法内容的软件不能作为有效标的。


## **第二步：合同主体（交易对手）分析**

* **出让人**：须为登记权利人或依法的开发者、继受人。合作开发软件适用合作作品规则：**转让须全体一致**。职务开发软件，财产权常属单位，个人开发者无权签署。
* **受让人**：拟自行使用、再许可或分发的，主体资格一般不设行政许可门槛；但经营特定行业软件（医疗器械软件、网游等）另受行业准入约束，那是使用侧问题，不替代权属审查。
* **关联主体**：
* **实际开发者、外包方、开源贡献者**：权属链断裂的高频来源。
* **在先被许可人、OEM厂商**：已发放的分发许可不因转让当然消灭。
* **质权人**：软件著作权出质后转让须质权人同意。
* **进出口主管部门**：向境外转让视同技术出口，可能需许可或登记。
* **签约能力**：国资软件评估；上市公司重大无形资产；跨境主体身份与技术出口合规。


## **第三步：合同标的（交易对象）分析**

* **标的特定化**：**软件全称、版本号、平台（客户端/服务端/嵌入式）、开发语言、登记号**。附件列模块清单。禁止只写“某系统全部软件著作权”。
* **交付物**：目标程序、**全部源代码**、设计/使用说明等文档、编译环境说明、密钥与证书、第三方库清单。只交目标程序的，受让人无法行使修改、再开发对应的控制利益，转让对价应显著区分，或视为残缺给付。
* **权利负担**：
* 在先许可（尤其分发许可、SaaS授权）、开源协议（GPL等传染）、第三方SDK、字体与素材。
* 出质、查封、权属诉讼、海关备案。
* **可交易性**：思想、算法、处理过程本身不受软件著作权保护；专利、开源互惠义务可能独立限制行使。保护期自首次发表或开发完成起算，须核算剩余年限。


## **第四步：合同程序（交易步骤）分析**

* **书面签约** → 源码与文档交割（哈希/托管）→ 办理软件著作权转让登记/变更登记 → 技术出口手续（如需）→ 尾款。
* **登记对抗**：受让人应取得变更后的登记证书再对外维权、再许可、出质。出让人拒不配合登记的，构成根本违约。
* **过渡**：登记完成前谁维权、谁收取许可费、谁承担开源合规。未约定时，对外公示的权利人仍是登记名义人。
* **内部决策**：单位处分职务软件、共有人一致同意、国资程序。


## **第五步：交易结构设计（风险规避方案）**

* **对价**：固定价款 + 登记完成付尾款；或按模块拆分。定金不超过主合同标的额**20%**。权属被追夺、开源传染导致不能闭源分发的，返还并赔偿。
* **源码托管**：交割至第三方托管或双控仓库，登记完成或价款付清后释放。
* **负担清除**：终止或由受让人承继在先许可；开源组件清单和许可证意见作为交割条件。
* **技术支持边界**：可约定有限期的安装、编译协助，性质是转让附随义务，**不要写成开发验收条款**，以免合同被识别为技术开发。
* **文本形态**：**主转让协议 + 版本与模块清单 + 源码文档交接单 + 开源/第三方清单 + 无负担声明 + 登记申请草本 + 技术出口文件（如有）**。


## **第六步：宏观风险预警与尽调指引**

* **高频争议**：只转登记证书不交源码；版本号与登记不一致；外包开发未取得权属即出让；开源传染后受让人无法闭源销售；名为转让实为许可。
* **尽调清单**：
* [ ] 登记证书名称、版本、权利人、权利取得方式
* [ ] 源码可编译性与文档完整性
* [ ] 合作开发、职务开发、委托开发的权属合同
* [ ] 在先许可、分发/OEM、出质
* [ ] 开源组件及许可证
* [ ] 跨境转让的技术进出口分类
* **重大风险红旗**：登记权利人与签约主体不一致；“转让后出让人继续向全市场供应该软件”；无版本号；源码以“后续配合提供”代替当场校验。
