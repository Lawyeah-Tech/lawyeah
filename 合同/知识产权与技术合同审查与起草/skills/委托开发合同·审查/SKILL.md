# 委托开发合同·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》技术开发章、《技术合同法》及其实施条例、1990 年《技术合同认定登记管理办法》当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **技术类合同 / 委托开发合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「委托开发合同·审查」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证研发成功或拿到专利、把技术开发总册/合作开发/委托父级文本改完。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **一方出资、研究开发人独立完成**：委托人只出经费、设备、材料或辅助协作。双方按计划分工承担设计、工艺、试验、试制 → 负触发 `合作开发合同·审查`。标题只写“技术开发合同”且未独立成册为委托开发 → 负触发 `技术开发合同·审查`。用户或材料按委托合同父级进入 → 负触发 `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`。
2. **第859条默认归研究开发人**：无约定时，申请专利的权利属于研究开发人；研究开发人取得专利权的，委托人可以依法实施；研究开发人转让申请权的，委托人同等条件优先受让。禁止把“甲方出钱即当然归甲方”或“当然双方共有”写成现行法默认。买断必须明示。
3. **技术风险不是保底交付**：无法克服的技术困难导致失败，无约定则合理分担。禁止放行“保证研发成功 / 保证拿到专利 / 失败全额退款”。已尽合理专业努力仍失败，不得径直写成违约。
4. **现有技术冒充开发或重复收取**：把已有成果当作研究开发标的收经费，或同一课题向多个委托人重复收费：只告知可撤销风险，不改成可履行假开发。用户坚持：整体停止。
5. **非法垄断技术（850）**：限制继续研发、不对等回授、限制从其他来源获得竞争技术：必须删除。不得改成可履行禁研结构。
6. **资料交付与可量化验收**：须交付成果、技术资料并给予必要指导，帮助委托人掌握成果。禁止只交黑盒。指标须客观可测；签收、付款、试用不当然等于验收。
7. **主要研发不得擅自交第三人**：核心课题须亲自完成或事先书面同意。不得把委托合同任意解除或转委托条文当作本类型默认。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签委托开发正文，尚未签署，尚未成争，核心给付是一方出资、另一方独立研究开发订立时尚不存在的技术方案，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 标题或主文件是未细分的《技术开发合同》 → `技术开发合同·审查`；
- 双方分工参与设计、工艺、试验、试制 → `合作开发合同·审查`；
- 用户或材料按委托合同父级进入，主路径是处理事务、任意解除或转委托 → `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`；
- 主轴是可运行软件交付、几乎无研发不确定性 → `软件委托开发合同·审查`；
- 已有成熟技术转让或许可 → `技术转让合同·审查` / `技术许可合同·审查` / `专利实施许可合同·审查`；
- 按既有图纸常规加工、验证、测试 → `按既有图纸加工定作实物→负触发`；
- 仅出具可行性或评价意见 → `知产技术咨询·审查` 或 `或`；
- 只解决特定技术问题、不产出新方案 → `知产技术服务·审查`；
- 已有科技成果实施转化 → `技术转化合同·审查`（P1；专业版未装则 `unavailable`）；
- 无文本、本类型条件已谈妥、要出己方稿 → `委托开发合同·起草`；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼或仲裁，或要权属诉讼策略 → `或知产争议专项。` 或对应专项领域。

假开发骗经费、未批限制进出口、通谋虚假经费：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（委托人侧或研究开发人侧择一）；相对方；全文及任务书/预算/进度表/背景IP清单版本；委托人是否只出钱还是派员共同攻关；标的是否订立时尚未掌握；专利申请权是否另约；是否保证成功或失败全额退款；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的经费、指标、期限用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验一方出资定性、859 归属、858 风险、850 垄断、解释第 9/17/19 条、格式条款、定金上限；`search_practiced` 只补审查反例；`search_template` 只借科技部委托开发栏目。不虚构案件系统。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》技术开发章、《技术合同法》及其实施条例、1990 年认定登记办法时记为噪声，不得写入 `L#`。第 854、855 条若未返回独立全文，该条号法律结论字段停止。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)
- [框架](references/框架.md)

禁止打开其他类型目录。`框架.md` 中“优先受偿权”按第 859 条纠正为优先**受让**。“失败全额退款可能被认定为工程或劳务”只作审查警告，不自动改定性。认定登记不是合同民事生效条件。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `委托开发合同·起草`；已签履约 → 本套导航履约步骤；已成争或权属诉讼策略 → 合同争议。未签且目标是评改已有委托开发文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。合作开发、技术开发总册、委托父级、纯软件、转让、承揽、咨询、服务负触发。

### 2. 主体、资质与核心人员

签约名、履行名、付款名、发票名分列。特殊行业许可与核心人员锁定未核：字段停止，不编造法定必须点名某自然人。

### 3. 课题、三新与背景知识产权

订立时尚未掌握；列明背景技术清单；禁止把验证测试写成开发。

### 4. 第859条归属与第861条技术秘密

无约定不得写成归委托人或当然共有。买断须明示。技术秘密交付前不得转让第三人。

### 5. 经费、报酬与里程碑

经费与报酬分列；包干或据实写清；付款挂钩阶段验收。

### 6. 技术风险、850垄断与格式条款

858 与保底分列。禁研条款删除。无核验引文则法律结论字段停止。

### 7. 交付资料、验收、转第三人与违约

黑盒必须改。核心课题不得擅自转包。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效或拿到专利、把假开发/未批限制进出口/850 禁研/失败全额退款改成可履行结构。
- `字段停止`：法域、854/855 条号冲突、认定登记现行办法、进出口目录、行业许可未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
