# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然可执行或一定能量产；编造未给出的入门费、提成、指标；把已失效《合同法》《技术合同法》及其实施条例、1996 年未修正转化法专条、1984 年专利法旧文写入结论；把从零开发或买断转让当成已完成的本类型审查；把个人擅自处分职务成果写成可履行；套用第八百五十九条、第八百六十条或第八百七十条作为本类型默认。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术转化合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、1996 年未修正转化法专条、1984 年专利法旧文时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `技术转化合同`。定性理由、易混切开结果（委托开发 / 合作开发 / 技术开发父级 / 技术转让许可 / 技术咨询服务 / 技术入股）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、职务成果与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。职务成果表：是否职务成果、单位授权或第十九条协议、完成人优先受让、公示或挂牌拍卖。版本表：正文、成果清单、资料移交清单、工艺达标协议、分成办法、聊天确认；冲突并列。

## 5. 阶段性成果、失败定性与给付闭环

订立时成果是否已存在及成熟度；后续试验/中试/试产目标；资料移交是否足以复现；失败原因如何拆分；阶段验收指标；入门费与提成；背景权利与转化增量。缺口标 `G#`。批准、公示、登记写成生效条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款。限制后续改进按第八百五十条和解释第十条逐项核对。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“二年未实施即可收回”或“谁改进谁所有”写成法定义务。

## 9. 谈判与签署提醒

谈判顺序：先红线（个人处分职务成果、从零开发或买断误入、保证量产、850 垄断、倒签），再必须改（成果清单、失败定性、阶段验收、背景/增量、授权或公示、圈占收回），最后可优化。签署提醒：单位用印、日期、成果/资料/工艺/分成附件、公示完成是否作为生效条件。不指导倒签或补假公示。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是委托开发、合作开发或技术转让安排。
