# 合作开发合同·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、已失效《技术合同法》及其实施条例、1984 年《专利法》旧文当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **合作开发合同** 己方稿，出稿后用本类型硬闸自审。交付草稿、未决项、自审风险表和自审后修改句。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「合作开发合同·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、把一方出钱一方干活改成可履行“共有”、把房地产合作开发或技术入股整案改完。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **双方共同投入**：各方须按约定投资（含技术投资）、**分工参与研究开发工作**并协作配合（民法典第八百五十五条）。一方只出资金、设备、材料或只做辅助协作，另一方独自研发 → 解释（2020 修正）第十九条认定为委托开发；负触发 `委托开发合同·审查`（文本落在委托技术开发目录则 `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`），不把共有申请权写成已锁定。
2. **860 共有**：合作开发完成的发明创造，申请专利的权利原则上属于合作各方共有；转让共有申请权时其他方有同等条件优先受让权。另有约定须写清归谁、是否放弃、放弃方免费实施。禁止只写“知识产权归甲方”而不区分背景技术、前景技术、专利申请权与技术秘密。
3. **一方不同意不得申请专利**：第八百六十条第三款无“另有约定除外”。共有结构下写“任一方可单独申请”“对方沉默视为同意申请”→ 红线删除。要单方申请：须先按第一款把申请权明确归一方，或按第二款取得他方书面放弃；不得在仍称共有时架空否决权。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签合作开发正文，尚未签署，尚未成争，核心给付是各方共同投资并分工参与新技术、新产品、新工艺、新品种或新材料及其系统的研究开发，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 一方出资提需求、另一方独立完成研发，出资方不承担设计/工艺/试验/试制 → `委托开发合同·审查`；标题写成委托技术开发则 `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`；
- 标题或主轴是未区分委托/合作的《技术开发合同》，且看不出共同参与 → `技术开发合同·审查` 或回引擎重新定性；
- 可运行软件、系统上线、源码交付且只有一方开发 → `软件委托开发合同·审查`；
- 就已有实用成果做实施转化、不开展新的共同研究 → `技术转化合同·审查`（P1；专业版未装则 `unavailable`）；
- 让与已有专利、申请权或技术秘密，对价是转让费而非共同攻关 → `技术转让合同·审查` / `专利权转让合同·审查` / `专利申请权转让合同·审查` / `技术秘密转让合同·审查`；
- 许可实施已有技术 → `技术许可合同·审查` / `专利实施许可合同·审查` / `技术秘密使用许可合同·审查`；
- 特定技术项目可行性、预测、评价，不共同研发 → `知产技术咨询·审查` 或 `委托合同目录下的技术咨询→`；
- 解决特定技术问题、调试、培训，无共同创造新技术 → `知产技术服务·审查` 或 `委托合同货架按处理事务费用预付任意解除起草的同名《技术服务合同》→`；
- 以地换房、共同投资房地产、固定回报拿房 → `以地换房共同投资房地产固定回报拿房→`（P1；未装则 `unavailable`）；
- 技术折价入股、设立合资公司并办理股权变更为主给付 → 回引擎按公司/出资类重新定性，不按本类型改完；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼或仲裁 → `或知产争议专项。` 或对应专项领域。

以合作开发为名套取对方背景技术、单方抢注中间成果、规避出口管制或把限制后续改进写成可履行垄断：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（出资兼研发的哪一方）；相对方；全文及任务分工表、背景技术清单、经费预算版本；各方是否都承担设计/工艺/试验/试制；专利申请权是共有、归一方还是沉默；一方不同意时能否申请；背景与前景是否隔离；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的投资额、人员工时、分成比例用 `【待填】`，不编造。

## 起草模式

本原子只承担本类型起草。待签评改转 `合作开发合同·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务，不转 `合作开发合同·起草`。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

起草必写：各方按约定投资（含技术投资）、分工参与研究开发工作并协作配合；合作开发完成的发明创造，申请专利的权利原则上属于合作各方共有；转让共有申请权时其他方有同等条件优先受让权；另有约定须写清归谁、是否放弃、放弃方免费实施；一方不同意申请专利的，不得申请；背景技术、前景技术、专利申请权与技术秘密必须分项写。
附件必附：任务分工表；背景技术清单。
禁止出现：一方只出资金、设备、材料或只做辅助协作却写成共有申请权已锁定；只写知识产权归甲方而不区分背景技术、前景技术、专利申请权与技术秘密；共有结构下写任一方可单独申请、对方沉默视为同意申请。限制后续改进或套取背景技术：只告知，不改成可履行垄断结构。

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → 本任务起草并自审；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有合作开发文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。仅出资、已有技术转让、房地产合作、技术入股、咨询服务负触发。

### 2. 主体、互补能力与人员

签约名、履行名、经费账户名、发票名分列。关键研发人员（PI）名单与工时须落附件。口头“我们实验室会派人”不得写成已投入。

### 3. 双方共同投入

投资形式、分工模块、协作机制缺一项则不得写成已构成合作开发。

### 4. 860 共有与申请否决

默认共有；另有约定须明示；一方不同意不得申请；禁止共有下的单方抢注授权。

### 5. 背景/前景、技术秘密与后续改进

背景清单隔离；技术秘密使用权按第八百六十一条约定；改进不得落入非法垄断技术。

### 6. 程序、失败风险与公开

里程碑、联合验收、研发失败合理分担、标的被他人公开可解除。

### 7. 格式条款、免责与强制规范

限额可留，人身损害与故意/重大过失不得排除。无核验引文则法律结论字段停止。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把仅出资写成法定共有、在共有结构下保留单方申请、把限制后续改进或套取背景技术改成可履行结构。
- `字段停止`：法域、出口管制、职务发明内部规章、国资/高校成果转化审批未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
