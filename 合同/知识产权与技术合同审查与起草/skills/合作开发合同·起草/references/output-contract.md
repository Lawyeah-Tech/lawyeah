# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的投资额、工时、分成；把已失效《合同法》《技术合同法》及其实施条例、1984 年专利法旧文写入结论；把仅出资写成已构成合作开发；在共有结构下保留单方申请；把房地产合作开发或技术入股文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查合作开发合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、1984 年专利法旧文时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `合作开发合同`。定性理由、易混切开结果（委托开发 / 技术开发父级 / 软件委托开发 / 技术转化 / 技术转让许可 / 技术咨询服务 / 房地产合作开发 / 技术入股）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、人员与文本版本

主体表：签约名、履行名、经费账户名、发票名、授权签字人。人员表：各方 PI、工时、撤换限制。版本表：正文、任务分工表、背景技术清单、经费预算、聊天确认；冲突并列。

## 5. 共同投入、860 共有与申请否决

各方投资形式（货币/设备/场地/技术折价）是否落到可核验清单；是否分工承担设计、工艺、试验或试制；专利申请权默认共有还是另有约定；一方不同意时他方不得申请是否落句；放弃申请与免费实施；技术秘密使用/转让/收益；背景与前景隔离。缺口标 `G#`。

## 6. 失败风险、格式条款与强制规范

研发失败如何分担；标的被他人公开的解除；限额与除外（人身损害、故意或重大过失、侵权、泄密不得排除）。是否构成格式条款；提示说明痕迹。限制后续改进按第八百五十条和解释第十条逐项核对，不宣告一切“改进须同意”当然无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“联合账户共同签章”“授权协商机制”写成法定义务。

## 9. 谈判与签署提醒

谈判顺序：先红线（仅出资假合作、共有下单方申请、套取背景技术、限制后续改进落入解释第十条、违法结构），再必须改（分工表、860 共有与否决落句、背景清单、失败风险、放弃与优先受让），最后可优化。签署提醒：授权、用印、日期、分工表/背景清单/预算作为附件、经费到账是否作为生效条件。不指导倒签或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是委托开发、软件单方开发、技术转让或房地产合作开发安排。
