# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的使用费、地域、期限；把已失效《合同法》《技术合同法》及其实施条例写入结论；把许可写成过户；把未约定方式写成独占；把“提出无效即立即终止”当最佳实践；把专利实施许可专件或技术转让文本当成已完成的本类型审查；写“先交付后补批”进出口或国家秘密路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术许可合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `技术许可合同`。定性理由、易混切开结果（转让 / 专利实施许可专件 / 技术秘密使用许可专件 / 开发 / 咨询 / 服务 / 中介）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、共有人或转许可授权人。权属表：专利号/秘密描述、登记权利人、在先许可、质押或无效程序。版本表：正文、范围表、专利/秘密清单、许可费计算表、聊天确认；冲突并列。

## 5. 许可闭环

是否所有权不更替；方式/地域/期限/领域/人员是否落句；分许可；入门费/提成/保底/查账；专利费与秘密费是否分列；资料是否足以实施；850 条款；后续改进；备案义务主语。缺口标 `G#`。不输出转让过户或开发“必然交付成果”口径。

## 6. 格式条款、强制规范与进出口

是否构成格式条款；提示说明痕迹。850 条款不得写成可放行。强制规范只按第 153 条区分，不用失效口诀。备案不是生效要件。技术进出口或国家秘密未批准：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“挑战即终止”写成可放行最佳实践。不得把未约定方式写成独占。

## 9. 谈判与签署提醒

谈判顺序：先红线（其实是让与、850 拒删、无权处分/共有人未同意、未批进出口、挑战即终止），再必须改（方式/地域/期限、分许可、分费、资料清单、查账、备案义务），最后可优化。签署提醒：授权、用印、日期、范围表与专利/秘密清单、共有人同意书。不指导倒签或先交付后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是技术转让、专利实施许可专件或技术开发安排。
