# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的报酬、费用、期限；把已失效《合同法》《技术合同法》及其实施条例写入结论；保证第三人投产或固定收益；把签字即全额写成可放行结构；把跳单写成交易当然无效或中介必然胜诉；把仅报告机会或技术服务文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术中介合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、2004 年未修正技术合同解释时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `技术中介合同`。定性理由、易混切开结果（技术转让中介 / 技术服务 / 本约让与或许可 / 咨询 / 其他中介 / 委托 / 行纪）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、专业能力与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。专业能力表：披露的领域或经历、与拟介绍第三人有无利益关联、是否双边委托。版本表：正文、受保护名单、费用报销标准、聊天确认；冲突并列。

## 5. 给付闭环：专门服务、促成、报酬、报告与跳单

是否对履行提供专门服务；拟促成的技术合同类型；促成是否定义为正式技术合同而非 MOU；报酬、经费、必要费用是否分列；是否出现签字即全额；965 是否写范围与自行获知例外；书面如实报告是否作为附件；是否保证第三人经济效益。缺口标 `G#`。不输出本约交付登记口径或技术服务工作成果验收口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。全额预付、跳单无效、排除故意或重大过失的免责必须改。强制规范只按第 153 条区分，不用失效口诀。技术进出口或国家秘密未批准：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把「无技术经纪人证合同无效」或「跳单交易当然无效」写成法定默认。

## 9. 谈判与签署提醒

谈判顺序：先红线（不是本类型、签字即全额、收益保证、虚假参数、未批进出口、跳单无效），再必须改（促成定义、经费分列、965 例外、书面报告、专门服务内容、保密阶段），最后可优化。签署提醒：授权、用印、日期、受保护名单、费用表、诚实信用承诺书、书面报告模板。不指导倒签或先披露核心工艺。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是技术转让中介、技术服务或本约安排。
