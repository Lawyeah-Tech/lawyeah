# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、申请号、期限；把已失效《合同法》及其解释、已失效《技术合同法》及其实施条例写入结论；保证必然授权或“包过”；把签字盖章写成已取得申请人地位；把专利权转让、技术秘密转让或实施许可文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查专利申请权转让合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、已失效审查指南时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `专利申请权转让合同`。定性理由、易混切开结果（专利权转让 / 申请专利的权利 / 技术秘密转让 / 专利实施许可 / 技术开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、共有、跨境与文本版本

主体表：签约名、受理通知书申请人、付款名、发票名、授权签字人、共有人。跨境表：受让人是否外国人、外国企业或其他组织；技术进出口手续是否写入。版本表：正文、受理通知书、法律状态检索、审查意见、聊天确认；冲突并列。

## 5. 标的、登记、对价与授权风险

申请号与未授权状态是否特定化；著录项目变更义务与登记生效是否拆开；价款节点是否挂钩手续合格通知书及授权/驳回；授权风险由谁承担；分案申请权；案卷与 Know-how 移交。缺口标 `G#`。不输出专利权年费维持或无效宣告整案口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。限制出口未经许可、侵害他人技术成果、非法垄断技术：不改成可履行。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“全民所有制上级审批”写成现行义务。

## 9. 谈判与签署提醒

谈判顺序：先红线（标的已是专利权或尚无申请号、签字即取得申请权、保证授权、共有未同意、禁止/限制出口未办手续），再必须改（登记义务期限、驳回价款、OA 披露、分案、变更前禁撤），最后可优化。签署提醒：授权、用印、日期、受理通知书与法律状态检索附件、著录项目变更委托书。不指导倒签或补假登记。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、效力保证或代办国家知识产权局变更整案。
