# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的报酬、人数、时限；把已失效《合同法》《技术合同法》及其实施条例写入结论；把劳动合同服务期或“保证修好”写成技术培训法定默认；把场地写成受托人法定负担；把“3 个工作日”写成法定期限；把服务、开发或劳动服务期文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术培训合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例、2004 年未修正解释、1990 年认定登记办法时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `技术培训合同`。定性理由、易混切开结果（服务 / 开发 / 劳动服务期 / 职业或文化培训 / 中介）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、指定学员、教员与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。学员名单与准入条件。教员资格与可否更换。特种作业许可。版本表：正文、教学大纲、学员名单、教员简历、场地设备清单、考核标准、报价；冲突并列。

## 5. 特定项目、场地、准入分轨、考核与归属

特定技术项目是否可识别；场地设施试验条件由谁提供；学员/教员准入与报酬分轨；通知改派程序；考核是否客观；差旅食宿；教材与新成果有无另约；实操安全。缺口标 `G#`。不输出服务质保应急、开发 858 风险或劳动合同服务期口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。850 条款不得写成可放行。人身损害、故意或重大过失财产损失不得免责。认定登记不是生效要件。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“新成果一律归委托人”或“3 个工作日依法通知”写成法定默认。

## 9. 谈判与签署提醒

谈判顺序：先红线（不是传授已有特定项目技术、空项目或通识课、劳动服务期结构、保证修好当培训、未批进出口传授），再必须改（指定学员与准入、教员资格、场地负担、通知改派、客观考核、差旅食宿、教材归属、实操安全），最后可优化。签署提醒：授权、用印、日期、大纲与学员/教员/场地/考核附件、首笔报酬到账是否作为开课条件。不指导倒签。认定登记如需办理，写成协助义务，不写成未登记不生效。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是技术服务、技术开发或劳动合同服务期安排。
