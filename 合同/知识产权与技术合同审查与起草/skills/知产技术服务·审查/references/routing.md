# 边界与路由

本技能只审查 **技术类合同 / 技术服务合同** 的待签、以现有技术知识解决特定技术问题的文本。中文展示名是「审查技术服务合同（技术类合同）」。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符 | 本套导航的类型切开步骤 |
| 可行性论证、技术预测、专题调查、分析评价，不承担把问题做掉 | `知产技术咨询·审查` |
| 商务管理咨询意见、战略或行业分析 | `或` |
| 尚待研究开发、成果订立时尚不存在 | `技术开发合同·审查` |
| 委托开发作为已独立成册的细分主文件 | `委托开发合同·审查` |
| 双方共同投资并分工参与研究开发 | `合作开发合同·审查` |
| 核心是交付可运行软件而非解决已特定化现场问题 | `软件委托开发合同·审查` |
| 落在委托合同目录、按委任事务/费用预付/任意解除起草的同名技术服务 | `委托合同货架按处理事务费用预付任意解除起草的同名《技术服务合同》→` |
| 委托合同目录下的技术咨询 | `委托合同目录下的技术咨询→` |
| 常规加工、修理、复制、测试、检验 | `按既有图纸加工定作实物→负触发` |
| 建设工程勘察、设计、施工、监理为主给付 | `或对应工程原子；` 或对应工程原子 |
| 指定学员的特定项目专业技术训练为主给付 | `技术培训合同·审查`（P1；专业版 `unavailable`） |
| 为与第三人订立技术合同做联系介绍 | `技术中介合同·审查`（P1；专业版 `unavailable`） |
| 用户指定狭义技术服务细分主文件 | `技术服务合同（狭义）·审查`（P1；专业版 `unavailable`） |
| 名为服务、实为劳务派遣 | `或劳动专项，不改写成可履行派遣。挂靠违法分包未批限制进出口仍要跨境交付：只出告知，不改写成可履行路径。` 或劳动专项；本任务只告知 |
| 无文本、本类型条件已谈妥、要出己方稿 | `知产技术服务·起草` |
| 已签未争、只问履约节点 | 本套导航的履约步骤 |
| 已成争的普通合同路径 | `或知产争议专项。` 或对应专项领域 |
| C 端大众快检 | 只分流，不回改 |

服务正文里夹带一小段咨询评估或背景许可：专章交接对应原子；解决特定技术问题的条款可继续审。用户坚持本技能把咨询、开发、委托侧同名、承揽或施工整案改完：`目标停止`。

专业版未收录的 P1 场景不会安装本原子。若用户拿 P1 文本来找专业版：输出 `unavailable`，提示，不得用邻类硬套。
