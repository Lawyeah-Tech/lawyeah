# 知产技术服务·审查

## 任务目标

在单一立场下，只审查 **技术类合同 / 技术服务合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「知产技术服务·审查」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、把咨询意见写成已解决问题、把尚待研发写成已可交付服务、把委托合同任意解除或费用预付写成技术服务默认法。

## 本类型硬闸

1. **解决特定技术问题（正像）**：正像是受托人**已经掌握**的技术知识、经验和信息，动手为委托人解决**已特定化**的专业技术问题。解释第 33 条列举：改进产品结构、改良工艺流程、提高产品质量、降低产品成本、节约资源能耗、保护资源环境、实现安全操作、提高经济效益和社会效益等。标的是解决问题的**行为和质量**，不是从无到有的新技术成果。问题未写到可检测指标：必须改，不得放行“提供技术服务”“负责相关技术事项”这类空给付。
2. **服务 ≠ 咨询 ≠ 开发 ≠ 委托侧同名**：只出可行性论证、技术预测、专题调查、分析评价、不保证把问题做掉 → `知产技术咨询·审查`；商务管理意见 → `或`。订立时尚不存在、当事人尚未掌握的技术方案要研究开发 → `技术开发合同·审查` / `委托开发合同·审查` / `合作开发合同·审查`。落在**委托合同**货架、按处理事务/费用预付/任意解除起草的同名《技术服务合同》 → `委托合同货架按处理事务费用预付任意解除起草的同名《技术服务合同》→`。标题“技术服务”但正文是常规加工修理测绘检验 → `按既有图纸加工定作实物→负触发`；勘察设计施工 → `或对应工程原子；`。
3. **保证工作质量，并传授知识**：第 883 条要求完成服务项目、解决技术问题、**保证工作质量**、传授解决该问题的知识。禁止放行“只到场、不保证修好/调通/达标”却仍按技术服务收全款。未写传授、未写指标对应的检测方法：必须改。这与咨询合同“报告符合约定即可、决策损失原则上自负”不是同一条债。
4. **费用默认受托人负担**：第 886 条，正常开展工作所需费用无约定或约定不明的，由**受托人**负担。禁止把第 921 条“委托人应当预付处理委托事务的费用”写成技术服务法定默认。备件、耗材、差旅、检测外协必须分列；要由委托人承担的，必须书面点名，不能靠“按委托合同惯例”。
5. **新成果默认归完成方**：第 885 条，受托人利用委托人资料和工作条件完成的新成果，无另行约定时属于**受托人**；委托人利用受托人工作成果完成的新成果属于**委托人**。禁止把“无约定一律归委托人/甲方”写成现行法。委托人要单独所有或共有，必须落书面约定。
6. **治标不治本 + 质保期 + 应急响应**：本类型高频争点是暂时压住故障、根因未改、同类问题复现。验收合格后须约定保证期（本类型谈判量级常见 **3–6 个月**，数字用 `【待填】`，不是法定期限）；保证期内同一技术问题复现，受托人免费返工或补救，委托人使用或保管不当除外。服务期内紧急故障须写远程/到场时限（本类型实务量级常见远程 **4–8 小时**、到场 **24 小时**，写入修改句时仍用 `【待填】` 或双方已谈数字）。禁止把这两档量级写成“法律规定必须 4 小时/必须 3 个月”。
7. **不包括承揽和建设工程；培训/中介另册**：第 878 条第 2 款明文排除承揽合同和建设工程合同。常规加工、定作、修理、复制、测试、检验走承揽；现场建筑安装施工走工程。核心给付是对指定学员做特定项目专业技术训练 → P1 `技术培训合同·审查`；为核心是促成与第三人订技术合同 → P1 `技术中介合同·审查`；用户只要狭义服务细分主文件 → P1 `技术服务合同（狭义）·审查`。专业版未装 P1 时输出 `unavailable`，不得用本原子硬套。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签技术服务正文，尚未签署，尚未成争，核心给付是以**现有**技术知识解决**已特定化**的技术问题，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 只出可行性、技术预测、专题调查、分析评价，不承担把问题做掉 → `知产技术咨询·审查`；
- 商务、管理、战略意见 → `或`；
- 尚待研究开发、成果尚不存在 → `技术开发合同·审查`；已独立成册的委托开发 / 合作开发 / 软件委托开发 → `委托开发合同·审查` / `合作开发合同·审查` / `软件委托开发合同·审查`；
- 落在委托合同目录、按委任事务或任意解除起草的同名技术服务 → `委托合同货架按处理事务费用预付任意解除起草的同名《技术服务合同》→`；委托合同目录下的技术咨询 → `委托合同目录下的技术咨询→`；
- 常规加工、修理、复制、测试、检验，几乎不运用专业技术解决解释第 33 条所列问题 → `按既有图纸加工定作实物→负触发`；
- 建设工程勘察、设计、施工、监理 → `或对应工程原子；` 或对应工程原子；
- 核心是指定学员的专业技术训练 → `技术培训合同·审查`（P1）；
- 核心是为与第三人订立技术合同做联系介绍 → `技术中介合同·审查`（P1）；
- 用户出示的主文件已标明“狭义技术服务”并要求按该细分审 → `技术服务合同（狭义）·审查`（P1）；
- 无文本、本类型条件已谈妥、要出己方稿 → `知产技术服务·起草`；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁 → `或知产争议专项。` 或对应专项。

名为技术服务、实为把人员交给对方考勤指挥的劳动派遣结构：只出告知，转 `或劳动专项，不改写成可履行派遣。挂靠违法分包未批限制进出口仍要跨境交付：只出告知，不改写成可履行路径。` 或劳动专项，不改写成可履行派遣。挂靠、违法分包、未批限制进出口仍要跨境交付：只出告知，不改写成可履行路径。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及附件/技术规范/验收清单版本；**要解决的特定技术问题**及可检测指标；是否保证工作质量并传授知识；费用与备件由谁负担；新成果有无另行约定；质保期与应急时限；驻场还是远程；现场安全；是否长期派人受对方指挥；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的报酬、指标、时限用 `【待填】`，不编造。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `知产技术服务·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有技术服务文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。咨询、开发、委托侧同名、承揽、工程、培训、中介负触发。

### 2. 主体、资质、派遣红旗与现场安全

签约名、履行名、付款名、发票名分列。特种设备、安评、检验检测等许可未提及则资质字段停止。长期派人接受对方考勤人事考核：派遣红旗。现场作业必须有安全责任和意外险安排。

### 3. 特定技术问题、工作质量与传授

问题、基线、目标值、检测方法一一对应。删除“不保证解决问题”却按服务收全款。补传授义务。

### 4. 工作条件与解释第 35 条通知

委托人提供资料、样品、场地。受托人发现不符须在合理期限通知，否则视为认可。委托人接到通知不补正，损失归委托人。

### 5. 新成果、使用与保密

885 分轨。委托人要所有权必须另约。工作成果的再修改、再授权写清。接触工艺和数据的保密与违约金必须改。

### 6. 费用、备件、验收、质保、应急

886 默认受托人负担正常费用。备件耗材单列。禁止拟制全面合格并放弃缺陷。质保期和应急时限必须落句。

### 7. 格式条款与强制规范

无核验引文则法律结论字段停止。人身损害、故意或重大过失财产损失不得免责。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把未特定化空给付或派遣结构改成可履行、坚持用第 921/933 条替换本类型费用与退出规则、把未批限制进出口改成先履行后补批。
- `字段停止`：法域、动态规则、特种行业许可、进出口目录、认定登记能否免税未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁咨询、开发、委托侧同名、承揽、工程。
