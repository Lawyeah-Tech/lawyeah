# 审查方法（锁定 技术类合同 / 计算机软件著作权许可合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型，禁止打开知产分发许可、知产自用许可或软件著作权转让双文件“对照一下”。

本文件是**技术类计算机软件著作权许可**的签前判断节点，不是栏目说明书，也不是知产分发出货清单或权属过户清单。禁止把 SKU／渠道出货、仅内部自用双轨或“许可人把软著全部过户”写成默认路径。

每个会改变放行、修改句或转出结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、必然不侵权、对方必然接受或唯一必得金额。

`search_law` 返回已失效《合同法》及其解释、《技术合同法》及其实施条例、1991 年《计算机软件保护条例》、1992 年《计算机软件著作权登记办法》、1985 年《技术引进合同管理条例》、2004 年未修正技术合同解释单行本时记为噪声，不得写入 `L#`。著作权法实施条例第二十四条仍引用“著作权法第二十四条”的，运行时对照 2020 年著作权法第二十六条，记条号错位。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准。

示范文本只参考结构。计算机软件许可／系统购买范本不证明本约是技术类许可，也不证明条款已被接受。

## 节点 1　类型识别与负触发

### 1.1 本类型正像

同时满足才继续：

- 父级是**技术类合同**，不是已锁定的知识产权相关合同分发／自用货架；
- 标的是**现有**计算机程序及其文档，订立时已存在，不是尚待开发的系统；
- 核心给付是许可人**保留软件著作权**，将被许可人在约定范围、方式、期限、地域内的**财产权利**授予对方，换取许可费；
- 采用书面形式（民法典第八百六十三条参照；软件保护条例第十八条、第十九条）。

标题写成“计算机软件著作权许可使用合同”“软件许可协议”“Software License”只是线索。名实不符按核心给付归类，标题冲突写入 `C#`。

法律路径：民法典第八百七十六条——计算机软件著作权的许可参照适用技术合同节；解释第一条将计算机软件列入技术成果。权利种类、未明确不得行使、专有／非专有，优先适用著作权法第二十六条、第二十九条和软件保护条例第十八条、第十九条。

### 1.2 必须切开（禁止两套知识）

| 信号 | 归入 | 本技能动作 |
| --- | --- | --- |
| 权属转移、登记权利人变更、一次买断全部财产权、许可人永久退出该软件 | 计算机软件著作权转让合同 | **负触发** → `计算机软件著作权转让合同·审查`（技术类）或 `软件著作权转让合同·审查`（知产）。不得当许可审，不得复制其过户／登记主路径 |
| 用户或引擎已锁定知识产权相关合同，核心是 OEM／渠道／预装／再分发／SKU 出货 | 软件许可合同（分发许可模式） | **负触发** → `软件许可合同（分发许可模式）·审查`。不得用本类型硬套出货清单 |
| 用户或引擎已锁定知识产权相关合同，仅内部安装、禁止再分发 | 软件许可合同（自用许可模式） | **负触发** → `软件许可合同（自用许可模式）·审查`。不得用本类型硬套席位自用清单 |

| 主文是未公开配方／工艺，软件只是载体 | 技术秘密使用许可 | **负触发** → `技术秘密使用许可合同·审查` |

转让误入是硬闸：一旦核心给付滑入买断过户，立即停笔转出。不得删掉“全部财产权转让／变更登记权利人”后继续当许可审。

知产父级误入是硬闸：货架已是「知识产权相关合同」且按分发／自用切开的，立即转出。技术类场景下的分销、SaaS、SDK、多分支授权，仍留本任务，用权利项＋安装限额＋876 参照规则审，不改加载知产双文件。

### 1.4 违法结构停笔

出现下列任一结构，只出告知，不改写成可履行文本：

- “未点名的权利视为已全部授予，包括修改、再许可和转让”；
- 明知侵权或职务／共有权属未闭合，仍要“改到能继续用”；
- “被许可人对软件的任何改进无偿、独占归许可人，被许可人不得使用，亦不得质疑软著有效性，不得从他源获得竞争软件”；
- 限制进出口或含加密／管制算法的软件“先向境外交付安装包或源码，许可证后补”；
- 倒签合同日期以改变纳税义务或进出口申报时点。

用户坚持“改到能签／先出境再补证／把买断当许可放行”：整体停止。合规改道（补点名权利项、改非独占交叉许可、补许可证后再交付）只点名并出修改句，不在本任务起草规避方案。

## 硬闸 A　技术合同节路径，切开知产父级许可

本闸改变能否留在本任务。

1. **父级必须是技术类合同**  
   本技能的货架路径是「技术类合同 / 计算机软件著作权许可合同」。用户材料、引擎定性或标题已锁定「知识产权相关合同」项下分发或自用许可：负触发对应原子。  
   技术类正像可以覆盖分销、SaaS、SDK／API、企业内部多分支——那是本类型适用场景，不是改加载 `软件许可合同（分发许可模式）·审查`／`软件许可合同（自用许可模式）·审查` 的理由。

2. **876 参照适用，不是另立知产双轨**  
   权利种类、未明确不得行使、专有／非专有走著作权法／软件保护条例。许可方式（独占／排他／普通）、不得限制竞争、非法垄断技术、后续改进、权利瑕疵，参照技术合同节及解释第十条、第二十五条、第二十八条。  
   **修改句**：`各方确认：本协议是计算机软件著作权许可使用合同，适用民法典合同编技术合同节（第八百七十六条参照适用），并受著作权法及计算机软件保护条例约束。软件著作权仍归许可人。本协议不是软件著作权转让，也不是知识产权相关合同项下的分发许可本约或自用许可本约。`

3. **最强反方**  
   相对方可主张：标题写“技术类许可”但附件是 OEM 出货清单或权属转让协议。签前按核心给付和货架锁定分流，不两套都审。

## 硬闸 B　许可使用 ≠ 转让（切开 `计算机软件著作权转让合同·审查`）

本闸改变能否留在本任务。

1. **权属有没有留下**  
   文本须能指出：许可人仍是软件著作权人；被许可人取得的是已点名权利项的使用权，不是全部财产权买断。  
   出现“甲方将软件著作权全部／财产权一并转让”“办理著作权人变更登记”“永久买断、一次付清后许可人退出”→ 负触发 `计算机软件著作权转让合同·审查` 或 `软件著作权转让合同·审查`。  
   **修改句（留在本任务时）**：`各方确认：本协议项下交易是许可人将其合法享有的、附件一列明的软件（名称【待填】、版本【待填】、登记号【待填】）之约定财产权利，按本协议许可被许可人使用。软件著作权仍归许可人。本协议不是计算机软件著作权转让。`

2. **交付源码 ≠ 转让**  
   交付源代码只解决二次开发或托管，不当然转移著作权。用户要源码托管或破产时释放：写成托管／停用保障，不写成过户。

3. **最强反方**  
   相对方可主张：永久独占＋源码交付＋许可人停用就是转让。签前按有无权利人变更和财产权让与句分流，不两套都审。

## 硬闸 C　权利项、许可方式、安装限额

1. **权利项必须点名**  
   软件保护条例第八条分列发表、署名、修改、复制、发行、出租、信息网络传播、翻译等。第十八条、著作权法第二十九条：未明确许可的权利，被许可人不得行使。空写“合法使用本软件”“全部授权”：必须改。修改权／二次开发权未点名不得交付源码作定制。  
   **修改句**：`许可人许可被许可人行使下列财产权利：【复制／运行／发行／出租／信息网络传播／修改，择一或并列】。未在本条点名的权利，被许可人不得行使，不得解释为默示授予。修改权仅在【交付源码且双方书面确认二次开发范围】时授予，且修改成果的著作权归属按第【待填】条约定，人身权仍归原权利人。`

2. **独占／排他／普通，对接专有／非专有**  
   解释第二十五条的三类许可，经第八百七十六条参照用于本类型。软件保护条例第十九条：专有许可须书面；未明确专有的，视为非专有。未约定许可方式：按普通／非专有处理，并必须改出明示。  
   **修改句**：`本许可为【独占／排他／普通】许可。独占：在约定范围和期限内，许可人不得自行以相同方式使用，亦不得再许可第三人。排他：仅许可人与被许可人可以使用，许可人不得再许可第三人。普通：许可人保留自行使用和再许可第三人的权利。未书面约定为独占或排他的，不得解释为专有许可。`

3. **范围、期限、安装限额**  
   解释第二十八条参照：范围含期限、地域、方式。期限不明则使用不受期限限制——对许可人极不利，必须改。安装限额落到服务器、终端、IP、CPU、席位或站点。关联公司不自动获得许可，除非点名。  
   **修改句**：`许可期限自【交付安装包或激活码且验收合格】起【待填】年，且不得超过该软件著作权剩余保护期。地域：【待填】。安装限额：【终端数／并发用户／CPU 核数／站点，待填】。被许可人超出限额的复制、部署或向关联公司提供，构成超范围使用。双方未书面续期的，不得以期限约定不明主张无限期使用。`

4. **分许可**  
   除合同另有约定外，被许可人再许可须取得著作权人许可。结构性缺陷常是漏写分许可。关联公司、分包商、最终用户是否需要分许可或 EULA，必须落句。

## 硬闸 D　交付物、开源、验收与停用保障

1. **交付物清单**  
   分列：目标程序（安装包、激活码、驱动）、是否交付源码、用户手册、API 文档、部署手册。只有“有关软件系统”：标缺口。签收安装包不等于验收。  
   **修改句**：`许可标的以附件一《软件与交付物清单》为准，列明软件名称、版本、登记号、校验值、交付介质和是否含源码。未列入附件一的模块、接口或后续大版本，不因本合同自动纳入许可范围。签收安装包或激活码不等于验收合格。`

2. **开源合规**  
   许可人应声明是否包含 GPL 等强传染协议及弱传染组件清单。未披露仍要被许可人二次开发并闭源发布：红线。本任务不鉴定某一开源许可证的终局解释。  
   **修改句**：`许可人声明：附件二是本软件使用的开源组件清单，列明许可证类型。许可人保证：除附件二列明者外，本软件不含要求被许可人衍生作品必须开源的条款。因未披露的传染性开源导致被许可人闭源产品必须开源或被索赔的，由许可人负责抗辩并承担最终责任。`

3. **SLA 与重大升级**  
   维护更新（缺陷修复、安全补丁）与重大升级（新主版本）必须切开。兼容性：约定支持的操作系统／中间件范围；范围外升级导致不能运行，不当然由许可人免费重写。  
   **修改句**：`许可费含【待填】个月内针对本版本的缺陷修复和安全补丁。主版本号变化的升级另行报价。许可人保证本软件在附件三列明的运行环境中达到约定指标；该环境发生供应商变更或大版本升级的，双方另行评估，不视为许可人当然违约。`

4. **停用保障**  
   知识稿建议：许可人破产或授权验证服务停运时，应提供永不过期离线补丁。必须改出，不得只写“按法律规定处理”。  
   **修改句**：`因许可人原因（含破产、停业、授权验证服务连续【待填】日不可用）导致被许可人无法验证许可的，许可人应在【待填】日内提供不依赖在线验证的离线授权文件。该文件仅维持本协议已付费范围内的使用，不扩大权利项，也不构成权属转让。`

5. **退场**  
   终止后【待填】日内卸载、销毁副本（含备份），并出具销毁说明。已合法取得的备份复制品按软件保护条例第十六条处理，丧失合法复制品所有权时应销毁备份。

## 硬闸 E　权利瑕疵、850、登记幻觉与进出口

1. **权利瑕疵与维权**  
   许可人保证自己是著作权人或有再许可权，软件具有独创性，不侵犯第三人著作权或专利权。被许可人按约使用被诉侵权：许可人主导抗辩并承担最终责任，另有书面约定除外（参照第八百七十四条）。职务作品、合作开发、在先专有许可未闭合：签署能力字段停止。  
   **修改句**：`许可人保证：其是附件一软件的著作权人或已取得书面再许可权；该软件不存在未向被许可人披露的质押、查封、在先独占许可或权属争议。第三方就本软件向被许可人主张侵权的，被许可人应在【待填】日内书面通知许可人；许可人应主导抗辩并承担终局赔偿。本条不构成对未披露开源风险的豁免。`

2. **第八百五十条＋解释第十条（876 参照）**  
   下列条款红线删除：限制继续研发或使用改进；改进成果无偿独占归许可人；禁止从他源获得竞争软件；不合理限制产量、价格、渠道；搭售非必需模块；禁止质疑软著或专利有效性。  
   **修改句**：`删除禁止被许可人自行或从第三人获得竞争软件、禁止质疑附件一软件知识产权有效性的条款。一方在本软件基础上后续改进的，改进成果归完成方。对方享有普通、有偿或互惠的非独占实施许可，条件另行书面约定；任何一方不得约定改进成果无偿独占归对方所有。`

3. **登记与备案**  
   - 软件保护条例第七条：登记证明是登记事项的初步证明，不是著作权产生或许可生效要件。  
   - 2002 年登记办法第三条：办法适用于软件著作权登记、专有许可合同和转让合同登记。著作权法实施条例第二十五条：专有许可使用合同、转让合同可以向著作权行政管理部门备案。  
   - 不得写成未登记则合同未生效，也不得用 1992 年失效办法写成“未备案不能对抗第三者侵权”。独占许可：建议登记以便举证和防止重复专有授权，写成双方义务期限。  
   - 本类型不是专利实施许可，不适用《专利实施许可合同备案办法》。  
   **修改句**：`本合同自双方法定代表人或授权代表签字并加盖公章之日起成立并生效。国内计算机软件著作权许可不以软件登记或专有许可合同登记为生效条件。双方可在签署后【待填】日内共同向中国版权保护中心申请专有许可合同登记；未获登记不影响本合同在当事人之间的效力。许可人应在签署前提供软件登记证书复印件（如已登记）并说明有无质押或在先独占许可。`

4. **向外国人许可**  
   软件保护条例第二十二条：中国公民、法人或其他组织向外国人许可或转让软件著作权的，应当遵守技术进出口管理条例。限制进口：许可证管理，合同自进口许可证颁发之日起生效（条例第十六条）。限制出口：应先申请，取得许可意向书后方可实质性谈判（第三十一条、第三十三条）；自由出口合同成立即生效，不以登记为生效条件（第三十六条）。未批准：境外交付字段停止。  
   **修改句**：`若被许可人或交付目的地在中华人民共和国境外，或标的属于限制进出口技术，本合同自主管部门颁发相应许可证之日起就该跨境部分生效；在此之前任何一方不得向境外交付安装包、源码或密钥。自由进出口技术的合同登记不是国内主体之间许可条款的生效条件。`

## 节点 2　主体、授权、职务作品与共有

1. 建主体表：许可人、被许可人、付款名、发票名、授权签字人、共有人、转许可权来源。名称不一致不自动合并。
2. 许可人须是著作权人或经书面授权且有再许可权的人。口头“我们老板同意了”不得写成已授权。
3. 合作开发、职务作品、委托开发未约定权属：签署能力字段停止，列出待补的登记证书、开发合同或共有人同意。
4. 国资／上市公司内部决议未附：字段停止。
5. 被许可人经营性网站、SaaS 对外提供：点名是否具备所需电信／ICP 等资质，但不在本任务做行政许可整案。
6. 不足：列出待补材料，不补主体。

## 节点 3　标的、权利负担、交付标准

1. 标的确定到名称、版本、登记号、交付物清单，见硬闸 D。
2. 权利负担：质押、查封、在先独占或排他许可。材料未提及不得写成“无权利负担”，只能写 `依据不足`。
3. 保护期：自然人终生及死后 50 年；法人作品首次发表后 50 年（软件保护条例第十四条）。许可期限不得超过剩余保护期。
4. 交付与验收分列。付款、上线、使用不当然等于验收。
5. 不得在修改句中复述用户未要求写入的源码或密钥。

## 节点 4　程序与生效

把专有许可登记、进出口许可证、内部决议写成**义务和期限**，不写成已经完成。

| 文本写法 | 本任务动作 |
| --- | --- |
| “本合同签字即生效，源码当场交清，开源清单以后再补” | 红线；改为开源清单与权利项先闭环 |
| “须办理专利实施许可备案后生效” | 删除；本类型不是专利许可 |
| “未办软著许可登记则合同无效／不能对抗任何第三人” | 改为不影响当事人之间效力；登记是初步证明 |
| “限制出口软件先交付境外，许可证后补” | 整体停止或境外交付字段停止 |
| 用户要求倒签 | 整体停止 |

不得把“双方同意视为已批准／已取得共有人同意”写成可放行结构。

## 节点 5　对价、审计、自动续费与退出

1. 许可费与维保费分列；按 CPU／用户／站点／调用量计费的，基数可审计。许可人可按约定检查安装记录。未给数字用 `【待填】`。
2. 支付与交付、验收挂钩：预付款 → 交付安装包／激活码 → 验收后尾款。
3. 自动续费：必须写续期通知期、费用调整方式和退出路径。未约定到期处理：必须改。
4. 退出：约定解除条件、通知、卸载销毁、已付费用结算。禁止只写“双方协商解除”。
5. 禁止编造单价、席位或流量单价。

## 节点 6　格式条款与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

重复使用的许可模板仍可能构成格式条款。审查单方解约、自动续费、不得调整的高额违约金、禁止质疑有效性、管辖、最终解释权是否有显著提示。

违反法律、行政法规强制性规定不一律无效。850 针对非法垄断技术和侵害他人技术成果。进出口许可证主要约束**履行和跨境交付**。禁止用已失效“效力性／管理性”口诀。

## 节点 7　违约、反向工程、数据与争议解决

1. 超范围复制、擅自增加终端、擅自反编译、擅自转许可、逾期交付补丁、验证服务中断，必须分别有可执行后果。避免“不得调整”或“按总价三十倍必得”。
2. 反向工程：通常可禁止反汇编、反编译、解码和去除权利标识。软件保护条例第十六条允许合法复制品所有人为实际应用环境或改进功能作必要修改，但除合同另有约定外不得向第三人提供修改后的软件。修改句保留兼容所必需的例外，并禁止把例外扩成再分发。
3. 数据采集：软件具备采集功能的，点名数据归属、处理目的和《个人信息保护法》合规义务，不在本任务出具 PIPL 整案意见。
4. 争议解决：已有仲裁条款，不得改成“应向某法院起诉”并假装已选定诉讼；或裁或诉、机构不明：改成单一机构或单一法院连结点。
5. 微信已读不写成已经送达，除非合同把该渠道定为送达。

## 节点 8　按框架六步出修改句

本节点是成果闸。没有修改句或红线，不得宣称审查完成。禁止只打红黄绿。

对照已加载框架级文件和本方法硬闸，按六步逐段出句。框架中的知产出货清单、转让过户清单：仅在文本确实出现时用于转出或删除，不得写成默认主路径。

| 步 | 本类型必须盯的点 | 必须产出 |
| --- | --- | --- |
| 首部 | 标题名实（许可使用，避免写成转让）；许可人／被许可人；鉴于写明名称、版本、登记号、权属仍归许可人 | 主体与鉴于修改句 |
| 交易条款 | 点名权利项；独占／排他／普通；地域期限；安装限额；交付物；许可费＋维保＋审计 | 闭环修改句；缺数字用 `【待填】` |
| 配套 | 开源声明；权利瑕疵与应诉；SLA／重大升级；反向工程；超范围／反编译分别后果；停用保障；退场卸载 | 可执行后果句 |
| 尾部 | 授权签字；附件：交付物清单、开源清单、运行环境、维保、共有人同意、许可证 | 生效与附件修改句 |
| 语言 | 正说加反说；许可 ≠ 转让；未明确 ≠ 全授；登记 ≠ 生效；技术类 ≠ 知产分发／自用双轨 | 替换空词的句子 |
| 常见问题 | 漏写分许可／关联公司；自动续费；未批出境；买断误入 | 结构级改法或红线 |

每条修改句固定格式：

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（买断当许可、未明确权利全授、未披露传染性开源仍二次开发、850 回授／禁质疑、未批出境）；
- `必须改`：可谈但签署前要落句（权利项、许可方式、安装限额、交付物、SLA、退场、停用保障、登记非生效）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级许可费或个人无限连带且用户拒绝升级：停止“可以签署”建议。
