# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、印数、期限；把已失效《合同法》、1990 年著作权法、1991 年实施条例写入结论；保证未约定专有也能对抗善意第三人；保证未备案则合同未成立或备案后必然对抗后手；把转让、软件许可、委托创作或合作创作文本当成已完成的本类型审查；在意见中复述未发表作品全文或完整母带。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查著作权许可使用合同（知识产权相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1990 年著作权法或 1991 年实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `知识产权相关合同`，子级 `著作权许可使用合同`。定性理由、易混切开结果（转让 / 软件许可 / 软件著作权转让 / 委托创作 / 合作创作 / 商标）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属、集管、在先负担与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。权属表：作者/继受/职务/视听制片者/集管组织、合作共有、出质、已向第三人专有许可的范围。版本表：正文、作品清单、权项表、登记证、集管函、聊天确认；冲突并列。意见只引用作品名称或清单编号，不摘录未发表全文。

## 5. 专有非专有、权项与给付闭环

专有、排他还是普通；未约定是否按非专有；第 10 条权项勾选；六要素是否闭环；再许可；价款与报数；样稿确认；期满下架。缺口标 `G#`。不输出转让权属变更口径，不输出未备案则未生效口径。

## 6. 格式条款、强制规范与备案

是否构成格式条款；提示说明痕迹。人身权买断、禁止出版传播作品不得写成可放行。强制规范不用失效口诀。备案只写成对抗或举证安排，不写成成立要件。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。原文摘录不得含未发表作品全文。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把未约定专有写成独家，不得把许可直接改成转让而不问是否权属变更。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为转让、未约定却按独家对抗、权项黑洞、人身权买断、集管冲突、禁止出版传播作品），再必须改（专有三选一、六要素、第 29 条反说、下架 SOP、权属与在先披露），最后可优化。签署提醒：授权、用印、日期、作品与权项清单、合作作品全体财产权人、专有书面、备案草本。不指导倒签或先使用后补专有书面。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是转让、软件许可、委托创作或合作创作安排。
