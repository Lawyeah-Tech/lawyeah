# 审查方法（锁定 技术类合同 / 委托开发合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止复制技术开发总册 method、委托合同任意解除/转委托主路径、承揽按图必然交付或施工挂靠节点。

定性校验：标题、核心给付与本类型一致才继续；共同攻关、未细分总册、委托父级、纯软件、转让、承揽、咨询或服务明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、保证研发成功、对方必然接受或唯一必得经费。

`search_law` 返回已失效《合同法》技术开发章、《技术合同法》及其实施条例、1990 年《技术合同认定登记管理办法》、1995 年科技纠纷意见时记为噪声，不得写入 `L#`。第 854、855 条若未返回独立全文，该条号法律结论字段停止，不凭记忆同时写成“研究开发人违约”和“分工参与”。

示范文本只参考结构。科学技术部《技术开发（委托）合同》不证明本约条款已被接受。软件开发或事务委托范本只证明是另一类型。

知识库纠正（不回写双文件）：

- `框架.md` “优先受偿权”：第 859 条是同等条件优先**受让**，不是优先受偿。
- `框架.md` “失败全额退款可能被认定为工程或劳务合同”：只作审查警告。本任务不自动改定性，也不把全额退款写成可放行保底。
- `框架.md` “技术秘密通常由双方共享或依贡献度分配”：无约定时按第 861 条和解释第 20 条，双方可自己使用和普通许可；转让或独占/排他须对方同意；交付前研究开发人不得转让第三人。
- `框架.md` “自首笔经费到账之日起生效”：约定生效条件，不是法定。
- `基本面.md` “须办理技术合同认定登记方可加计扣除”：登记不是民事合同生效要件；现行认定登记办法本次未核全文，税务结论字段停止。

## 节点 1　类型识别与单目录加载

### 1.1 定性

用标题、核心给付、对价方式和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

必须切开后再加载，禁止两可时灌入两套知识：

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 一方出经费、设备、材料或只做辅助协作，另一方独立完成尚不存在的技术方案 | 本类型 | 正触发 |
| 双方按计划共同或分别承担设计、工艺、试验、试制 | 合作开发 | 负触发 `合作开发合同·审查` |
| 标题《技术开发合同》，委托/合作尚未独立成册 | 技术开发总册 | 负触发 `技术开发合同·审查` |
| 用户锁定委托合同父级，或正文主轴是处理事务、随时解除、转委托 | 委托合同目录下的委托技术开发 | 负触发 `委托合同目录下的委托技术开发主文件且用户未锁定本类型→` |
| 主给付是可运行软件，几乎无研发不确定性 | 软件委托开发 | 负触发 `软件委托开发合同·审查` |
| 标的是已有专利、申请或技术秘密的让与/许可 | 转让或许可 | 负触发 `技术转让合同·审查` / `技术许可合同·审查` / `专利实施许可合同·审查` |
| 按既有图纸常规加工、验证、测试 | 承揽 | 负触发 `按既有图纸加工定作实物→负触发` |
| 只出意见，不研发 | 技术咨询或商务咨询 | 负触发 `知产技术咨询·审查` / `或` |
| 用现有技术解决特定问题，不产出新方案 | 技术服务 | 负触发 `知产技术服务·审查` |

支持切开的规范（法律结论须运行时复核）：

- 解释第 19 条第 2 款：一方仅提供资金、设备、材料等物质条件或者承担辅助协作事项，另一方进行研究开发工作的，属于委托开发合同。
- 第 859 条只规范委托开发完成的发明创造；第 860 条共有规则只规范合作开发。
- 第 862 条：转让/许可针对**现有**特定技术。
- 解释第 17 条：无创新的改型、工艺变更、配方调整、验证测试不是“三新”。

### 1.2 加载协议（硬闸）

本技能已锁定 **技术类合同 / 委托开发合同**。只打开 `references/基本面.md` 与 `references/框架.md`。禁止读其他子目录，禁止为对照再开第二类。

### 1.3 一方出资、研究开发人独立完成（硬闸）

| 文本写法 | 本任务动作 | 修改句方向 |
| --- | --- | --- |
| 甲方支付经费并提供样本/数据，乙方独立制定和实施研究开发计划 | 正触发，留下本类型 | 首部写明“技术委托开发，不适用合作开发共有规则” |
| 双方各派课题组，共同实验，成果共有 | 负触发合作开发 | 不按 859 改成归一方 |
| 标题《技术开发合同》，正文未锁定一方出资 | 负触发总册 | 不填本类型十节实体结论 |
| 授权乙方以甲方名义对外缔约，并约定甲方可随时解除 | 负触发委托父级 | 不用第 933、923 条当默认 |

最强反方：相对方主张委托人已派驻工程师即构成合作开发，应适用第 860 条共有。修改句必须写清：派驻人员仅限技术交底、取样和进度监督，不承担设计、工艺、试验、试制分工。用户坚持保留共同攻关主轴：负触发，不填本类型十节实体结论。

### 1.4 现有技术冒充开发 / 重复收取停笔（硬闸）

加载后或定性中出现：把已公开或已完成的技术成果当作研究开发标的收取经费；就同一课题向两个以上委托人重复收取研究开发费用；通谋以“开发”包装转移资金或骗取加计扣除。

动作：

1. 交付告知：解释第 9 条，受损害方可请求撤销；解释第 17 条排除无创新验证测试。不得改写成可履行假开发。
2. 不写可履行的“补一份新指标就能继续收经费”、假登记或体外资金路径。
3. 风险表只保留识别依据和删除/转出口径。
4. 用户坚持“改到能签且仍做这些事”：整体停止。

## 节点 2　主体、资质与核心人员

### 2.1 主体表

建表：签约名、履行名、付款名、发票名、授权签字人。名称不一致不自动合并。课题组、工作室等不具有民事主体资格的科研组织：未经法人或非法人组织授权或认可，不得写成已可约束该单位。

口头“我们院长同意了”不得写成已授权。国资、上市公司、高校院所内部决议未附：该签署能力字段停止。

### 2.2 资质与核心人员

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 新药、实验动物、特种设备、军工或出口管制课题，文本未提许可 | 字段停止；修改句要求作为附件 | 可以开工 |

## 节点 3　课题、三新与背景知识产权

### 3.1 课题须可核验

审查清单，缺一项则该字段不得写成已闭环：

1. 课题名称、技术领域、拟解决的技术问题。
2. 可量化指标：不得只写“国际先进”“质量优良”。
3. 订立时是否尚未掌握。已是现有技术：回到节点 1.4。
4. 经费预算与进度表作为附件，与正文效力关系写清。

禁止只写“完成本项目研发工作”而无指标、方法和验收环境。

### 3.2 背景知识产权隔离

双方签约前已持有的专利、申请、技术秘密、数据、工具链列入附件清单。未列入的，不得写成对方可免费实施的前景成果。材料未提及第三方权利负担：只能写 `依据不足`，不得写成“无权利负担”。

修改句：

「附件【待填】列明双方在本合同生效前已拥有的背景知识产权。背景知识产权不因本合同发生权属转移。乙方为完成本课题使用自有或第三方背景技术的，应保证有权使用，并保证甲方按本合同实施前景成果时无需另行向第三人付费；否则乙方应负责排除妨碍并赔偿甲方因此发生的直接损失。前景成果仅指履行本合同新完成的技术方案、实验数据、工艺包和文档。」

## 节点 4　第859条归属与第861条技术秘密（硬闸）

支持依据：第 859 条；专利法第八条；第 861 条；解释第 20 条。

| 文本写法 | 动作 |
| --- | --- |
| “因甲方出资，专利申请权及专利权当然归甲方，乙方不得实施” | 必须改。现有依据不支持把出资写成法定默认归属。买断须明示，并保留或放弃 859 的免费实施与优先受让 |
| 权属空白，意见写成“依法归委托人”或“依法共有” | 红线纠正：无约定则申请权属于研究开发人；共有是第 860 条合作开发规则 |
| 只写“知识产权归甲方”不区分专利、技术秘密、软件著作权、后续改进 | 必须改：分项落句 |
| 技术秘密未约定，却允许乙方交付前对外转让或独占许可 | 必须改。第 861 条禁止交付前转让第三人；解释第 20 条：独占/排他/转让须对方同意 |
| 框架用语“优先受偿权” | 改为优先受让 |

委托人要买断的修改句：

「委托开发完成的发明创造，专利申请权及此后取得的专利权归甲方。乙方应在甲方提出书面要求后【待填】日内配合办理申请、转让或著录项目变更，费用由【待填】承担。甲方取得专利权的，乙方在本课题范围内享有【非独占/不可转让/待填】实施权，范围以附件任务书为限。未办理权属变更前，乙方不得向第三人转让该申请权。」

保留法定默认的修改句：

「委托开发完成的发明创造，申请专利的权利属于乙方。乙方取得专利权的，甲方可以依法实施该专利，该实施权不得单独转让。乙方转让专利申请权的，甲方在同等条件下有权优先受让，乙方应在拟转让条件确定后【待填】日内书面通知甲方。」

技术秘密修改句：

「不申请专利的技术秘密成果，使用权、转让权和收益分配按附件【待填】执行。没有该附件的，在相同技术方案被授予专利权前，双方均可自己使用，并以普通使用许可方式许可他人使用并各自取得收益；任何一方将转让权让与他人，或以独占或排他许可方式许可他人使用的，须事先取得对方书面同意。乙方在向甲方交付研究开发成果之前，不得将研究开发成果转让给第三人。」

最强反方：委托人主张“我出钱所以当然是权利人”。现有依据不支持该默认。后续改进：可约定谁改进谁享有，但不得限制任何一方在标的技术基础上继续研究（节点 6.2）。

支持依据：第 852、853 条。

| 文本写法 | 动作 |
| --- | --- |
| 经费与报酬混写，结余归属空白 | 必须改：分列人员费、设备费、材料费、测试费；写明包干或据实 |

| 数字空白 | 用 `【待填】`，不编造 |

修改句：

「甲方应向乙方支付的研究开发经费与报酬分列。经费实行【包干制 / 据实结算制】：包干制项下超支由乙方自行承担，结余归乙方；据实结算项下乙方应按附件预算列支，结余在验收后【待填】日内返还甲方。支付节点：本合同生效后【待填】日内支付启动经费人民币【待填】元；完成附件进度表第【待填】阶段并签署《阶段性成果确认书》后【待填】日内支付人民币【待填】元；最终验收合格后【待填】日内支付人民币【待填】元。用经费购置且验收时仍可识别的设备、剩余材料归【待填】所有。」

定金：必须使用“定金”二字才讨论罚则。约定或推算超过主合同标的额百分之二十：超过部分不产生定金效力。无核验引文不得把 20% 写成现行法结论。

## 节点 6　技术风险、850垄断与格式条款

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 技术风险不是保底交付（硬闸）

支持依据：第 858 条。

| 文本写法 | 动作 |
| --- | --- |
| “任何原因失败，乙方全额退还已收经费并支付等额违约金” | 红线拆分：技术风险 vs 未尽义务的违约。技术风险下返还剩余经费，已发生的合理经费可不返还 |
| “乙方保证研发成功 / 保证获得专利 / 保证固定收益” | 红线删除保证。可改成未达指标的减酬、限期补救或解除 |
| 无风险定义、无通知、无第三方判定 | 必须改 |

修改句：

「因现有技术条件下无法克服的技术困难，致使研究开发失败或者部分失败的，构成技术风险。一方发现可能构成技术风险的情形，应在【待填】日内书面通知对方，并采取合理减损措施；未及时通知或未采取适当措施致使损失扩大的，就扩大部分承担责任。是否构成技术风险，由双方共同委托的【待填】机构或专家组书面确认。构成技术风险的，乙方应返还尚未使用的经费，已发生且有凭证的合理经费不予返还，乙方不按违约承担责任。乙方未按约定制定或实施研究开发计划、挪用经费、隐瞒订立时已可合理预知的不可行性，或未尽本专业通常努力的，不得主张技术风险，应按违约承担返还、减酬或赔偿直接损失的责任。」

最强反方：委托人主张“我付了钱就应拿到成果”。技术开发标的具有不确定性，现有依据不支持把失败一律写成违约，除非合同把保底写成给付内容——而保底本身会削弱 858 保护，必须向研究开发人侧提示。

### 6.2 非法垄断技术（硬闸）

支持依据：第 850 条；解释第 10 条。

限制一方在标的技术基础上继续研究，或限制使用改进技术；不对等回授、无偿独占改进成果；限制从其他来源获得竞争技术；禁止质疑知识产权：必须删除。不得改成“独家委托所以禁止甲方自己或委托第三人继续研发”的可放行结构。

修改句：

「任何一方有权在本合同标的技术基础上自行研究开发并使用所改进的技术。一方完成的后续改进，知识产权归完成方；对方可在【待填】日内要求以公平合理条件获得普通许可。删除任何禁止对方从其他来源获得类似或竞争技术、禁止对相关知识产权有效性提出异议的条款。」

用户坚持保留禁研或无偿独占回授：整体停止。

### 6.3 格式条款

为重复使用而预先拟定、订立时未与对方协商。依据示范文本制作，不当然排除格式条款。审查：权属买断、风险负担、免责、管辖/仲裁等是否有足以引起注意的标识（第 496 条）。小字、夹在附件、仅网络勾选：不得写成已尽提示。提供方对提示说明承担举证责任。

强制规范按第 153 条和通则解释第 16 条区分，不用失效“效力性/管理性”口诀。认定登记、科技计划立项多为行政管理或税务程序，不得单独写成民事合同当然无效。假开发、未批限制进出口、通谋虚假经费：不改写成有效履行。

## 节点 7　交付资料、验收、转第三人与违约

### 7.1 资料交付与验收（硬闸）

支持依据：第 853 条。

交付包括：约定载体上的成果、足以使委托人掌握该技术的技术资料，以及必要技术指导。样品、安装包或可执行程序单独交付，现有依据不支持写成已帮助委托人掌握成果。

| 文本写法 | 动作 |
| --- | --- |
| 只交样品/安装包，不交工艺包、实验记录、图纸或源代码 | 必须改 |
| “甲方逾期不验收视为全面合格且放弃一切技术缺陷” | 红线删除放弃；可约定催告后就已交付部分出具书面意见 |
| 签收、付款或试用即视为验收 | 必须改：交付与验收分列 |
| 无验收环境、样件、方法和合格阈值 | 必须改，数字用 `【待填】` |

修改句：

「乙方应向甲方交付：①符合附件任务书指标的研究开发成果；②完整技术资料，包括实验记录、设计图纸、工艺说明、测试报告、操作与维护手册，以及为掌握和实施该成果所必需的数据与【源代码/配方/待填】；③自交付之日起【待填】日内的必要技术指导。甲方签收资料或支付阶段款，不视为验收合格。验收按附件测试大纲在【待填】环境、使用【待填】样件进行；未达指标的，乙方应在【待填】日内补正一次；仍未达指标且不构成技术风险的，甲方可减付尚未支付的报酬或解除合同并要求返还与未完成部分对应的经费。」

阶段节点应签署《阶段性成果确认书》，避免一揽子终验。

### 7.2 主要研发不得擅自交第三人（硬闸）

第 853 条要求研究开发人按约定实施计划并交付成果。现行技术开发章未单列“主要部分交第三人”专条；失效实施条例的“逾期两个月”不得写入 `L#`。修改句仍应锁亲自完成或书面同意。

「未经甲方事先书面同意，乙方不得将本课题的主要研究开发工作交由第三人完成。辅助性测试、检测或加工可转交第三人，乙方仍就全部成果向甲方负责。擅自将主要工作交第三人的，甲方有权要求限期收回、减付报酬或解除合同，并要求赔偿因此发生的直接损失。」

不得引用第 933 条任意解除或第 923 条转委托作为本类型默认清理路径。辅助工作可转，不等于核心课题可转。

### 7.3 违约、解除与争议

1. 委托人逾期提供资料或经费、研究开发人逾期实施计划或交付资料：分别约定减酬、解除和直接损失。只有“依法承担违约责任”视为必须改。
2. 构成违约不等于当然解除。法定解除只点名催告或目的不能实现，不在本任务作出已解除结论。
3. 违约金不是必得金额。修改句避免“不得调整”或“按总经费必得”。
4. 争议解决：出现仲裁条款，不得改写成“应向某法院起诉”。或裁或诉、机构不明：改成单一仲裁机构或单一法院连结点。专属管辖可能：只标红旗。
5. 通知送达：微信已读不写成已经到达，除非合同把该渠道写成送达且用户要保留。
