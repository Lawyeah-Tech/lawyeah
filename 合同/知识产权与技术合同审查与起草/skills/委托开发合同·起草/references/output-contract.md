# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、研发成功或必然拿到专利；编造未给出的经费、指标、期限；把已失效《合同法》技术开发章或《技术合同法》写入结论；把无约定写成归委托人或当然共有；把失败全额退款写成可放行保底；把口头协作写成已构成合作开发或已尽指导义务；把未核认定登记写成可以加计扣除；把合作开发、技术开发总册或委托父级当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查委托开发合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》技术开发章、《技术合同法》及其实施条例、1990 年认定登记办法时，记噪声，不得写入 `L#`。第 854、855 条未核独立全文时，该条号不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `委托开发合同`。定性理由、易混切开结果（技术开发总册、合作开发、委托父级委托技术开发、软件委托开发、转让/许可、承揽、咨询、服务）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、授权、资质与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、核心研究人员岗位。资格表：特殊行业许可痕迹、职务成果可处分保证。版本表：正文、技术任务书、经费预算、进度表、背景 IP 清单、聊天确认；冲突并列。许可或内部决议未核：该签署能力字段停止。

## 5. 给付闭环

是否一方出资、研究开发人独立完成；课题是否订立时尚未掌握；可量化指标；859/861 分项或默认；经费与报酬、包干或据实、里程碑；资料交付范围；验收与阶段确认书。缺口标 `G#`。不输出合作开发共有表决、委托任意解除或承揽按图必然交付的主路径。认定登记写成税务或科技管理程序，不写成已经完成或合同生效条件。

## 6. 技术风险、垄断条款与强制规范

858 风险定义、通知、第三方判定、剩余经费；是否夹带保证成功或失败全额退款。850 与解释第 10 条禁研、回授、限制竞争技术来源。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分。假开发、未批进出口只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“优先受偿”写成条文；不得把“首笔到账生效”写成法定。

## 9. 谈判与签署提醒

谈判顺序：先红线（共同攻关错位、出钱即归委托人、保证成功或失败全额退款、假开发、850 禁研），再必须改（859/861 分项、资料交付、量化验收、转第三人、风险通知），最后可优化。签署提醒：法定代表人或授权人与项目负责人签字；任务书、预算、进度表、背景 IP 清单入附件并骑缝或校验码；认定登记如需办理，写成签署后的税务程序，不指导补假登记。不指导倒签。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、权属诉讼策略或效力保证，也不是技术开发总册、合作开发或委托父级审查。
