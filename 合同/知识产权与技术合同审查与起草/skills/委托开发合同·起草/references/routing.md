# 边界与路由

本技能只审查 **技术类合同 / 委托开发合同** 的待签文本。中文展示名是「审查委托开发合同（技术类合同）」。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符 | 本套导航的类型切开步骤 |
| 标题或主文件是未细分的《技术开发合同》，委托/合作尚未独立成册 | `技术开发合同·审查`。不得用本技能十节硬套总册 |
| 双方按计划分工承担设计、工艺、试验、试制，或设立联合课题组共同攻关 | `合作开发合同·审查`。不得按第 859 条改成归一方 |
| 用户或材料按委托合同父级进入，主路径是处理事务、任意解除或转委托 | `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`。不得把第 933、923 条当本类型默认 |
| 主轴是可运行软件交付、几乎无研发不确定性 | `软件委托开发合同·审查` |
| 已有成熟技术转让 | `技术转让合同·审查` |
| 已有技术许可 | `技术许可合同·审查` |
| 专利实施许可 | `专利实施许可合同·审查` |
| 按既有图纸常规加工、验证、测试，成果必然可复制 | `按既有图纸加工定作实物→负触发` |
| 仅出具可行性、FTO 或评价意见 | `知产技术咨询·审查` 或 `或` |
| 只解决特定技术问题、不产出新方案 | `知产技术服务·审查` |
| 已有科技成果实施转化 | `技术转化合同·审查`。P1：专业版未装则 `unavailable`，提示，不得用本技能硬套 |
| 已有可读待签文本要评改 | `委托开发合同·审查` |
| 无文本、本类型条件已谈妥、要出己方稿 | 本任务起草并自审 |
| 已签未争、只问履约节点 | 本套导航的履约步骤 |
| 已成争，或用户要权属诉讼策略 | `或知产争议专项。` 或对应专项领域 |
| C 端大众快检 | 只分流，不回改 |

委托开发正文里夹带一小段软件交付或后续维保：专条可交接 `软件委托开发合同·审查` 或服务原子；一方出资、859 归属、858 风险、资料交付条款可继续审。用户坚持本技能把合作开发、技术开发总册或委托父级整案改完：`目标停止`。
