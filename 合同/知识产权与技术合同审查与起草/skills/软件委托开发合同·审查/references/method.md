# 审查方法（锁定 技术类合同 / 软件委托开发合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止复制技术开发研发失败分摊主路径，禁止复制委托开发专利申请权默认主路径，禁止复制承揽按图必然交付主路径。

定性校验：标题、核心给付与本类型一致才继续；研发不确定性、一般技术委托开发、承揽实物、现成软件许可/转让明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受、著作权必然已归委托方，或唯一必得违约金。

`search_law` 返回已失效《合同法》技术合同章及其解释、《技术合同法》及其实施条例、2004 年技术合同解释未修正文本时记为噪声，不得写入 `L#`。计算机软件开发争议的现行接口是 **技术合同解释（2020 修正）第 46 条**：著作权法及其他法律、行政法规另有规定的，依照其规定；没有规定的，适用民法典合同编通则，并可参照技术合同章和该解释。著作权默认规则以 **计算机软件保护条例第 11 条** 和 **著作权法第 19 条** 为准，不以第 859 条专利申请权默认替代。

示范文本只参考结构。民法典第 470 条允许参照示范文本，不证明本约条款已被接受。

知识库纠正（不回写双文件）：

- `基本面.md` 写“复合型技术开发合同”：本类型争点优先走著作权法/软件条例；不得因此套用第 858 条研发失败合理分担作为默认主路径。
- `基本面.md` 写“智力成果承揽属性”：只说明要交付工作成果，**不是**把本约改成加工/定作承揽，也不得抄承揽“按图必然交付实物”。
- `框架.md` “3-3-3-1”“变更超过初始需求 10%”“质保 12 个月”“试运行 1–3 个月”：商事习惯，不是法定期限。缺数字用 `【待填】`。
- `框架.md` “竞业限制”：本类型只约束开发方在约定期限内不得为直接竞争对手开发功能实质相同的定制软件；不得写成劳动合同竞业限制或无限期禁业。
- `基本面.md` 无约定著作权归开发人：与软件条例第 11 条一致，必须守住。

## 节点 1　类型识别与单目录加载

### 1.1 定性

用标题、核心给付、对价方式和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。标题写“技术开发”的，先看交付物：可运行软件+源码、功能可描述、商业上期待上线，按本类型审并改标题；尚待攻关、不保证成果产生，负触发技术开发。

必须切开后再加载，禁止两可时灌入两套知识：

| 信号 | 归入 | 本任务动作 |

| 尚待研究开发新技术/新产品，不保证成果必然产生，约定研发失败风险分担 | 技术开发 | 负触发 `技术开发合同·审查` |

| 只出可行性/评价意见，不写代码 | 技术咨询/咨询服务 | 负触发 `知产技术咨询·审查` / `或` |

支持切开的规范（法律结论须运行时复核）：

- 技术合同解释（2020）第 46 条：计算机软件开发等合同争议，著作权法及其他法律、行政法规另有规定的，依照其规定。
- 计算机软件保护条例第 2、3 条：软件＝程序及其文档；源程序与目标程序为同一作品。
- 解释第 17 条：第 851 条“新技术……”包括订立时尚未掌握的技术方案，但无创新的改型、工艺变更、验证测试和使用除外。定制 OA/ERP/APP 功能可描述、期待上线的，现有依据不支持按“尚未掌握、失败可分摊”定性。
- 第 858 条：研发失败风险分担属于技术开发履行规则，**不是本类型默认主路径**。
- 第 770 条：承揽是按要求完成工作并交付工作成果，包括加工、定作、修理、复制、测试、检验。按图交付实物走承揽原子。
- 第 878 条：技术咨询出意见；技术服务解决特定技术问题，不包括承揽和建设工程。
- 解释第 19 条：一方只出资金设备、另一方研发，属于委托开发——用于切开合作开发，不把本类型改写成专利申请权主线。
- 解释第 22 条：尚待研究开发的技术成果不是技术转让/许可标的。
- 合同编通则解释第 15 条：不拘泥名称，按内容、结构和履行行为认定。

动作：

1. 交付告知：不得改写成可履行的黑盒控制或虚假价款。
2. 不写可履行的远程锁死、隐藏后门、假验收路径。
3. 风险表只保留识别依据和删除/转出口径。
4. 用户坚持“改到能签且仍做这些事”：整体停止。

## 节点 3　交付物与源码（硬闸）

支持依据：软件条例第 2、3 条；解释第 46 条。源程序与目标程序为同一作品。仅交目标程序、不交源码，现有依据支持认定为未完成核心交付，除非合同明确只需目标程序且对价与买断安排匹配。

| 文本写法 | 动作 |
| --- | --- |
| 交付“软件一套”，未列源码 | **必须改或红线**。补完整清单 |
| 只交安装包/APP，明确“不提供源码”，却约定著作权归甲方且付清全款 | **红线**。要么补源码交付，要么改为授权制并下调对价，不得两边通吃 |
| 有源码但无注释、无仓库、无提交记录 | 必须改：可读注释、指定 Git/SVN、与文档同步 |
| 大型核心系统无托管 | 可优化：第三方托管，开发方停业或拒维时可提取 |

修改句：

「乙方应向甲方交付：（1）可执行程序及安装包；（2）全部源代码（含必要注释、构建脚本和第三方依赖说明）；（3）数据库结构及初始化脚本；（4）需求规格、设计、接口与部署文档；（5）用户手册。源码应同步至甲方指定仓库。甲方支付本合同最高比例款项的前提是：前款第（2）项已交付，且甲方或其指定人员能够在附件环境中由源码复现构建。」

最强反方：开发方主张“行业惯例只交安装包”。现有依据不支持在买断或未明确放弃源码时把只交目标程序写成已完成核心交付。

## 节点 4　著作权与开源（硬闸）

支持依据：软件条例第 11 条；著作权法第 19 条；著作权民事解释第 12 条。无书面合同或约定不明，著作权归受托人。即使归受托人，委托人可在委托目的范围内免费使用——这不是买断，不得写成已经取得全部著作财产权。

| 文本写法 | 动作 |
| --- | --- |
| 未写归属，或写“依法归属” | **必须改**。不得写“已经归甲方” |
| “付清全款后，软件著作权归甲方，乙方配合登记；乙方基础库保留所有权并永久免费授权甲方” | 可接受买断制 |
| “著作权归乙方，甲方仅获本项目自用许可” | 可接受授权制；须写清期限、终端数、可否再许可 |
| 未列开源/第三方组件 | 必须改：附件清单+许可证+是否传染 |
| 允许使用 GPL 等强传染协议且甲方要闭源商用 | **红线**。删除或改为兼容许可 |

修改句（买断）：

「自甲方按约付清应付开发费用之日起，本项目定制代码、文档和数据库结构的著作权归甲方。乙方应在付清后【待填】日内配合甲方办理软件著作权登记。乙方对其既有基础库、工具类代码保留权利，并在此授予甲方不可撤销、免费、永久的使用许可，该许可以使甲方独立运行、维护和二次开发本软件为限。未在本合同及附件中书面约定归属的，不得推定著作权已转移。」

修改句（开源）：

「乙方应在附件《第三方组件与开源清单》中列明组件名称、版本、许可证和在本项目中的用途。未经甲方书面同意，乙方不得引入 GPL、AGPL 或其他具有强传染性、可能导致甲方闭源商业代码被迫公开的许可证组件。因未披露或违规引入导致甲方无法按约定闭源使用的，视为权利瑕疵，乙方应自费替换并赔偿因此发生的损失。」

最强反方：开发方主张法定默认归己故拒绝改；委托方主张付了钱就当然买断。现有依据支持默认归受托人，现有依据不支持把沉默写成已经买断。

## 节点 6　验收、格式条款与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 验收闭环（硬闸）

上线、付款、签收不当然等于验收。

| 文本写法 | 动作 |
| --- | --- |
| “上线即验收合格”或“使用满七日视为验收” | **必须改**。拆初验、试运行、终验 |
| 无量化性能（并发、响应、兼容） | 必须改：写入 SRS 或验收标准附件 |
| 未写 A/B 类缺陷清零 | 必须改：崩溃和功能缺陷未修复不得终验 |
| 甲方无期限拖延验收 | 开发方立场：补催告后合理期限；不得写成已经验收 |

修改句：

「验收分三步：乙方提交可运行版本并完成附件测试用例的，双方办理初验；初验通过后进入为期【待填】日的试运行；试运行期内未出现附件定义的 A 类（崩溃、数据丢失）或未修复的 B 类（核心功能不可用）缺陷的，办理终验。终验合格以双方签署《终验确认书》为准。上线、付款或签收安装包，不视为验收合格。性能指标以附件载明的并发量、响应时间和兼容范围为准。」

### 6.2 格式条款

为重复使用而预先拟定、订立时未与对方协商（第 496 条）。开发方制式文本、委托方制式采购文本均可构成。审查：免责限责、单方验收、最终解释权、自动续期维保、管辖是否有显著提示。仅电子勾选不足（解释第 10 条）。

第 497 条无效情形、第 498 条不利解释：只在核验后作为修改理由，不代替修改句。

### 6.3 强制规范与违约金

违反法律、行政法规强制性规定不一律无效（第 153 条；解释第 16 条）。禁止用已失效“效力性/管理性”口诀。逾期交付、质量不符、拒交源码须分别有可执行后果。只有“依法承担违约责任”视为必须改。违约金可增可减（第 585 条；解释第 64、65 条）；禁止“不得调整”或“按总价 30% 必得”。

## 节点 7　账号实名、维保与终止善后

1. **服务器、域名、云账号、应用商店**  
   必须以委托方名义实名注册；开发方仅获履行所需的有限权限。未见约定：必须改。

2. **质保与响应**  
   质保期数字用 `【待填】`。期内 BUG、环境迁移、漏洞补丁免费。紧急故障响应时限写入条款。质保金在维保期满且无未修复致命缺陷后支付。

3. **终止善后**  
   解除或终止后：交还账号、剩余源码和文档；删除委托方业务数据；保密继续。开发方拒交源码导致买断目的不能实现的，点名解除路径，不在本任务作出已解除结论。
