# 边界与路由

本技能只审查 **技术类合同 / 软件委托开发合同** 的待签文本。中文展示名是「审查软件委托开发合同（技术类合同）」。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符 | 本套导航的类型切开步骤 |
| 尚待研究开发、不保证成果必然产生、核心是研发失败风险分担 | `技术开发合同·审查`。不得把第 858 条失败分摊当本类型默认主路径继续审 |
| 一般新技术/新产品委托开发，交付物不是可运行软件+源码 | `委托开发合同·审查`。不得抄其专利申请权默认主路径 |
| 双方分工参与研发 | `合作开发合同·审查` |
| 委托合同目录下的委托技术开发主文件，用户未锁定本类型 | `委托合同目录下的委托技术开发主文件且用户未锁定本类型→` |
| 按图加工实物 | `按既有图纸加工定作实物→负触发` |
| 按图定作实物 | `按图定作实物` |
| 项目承揽、重劳务过程交付实物成果 | `项目承揽重劳务过程交付实物成果` |
| 对已有软件维护、升级、培训 | `知产技术服务·审查` |
| 仅出具可行性/FTO/工艺评价等咨询意见 | `知产技术咨询·审查` 或 `或` |
| 现成软件买授权、SaaS、不改底层代码 | `软件许可合同（分发许可模式）·审查`（分发）或 `软件许可合同（自用许可模式）·审查`（自用） |
| 现成软件著作权转让 | `软件著作权转让合同·审查` |
| 现成技术转让 | `技术转让合同·审查` |
| 已有可读待签文本要评改 | `软件委托开发合同·审查` |
| 无文本、本类型条件已谈妥、要出己方稿 | 本任务起草并自审 |
| 已签未争、只问里程碑/验收/付款留痕 | 本套导航的履约步骤 |
| 已成争 | `或知产争议专项。` 或对应专项领域 |
| C 端大众快检 | 只分流，不回改 |

软件委托开发正文里夹带一笔现成软件许可或一笔运维期服务：专条分别交接 `软件许可合同（自用许可模式）·审查` / `知产技术服务·审查`；可运行软件+源码、著作权、开源、需求与验收条款可继续审。用户坚持本技能把技术开发、一般委托开发、承揽或许可整案改完：`目标停止`。
