# 软件委托开发合同·起草

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》技术合同章、《技术合同法》及其实施条例、2004 年技术合同解释未修正文本当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只按已谈妥条件起草 **软件委托开发合同** 己方稿，出稿后用本类型硬闸自审。交付草稿、未决项、自审风险表和自审后修改句。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「软件委托开发合同·起草」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、把技术开发/一般委托开发/承揽/软件许可整案改完、把研发失败风险分担或按图必然交付写成可履行主路径。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **可运行软件+源码 ≠ 研发不确定性 ≠ 承揽**：正像是按需求定制、交付可运行软件及源代码。尚待研究开发、不保证成果必然产生、约定研发失败风险分担 → 负触发 `技术开发合同·审查`。按既有图纸加工/定作实物 → 负触发 `按既有图纸加工定作实物→负触发` / `按图定作实物` / `项目承揽重劳务过程交付实物成果`。一般新技术委托开发、交付物不是可运行软件+源码 → 负触发 `委托开发合同·审查`。禁止把民法典第 858 条失败分摊或承揽“按图必然交付”抄作本类型默认主路径。
2. **交付物必须含源码**：目标程序、带注释源代码、数据库结构、设计/接口/部署文档、用户手册。仅交付安装包：必须改或红线。最高比例款项以源码交付并核验为前置。
3. **著作权必须书面约定**：无书面约定或约定不明，著作权归受托人。不得把沉默写成“已经归甲方”。
4. **开源/第三方组件**：列清单与许可证。GPL 等强传染协议红线或必须改，不得写成“可任意使用开源”。
5. **需求冻结与变更**：SRS/PRD 入附件。聊天不得单独构成需求。超幅度变更须补协议并调整费用工期。
6. **验收闭环**：以附件需求与量化性能为准。初验 → 试运行 → 终验。上线、付款、签收不当然等于验收。
7. **核心模块不得擅自转包；账号实名**：未经书面同意不得转包核心功能。服务器、域名、云账号以委托方名义实名。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签软件委托开发、计算机软件开发或定制开发正文，尚未签署，尚未成争，核心给付是按需求交付可运行软件及源代码，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 尚待研究开发、不保证成果必然产生、核心是研发失败风险分担 → `技术开发合同·审查`；
- 一般新技术/新产品委托开发，交付物不是可运行软件+源码 → `委托开发合同·审查`；
- 双方分工参与研发 → `合作开发合同·审查`；
- 委托合同目录下的委托技术开发主文件且用户未锁定本类型 → `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`；
- 按图加工、定作实物、项目承揽 → `按既有图纸加工定作实物→负触发` / `按图定作实物` / `项目承揽重劳务过程交付实物成果`；
- 对已有软件维护、升级、培训 → `知产技术服务·审查`；仅出具咨询意见 → `知产技术咨询·审查` 或 `或`；
- 现成软件买授权/SaaS、不改底层代码 → `软件许可合同（分发许可模式）·审查` / `软件许可合同（自用许可模式）·审查`；现成软件著作权转让 → `软件著作权转让合同·审查`；
- 现成技术转让 → `技术转让合同·审查`；
- 无文本、本类型条件已谈妥、要出己方稿 → 留本任务起草并自审；
- 已签只问里程碑留痕、验收日、付款日 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁 → `或知产争议专项。` 或对应专项领域。

黑盒控制、逻辑炸弹、通谋虚假价款、倒签：只出告知，不改写成可履行结构。

## 建立审查坐标

确认：使用者与授权；单方立场（委托方或开发方择一）；相对方；全文及 SRS/PRD、里程碑、验收标准、开源清单版本；交付物是否含源码；著作权买断还是授权；是否保证上线或写研发失败分摊；是否按图加工实物；核心模块可否转包；服务器/域名登记名义；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的价款、工期、并发量、质保金用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验技术合同解释（2020）第 46、17、19、22 条，计算机软件保护条例第 2、3、11 条，著作权法第 19 条，著作权民事解释第 12 条，民法典第 851、852、853、858、770、878、496–498、153、585、586 条，合同编通则解释第 10、15、16、64、65 条；`search_practiced` 只补审查反例；`search_template` 只借栏目结构。不虚构案件系统。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》技术合同章、《技术合同法》及其实施条例、2004 年解释未修正文本时记为噪声，不得写入 `L#`。不得把第 858 条失败分摊或承揽按图交付写成默认法。


## 起草模式

本原子只承担本类型起草。待签评改转 `软件委托开发合同·审查`。无完整待签文本、但本类型条件已谈妥、要出己方稿时，留在本任务，不转 `软件委托开发合同·起草`。

仍只加载本目录 [基本面](references/基本面.md) 与 [框架](references/框架.md)。不另写一套硬闸。

1. 先按框架六步落稿：首部 → 交易条款 → 配套 → 尾部 → 正说反说 → 必写与禁忌。商业数字未给用 `【待填】`。
2. 出稿后必须用「本类型硬闸」和 [审查方法](references/method.md) 再审自己的稿，输出风险表和修改句。不得只交白稿。
3. 他类型出稿、已签履约、已成争：仍负触发。

起草必写：按需求定制、交付可运行软件及源代码；交付物含目标程序、带注释源代码、数据库结构、设计／接口／部署文档、用户手册；最高比例款项以源码交付并核验为前置；著作权必须书面约定，无书面约定或约定不明则著作权归受托人；开源／第三方组件列清单与许可证；SRS／PRD 入附件，聊天不得单独构成需求，超幅度变更须补协议并调整费用工期；验收以附件需求与量化性能为准，初验 → 试运行 → 终验，上线、付款、签收不当然等于验收；未经书面同意不得转包核心功能；服务器、域名、云账号以委托方名义实名。
附件必附：SRS／PRD；开源／第三方组件及许可证清单；量化验收标准。
禁止出现：仅交付安装包；把沉默写成已经归甲方；可任意使用开源；把民法典第八百五十八条失败分摊或承揽按图必然交付抄作本类型默认主路径。GPL 等强传染协议、黑盒控制、逻辑炸弹：只告知或必须改，不起可履行闭源／黑盒稿。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → 本任务起草并自审；已签履约 → 本套导航履约步骤；已成争 → 合同争议。未签且目标是评改已有软件委托开发文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。研发不确定性、一般委托开发、承揽实物、软件许可/转让、技术服务负触发。

### 2. 主体与转包

签约名、履行名、付款名、发票名分列。核心模块擅自转包：必须改或红线。

### 3. 交付物与源码

清单必须含可运行程序和带注释源码。仅安装包＝未完成核心交付，除非明确只买目标程序。

### 4. 著作权与开源

书面约定归属。沉默归受托人。开源清单与强传染协议。

### 5. 需求、里程碑与价款

需求确认书。变更补协议。源码核验后再付最高比例款。质保金与维保期满挂钩。

### 6. 验收、格式条款与强制规范

初验/试运行/终验。上线≠验收。无核验引文则法律结论字段停止。

### 7. 账号实名、维保与终止善后

服务器/域名/云账号委托方实名。质保期修 BUG。终止后交回账号与剩余源码。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、只交安装包永久不交源码却按买断收全款、把研发失败风险分摊或按图必然交付写成可履行主路径、把 GPL 写成闭源可用、把无约定著作权写成已经归委托方。
- `字段停止`：法域、动态规则、开源清单、等保级别、并发指标未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。

生存级预付款或个人无限连带且用户拒绝升级：停止“可以签署”建议。
