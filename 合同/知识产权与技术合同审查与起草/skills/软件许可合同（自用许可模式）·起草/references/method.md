# 审查方法（锁定 知识产权相关合同 / 软件许可合同（自用许可模式））

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止复制分发许可的出货／OEM／下游转授主路径、软件著作权转让的权属过户主路径，或商标许可“未备案不得对抗善意第三人”。

定性校验：标题、核心给付与本类型一致才继续；分发、转让、委托开发或纯云端服务明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受或唯一必得许可费。

`search_law` 返回已失效《合同法》及其解释、1991 年《计算机软件保护条例》、1991 年著作权法实施条例、2009 年《软件产品管理办法》时记为噪声，不得写入 `L#`。著作权民事纠纷解释第二十一条仍引用“著作权法第四十八条”：现行对应为 2020 年著作权法第五十二条，运行时复核后再写入 `L#`，不得把旧条号写成现行法。著作权法实施条例第二十四条仍引用“著作权法第二十四条”：现行对应为第二十六条，同样复核。

示范文本只参考结构。民法典第 470 条允许参照示范文本，不证明本约条款已被接受。分发许可或软件转让范本不得直接粘成本约。

知识库纠正（不回写双文件）：

- `基本面.md` 只点著作权法第二十九条不够：许可合同主要内容走第二十六条；软件专有／非专有走条例第十八条、第十九条。
- `框架.md` “集团内通用”“合理数量备份”是空词，必须落到法人名单和备份份数。
- `基本面.md`／`框架.md` “永久买断全部知识产权归用户”：买断只覆盖约定版本的使用权，不是著作权法第27条的转让。
- 实施上线、交密钥、验收合格 ≠ 许可成立条件，更 ≠ 权属交割。
- 许可人单方停运、密钥服务器故障按违约或 SLA 处理，不是不可抗力。
- 面向消费者的电子交易可能适用网销七日无理由；B 端定制许可通常排除。不得把消保规则默认套到全部 B 端订单。

## 节点 1　类型识别与单目录加载

### 1.1 定性

用标题、核心给付、对价方式和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

必须切开后再加载，禁止两可时灌入两套知识：

| 信号 | 归入 | 本任务动作 |
| --- | --- | --- |
| 著作权人保留权属，许可最终用户在约定席位／站点内自行安装运行，收许可费 | 本类型 | 正触发 |
| OEM、预装出货、按台计提、向下游客户转授使用权 | 软件分发许可 | 负触发 `软件许可合同（分发许可模式）·审查` |
| 软件著作权归对方、办理登记变更、转让价款 | 软件著作权转让 | 负触发 `软件著作权转让合同·审查` |
| 文字、视听等非计算机软件作品的许可 | 著作权许可使用 | 负触发 `著作权许可使用合同·审查` |
| 按里程碑开发、交源码、验收后权属归委托方 | 软件委托开发 | 负触发 `软件委托开发合同·审查` |
| 纯云端登录，软件不复制到用户控制的环境 | 服务／技术服务 | 负触发引擎或 `知产技术服务·审查` |
| 只撮合双方签约，自己不许可 | 中介 | 转引擎重新定性 |

支持切开的规范（法律结论须运行时复核）：

- 著作权法第二十六条：许可使用合同应写权利种类、专有或非专有、地域、期间、付酬、违约责任。
- 著作权法第二十九条、软件保护条例第十八条：未明确许可的权利，被许可人不得行使。
- 软件保护条例第十九条：未书面或未明确约定专有的，视为非专有。
- 著作权法第二十七条：转让财产权利须书面并写明转让的权利种类；许可不是本条。
- 民法典第 876 条：计算机软件著作权的转让和许可参照适用技术合同章有关规定；本任务只借用书面、范围和付酬纪律，不把专利实施许可的备案生效话术套进来。
- 著作权民事纠纷解释第二十一条：用户未经许可或超过许可范围商业使用计算机软件，依法承担民事责任。

## 节点 2　主体、权源与使用人名单

### 2.1 主体表

建表：签约名、履行名、付款名、发票名、授权签字人。名称不一致不自动合并。许可人须是软件著作权人或能出示再许可授权的发行商。口头“我们代理没问题”不得写成已授权。

代理商签约未附权利人再许可授权：权源字段停止，不写“许可有效、可对抗权利人”。

### 2.2 最终用户必须点名（硬闸）

被许可人是最终用户本身。集团公司、分公司、外包商、驻场供应商、合资公司是否纳入“使用人”，必须点名并入附件清单。未点名的关联公司安装，现有依据支持认定为超范围。

| 已有事实 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 正文列被许可人全称，附件列有权安装的法人 | 可继续 | 清单外主体“视同已授权” |
| 只写“甲方及其关联公司／集团内通用” | 必须改：落到统一社会信用代码名单 | 集团＝任意控制关系 |
| 外包或驻场可接触软件，但未列为使用人 | 必须改：或列入清单并受同等禁止再分发约束，或禁止其安装 | 接触即取得许可 |
| 集团统采、支付方与使用方分离 | 必须改：写清被许可主体清单；未列入的不得开通 | 付款方自动覆盖全集团 |

修改句：

「被许可人仅限于附件一列明的法人（名称及统一社会信用代码【待填】）。许可范围不包括未列入附件一的母公司、子公司、分公司、合资公司、外包商或驻场供应商。前述主体需要安装或使用的，应另行签订许可或变更订单。实施方、运维外包可接触本软件，但不因此成为被许可人，并须遵守与被许可人相同的禁止再分发、禁止再许可义务。」

点击同意的相对人是否为有权账号：线下合同核授权代表。面向消费者时适用消保法格式条款规则，见节点 6。

## 节点 3　终端自用与计量（硬闸）

支持依据：著作权法第二十六条、第二十九条；软件保护条例第十六条、第十八条；解释第二十一条。

### 3.1 许可范围六要素

必须写到可履行：软件名称与版本、模块；许可数量（指定用户／并发／CPU／实例／站点）；安装地点或实例标识；用途；期限；是否可升级。缺一项标 `G#`，不得默示“全公司任意安装”。

| 文本写法 | 动作 |
| --- | --- |
| 已写指定用户数／并发／实例，并与订单一致 | 正触发，留下本类型 |
| 无计量，或写“按实际需要”“不限用户” | 必须改。席位／实例／站点封闭；超额自动成单或按目录价补费 |
| 正文 80 席、订单 200 席、聊天“先按不限” | 三源并列，不选有利版；必须改到一致 |
| 灾备实例、跨数据中心未写是否另计 | 必须改。不得默认免费 |
| 用途空白或写“相关系统使用” | 必须改：内部生产经营；禁止经营性再提供 |

修改句：

「甲方将软件【名称／版本／模块，待填】以普通（非专有）自用许可授予乙方。乙方仅得在许可数量内（指定用户【待填】名／并发【待填】／实例【待填】／站点【待填】）于附件二列明的安装环境（办公地址／机房／云账号【待填】）安装和运行。灾备实例是否占用额外许可，按附件二执行；未约定的，灾备实例另行计费。用途限于乙方内部生产经营。未在订单中增加席位或站点前，乙方不得超员、超实例使用。」

### 3.2 权项锁定：正说加反说

正说：用户得在许可数量内安装、运行，并制作必要备份。

反说见节点 4。备份：条例第十六条允许为防止复制品损坏而制作备份，但备份不得以任何方式提供给他人，丧失合法复制品所有权时应销毁。合同须写死备份份数，禁止“合理数量”。

为互操作或改进功能的必要修改：条例第十六条第三项允许合法复制品所有人在自己环境做必要修改，但除另有约定外不得向任何第三方提供修改后的软件。合同若全面禁止修改，须提示可能与该条冲突；修改句可保留“不得向第三人提供修改件”，不要写成“连自己环境的必要适配也一律构成违约”。为学习研究设计思想的使用走条例第十七条，不得扩成商业使用免许可。

未明确的修改权、信息网络传播权、发行权、出租权、再许可：现有依据支持认定为不得行使。

订阅与买断：

- 订阅：期满使用权消灭，须卸载、删除备份、交回密钥。
- 买断：仍须写版本；不当然含未来大版本；停维后通常可继续运行已交付版本，订阅制通常不可以。两者必须点名，禁止用“永久授权”四个字代替。

不要把“实施验收”作为许可成立条件，以免已安装却无合法权源。

## 节点 4　禁止再分发（硬闸）

本节点是自用许可的生存闸。没有反说句，不得宣称范围已闭环。

| 文本写法 | 动作 |
| --- | --- |
| 正说内部使用，并逐项禁止再许可、分发、出租、嵌入出货、向第三人提供在线使用权 | 可保留；补违约后果 |
| 只写“不得外传”，未点名再许可／分发／SaaS 化 | 必须改。空词不够 |
| “可给客户远程登录同一套系统”“可作为服务对外提供” | 红线删除，或整案转 `软件许可合同（分发许可模式）·审查` |
| “可随产品预装销售”“可再授权下游” | 负触发 `软件许可合同（分发许可模式）·审查` |
| 允许外包使用但未禁止外包再提供给其客户 | 必须改：外包仅得为被许可人内部目的接触，不得再分发 |

修改句：

「乙方有权在第【待填】条约定的许可数量和安装环境内安装、运行本软件，并制作不超过【待填】份的备份。备份仅得由乙方持有，不得以任何方式提供给他人；本合同终止或乙方丧失合法复制品时，乙方应销毁全部备份并出具书面说明。未经甲方书面同意，乙方不得再许可、不得分发、不得出租、不得将本软件嵌入对外销售的产品或设备，不得向任何第三人提供本软件的使用权或实质等同的在线服务（包括但不限于以 SaaS、ASP、托管或共享账号方式向客户、经销商或无关第三方开放）。未在本合同中明确许可的修改权、信息网络传播权、发行权和出租权，乙方不得行使。超出席位、向未列入附件一的主体提供账号，或实施本条禁止行为的，构成超范围商业使用；甲方有权关闭超额或违规实例，但应保留乙方仍符合本条的部分继续使用，并按当年度目录价追溯补收许可费人民币【待填】／席或按双方另行书面确认的标准结算。」

最强反方：被许可人主张“内部集团调拨”“给客户演示账号”仍属自用。本任务处理：集团调拨必须先入法人名单；对外演示若使第三人获得实质使用权，按再分发处理，不得放行。

用户坚持保留出货或对外提供句：不改写成可履行自用结构；整体停止或负触发 `软件许可合同（分发许可模式）·审查`。

## 节点 5　对价、EULA 位阶、审计与数据

### 5.1 对价闭环

许可费、维保费、超额单价、币种、税、发票、支付节点分列。未给出的数字写 `【待填】`。禁止编造目录价。

未付到期订阅费：可约定使用权中止，但不得写成许可人可扣留用户自有数据。买断后拒付维保：修改句写明已交付版本可继续运行，升级与维保另行成单，不得把停维写成已交付版本必须停用——除非本约本就是订阅。

定金：必须使用“定金”二字才讨论罚则。预付年费是许可费；实施预付款不要写成定金，除非确有定金罚则。约定或推算超过主合同标的额百分之二十：超过部分不产生定金效力。无核验引文不得把 20% 写成现行法结论。

### 5.2 EULA 与主合同位阶（硬闸）

B 端复杂许可常是“主合同 + 订单 + EULA + 服务单”。点击条款不得偷偷扩大使用限制或缩小已买席位，也不得把已买永久许可改成可随时收回。

| 已有事实 | 动作 | 不得写成 |
| --- | --- | --- |
| 主合同写明：主合同优于 EULA，EULA 优于产品说明；订单锁定席位和期限 | 可保留 | 已不存在冲突 |
| 主合同永久 200 席，EULA 写许可人可随时收回且数据不导出 | 必须改。冲突并列；修改句以订单／主合同为准 | 点击即已同意收回 |
| 仅有网络勾选或弹窗 | 提示说明字段停止 | 已尽提示或说明义务 |
| 简单许可、无主合同、只有网页 EULA | 可审 EULA；异常免责按格式条款处理 | 必然成为合同内容 |

修改句：

「本合同、附件订单、EULA 与产品说明构成完整协议。解释顺序为：订单优于本合同正文，本合同正文优于 EULA，EULA 优于产品说明。EULA 中与订单或正文冲突的条款（包括但不限于缩减已购席位、将买断改为可随时收回、排除数据导出）不生效。乙方通过网页勾选 EULA 不视为已就上述异常条款获得单独提示和说明。」

### 5.3 审计

许可人可审计安装点和账号。须写通知期、远程或现场、超额处理（补费／卸载）。审计不得变成无限期停服威胁。关闭超额实例时保留合规部分。

### 5.4 数据与终止清理

用户数据归属用户。许可终止不等于服务商可以扣留用户自有数据。修改句并列：导出窗口、卸载证明、交回密钥、销毁备份。许可人远程停服：故意停服或侵害用户数据不宜全部免责。

修改句：

「乙方在本软件中录入或生成的业务数据归乙方所有。本合同终止或使用权中止的，甲方应在【待填】日内以通用机器可读格式向乙方开放数据导出，不得以许可费争议、权属争议或审计未完成为由扣留数据。乙方应在导出完成后【待填】日内卸载软件、删除备份并交回密钥，书面确认已完成清理。甲方因密钥服务器故障或单方停运导致乙方无法使用已付费期限内的许可的，按违约或附件服务水平处理，不得主张不可抗力。」

## 节点 6　格式条款、消费者规则与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 6.1 未明确的权利与非专有默认

未明确许可的权利不得行使。未书面或未明确约定专有的，视为非专有。自用许可默认为普通（非专有），许可人可再许可他人。用户要“独家／专有”：必须改书面点名，并评估是否已滑向分发或封锁许可人；本类型通常不需要专有。

专有许可、转让合同可向著作权行政管理部门备案（实施条例第二十五条）：备案不是自用普通许可的生效要件。不得把未备案写成合同未生效，也不得把备案写成权属转移。

### 6.2 格式条款

为重复使用而预先拟定、订立时未与对方协商。依据示范文本制作，不当然排除格式条款。

审查：席位限制、自动续期、单方调价、随时收回许可、数据不返还、管辖／仲裁等异常条款是否有足以引起注意的标识，以及是否按要求说明（第 496 条；解释第 10 条）。

| 已有事实 | 不得写成 |
| --- | --- |
| 小字印刷、夹在附件 | 已尽提示义务 |
| 仅有网络勾选或弹窗 | 已尽提示或说明义务 |
| 对方未异议 | 条款必然成为合同内容 |

提供方对其已尽提示或说明承担举证责任。相对方立场：修改句要求加黑提示、单独签署确认页，或删除异常条款。第 497 条无效情形只在核验后作为修改理由，不代替修改句。

面向消费者：再压一档。最终解释权、签收即认可质量等条款，对照网络消费纠纷解释（一）第一条评估。七日无理由：面向个人的电子交易可能适用；定制许可、数字化商品拆封或下载后除外的，须显著标注并经确认，不得写成默认勾选即排除。B 端定制许可通常排除，不得把消保七日写成全部企业订单的法定义务。

### 6.3 强制规范

违反法律、行政法规强制性规定不一律无效。区分规范目的、是否仅行政管理、是否只规制履行行为（第 153 条；合同编通则解释第 16 条）。禁止用已失效“效力性／管理性”口诀。未办软件著作权登记或许可备案，不得单独写成民事合同当然无效。向外国人许可还须核技术进出口：字段停止，不代做目录归类。

挂靠、违法分包、规避限购：只告知，不改写成可履行。

## 节点 7　违约、解除与争议

1. 超范围使用、破解授权、向外包或客户再提供、逾期付款、未按约开通，必须分别有可执行后果。只有“依法承担违约责任”视为必须改。
2. 许可人可关闭超额或违规实例，但应保留合规部分的使用。
3. 构成违约不等于当然解除。法定解除路径只点名催告或目的不能实现，不在本任务作出已解除结论。
4. 违约金不是必得金额；不在本任务做第 585 条精算。修改句避免“不得调整”或“按总价 30% 必得”。
5. 争议解决：出现仲裁条款，不得改写成“应向某法院起诉”并假装已选定诉讼。或裁或诉、机构不明：标待核，修改句改成单一仲裁机构或单一法院连结点。专属管辖可能：只标红旗，不选定唯一法院充作法律意见。
6. 通知送达：微信已读不写成已经到达，除非合同把该渠道写成送达且用户要保留。
7. 电子订单独认点击日志、账号实名、支付记录。不要指导补假点击日志。

| 步 | 动作 | 必须产出 |
| --- | --- | --- |

| 尾部 | 签署权限；生效＝支付或盖章，不是实施验收；订单、EULA、产品说明、主体清单、再许可授权入附件 | 生效与附件修改句 |

| 常见问题 | 无计量；自用里写分发；EULA 吞主合同；名许实转／实开；面向消费者用纯 B 端免责 | 结构级改法或红线 |

每条修改句固定格式：

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（再分发／预装出货主轴、权属过户主轴、无计量仍要全公司安装、EULA 随时收回已买席位并扣数据、倒签或补假点击日志）；
- `必须改`：可谈但签署前要落句（点名席位与使用人、禁止再分发正说反说、EULA 位阶、订阅／买断期满效果、数据导出、权源附件）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级买断且权源未核、用户拒绝升级：停止“可以签署”建议。

定制代码：实施或少量定制可分条计价；定制部分权属单写，默认不改变基础软件权属。定制成为主给付、按开发里程碑交源码：负触发 `软件委托开发合同·审查`。
