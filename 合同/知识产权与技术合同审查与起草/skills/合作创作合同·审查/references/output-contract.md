# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、分成、工期；把已失效《合同法》及其解释、1990 年著作权法或 1991 年实施条例写入结论；保证挂名作者有效；把委托创作、技术合作开发、合伙、著作权转让或许可文本当成已完成的本类型审查；写“未创作的人可以靠合同成为合作作者”；写“一方不同意则任何使用都必须停止”；写“单方专有许可对全体作者发生处分效力”。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查合作创作合同（知识产权相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1990 年著作权法或 1991 年实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `知识产权相关合同`，子级 `合作创作合同`。定性理由、易混切开结果（委托创作 / 著作权转让 / 著作权许可 / 软件著作权转让 / 技术合作开发 / 合伙 / 视听制作者权）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型、未打开 `知产委托创作·审查` 的 method。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、作者身份与文本版本

主体表：签约名、履行名、收款名、发票名、授权签字人。作者表：是否实际贡献独创性表达、拟署名、是否投资人挂名、职务作品边界。版本表：正文、分工署名表、素材清单、分配表、授权审批流程、聊天确认；冲突并列。

## 5. 共有、行使与给付闭环

作品是否特定化；可分割还是不可分割；不可分割是否整体共有；一方能否不当阻止自己使用或普通许可；转让/专有许可/出质是否全体书面同意；署名；收益代收与分配；带入素材；登记作者栏是否与合同一致；退出清理。缺口标 `G#`。不输出按份共有物分割口径，不输出“须全体同意才能做任何使用”且无例外的放行口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。金主挂名、买卖署名、单方重大处分不得写成可放行。强制规范只按核验后的现行条文区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为委托或开发或合伙、金主当作者、不可分割被拆成可单卖整部、一方无理由永久阻止使用、单方专有/转让/出质对全体生效），再必须改（可分割性说明、不得阻止的通知和分账、重大处分清单、代收、登记名单、素材许可、退出），最后可优化。签署提醒：全体作者亲签、用印、日期、附件清单、登记与合同作者栏一致后再对外专有授权。不指导倒签或先对外专有授权再补其他作者签字。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是委托创作、著作权转让、许可、技术开发或合伙安排。
