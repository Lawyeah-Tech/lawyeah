# 软件许可合同（分发许可模式）·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》、《计算机软件保护条例》（1991）“许可不超过十年”、1990 年著作权法“合同有效期限不超过十年”、2009 年《软件产品管理办法》当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **知识产权相关合同 / 软件许可合同（分发许可模式）** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「软件许可合同（分发许可模式）·审查」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、侵权诉讼策略、有效性保证、把自用许可改成分发或把分发改成权属过户。

## 本类型硬闸

每闸必须出修改句或明确停笔口径，禁止只打红黄绿。

1. **再分发／渠道必须点名**：核心给付是带再分发权的使用权，不是内部安装。权项至少写清复制、发行（及是否含信息网络提供），并允许被许可人仅向最终用户转授有限自用许可（须使用附件 EULA）。授权产品用封闭 SKU 清单，渠道（线上、运营商、指定经销商、自有门店）写死。缺发行权、缺终端转授、缺授权产品：现有依据支持认定未明确许可的权利不得行使，不得出货。
2. **与自用许可切开**：文本把使用限定在被许可人内部安装点、禁止再许可和再分发，或标题是最终用户许可／EULA／仅限内部使用，而用户却要按 OEM／预装／转售审完 → 负触发 `软件许可合同（自用许可模式）·审查`。不得删掉“仅限内部使用”后按分发改完，也不得在自用稿里塞出发行权和出货权。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签软件分发许可／OEM／预装与再分发许可正文，尚未签署，尚未成争，核心给付是许可对方复制、集成、再分发软件并随自身产品提供给最终用户，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 主给付是被许可人内部安装、按席位或按站点自用，禁止再分发 → `软件许可合同（自用许可模式）·审查`；
- 主给付是软件著作权权属转移、办理著作权人变更／转让登记、转让价款 → `软件著作权转让合同·审查`；
- 主给付是一般文字、美术、视听等非软件作品的许可使用 → `著作权许可使用合同·审查`；
- 主给付是非软件作品著作权转让 → `著作权转让合同·审查`；
- 尚待研发、验收合格后权属归甲方、不授予出货权 → `软件委托开发合同·审查` 或 `技术开发合同·审查`／`委托开发合同·审查`／`合作开发合同·审查`；
- 标题是技术类“计算机软件著作权许可”且无法拆出再分发／渠道／SKU 出货轴 → `计算机软件著作权许可合同·审查`（P1；专业版未装则 `unavailable`）；
- 无文本、本类型条件已谈妥、要出己方稿 → `软件许可合同（分发许可模式）·起草`；
- 已签只问报数日、密钥交付、备案进度 → 本套导航的履约步骤；
- 已催告、解除、索赔、侵权诉讼或仲裁策略 → `或知产争议专项。` 或知识产权争议专项。

任意再许可给其他厂家、源码用于竞争性产品、把最终用户许可写成买断：只出告知与删除句，不改成可履行越权结构。用户坚持保留：整体停止。

## 建立审查坐标

确认：使用者与授权；单方立场（许可人侧或被许可人侧择一）；相对方；全文及授权产品清单／EULA／开源清单版本；软件名称与版本是否可见；复制／发行／信息网络／终端转授是否点名；SKU 与渠道是否封闭；专有／排他／普通是否书面点名；报数与审计；基础费与提成；期满库存与已售用户存续；是否夹带权属转让；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的许可费、提成、SKU、期限用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验著作权法第二十六、二十九条，软件条例第十九、二十一条，民法典第 876、496、506、586 条；`search_practiced` 只补审查反例；`search_template` 只借栏目结构。不虚构案件系统。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》、1991 年软件条例“许可不超过十年”、1990 年著作权法十年期限、2009 年《软件产品管理办法》时记为噪声，不得写入 `L#`。不得把商标许可“未经备案不得对抗善意第三人”或专利实施许可“生效之日起 3 个月内备案”套到本类型。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)
- [框架](references/框架.md)

禁止打开其他类型目录。`基本面.md` 中“专有分发许可宜书面并备案，否则难以对抗许可人另授其他厂家”不得写成商标式对抗规则；未点名专有视为非专有，备案／登记是自愿手续。`框架.md` 中交 SDK、交密钥不等于转让著作权。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `软件许可合同（分发许可模式）·起草`；已签履约 → 本套导航履约步骤；已成争或侵权诉讼策略 → 合同争议。未签且目标是评改已有分发许可文本，才进入本任务。

### 1. 类型锁死与自用／转让切开

标题、核心给付与对价方式一致才继续。自用许可、软件著作权转让、软件委托开发、一般作品许可负触发。

### 2. 主体、权属链与出货主体

许可人须是软件著作权人或有再许可权的人。集团多工厂出货须把生产主体、销售主体写入被许可人范围。未核登记证书：不写“权属无争议”。

### 3. 再分发权项、授权产品与许可方式

复制／发行／信息网络／终端转授点名；SKU 与渠道封闭；专有须书面点名，否则视为非专有。

### 4. 生效、专有备案与进出口

合同成立生效；专有备案／登记不是生效要件，也不是权属变动。跨境出货字段停止，不代做目录归类。

### 5. 对价、报数审计与源码

基础费与提成分列；计费对象可审计；默认不交源码。

### 6. 格式条款、责任限制与强制规范

EULA 与主合同的免责不得排除人身损害或故意／重大过失财产损失。无 `search_law` 引文则效力字段停止。

### 7. 违约、期满库存与已售用户

超 SKU、瞒报、转分发须有可执行后果。售完窗口与已售最终用户许可是否存续必须明示。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证必然不侵权、把权属过户当许可放行、把任意再许可或源码竞争性使用改成可履行结构。
- `字段停止`：法域、权属证书、在先专有分发、限制／禁止出口或出口管制、开源传染义务未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书、侵权诉讼策略，或已锁他类。
