# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可出货；编造未给出的许可费、提成、SKU、期限；把已失效《合同法》、1991 年软件条例十年期限或 2009 年《软件产品管理办法》写入结论；把未点名专有写成独占；把未备案写成合同未生效或当然可对抗第三人；把交 SDK／密钥写成著作权转让；把仅限内部使用的自用许可当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查软件许可合同（分发许可模式）（知识产权相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》、1991 年软件条例十年期限、1990 年著作权法十年期限或 2009 年《软件产品管理办法》时，记噪声，不得写入 `L#`。不得把商标许可备案对抗或专利实施许可备案 3 个月写入 `L#`。

## 3. 类型与加载路径

父级 `知识产权相关合同`，子级 `软件许可合同（分发许可模式）`。定性理由、易混切开结果（自用许可、软件著作权转让、软件委托开发、一般著作权许可、技术类软件著作权许可）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属链与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人、实际生产主体与销售主体。状态表：软件名称与版本、登记号（如有）、在先专有分发、开源组件。版本表：正文、授权产品清单、EULA、开源清单、提成表、聊天确认；冲突并列。未核登记证书或合作开发／共有同意：该签署能力字段停止。

## 5. 再分发权项、授权产品、对价与报数

核心给付是否含复制、发行、约定范围内的信息网络提供及向最终用户转授自用许可；SKU 与渠道是否封闭；专有／排他／普通是否书面点名；基础费／单价／提成／最低出货；报数模板与审计；默认不交源码。缺口标 `G#`。不输出著作权转让登记主路径，不输出自用安装点主路径。

## 6. 备案、EULA、责任限制与格式条款

专有备案／登记写成自愿协作，不写成合同未备案不生效，也不写成权属变动。EULA 权利不得宽于本合同，最终用户不得再分发。责任上限是否剔除权属瑕疵与开源未披露；免责是否触及人身损害或故意／重大过失。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“未备案不得对抗善意第三人”或“许可期限法定不超过十年”写成默认句。

## 9. 谈判与签署提醒

谈判顺序：先红线（自用模板错位、无发行权做出货、无 SKU、任意再许可、权属过户错位、源码竞争性使用），再必须改（权项点名、SKU／渠道封闭、专有书面点名、EULA 附件、报数审计、期满库存与已售用户存续），最后可优化。签署提醒：授权产品清单、EULA、开源清单、提成表、审计规程入附件；生效日与专有备案申请日分列。不指导倒签或补假备案。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、侵权诉讼策略或效力保证，也不是自用许可或软件著作权转让审查。
