# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的经费、指标、工期；把已失效《合同法》《技术合同法》及其实施条例写入结论；保证研发成功或拿到专利；把专利申请权写成一律归委托方；把转让、承揽、咨询或纯软件文本当成已完成的本类型审查；写“先做后补批”进出口或国家秘密路径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术开发合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `技术开发合同`。定性理由、易混切开结果（转让 / 许可 / 承揽 / 咨询 / 服务 / 纯软件 / 委托开发细分 / 合作开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、转第三人与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。转第三人表：核心研发是否可转、是否须书面同意、Key person 是岗位还是点名自然人。版本表：正文、技术任务书、研发计划、背景 IP 清单、聊天确认；冲突并列。

## 5. 标的、风险、归属、对价与验收

标的是否尚待开发；是否出现成功/专利/固定收益保证；850 禁研或回授；技术风险判定与分担；专利申请权/著作权/技术秘密/后续改进分项；交付物是否含源代码、实验记录、图纸；报酬与节点；验收里程碑与第三方测评。缺口标 `G#`。不输出转让对价或承揽“必然合格交付”口径。

## 6. 格式条款、强制规范与进出口

是否构成格式条款；提示说明痕迹。850 条款不得写成可放行。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。技术进出口或国家秘密未批准：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“专利申请权无约定归开发者”写成合作开发默认。

## 9. 谈判与签署提醒

谈判顺序：先红线（不是尚待开发、成功保证、850 禁研、未批进出口/国家秘密、拟制合格放弃缺陷），再必须改（风险分担程序、归属分项、转第三人同意、交付物清单、验收里程碑），最后可优化。签署提醒：授权、用印、日期、任务书与附件清单、首笔经费到账是否作为履行起点。不指导倒签或先做后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是转让、承揽、咨询或纯软件交付安排。
