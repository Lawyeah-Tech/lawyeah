# 审查方法（锁定 技术类合同 / 技术开发合同）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型。禁止复制咨询“意见非交付物/禁固定节约”主路径，禁止复制承揽“按图完成、成果必然可复制”method。

定性校验：标题、核心给付与本类型一致才继续；转让、许可、承揽、咨询、纯软件或他类明显则负触发，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、对方必然接受、保证研发成功或唯一必得金额。

`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》及其实施条例时记为噪声，不得写入 `L#`。

示范文本只参考结构。民法典第 845 条允许把任务书、计划书作为合同组成部分，不证明本约条款已被接受。科学技术部技术转让示范文本、技术咨询合同范本只证明那是另一类型，不得当作本类型范本。

知识库纠正（不回写双文件）：

- `基本面.md` “专利申请权：无约定时，归开发者所有”：只覆盖**委托开发**默认（第 859 条归研究开发人）。**合作开发**无约定时专利申请权原则上共有（第 860 条）。不得写成一律归开发方，更不得编造一律归委托方。
- `基本面.md` “项目分包……应当经委托人同意”：现行依据是第 551 条债务转移须债权人同意、第 853 条研究开发人实施计划并完成工作，加上合同必须改。失效《技术合同法实施条例》不得写入 `L#`。不得把第 772 条承揽专条直接写成技术开发法定转包条。
- `基本面.md` 适用场景把“软件系统定制开发”一并列上：若核心是交付可运行软件、技术上没有创新或无可克服的研发不确定性，负触发 `软件委托开发合同·审查`，不在本任务按研发风险改完。
- `框架.md` 委托开发专利申请权归研发方、合作开发共有：与第 859、860 条一致，采用。若正文写成“无约定一律归甲方/委托方”，必须改。
- `框架.md` 验收、里程碑：采用阶段验收思路。若出现“逾期不验收视为全面合格且放弃一切技术缺陷”，必须改，不得当最佳实践放行。
- 第 850 条现行表述是“非法垄断技术或者侵害他人技术成果的技术合同无效”，条文本身不再写“妨碍技术进步”。认定清单走技术合同解释（2020 修正）第 10 条。

## 节点 1　类型识别与单目录加载

### 1.1 定性

用标题、核心给付、对价方式和用户陈述定性，不用标题单独定性。名实不符时按核心给付归类，标题冲突写入 `C#`。

支持切开的规范（法律结论须运行时复核）：

- 第 851 条：技术开发合同是就新技术、新产品、新工艺、新品种或者新材料及其系统的研究开发所订立的合同；包括委托开发和合作开发；应当采用书面形式。
- 解释第 17 条：包括订立时尚未掌握的产品、工艺、材料及其系统等技术方案；**对技术上没有创新的现有产品改型、工艺变更、材料配方调整以及对技术成果的验证、测试和使用除外**。
- 第 862 条、解释第 22 条：转让/许可针对**现有**特定专利、专利申请或技术秘密；**就尚待研究开发的技术成果订立的合同不属于转让或许可**。
- 第 770 条：承揽是按定作人要求完成工作并交付工作成果，包括加工、定作、修理、复制、测试、检验。
- 第 878 条：技术咨询是就特定技术项目提供可行性论证、技术预测、专题技术调查、分析评价报告；技术服务是以技术知识解决特定技术问题，不包括承揽和建设工程。

## 节点 2　主体、能力、Key person 与转第三人

### 2.1 主体表

建表：签约名、履行名、付款名、发票名、授权签字人。名称不一致不自动合并。课题组、工作室无法人资格：解释第 7 条，未经所属法人或非法人组织授权或认可的，不得写成已由该组织承担责任。

口头“我们老板同意了”不得写成已授权。国资、高校、上市公司内部决议或科研项目立项未附：该签署能力字段停止，不写成“可以盖章”。

新药临床前、特种设备、人类遗传资源等：文本或用户材料未提及相应许可或备案的，资质字段停止，不编造“已具备法定资质”。

### 2.2 Key person（必须改，非法定义务点名）

技术开发高度依赖人。未锁定核心岗位、替代条件和离职通知的，标必须改。

修改句方向：

- 列**岗位与最低资质**（如项目负责人须具备【待填】年相关研发经历），不要假装法律强制点名某个自然人。
- 更换核心岗位人员须书面通知；实质削弱履约能力的，对方可要求更换或中止相应付款。
- 用户已经点名某研究员且双方要锁人：可写入，但写明离职、病休时的同等资质替代，避免合同因特定自然人无法履约而目的落空。

不得写成：法律规定必须由张某签字才生效。

### 2.3 主要部分转第三人（硬闸）

研究开发工作的**主要部分**交给第三人，须对方书面同意。辅助试验、常规检测、外协加工可另列，但核心方案、关键实验、主要源代码不得擅自转包。

| 文本写法 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 开发方可任意将项目分包、转包或转让合同义务 | 必须改：主要部分须事先书面同意；未经同意构成违约，对方可解除并要求返还未用于本项目的经费 | 已有法定任意转包权 |
| 核心研发已交未具名第三方，正文未披露 | 红线：披露第三人并取得同意，否则不签 | 辅助工作所以不必说 |
| 同意转包但开发方免责 | 必须改：开发方仍就第三人完成的工作向对方负责（第 523、593 条） | 转包后风险转移 |

## 节点 3　标的、成功保证与非法垄断技术

### 3.1 尚待开发与任务书

审查清单，缺一项则该字段不得写成已闭环：

1. 拟开发技术的名称、应用领域、与背景技术的界限。
2. 定量指标：性能参数、精度、标准（国标/行标/企业标准）。禁止单独用“国内领先”“国际先进”。
3. 阶段：方案、初样、测试、试产或现场运行；每阶段完成物和时间。
4. 背景 IP 清单：合作前各自已有技术不因本合同转移。

出现已公开、已鉴定、已授权的现成技术作为唯一标的：回到节点 1，按转让或许可负触发。解释第 9 条：把现有成果当作研究开发标的收取费用，受损害方可请求撤销——标红旗，不改成“继续当开发履行”。

### 3.2 不保证成果必然产生（硬闸）

技术开发的标的具有尚待开发性。合同保证的是**研发义务**（订计划、合理使用经费、专业努力、按约通知），不是成果必然产生。

| 文本写法 | 动作 |
| --- | --- |
| 保证研发成功、保证交付可产业化成果、保证通过任何验收 | 红线删除保证；改成：按任务书实施研究开发；未达约定指标的，按第 3.3 节减酬、限期补救或解除，并区分风险与违约 |
| 保证拿到发明专利、实用新型或软件著作权登记 | 红线删除。可写：开发方应按约定配合申请；授权与否取决于审查机关，不构成违约，除非因开发方迟延、隐瞒或拒不提供申请材料 |
| 保证固定收益、年节约额、利润分成保底 | 红线删除保证。可保留按实际实施收入分成，且分成事件不得写成“保证产生” |
| 鉴于条款写“保证成功转化” | 首部必须改；鉴于不得充当承诺 |

可约定的不是成功保证，而是**未达指标的法律后果**：减酬公式、解除条件、已发生费用如何分担。数字用 `【待填】`。

最强反方：委托方主张“不保证成功等于可以随便做做”。修改句必须保留可核验的过程义务和未尽努力的违约后果。

### 3.3 非法垄断技术（硬闸）

第 850 条：非法垄断技术或者侵害他人技术成果的技术合同无效。解释第 10 条下列情形属于非法垄断技术，必须改或删除，不得写成可放行的“独家对价”：

1. 限制一方在标的技术基础上进行新的研究开发，或限制使用所改进的技术；或交换改进技术的条件不对等（无偿回授、非互惠转让、无偿独占或共享改进技术的知识产权）。
2. 限制一方从其他来源获得与技术提供方类似或与其竞争的技术。
3. 明显不合理地限制实施数量、品种、价格、销售渠道或出口市场。
4. 要求接受并非实施技术必不可少的附带条件。
5. 不合理限制购买原材料、零部件、产品或设备的渠道或来源。
6. 禁止对合同标的技术知识产权的有效性提出异议，或对提出异议附加条件。

| 文本写法 | 本任务动作 | 不得写成 |
| --- | --- | --- |
| 独家开发，故甲方不得自行或委托第三方研发同类技术 | 红线删除禁研。可保留：项目期内就本合同任务书范围内的重复委托须书面告知，但不禁止甲方独立研发或从他处获得竞争技术 | 独家所以合法禁止对方研发 |
| 乙方改进技术无偿回授甲方并归甲方独占 | 必须改：对等互惠，或谁改进谁享有，对方仅有优先商谈或普通许可 | 回授是行业惯例所以有效 |
| 乙方不得质疑甲方背景专利有效性 | 删除。可保留：发现无效事由应及时通知，但不限制依法请求宣告无效 | 已经放弃异议权 |

条款无效不等于整份合同当然无效。修改句删除或改写该条，不在本任务宣告整约无效。

## 节点 4　技术风险分担（硬闸）

第 858 条：因出现无法克服的技术困难，致使研究开发失败或者部分失败的，风险由当事人约定；没有约定或约定不明确，依据第 510 条仍不能确定的，由当事人合理分担。一方发现可能失败的情形，应当及时通知另一方并采取适当措施减少损失；未及时通知并减损的，就扩大的损失承担责任。

与违约切开：第 854、856 条，违反约定造成停滞、延误或失败，承担违约责任。开发方不能证明已尽合理专业努力的，按违约，不按风险。

修改句必须同时写清四件事：

1. **判定程序**：由双方共同委托的【待填】名专家或具备相应资质的第三方机构，就是否属于订立时无法预见、现有技术水平无法克服的技术困难出具书面意见。单方自认“做不了”不构成风险。
2. **通知**：发现可能失败之日起【待填】日内书面通知，说明依据、已采取的措施和后续建议。
3. **资料保全**：实验记录、失败样品、测试数据、过程代码同时封存，供判定使用。
4. **费用分担**：无其他约定时，已发生且用于本项目的经费合理分担；未使用经费返还；任何一方未尽努力或迟延通知的，自行承担扩大损失，并不得就该部分主张风险分担。

禁止：

- 写成开发方对任何失败免责。
- 写成任何未达指标都是违约，不考虑无法克服的技术困难。
- 把技术风险混同不可抗力（战争、自然灾害等）。

第 857 条：作为标的的技术已经由他人公开，致使履行没有意义的，当事人可以解除。修改句补公开后的通知、解除和经费清理。本任务不作出已解除结论。

| 模式 | 无约定时的法定默认（须运行时复核） | 修改句注意 |
| --- | --- | --- |
| 委托开发 | 第 859 条：申请专利的权利属于**研究开发人**；其取得专利权的，委托人可以依法实施；研究开发人转让专利申请权的，委托人同等条件优先受让 | 委托方要单独所有或共有，必须书面约定，并处理委托人实施权和优先受让 |
| 合作开发 | 第 860 条：原则上**共有**；一方转让，其他方优先受让；一方放弃，他方可申请，放弃方可免费实施；一方不同意申请，他方不得申请 | 必须写清共有份额、申请决策、费用分担、不同意申请时的保密 |

禁止编造“无约定一律归委托方”。知识库“归开发者”不得套到合作开发。

### 5.2 技术秘密

第 861 条：使用权、转让权及收益分配由约定；无约定走 510 后，在相同技术方案被授予专利权前，当事人均有使用和转让的权利；但委托开发的研究开发人**交付前不得转让第三人**。

修改句：独占、排他还是普通使用；是否可再许可；收益如何分；交付前禁止对外转让。不得把“均有使用权”写成已取得独占权。

### 5.3 著作权与源代码

计算机软件、图纸、文档的著作权与专利申请权不是同一件事。未约定时不得写成委托方当然享有全部著作权。委托方需要后续维护和二次开发的，必须书面约定源代码、构建脚本、接口文档的交付和使用权或著作权归属。

职务技术成果：第 847–849 条。开发方应保证其参与人员已处理职务成果关系。完成人的表明身份和获奖权利不得用合同剥夺。

### 5.4 后续改进

必须单列。无约定不得编造归委托方。第 875 条（转让/许可节）的分享逻辑：无约定走 510 后，一方后续改进他方无权分享。开发合同仍应自己落句。解释第 10 条第（一）项：无偿不对等回授属于非法垄断，走节点 3.3。

最佳实践修改句：谁改进谁享有；对方在【待填】期限内有权优先商谈普通许可或受让，条件对等。

### 5.5 交付物

开发方不仅交付样机、样品或安装包，还须移交支撑实现的：

- 源代码或工艺配方（按约定加密或托管）；
- 实验记录、测试报告、失败与成功批次数据；
- 图纸、模具参数、物料清单；
- 必要的技术指导，帮助对方掌握成果（第 853 条）。

只交安装包或只交结论页：必须改。背景 IP 与前景 IP 分列，合作不导致背景 IP 转移。

## 节点 6　验收、对价与进出口

### 6.1 验收（硬闸）

第 845 条把验收标准和方法列为技术合同一般条款。本类型验收不得只写“甲方满意”或“签收即合格”。

必须具备：

1. 与任务书指标一一对应的检测方法、样品量和合格判定。
2. 阶段里程碑：方案评审、中试验收、最终验收分别通过才触发对应付款。
3. 复杂系统：第三方检测、专家评审或约定期限的现场运行/试生产考核，至少选一种写入。
4. 异议须书面指出与任务书不符的具体项；开发方在【待填】日内补正；超出约定轮次的需求变更另签。

禁止放行：

> 委托方逾期不验收视为全面合格，并放弃一切技术缺陷索赔。

修改句：逾期未提出书面异议的，仅视为该阶段**形式验收通过**，不视为放弃隐蔽缺陷、指标不符或知识产权瑕疵的主张；付款条件可约定与形式验收挂钩，但质量与权属责任不因此消灭。

### 6.2 对价与经费

研究开发经费与报酬分列。包干还是据实结算写清。预付款 + 进度款 + 验收款。未给出的数字写 `【待填】`。经费须专款专用；挪作他用造成停滞、延误或失败的，按违约（第 854 条），不得主张 858 风险。

定金：必须使用“定金”二字才讨论罚则。约定超过主合同标的额百分之二十：超过部分不产生定金效力。无核验引文不得把 20% 写成现行法结论。

禁止编造单价、总价、节约额。

### 6.3 技术进出口与国家秘密

限制进口技术未经许可不得进口；限制出口技术须向外经贸主管部门申请（技术进出口管理条例第 8、10、31 条）。未取得许可或国家秘密技术出口审查文件：

- 履行字段停止；
- 修改句把批准作为生效或履行条件；
- **不得**写“先履行研发或跨境交付，后补许可证”的可履行路径。

目录条目、密级、许可证号未知：标 `G#`，建议缓签。

## 节点 7　格式条款、免责与争议

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

### 7.1 免责与限额

研究开发失误可约定赔偿上限（如已收经费或报酬的【待填】倍）。间接损失、预期利润可排除。

下列不得排除，排除则必须改：

- 造成对方人身损害；
- 因故意或者重大过失造成对方财产损失（第 506 条）；
- 侵害他人技术成果或知识产权；
- 泄露技术秘密或违反保密约定；
- 擅自将主要部分转第三人造成的损失。

“开发方对研发失败不承担任何责任”且无 858 程序、无除外：必须改。

### 7.2 格式条款

为重复使用而预先拟定、订立时未与对方协商。依据示范文本制作，不当然排除格式条款。免责、限责、禁研、管辖、单方解释权等异常条款须有足以引起注意的标识。小字、夹在附件、仅网络勾选：不得写成已尽提示义务。

### 7.3 违约、解除、争议

逾期进度按日计违约金；指标不达标先补正再减酬，再不能实现目的的可解除。只有“依法承担违约责任”视为必须改。构成违约不等于当然解除。违约金不是必得金额。

争议解决：出现仲裁条款，不得改写成“应向某法院起诉”。或裁或诉、机构不明：标待核，改成单一机构或单一法院连结点。专属管辖可能：只标红旗，不选定唯一法院充作法律意见。

通知送达：微信已读不写成已经到达，除非合同把该渠道写成送达且用户要保留。
