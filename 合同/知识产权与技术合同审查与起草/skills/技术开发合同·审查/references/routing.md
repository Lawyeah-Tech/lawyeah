# 边界与路由

本技能只审查 **技术类合同 / 技术开发合同** 的待签、尚待研究开发文本。中文展示名是「审查技术开发合同（技术类合同）」。

负触发只写触发判定、路由和最小交接，不填十节实体结论。禁止使用半截 ID。

| 主要目标或文本信号 | 路由 |
| --- | --- |
| 类型未定，或名实明显不符 | 本套导航的类型切开步骤 |
| 已有成熟专利、专利申请或技术秘密的权利让与 | `技术转让合同·审查` |
| 已有技术的实施或使用许可 | `技术许可合同·审查` |
| 专利实施许可为主给付 | `专利实施许可合同·审查` |
| 按既有图纸常规加工、复制、测试、检验，成果必然可复制 | `按既有图纸加工定作实物→负触发` |
| 特定技术项目可行性、技术预测、工艺评价、FTO，不出研发成果 | `知产技术咨询·审查` |
| 商务管理咨询意见、战略或行业分析 | `或` |
| 以技术知识解决特定技术问题，无研究开发不确定性 | `知产技术服务·审查` |
| 委托开发作为已独立成册的细分主文件 | `委托开发合同·审查` |
| 双方共同投资并分工参与研究开发 | `合作开发合同·审查` |
| 核心是交付可运行软件而非研发不确定性 | `软件委托开发合同·审查` |
| 落在委托合同目录下的委托技术开发 | `委托合同目录下的委托技术开发主文件且用户未锁定本类型→` |
| 无文本、本类型条件已谈妥、要出己方稿 | `技术开发合同·起草` |
| 已签未争、只问履约节点 | 本套导航的履约步骤 |
| 已成争的普通合同路径 | `或知产争议专项。` 或对应专项领域 |
| 权属诉讼、专利无效或商业秘密侵权已立案 | 知产或争议专项，不在本任务评改 |
| C 端大众快检 | 只分流，不回改 |

技术开发正文里夹带一小段已有背景技术许可或咨询评估：专章交接对应原子；尚待开发条款可继续审。用户坚持本技能把转让、承揽、咨询或纯软件交付整案改完：`目标停止`。

专业版未收录的 P1 场景不会安装本原子。若用户拿 P1 文本来找专业版：输出 `unavailable`，提示，不得用邻类硬套。
