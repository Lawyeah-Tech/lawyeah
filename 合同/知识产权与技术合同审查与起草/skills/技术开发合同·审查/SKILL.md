# 技术开发合同·审查

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现审查反例；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释、已失效《技术合同法》及其实施条例当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成文本与事实审查；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在单一立场下，只审查 **技术类合同 / 技术开发合同** 的待签文本，输出风险表、可回给对方的修改句或红线、谈判与签署提醒。

本技能类型锁死。不扫描其他 289 类。场景分层为 **P0**。中文显示名为「技术开发合同·审查」。

`depends-on` 为空。不要求先跑导航。

不交付：他类文本审查、从零起草、履约交底、争议文书、有效性保证、保证研发成功或拿到专利。

## 本类型硬闸

1. **开发 ≠ 转让 ≠ 承揽 ≠ 咨询**：正像是新技术、新产品、新工艺、新品种、新材料或其系统**尚待研究开发**。不保证成果必然产生，但保证研发义务。已有成熟技术转让/许可 → `技术转让合同·审查` / `技术许可合同·审查`；按既有图纸常规加工、成果必然可复制 → `按既有图纸加工定作实物→负触发`；仅出具咨询意见不研发 → `知产技术咨询·审查` 或 `或`。委托开发细分主文件 → `委托开发合同·审查`；合作开发双方共同投入并分工参与 → `合作开发合同·审查`；纯软件交付导向 → `软件委托开发合同·审查`。标题“技术开发”但正文是买现成软件授权：负触发。
2. **不保证成果必然产生**：禁止放行“保证研发成功 / 保证拿到专利 / 保证固定收益”作为可履行承诺。可约定验收指标与未达指标的减酬、解除、费用分担。
3. **技术风险分担**：无法克服的技术困难导致失败或部分失败，无约定则合理分担；开发方须证明已尽合理专业努力，否则按违约而非风险。修改句写判定程序、通知、资料保全、费用分担。
4. **非法垄断技术**：限制另一方继续研发、限制从其他来源获得竞争技术、不合理回授、禁止质疑知识产权：条款无效，必须改或删除。不得写成“独家开发所以禁止对方自己研发”的可放行结构。
5. **主要部分转第三人**：须对方同意。未经同意转包核心研发：解除或违约。Key person 锁定可作必须改，但不编造法定必须点名某自然人。
6. **成果与 IP 归属**：专利申请权、著作权/源代码、技术秘密、后续改进必须分项写。无约定时按核验后的法定默认（委托 vs 合作不同），不得编造“一律归委托方”。交付物含源代码、实验记录、图纸，不能只交安装包。
7. **验收**：阶段里程碑 + 第三方测试/专家评审/现场运行。禁止“委托方逾期不验收视为全面合格且放弃一切技术缺陷”。

禁止只打红黄绿。每个风险回链文本位置。必须有修改句。

## 工作边界

正触发：已有可读待签技术开发正文，尚未签署，尚未成争，核心给付是对订立时尚不存在、当事人尚未掌握的技术方案进行研究开发，用户问能否签、哪里必须改、怎么回对方。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 已有成熟专利、专利申请或技术秘密的权利让与 → `技术转让合同·审查`；
- 已有技术的实施或使用许可 → `技术许可合同·审查`；专利实施许可 → `专利实施许可合同·审查`；
- 按既有图纸常规加工、复制、测试、检验，成果必然可复制 → `按既有图纸加工定作实物→负触发`；
- 特定技术项目可行性、技术预测、工艺评价、FTO，不出研发成果 → `知产技术咨询·审查`；商务管理咨询意见 → `或`；
- 以技术知识解决特定技术问题、无研究开发不确定性 → `知产技术服务·审查`；
- 委托开发作为已独立成册的细分主文件 → `委托开发合同·审查`；
- 双方共同投资并分工参与研究开发的合作开发主文件 → `合作开发合同·审查`；
- 核心是交付可运行软件而非研发不确定性 → `软件委托开发合同·审查`；
- 落在委托合同目录下的委托技术开发 → `委托合同目录下的委托技术开发主文件且用户未锁定本类型→`；
- 无文本、本类型条件已谈妥、要出己方稿 → `技术开发合同·起草`；
- 已签只问履约节点 → 本套导航的履约步骤；
- 已催告、解除、索赔、诉讼、仲裁或权属诉讼 → `或知产争议专项。` 或知产/争议专项。

以开发为名买卖国家秘密、未批限制进出口技术，或把 850 禁研条款改成可履行结构：只出告知，不改写成可履行路径。

## 建立审查坐标

确认：使用者与授权；单方立场；相对方；全文及附件/任务书版本；标的是否尚待开发；委托或合作；是否保证成功或专利；是否含 850 禁研或回授；核心研发可否转第三人；归属分项；验收安排；进出口或国家秘密；不可接受事项；法域与拟签署日。缺立场或无可读文本则不启动实体审查。同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。冲突版本并列，不自行选取对用户有利的一版。未给出的经费、指标、期限用 `【待填】`，不编造。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验 850 与解释第 10 条、851–861、858 风险、859/860 归属、862 与解释第 22 条转让切开、551 转债务、进出口许可；`search_practiced` 只补审查反例；`search_template` 只借栏目结构。不虚构案件系统。

`search_law` 对上述法律结论为 required 级：不可用时不拒绝执行，只停止效力字段。返回已失效《合同法》或其解释、已失效《技术合同法》或其实施条例时记为噪声，不得写入 `L#`。

## 判断节点

执行顺序和停止条件以 [审查方法](references/method.md) 为准。这里只列入口。本技能固定加载：

- [基本面](references/基本面.md)
- [框架](references/框架.md)

禁止打开其他类型目录。`基本面.md` 中“专利申请权无约定归开发者”不得写成一律规则：委托开发默认归研究开发人，合作开发默认共有。`框架.md` 中“逾期不验收视为合格”若写成放弃一切技术缺陷，必须改。

### 0. 签署状态与成果分流

无文本且本类型条件已谈妥 → `技术开发合同·起草`；已签履约 → 本套导航履约步骤；已成争 → 合同争议或知产。未签且目标是评改已有技术开发文本，才进入本任务。

### 1. 类型锁死

标题、核心给付与对价方式一致才继续。转让、许可、承揽、咨询、纯软件、细分委托/合作主文件负触发。

### 2. 主体、能力与转第三人

签约名、履行名、付款名、发票名分列。核心研发转第三人须同意。Key person 可锁岗位与资质，不编造法定点名自然人。

### 3. 标的、成功保证与 850

任务书定量化。删除成功/专利/固定收益保证。禁继续研发、禁他源技术、不对等回授、禁质疑 IP：必须改或删除。

### 4. 技术风险

判定程序、通知、资料保全、费用分担。未尽合理专业努力按违约，不按风险免责。

### 5. 归属与交付物

专利申请权、著作权/源代码、技术秘密、后续改进分项。无约定不得编造一律归委托方。不能只交安装包。

### 6. 验收、对价与进出口

阶段里程碑 + 第三方测评。禁止拟制全面合格并放弃缺陷。未批进出口或国家秘密：履行字段停止。

### 7. 格式条款与强制规范

无核验引文则法律结论字段停止。

### 8. 按框架六步出修改句

必须有可回给对方的修改句或红线。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；无书面文本仍要实体意见；用户坚持倒签、保证有效、把禁研/未批进出口/国家秘密改成可履行结构、坚持保留成功保证或 850 禁研条款。
- `字段停止`：法域、动态规则、进出口目录、国家秘密审批、行业许可未核验。
- `目标停止`：主目标已变为从零起草、履约交底、争议文书，或已锁他类。
