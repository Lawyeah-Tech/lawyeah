# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、指标、工期；把已失效《合同法》《技术合同法》及其实施条例写入结论；保证秘密永远不被反向工程或永远具有竞争优势；把许可、专利转让、开发或服务文本当成已完成的本类型审查；写“未向专利局登记则本合同未生效”；写“先交核心后补进出口许可证”；在意见中复述配方、关键参数或完整源码。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查技术秘密转让合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `技术秘密转让合同`。定性理由、易混切开结果（许可 / 专利权转让 / 专利申请权转让 / 笼统技术转让 / 开发 / 服务 / 软件著作权）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属、在先许可与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。权属表：合法拥有声明、职务成果、共有、已向第三人许可的范围与可否买断。版本表：正文、密级目录、交接清单、NDA、指导计划、聊天确认；冲突并列。意见只引用载体编号，不摘录秘密内容。

## 5. 秘密性、披露、给付与验收

保密期限是否随秘密状态存续；披露是否分阶段、是否用密级目录；是否黑盒；买断后让与人是否停用及不得再处分；交付资料与指导；价款与节点；还原性测试与验证期；第三方合法公开后的价款安排。缺口标 `G#`。不输出专利登记生效口径，不输出许可续期口径。

## 6. 格式条款、强制规范与进出口

是否构成格式条款；提示说明痕迹。850 条款不得写成可放行。强制规范只按第 153 条和合同编通则解释第 16 条区分，不用失效口诀。技术进出口或国家秘密未批准：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。原文摘录不得含配方、关键参数或源码正文。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把独占/排他/普通许可方式直接写成“转让类型”而不问是否买断。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为许可或专利转让、保密期限自动解密、主文泄密、黑盒、明知侵权、未批进出口/国家秘密），再必须改（密级目录、分阶段披露、权属与在先许可、指导与验证期、850/回授、泄密后果），最后可优化。签署提醒：授权、用印、日期、密级目录与交接清单、接收确认书、首笔价款到账后再交核心。不指导倒签或先交核心后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是许可、专利转让、开发或服务安排。
