# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、指标、保护期；把已失效《合同法》《技术合同法》及其实施条例写入结论；保证独创性永不被撤销或必然可流片；把许可、专利权转让、软著转让或技术秘密文本当成已完成的本类型审查；写“无须向国知局登记权利即已转移”；写“先交 GDS 后补向外国人转让批准”；在意见中复述 GDS、网表或掩膜数据；套用专利年费维持或软著登记对抗口径。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查集成电路布图设计专有权转让合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、已失效《技术合同法》或其实施条例时，记噪声，不得写入 `L#`。条例转让专条未命中全文时，不得把记忆条号写成已核验 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `集成电路布图设计专有权转让合同`。定性理由、易混切开结果（许可 / 专利权转让 / 软著转让 / 技术秘密转让 / 笼统技术转让 / 植物新品种 / 开发）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属、在先许可与文本版本

主体表：签约名、证书记载权利人、履行名、付款名、发票名、授权签字人。权属表：登记号、共有、职务布图、已向第三人许可或出质的范围与可否买断。版本表：正文、电子数据清单、证书、变更委托书、聊天确认；冲突并列。意见只引用清单编号，不摘录版图数据。

## 5. 专有权范围、登记、给付与验收

两项专有权是否写全；是否误写思想/工艺/专利；剩余保护期是否可算；合同生效与著录变更是否分列；GDS 交付与 EDA 验证；价款与节点；变更合格通知书。缺口标 `G#`。不输出“无须登记即已取得专有权”，不输出许可续期或按晶圆提成作为买断主对价。

## 6. 格式条款、强制规范与跨境

是否构成格式条款；提示说明痕迹。850 条款不得写成可放行。强制规范只按第 153 条和合同编通则解释第 16 条区分，不用失效口诀。向外国人转让未提交主管部门允许证明：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。原文摘录不得含 GDS、网表或掩膜数据正文。

## 8. 修改句

按已加载 `框架.md` 的六步组织，但须按 method 节点 8 重映射（框架正文是技术秘密错配，不得按其“无须登记”“独占/排他/普通转让”“永久保密生命线”出句）。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为许可、未登记卖权、买到即到期、范围写成思想或专利、未批向外国人转让、黑盒 GDS），再必须改（登记号与两项专有权、著录变更义务与节点、权属与在先许可、EDA 验证、独创性/撤销安排、恶意改数据），最后可优化。签署提醒：授权、用印、日期、电子数据清单、变更委托书、证书原件交接、首笔到账后再交核心数据。不指导倒签或先交后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是许可、专利权转让、软著转让或技术秘密安排。
