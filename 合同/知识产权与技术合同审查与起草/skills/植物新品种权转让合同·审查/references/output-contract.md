# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、登记或批准一定办成；编造未给出的价款、数量、保护期届满日；把已失效《合同法》、1997／2014 年条例旧保护期或“农业自公告／林业自登记”旧分工写入结论；把许可、专利权转让、布图转让或软件著作权文本当成已完成的本类型审查；写“未向专利局登记则本合同未生效”；写“先交繁殖材料后补对外批准”；在意见中复述亲本配组或未公开育种参数。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查植物新品种权转让合同（技术类合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1997／2014 年条例旧义、2000 年种子法同号旧义时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `技术类合同`，子级 `植物新品种权转让合同`。定性理由、易混切开结果（许可 / 专利权转让 / 专利申请权转让 / 布图转让 / 软件著作权 / 笼统技术转让 / 技术秘密）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权属、共有与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。权属表：品种权人／申请权人、职务或合作育种、共有、已向第三人许可的范围与可否买断、出质。版本表：正文、品种权证书副本、繁殖材料移交清单、亲本交接清单、审批许可文件、聊天确认；冲突并列。意见只引用载体编号，不摘录亲本配方。

## 5. 品种身份、审批登记、繁殖材料与年费

品种名称与品种权号是否锁定；保护期按 25／20 年核算剩余寿命；合同成立与转让自登记之日起生效是否切开；对外转让是否先批准；繁殖材料数量质量与田间观察期；杂交亲本是否在范围内；年费缴纳主体。缺口标 `G#`。不输出专利局登记口径，不输出许可续期口径。

## 6. 格式条款、强制规范与跨境／转基因

是否构成格式条款；提示说明痕迹。未批对外转让、未批出境种质不得写成可放行。强制规范只按第 153 条和合同编通则解释第 16 条区分，不用失效口诀。转基因安全证书未附：履行字段停止。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。原文摘录不得含亲本配组、选育参数或未公开育种技术正文。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把独占／排他／普通许可方式直接写成“转让类型”而不问是否买断。不得把保护期改回 20／15 年。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为许可或专利权转让、未批对外转让、先交后补批、改品种名称、拟制签收放弃种性抗辩、未批出境种质），再必须改（登记协作与年费、繁殖材料与观察期、亲本范围、共有／在先许可／出质、对价与登记／验证挂钩），最后可优化。签署提醒：授权、用印、日期、品种权证书副本、繁殖材料移交清单、对外批准文件（如有）、首笔价款到账后再交核心亲本。不指导倒签或先交后补批。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是许可、专利权转让、布图转让或软件著作权安排。
