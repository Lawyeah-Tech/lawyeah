# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的价款、地域、保护期；把已失效《合同法》、1990 年未修正《著作权法》或其 1991 年实施条例写入结论；保证备案或登记一定办成；把许可、委托创作、软件著作权本约或商标转让文本当成已完成的本类型审查；写“未备案则本合同未生效”；写“人身权已随转让移转”；把原件交付写成全部财产权已移转。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查著作权转让合同（知识产权相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1990 年未修正著作权法或 1991 年实施条例时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `知识产权相关合同`，子级 `著作权转让合同`。定性理由、易混切开结果（许可 / 委托创作 / 合作创作 / 软件著作权 / 商标转让 / 原件买卖）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、权源、在先负担与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。权源表：作者／继受人／职务单位／制片者／委托约定；合作作者是否全体签署；集管、出质、在先专有或非专有许可。版本表：正文、作品与权利清单、权属声明、共有人／单位同意书、在先许可清单、载体交接单、聊天确认；冲突并列。

## 5. 人身权切割、权利清单、给付与书面／备案

人身权是否被写成转让标的；第十条财产权是否逐项列举；地域、价金、支付日期和方式、违约责任是否齐；书面是否具备；备案／登记是否被误写成生效要件；原件与财产权是否分条；价款是否与交载体／交权属文件／配合备案挂钩。缺口标 `G#`。不输出许可续期口径，不输出商标核准或专利登记生效口径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。人身权卖断、明知无权处分、禁止传播作品不得写成可放行。强制规范只按第一百五十三条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把专有／非专有许可方式直接写成“转让类型”而不问是否让与。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为许可或委托创作、人身权卖断、不列权利种类、合作作者未全体签署、明知无权处分），再必须改（第二十七条必备项、原件与财产权分条、在先许可披露、备案配合义务、价款节点），最后可优化。签署提醒：作者亲签或有权单位公章、合作作者全部签署、授权书须含“转让著作财产权”、作品与权利清单、权属声明、载体交接单。不指导倒签或把未备案写成合同无效。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是许可、委托创作、软件著作权或商标转让安排。
