# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的佣金、套数、期限；把已失效《合同法》委托章或居间章写入结论；把仅交定金写成已成交；把按揭未放写成可无限拖佣；把自然到访洗成渠道客户；把未核备案写成可以展业；把购房款改入渠道私户；把返佣/洗客/截客改成可履行结构；把全案、经销或行纪当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查渠道销售委托代理合同（买卖合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》委托章、居间章或其解释、已失效《城市房地产中介服务管理规定》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `买卖合同`，子级 `渠道销售委托代理合同`。定性理由、易混切开结果（全案 `房地产全案销售代理·审查`、经销 `经销买卖合同·审查`、行纪 `购房人终端订立本约，也不自负本约权利义务。以自己名义成交或先买后转→负触发`、销售代理、存量房中介、商品房本约）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、备案、委托书与文本版本

主体表：签约名、履行名、付款名、发票名、授权签字人。资格表：经纪机构备案痕迹、委托书是否出具。版本表：正文、报备流程、佣金标准表、到访确认单样张、廉洁协议、聊天确认；冲突并列。未核备案或委托书：该签署能力字段停止。

## 5. 渠道给付、报备闭环、结佣与购房款

核心给付是否仅为引流推介；是否夹带驻场、买断或以自己名义成交；独家或非独家；报备有效期与判重；结佣节点与退房退佣；购房款账户是否出卖人户或监管户。缺口标 `G#`。不输出全案驻场排班、经销货权过户或行纪介入权主路径。

## 6. 返佣、格式条款与强制规范

禁止私自返佣/截客/洗客；防绕开是否限定“利用该报备或带看”。是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效口诀。返佣/洗客/未达预售条件只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“CRM 唯一依据”写成开发商单方不可复核。

## 9. 谈判与签署提醒

谈判顺序：先红线（买断/全案/行纪错位、返佣/洗客、房款进私户、定金即结佣），再必须改（报备闭环、结佣与退房退佣、非独家、终止后结佣、备案委托书），最后可优化。签署提醒：委托书与备案证明入附件；《客户报备及成交确认书》样张、佣金标准表、廉洁协议入附件。不指导倒签或补假备案。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务成果是可编辑草稿、未决项、自审风险表和自审后修改句。有完整待签文本要评改转 `渠道销售代理·审查`。草稿必须落入本类型起草必写 / 附件必附 / 禁止出现。不是履约交底、争议文书、佣金诉讼策略或效力保证，也不是全案、经销、行纪或商品房本约审查。
