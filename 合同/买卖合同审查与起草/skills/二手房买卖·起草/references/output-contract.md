# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、必然过户、户口必然迁出或对方接受；编造未给出的房价、面积、税负；把已失效《合同法》《物权法》写入结论；把商品房预售规则硬套本类型。

## 1. 触发、单方立场与成果状态

立场（买方／卖方）、授权、签署状态、主要目标。预售稿、已过户求解除或其他负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》《物权法》及其解释时记噪声，不得写入 `L#`。返回商品房预售专属规则时标明“不适用本类型”，不得写入默认法。

## 3. 类型与加载路径

父级 `买卖合同`，子级 `二手房（存量房）买卖合同`。写定性理由和与预售／经适房／共有产权／让与担保／中介的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。阴阳合同或规避限购写停笔告知，不填可履行避税／过限购结构。

## 4. 主体、授权、权属人与文本版本

主体表：登记权利人、签约名、收款名、配偶、其他共有人、承租人、受托人。版本表：正文、附件、网签稿、居间确认、聊天记录；价格冲突按阴阳合同处理，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定检查并回链文本：

- 标的与登记簿是否一致（坐落、面积、用途、土地性质、随房车位储藏室）；
- 权利负担：抵押、查封、居住权、预告／异议登记；
- 共有人与配偶签署是否闭合；
- 户口在册人员、迁出时限、保证金；
- 单一成交价；资金监管账户与释放条件；
- 解押 → 网签 → 缴税 → 转移登记 → 交房的顺序及未完成后果；
- 税费承担清单（契税对外纳税人 vs 对内承担人）；
- 贷款未批、限购无法网签时的退出。

缺口标 `G#`，不补商业数字。网签、登记写成义务或条件，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款（含示范文本填充）；提示说明痕迹。强制规范只区分是否导致民事行为无效与是否仅造成履行障碍（限购、网签、监管）。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。硬闸六项若文本或事实触及，必须各有至少一行，不得用色块代替。

## 8. 修改句

按框架六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止输出商品房面积误差百分之三公式充当修改句。

## 9. 谈判与签署提醒

谈判顺序：先红线（查封、阴阳合同、共有人、无监管大额支付），再必须改（户口、解押、税费、顺序），最后可优化。签署提醒：全体产权人及配偶到场或核验授权、用印、日期不得倒签、附件清单、登记簿查询时点、监管开户凭证。不指导倒签或补假完税。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务成果是可编辑草稿、未决项、自审风险表和自审后修改句。有完整待签文本要评改转 `二手房买卖·审查`。草稿必须落入本类型起草必写 / 附件必附 / 禁止出现。不是履约交底、争议文书、过户代办或效力保证。
