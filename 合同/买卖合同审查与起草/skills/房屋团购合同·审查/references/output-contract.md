# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然成团或网签必然沿用团购价；编造未给出的价格、套数、证号；把已失效《合同法》及其解释、已被删除的 2003 年商品房解释第 7、8、9、14 条写入结论；把个卖面积 3%/先验房主路径当作本任务已完成。

## 1. 触发、单方立场与成果状态

立场（拟入团买受人、单位组织方、中间服务方或开发企业出卖人）、授权、签署状态、组织模式（单位团购 / 中间方 / 混合）、预约或已被材料推成疑似本约、主要目标。负触发写路由，不启动实体审查。已网签后要解除：负触发转争议。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、2003 年商品房解释被删条文、1994 年房地产管理法第 45 条再转让旧义时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `买卖合同`，子级 `房屋团购合同`。定性理由必须写清：是否存在成团基数换优惠、组织方或中间方、本文件是否主要锁定名单/房源/团购价并预约转本约。易混切开结果必须点名是否排除：`一般商品房买卖合同·审查` 个卖本约、`房屋整售合同·审查` 整售、`房产定制销售合同·审查` 定制、`二手房买卖·审查` 二手房、`经济适用房买卖合同·审查` 经适房、`产权式酒店买卖合同·审查` 产权式酒店。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。挂靠、规避限购、阴阳合同、无证预售、中间方代收房款写停笔告知，不填可履行结构。

## 4. 主体、授权、组织模式与文本版本

主体表：签约名、组织方/单位、中间方（代理商或服务商）、开发企业出卖人、拟指定买受人、履行名、**购房款收款账户名**、服务费收款名、发票名（房款 / 服务费分列）、授权签字人。名称不一致不自动合并。

组织模式表（每行：角色｜文本自称｜材料能支持的地位｜缺口）：

- 单位是组织者还是被写成买受人
- 中间方是否出示销售委托书和商品房有关证明文件
- 指定员工是否被约定可直接请求开发商签约
- 三方签章是否抽位

版本表：团购协议正文、团购服务协议、名单及份额表、房源及价格表、正式网签模板、委托书、宣传/入园资料、聊天确认。冲突并列，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定回答，缺项标 `G#`，不补商业数字：

- 本文件是预约还是已被材料推成疑似本约（是否具备销售管理办法第 16 条主要内容且已收受购房款）
- 转本约条件：最低成团**且**预售许可/现售条件 + 启动网签的责任主体、期限、未完成后果
- 预留房源是否锁定到栋/户型/比例；选房顺序
- 团购价是一口价还是阶梯价；公式是否写成 `实付总价=（备案单价×折扣）×建筑面积 - 团购抵减额`
- 是否有最惠待遇 / 差价补偿
- 是否约定团购价独立效力、不被后续网签格式价覆盖
- “5 万抵 10 万”等：前款是定金、意向金还是服务费；后款是减免总价还是计入总价
- 服务费是否抵扣房款；服务费由谁开票、房款由谁开票
- 购房款/定金/意向金收款账户是否该项目预售资金监管账户（户名、账号、监管银行）
- 未达销售条件是否已收取任何预订款性质费用
- 成团失败：退还期限、是否无息、是否互不违约
- 开发商拒签本约：对组织方违约金 + 对买受人定金双倍或预约违约金
- 限购或政策退出：是否无损退款（只描述文本，不设计借名）
- 名单置换次数、截止日、指定人条款
- 批准、登记、网签写成生效条件或期限，不写成已经完成

## 6. 格式条款、强制规范与宣传

是否构成格式条款；团购制式文本、入园系统勾选不排除格式条款；提示说明痕迹；成团失败不退、最终解释权、最终以网签为准、中间方代收免责等异常条款。强制规范只区分是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

宣传/团购优惠/配套：列出用户或材料中的具体允诺，标明是否已写入合同或附件。未写入且具体确定、影响订约或房价：必须改。限购、阴阳、借名：只告知，不改结构。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔/转出口径。禁止输出无修改句的色块表。

本类型默认应出现（有事实则单列，无事实则在缺口节说明未检出）：预约/本约错位、组织模式/抽位、成团与阶梯价、价格独立、名单与指定人、非监管户或中间方代收、未达销售条件预订款、成团失败退款、拒签本约、网签模板未锁定。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`，不编造。

资金路径建议句必须写出“直接支付至主管部门公布的该项目预售资金监管账户”，账号用 `【待填监管账号】`。价格建议句必须含独立效力，不得以“双方协商”或“以网签为准”收尾。成团失败建议句必须含期限+全额无息+互不违约。

## 9. 谈判与签署提醒

谈判顺序：先红线（无证收款、中间方代收、抽位、规避限购、阴阳价），再必须改（转本约条件、成团与阶梯价、价格独立、名单指定人、成团失败/拒签、网签模板），最后可优化。

签署提醒：核预售证范围是否覆盖预留房源；监管账户与项目一致后再付款；三方签章齐全；名单与房源表、网签模板作为附件骑缝或逐页确认；不倒签；不指导先付款后补证；不指导借名入团。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务成果是审查意见与修改句，不是整份起草终稿。无文本或要出己方稿转 `房屋团购合同·起草`。不是履约交底、争议文书、效力保证、成团保证或学区保证。单套本约面积、交付、先验房等个卖闸如需继续，转 `一般商品房买卖合同·审查`，不在本任务代做。
