# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、规划必然获批、对方必然接受或工期必然赶上；编造未给出的价款、工期、面积、荷载或电容量；把已失效《合同法》写入结论；把一般商品房预售规则整份硬套本类型。

## 1. 触发、单方立场与成果状态

立场（买受／定制需求方，或出卖／开发方）、授权、签署状态、主要目标。标准预售稿、整售稿、存量房稿或其他负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释时记噪声，不得写入 `L#`。返回一般商品房预售专属规则时标明“先判断是否确有前置定制，不得据此改走 `一般商品房买卖合同·审查`”。

## 3. 类型与加载路径

父级 `买卖合同`，子级 `房产定制销售合同`。写定性理由和与一般商品房、房屋整售、存量房、施工总包的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。挂靠、违法分包或伪造规划批准写停笔告知，不填可履行规避结构。

## 4. 主体、授权、资质与文本版本

主体表：签约名、履行名、付款名、发票名、最终产权登记人、授权签字人、内部决议机关。资质表：房地产开发资质；代建或自行施工时的工程管理／施工资质。版本表：正文、技术任务书／TRD、深化图纸、封样清单、规划报批材料、聊天或会议纪要；冲突并列，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定检查并回链文本：

- 定制规格是否量化到可验收（荷载标准值／设计值、电力容量、指定品牌及型号、别墅花园／地下室／车库）；
- 报规报建责任主体、规划变更是否已批或作为生效／履行条件；
- 工期节点：设计确认、变更申报、封顶、竣工验收、定制验收、交付；迟延确认与顺延规则；
- 面积四分法：规划面积、约定面积、实测产权面积、定制引起的增减及计价；花园／地下室单列；
- 价款构成：基础房屋价款与定制差价／增项；变更造价由谁承担；
- 两阶段验收：法定竣工验收与个性化定制验收、带电试运行或异议期；
- 期房：预售许可是否被文本或材料提及（有许可不改类型；无许可且构成预售则标红线，不假装有效）。

缺口标 `G#`，不补商业数字。规划批准、预售许可、竣工验收写成条件或义务，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款（含商品房示范文本填充后的“缺货改同档次”）。提示说明痕迹。强制规范只区分是否导致民事行为无效与是否仅造成履行障碍（规划未批、预售未许可、限购）。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。硬闸四项若文本或事实触及或沉默，必须各有至少一行，不得用色块代替。

## 8. 修改句

按框架六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止输出“参考品牌／同等档次”充当交付标准，禁止用面积误差百分之三公式吞掉定制改造。

## 9. 谈判与签署提醒

谈判顺序：先红线（无技术任务书、核心指标不可验收、规划违法定制、期房无预售许可却要放行、挂靠），再必须改（工期节点、面积四分法、两阶段验收、指定品牌及备选），最后可优化。签署提醒：最终产权登记人与内部决议、用印、日期不得倒签、附件签章（蓝图、封样、TRD）、规划批复或报批责任条款。不指导倒签或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务成果是可编辑草稿、未决项、自审风险表和自审后修改句。有完整待签文本要评改转 `房产定制销售合同·审查`。草稿必须落入本类型起草必写 / 附件必附 / 禁止出现。不是履约交底、争议文书、报规代办或效力保证。
