# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然过户或必然排除执行；编造未给出的债权额、房价、证号；把已失效《合同法》及其解释、法释〔2002〕16 号写入结论；把工抵房写成当然优于抵押权。

## 1. 触发、单方立场与成果状态

立场（开发商／债权人／指定买受人）、授权、签署状态、主要目标。负触发写路由，不启动实体审查。已过户或已成争要排除执行：负触发转争议。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释或法释〔2002〕16 号时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `买卖合同`，子级 `以房抵债（“工抵房”）合同`。定性理由必须写清：原债权性质、履行期是否届满、买受人是债权人还是指定人、是否排除让与担保和普通买卖。

加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。挂靠、虚假抵债、规避限购、二房东转售写停笔告知，不填可履行结构。

## 4. 主体、1+N 版本与授权

主体表：开发商签约名、债权人（施工方）签约名、买受人、履行名、**收款账户名**、发票名、授权签字人。名称不一致不自动合并。

1+N 清单（每份一行：名称｜是否已提供｜是否三方会签｜与房号／债权额是否对齐）：

- 开发商与债权人的以房抵债协议
- 开发商、债权人、买受人的三方结算／指定／转让协议
- 开发商与买受人的商品房买卖合同或网签稿
- 结算单／对账单／欠款确认
- 收据或房款确认函样张
- 优先受偿权安排或声明（如有）

版本冲突并列，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定回答，缺项标 `G#`，不补商业数字：

- 原债权：项目名称、基础合同、已结算额、欠付额、履行期是否届满
- 抵债性质：届满后清偿安排 / 届满前担保嫌疑 / 依据不足
- 房号是否锁定；买卖合同总价与债权额如何折算；差额谁补、补给谁
- 旧债消灭时点：网签 / 过户 / 交房 / 其他；未完成是否恢复原债权
- 买受人付款流向：是否禁止向施工方直接付款
- 发票：开发商是否向买受人全额开具销售发票；债权人是否向开发商开具工程款发票
- 抵押、查封、预告登记：已披露 / 未披露 / 依据不足
- 网签、预告登记、交付、转移登记的责任主体、期限、未完成后果
- 买受人身份：债权人自己 / 指定第三方；指定权是否写明
- 优先受偿权：保留 / 就本套对应金额安排 / 概括放弃（须标建筑工人利益风险）
- 消费者购房保护：主张 / 不主张 / 依据不足（不得默认成立）
- 批准、登记、网签写成生效条件或期限，不写成已经完成

## 6. 格式条款、强制规范与违法结构

是否构成格式条款；示范文本不排除格式条款。强制规范只区分是否导致民事行为无效。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

点名：虚假抵债／恶意串通；挂靠或违法分包基础合同；规避限购；无证预售；二房东转售。只告知，不改成可履行路径。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。级别不是成果：每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

本类型默认应出现（有事实则单列，无事实则在缺口节说明未检出）：抵债真实性、履行期届满前／后、旧债消灭与回溯、付款流向、优先受偿／消费者切开、三方会签。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`，不编造。

硬闸五项凡触及或原文沉默，必须有对应修改句：真实性担保与结算附件；履行期与旧债消灭时点；网签／过户落空回溯及优先权／消费者口径；让与担保或普通买卖若误写入正文则写出转出口径或删除担保／回购句。禁止以“依法处理”收尾。

## 9. 谈判与签署提醒

谈判顺序：先红线（虚假债权、流押、查封、二房东转售、买受人向施工方付款、无证预售），再必须改（结算附件、消灭时点、差额、发票、预告登记、退款路径），最后可优化。

签署提醒：三方会签；结算单原件核对；开发商收据确认抵销金额；不向施工方场外付款；网签时限与预告登记；不倒签履行期；不指导补假结算。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。本任务成果是可编辑草稿、未决项、自审风险表和自审后修改句。有完整待签文本要评改转 `以房抵债工抵房·审查`。草稿必须落入本类型起草必写 / 附件必附 / 禁止出现。不是履约交底、争议文书、效力保证、过户保证或排除执行保证。
