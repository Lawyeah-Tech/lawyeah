# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然可执行；编造未给出的基准日、评估值、对价、债权人名单；把已失效《合同法》第九十条或 1993／2005／2018 年公司法旧分立条号写入结论；保证工商一定办成；保证内部债务分割已对外免责；保证特殊性税务处理一定获准；把合并、减资、资产收购或债务转移文本当成已完成的本类型审查；把知识库误植的“三十日／四十五日要求清偿或提供担保”写成内资公司分立的普遍法定权利。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查公司分立合同（公司相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1993 年公司法第六十六条旧义或已修改的旧分立条号时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `公司分立合同`。定性理由、易混切开结果（合并 / 减资 / 资产收购 / 债务转移 / 股权转让）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。挂靠、违法分包或以分立逃债写停笔告知，不填可履行逃债结构。

## 4. 主体、决议、版本

主体表：被分立公司、拟存续公司、拟新设公司（可写“拟设立”）、全体股东、授权签字人。决议表：股东会是否已作、表决比例是否可见、异议股东是否点名。版本表：正文、资产负债表及财产清单、债权债务清单、职工安置、股东会决议、债权人通知／公告草稿、聊天确认；冲突并列。

## 5. 派生／新设、财产清单、债务连带与通知公告

是否点名存续分立或解散分立；人的分立还是物的分立；财产清单是否逐项；内部债务安排是否冒充对外免责；十日通知、三十日公告的义务主体与起算；登记是否被写成合同成立要件。缺口标 `G#`。不输出减资清偿担保主路径，不输出合并协议对价换股主路径。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。逃废债务、伪造通知、倒签决议不得写成可放行。强制规范只按民法典第一百五十三条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把“按资产比例分担”直接写成对外免责。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为合并或减资、内部安排消灭连带、无清单仍要交割、逃债结构），再必须改（点名派生／新设、通知公告义务、决议附件、人员安置、追偿），最后可优化。签署提醒：被分立公司公章、全体股东签章、股东会决议作为附件、资产负债表及财产清单、债权债务清单、职工安置方案、通知与公告草稿。不指导倒签决议日或补假通知。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书或效力保证，也不是合并、减资、资产收购或单笔债务转移安排。
