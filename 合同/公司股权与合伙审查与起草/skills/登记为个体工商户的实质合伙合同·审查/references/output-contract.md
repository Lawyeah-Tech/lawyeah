# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然可登记或必然可执行；编造未给出的出资、分配、估值；把已失效《民法通则》个人合伙章、已失效《城乡个体工商户管理暂行条例》或已失效《个体工商户登记管理办法》写入结论；把对内分担写成对外免责；把内部协议写成已经对抗善意第三人；把隐名合伙或个人合伙当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查登记为个体工商户的实质合伙合同（合伙合同相关）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《民法通则》个人合伙章、已失效《城乡个体工商户管理暂行条例》、已失效《个体工商户登记管理办法》或已失效《合同法》及其解释时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `合伙合同相关`，子级 `登记为个体工商户的实质合伙合同`。定性理由、易混切开结果（隐名合伙、个人合伙、普通/有限合伙企业、劳务出资型、股权激励型、借款、劳务/劳动合同）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、登记外观、组成形式与文本版本

主体表：登记名义人、非登记实质合伙人、签约名、出资名、授权签字人。登记表：拟用字号、执照路径、组成形式（个人经营/家庭经营）、特许许可。版本表：正文、出资清单、资产清单、执照复印件、家庭成员告知、聊天确认；冲突并列。未核执照路径或家庭财产：该签署能力字段停止。

## 5. 财产锁定、对外责任、执行与退伙

字号与经营财产是否锁定为合伙财产；账户是否混同；对外连带与内部追偿是否分行；家庭经营分层是否写明；证照与公章是否共管；退伙是注销还是变更经营者及估值办法。缺口标 `G#`。不输出隐名合伙“不经营不担债”或合伙企业执照主路径。

## 6. 格式条款与强制规范

是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效“效力性/管理性”口诀。挂靠、出借执照、规避准入、对外豁免连带只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的质押或公司化过渡写成法定义务。

## 9. 谈判与签署提醒

谈判顺序：先红线（对外免责、内部协议对抗任何第三人、挂靠规避、保底借贷、只分红不亏损），再必须改（名实分离鉴于、对外连带明示、财产锁定、证照共管、退伙变更、家庭经营分层），最后可优化。签署提醒：全体合伙人签名；执照复印件、资产清单、出资凭证、家庭成员告知入附件；变更或注销义务主体、期限。不指导倒签或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、清算诉讼策略或效力保证，也不是隐名合伙、个人合伙或合伙企业审查。
