# 审查方法（锁定 公司相关合同 / 债务转移三方协议）

本技能不得改换类型。只加载同目录 `基本面.md` 与 `框架.md`。禁止通读其他类型，禁止打开代付款、债权收购或债权转让双文件“对照一下”。

本文件是**债务人将已特定债务转移给第三人、须经债权人同意**的签前判断节点，不是栏目说明书，也不是债权让与通知清单或代付款结算清单。禁止把“通知债务人即可”“从权利随同转让”“禁止转让特约对抗善意第三人”写入本类型默认结论。

每个会改变放行、修改句或转出结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出必然有效、必然无效、原债务人必然免责、担保必然存续、对方必然接受或唯一必得金额。

`search_law` 返回已失效《合同法》第八十四条及其解释、《担保法》及其解释、1994 年《关于审理经济合同纠纷案件有关保证的若干问题的规定》时记为噪声，不得写入 `L#`。返回第六百九十六条（债权转让通知保证人）时，只作与第六百九十七条的对照，不得把通知保证人写成债务转移的主路径。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突。

示范文本只参考结构。市场监管或行业协会债务承担示范文本不证明本约条款已被接受。

### 双文件使用（标题与文件名不完全对应时不拒跑）

同目录两份知识文件按标题语义使用，不回改正文，不因文件名拒跑：

- 含“首部 / 交易条款 / 配套 / 尾部 / 语言”的当框架级条款清单，供节点 8 出句；
- 宏观的类型切开、债权人同意、免责与并存、担保脱落由本方法节点承担。知识稿把“债权人未盖章即不同意／协议无效”一笔写死的，**降级**：对债权人可能不发生效力，但不把原债务人与新债务人之间的约定写成当然无效。知识稿把“本协议通常指免责的债务承担”写成默认结论的，**降级**：文本未写明原债务人退出前，不得写成已经免责。
- 文件不可用（空、代码块、与本类型明显无关）：记 `G#`，用本方法节点继续，不得改去加载代付款或债权收购双文件，不得编造同意日或免责结论。

## 节点 1　类型识别与负触发

### 1.1 本类型正像

同时满足才继续：

- 存在已特定（或可特定）的原债务：能指向原合同、债权人、原债务人和未偿范围；
- 核心给付是该债务的全部或部分改由第三人作为债务人向债权人履行；
- 文本寻求债权人同意，或虽未写同意但把原债务人写成已经退出。

标题写成“债务转移协议”“债务承担协议”“三方还款协议”只是线索。名实不符按核心给付归类，标题冲突写入 `C#`。

### 1.2 必须切开（禁止两套知识）

| 信号 | 归入 | 本技能动作 |
| --- | --- | --- |
| 第三人只负责向债权人付款，原债务人不退出；第三人不付则原债务人仍向债权人担责 | 代付款三方协议（第三人履行） | **负触发** → `代付款三方协议·审查`。不得当免责转移审 |
| 债权人把它对债务人的债权卖给收购方，债务人主体不变，关键动作是通知债务人 | 债权收购合同 | **负触发** → `债权收购合同·审查`。不得把通知债务人写成债权人同意 |
| 不改变债之内容，债权人将债权让与第三人 | 债权转让合同 | **负触发** → `主给付是债权让与通知债务人为轴→`。不得复制可转让性／通知／从权利主路径 |
| 主文是保证、抵押、质押，转移只是背景一句 | 担保主文件 | **负触发** → `主文件是保证或抵押借款→`／`或`／`主文件是抵押借款` |
| 主文是股权或资产买卖，用户只要审主文件 | 股权／资产转让 | **负触发**对应原子；债务转移专章可单独评改且用户只要审该专章：本任务只审专章，主文件标转出 |
| 只有第三人向债权人出具“我来还”的单方承诺，无人要把原债务人免责 | 债务加入或增信 | 若用户明确只要并存：留本任务按硬闸 B 出并存口径；若主给付是保证：转担保原子。不得写成已经免责 |

代付款、债权收购误入是硬闸：一旦核心给付滑入上述结构，立即停笔转出。不得删掉代付结算或让与通知条款后继续当债务转移审。

### 1.3 加载协议

只打开本目录 `基本面.md` 与 `框架.md`。禁止读 `types/` 或其他场景原子目录。

### 1.4 违法结构停笔

出现下列任一结构，只出告知，不改写成可履行文本：

- 原债务人与新债务人通谋，把债务转到无清偿能力主体，目的是逃废对债权人或担保人的责任；
- 虚构原债务或阴阳两套金额，一套对内、一套对外；
- 把业务员签字或倒签的同意日写成“债权人早已同意”；
- 用债务转移规避国资进场、上市公司重大义务披露或外资准入。

用户坚持“改到能签／先写上已经同意再补章／担保人不用签字”：整体停止。合规改道（补债权人签章、写明免责或并存、取得担保人书面同意）只点名并出修改句，不在本任务起草逃债方案。

## 硬闸 A　债权人书面同意

本闸改变本次转移能不能对债权人生效。依据：民法典第五百五十一条。

1. **同意是对债权人生效的要件，不是可有可无的礼貌通知**  
   债务人将债务的全部或部分转移给第三人，应当经债权人同意。债务人或者第三人可以催告债权人在合理期限内予以同意，债权人未作表示的，视为不同意。  
   原债务人与新债务人之间的约定，即使双方都盖章，也只在二者之间可能有效；未经债权人同意，对债权人不发生效力。不得写成“双方约定即已转移”“通知到达即生效”。

2. **谁签、签什么才算同意**  
   实践中必须取得债权人明确的书面同意：债权人作为本协议一方签章，或出具单独的《同意函》并指向本协议和债务清单。  
   下列情形**不得写成已经同意**：  
   - 债权人业务员、项目经理或分支机构在《供应商告知函》《对账单》《收货确认》上签字；  
   - 仅向债权人发出通知、抄送邮件或微信，债权人未回复；  
   - 债权人财务人员口头说“知道了”；  
   - 债权人未在本协议加盖公章或合同专用章。  
   知识稿“未盖章即不同意”的口径降级为：对债权人可能不发生效力；是否构成法人意思，字段停止，不补写成已经同意，也不把双方约定写成当然无效。

3. **修改句**  
   `债权人【名称】在此不可撤销地同意：原债务人【名称】将其在【原合同名称及编号】项下截至本协议签署日的全部未偿债务（范围见附件《债务确认清单》）转移给新债务人【名称】。本同意以本协议加盖债权人公章或合同专用章、并由法定代表人／授权代表签字为准。债权人业务人员在告知函、对账单上的签字，或仅向债权人发出通知而未获本条书面同意的，不构成本协议项下的同意。债权人未在合理期限内作出本条书面同意的，视为不同意本次转移，本次转移对债权人不发生效力。`

4. **最强反方**  
   相对人可能主张：业务员签字构成表见代理，或债权人收款、对账构成默示同意。签前两极都不写。只写：未取得债权人签章或单独同意函的，对债权人生效字段停止；不得靠默示把转移写成已经完成。

核验失败：第五百五十一条的法律结论字段停止，事实摘录和“补债权人签章”的修改句草稿继续。

## 硬闸 B　免责的债务承担 ≠ 并存的债务承担

本闸改变原债务人是否还要对债权人负责。依据：民法典第五百五十一条、第五百五十二条；合同编通则解释第五十一条；担保制度解释第三十六条。

1. **先问用户要哪一种，再看文本写了没有**  
   - **免责的债务承担（典型三方协议目的）**：新债务人替代原债务人，原债务人退出。必须同时具备：新债务人承诺承担；债权人同意仅向新债务人主张；原文写明原债务人不再承担。  
   - **并存的债务承担（债务加入）**：第三人加入，与原债务人在其愿意承担的范围内连带。通知债权人或向债权人表示愿意加入，债权人未在合理期限内明确拒绝的，债权人可以请求第三人与原债务人连带。加入**不需要**以免除原债务人为条件。

2. **约定不明不得写成已经免责**  
   仅有“由新债务人负责偿还”“新债务人承诺代为清偿”“后续款项由新债务人支付”，未写“债权人不再向原债务人主张”或“原债务人退出”：不得写成免责已经完成。权利的放弃须明示。审查口径：保护债权人方向，约定不明按并存或未生效转移处理，不按原债务人已经脱责放行。  
   不得把担保制度解释第三十六条（承诺文件难以确定是保证还是加入时认定为保证）误用成“约定不明就是免责转移”。

3. **禁止的写法**  
   “本协议生效后原债务人自动免责。”“双方同意视为债权人已放弃对原债务人的请求权。”“新债务人还款即视为原债务人退出，无论债权人是否签章。”

4. **修改句（免责口径，须债权人签章）**  
   `自本协议生效之日起，原债务人在原合同项下对债权人的全部义务转由新债务人承担。债权人同意仅向新债务人主张原合同项下权利，不再请求原债务人履行、承担连带或补充责任。本条构成免责的债务承担，不构成民法典第五百五十二条项下的债务加入。未经本条明示，任何“由新债务人负责偿还”的表述不得解释为原债务人已经退出。`

5. **修改句（并存口径，仅在用户明确要加入时）**  
   `各方确认本次安排为并存的债务承担（债务加入）：新债务人在人民币【待填】元范围内与原债务人对债权人承担连带债务；原债务人并不退出。债权人未在合理期限内明确拒绝的，有权请求新债务人与原债务人连带履行。保证人的保证责任不受本次加入影响。删除任何将原债务人写成已经免责的句子。`

6. **公司加入债务的额外闸**  
   法定代表人以公司名义加入债务的，效力认定参照公司为他人提供担保的规则（担保制度解释第十二条）。未见股东会或董事会决议：加入效力字段停止，不得写成公司已经加入。

7. **最强反方**  
   原债务人会主张“写了由新债务人还就是免责”；债权人会主张“没写放弃就仍可两头要”。签前两极都不保证。只逼出正说和反说。

## 硬闸 C　担保是否存续

本闸改变债权人签字后手里的担保还在不在。依据：民法典第六百九十七条、第三百九十一条；担保制度解释第三十九条。

1. **保证**  
   债权人未经保证人书面同意，允许债务人转移全部或部分债务的，保证人对未经其同意转移的债务不再承担保证责任，但是债权人和保证人另有约定的除外。  
   **对照**：第三人加入债务的，保证人的保证责任不受影响。因此，免责转移会动保证，并存加入通常不动保证。用户要免责又要保证留下：必须拿到保证人书面同意。

2. **第三人提供的抵押／质押**  
   第三人提供担保，未经其书面同意，债权人允许债务人转移全部或部分债务的，担保人不再承担相应的担保责任。主债务部分转移时，第三人物保可主张对未经书面同意转移的部分不再承担责任。

3. **债务人自己提供的物保**  
   债务人自己提供的抵押或质押，通常继续担保全部债务。须约定：新债务人知悉该负担，并配合办理债务人变更及抵押权／质权变更登记。不得把“带押过户”写成已经完成登记。

4. **禁止的写法**  
   “担保权利随债务转移自动继续有效。”“保证人口头同意即可。”“未通知保证人则转移无效。”（后一句是把第六百九十六条债权转让规则误套到本类型。）

5. **修改句**  
   `为保证人对未经其书面同意转移的债务继续承担保证责任，保证人【名称】应作为本协议一方签署，或另行出具《同意函》，载明：其已知悉并同意本次债务转移，同意以原保证合同为新债务人在原保证范围、保证期间和保证方式内继续提供保证。未经上述书面同意，保证人对未经其同意转移的债务不再承担保证责任。第三方抵押人／出质人比照办理书面同意；未取得书面同意的，该第三人担保人不再承担相应担保责任。债务人自己提供的抵押／质押继续担保全部债务，新债务人应于【待填】日内配合办理债务人变更及登记。`

6. **最强反方**  
   保证人会主张未经书面同意已经免责；债权人会主张“另有约定”或保证合同写过“债务转移不影响保证”。签前：有另有约定的，摘录该句并核是否覆盖本次转移；没有书面同意也没有另有约定的，担保存续字段停止，不得写成担保还在。

核验失败：第六百九十七条、第三百九十一条的法律结论字段停止，“补保证人书面同意”的修改句草稿继续。

## 硬闸 D　与代付款、债权收购、债权转让切开

本闸改变能不能留在本任务。

1. **代付款（第三人履行）**  
   当事人约定由第三人向债权人履行，第三人不履行或履行不符合约定的，**债务人仍向债权人承担违约责任**。原债务人不换人。标题写成三方协议但正文是“代付、原债务人仍负责”：负触发 `代付款三方协议·审查`。  
   **修改句（仅告知／转出）**：`删除将本次交易写成代付款、代为结算或原债务人不退出的表述。若各方真实意思仅为第三人向债权人付款、原债务人仍是债务人，应另立代付款三方协议，不适用本协议的免责安排。`

2. **债权收购／债权转让**  
   债权人把债权让与第三人，债务人主体不变。对债务人生效靠通知，不是靠债务人同意。从权利随同，专属于债权人自身的除外。这是相反方向的主体变更。标题写成债务转移但正文是“出让人将债权出售给收购方、通知债务人”：负触发 `债权收购合同·审查` 或 `主给付是债权让与通知债务人为轴→`。  
   **修改句（仅告知／转出）**：`删除将本次交易写成债权收购、债权转让、通知债务人即可或从权利随同转让的表述。若各方真实意思是债权人将其对债务人的债权出让，应另立债权收购或债权转让合同并通知债务人，不得在本协议写成债务转移。`

3. **留在本任务时的隔离句**  
   `各方确认：本次交易是债务人将特定债务转移给第三人，须经债权人书面同意；原债务人是否免责以第【】条为准。本次交易不构成代付款，也不构成债权转让或债权收购。`

4. **最强反方**  
   相对人可能主张按标题或按代付／让与条款履行。签前按核心给付分流，不两套都审。

---

## 节点 2　主体、授权、决议

1. 建主体表：债权人、原债务人、新债务人、保证人、第三方抵押人／出质人、授权签字人。名称不一致不自动合并。
2. 协议必须由债权人、原债务人、新债务人三方签署。只有后两方：对债权人生效字段停止，硬闸 A 出红线。
3. 原债务人或新债务人为公司，且本次构成重大义务承担或重大债务豁免：应提交股东会或董事会决议作为附件。口头“我们老板同意了”不得写成已授权或已决议。
4. 法定代表人以公司名义加入债务：参照公司为他人提供担保的决议规则。未见决议：加入效力字段停止。
5. 国资／上市公司／外资：进场、披露或准入未核则字段停止，不写场外可履行。
6. 不足：字段停止，列出待补材料，不补主体。

---

## 节点 3　原债务范围、从债务、抗辩

1. 标的确定到原合同名称及编号、签署日、本金、利息计算方式及已付未付、违约金／损害赔偿／实现债权费用、是否到期、有无争议。只有“有关债务”“全部应付款”则标缺口。  
   **修改句**：`被转移债务以附件《债务确认清单》为准，至少列明：原合同名称及编号、签署日、债权人、原债务人、本金人民币【待填】元、截至【待填】日已付／未付利息及计算方式、违约金／损害赔偿金／实现债权费用人民币【待填】元、是否到期、有无争议或抗辩。`

2. 从债务：新债务人应当承担与主债务有关的从债务，但是专属于原债务人自身的除外。基于原债务人特定身份的优惠利率、政策补贴挂钩义务，不当然由新债务人享受或承担。  
   **修改句**：`新债务人承担与主债务有关的从债务，包括利息、违约金、损害赔偿金和实现债权的费用。专属于原债务人自身的从债务（如基于原债务人特定身份的优惠利率或政策挂钩义务）不随同转移，由【待填】另行约定。`

3. 抗辩：新债务人可以主张原债务人对债权人的抗辩；原债务人对债权人享有债权的，新债务人不得向债权人主张抵销。签署前应披露已知抗辩、时效和争议。  
   **修改句**：`新债务人有权主张原债务人对债权人的抗辩，包括原合同无效或可撤销、同时履行抗辩、先履行抗辩、诉讼时效。原债务人对债权人另享有的债权，新债务人不得向债权人主张抵销。原债务人应于签署前向新债务人书面披露已知抗辩、抵销和争议；未披露的，原债务人向新债务人承担赔偿责任，但不影响新债务人对债权人主张抗辩。`

4. 材料未提及担保或抗辩，不得写成“无担保、无抗辩”，只能写 `依据不足`。

---

## 节点 4　程序与生效

把债权人同意、担保人书面同意、公司决议、批准登记写成**义务和期限**，不写成已经完成。

| 文本写法 | 本任务动作 |
| --- | --- |
| “本协议签字即视为债务已转移、原债务人已免责” | 拆成：合同在三方之间成立 vs 对债权人生效（须债权人同意）vs 原债务人退出（须明示）vs 担保存续（须担保人书面同意） |
| “通知债权人后生效”且无谁通知、几日内、未回复的后果 | 改为债权人书面同意；未表示视为不同意 |
| “双方同意视为已决议／已取得保证人同意” | 红线；改为书面附件和先决条件 |
| 用户要求倒签同意日或补假决议、假同意函 | 整体停止 |

法律、行政法规规定转移义务应当办理批准、登记手续的，把批准、登记写成生效条件或双方义务期限，不写成已经完成。

---

## 节点 5　格式条款与强制规范

运行时核验后再落法律结论。核验失败：摘录条款继续，法律结论字段停止。

债权人或集团公司重复使用的债务转移模板仍可能构成格式条款。审查单方免责、不得调整的高额违约金、管辖、最终解释权是否有显著提示。

违反法律、行政法规强制性规定不一律无效。第五百五十一条主要约束**对债权人是否发生效力**，不轻易写“未经同意则原债务人与新债务人之间的约定当然无效”。通谋逃债、虚构债务：只告知，不写假架构。禁止用已失效“效力性／管理性”口诀。

---

## 节点 6　对价、交接、违约、争议解决

1. 若本次转移构成股权转让、资产买卖的部分对价：写明与主交易合同付款条款的呼应，以及主交易未交割时转移是否中止。不在本任务整份代审股权或资产主文件。
2. 资料、图纸、凭证交接：列清单、时间和签收，未移交不得视为转移已完成履行。
3. 新债务人逾期向债权人履行、原债务人未移交资料、债权人违反“仅向新债务人主张”的约定，必须分别有可执行后果。只有“依法承担违约责任”视为必须改。
4. 构成违约不等于当然解除。不在本任务作出已解除结论。
5. 争议解决：本协议管辖与原合同管辖可能不同，必须点名。已有仲裁条款，不得改成“应向某法院起诉”并假装已选定诉讼；或裁或诉、机构不明：改成单一机构或单一法院连结点。
6. 微信已读不写成已经送达，除非合同把该渠道定为送达。

## 节点 7　跨境与其他结构

1. 涉外主体或境外付款：准据法不明则停止外国法结论。
2. 权利义务一并转让：适用债权转让和债务转移两套规则，本任务只审债务一侧；债权一侧标转出 `主给付是债权让与通知债务人为轴→`。
3. 企业合并、分立导致的债务承继不是意定三方转移，标红旗并转公司合并／分立原子，不按本协议免责口径改写。
4. 破产程序中的债务转移另受破产法约束：字段停止，不写成场外可履行。

## 节点 8　按框架六步出修改句

本节点是成果闸。没有修改句或红线，不得宣称审查完成。禁止只打红黄绿。

对照已加载框架级文件和本方法硬闸，按六步逐段出句。框架中的股权对价、带押过户清单：仅在文本确实出现时使用；主给付滑入代付款或债权收购则按节点 1.2 转出。

| 步 | 本类型必须盯的点 | 必须产出 |
| --- | --- | --- |
| 首部 | 标题名实（债务转移／债务承担，避免写成债权转让或代付款）；三方主体；鉴于只描述原债务和转移背景，不把同意或免责写成已完成 | 主体与鉴于修改句 |
| 交易条款 | 债权人书面同意；免责或并存正说反说；新债务人承担；原债务清单；从债务与专属例外 | 闭环修改句；缺数字用 `【待填】` |
| 配套 | 保证人／第三人物保书面同意；抗辩披露与禁止抵销；资料交接；与主交易对价的呼应；分别违约后果 | 可执行后果句 |
| 尾部 | 三方签章；保证人作为一方或同意函附件；公司决议；原合同与清单作为附件 | 生效与附件修改句 |
| 语言 | 正说加反说；转移 ≠ 加入 ≠ 代付 ≠ 债权转让；同意 ≠ 通知；担保存续 ≠ 自动跟随 | 替换空词的句子 |
| 常见问题 | 缺债权人签章、约定不明却写成免责、担保未书面同意、清单不可核验 | 结构级改法或红线 |

每条修改句固定格式：

`定位（条/款/附件）｜原文｜建议改为｜理由（回链 C# / L# / I#）｜可退让点｜不接受时的红线`

风险表每一行必须能指回上述某条修改句。级别：

- `红线`：不改则建议不签或整体停止（债权人未同意却写成已转移、约定不明却写成免责、担保未书面同意却写成存续、通谋逃债、倒签同意日）；
- `必须改`：可谈但签署前要落句（债务清单、免责或并存落句、保证人／第三人物保书面同意、抗辩披露、决议附件、管辖与原合同切开）；
- `可接受可优化`：仍要给句子，不得只标绿。

用户不可接受事项优先写成红线。生存级债务额或个人无限连带且用户拒绝升级：停止“可以签署”建议。

## 版本冲突

正文、附件、原合同、担保合同、告知函、决议、聊天确认冲突时：

1. 并列 `D#` / `C#`，不选对用户有利的一版。
2. 修改句写明冲突项以哪一份为准，或删除冲突句。债权人是否同意、原债务人是否免责、担保是否存续冲突不得调和成“两套都有效”。
3. 不得在意见里悄悄采用有利版本并称“合同已明确”。
