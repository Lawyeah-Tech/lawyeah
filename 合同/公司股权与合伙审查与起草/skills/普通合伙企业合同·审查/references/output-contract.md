# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然可登记或必然可执行；编造未给出的出资、评估、期限；把已失效《民法通则》个人合伙章或 1997 年《合伙企业法》写入结论；把对内分担写成对外免责；把未领执照写成可以合伙企业名义经营；把个人合伙或有限合伙当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查普通合伙企业合同（合伙合同相关）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《民法通则》个人合伙章、1997 年《合伙企业法》原文或已失效《合伙企业登记管理办法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `合伙合同相关`，子级 `普通合伙企业合同`。定性理由、易混切开结果（个人合伙、有限合伙、特殊普通合伙、股东协议、借款、劳务/劳动合同）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、书面协议、登记与文本版本

主体表：签约名、履行名、出资名、授权签字人、法人合伙人的委派代表。禁入表：是否出现国独/国企/上市公司/公益事业社团。登记表：拟用名称是否标明“普通合伙”、执照路径、前置许可。版本表：正文、出资清单、评估确认、委派书、聊天确认；冲突并列。未核执照路径或禁入：该签署能力字段停止。

## 5. 出资、利润亏损、执行事务与入伙退伙

出资方式、缴付期限、劳务评估办法、企业财产范围；利润亏损是否禁止全部归一方；执行事务是共同执行还是委托执行，内部限制是否拟登记；入伙书面协议与入伙前债务；退伙结算与退伙前债务。缺口标 `G#`。不输出个人合伙“无法人”或有限合伙 LP 避风港主路径。

## 6. 格式条款与强制规范

是否构成格式条款。强制规范只按第 153 条和解释第 16 条区分，不用失效“效力性/管理性”口诀。未领执照对外经营、禁入主体、对外豁免无限连带只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的仲裁建议写成法定义务。

## 9. 谈判与签署提醒

谈判顺序：先红线（对外免责、禁入主体、未领执照对外经营、全部利润/亏损、保底借贷），再必须改（无限连带明示、入伙退伙对外责任、执行限制登记、劳务评估、退伙通知），最后可优化。签署提醒：全体合伙人签名盖章；法人合伙人委派代表；出资确认、评估报告、委派书入附件；名称预先核准与设立登记义务主体、期限。不指导倒签或补假批准。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、清算诉讼策略或效力保证，也不是个人合伙或有限合伙审查。
