# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或不可撤销必然排除任意解除；编造未给出的托管费、违约金、期限；把已失效《合同法》或其第四百一十条写入结论；写“托管后受托人即为股东”；写未通知公司也能对抗公司；把代持或转让当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查股权托管协议（公司相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1993 年《公司法》同条号旧义、商业银行／信托集中托管规章充当本类型主依据时记噪声，不得写入 `L#`。2023 年第五十六条、合同编通则解释第十六条未核验原文前不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `股权托管协议`。定性理由、易混切开结果（代持、转让、股东协议、回购、集中存管）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准：不得把“为受托人利益则不得任意解除”写成法条；过户条款转出。挂靠、规避准入、违法代持上市股票写停笔告知，不填可履行结构。

## 4. 主体、授权、权利人与文本版本

主体表：目标公司、委托人（登记股东）、受托人、主交易相对人、质权人或配偶、授权签字人。写明委托人是否名册／登记股东，受托人是否同时为买方或债权人。版本表：正文、授权委托书、收购／借款主合同、章程、致公司通知函、聊天确认；冲突并列。未见书面授权书：行权对抗公司字段停止。

## 5. 给付闭环

托管股权数量或比例、权利清单（表决／分红／提案／召集／知情／处分）、全权或指示、积极／消极列表、分红账户与税负、期限及是否挂钩主交易交割、通知公司、授权书提交、返还清单、费用。缺口标 `G#`，不补商业数字。批准、信披、质权人同意写成生效条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款（不可撤销、单方终局解释、放弃任意解除赔偿）。强制规范只按民法典第一百五十三条和已核验解释区分，不用失效“效力性／管理性”口诀。第九百三十三条、第一百一十八条、上市权益变动只作为修改理由，不代替修改句。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止写出“本委托不可撤销，任何一方不得依照法律规定解除且无需赔偿”。

## 9. 谈判与签署提醒

谈判顺序：先红线（名为代持、规避监管、受托人可处分股权），再必须改（权利清单、指示规则、授权书、通知公司、返还、任意解除成本），最后可优化（行权报告周期、公证授权、质权组合）。签署提醒：授权委托书与正文权限一致、致目标公司通知函、主合同交叉违约附件、质权人同意、日期与附件清单。不指导倒签或补假授权。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、效力保证，也不是代持本约或转让本约审查。
