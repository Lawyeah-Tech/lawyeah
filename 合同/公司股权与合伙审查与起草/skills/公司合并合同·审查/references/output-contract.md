# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、必然获准登记或经营者集中批准、对方必然接受；编造未给出的换股比例、对价、职工补偿；把已失效《合同法》、2004／2018 年合并旧程序、2008 年申报门槛数字、股权收购或分立规则写入本类型结论。

## 1. 触发、单方立场与成果状态

立场（存续公司／被吸收方／新设合并某一方）、授权、签署状态、吸收或新设、主要目标。股权收购、分立、资产收购、已成争或其他负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》、2004／2018 年《公司法》合并旧程序、1993 年同条号或 2008 年申报门槛时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `公司合并合同`。写定性理由和与股权收购、公司分立、存量转让、资产收购的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。内部互免对抗债权人或一律解除劳动合同写停笔告知，不填可履行规避结构。

## 4. 主体、授权、合并当事方与文本版本

主体表：各合并公司（全称、统一社会信用代码、存续或解散角色）、授权签字人、国资或外资审批主体、拟设公司（如有）。版本表：正文、资产负债表及财产清单、股东会／董事会决议、职工安置方案、评估报告、债权人清单、聊天确认；数字冲突并列，不选对用户有利的一版。

## 5. 给付闭环（本类型必填）

固定检查并回链文本：

- 吸收合并还是新设合并；谁解散、谁存续或谁新设；
- 合并基准日、协议生效日、交割日是否三分；
- 全部资产、负债、合同、资质、或有负债是否概括承继；
- 换股比例或现金对价、调整机制；
- 股东会特别决议或依法适用的第 219 条简化合并＋董事会决议；异议股东收购安排；
- 债权人：十日通知、三十日公告（报纸或国家企业信用信息公示系统）、三十日／四十五日请求；
- 职工：劳动合同继续有效、承继单位继续履行、工作年限合并计算口径、安置方案；
- 经营者集中及其他政府批准是否写成交割先决；
- 过渡期禁令和交割后注销／权属变更。

缺口标 `G#`，不补商业数字。决议、公告、登记、集中批准写成义务或条件，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款（含示范文本或中介填充版）；提示说明痕迹。强制规范只区分是否导致民事行为无效与是否仅造成履行障碍（未公告、未达三分之二、未申报）。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。硬闸五项若文本或事实触及或沉默，必须各有至少一行，不得用色块代替。

## 8. 修改句

按框架六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止输出“职工一律终止后重签”“债务由原股东自行消化即可对抗债权人”“报纸公告三次、九十日”充当本类型默认修改句。

## 9. 谈判与签署提醒

谈判顺序：先红线（合并方式未写死、内部互免对抗债权人、一律解聘、倒签公告、达标准不申报、假股权收购规避），再必须改（三日期、决议附件、通知公告条款、安置方案、过渡期、换股表），最后可优化。签署提醒：各方法定代表人或授权代表签字并加盖公章、决议与清单附件、日期不得倒签。不指导倒签或补假决议、假公告。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、代办登记或经营者集中申报、效力保证。
