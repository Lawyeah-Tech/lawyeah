# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然收回债款或必然可执行；编造未给出的价款、未偿额、通知日；把已失效《合同法》第七十九条至第八十三条、法释〔2001〕12 号报纸公告通知、《物权法》《担保法》写入结论；写“未通知则本协议不成立”；写“签字即视为已通知目标公司”；写“未登记则抵押权未转移给收购方”；写“普通贸易债权必须持有 AMC 牌照”；写“收购后目标公司不得再抗辩”；把债务转移、普通债权让与或保理文本当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查债权收购合同（公司相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、法释〔2001〕12 号、2003 年企业国有产权转让管理暂行办法时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `债权收购合同`。定性理由、易混切开结果（债务转移 / 普通债权让与 / 代付款 / 保理 / 股权或营业收购 / 债务重组）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、并购结构、资质与文本版本

主体表：出让人、收购方（并购主体或 SPV）、目标公司（债务人）、保证人、抵押人／出质人、付款名、授权签字人。版本表：正文、债权清单、基础合同、担保合同、通知书、内部决议、聊天确认；冲突并列。金融不良受让资格、国资进场单独标状态。

## 5. 给付闭环

标的债权是否特定；主债权与从权利是否一并列入；通知与保证人通知是否作为付款先决；担保变更登记义务与期限；禁止转让特约是否披露；价款、税、发票、分期节点；抗辩抵销披露。缺口标 `G#`。批准、登记、进场写成生效条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹。禁止转让特约、先款后通知、转让后不得抗辩等异常条款单独点名。强制规范只按第一百五十三条区分是否导致民事行为无效，不用失效口诀。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。五项硬闸在本节约须各有至少一句可回给对方的句子，或写明因负触发／停笔未出句的理由。

## 9. 谈判与签署提醒

谈判顺序：先红线（实为债务转移、金融不良无资质、只买裸债权、先全款后通知、虚构债权），再必须改（通知先决、保证人通知、特约披露、登记义务、抗辩抵销），最后可优化（保密、后续维权协助、以债抵股另约）。签署提醒：内部决议、债权清单、基础合同与担保原件、两套通知书（致目标公司／致保证人）、变更登记申请文件。不指导倒签通知日或补假回证。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约催收交底、争议文书或效力保证，也不是债务转移、普通债权让与或保理安排。向目标公司主张债权时，原债权合同争议解决条款原则上仍约束收购方，不得把本协议管辖写成已经覆盖追索目标公司。
