# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受或必然完成民政登记；编造未给出的交接基准日、异议期、违约金；把已失效《合同法》或其解释、1989 年条例、1998 年已被修改文本写入结论；写“双方签字即视为已完成民政变更”；把社团写成可转让股权或可分配利润；把未登记写成交接协议未成立；把民办学校转让或公司股权买卖当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查社会团体负责人变更合同（公司相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》及其解释、1989 年《社会团体登记管理条例》、1998 年条例旧文本、已失效《公司登记管理条例》时记噪声，不得写入 `L#`。民法典第八十五条、党政干部兼职中央文件、地方“内地居民”条款未核验原文前不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `社会团体负责人变更合同`。定性理由、易混切开结果（民办学校转让、公司股权买卖、公司法定代表人变更、劳动合同、基金会／民非）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准：决议瑕疵不当然写成变更行为无效；第八十五条不写成社团默认。挂靠、把社团当股权出售、出租出借印章证书写停笔告知，不填可履行结构。

## 4. 主体、授权、决议与文本版本

主体表：社会团体法人（统一社会信用代码）、原负责人、新任负责人、监交人／监事、业务主管单位（如有）、授权签字人。职务表：法定代表人、会长／理事长、副会长、秘书长分列。版本表：正文、核准章程、会员（代表）大会或理事会决议与签到、业务主管单位批复、交接清单、聊天确认；冲突并列。未见社团盖章或章程规定的决议：登记配合字段停止。

## 5. 给付闭环

拟变更职务与是否含法定代表人、决议机构与表决比例、业务主管单位书面同意、民政三十日递件义务、交接基准日、交接清单（印章／证书／账户／账册／在履合同）、异议期、离任审计、银行预留印鉴。缺口标 `G#`，不补日期。批复、登记、公告写成义务和期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款。强制规范只按民法典第一百五十三条和合同编通则解释第十六条区分，不用失效“效力性／管理性”口诀。非营利禁止分配、不得从事营利性经营、不得兼任其他社团法定代表人、三十日变更登记只作为修改理由，不代替修改句。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的日期和金额用 `【待填】`。禁止只给原则、不给句子。禁止写出“本协议签字即视为民政变更完成且无需章程决议或业务主管单位同意”。

## 9. 谈判与签署提醒

谈判顺序：先红线（股权化出售、利润分配、无决议即视为登记、出租出借印章证书），再必须改（章程条款回链、决议附件、三十日递件、交接清单、资格与兼任声明），最后可优化（监交人、离任审计、异议期、不招揽）。签署提醒：社团公章与新任负责人签字、原负责人亲笔签名、决议和批复作附件、交接清单三方（或监交）签字、签订日在决议之后登记之前。不指导倒签或补假决议、假批复。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、效力保证，也不是民办学校转让或公司股权买卖审查。
