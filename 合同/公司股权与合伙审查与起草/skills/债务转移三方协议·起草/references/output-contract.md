# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、原债务人必然免责或担保必然存续；编造未给出的金额、利率、日期；把已失效《合同法》第八十四条或担保法写入结论；把业务员签字或告知函写成债权人已同意；把约定不明写成已经免责；把代付款或债权收购当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查债务转移三方协议（公司相关合同）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》第八十四条及其解释、《担保法》及其解释、1994 年保证规定时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `债务转移三方协议`。定性理由、易混切开结果（代付款、债权收购、债权转让、债务加入承诺、保证／抵押主文件）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准：未盖章不写成协议当然无效；约定不明不写成已经免责。通谋逃债、虚构债务写停笔告知，不填可履行结构。

## 4. 主体、授权、担保人与文本版本

主体表：债权人、原债务人、新债务人、保证人、第三方抵押人／出质人、授权签字人。写明债权人是否作为协议一方签章。版本表：本协议正文、原合同及补充、担保合同、决议、告知函、聊天确认；冲突并列。未见债权人签章：对债权人生效字段停止。

## 5. 给付闭环

原债务清单（原合同编号、本金、利息、违约金、履行状态）、转移范围（全部／部分）、债权人同意句、免责或并存口径、新债务人承担句、从债务与专属例外、抗辩披露、担保书面同意、交割与资料交接、对价或与主交易合同的呼应。缺口标 `G#`，不补商业数字。批准、登记、决议写成生效条件或期限，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款；提示说明痕迹；异常条款。强制规范只按民法典第一百五十三条和合同编通则解释第十六条区分，不用失效“效力性／管理性”口诀。第五百五十一条同意要件、第六百九十七条和第三百九十一条担保脱落只作为修改理由，不代替修改句。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。禁止输出无修改句的色块表。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止写出“业务员签字视为债权人同意”“原债务人当然免责”“担保当然存续”。

## 9. 谈判与签署提醒

谈判顺序：先红线（债权人未同意却写成已转移、约定不明却写成免责、担保未书面同意却写成存续、通谋逃债），再必须改（债务清单、免责或并存正说反说、保证人／第三人物保作为一方或出具同意函、抗辩披露、决议附件），最后可优化（资料交接清单、交叉违约、新债务人偿债能力陈述）。签署提醒：三方公章与法定代表人／授权代表、保证人书面同意、公司决议、原合同与清单作为附件、日期一致。不指导倒签或补假同意。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、效力保证，也不是代付款三方协议或债权收购合同审查。
