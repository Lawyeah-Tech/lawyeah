# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、签字即债消灭、必然追回、对方必然接受；编造未给出的金额、账户、日期；把已失效《合同法》第六十五条、第八十四条写入结论；把债务转移、债务加入或债权转让硬套本类型；把虚构走账改成可履行结构。

## 1. 触发、单方立场与成果状态

立场（代付方／债务人／债权人）、授权、签署状态、主要目标。债务转移、债务加入、债权转让、已成争或其他负触发写路由，不启动实体审查。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回已失效《合同法》第六十五条、第八十四条或其解释时记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `公司相关合同`，子级 `代付款三方协议`。写定性理由和与债务转移、债务加入、债权转让的切开结果。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。`基本面.md` 若与本类型明显无关，记降级，不改加载买卖或转移双文件。虚构原债或走账写停笔告知，不填可履行规避结构。

## 4. 主体、授权、资金与文本版本

主体表：代付方、债务人、债权人、担保人、指定收款名、付款名、授权签字人。版本表：正文、原债务合同、账户信息、担保登记、主交易（如股权收购）、聊天确认；金额或账户冲突并列，不选对用户有利的一版。

框架用语“受让方／转让方／目标公司”按代付方／债务人角色入表，并在表下注明，避免与债权受让人混淆。

## 5. 给付闭环（本类型必填）

固定检查并回链文本：

- 原债务：合同名称编号、形成原因、未偿本金／利息／违约金、是否真实、是否已部分清偿；
- 代付金额：全额、部分或折价；与原债务勾稽；
- 定性：代付≠转移≠加入；523 下第三人不履行时债务人仍向债权人负责；
- 清偿效果：指定唯一收款账户、到账日、结清或部分结清证明；签署本身不消灭债务；
- 追偿：单一路径（返还／股东借款／524 法定移转／赠与）及入账科目；禁止双重主张；
- 担保：对应部分主债权消灭后的注销登记、返还权证、逾期违约金；
- 付款前提：三方签署、账户确认、原债务确认书；未完成不得放行付款。

缺口标 `G#`，不补商业数字。到账、注销写成义务或条件，不写成已经完成。

## 6. 格式条款与强制规范

是否构成格式条款（含示范文本或收购附件填充版）；提示说明痕迹。强制规范只区分是否导致民事行为无效（146／153／154、反洗钱）与是否仅造成未收妥则债务不消灭、追偿不能。无 `search_law` 引文则本节点法律结论字段停止，事实摘录继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔／转出口径。硬闸五项若文本或事实触及或沉默，必须各有至少一行，不得用色块代替。

## 8. 修改句

按框架六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点、不接受时的红线。未给出的商业数字用 `【待填】`。禁止只给原则、不给句子。禁止输出“签署之日起原债务消灭”“代付方成为新债务人”“同一笔款既是股东借款又法定移转债权”充当修改句。

## 9. 谈判与签署提醒

谈判顺序：先红线（债务转移伪装、签字即结清、洗钱走账、追偿双重主张），再必须改（指定账户、收妥证明、单一追偿、担保注销期限），最后可优化。签署提醒：原债务确认、唯一收款账户、不得倒签到账日、结清证明与付款挂钩、附件清单。不指导倒签或补假回单。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议追索文书、代办注销登记或效力保证。
