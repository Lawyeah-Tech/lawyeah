# 输出合同

正触发固定十节，除安全整体停止外不得省略。负触发只写触发判定、路由和最小交接，不填十节实体结论。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

禁止：只打红黄绿不给修改句；保证有效、对方接受、必然可登记、必然不被认定为劳动关系或必然可执行；编造未给出的作价、份额、年限、报酬；把已失效《民法通则》个人合伙章、1997 年《合伙企业法》或已失效《合同法》写入结论；把“没出钱”写成对外已经免责；把劳务本身写成可折现撤资；把 LP 或公司股东劳务出资改成可履行；把劳动合同或承揽当成已完成的本类型审查。

## 1. 触发、单方立场与成果状态

立场、授权、签署状态、主要目标。负触发写路由，不启动实体审查。写明中文成果名称是「审查劳务出资型合伙合同（合伙合同相关）」。

## 2. 来源登记与 MCP 调用表

`S/D/A/C/L/I/G`。MCP 未调用也留一行状态：`not-registered` / `permission-denied` / `error` / `no-result` / `partial` / `conflict` / `verified-result`。`search_law` 返回 1997 年《合伙企业法》同号条文、已失效《民法通则》个人合伙章、已失效《合同法》或其解释、已失效《合伙企业登记管理办法》时，记噪声，不得写入 `L#`。

## 3. 类型与加载路径

父级 `合伙合同相关`，子级 `劳务出资型合伙合同`。定性理由、易混切开结果（普通合伙无劳务作价、个人合伙无劳务作价、有限合伙、劳动合同、个人劳务、承揽、技术入股、股权激励型合伙、隐名合伙）。加载路径必须写成：`references/基本面.md` 与 `references/框架.md`。写明只读这一对、未通读其他类型。知识库与硬闸冲突时，以 method 硬闸为准。

## 4. 主体、显名、双重身份与文本版本

主体表：签约名、劳务出资人是否列为合伙人、资金/实物合伙人、授权签字人、拟领执照与否。资质表：技能证书、兼职、在先竞业。禁入表：国独/国企/上市公司/公益事业社团是否被列为普通合伙人。版本表：正文、出资确认书、岗位/劳务说明书、技能证书复印件、聊天确认；冲突并列。未核证书或在先竞业：该字段停止。

## 5. 劳务评估、份额、报酬与退伙

评估办法（全体协商或第三方评估）、作价金额、财产份额、交付标准、服务年限或分期归属；执行事务报酬是否另约、是否抵扣分红；亏损分担与对外责任；退伙时劳务不可折现、现金/实物份额结算、中途退出与丧失能力。缺口标 `G#`。不输出劳动合同必备条款主路径，不输出承揽验收主路径。

## 6. 格式条款与强制规范

是否构成格式条款。强制规范只按民法典第 153 条和合同编通则解释第 16 条区分，不用失效“效力性/管理性”口诀。LP 劳务出资、公司股东劳务出资、只分红不担责、把纯雇佣包装成合伙以避劳动法：只保留识别与停笔。无 `search_law` 引文则本节点法律结论字段停止，事实摘录和修改句草稿继续。

## 7. 风险表（必须回链文本位置）

固定列：`编号｜文本位置｜原文摘录｜问题｜判断｜级别｜修改句或红线｜来源｜最强反方`。

级别只用 `红线`、`必须改`、`可接受可优化`。每一行必须有修改句或明确停笔/转出口径。

## 8. 修改句

按已加载 `框架.md` 的六步组织：首部、交易条款、配套、尾部、语言、常见问题。每条含：定位、原句、建议句、理由、可退让点。未给出的商业数字用 `【待填】`。不得把框架里的“股权解锁”“视为已履行完毕”原样写入建议句。

## 9. 谈判与签署提醒

谈判顺序：先红线（LP/公司股东劳务出资、只分红不担责、纯雇佣包装合伙、倒签），再必须改（评估办法与份额、交付标准、退伙不可折现劳务、对外责任明示、劳动/承揽用语剥离），最后可优化（分期归属、丧失能力退出、人身意外险）。签署提醒：全体合伙人签名盖章；《出资确认书》《劳务/岗位说明书》、技能证书入附件；拟登记企业的，劳务出资方式及数额列入合伙人名录申请材料。不指导倒签或补假证书。

## 10. 缺口、停止项与提示

`G#`、字段停止、整体停止、转介。审查模式成果不是整份起草终稿；起草模式见文末。不是履约交底、争议文书、劳动仲裁策略或效力保证，也不是普通合伙无劳务条款、有限合伙、劳动合同或承揽审查。
