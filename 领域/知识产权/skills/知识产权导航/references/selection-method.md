# 原子 Skill 选择方法

当前安装包是，按成果而不是按商标、专利或案由名称匹配。

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果：

- 事项总图；侵权对照；商业秘密权利与侵权；
- 权利清单；路径比较；期间表；权属链；管辖；权利稳定性；
- 商标申请核验、驳回复审、异议两造、无效两造、撤三两造；
- 专利申请风险、审查意见框架、专利无效两造、自由实施；
- 作品登记利弊、作品权属、软件著作权、合理使用；
- 商业秘密建设、应对指控、客户名单；
- 商标混淆、权项对照、实质性相似、被控抗辩地图、定牌合法来源、先用与用尽；
- 平台责任、仿冒、域名、品种权／布图／地理标志；
- 警告函或回复、平台通知或反通知、海关备案或扣留；
- 网页公证购买、行为保全申请或应对、证据保全、鉴定、测算、惩罚性；
- 和解参数、已成争许可或转让争议；
- 一审起诉或应诉、庭审、上诉、确认不侵权、反诉或另行无效影响；
- 行政投诉或应对调查、刑民交叉、执行。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权；
2. 主轴是权利保护、劳动竞业/保密、数据合规还是竞争秩序；
3. 是否已有警告函、起诉状、保全裁定、海关扣留或行政通知；
4. 本次要分析、发函、测算、建卷、禁令、行政、确权程序还是民事文书；
5. 权属能否回链到具体对象。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再发函；
4. 用户确认后只启动所选入口；等价评估、测算或证据可由用户或律师提供。

## 四、停止

立场冲突、劳动竞业/保密主轴、数据合规主轴、反垄断主轴或未成争改许可合同时，说明边界并转出，不代做。P2 能力输出 `unavailable`。信息不足时每轮只追问一个最能改变入口的问题。
