# 发函方法

不执行发送。没有送达事实禁止写已下架或已构成侵权。MCP 把 2025-10-15 已施行的《反不正当竞争法》标成尚未施行时，以施行日为准并记冲突。

## 节点 0　分流

被发函方转 `respond-warning-notice`（未安装则 C 端 093，只分流）。竞业／数据／反垄断转出。C 端警告函只分流，本任务仍做专业错误通知与专利／商业秘密场景。

## 节点 1　发送闸

同时满足才可出 `待发送` 稿：主张方立场；中国大陆；权属链闭合或仅差已核验登记查询；被控原文或可定位地址已保存；例外线索已展示；请求成比例；已展示错误通知风险；用户未要求刑事威胁或伪造权属。

缺任一项：只给不可发送占位稿和 `G#`。

## 节点 2　路径

| 文书 | 条件 |
| --- | --- |
| 警告函（本任务主成果） | 能确定收件主体，需要停止使用或书面回复 |
| 平台通知 | 只列接口与错误通知风险，终稿转 `prepare-platform-takedown` |
| 并行 | 站内与站外同时存在时分列，不把平台终稿写进本包 |

电商平台用电子商务法第 42–43 条；其他网络服务用民法典第 1195–1196 条。条例通知书要素可借鉴，不得把条例“立即恢复”写成现行默认等待规则。禁止写入 DMCA、§512 或伪证宣誓。

## 节点 3　正文纪律

允许：停止特定使用、删除或断开特定链接、下架特定商品页、书面说明来源、合理期限回复。

禁止：已经构成侵权／假冒／犯罪；威胁公安或刑事责任；三日内不删就必赢；要求转让权利、交出账号、未经测算的罚金或全店封杀。赔偿、许可、销毁库存列为升级，不写入可发送请求。

## 节点 4　错误通知

电子商务法第 42 条：通知错误致损承担民事责任；恶意错误通知加倍赔偿。声明到达后未在法定期间投诉或起诉的，平台应及时终止措施。法释〔2020〕9 号：合理期限因公证认证等不可控迟延可不计入，但最长不超过 20 个工作日。不得把该期间写成诉讼时效。

## 节点 5　送达

按约定渠道、工商地址、平台站内信和备份送达设计。已读、口头转告不得写成到达。本任务不预填回证、不代提交。
