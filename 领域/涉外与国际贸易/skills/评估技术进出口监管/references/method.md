# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变请求、路径、期限或金额结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然获批、必然解除、必然承认或唯一必得总额。

限制类技术进出口合同须许可，未经许可不得擅自进出口。自由类通常登记，登记与生效关系须按现行条例核验，不得沿用旧“登记才生效”或新口径而不核验。不得用已失效《合同法》技术合同章条号。

`search_law` 返回已失效《合同法》及其解释、法释〔1999〕19 号、法释〔2007〕14 号或已废外资备案办法时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

## Q# 矩阵

固定列：`编号｜技术内容｜进或出｜分类候选｜程序｜效力红旗｜判断｜待核`。

至少分列：

- `Q-禁 禁止类`
- `Q-限 限制类许可`
- `Q-自 自由类登记`
- `Q-效 合同效力红旗`
- `Q-管 出口管制交叉`

同一事实支持多项时分别说明效果，不重复金额。构成违约不等于当然解除。约定外法不等于可以无证出口或绕开准入。

## 节点 0　分流

纯权属、侵权、海关知识产权备案作为权利保护 → 知识产权。数据出境专项 → 数据。起草许可合同 → 审查起草搁置。
两用物项技术出口管制 → 同时标管制原子，不互相替代。
用户要求把禁止类改写成自由类：停止。

## 节点 1　技术画像

1. 专利、专有技术、软件、技术服务、源代码、培训分列。
2. 实际提供内容以合同和已披露材料为准，不用项目名称粉饰。
3. 进口与出口方向决定适用目录，反向不得套用。

## 节点 2　目录分类

1. 对照禁止进口、禁止出口、限制进口、限制出口目录。未命中则评估自由类。
2. 目录未核验：分类 `依据不足`，不得凭记忆。
3. 禁止类：现有依据支持不得进出口。

## 节点 3　程序

1. 限制类：许可机关、材料接口，不写许可终稿（可转出口许可原子若属于两用许可）。
2. 自由类：合同登记时点和未登记后果待核。
3. 不得把登记回执写成批准实施禁止类。

## 节点 4　合同效力红旗

1. 未经许可的限制类合同效力按条例和民法典待核，不得写成当然有效或当然无效而不核验。
2. 限制受让人改进、强制回授等条款的效力另列，本任务只标监管红旗，条款改写搁置。
3. 出口管制许可与技术进出口许可并行时都要列。

## 节点 5　下一步

输出分类、程序、效力红旗、与 IP 和管制的分界。不起草合同。

## 补充判断

若：合同既含专利实施许可又含专有技术培训 → 分类逐项对照目录，不得只按专利号判断。
若：限制类技术已实际交付但未获许可 → 效力与行政责任分列，不得写成可以补办即溯及有效。
若：自由类登记时点与合同生效条款冲突 → 并列合同约定和条例规则，不选对用户有利的一版写成已生效。
若：技术内容同时落入两用物项清单 → 两条许可并行，不得互相替代。
改进成果归属条款只标效力红旗，改写搁置。
