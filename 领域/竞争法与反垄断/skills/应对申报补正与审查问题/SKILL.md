# 应对申报补正与审查问题

## 任务目标

在明确、无利益冲突的申报方立场下，形成“补正与审查问题答复包”：逐问答复、保密标注、停钟影响。

`depends-on` 为空。接受用户或律师提供的等价申报稿、立案回执和问题清单。

## 工作边界

正触发：已立案审查，收到补正通知或问题清单，本次主成果是答复。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 尚未申报、只要申报包（转 准备经营者集中申报）；
- 改写交易整体、对价或交割（投资并购）；
- 准备附加限制性条件方案（转 准备附加限制性条件方案）；
- 承诺审查结果或批准日；

本任务不改写交易整体，不承诺审查结果，不代提交答复。

## 建立评估坐标

确认：申报义务人；案号或受理号；问题清单版本；答复期限；已提交材料版本；是否已停钟。

同时掌握双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`S#` `D#` `A#` `R#` `C#` `L#` `I#` `G#` `Q#` `ANS#` 答复项；`V#` `E#`。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。不得把 2008 年申报门槛或 2007 年反垄断法条号当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 使用 Lawyeah MCP

`search_law` 核验经营者集中审查规定关于补正、进一步审查、中止计算审限。工具不可用时继续逐问事实答复；停钟法律效果字段停止。

工具不可用时继续事实、主体、程序文书状态和问题清单；法律结论及期限字段停止。

## 五个判断节点

执行顺序和停止条件以 [答复方法](references/method.md) 为准。这里只列入口，不代替节点。

### 节点 1　文书与期限

固定补正或问题清单的作出日、收到日、要求答复日。口头转述不写成已停钟。

### 节点 2　逐问拆解

每问区分事实、数据、法律评价和不知道。不得扩大自认或编造市场份额。

### 节点 3　保密标注

商业秘密、未披露交易信息逐段标注。不得向相对方扩散竞争敏感答复。

### 节点 4　停钟与交割窗口

只列停钟事由接口和交割不得提前。不预测批准日。

### 节点 5　提交核验

文稿为草案。不代提交。交易结构调整归投资并购。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；基础主体或做法无法建立；用户坚持伪造、隐匿、威胁、违法取证或指导规避执法。
- `字段停止`：法域、日期、文书送达、申报标准、动态规则未核验。
- `目标停止`：主目标已变为相邻原子或相邻领域的终稿。

## 交付

严格按 [输出合同](references/output-contract.md) 交付。正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。边界见 [路由](references/routing.md)。
