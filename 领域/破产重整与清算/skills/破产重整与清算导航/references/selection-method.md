# 原子 Skill 选择方法

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果，而不是按清算、重整、和解或行业名称匹配：

- 程序路径总图；破产原因专项；申请权与清算义务；管辖；预重整效力；强制清算转破产；实质合并；代理冲突；
- 债务人／债权人／清算义务人申请；不予受理或驳回上诉；程序转换；受理效果清单；
- 债权申报、补报、债权表异议、确认之诉两造、职工清单一造、别除权、抵销、税社、或然保证债权；
- 财产盘点、撤销应诉、内部人追收、取回两造、待履行合同、保全接口、变价与处置异议；
- 管理人更换、工作报告、会议表决、查阅、衍生诉讼庭审；
- 重整可行性、计划草案、分组表决、强制批准、计划异议、投资招募、终止重整、共益债融资；
- 法定和解可行性与协议、和解异议、庭外或程序内谈判；
- 宣告条件、分配方案与异议、分配瀑布、董事责任、出资加速或抽逃。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权（债务人／债权人／管理人／出资人）；
2. 法院是否已裁定受理；
3. 本次要分析、申请、异议、申报、测算、建卷还是追收诉讼；
4. 是否实为程序外催收、职工安置或普通注销；
5. 是否自然人债务且不在已核验试点条例范围内。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再申请；
4. 用户确认后只启动所选入口；等价评估、测算或证据可由用户或律师提供。

## 四、停止

立场冲突、金融实现主轴、劳动安置主轴或未进入程序只改合同时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。
