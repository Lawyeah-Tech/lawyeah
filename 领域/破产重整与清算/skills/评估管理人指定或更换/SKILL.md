# 评估管理人指定或更换

## 任务目标

形成“法定情形、证据和申请要点”。不保证更换。不指定继任。

`depends-on` 为空。接受用户、律师、管理人、机关或其他来源的等价事实、测算和证据清单。

## 工作边界

正触发：拟申请更换管理人，或审查指定是否存在利害关系。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 保证更换成功或指定某所继任；
- 收案冲突筛查（冲突原子）；
- 日常对中介不满而无破产法定事由；

更换由法院决定。债权人会议可申请。法定情形未核验则申请闸不打开。

## 建立评估坐标

确认：指定裁定、管理人职责履行、利害关系线索、会议决议、拟提交证据。

同时掌握双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`R#` 指定裁定；`D#` 履职；`C#` 利害关系；`L#` 规则；`I#` 判断。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验第 22、24 条及管理人指定规定更换条款。

工具不可用时继续事实、主体、程序文书状态和问题清单；依赖未核验规则的法律结论、期限或机关路径字段停止。

## 五个判断节点

执行顺序和停止条件以 [方法](references/method.md) 为准。这里只列入口，不代替节点。

### 节点 1　角色

债权人会议申请与个别债权人投诉分列。个别投诉可能不够。

### 节点 2　法定情形

不能依法公正执行职务或有其他不能胜任情形，条文待核。

### 节点 3　证据

拖延、利害关系、重大过失须可回链。主观不满不够。

### 节点 4　申请要点

向法院申请。不写继任人选作为法院必须指定的对象。

### 节点 5　与冲突筛查分工

本所自己要不要接任转冲突原子。

## 停止与安全

- `整体停止`：贿买更换或诬告。
- `字段停止`：第 22 条情形未核验。
- `目标停止`：主目标变为指定继任或保证更换。

## 交付

严格按 [输出合同](references/output-contract.md) 十节交付。正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。边界见 [路由](references/routing.md)。
