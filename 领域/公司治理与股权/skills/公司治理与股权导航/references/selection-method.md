# 原子 Skill 选择方法

当前安装包是。先按成果选入口，不按有限公司、股份公司或法条名称匹配，也不存在必须先跑总体评估的流水线。

## 一、先识别成果

- 治理与股东关系总图；
- 公司类型与机关比较、设立文件、章程或章程冲突；
- 形式变更、一人公司安排；
- 出资瑕疵、催缴通知、失权、非货币作价、增资减资、认缴整改、股东责任；
- 决议效力、会议程序、股东会／董事会／书面一致、监事履职；
- 董事义务、任免登记、关联交易；
- 股权控制图、转让、优先购买、名册登记、代持与显名、激励结构与公司文件、股权出质；
- 查阅评估／请求／诉讼，分配评估／诉讼，异议回购，代表诉讼评估／前置／起诉，增资优先认缴；
- 控制权争夺、表决协议、僵局、司法解散、人格否认、控制股东责任、章证照交接；
- 利润或回购测算、出资差额测算、送达设计、账簿保全、鉴定准备；
- 退出谈判、和解协议、股东协议、治理重置；
- 一审起诉或应诉、专项决议／查阅／分配／代表诉讼／解散起诉、庭审、上诉、管辖仲裁、保全申请或应对。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权；
2. 主目标是否为交割、婚家分割、劳动激励或破产；
3. 是否已有仲裁条款、起诉状、催缴、决议或保全裁定；
4. 本次要分析、发通知、作决议、测算、建卷、谈判还是程序文书。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再作决议；
4. 用户确认后只启动所选入口；等价评估、测算或证据可由用户或律师提供。

## 四、停止

立场冲突、专项主轴或一般合同审查起草时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。能力地图未列的入口输出 `unavailable`。
