# 保全公司账簿印章与电子治理记录方法

本文件是可执行判断节点。复制不是已封存。哈希不是已公证。申请不是已裁定。对方控制不是内容有利。占有不是合法封存。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已封存、已裁定、选定法院、代提交、未知写零。本任务不定罪，不执行发送，不写保全申请终稿。本窗闸名只能是封存闸，禁止复用保全闸、印章闸、案卷闸。本窗封存闸不是医疗病历封存闸，也不是财产保全窗保全闸。预留不得占用：僵局闸、谈判闸、和解闸、立案闸、显名闸、保全闸。本窗 `FC#` 是封存行。主路径只用 `Q-账`，禁止用 `Q-保`、`Q-印`、`Q-卷` 作主路径。英文 id 禁止使用，一律用中文技能名 `保全公司账簿印章与电子治理记录`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回 1991 年民事诉讼法第一百零三条协助执行罚款、诉讼文书样式仍引旧第八十一条、解释四第九条仍引旧第三十三条、把复制写成已封存时记为噪声。禁止指导抢夺、破解或侵入。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现对象切片扫描，不是默认闭集。
`FC#` 固定列：`编号｜对象切片｜持有范围｜合法自固｜公证与保全接口｜禁止动作红旗｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已封存」或「已裁定」。无 `E#` 不得写已封存或已公证。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-账`。禁止 `YZ#`、`AJ#`、`QH#`、`A#`、`N#`。文件状态只用 `草案`、`停止`。

口头「已经备份了」「今晚去把账抢回来」「哈希就算公证了」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：仅对己方合法持有或公司已同意接触的材料做复制、哈希、见证人。对方控制办公室强行搬离是抢夺。公证机构只证明提取过程，不保证必然可采。区块链上链前仍是普通证据。行为保全和证据保全申请书终稿转财产保全窗。公司法第五十七条是查阅路径，不是抢簿权源。

## 节点 0　分流、立场、封存闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、抢夺、隐匿、破解、侵入、伪造倒签、违法取证不进负表。利益冲突未解不进整体停止。抢夺不是负触发。

整案转出只交付第 1、2、10 节，不出 `FC#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是证照印章交接包 | 负触发 `准备证照印章管控与交接` |
| 主成果是法院保全申请书终稿 | 负触发 `准备股权或公司财产保全` |
| 主成果是证据案卷矩阵 | 负触发 `建立公司治理与股东争议证据案卷` |
| 主成果是查阅书面请求 | 负触发 `准备查阅复制书面请求` |
| 主成果是查阅权评估 | 负触发 `评估股东知情查阅权` |
| 主成果是已作出保全之应对 | 负触发 `应对股权冻结或行为保全` |
| 主成果是控制权争夺路径 | 负触发 `评估控制权争夺与表决权约束` |
| 合伙或个人独资 | 整案转出，非公司主体 |
| 「不代提交」「不写已封存」「不指导抢夺」 | 交付禁令，不是负触发 |

出现「账簿」「印章」「邮箱」「保全」一词不是转出。

封存闸打开（可出 `FC#` 草案，仍不得标「已封存／已公证／已裁定」）须同时满足：单方无冲突立场已闭合；主成果是合法自固步骤，不是申请书终稿、不是交接包、不是案卷终稿、不是抢簿方案；至少一项可编号对象或持有范围碎片。口头「已经备份了」不算单独开闸材料。

封存闸部分打开：已有碎片，但持有范围未闭合；对应格待核；仍交十节。

封存闸关闭（仍正触发）：无一可编号碎片。「今天必须出已封存终稿」而无最小碎片不得开闸。不出 `FC#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `FC#` 终稿，**第 7 节不得出已封存或抢簿**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「复制即已封存」「哈希即已公证」「申请即已准许」「对方控制即内容有利」「占有即合法封存」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `FC#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 封存闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出抢夺、隐匿、私刻、破解、侵入、购买非法数据、伪造倒签或违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 1　对象切片与持有范围

一行一个对象切片。缺项记 `G#`，不得把未知写成 `0`。本节禁止出 `FC#` 终稿。

| 字段 | 必须记录 | 禁止 |
| --- | --- | --- |
| 对象 | 账簿／凭证／决议／邮箱／网盘／Ukey／印章分列 | 混成一包已封存 |
| 持有 | 己方合法持有／公司同意接触／对方控制分列 | 对方控制办公室强行搬离当自固 |
| 风险 | 灭失、隐匿、难以取得的具体迹象 | 口头「可能没了」升格已灭失 |

检索锚点（写入 `L#` 前须核验）：

- 民事诉讼法（2023 修正）证据保全常见检索第八十四条：可能灭失或以后难以取得。条号须核验全文。噪声：诉讼文书样式仍引旧第八十一条。
- 第一百零三条诉讼中保全含行为保全。第一百零四条诉前保全后三十日内起诉。噪声：1991 年第一百零三条。
- 公司法第五十七条查阅不是封存已完成，不是抢簿权源。第一百一十条股份查阅只开接口。第二百一十六条不得隐匿谎报会计资料只开接口。
- 解释二第三条解散之诉中保全只开接口。
- 民事证据规定电子数据与公证效力只开接口；公证不是必然可采。

## 节点 3　封存行 `FC#`

按已出现对象切片扫描，不是默认闭集。每条须能指向持有范围、自固方法和保全接口。

无 `E#` 不得写已封存或已公证。状态默认 `草案`。一次只推荐下一步。未知件数不写零。

热冲突强制处理：

- 复制即已封存／哈希即已公证／申请即已准许／对方控制即内容有利／占有即合法封存／未知写零 → 该格不支持或字段停止；仍出其他 `FC#`。
- 无一碎片 → 关闸，不出 `FC#` 终稿，窗口不关。
- 指导抢夺、破解、侵入 → 整体停止，不是该格不支持。

## 节点 4　印章、案卷、法院保全与查阅接口

第 7 节只开接口，不得夹带 `FC#` 终稿、已封存结论或抢簿步骤绕闸。闸关闭时第 7 节可写「闸未开，转介待对象编号」，不得补写已封存。不选定法院。不代提交。不保证裁定。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：对方控制财务室和邮箱。用户主张复印件就算封存、哈希就算公证、申请草稿法院一定会准、对方拿着账就推定内容对我有利、不清楚的件数先写零。封存闸打开或半开。`Q-固`、`Q-时`、`Q-推`、`Q-零` 不打开为可靠路径。第 6 节不得把已封存、已公证、已裁定写入可执行 `FC#`；对应格 `现有依据不支持`；仍出对象分列、持有范围、自固缺口、保全接口等其他 `FC#`。不关窗。不代提交。不保证裁定。

场景②：用户同时交出公司「账已封存」与对立股东「对方在毁邮件」口径，要求选对公司有利的一版，并指导「今晚去财务室把账本搬出来、邮箱密码先破解」。命中双方秘密＋抢夺＋侵入。第一次整体停止。只交第 1、10 节。不出 `FC#`。不得问代表哪一方后继续。不以「坚持」为门槛。
