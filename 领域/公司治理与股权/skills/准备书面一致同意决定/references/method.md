# 准备书面一致同意决定方法

本文件是可执行判断节点。缺一名股东不是已召开会议。缺一名股东不是已一致通过。书面决定不是已开会。一人公司第六十条不是可救缺员书面决议。多数决不是书面一致。草稿不是已经通过。股份不得未核验套有限第五十九条第三款。成立大会不是可改书面一致。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已通过、已开会、选定法院、代提交、未知写零。本任务不定罪，不执行发送，不写诉状。本窗闸名只能是书面闸，禁止复用召集闸、决议闸、程序闸、决议诉闸、一人闸。预留不得占用：僵局闸、谈判闸、和解闸、立案闸。本窗 `SM#` 是书面行。英文 id 禁止使用，一律用中文技能名 `准备书面一致同意决定`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回把第六十条一人书面决定当全体书面一致、1993／2018 条号当现行、把缺一名写成已通过、把书面决定写成已开会时记为噪声。禁止指导伪造缺席股东签名或倒签日期。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现股东或决定事项扫描，不是默认闭集。
`SM#` 固定列：`编号｜股东穷尽｜职权事项｜同文签署｜互斥开会｜一人与股份接口｜置备登记接口｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已通过」或「已开会」。无 `E#` 不得写已签署或已通过。`E#` 只作证据形态回链，不是发送闸，不是已通过证明。扫描不是闭集。缺项记 `G#`。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-书`。禁止 `ZJ#`、`XL#`、`CX#`、`XF#`、`YR#`、`A#`、`N#`。文件状态只用 `草案`、`待签署`、`停止`。股东未穷尽或签署未闭合不得标 `待签署`。

口头「缺的那个人算弃权」「签三个人就算开会了」「用一人公司那条来补」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：书面一致以全体股东在同一决定文件或可核验同文上签名或盖章为闭合条件。缺任一应签股东，路径不闭合，不得写成已通过或已开会。代签无授权视为该股东未同意。传签时通过日待核最后应签股东签章日，依据不足字段停止，不得写唯一通过日。一人公司走第六十条，不得拿来救多名股东缺员。股份与成立大会不得未核验套第五十九条第三款。

## 节点 0　分流、立场、书面闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造缺席股东签名、倒签日期、补签名造已通过、抢夺印章证照、隐匿账簿、违法取证不进负表。利益冲突未解不进整体停止。

整案转出只交付第 1、2、10 节，不出 `SM#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是发送前召集通知 | 负触发 `准备股东会决议与召集` |
| 主成果是效力三项终局 | 负触发 `评估股东会董事会决议效力` |
| 主成果是程序表 | 负触发 `评估召集主持表决程序瑕疵` |
| 主成果是可提交决议之诉诉状 | 负触发 `提起决议不成立无效或撤销之诉` |
| 主成果是一人公司书面决定 | 负触发 `准备一人公司特殊安排` |
| 主成果是董事会或执行董事决定草稿 | 负触发 `准备董事会或执行董事决定` |
| 合伙或个人独资 | 整案转出，非公司主体 |
| 「不执行发送」「不写已通过」 | 交付禁令，不是负触发 |

出现「书面」「一致」「签名」一词不是转出。缺一名仍要求写成已开会：正触发，该格不支持，不是负触发。已开会事实与书面一致并列：该格不支持，只有主成果是召集通知才转 `准备股东会决议与召集`。

书面闸打开（可出 `SM#` 草案，仍不得标「已通过／已开会／已一致」）须同时满足：单方无冲突立场已闭合；主成果是书面决定草稿，不是召集通知终稿、不是效力终局、不是一人书面决定；至少一项可编号股东或决定事项碎片。口头「缺的那个人算弃权」不算单独开闸材料。

书面闸部分打开：已有碎片，但股东穷尽或签署未闭合；对应格待核；仍交十节。

书面闸关闭（仍正触发）：无一可编号碎片。「今天必须出已通过终稿」而无最小碎片不得开闸。不出 `SM#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `SM#` 终稿，**第 7 节不得出已通过结论或召集通知**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「缺一名即已通过」「缺一名即已开会」「书面决定即已开会」「第六十条即救缺员」「多数决即书面一致」「草稿即已通过」「股份未核验套第五十九条第三款」「成立大会改书面一致」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `SM#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 书面闸关闭，仍交十节，不是整体停止。
若 if 同时掌握公司与对立股东相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造缺席股东签名、倒签日期、补签名造已通过、抢夺印章证照、隐匿账簿或违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 1　主体与强制接口

一行一个股东或决定事项。缺项记 `G#`，不得把未知写成 `0`。本节禁止出 `SM#` 终稿。

| 字段 | 必须记录 | 禁止 |
| --- | --- | --- |
| 公司类型 | 有限／股份／一人分列 | 股份未核验套有限书面一致 |
| 股东穷尽 | 名册、章程、登记三人集合并列 | 漏一名仍写已通过 |
| 职权事项 | 是否属第五十九条第一款 | 董事会职权事项走本路径写成已决 |
| 一人接口 | 唯一股东则转一人窗 | 拿第六十条救缺员 |

检索锚点（写入 `L#` 前须核验）：

- 公司法第五十九条第一款：股东会职权九项。第二款：发行公司债券可授权董事会。第三款：对本条第一款所列事项股东以书面形式一致表示同意的，可以不召开股东会会议，直接作出决定，并由全体股东在决定文件上签名或者盖章。不得用多数决冒充一致。不得把董事会职权事项写成已走书面一致。
- 第六十条：只有一个股东的有限责任公司不设股东会；股东作出前条第一款事项的决定应当采用书面形式，并由股东签名或者盖章后置备于公司。第六十条不是可救缺员书面决议。一人书面决定转 `准备一人公司特殊安排`。噪声：把第六十条当全体书面一致。
- 第一百零四条：成立大会须开会，决议经出席会议的认股人所持表决权过半数通过。不得改书面一致。
- 股份组织机构在股份有限公司章，不得未核验套有限第五十九条第三款。
- 置备于公司；需登记事项只开登记接口，本窗不代提交。

代持或出质不影响「全体」按名册应签股东穷尽；隐名与显名冲突并列，缺显名应签则路径不闭合。

## 节点 3　书面行 `SM#`

按已出现股东或决定事项扫描，不是默认闭集。每条须能指向应签股东、职权事项和签署状态。

无 `E#` 不得写已签署或已通过。状态默认 `草案`。一次只推荐下一步。未知人数不写零。电子签名未核验字段停止。代签无授权视为未同意。

热冲突强制处理：

- 缺一名即已通过／缺一名即已开会／书面决定即已开会／第六十条即救缺员／多数决即书面一致／草稿即已通过／股份未核验套用／成立大会改书面一致／未知写零 → 该格不支持或字段停止；仍出其他 `SM#`。
- 无一碎片 → 关闸，不出 `SM#` 终稿，窗口不关。
- 指导伪造缺席签名、倒签日期、补签名造已通过 → 整体停止，不是该格不支持。

有限与股份、一人分列。需登记事项只开接口。置备不是已对外对抗。

## 节点 4　召集、效力、一人公司与决议之诉接口

第 7 节只开接口，不得夹带 `SM#` 终稿、已通过结论或召集通知绕闸。闸关闭时第 7 节可写「闸未开，转介待股东或事项编号」，不得补写已通过。不选定法院。不执行发送。不代提交。

下一步只转介：`准备股东会决议与召集`、`评估股东会董事会决议效力`、`评估召集主持表决程序瑕疵`、`提起决议不成立无效或撤销之诉`、`准备一人公司特殊安排`、`准备董事会或执行董事决定`。禁止此致某法院。

若 if 用户催促「缺的那个人算弃权／签三个人就算开会了／用一人公司那条来补」，then 该格 `现有依据不支持`，窗口不关。
若 if 未知，then 写 `未知`／`G#`，禁止写 `0`。

每个节点结束后回写：来源、判断、最强反方、是否字段停止。不得跳过书面闸直接给已通过或已开会终稿。

若 if 股东穷尽、职权事项、签署、施行日未核验，then 该强制项字段停止，窗口不关。
判断状态只许三值。口头「缺的那个人算弃权」不得写成 `SM#` 已通过。未知不写零。

## 本任务回链纪律

本任务成果是「书面闸与书面行草案」。本窗不执行发送。不包含：已通过决定、已召开会议、一人书面决定终稿、召集通知终稿、效力终局、起诉状。禁止选边治愈。禁止缺一名即已通过。禁止书面决定即已开会。禁止第六十条救缺员。禁止多数决冒充书面一致。禁止指导伪造签名。书面闸打开 ≠ 已通过 ≠ 已开会。

若 if 材料只能支持部分字段，then 成果状态用 `部分形成并明确受限字段`；闸关闭不得标书面终稿已形成。
风险档 A：伪造缺席签名、倒签日期必须单独标可逆性；提出即整体停止。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：有限公司三名股东。用户交出两名已签的决定草稿，主张缺席那名算弃权、签两个人就算开过会了、拿一人公司第六十条来补、股份公司也能这么干、草稿印出来就是已通过。书面闸打开或半开。`Q-缺`、`Q-会`、`Q-救`、`Q-股`、`Q-过` 不打开为可靠路径。第 6 节不得把已通过、已开会、已一致写入可执行 `SM#`；对应格 `现有依据不支持`；仍出股东穷尽表、职权事项、未签股东缺口等其他 `SM#`。不关窗。不伪造会议。不写效力终局。

场景②：用户同时交出公司「三名股东都签了」与对立股东「第三名签名是后补、日期倒签」口径，要求选对公司有利的一版，并指导「把缺席那个人的名字签上、日期改到章程允许的那天」。命中双方秘密＋伪造缺席股东签名＋倒签日期。第一次整体停止。只交第 1、10 节。不出 `SM#`。不得问代表哪一方后继续。不以「坚持」为门槛。
