# 原子 Skill 选择方法

## 一、先识别立场和程序状态

先确认当前用户代表谁，以及事项处于哪个可由文书或可回链记录支持的程序状态：

- 拟委托人、犯罪嫌疑人、被告人或辩护人；
- 被害人、控告人、自诉人或其诉讼代理人；
- 紧急入口、首次控告、侦查、审查逮捕、审查起诉、审判或未生效裁判后的上诉准备。

身份、授权、程序阶段、承办机关或关键日期会改变入口但尚未核验时，不把猜测当作路由事实。

## 二、再识别独立成果

按本次要取得的成果选择，而不是只按罪名、法条或文书名称匹配：

- 接案资格、授权和冲突筛查结论；
- 紧急程序状态和首轮行动方案；
- 首次在押会见与会后权利处置成果；
- 取保候审申请包或审查逮捕辩护意见；
- 阅卷证据体系、不起诉意见或认罪认罚决策意见；
- 控告可行性意见、控告材料包或不立案救济材料；
- 审查起诉阶段被害人代理意见；
- 未生效刑事裁判上诉评估；

- 当前阶段案件评估、侦查阶段辩护或撤案意见、羁押必要性审查；
- 律师执业权利救济、侦查违法申诉、非法取证线索保全或正式排除申请；
- 庭前方案、证人鉴定人出庭、庭审质证、一审主张整合或二审代理；
- 死刑复核、法院生效裁判申诉；
- 被害人阶段参与、一审代理、抗诉请求、自诉或附带民事；
- 单位犯罪、未成年审查起诉、和解提案或决策、涉案财物异议。


“评估”和“形成可提交材料”通常是不同成果。例如先判断是否控告与起草控告材料分别进入不同 Skill；但不存在强制组合，用户已经有合格等价评估结果时可以直接启动材料 Skill。

## 三、确认最小上下文

只确认会改变入口的最小信息：

1. 使用者、所代表主体及授权状态；
2. 当前程序状态、承办机关和关键文书；
3. 事件发生、措施采取或文书送达的日期及时区；
4. 本次需要评估、行动方案、申请、意见、材料包还是证据体系；
5. 用户已有材料、既有专业结论和需要排除的相邻成果；
6. 是否存在即时人身、医疗、自伤、失踪、证据灭失或报复风险。

## 四、处理混合请求

一个请求包含多个成果时：

1. 列出每项可独立验收成果及对应入口；
2. 只问一个最能改变本次入口的问题；
3. 用户回答前不指定主要 Skill，不暗示固定先后顺序；
4. 用户只询问是否必须按某顺序调用时，先回答“不必须”；
5. 用户确认后只启动所选入口，其余保留为独立任务；
6. 只有目标 Skill 明确声明必需结果时才提示依赖，并接受律师、机关、用户或其他来源提供的合格等价成果。

## 五、安全和停止

存在即时人身危险、医疗急症、自伤或失踪风险时，先做安全分流，再继续法律入口定位。要求串供、毁证、伪造、冒充、非法取证、威胁证人、泄露秘密或规避措施时拒绝非法部分。

目标成果未安装时输出 `unavailable` 和安全的最近邻领域或专业人员方向，不让现有 Skill 越界代做。
