# 原子 Skill 选择方法

当前安装包是（P0+P1）。先识别成果，再确认上下文。未列入的 P2 输出 `unavailable`。

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果，而不是按商品房、租赁或法条名称匹配：

- 争议总图；
- 管辖、专属或仲裁协议判断；
- 管辖异议或仲裁协议异议；
- 土地使用权、合作开发、预售许可、签约主体；
- 成立效力、认购预约、商品房解除权；
- 逾期交房、面积、宣传、规划变更、办证、质量、按揭不能、资金查封、一房二卖；
- 存量房总图、产权负担、定金、户口占有、中介、交房后隐蔽瑕疵；
- 租赁总图、租赁解除权、租金押金、转租优先、装修附合、买卖不破租赁；
- 物业费、业主大会、业委会、车位共有、擅自改建、物业移交、维修资金；
- 预告异议登记、征收补偿民事段、安置房；
- 催告或解除通知、租赁通知、物业费催缴、对解除的异议；
- 购房款测算或租金物业费测算；
- 证据案卷、现场保全、送达设计、鉴定、保全必要性；
- 谈判方案、和解协议、执行力补强；
- 起诉、应诉、仲裁申请或应诉、庭审、上诉、反诉评估或反诉状、支付令；
- 申请执行或应对执行。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权；
2. 争议是否已经形成；
3. 轨道是商品房、存量房、租赁、物业、开发合作还是登记征收民事段；
4. 是否已有仲裁条款、起诉状、解除通知或执行名义；
5. 本次要分析、发函、测算、建卷、谈判还是程序文书；
6. 是否属于工程价款工期质量、一般合同、金融借贷、婚家或征收行政专项。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再发函；
4. 用户确认后只启动所选入口；等价评估、测算或证据可由用户或律师提供。

## 四、停止

立场冲突、专项主轴或未成争改合同时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。P2 或未安装入口输出 `unavailable`。
