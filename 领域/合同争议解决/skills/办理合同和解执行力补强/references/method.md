# 办理合同和解执行力补强方法

本文件是可执行判断节点。单独和解不是已可强制执行。申请不是已裁定。赋强不是证据保全公证。私下微信和解不是人民调解协议。给付不确定不是可赋强。未知不写零。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已裁定、已赋强、已可执行、选定法院、代申请、未知写零。本任务不定罪，不代申请。本窗闸名只能是力补闸，禁止复用和解闸、方案闸、公证闸、补强闸。预留不得占用：立案闸、和解闸、方案闸、公证闸。本窗 `QF#` 是力补行。主路径只用 `Q-力`，禁止用 `Q-和`、`Q-方`、`Q-公`、`Q-执`、`Q-赋`、`Q-强`、`Q-签` 作主路径。本窗 `Q-签` 只作「草稿即已提交」不关窗码。本窗 `Q-执` 只作「单独和解即已可强制执行」不关窗码。英文 id 禁止使用，一律用中文技能名 `办理合同和解执行力补强`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回 1991 年民事诉讼法第二百零五条破产管辖、2012 年第一百九十四条、2021 年第二百零一条、2005 年公证法第三十七条未核 2017、把单独和解写成已可强制执行时记为噪声。禁止指导伪造调解组织或倒签。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现名义切片扫描，不是默认闭集。
`QF#` 固定列：`编号｜名义切片｜路径分流司法确认／公证赋强／调解书｜给付是否确定｜申请接口｜失败分流｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已可强制执行」。无 `E#` 不得写已确认、已赋强或已出调解书。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-力`。禁止 `HJ#`、`FA#`、`GD#`、`Pth#`、`LB#`、`A#`、`N#`。文件状态只用 `草案`、`停止`。

口头「签了就能强制执行」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：私下和解通常只有合同约束力。人民调解后双方三十日内共同申请司法确认。诉讼中自行和解可申请制作调解书，不得请求出判决书。赋强须给付确定、无疑义、债务人书面承诺接受强制执行。证据保全公证不是赋强。执行和解另窗。

## 节点 0　分流、立场、力补闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造调解组织、伪造赋强承诺、倒签、掩盖犯罪或逃废债务、违法取证不进负表。利益冲突未解不进整体停止。不代申请、不保证确认不是负触发。

整案转出只交付第 1、2、10 节，不出 `QF#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是可签和解正文 | 负触发 `起草合同和解协议` |
| 主成果是谈判方案要点 | 负触发 `谈判合同和解方案` |
| 主成果是调解方案利弊 | 负触发 `评估合同调解方案与效力` |
| 主成果是执行中分期或以物抵债 | 负触发 `准备合同执行和解` |
| 主成果是证据保全公证 | 负触发 `准备合同案件公证保全` |
| 主成果是已生效名义强制执行 | 负触发 `执行合同生效文书` |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改合同或出稿 | 整案转审查起草（本窗搁置，只说明不实施） |
| 建设工程／金融借贷担保／房地产物业／海事／劳动主轴 | 整案转对应领域 |
| 「不代申请」「不保证确认」 | 交付禁令，不是负触发 |

出现「和解」「确认」「公证」一词不是转出。

力补闸打开须同时满足：单方无冲突立场已闭合；主成果是手续草稿，不是协议正文、不是已可执行终稿；至少一项可编号给付和解碎片或路径前提。口头「签了就能强制执行」不算单独开闸材料。

力补闸部分打开：已有碎片，但路径前提、给付或承诺未闭合；仍交十节。

力补闸关闭（仍正触发）：无一可编号碎片。不出 `QF#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `QF#` 终稿，**第 7 节不得出已裁定、已赋强或已出调解书**。

「单独和解即已可强制执行」「申请即已裁定」「赋强即证据保全公证」「私下微信即人民调解」「未知写零」**不关窗**。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 力补闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造调解组织、伪造赋强承诺、倒签调解或公证日、以确认或赋强掩盖犯罪或逃废债务、违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 3　力补行 `QF#`

按已出现名义切片扫描，不是默认闭集。每条须能指向路径、给付或申请接口之一。

无 `E#` 不得写已确认、已赋强或已出调解书。状态默认 `草案`。一次只推荐下一步。未知不写零。给付或承诺未闭合不得标待提交。

热冲突强制处理：

- 单独和解即已可强制执行／申请即已裁定／赋强即证据保全公证／私下微信即人民调解／未知写零 → 该格不支持或字段停止；仍出其他 `QF#`。
- 无一碎片 → 关闸，不出 `QF#` 终稿，窗口不关。
- 指导伪造调解组织、倒签、掩盖犯罪 → 整体停止，不是该格不支持。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：买卖尾款私下微信和解。用户主张签了就能强制执行、把聊天记录拿去司法确认、申请了就一定裁定、金额先写大概、此致某中院、不清楚先写零。力补闸打开或半开。`Q-执`、`Q-准`、`Q-院`、`Q-零` 不打开为可靠路径。第 6 节不得把已可执行、已裁定、0、私下微信当人民调解写入可执行 `QF#`；对应格 `现有依据不支持` 或字段停止；仍出路径分列、给付缺口、失败分流。不代申请。

场景②：用户同时交出己方「必须马上能执行」与对方「只同意延期、不同意赋强承诺」口径，并要「倒签人民调解、把逃废债务写成已确认」。命中双方秘密＋伪造调解组织＋倒签＋逃废。第一次整体停止。只交第 1、10 节。不出 `QF#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代伪造方案。
