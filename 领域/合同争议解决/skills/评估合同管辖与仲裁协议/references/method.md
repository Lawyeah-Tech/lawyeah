# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变主位论坛、效力或异议期限结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然受理、唯一有管辖权法院，或在表面有效仲裁条款下写“应起诉”。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

《仲裁法》版本、条号和施行日一律运行时核验后写入 `L#`。不得沿用记忆条号。无法核验则效力、论坛和期限字段停止。

## Q# 论坛假设

固定列：`编号｜论坛类型｜提出方｜相对方｜文本定位｜成立条件｜支持事实｜不利事实｜控制方｜最强反方｜主备位｜判断｜待核`。

至少分列：`Q-仲` 仲裁入口；`Q-诉` 一审诉讼入口；`Q-协管` 协议管辖；`Q-法定` 法定地域／级别管辖；`Q-异` 管辖或仲裁协议异议。同一条款支持多项时分别说明效果。构成违约不等于当然取得起诉权。

## 节点 1　主体、文本版本和程序状态

1. 固定主合同、补充协议、订单、对账单、单独仲裁协议和事后书面协议的版本层级。仲裁条款与管辖条款冲突时并列，不选对用户有利的一版冒充唯一文本。
2. 主体表记录签约名、履行名、未签字但可能被主张受约束的主体。名称不一致不自动合并；未签字主体对仲裁协议的约束标 `依据不足`。
3. 程序表逐动作记录协商、起诉、仲裁申请、应诉通知、答辩、首次开庭、已提出的管辖或仲裁协议异议：机关／机构、案号、文书、作出日、收到日、送达方式和效力凭证。
4. 口头转述、截图、微信“已读”不得写成已受理、已送达或异议期限已起算。
5. 同时掌握双方秘密或立场不明：整体停止策略输出。

若：用户只要起诉状或完整立案包 → 目标停止，转 `file-first-instance` 或 `file-arbitration`，本任务不改写成立案包。  
若：异议期已过且唯一目标是赶写异议书 → 负触发，转 `object-to-jurisdiction` 或 `object-to-arbitration-agreement`，并标明逾期风险，不代写终稿。

## 节点 2　协议文本回链与书面形式

每个条款一行，必须能回链到 `C#` 或 `D#` 的页码／条款号／聊天原文。

| 条件 | 判断 | 禁止写成 |
| --- | --- | --- |
| 合同、补充协议、事后书面协议均无仲裁条款，且无单独仲裁协议 | `Q-仲` 现有依据不支持 | 仍须先仲裁 |
| 仅有口头“以后仲裁／到某地打官司” | 书面形式现有依据不支持 | 已存在仲裁协议或协议管辖 |
| 有可定位书面条款，但签署页、电子确认或授权不明 | 书面形式 `依据不足` | 当然有效或当然无效 |
| 格式条款且相对方主张未作提示说明 | 效力字段停止或 `依据不足` | 直接无效或直接有效 |
| 主合同仲裁、补充协议约定起诉，或相反 | 文本冲突并列 | 只保留对用户有利的一版 |

书面形式包括合同条款和其他书面方式，含数据电文；是否构成现行法上的书面仲裁协议，必须 `search_law` 核验 2025 文本后再落 `L#`。核验失败则本节点法律结论字段停止，文本对照表继续。

## 节点 3　仲裁意思、事项覆盖、机构是否选定或存在

三项独立判断，不得合成“仲裁条款看起来有效”。

### 3.1 请求仲裁的意思

若：条款仅约定“协商不成依法解决／可诉讼可仲裁”而无法读出确定的仲裁意思 → 仲裁意思 `依据不足`，不选定唯一论坛。  
若：条款写明将争议提交仲裁 → 仲裁意思现有依据支持，仍须过事项和机构闸。

### 3.2 事项是否覆盖本案

将本案 `Q#` 请求与条款中的“本合同争议／与本合同有关／明确排除的事项”逐项对照。  
若：价款、质量、解除、违约金等本案请求未被覆盖 → 未被覆盖的请求不得写入仲裁主位。  
若：覆盖范围原文含混 → 事项覆盖 `依据不足`。

### 3.3 机构是否选定或存在

| 条件 | 判断 | 本任务输出 |
| --- | --- | --- |
| 机构名称可确定且有现行存续依据 | 选定现有依据支持 | 记下机构全称、规则待核 |
| 名称不准但依表面文义可能确定 | `依据不足` | 列可能对应机构，转介核验，不指定唯一机构 |
| 未写机构、机构已撤销且无承继、约定两个机构而未选定 | `依据不足` | **不选定唯一论坛** |
| 仅约定仲裁地或仅约定适用某规则、未确定机构 | `依据不足` | 不补写一个“常用机构” |

临时仲裁仅在现行法明文允许的有限情形下作为待核接口，不在一般合同国内争议中写成默认入口。

## 节点 4　或裁或诉、独立性与主位论坛

### 4.1 或裁或诉

若：同一争议既约定仲裁又约定起诉，或约定“可仲裁也可诉讼” → 效力必须运行时核验现行《仲裁法》及配套解释；核验完成前主位论坛标 **未选定**，输出 `依据不足，无法形成结论`。  
禁止凭 2017 文本记忆直接写成无效或有效。

一方已申请仲裁且对方未在法定期间提出异议，或一方已起诉且对方应诉未提异议：只记录程序事实和失权红旗，是否构成对救济途径的变更仍须 `search_law`；不得把“准备起诉”写成已经排除仲裁。

### 4.2 独立性

若：用户主张主合同未成立、无效、被撤销或已终止，因而仲裁条款当然消灭 → 现有依据不支持该推论。合同无效不当然消灭仲裁协议。独立性规则写入 `L#` 前必须核验 2025 文本，不得写 2017 年记忆条号。

### 4.3 主位论坛闸

| 条件 | 主位论坛 | 禁止 |
| --- | --- | --- |
| 书面形式、仲裁意思、事项覆盖、机构选定均现有依据支持，且无或裁或诉冲突 | 仲裁 | 写“应向法院起诉”“去法院更稳妥” |
| 或裁或诉、机构不明、未签字主体、事项覆盖不清 | 未选定 | 指定唯一论坛 |
| 无仲裁协议，或现有依据不支持其适用于本案 | 诉讼入口可列为可行 | 仍写成必须仲裁 |
| 已有可回链的无效、失效或双方以应诉等方式变更救济的事实 | 按核验后的事实列主备位 | 忽略已发生的应诉或异议 |

有表面有效仲裁条款，不得写“应起诉”。用户坚持“直接去法院更稳妥”时，先完成本闸；诉讼入口标负触发，除非无效、失效或变更救济的事实已经可回链。

## 节点 5　诉讼连结点、异议期限待核与转出

### 5.1 诉讼入口

仅当节点 4 允许诉讼列为可行入口时，才展开连结点表。固定列：`连结点｜事实依据｜与争议有无实际联系｜级别管辖待核｜专属管辖待核｜协议管辖原文｜判断｜最强反方`。

协议管辖只承认与争议有实际联系的地点候选（被告住所地、合同履行地、合同签订地、原告住所地、标的物所在地等），且不得违反级别管辖和专属管辖。连结点冲突建立并行情景，**不选定唯一法院**。

履行地不明、合同未实际履行且双方住所地均不在约定履行地：标 `依据不足`，并列被告住所地候选，不编造履行地。

### 5.2 异议期限

每种期间单独一行，类型标明仲裁协议异议／法院管辖异议／应诉失权。禁止用三年诉讼时效去算异议期。

| 条件 | 本任务输出 | 禁止 |
| --- | --- | --- |
| 尚未进入诉讼或仲裁 | 标“进入程序后待核” | 编造一个截止日期充作法律意见 |
| 已收到起诉状或应诉通知 | 红旗：答辩期间提出管辖异议；具体起算依赖送达事实和 `search_law` | 写管辖异议书终稿；仅凭微信已读起算 |
| 已收到仲裁申请或仲裁通知 | 红旗：对仲裁协议效力提出异议的时点待核 | 写仲裁协议异议终稿 |
| 送达日冲突或仅有“已读” | 并行情景 + 字段停止 | 选对用户最有利的一天 |

微信已读不等于到达。没有送达事实和规则引文，禁止写“异议期已起算”或“已经失权”。

### 5.3 转出

| 条件 | 本任务输出 | 转介 |
| --- | --- | --- |
| 主位论坛为仲裁且用户决定申请 | 最小交接：机构、事项、协议文本定位 | `file-arbitration` |
| 主位论坛为诉讼且用户决定起诉 | 最小交接：连结点待核表，不指定唯一法院 | `file-first-instance` |
| 已被起诉，需在法定期限提管辖异议 | 红旗、连结点、逾期风险 | `object-to-jurisdiction`，不写终稿 |
| 对方依仲裁条款推进，己方主张无效或不适用 | 效力争点表 | `object-to-arbitration-agreement` |
| 已进入实体应诉且目标变为答辩 | 目标停止 | `defend-first-instance` 或 `defend-arbitration` |

保全只做红旗，不写保全申请。C 端 032／012／011 只分流，不回改、不在本任务实施其成果。

## 证据与下一步

证据矩阵列待证事实（签署、提示说明、机构存续、送达、应诉）、支持与不利、控制方、合法取得、缺口和最晚时点。不能因对方控制而推定材料存在或内容有利。

下一步按异议期限灭失、送达固定、条款原文调取、可逆性排序。管辖异议书、仲裁申请、起诉状只写转介条件和最小交接。禁止指导伪造连结点、伪造送达或隐匿仲裁条款。
