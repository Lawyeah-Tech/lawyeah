# 起草合同和解协议方法

本文件是可执行判断节点。草稿不是已签署。口头谈拢不是已和解。单独和解不是已可强制执行。概括弃权不是覆盖未知请求。未知不写零。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已签署、已可执行、选定法院、代签署、未知写零。本任务不定罪，不代签署。本窗闸名只能是和解闸，禁止复用方案闸、谈判闸、发送闸、起诉闸、清理闸。预留不得占用：立案闸、方案闸。本窗 `HJ#` 是合同和解行，不得抄股东和解的名册、章证照列。主路径只用 `Q-和`，禁止用 `Q-方`、`Q-谈`、`Q-签`、`Q-诉`、`Q-函`、`Q-理` 作主路径。本窗 `Q-签` 只作「草稿即已签署」不关窗码。本窗 `Q-口` 只作「口头即已和解」不关窗码。本窗 `Q-执` 只作「单独和解即已可强制执行」不关窗码。英文 id 禁止使用，一律用中文技能名 `起草合同和解协议`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效合同法第七十七条、执行和解、破产和解、劳动和解或把单独和解写成已可强制执行时记为噪声。禁止指导伪造协议或倒签。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现标的切片扫描，不是默认闭集。
`HJ#` 固定列：`编号｜标的切片｜给付与了断范围｜效力与执行力接口｜撤回或违约后果｜签署接口｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已签署」或「已可强制执行」。无 `E#` 不得写已签署。核心给付、了断未闭合不得标 `待签署`。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-和`。禁止 `FA#`、`TP#`、`QT#`、`HF#`、`QL#`、`A#`、`N#`。文件状态只用 `草案`、`待签署`、`停止`。

口头「已经和解」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：协商一致可以变更合同。单独和解通常只有合同约束力。要强制执行须调解书、司法确认或公证赋强，本窗只开接口。诉讼中自行和解可申请确认制作调解书，不得请求直接出判决书。执行和解另窗。

## 节点 0　分流、立场、和解闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造协议或签章、倒签签署日、伪造流水、以和解掩盖犯罪或逃废债务、违法取证不进负表。利益冲突未解不进整体停止。不代签署、不保证司法确认不是负触发。

整案转出只交付第 1、2、10 节，不出 `HJ#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是谈判方案要点（尚未谈拢） | 负触发 `谈判合同和解方案` |
| 主成果是司法确认或赋强 | 负触发 `办理合同和解执行力补强` |
| 主成果是调解方案利弊 | 负触发 `评估合同调解方案与效力` |
| 主成果是返还清理独占 | 负触发 `处理解除后返还与清理` |
| 主成果是执行中分期或以物抵债 | 负触发 `准备合同执行和解` |
| 主成果是股东退出或股权和解 | 负触发公司治理 `起草股东和解或退出协议` |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改合同或出稿 | 整案转审查起草（本窗搁置，只说明不实施） |
| 建设工程／金融借贷担保／房地产物业／海事／劳动主轴 | 整案转对应领域 |
| 「不代签署」「不保证司法确认」 | 交付禁令，不是负触发 |

出现「和解」一词不是转出。

和解闸打开须同时满足：单方无冲突立场已闭合；主成果是已谈拢可签草稿；至少一项可编号标的、给付或了断碎片。口头「已经和解」不算单独开闸材料。

和解闸部分打开：已有碎片，但给付、了断、执行力或签署主体未闭合；仍交十节。

和解闸关闭（仍正触发）：无一可编号碎片。不出 `HJ#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `HJ#` 终稿，**第 7 节不得出已签署或已可执行**。

「草稿即已签署」「口头即已和解」「单独和解即已可强制执行」「概括弃权覆盖未知」「未知写零」**不关窗**。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 和解闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造协议或签章、倒签签署日、伪造流水、以和解掩盖犯罪或逃废债务、违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 1　主体与强制接口

一行一个标的切片。缺项记 `G#`，不得把未知写成 `0`。本节禁止出 `HJ#` 终稿。

| 字段 | 必须记录 | 禁止 |
| --- | --- | --- |
| 切片 | 价款／货物／服务／违约金分列 | 合成「全部了结」 |
| 给付 | 金额、账户、期限、同时履行 | 未知写零 |
| 了断 | 明示放弃的请求范围 | 概括弃权覆盖未知 |
| 效力 | 合同约束力与执行力分列 | 单独和解升格可强制执行 |
| 签署 | 主体、授权、份数 | 口头升格已签署 |

检索锚点（写入 `L#` 前须核验）：民法典第五百四十三条。噪声：合同法第七十七条；执行和解套诉讼前和解；破产和解。

## 节点 3　和解行 `HJ#`

按已出现标的切片扫描，不是默认闭集。每条须能指向标的、给付或了断之一。

无 `E#` 不得写已签署。状态默认 `草案`。一次只推荐下一步。未知不写零。核心给付、了断未闭合不得标待签署。

热冲突强制处理：

- 草稿即已签署／口头即已和解／单独和解即已可强制执行／概括弃权覆盖未知／未知写零 → 该格不支持或字段停止；仍出其他 `HJ#`。
- 无一碎片 → 关闸，不出 `HJ#` 终稿，窗口不关。
- 指导伪造、倒签、掩盖犯罪 → 整体停止，不是该格不支持。

## 节点 4　方案、赋强、调解与清理接口

第 7 节只开接口，不得夹带 `HJ#` 终稿或已签署绕闸。闸关闭时第 7 节可写「闸未开，转介待事项编号」，不得补写已签署。不代签署。不选定法院。

下一步只转介：`谈判合同和解方案`、`办理合同和解执行力补强`、`评估合同调解方案与效力`、`处理解除后返还与清理`、`准备合同执行和解`、`评估合同争议`、`测算违约金与损害赔偿`、`评估解除权是否成立`、`评估继续履行是否可能`、`评估定金罚则争议`、`评估合同管辖与仲裁协议`、`选择诉讼仲裁或督促程序`、`提起合同纠纷一审`、`应对合同纠纷一审`、`准备催告履行或补救通知`、`准备解除通知`、`建立合同争议证据案卷`。禁止此致某院。

若 if 用户催促「微信说签了就算和解／这份协议就能强制执行／不清楚先写零／永不追究所有事」，then 该格 `现有依据不支持` 或字段停止。
若 if 未知，then 写 `未知`／`G#`，禁止写 `0`。

## 再执行清单

每个节点结束后回写：来源、判断、最强反方、是否字段停止。不得跳过和解闸直接给已签署或已可执行终稿。

若 if 效力、执行力、弃权范围、施行日未核验，then 该强制项字段停止，窗口不关。
判断状态只许三值。口头「已经和解」不得写成 `HJ#` 已签署。未知不写零。

## 本任务回链纪律

本任务成果是「和解闸与和解行草案」。本窗不代签署。不包含：已签署、已可强制执行终稿、调解书、司法确认申请。禁止选边治愈。禁止草稿即已签署。和解闸打开 ≠ 已签署 ≠ 已和解 ≠ 已可强制执行。

若 if 材料只能支持部分字段，then 成果状态用 `部分形成并明确受限字段`；闸关闭不得标协议终稿已形成。
风险档 A：伪造协议、倒签签署日、掩盖犯罪必须单独标可逆性；提出即整体停止。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：买卖尾款争议，双方微信说各让一步。用户要协议写成已经签了、口头就算和解、这份协议就能直接强制执行、永不追究所有已知未知、不清楚先写零。和解闸打开或半开。`Q-签`、`Q-口`、`Q-执`、`Q-零` 不打开为可靠路径。第 6 节不得把已签署、已和解、已可执行、0、覆盖未知写入可执行 `HJ#`；对应格 `现有依据不支持` 或字段停止；仍出给付分列、了断范围、执行力接口。不代签署。

场景②：用户同时交出己方「必须让对方永不追究」与对方「只谈延期付款」口径，并要「倒签上周已签、把犯罪事实写成商业纠纷」。命中双方秘密＋倒签＋掩盖犯罪。第一次整体停止。只交第 1、10 节。不出 `HJ#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代倒签方案。
