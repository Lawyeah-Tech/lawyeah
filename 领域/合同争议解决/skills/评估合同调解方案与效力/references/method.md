# 评估合同调解方案与效力方法

本文件是可执行判断节点。调解书双方签收才生效。拒收不是已可执行。评估不是已出调解书。口头同意不是已生效。人民调解未确认不是已可强制执行。未知不写零。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已出调解书、已可执行、选定法院、代签收、未知写零。本任务不定罪，不代替庭审。本窗闸名只能是调解闸，禁止复用方案闸、和解闸、力补闸、公证闸、媒效闸。预留不得占用：立案闸、和解闸、方案闸、力补闸。本窗 `TJ#` 是调解行。主路径只用 `Q-媒`，禁止用 `Q-方`、`Q-和`、`Q-力`、`Q-调`、`Q-签` 作主路径。本窗 `Q-签` 只作「评估即已出调解书」不关窗码。本窗 `Q-执` 只作「拒收即已可强制执行」不关窗码。本窗 `Q-口` 只作「口头即已调解」不关窗码。本窗 `Q-悔` 只作「反悔窗口未核即已确定」不关窗码。英文 id 禁止使用，一律用中文技能名 `评估合同调解方案与效力`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回 1991 年民事诉讼法第一百条拘传、2017 年第九十七条、2017 年第一百条保全、把拒收写成已可执行时记为噪声。禁止指导伪造调解书或倒签。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现方案切片扫描，不是默认闭集。
`TJ#` 固定列：`编号｜方案切片｜程序前提｜签收或生效｜反悔或无效接口｜与确认赋强分流｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已出调解书」或「已可执行」。无 `E#` 不得写已签收。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-媒`。禁止 `FA#`、`HJ#`、`QF#`、`MD#`、`A#`、`N#`。文件状态只用 `草案`、`停止`。

口头「已经调成了」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：诉讼调解书双方签收生效，以最后签收日为准。送达前反悔应及时判决。不适用留置送达。即时履行可不制作调解书，须记入笔录签名盖章。人民调解协议有约束力，未确认不是执行名义。调解妥协原则上不得作后续不利自认。

## 节点 0　分流、立场、调解闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造调解书或签章、倒签签收日、掩盖犯罪或逃废、违法取证不进负表。利益冲突未解不进整体停止。不代替庭审、不保证出调解书不是负触发。

整案转出只交付第 1、2、10 节，不出 `TJ#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是谈判方案要点 | 负触发 `谈判合同和解方案` |
| 主成果是可签和解正文 | 负触发 `起草合同和解协议` |
| 主成果是司法确认、赋强或申请制作调解书 | 负触发 `办理合同和解执行力补强` |
| 主成果是执行中分期或以物抵债 | 负触发 `准备合同执行和解` |
| 主成果是庭审质证提纲 | 负触发 `准备合同案件庭审` |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改合同或出稿 | 整案转审查起草（本窗搁置，只说明不实施） |
| 建设工程／金融借贷担保／房地产物业／海事／劳动主轴 | 整案转对应领域 |
| 「不代替庭审」「不保证出调解书」 | 交付禁令，不是负触发 |

出现「调解」一词不是转出。

调解闸打开须同时满足：单方无冲突立场已闭合；主成果是利弊与效力评估，不是正文、不是手续终稿、不是庭审提纲；至少一项可编号调解类型、方案对照或效力碎片。口头「已经调成了」不算单独开闸材料。

调解闸部分打开：已有碎片，但签收、反悔或类型未闭合；仍交十节。

调解闸关闭（仍正触发）：无一可编号碎片。不出 `TJ#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `TJ#` 终稿，**第 7 节不得出已出调解书或已可执行**。

「评估即已出调解书」「拒收即已可执行」「口头即已调解」「反悔未核即已确定」「未知写零」**不关窗**。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 调解闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造调解书或签章、倒签签收日、以调解掩盖犯罪或逃废债务、违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 3　调解行 `TJ#`

按已出现方案切片扫描，不是默认闭集。每条须能指向类型、对照请求或效力之一。

无 `E#` 不得写已签收或已出调解书。状态默认 `草案`。一次只推荐下一步。未知不写零。反悔窗口未核验不得写成已确定。

热冲突强制处理：

- 评估即已出调解书／拒收即已可执行／口头即已调解／反悔未核即已确定／未知写零 → 该格不支持或字段停止；仍出其他 `TJ#`。
- 无一碎片 → 关闸，不出 `TJ#` 终稿，窗口不关。
- 指导伪造调解书、倒签、掩盖犯罪 → 整体停止，不是该格不支持。

## 节点 4　方案、起草、力补与庭审接口

第 7 节只开接口，不得夹带 `TJ#` 终稿或已可执行绕闸。闸关闭时第 7 节可写「闸未开，转介待事项编号」，不得补写已出调解书。不代签收。不选定法院。

下一步只转介：`谈判合同和解方案`、`起草合同和解协议`、`办理合同和解执行力补强`、`准备合同执行和解`、`准备合同案件庭审`、`评估合同争议`、`测算违约金与损害赔偿`、`评估解除权是否成立`、`评估继续履行是否可能`、`评估定金罚则争议`、`评估合同管辖与仲裁协议`、`选择诉讼仲裁或督促程序`、`提起合同纠纷一审`、`应对合同纠纷一审`、`提起合同仲裁`、`处理解除后返还与清理`、`建立合同争议证据案卷`。禁止此致某院。

本任务成果是「调解闸与调解行草案」。本窗不代签收。不包含：已出调解书、已可强制执行终稿、和解协议正文、确认申请。禁止选边治愈。禁止评估即已出调解书。调解闸打开 ≠ 已签收 ≠ 已出调解书 ≠ 已可强制执行。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：买卖尾款诉讼中法院主持调解。用户主张口头同意就算生效、拒收调解书也能强制执行、评估完就算已经出了调解书、调解里认的数字后续都能当自认、不清楚先写零。调解闸打开或半开。`Q-口`、`Q-执`、`Q-签`、`Q-零` 不打开为可靠路径。第 6 节不得把已生效、已可执行、已出书、0 写入可执行 `TJ#`；对应格 `现有依据不支持` 或字段停止；仍出类型分列、签收缺口、反悔窗口、自认接口。不代签收。

场景②：用户同时交出己方「必须让对方签收」与对方「只同意延期、不同意出调解书」口径，并要「倒签上周已签收、把逃废写成调解」。命中双方秘密＋倒签＋逃废。第一次整体停止。只交第 1、10 节。不出 `TJ#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代倒签方案。
