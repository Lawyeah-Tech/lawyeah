# 解释争议条款与填补漏洞

## 任务目标

在明确、无利益冲突的单方立场下（主张某一解释或填补一方或其受托律师，互斥），形成争议条款解释草案：解释闸、主体与强制接口、`Q#` 路径、`JX#` 解释行（条款切片／文义与体系／目的习惯诚信／格式／不利解释接口／漏洞填补候选／`E#` 回链）。本窗 `JX#` 是解释行草案，不是已改约，不是补充协议已成立，不是唯一有利解释，不是确认之诉诉状。本窗闸名只能是解释闸，禁止复用条款闸、格式闸、填补闸、成立闸、效力闸、评估闸、争议闸、变更闸。预留不得占用：立案闸。本窗主行只能是 `JX#`，禁止 `SY#`、`CL#`、`ZT#`、`TK#`、`JS#`、`A#`。主路径只用 `Q-释`，禁止用 `Q-契`、`Q-条`、`Q-漏`、`Q-补`、`Q-文`、`Q-义`、`Q-格`、`Q-签` 作主路径。邻窗 `Q-释` 只作转介进本窗；本窗打开为主路径，不是已解释终局、不是已改约。本窗 `Q-签` 只作「解释即已确认或已改约」不关窗码。解释闸打开不等于已改约不等于补充协议已成立不等于习惯已证成不等于不利解释已适用不等于请求已成立不等于应起诉。填补漏洞不是已经改约。有歧义不是当然不利格式提供方。单方惯例不是双方习惯。对我方有利不是唯一解释。目的不是推翻清晰文义。未知不写零。不重写整份合同。不写确认之诉诉状。不选定法院。不代提交。不定罪。不保证胜诉。伤残等级与本窗无关，禁止折入。

`depends-on` 为空。主成果是争议总图转 `评估合同争议`。主成果是成立效力专项转 `评估合同成立与效力`。主成果是格式条款提示说明与效力转 `评估争议中的格式条款`。主成果是框架与订单冲突转 `评估框架协议与订单冲突`。主成果是变更是否成立转 `评估变更是否成立`。英文 id 禁止使用，一律用中文技能名。

## 工作边界

正触发：一般合同已成争，核心条款歧义、冲突或漏洞决定请求或抗辩能否成立。「这句话怎么解释」「价款没写清怎么补」仍正触发，成果状态 `草案`。习惯、目的、文本冲突未核验仍正触发：有可编号争议条款、冲突文本或约定不明碎片则解释闸打开或半开，第 6 节出 `JX#` 草案，缺项记 `G#`。无一可编号碎片、又要求「今天必须出已改约／唯一有利解释终稿」才关闸，仍交十节，第 6 节不出 `JX#` 终稿，第 7 节不得出新合同或已改约，窗口不关。用户要把填补写成已改约、把有歧义写成当然不利格式提供方、把单方惯例写成双方习惯、把对我方有利写成唯一解释、把目的写成推翻清晰文义、把选有利文本写成唯一文本、把未知写成零，仍正触发：对应格填 `现有依据不支持` 或字段停止，窗口不关；闸已开仍出其他 `JX#` 草案。不得因「不重写合同」「不把解释写成已改约」改走负触发关窗。利益冲突未解不是整体停止。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 主成果是争议总图（转 `评估合同争议`）；
- 主成果是成立或效力专项（转 `评估合同成立与效力`）；
- 主成果是格式条款提示说明与效力（转 `评估争议中的格式条款`）；
- 主成果是框架与订单冲突（转 `评估框架协议与订单冲突`）；
- 主成果是变更是否成立（转 `评估变更是否成立`）；
- 主成果是电子到达或电子签名专项（转 `评估电子合同成立与送达`）；
- 主成果是确认之诉诉状（转 `提起合同成立或效力确认之诉`）；
- 尚未成争，只要改条款或重写合同（审查起草领域，本窗搁置，只说明不实施）；
- 建设工程、金融借贷担保、房地产物业、海事、劳动专项争议主轴。

双方秘密、伪造合同或修订、倒签修订日、隐匿文本、违法取证**不在负触发表**，走整体停止。「填补即已改约」「有歧义即不利提供方」「单方惯例即双方习惯」「对我方有利即唯一解释」「目的推翻清晰文义」「选有利文本冒充唯一」「未知写零」**不在负触发表**，该格 `现有依据不支持` 或字段停止，窗口不关。「不重写合同」「不把解释写成已改约」是交付禁令，不是负触发。主成果才转；出现「解释」「漏洞」一词不是转出。

## 建立工作坐标

确认：解释授权；单方立场；合同及附件、订单、修订记录版本；争议条款原文；法域；当前协商、催告、仲裁或诉讼状态。

口头「按对我们有利的意思」「行业都这么做」只登记 `S#`／`V#`。不得升格已改约、习惯已证成或唯一解释，**不得单独算作开闸材料**。可编号争议条款原文、冲突文本或约定不明碎片可开闸。本窗不执行发送，不代提交，不重写整份合同。

立场只许主张某一解释或填补一方或其受托律师，互斥。同时掌握对立双方相互冲突的秘密：`整体停止`，不得选边，不得问代表哪一方后继续。无一可编号碎片：解释闸关闭，仍交十节，不是整体停止。无书面解释授权但单方立场已闭合、且已有碎片：解释闸部分打开，仍交十节，不是整体停止。提出伪造合同或修订、倒签修订日、隐匿文本或违法取证：第一次提出即整体停止，不以「坚持」为门槛。利益冲突未解：不是整体停止。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`R#` 机关或生效文书；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口；`Q#` 路径；`JX#` 解释行；`V#` 版本；`E#` 证据形态回链（条款原文、冲突文本、磋商或履行，不是发送闸，不是已改约证明）。承认只进 `S#`／`D#`，不得占用 `A#`。禁止 `N#`、`A#`、`SY#`、`CL#`、`ZT#`、`TK#`。技能正文中的条号是检索锚点，不是已核验 `L#`。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。稿件状态默认 `草案`。未知不写零。填补 ≠ 已改约。有歧义 ≠ 当然不利提供方。单方惯例 ≠ 双方习惯。对我方有利 ≠ 唯一解释。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务或裁判案例检索。本窗是评估，**不要**用 `search_template` 生成新合同或已改约证明，**不要**用类案写成唯一解释。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现填补即已改约、有歧义即不利提供方、单方惯例即双方习惯、选有利文本冒充唯一的反例。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》第一百二十五条、第四十一条、第六十一条、第六十二条及其解释当作现行规则。不得把预付式消费解释第八条消费者有利解释套一般商事合同。MCP 效力字段与公布施行日冲突时，以施行日为准。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的解释、习惯或填补结论保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 使用 Lawyeah MCP

宿主可调用时：

- `search_law` 核验将被写入 `L#` 的现行规则：民法典第一百四十二条有相对人的意思表示，按照所使用的词句，结合相关条款、行为的性质和目的、习惯以及诚信原则确定含义。第四百六十六条第一款条款争议依据第一百四十二条第一款；第二款多文本同等效力时词句推定相同，不一致的按相关条款、性质、目的以及诚信原则解释。合同编通则解释第一条：以词句通常含义为基础，参考缔约背景、磋商过程、履行行为；有证据证明存在不同于通常含义的共同理解的，不得再主张通常含义；两种以上解释可能影响效力的，选择有利于该条款有效的解释，无偿合同选择对债务人负担较轻的解释。第五百零九条全面履行与诚信附随，不是填补主条，不得写成已填补或已改约。第五百一十条没有约定或约定不明，可以协议补充；不能达成补充协议的，按照合同相关条款或者交易习惯确定。第五百一十一条仍不能确定时质量、价款、履行地、期限、方式、费用分项适用，一行一项，不得合成一笔填补。交易习惯须主张方举证，单方内部惯例不是双方习惯；总则编解释第二条习惯认定与举证只开接口。第四百九十八条不利解释与非格式优先只开 `评估争议中的格式条款` 接口，协商条款不得套不利解释，不得写入本窗主核验。噪声：已失效合同法第一百二十五条、第四十一条、第六十一条、第六十二条；合同法解释二第一条仍引合同法第六十一条、第六十二条、第一百二十五条；预付式消费解释第八条消费者有利解释不得套一般商事。技能正文条号不是 `L#`。
- 已有真实 `regulation_id` 且宿主暴露 `get_law_detail` 时，核验将改变解释路径、习惯或填补顺序的正文再写入 `L#`。不得编造 `regulation_id`。
- `search_practiced` 补填补不是已改约、有歧义不是当然不利提供方、单方惯例不是双方习惯、不得挑选有利文本冒充唯一、交易习惯须举证的实务反例。
- `search_case_by_fact` 只比较事实差异与翻转条件：填补不是改约；有歧义不是当然不利提供方；单方惯例不是双方习惯；对我方有利不是唯一解释。无类案不得写成唯一解释或已改约终稿。评估类禁止用 `search_template` 生成新合同或已改约证明。

工具不可用时继续条款碎片和 `JX#` 编目；解释、习惯、填补结论字段停止。不得拒跑，不得凭记忆写成已改约或唯一有利解释。

## 判断节点

执行顺序和停止条件以 [方法](references/method.md) 为准。这里只列入口，不代替节点。

### 1. 分流、立场、解释闸与不关窗

主成果才整案转出。双方秘密、伪造修订、倒签修订日第一次停。填补即已改约、有歧义即不利提供方不关窗。闸关仍交十节，第 6 节不出 `JX#` 终稿。利益冲突未解不是整体停止。

### 2. 主体与强制接口

冲突文本并列。文义、体系、目的、习惯分列。本节禁止出 `JX#` 终稿。

### 3. 解释闸与路径 `Q#`

本节禁止出 `JX#` 终稿。有可编号碎片：闸打开或半开。主路径只用 `Q-释`。

### 4. 解释行 `JX#`

条款切片、文义与体系、目的习惯诚信、格式接口、漏洞填补候选。状态 `草案`。禁止升格已改约、习惯已证成、唯一有利解释。无 `E#` 不得写已改约。

### 5. 格式、框架、变更、成立接口

格式专项转格式窗。框架订单转框架窗。第 7 节不得夹带 `JX#` 终稿或新合同绕闸。

## 停止与安全

- `整体停止`：立场或委托无法闭合；双方秘密未解；提出伪造合同或修订、倒签修订日、隐匿文本或违法取证。整体停止优先于负触发。不以「坚持」为门槛。第一次提出即停。不得选边治愈。无一可编号碎片：解释闸关闭，仍交十节，不是整体停止。无书面解释授权但有碎片：解释闸部分打开，不是整体停止。利益冲突未解：不是整体停止。
- `字段停止`：通常含义、共同理解、习惯举证、第五百一十一条分项、施行日未核验。填补即已改约、有歧义即不利提供方、单方惯例即双方习惯、对我方有利即唯一解释、目的推翻清晰文义、选有利文本冒充唯一、未知写零：该格 `现有依据不支持` 或字段停止，窗口不关；闸已开仍出其他 `JX#` 草案。
- `目标停止`：主目标变为未成争改稿、整份合同重写或确认之诉诉状。禁止把「填补即已改约」当作用户错误主张时的目标停止；那是不关窗。

禁止指导伪造合同或倒签修订。不给胜诉率。不定罪。不选定法院。不代提交。未知不写零。不重写整份合同。不写诉状。

## 交付

严格按 [输出合同](references/output-contract.md) 交付。解释闸关闭仍交十节，第 6 节不出 `JX#` 终稿。不关窗主张仍交十节，该格不支持，闸已开仍出其他 `JX#`。节点 0 整案转出只交第 1、2、10 节。整体停止只交第 1、10 节。解释闸未打开时不得交付「已改约」或「唯一有利解释」。边界见 [路由](references/routing.md)。
