# 条款解释方法

本文件是可执行判断节点，不是栏目说明书。每个会改变结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然结果或唯一必得总额。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。实务检索若出现“违约金不超过合同标的百分之三十”，记为噪声。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

应诉答辩或提出反诉，不等于当然放弃仲裁协议。解除通知到达对方时解除；未通知而起诉或申请仲裁主张解除的，仅在该主张获确认后，自起诉状或仲裁申请书副本送达时解除，不得把立案日写成解除时点。第 585 条“过分高于”对照违约造成的损失，不对照合同总价。

## 节点 1　固定解释对象

1. 列出发生歧义或冲突的条款原文、版本、修订和所在文件。
2. 同一事项多份文件不一致：先判断是否属于框架与订单冲突；是则转 `评估框架协议与订单冲突`，本任务只解释被指定的那一层。
3. 口头陈述与书面冲突：书面优先，但长期实际履行可能构成变更，变更争点转 `评估变更是否成立`。
4. 禁止直接改写条款使对用户有利。

若：用户要求“按对我们有利的意思出一版新合同” → 目标停止，审查起草搁置。
若：文本无法识别解释对象 → 整体停止。

## 节点 2　解释顺序

运行时核验民法典第 142 条、第 466 条后再落判断。

1. 有明确通常含义且与上下文不冲突：先采用通常含义。
2. 专业术语有行业通常理解的，记录来源，不得用日常口语替换。
3. 体系解释：定义条款、前后条、附件和清单相互约束。
4. 目的解释不得推翻清晰文义，除非文义导致明显荒谬且有磋商证据支持。
5. 两种解释都能成立时，记录并行情景，标 `依据不足`，不选唯一“对我方有利”解释充作法律意见。

## 节点 3　习惯、诚信与格式

1. 交易习惯须证明双方知道或应当知道，并在同类交易中通常遵守。
2. 诚信原则用于限制明显违背诚实信用的解释，不得当作任意改写权。
3. 格式条款：提示说明不足可能使条款不成为合同内容，那是效力问题，转格式条款原子。
4. 对格式条款有两种以上解释，作出不利于提供方的解释。此规则不得用于双方协商条款。
5. `search_law` 返回已失效合同法第四十一条时记为噪声。

## 节点 4　漏洞填补

1. 确认属于没有约定或约定不明，而不是已有明确不利条款。
2. 先看是否存在补充协议或实际履行形成的变更。
3. 再按相关条款和习惯。
4. 仍不能确定：质量、价款、履行地、履行期限、方式、费用按第 511 条分别填补，每项单独一行。
5. 填补结果只是解释候选，不是已经成立的新协议。

若：履行地或标的质量无法填补且影响请求能否成立 → 相应 `Q#` 标依据不足。
若：用户要把填补写成已经改合同 → 停止，说明须双方合意或裁判。

## 节点 5　对请求的影响

1. 每一种解释路径写明：支持哪个 `Q#`，推翻哪个 `Q#`。
2. 解释不能补正解除权缺失，也不能单独产生违约金。
3. 需要鉴定或外部习惯证明时列入待证事实，不编造行业标准数字。
4. 金钱后果只标接口。第 585 条调整仍对照损失，不对照总价。

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因对方控制而推定材料存在或内容有利。

下一步按期限灭失、易失证据、改变本任务结论、可逆性排序。每项写执行人、前置、最晚时点、预期改变、备选、可逆性和停止条件。

禁止指导伪造、隐匿、威胁或违法取证。未知金额不写零。不把应诉写成放弃仲裁。不把立案日写成解除时点。
