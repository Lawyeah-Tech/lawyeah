# 准备解除通知

## 任务目标

在明确、无利益冲突的单方立场下，于解除权评估或等价材料已经支持发出解除通知时，形成“发送前解除通知包”：发送闸与催告闭合、通知路径、发送前解除通知、到达设计、异议应对要点。

`depends-on` 为空。接受用户、律师、机关或其他来源的等价解除权评估、事实和证据清单，不要求先运行其他 Skill。

本任务只形成待发送材料，不执行发送，不伪造送达，不把准备起诉写成已经解除。

## 工作边界

正触发：一般合同已成争，解除权评估或等价材料支持发送解除通知，用户需要发送前稿、到达设计和异议应对。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 尚未成争，只要改合同或出稿（审查起草领域，本生产线搁置，只说明不实施）；
- 只要总体争议总图，或解除权本身尚未评估、材料不支持发送；
- 依法须催告且催告未完成，本次主成果却是解除通知；
- 只要催告履行或补救，不以解除为本次主成果；
- 只要精算工作表或完整证据卷；
- 已决定起诉／仲裁申请／答辩／确认解除效力之诉并只要相应文书；
- 建设工程、金融借贷担保、房地产物业、海事、劳动专项争议。

本任务不生成催告终稿、可提交诉状或仲裁申请、保全申请或执行申请，不给胜诉率，不执行发送。

## 建立发函坐标

确认：使用者与授权；单方立场；相对方及可能接收主体；合同及附件版本；拟主张的解除路径（约定／法定／不定期随时解除）；解除权评估或等价材料；催告是否依法必要及是否已完成；法域；当前协商、催告、仲裁、诉讼或执行状态；拟签发主体、拟发送日和约定送达渠道；关键材料及缺失。

同时掌握双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`R#` 机关或生效文书；`C#` 合同条款定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口；`Q#` 请求／抗辩；`V#` 通知版本；`E#` 发送／送达／履行凭证。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

通知状态只用 `草案`、`待发送`、`已发送待证明到达`、`已到达`、`停止`。没有送达事实和规则引文，禁止写 `已解除`。微信“已读”不等于到达。构成违约不等于当然解除。

- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验解除权行使、通知到达、除斥、催告必要；`search_practiced` 补送达失败模式与异议路径；`search_template` 只借鉴通知栏目结构，不照抄事实和结论。特殊事实用 `search_case_by_fact`，明确筛选用 `search_case_by_filter`。不虚构案件系统。

工具不可用时继续主体、文本、催告事实和发送前结构；解除效果、除斥截止、到达法律结论字段停止。无引文不得写“解除已生效”。

## 五个判断节点

执行顺序和停止条件以 [发函方法](references/method.md) 为准。这里只列入口，不代替节点。

### 1. 专项分流、立场和发送闸

先做专项分流，再固定单方立场、授权、合同版本和相对人。解除权评估或等价材料必须已经支持发送；材料只证明存在违约、用户“想今天发函”或对方未异议，均不得打开发送闸。

### 2. 催告闭合与解除路径

依法须催告且催告未完成：目标停止，不产出发送前终稿，转介催告通知。已闭合的路径只写通知解除，不写起诉状或仲裁申请。附自动解除期限的，期限届满未履行时解除；不得用该格式规避尚未完成的法定催告。

### 3. 发送前通知正文

正文只写已支持的主体、合同版本、解除依据、关键事实、生效设计、结算清理保留和异议窗口提示。逐句回链来源。不把违约金数字写成必得，不宣称合同已经解除，不倒签日期。

### 4. 到达设计与送达证据

按约定渠道、合同地址、备份送达和失败升级设计到达方案。每次尝试预列实施人、内容版本、渠道、回证和失败升级。已读、口头转告或截图不得写成到达。本任务不执行发送，不补造送达回证。

### 5. 异议应对、状态词和不可逆提示

预列对方最强异议、继续履行主张、确认解除效力或未解除之诉分流。成果状态保持 `待发送`。没有送达事实加规则引文，任何字段都不得写成 `已解除`。无解除权的通知不因对方未异议而生效。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；基础主体或文本无法建立；用户坚持倒签、伪造送达、隐匿不利材料、威胁或违法取证。
- `字段停止`：法域、除斥、送达规则、动态规则未核验。
- `目标停止`：依法须催告且催告未完成；主目标已变为催告、评估、精算、建卷、和解协议或程序文书。

本任务不执行发送，不伪造送达。拒绝倒签和伪造送达。

## 交付

严格按 [输出合同](references/output-contract.md) 十节交付。正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。发送闸未打开时不得交付发送前终稿。边界见 [路由](references/routing.md)。
