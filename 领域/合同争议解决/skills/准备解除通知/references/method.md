# 发函方法

本文件是可执行判断节点，不是栏目说明书。每个会改变发送闸、通知路径、到达效果或状态词的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然解除、必然到达或合同已经解除。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

构成违约不等于当然解除。微信已读不等于到达。对方未异议不能补正解除权缺失。

---

## 节点 0　专项分流

先于发函判断。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填十节实体结论。

| 信号 | 转出 |
| --- | --- |
| 建设工程施工、分包、优先受偿、工程造价鉴定、实际施工人 | 建设工程领域 |
| 金融借贷、保证、抵押质押、保理、融资租赁主轴 | 金融借贷担保领域 |
| 商品房买卖、开发合作、物业服务主轴 | 房地产物业领域 |
| 海上货物、船舶、海事保全 | 海事领域 |
| 劳动关系、劳动报酬、解除劳动合同、工伤待遇 | 劳动领域 |
| 尚未成争，只要改合同或出稿 | 审查起草领域（本窗搁置，只说明不实施） |

混合信号：一般买卖／服务主轴可留本任务；专项只作为背景时在缺口标明，不把专项规则硬套进一般合同通知。

---

## 节点 1　立场、授权、文本和发送闸

1. 固定合同、附件、订单、对账单、会议纪要、聊天变更的版本层级。冲突并列，不选对用户有利的一版写入通知。
2. 主体表记录签约名、履行名、通知接收名和可能责任主体。名称不一致不自动合并。通知必须发给合同相对人或其有权接收人，不得发给随意微信联系人充作到达。
3. 确认使用者、签发主体、授权范围和拟发送日。授权不明不得锁定 `待发送` 终稿。
4. 同时掌握双方秘密或立场不明：整体停止策略输出。
5. **发送闸**必须同时满足：
   - 存在解除权评估，或用户／律师提供的等价材料已经覆盖路径、成立条件、催告必要、除斥情景和最强反方；
   - 对该材料作判断：`现有依据支持` 发出解除通知。
6. 下列情形打不开发送闸：
   - 材料只证明迟延、质量不符或用户想今天发函；
   - 判断为 `现有依据不支持` 或 `依据不足，无法形成结论`；
   - 对方未在异议期内异议被当成解除权已经补正。

发送闸未打开：目标停止或字段停止。可交付缺口清单和转介，**不产出发送前终稿**。转介 `评估解除权是否成立`。

## 节点 2　催告闭合与路径选择

本节点决定能不能写解除通知，不生成催告终稿，不写诉状。

### 2.1 先分账

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 对方迟延或质量不符 | 解除权已成立，今日发出即生效 |
| 用户想把催告和解除写在同一封信 | 催告期满合同已经解除 |
| 约定了违约金或目的落空的情绪表述 | 法定解除条件已闭合 |
| 对方未异议或微信已读 | 即使无解除权也已解除 |
| 准备起诉或已请律师 | 合同已解除 |

### 2.2 催告必要

运行时核验现行《中华人民共和国民法典》第五百六十三条后再落判断。核验失败则本节点字段停止，事实与问题清单继续。

1. **不可抗力致目的不能实现**：通知解除前仍须核事件、通知和减损；商业困难不等于法律上的不能。
2. **预期拒绝主要债务**：表示主体、权限、原文和到达必须可回链。
3. **迟延主要债务**：原则上先催告并经过合理期限。期限是否合理标待核，不编造“一律十五日”。**依法须催告且催告未完成：目标停止，不产出发送前解除终稿**，转介 `准备催告履行或补救通知`。
4. **迟延或其他违约致使目的不能实现**：目的来自合同目的条款、标的性质和磋商，不来自用户事后情绪。轻微迟延、可补救瑕疵不得直接跳到解除通知。
5. **约定解除**：核对该当条件是否已成就；成就不等于已经发出有效通知。
6. **不定期持续履行合同随时解除**：另列合理期限通知义务，不与违约解除混写。

不得用第五百六十五条“通知载明一定期限内不履行则自动解除”的格式，规避尚未完成的法定催告。催告与解除通知是两种成果；催告稿不在本任务生成。

### 2.3 除斥

- 解除权存续：约定或法定期间；无约定且无法定期间时，知道或应当知道解除事由之日起一年，或经对方催告后的合理期限（第五百六十四条）。除斥不适用诉讼时效中止、中断、延长（第一百九十九条）。
- 关键日期冲突建并行情景，不给唯一除斥截止日。
- 除斥可能已经届满：发送闸关闭，判断写 `现有依据不支持` 或 `依据不足，无法形成结论`，不出终稿。

### 2.4 通知路径与起诉／仲裁路径

运行时核验现行第五百六十五条后再写效果字段。

| 路径 | 本任务是否展开 | 效果锚点 | 禁止 |
| --- | --- | --- | --- |
| 通知解除 | 展开 | 合同自通知到达对方时解除 | 把拟发送写成已到达或已解除 |
| 通知载明自动解除期限 | 仅在解除权已闭合时展开 | 债务人在该期限内未履行的，自通知载明的期限届满时解除 | 用该格式代替未完成的法定催告 |
| 未通知而起诉或申请仲裁主张解除 | 只说明这是另一路径 | 机关确认该主张后，自起诉状或仲裁申请书副本送达对方时解除 | 本任务写诉状或申请书；把“准备起诉”写成已经解除 |

对方对解除合同有异议的，任何一方可以请求人民法院或者仲裁机构确认解除行为的效力。确认之诉材料转介 `提起合同纠纷一审`，本任务不写诉状。

### 2.5 通则解释第五十三条

当事人一方以通知方式解除合同，并以对方未在约定的异议期限或者其他合理期限内提出异议为由主张合同已经解除的，人民法院应当审查其是否享有法律规定或者合同约定的解除权。享有解除权的，合同自通知到达对方时解除；**不享有解除权的，不发生合同解除的效力**。

不得用对方未异议补正解除权缺失。发送闸和正文都不得依赖“对方大概不会异议”。

## 节点 3　发送前通知正文

发送闸打开后才制作唯一 `V#`。正文、附件、签发页拟用同一版本，禁止跨版本拼盖章页。

### 3.1 必备栏目

1. 发函主体与授权依据；
2. 收函主体及与合同相对人的对应关系；
3. 合同名称、编号、签署日和约束文本版本；
4. 解除路径及条款／法条定位（只写已核验或明确待核的规则，不写已失效《合同法》）；
5. 支持解除的关键事实，逐句回链 `S/D/A/R/C/E`；
6. 生效设计：到达时解除，或附自动解除期限且写明期限起算、届满日计算方式和未履行的含义；
7. 解除后结算清理、返还、保管、违约责任主张的保留（第五百六十六条、第五百六十七条），不在本通知里锁定必得金额；
8. 异议窗口提示：可依法请求确认解除行为的效力，不把未异议写成已经生效；
9. 落款日期必须是真实拟制日期，禁止倒签；
10. 附件清单与 `V#` 一致。

### 3.2 禁止写入正文的内容

- “合同已经解除”“本通知发出即解除”“已读视为到达”“未异议视为同意解除”；
- 把约定违约金数字写成对方必须立即支付的唯一总额；
- 尚未闭合的催告期满自动解除；
- 伪造的历史催告、送达或签收；
- 威胁人身、损毁商誉、违法披露个人信息；
- 起诉状请求、管辖选择或仲裁请求主文。

范本只借鉴栏目结构，不移植他案事实和结论。

### 3.3 版本与状态

锁定后的稿件状态为 `待发送`。用户事后改事实必须升版本，旧 `V#` 作废，不得混用。本任务不把状态推进到 `已发送` 或 `已到达`。

## 节点 4　到达设计与送达证据

本任务设计到达，不执行发送，不补造回证。

1. 先读合同约定送达条款：地址、电子邮箱、传真、平台站内信、指定联系人。约定渠道作为主方案，但约定不等于已经到达。
2. 备份方案：合同载明地址的能证明交寄与妥投的邮寄、公证送达、当面签收。失败升级预列，不在未失败时宣称已经公告送达。
3. 每次拟尝试预登记：实施人、真实拟发送日、内容 `V#`、渠道、拟形成的 `E#`、失败升级。
4. 电子方式：数据电文进入指定系统的事实与约定必须可回链。**微信已读、消息回执、对方沉默，不得写成到达。**
5. 口头转告、同事转达、朋友圈或无关群聊，不得列入到达方案。
6. 用户要求倒签发送日、补造快递面单、伪造签收、篡改已读记录：整体停止，只输出拒绝、保全真实材料和按真实日期恢复的条件，不提供规避技巧。
7. 已经发生的真实发送必须如实登记为 `E#`，状态最多写到 `已发送待证明到达`。没有送达事实和规则引文，禁止写 `已到达`，更禁止写 `已解除`。

---

## 节点 5　异议应对与不可逆提示

1. 预列对方最强异议：无解除权；催告未完成；除斥届满；主体或文本错误；通知未到达；目的仍能实现；己方先违约。
2. 每项异议写：现有依据判断、通知发出后是否仍可补正、应停止的后续动作。发出后通常难以若无其事撤回；用户坚持先发再补权，必须书面揭示不可逆风险。
3. 对方提出异议后：任何一方均可请求确认解除行为的效力。本任务只给分流和最小交接，不写确认之诉诉状。
4. 无解除权的通知不生效。不得建议“发出后看对方是否异议再决定有没有解除权”。
5. 下一步按除斥风险、易失送达证据、发送前复核、可逆性排序。发送、公证、起诉、精算、建卷只写转介，不在本方法执行。

禁止指导伪造、隐匿、威胁、倒签或违法取证。本任务不代为发送、不联系对方、不冒充律师向机关提交。
