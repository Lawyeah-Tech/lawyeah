# 评估价款结算与发票争议方法

本文件是可执行判断节点。对账单不是当然改约。发票不是当然结算。质保金扣留不是当然抵销。未开票不是当然拒付全部。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已结算、已付款、已改约、选定法院、代提交、未知写零。本任务不定罪，不写催收函，不写精算终稿。本窗闸名只能是结算闸，禁止复用对账闸、发票闸、抵留闸、精算闸、金罚闸。预留不得占用：立案闸、和解闸。本窗 `ZP#` 是账票行。主路径只用 `Q-票`，禁止用 `Q-对`、`Q-结`、`Q-测`、`Q-销`、`Q-签` 作主路径。本窗 `Q-对` 只作「对账单即改约或即已结算」不关窗码。本窗 `Q-签` 只作「评估即已结清、已提交或已立案」不关窗码。英文 id 禁止使用，一律用中文技能名 `评估价款结算与发票争议`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效合同法第一百五十九条至第一百六十一条、把通则解释第三十一条先返回买卖解释第三十一条、把发票管理办法 2019 年第十九条当现行时记为噪声。禁止指导伪造对账单或虚开。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现批次碎片扫描，不是默认闭集。
`ZP#` 固定列：`编号｜批次切片｜约定价与已付｜付款条件与发票牵连｜对账确认效力｜质保金／扣款／抗辩接口｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已结算」或「已付款」。无 `E#` 不得写已结清。对账或已付未闭合不得标 `待提交`。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-票`。禁止 `JS#`、`DJ#`、`SJ#`、`DN#`、`SH#`、`DX#`、`A#`、`N#`。

口头「对过账就算结了」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：双方盖章对账是较强结算证据，不是当然改约。开票通常从给付，无约定时不当然拒付全部价款。质保金到期条件逐项核。

## 节点 0　分流、立场、结算闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造对账或发票、虚开、倒签不进负表。利益冲突未解不进整体停止。不定已结清、不写催收函不是负触发。把对账单写成已改约、把发票写成已付款不是负触发。

整案转出只交付第 1、2、10 节，不出 `ZP#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是精算工作表或必得核算 | 负触发 `测算违约金与损害赔偿` |
| 主成果是抵销、留置或扣款终稿 | 负触发 `评估抵销留置与扣款抗辩` |
| 主成果是框架与订单冲突 | 负触发 `评估框架协议与订单冲突` |
| 主成果是定金定性 | 负触发 `评估定金罚则争议` |
| 主成果是纯无争议到期欠款催收或支付令 | 负触发 `申请合同金钱支付令` |
| 主成果是工程造价或竣工结算 | 整案转建设工程领域 |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改合同或出稿 | 整案转审查起草（本窗搁置，只说明不实施） |
| 只要开票税务筹划 | 整案转税务领域 |
| 「不定已结清」「不给必得总额」「不写催收函」 | 交付禁令，不是负触发 |

出现「结算」「发票」「对账」一词不是转出。

结算闸打开（可出 `ZP#` 草案，仍不得标「已结算／已付款／已改约」）须同时满足：单方无冲突立场已闭合；主成果是结算评估，不是精算终稿、不是催收函；至少一行可编号价款、对账、发票、质保金或付款碎片。口头「对过账就算结了」不算单独开闸材料。

结算闸部分打开：已有碎片，但对账、发票或已付未闭合；对应格待核；仍交十节。无书面授权但单方立场已闭合且已有碎片：结算闸部分打开，仍交十节，不是整体停止。

结算闸关闭（仍正触发）：无一可编号碎片。「今天必须出已结算／已付款终稿」而无最小碎片不得开闸。不出 `ZP#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `ZP#` 终稿，**第 7 节不得出催收函或精算终稿**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「对账单即改约」「发票即已结算或已付款」「质保金扣留即抵销」「未开票即拒付全部」「沉默即确认」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `ZP#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 结算闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造对账单或发票或流水、虚开、隐匿已付款或已开票、倒签对账日或开票日或违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 3　账票行 `ZP#`

按已出现批次碎片扫描，不是默认闭集。每条须能指向约定价与已付、发票牵连、对账效力或质保金扣款之一。

无 `E#` 不得写已结清。状态默认 `草案`。一次只推荐下一步。未知不写零。禁止唯一必得总额。对账或已付未闭合不得标 `待提交`。

热冲突强制处理：

- 对账单即改约／发票即已结算或已付款／质保金扣留即抵销／未开票即拒付全部／沉默即确认／未知写零 → 该格不支持或字段停止；仍出其他 `ZP#`。
- 无一碎片 → 关闸，不出 `ZP#` 终稿，窗口不关。
- 指导伪造对账、虚开、倒签 → 整体停止，不是该格不支持。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：卖方发来单方对账单和一张专票，买方未回，质保金被扣。用户主张对过账就算改约、开了票就算付了、没开票就能拒付全部、质保金扣了就是抵销、不清楚先写零。结算闸打开或半开。`Q-对`、`Q-默`、`Q-拒`、`Q-质金`、`Q-零` 不打开为可靠路径。第 6 节不得把已改约、已付款、拒付全部、已抵销、0 写入可执行 `ZP#`；对应格 `现有依据不支持` 或字段停止；仍出约定价与已付分列、对账范围缺口、开票从给付待核、质保金条件等其他 `ZP#`。不关窗。不写催收函。不写精算终稿。

场景②：用户同时交出己方「对账日改到上周、空白发票先补一张」与对方「从未对过账、货也没交齐」口径，并要「先按已结清写」。命中双方秘密＋倒签＋伪造。第一次整体停止。只交第 1、10 节。不出 `ZP#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代违法方案。
