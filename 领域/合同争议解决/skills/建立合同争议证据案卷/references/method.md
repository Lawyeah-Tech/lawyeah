# 建卷方法

本文件是可执行判断节点，不是栏目说明书。每个会改变要件、举证责任、材料采信或补证路径的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然采信或对方控制材料“一定存在且有利”。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。举证责任、举证期限、书证提出命令和非法证据排除的条号必须运行时核验现行《中华人民共和国民事诉讼法》及民事诉讼证据规定，不得凭记忆写旧条号。核验失败则法律分配和期限字段停止，材料编目继续。

本任务不是策略备忘，也不是起诉状或答辩状。构成违约不等于当然解除。微信已读不等于到达。

---

## 节点 0　专项分流

先于编目。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填十节实体矩阵。

| 信号 | 转出 |
| --- | --- |
| 建设工程施工、分包、优先受偿、工程造价鉴定、实际施工人 | 建设工程领域 |
| 金融借贷、保证、抵押质押、保理、融资租赁主轴 | 金融借贷担保领域 |
| 商品房买卖、开发合作、物业服务主轴 | 房地产物业领域 |
| 海上货物、船舶、海事保全 | 海事领域 |
| 劳动关系、劳动报酬、解除劳动合同、工伤待遇 | 劳动领域 |
| 尚未成争，只要改合同或出稿 | 审查起草领域（本窗搁置，只说明不实施） |
| 只要策略总图 | `评估合同争议` |
| 只要诉状或答辩 | `提起合同纠纷一审` 或 `应对合同纠纷一审` |

混合信号：一般买卖／服务主轴可留本任务；专项只作为背景时在缺口标明，不把专项鉴定规则硬套进一般合同案卷。

## 节点 1　立场、争点和要件拆解

1. 固定单方立场、授权、合同版本和程序阶段。已进入举证期的，另列机关指定的举证期限，但不在本任务写出完整交换计划。
2. 每个 `Q#` 先写法律效果，再拆成最小待证要件。禁止合成“合同权益”一笔。默认分开：
   - 合同成立与文本版本；
   - 履行、质量、检验与异议；
   - 催告是否发出及是否到达；
   - 解除权是否成立、通知是否发出、是否到达；
   - 损失、违约金、定金、已付款；
   - 同时履行、先履行、质量异议、时效、仲裁／管辖抗辩。
3. 构成违约的要件与解除的要件必须分列。已读、送达回证、约定送达条款分列，不得把已读并进到达要件并标为已满足。
4. 同时掌握双方秘密或立场不明：整体停止策略输出。
5. 用户只要策略或只要诉状：目标停止，不把本矩阵改写成请求主文。

## 节点 2　举证责任分配

逐要件填写：提出方、本证责任、反证对象、是否存在举证责任转移或倒置、规则核验状态、判断。

执行规则：

1. 一般原则：提出主张的当事人对自己的主张提供证据。具体条文运行时核验，不写死旧条号。
2. 合同内部事实：主张合同关系成立并生效的一方，一般对合同订立和生效事实举证；主张合同变更、解除、终止、撤销的一方，对引起变动的事实举证。上述分配以现行证据规定核验结果为准；未核验则本表规则状态为待核，判断为 `依据不足，无法形成结论`。
3. 违约金过分高于损失、减损不当、双方过错、因违约获益：谁主张相应调整或扣减，谁对该节事实举证。不在案卷里提前写成法院会主动调低。
4. 对方控制的书证：只记录是否具备依法申请责令提交或调查的事实基础。不得把“对方应当持有”写成“已经证明该文书存在且内容有利”。
5. 无法核验分配规则时，材料仍按支持／不利编目，分配结论字段停止。

## 节点 3　证据矩阵：支持、不利、控制方、合法取得

每个 `EV#` 固定列：

`编号｜对应要件｜材料名称｜支持／不利｜形成主体｜形成时间｜控制方｜取得方式｜合法取得｜完整性／冲突｜判断｜来源`

### 3.1 并列而不是挑选

- 同一要件必须同时扫描支持材料和不利材料。不利材料不得省略。
- 聊天截图、单方制作的对账单、事后补做的验收单，标形成时间和控制方，不自动升格为 `A#`。
- 冲突来源并列，不选对用户有利的一版冒充唯一事实。

### 3.2 控制方

控制方只根据现有依据填写：己方、相对方、第三人、机关、不明。

**不能因对方或第三人控制而推定：**

- 该材料确实存在；
- 该材料内容有利于己方；
- 对方拒不提交即视为己方主张成立。

只能写：线索来源、何以认为可能由对方持有、合法调取或申请提出的条件是否具备、缺口编号。

### 3.3 合法取得

取得方式必须可回链：合同交付、己方履行形成、对方自愿发送、公开渠道、公证、机关调取、律师依法调查。

下列请求第一次出现，即对该争点或材料实施**该部分整体停止**：

- 伪造、变造合同、印章、验收或送达回证；
- 隐匿、销毁、篡改已持有材料；
- 偷拷对方电脑、手机或网盘；
- 非法侵入邮箱、聊天系统或监控；
- 窃听、私拆邮件、收买内部人员窃取商业秘密或个人信息。

停止后只输出拒绝、已持有材料的保全提示和按合法途径恢复的条件，**不提供替代违法方法**。用户明确放弃该部分违法目标后，其余合法争点可继续；坚持则整案整体停止。

合法取得分三态：`合法性未知`、`存在违法风险`、`已核验应排除`。前两态只标风险并保全原件，不直接排除。仅第三态不得当作本证。法源未核验时，合法取得和可采性字段停止，只保留取得方式事实。

### 3.4 电子数据与复印件

电子数据记录原始载体、提取人、完整性校验和是否可核对原始介质。缺失校验不自动写成虚假，但证明力字段不得写成 `现有依据支持` 已完整。复印件、转发截图与原件核对状态分列。

## 节点 4　缺口、补证和最晚时点

每个 `G#` 必须能执行：

1. 待证事实和对应要件；
2. 缺口是“没有材料”“材料不利”“材料不完整”还是“合法取得不能”；
3. **合法**补证步骤：自行收集己方履行凭证、申请公证、申请鉴定、申请调查令或法院调查、申请书证提出、申请证人出庭。步骤只写到合法动作名称和最小输入，不写规避监控、伪装身份套取。
4. 责任人或控制方；
5. 最晚时点按类型分列，禁止混算：
   - 诉讼时效；
   - 解除权除斥；
   - 质量异议／检验期间；
   - 约定催告期；
   - 举证期限。
6. 日期冲突建并行情景，不给唯一截止日充作法律意见。
7. 不能合法取得：该要件判断保持 `依据不足，无法形成结论`，停止该补证分支，不改写为推定有利。

质量现场、易腐标的、即将覆盖的聊天或邮件：在缺口中标红旗，合法下一步转介 `保全质量现场与电子证据` 或公证、鉴定原子。本任务只列红旗和转介条件，不展开潜入现场、私拆设备或无授权镜像硬盘的操作说明。

---

## 节点 5　保全红旗、禁止动作和转介

1. 保全红旗仅限于：标的或现场可能改变、电子数据易失、对方转移财产迹象、证人即将出境或记忆关键事实。红旗不是保全申请。
2. 合法步骤：固定己方持有的原始载体、申请公证保全、申请鉴定、申请证据保全或财产保全。申请文书转介相应原子，本任务不代写、不代提交。
3. 调查令、法院调查、鉴定异议、证据交换计划全部转介，不在本包生成那些终稿。
4. 下一步按期限灭失、易失证据、能否改变要件判断、可逆性排序。每项写执行人、前置、最晚时点、预期改变、备选、可逆性和停止条件。
5. 禁止把案卷矩阵改写成诉讼请求、管辖选择或胜诉预测。

禁止指导伪造、隐匿、威胁、偷拷电脑或任何违法取证。本任务不代为调取、不联系对方、不冒充律师向机关提交。
