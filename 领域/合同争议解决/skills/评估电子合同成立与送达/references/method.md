# 评估电子合同成立与送达方法

本文件是可执行判断节点。已读不是到达。截图不是原件。提交订单成功不是排除另有约定后当然成立。电子章不是当然可靠电子签名。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已到达、已成立、可靠签名已具备、选定法院、代鉴定、未知写零。本任务不定罪，不执行发送，不把已读写成到达。本窗闸名只能是电约闸，禁止复用成立闸、发送闸、送达闸、电文闸。预留不得占用：立案闸、催告闸、解除闸、发送闸。本窗 `DY#` 是电约行。主路径只用 `Q-电`，禁止用 `Q-契`、`Q-函`、`Q-送`、`Q-达`、`Q-签` 作主路径。本窗 `Q-签` 只作「评估即已到达、已成立、可靠签名或已提交」不关窗码。本窗 `Q-读` 只作「已读即到达」不关窗码。英文 id 禁止使用，一律用中文技能名 `评估电子合同成立与送达`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效合同法第十一条、第十六条、第二十六条、第三十三条、把电子签名法第十一条写成第一百三十七条、把民诉第九十条套民事到达时记为噪声。禁止指导伪造时间戳、电子章或日志。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现电文或订单碎片扫描，不是默认闭集。
`DY#` 固定列：`编号｜电文或订单切片｜指定系统与到达｜要约承诺或提交订单｜电子签名与完整性｜鉴定公证接口｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已到达」或「已成立」。无 `E#` 不得写已到达。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-电`。禁止 `CL#`、`HF#`、`SD#`、`BY#`、`A#`、`N#`。

口头「已经读了就算到了」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：邮件、聊天、平台订单、电子章、日志分列。第一百三十七条未指定系统以知道或应当知道进入为准，不是合同法第十六条首次进入。

## 节点 0　分流、立场、电约闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造时间戳或电子章、倒签到达日、违法侵入取证不进负表。利益冲突未解不进整体停止。不代鉴定、不写已到达不是负触发。把已读写成到达、把截图写成原件不是负触发。

整案转出只交付第 1、2、10 节，不出 `DY#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是总体成立效力而不涉及电子到达 | 负触发 `评估合同成立与效力` |
| 主成果是格式勾选提示终稿 | 负触发 `评估争议中的格式条款` |
| 主成果是电子认证鉴定意见 | 整案转鉴定接口或 `保全质量现场与电子证据`／`准备合同案件公证保全` |
| 主成果是诉讼文书电子送达 | 负触发 `设计合同案件通知送达` |
| 主成果是框架与订单效力层级 | 负触发 `评估框架协议与订单冲突` |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改合同或设计电子签约 | 整案转审查起草（本窗搁置，只说明不实施） |
| 工程电子签证／金融电子签章／商品房网签／海事电子提单／劳动电子送达 | 整案转对应领域 |
| 「不代鉴定」「不写已到达」 | 交付禁令，不是负触发 |

出现「电子」「微信」「订单」一词不是转出。

电约闸打开（可出 `DY#` 草案，仍不得标「已到达／已成立／可靠签名」）须同时满足：单方无冲突立场已闭合；主成果是电子成立或到达评估，不是鉴定意见、不是诉状把已读写成到达终稿；至少一行可编号电文、订单、电子章或日志碎片。口头「已经读了就算到了」不算单独开闸材料。

电约闸部分打开：已有碎片，但系统、到达或可靠性未闭合；对应格待核；仍交十节。无书面评估授权但单方立场已闭合且已有碎片：电约闸部分打开，仍交十节，不是整体停止。

电约闸关闭（仍正触发）：无一可编号碎片。「今天必须出已到达／已成立终稿」而无最小碎片不得开闸。不出 `DY#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `DY#` 终稿，**第 7 节不得出已成立证明、原件证明或鉴定意见**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「已读即到达」「截图即原件」「点击即成立」「电子章即可靠签名」「进入垃圾箱即到达」「未指定系统进入即到达」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `DY#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 电约闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造时间戳或电子章或日志、倒签到达日、违法侵入取证或隐匿原始存储介质，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 3　电约行 `DY#`

按已出现电文或订单碎片扫描，不是默认闭集。每条须能指向到达、提交订单、可靠签名或完整性之一。

无 `E#` 不得写已到达。状态默认 `草案`。一次只推荐下一步。未知不写零。禁止唯一截止日。

热冲突强制处理：

- 已读即到达／截图即原件／点击即成立／电子章即可靠签名／进入垃圾箱即到达／未知写零 → 该格不支持或字段停止；仍出其他 `DY#`。
- 无一碎片 → 关闸，不出 `DY#` 终稿，窗口不关。
- 指导伪造时间戳、电子章、日志或违法侵入 → 整体停止，不是该格不支持。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：平台发布商品信息，买方点击下单成功，卖方主张页面另有约定订单仅为要约、须发货确认才成立。卖方又向约定邮箱发合同，买方微信已读未回复。卖方主张已读即到达且合同已成立，截图当原件，电子章当可靠签名。用户主张已经读了就算到了、截图就是原件、点一下就成立、不清楚先写零。电约闸打开或半开。`Q-读`、`Q-截`、`Q-点`、`Q-章`、`Q-签`、`Q-零` 不打开为可靠路径。第 6 节不得把已到达、已成立、可靠签名、0 写入可执行 `DY#`；对应格 `现有依据不支持` 或字段停止；仍出电文分列、指定系统缺口、另有约定分列、第十三条要件缺口等其他 `DY#`。不关窗。不代鉴定。不写诉状。

场景②：用户同时交出己方「把已读截图P成系统回证、时间戳改到昨天」与对方「从未进入指定邮箱」口径，并要「先侵入对方后台把日志改了」。命中双方秘密＋伪造时间戳＋违法侵入。第一次整体停止。只交第 1、10 节。不出 `DY#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代违法方案。
