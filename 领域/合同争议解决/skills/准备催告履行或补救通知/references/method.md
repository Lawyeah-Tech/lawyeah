# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变催告请求、补救期限或函件法律效果的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率，不得把催告写成已经解除，不得编造一律 15 日。

`search_law` 对期限依据和“逾期即解除”一类效果句为 required。核验失败则这些字段停止，事实回链和稿件结构继续。`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。

范本只借鉴称谓、事实、请求、期限、送达和权利保留等栏目，不得把解除通知模板改头换面当作催告。

## Q# 催告请求

固定列：`编号｜义务性质｜原履行期｜现状｜具体请求｜合同定位｜支持事实｜不利事实｜期限依据｜控制方｜最强反方｜判断｜待核`。

继续履行、修理、更换、重作、减价、补足、付款分列，不得合成“请尽快处理”。催告本身不是解除。构成违约不等于当然在函内预告解除已经发生。

文稿状态：`草案`＝结构未锁；`发送前复核`＝唯一 `V#` 已形成但未发送；`不得发送`＝主成果闸未过或含禁止语句。

---

## 节点 0　专项分流与主成果闸

先于出稿。命中整案转出则只交付分流理由和最小交接，不填十节催告稿。

| 信号 | 转出 |
| --- | --- |
| 建设工程施工、分包、优先受偿、工程造价鉴定、实际施工人 | 建设工程领域 |
| 金融借贷、保证、抵押质押、保理、融资租赁主轴 | 金融借贷担保领域 |
| 商品房买卖、开发合作、物业服务主轴 | 房地产物业领域 |
| 海上货物、船舶、海事保全 | 海事领域 |
| 劳动关系、劳动报酬、解除劳动合同、工伤待遇 | 劳动领域 |
| 尚未成争，只要改合同或出稿 | 审查起草领域（本窗搁置，只说明不实施） |

主成果闸：

| 条件 | 动作 |
| --- | --- |
| 用户仍要对方履行或补救，主成果是催告 | 正触发，继续 |
| 本次主成果是解除通知，或用户要求函内写“逾期即已解除”且拒绝删除 | 负触发或目标停止，转 `prepare-termination-notice`；解除条件未核验则先转 `assess-termination-right` |
| 只要索赔金额终稿 | 负触发，转 `calculate-damages` 或 `prepare-damages-notice` |
| 只要争议总图 | 负触发，转 `assess-contract` |

已发出过内容相同的催告：登记前函 `E#`，本任务只做出补充催告或更正稿，不把旧函改写成未发送。

## 节点 1　主体、接收权限和既有函件

1. 固定合同版本和被催告义务的条款定位。订单、对账单与主合同冲突时并列，催告请求不得偷偷换成对用户有利的一版。
2. 发送人必须有权代表债权人或被授权主体；接收人优先使用合同约定的通知主体、地址和电子账号。
3. 既有催告、索赔、协商纪要逐件登记：文本、发出、到达证据、对方回复。重复催告须说明与前函的增量，避免自相矛盾。
4. 同时掌握双方秘密或立场不明：整体停止策略输出。
5. 用户坚持伪造已催告、倒签日期或虚构履行事实：整体停止，不给规避方法。

---

## 节点 2　催告事项与事实回链

每个 `Q#` 先写请求的法律效果（要求履行或补救），再写事实。

若：义务、原履行期或现状无法定位 → 该 `Q#` 字段停止，不得用空泛“贵司违约在先”出稿。  
若：质量瑕疵但检验期间、通知是否逾期未核验 → 催告可以要求配合检验或说明，但不得把验收争议写成已经确认的质量责任。  
若：用户要求把继续履行和解除写成同一封已生效法律效果 → 拆开；解除效果不进入本催告稿。

催告正文允许保留“将依法追究违约责任”的概括保留，但：

- 不得把未测算金额写成确定债权；
- 不得把未核验的解除权写成已经成立；
- 不得要求对方自认不存在的事实。

## 节点 3　补救期限依据

禁止编造一律 15 日。期限行固定列：`来源｜原文或规则｜起算事件｜拟写入天数｜是否合理待核｜判断`。

| 条件 | 写入正文的方式 | 禁止 |
| --- | --- | --- |
| 合同约定催告期、宽限期或自动解除预备期 | 回链条款，按约定日数表述，并标明自到达起算 | 把约定期改写成“法定 15 日” |
| 无法定或约定的固定日数 | 写“合理期限”并列出考量因素；若用户指定日数，标注 **待核**，不写成法定期 | 声称“法律规定 15 日” |
| `search_law` 不可用 | 期限是否合理字段停止；稿中用“请在合理期限内／请贵方确认可完成日期” | 用 15 日填空 |
| 期限短到依标的性质显然无法完成 | 现有依据不支持该日数作为合理期限；改待核或拉长候选 | 为了“好看”强行 3 日或 7 日 |

合理期限考量只列已有事实：标的是否特定、备货或返工所需时间、已迟延长度、季节性、对方已知的使用节点。未知项保持未知，不编行业惯例天数。

## 节点 4　发送前催告稿

### 4.1 必须具备的栏目

称谓与主体；合同名称和版本；催告所依据的事实（回链日期和凭证）；具体履行或补救请求；补救期限及依据类型；履行方式、地点、账户或验收安排（已知才写）；不承认事项；权利保留；发送人、日期和联系方式；送达信息。

锁定唯一 `V#`。正文、附件清单和拟送达件一致。跨版本盖章页不得发送。

### 4.2 自动解除语句闸

| 条件 | 处理 |
| --- | --- |
| 解除条件未经 `assess-termination-right` 或等价材料核验 | **不得**写“逾期即已解除”“逾期本合同自动解除”“视为贵司同意解除” |
| 依法须催告且本次正是该催告 | 只催告履行或补救；解除只可作为后续权利保留，且不得写成已经发生 |
| 解除条件已核验，用户仍要把解除效果写进本函 | 本技能不把该句写入发送前催告稿；目标停止该句，转介 `prepare-termination-notice` |
| 用户要求“15 日内不处理即已解除”且拒绝改写 | 该句 `不得发送`；能改写为单纯催告则继续，否则目标停止 |

构成违约不等于当然解除。催告到达通常启动合理期限，不当然消灭合同。

### 4.3 不得写入的其他内容

胜诉承诺、虚假履行事实、威胁人身或违法曝光、要求对方销毁证据、伪造已协商一致。金额未测算时只保留权利，不写唯一必得总额。

稿件形成后状态为 `发送前复核`，不是已发送。本任务不代为发送。

## 节点 5　约定渠道、备份渠道与回证

通知内容在本技能完成。复杂、多法域或需公证／公告的独立送达方案转介 `plan-notice-service`，但本任务最低仍须填完下表，不得只写“建议另做送达方案”。

固定列：`层级｜渠道｜依据（约定／已知地址／公开登记）｜接收主体｜内容版本 V#｜拟留痕｜失败升级｜到达证明｜不得写成`。

最低三层：

1. **约定渠道**：合同通知条款中的地址、传真、电子邮箱或指定联络人。有约定先走约定。  
2. **备份渠道**：登记住所、合同载明的另一地址、已知办公地或可证明的电子账号，与约定渠道并行或在约定失败后启用。  
3. **回证字段**：寄送单号、签收／拒收／退回、邮件服务器回执、公证发送记录的计划位置。实际凭证记入 `E#`；尚未发送不得预填“已送达”。

| 条件 | 判断 | 禁止 |
| --- | --- | --- |
| 仅准备发微信或仅看到“已读” | 到达 `依据不足` | 已读＝到达＝催告期已起算 |
| 约定电子邮箱与微信并存 | 主送约定邮箱，微信可作为备份告知，不替代约定渠道 | 只发微信并声称已合法送达 |
| 地址冲突或迁址不明 | 并行情景，备份同时列出 | 选对用户方便的一个并保证有效 |
| 需要公证送达、公告或境外送达作为独立方案 | 转介 `plan-notice-service`，本表仍保留约定＋备份＋回证 | 因转介而省略最低三字段 |

微信已读不等于到达。公告、口头转告或群内@不得类推为当然有效。禁止指导伪造签收、拦截退件或篡改物流记录。

C 端 032／012／011 只分流，不回改、不在本任务实施其成果。

下一步只包括：核验期限依据、补齐地址、发送前复核、按渠道留痕、跟踪是否履行。解除通知、起诉、精算另写转介。用户要求立即发送且稿内仍有禁止语句：停止发送建议。
