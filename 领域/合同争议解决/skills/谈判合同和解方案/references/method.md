# 谈判方法

本文件是可执行判断节点，不是栏目说明书。每个会改变让步档、底线、弃权范围或执行力结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出对方必履行、法院必确认、必然撤回起诉或唯一成交总额。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

## 让步矩阵

固定列：`编号｜争点Q#｜提出方｜相对方｜主位主张｜可让档N#｜对价｜互斥｜底线｜弃权接口W#｜最强反方｜判断｜待核`。

解除、继续履行、违约金、赔偿、定金、返还清理分列。同一让步支持多项时分别说明效果，不把多项请求折成一笔“了结款”。构成违约不等于必须以解除为成交条件。

## 节点 0　专项分流

先于实体谈判。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填十节实体方案。

| 信号 | 转出 |
| --- | --- |
| 建设工程施工、分包、优先受偿、工程造价鉴定、实际施工人 | 建设工程领域 |
| 金融借贷、保证、抵押质押、保理、融资租赁主轴 | 金融借贷担保领域 |
| 商品房买卖、开发合作、物业服务主轴 | 房地产物业领域 |
| 海上货物、船舶、海事保全 | 海事领域 |
| 劳动关系、劳动报酬、解除劳动合同、工伤待遇 | 劳动领域 |
| 尚未成争，只要改合同或出稿 | 审查起草领域（本窗搁置，只说明不实施） |

混合信号：一般买卖／服务主轴可留本任务；专项只作为背景时在缺口标明，不把专项规则硬套进一般合同方案。

## 节点 1　立场、授权和仍可谈状态

1. 固定使用者、代表主体、授权范围和信息披露权限。同时掌握双方秘密或立场不明：整体停止策略输出。
2. 固定合同、附件、订单、对账单、会议纪要、聊天变更的版本层级。冲突并列，不选对用户有利的一版冒充唯一文本。
3. 程序表逐动作记录协商、催告、解除通知、仲裁、诉讼或执行：机关／机构、案号、文书、作出日、收到日、送达方式和效力凭证。口头转述、截图、“已读”不得写成已受理、已送达、协议已成立或期限已起算。
4. 判断协商渠道是否切断。已起诉、已仲裁、已保全，只要当事人仍可自行和解（民事诉讼法第 53 条，运行时核验现行文本），本任务仍可正触发；用户只要答辩则负触发，转应诉原子。
5. 报价记录分列：谁提出、何时、通过何渠道、是否到达、是否附期限、是否已撤回。聊天已读不等于报价到达，更不等于承诺成立。

## 节点 2　争点让步表

每个 `Q#` 先写法律效果，再写可让档。禁止合成“合同权益”或“一揽子了结”一笔。

默认主位候选按事实分别建立：

- `Q-履` 继续履行或补救
- `Q-解` 约定解除、法定解除或确认解除／未解除
- `Q-金` 违约金
- `Q-损` 损害赔偿
- `Q-定` 定金罚则（与违约金选用，不得双计）
- `Q-清` 返还、折价、保管、发票、质保金
- `Q-程` 撤诉、解除保全、撤回仲裁、中止执行等程序对价

每个 `N#` 至少写三档：开价、可谈、底线。档位必须对应具体对价，不得只写“各让一步”。主备位和互斥必须可见：`Q-解` 与 `Q-履` 不得同时写成均已作为成交必选项。定金与违约金选用不明时两项都标待核，不输出相加总额。

金额引用已有测算或用户材料；本任务不替代 `calculate-damages`。约定违约金不是必得金额。第 585 条调整只作为谈判理由，不得把“法院一定会调到损失的百分之三十”写成成交依据。

## 节点 3　底线、弃权与明示确认

### 3.1 底线分列

| 底线类型 | 允许的写法 | 禁止 |
| --- | --- | --- |
| 金钱 | 本金、违约金、损失、已付款、质保金分项下限／上限 | 把未测算项目写成零；输出唯一必得总额 |
| 非金钱 | 交付、修理更换、配合过户、开票、保密、竞业 | 用“妥善处理”代替标的和期限 |
| 期限 | 付款日、交付日、撤诉日，并列起算事件 | 用“尽快”充作截止日 |
| 程序 | 是否撤诉、是否解除保全、是否撤回仲裁 | 把尚未授权的程序处分写成已决定 |

### 3.2 弃权闸

未获用户就具体范围的明示确认，不得把任何现有 `Q#` 写成已放弃。

`W#` 必须逐项回答：

1. 放弃的是哪些请求、哪些期间发生的事实；
2. 是否包含违约金、利息、损失、律师费、保全担保损失；
3. 是否包含担保人、共同债务人、隐名主体；
4. 是否包含未知损害、后续发现的质量或权利瑕疵；
5. 是否以对方实际履行为生效条件。

出现下列任一情形：字段停止或负触发，不写入成交条件。

- “永不追究”“全部债权消灭”且覆盖未知损害或未发生事实；
- 要求放弃对第三人的权利而该第三人未参加谈判；
- 要求用户承认不存在的违约，作为换取付款的条件，且用户未明示接受虚假自认风险。

和解让步本身可能构成诉讼时效中断或债务确认，须运行时核验现行规则后再写对时效的影响；核验失败则时效字段停止，不把报价写成已经中断。

### 3.3 输出

| 条件 | 本任务输出 | 转介 |
| --- | --- | --- |
| 用户未确认弃权 | 弃权接口留空，底线保留请求 | 不起草弃权条款 |
| 用户已就有限范围明示确认 | 写入 `W#`，标可逆性和撤回窗口 | 签章条款转起草原子 |
| 用户坚持概括永久弃权 | 目标停止或字段停止 | 不实施 |

## 节点 4　付款、交付、解除与清理

1. 每笔义务写：主体、相对方、标的、数量或金额、履行地、时间或条件、凭证、验收、未履行后果。未知不编造。
2. 解除是否作为成交条件必须单列。现有依据尚不支持解除权时，不得把“双方同意解除”以外的法定解除效果写成已经发生。双方同意终止或变更的，按民法典合同编变更、终止规则运行时核验，不沿用已失效《合同法》。
3. 结算清理、争议解决、保密条款不因合同终止当然失效（第 567 条）。返还、折价、保管减损、发票和质保金必须在方案中有位置，即使双方口头说“以后再说”。
4. 分期付款写明每期金额、账号、逾期是否恢复原请求或仅计迟延后果。以物抵债写明物权变动是否另需登记、价值争议和差额处理。第三方代付写明代付人是否免责、原债务人是否退出。
5. 已有仲裁或诉讼时，方案须写清：何日撤诉或撤回申请、诉讼费／仲裁费负担、保全如何解除、担保如何返还。未获特别授权，不得把撤诉写成已经指令。

## 节点 5　执行力路径

本节点只判断路径和风险，不代办任何赋强程序，不生成可签协议终稿。

### 5.1 单独和解必须明示

当事人诉讼外达成的和解协议，原则上仅有民事合同拘束力。一方不履行时，通常只能另行主张合同权利或恢复原争议路径，不能直接申请强制执行。本句必须出现在第 8 节，不得用“签了就能执行”代替。

不得把下列事实写成已经取得执行力：双方在聊天中达成一致；律师见证；人民调解口头了解；诉讼外和解备忘录；“已读”或已签字但未经法定赋强程序。

### 5.2 赋强路径只转介

运行时核验现行文本后再落判断。核验失败则执行力字段停止，方案其余部分可继续。

| 路径 | 现有依据通常要求 | 本任务允许 | 禁止 |
| --- | --- | --- | --- |
| 单独和解协议 | 合同成立和拘束力 | 明示无执行力；标违约后另诉或另仲风险 | 写成可直接申请执行 |
| 诉讼调解书 | 法院调解、双方签收（民事诉讼法第 99–102 条） | 转介 `assess-mediation`；提示签收前可反悔 | 保证法院出具调解书 |
| 仲裁调解书 | 有效仲裁程序中调解 | 转介仲裁应诉／申请侧；提示与裁决书效力比较待核 | 无仲裁协议却写可出仲裁调解书 |
| 司法确认 | 依法设立的调解组织调解；双方自协议生效之日起三十日内共同申请（民事诉讼法第 205–206 条） | 转介 `confirm-settlement-enforceability` | 把未经调解组织的私下和解直接写成可司法确认；代写并承诺裁定有效 |
| 公证赋强 | 给付内容明确、债权无疑义、载明债务人接受强制执行承诺（公证法及民事诉讼法执行规范，运行时核验） | 只标是否表面符合给付明确；转介赋强项 | 对争议未闭合的质量或解除争点承诺可办公证赋强 |

司法确认被裁定驳回后，当事人可以再调解或起诉，不得写成“确认失败即丧失实体权利”。

### 5.3 论坛约束

合同、补充协议或事后书面协议中出现仲裁条款时：

1. 不得写“谈不拢就向法院起诉”。
2. 书面要件和支持条件闭合时论坛主位写成仲裁。仅在已核验的无效、不覆盖，或依法未在规定节点提出异议并视为放弃时，才评估诉讼入口。不得用“双方应诉”概括放弃。未核验则论坛字段停止。
3. 或裁或诉、机构不明：效力标 `依据不足`，转介 `assess-forum-and-arbitration`。
4. 合同无效、被撤销或终止，不当然消灭仲裁协议。独立性规则须运行时核验现行《仲裁法》文本，不得沿用记忆条号。无法核验则论坛字段停止。

C 端 032 只要第一轮止损清单时只分流，不把本方案降成止损话术，不回改 032。

## 程序与报价表

程序动作记录机关、案号、文书、作出、收到、送达、效力。报价每行只对应一个提出主体、一个到达状态和一个有效期情景。关键日期冲突则并行情景。

## 方案表

固定列：争点、主位、开价、可谈、底线、对价、弃权范围、履行安排、执行力、互斥、最强反方、判断、待核。参数不足不输出唯一成交总额。

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因对方控制而推定材料存在或内容有利。不得指导伪造履约、制造资金流水或虚假和解。

下一步按期限灭失、易失证据、能否改变 `N#`／`W#`、可逆性排序。每项写执行人、前置、最晚时点、预期改变、备选、可逆性和停止条件。

签章和解协议、司法确认申请、起诉、应诉只写转介条件和最小交接，不在本方法生成那些终稿。禁止指导伪造、隐匿、威胁或违法取证。
