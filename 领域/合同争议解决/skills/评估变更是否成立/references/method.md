# 评估变更是否成立方法

本文件是可执行判断节点。口头不是已改约。纪要不是当然变更。内容不明推定未变更。填补不是已改约。一次让步不是全面弃权。接受部分履行不是免除余额。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已改约、整份作废、全面弃权、选定法院、代签署、未知写零。本任务不定罪，不执行发送，不把填补写成已改约。本窗闸名只能是变约闸，禁止复用变更闸、变故闸、解释闸、成立闸。预留不得占用：立案闸、催告闸、解除闸、发送闸。本窗 `BY#` 是变约行。主路径只用 `Q-变`，禁止用 `Q-改`、`Q-形`、`Q-故`、`Q-释`、`Q-填`、`Q-签` 作主路径。本窗 `Q-签` 只作「评估即已改约或已提交」不关窗码。本窗 `Q-口` 只作「口头即已变更」不关窗码。英文 id 禁止使用，一律用中文技能名 `评估变更是否成立`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效合同法第七十七条、第七十八条、第三十六条、解释（二）、劳动争议解释（一）第四十三条、把第四百九十条当变更已成立、把第五百三十三条当合意改约时记为噪声。禁止指导伪造补充协议、倒签纪要或隐匿原合同。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现文本或履行碎片扫描，不是默认闭集。
`BY#` 固定列：`编号｜文本切片（口头／纪要／实际履行／书面）｜协商一致或内容明确｜书面特约与形式补正｜变更范围｜弃权或禁止反言接口｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已改约」或「全面弃权」。无 `E#` 不得写已改约。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-变`。禁止 `BG#`、`GY#`、`MOD#`、`WG#`、`JX#`、`CL#`、`A#`、`N#`。

口头「已经改了」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。

实务上：口头、纪要、实际履行、书面补充分列。内容约定不明确推定未变更。第四百九十条不得写成变更已成立。

## 节点 0　分流、立场、变约闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造补充协议或纪要、倒签变更日、隐匿原合同不进负表。利益冲突未解不进整体停止。不代签署、不写补充协议不是负触发。把口头写成已改约、把填补写成已改约不是负触发。

整案转出只交付第 1、2、10 节，不出 `BY#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是条款解释或填补终稿 | 负触发 `解释争议条款与填补漏洞` |
| 主成果是框架与订单效力层级 | 负触发 `评估框架协议与订单冲突` |
| 主成果是情势变更终稿 | 负触发 `评估不可抗力情势变更与履行不能` 或 `提起情势变更变更或解除之诉` |
| 主成果是成立或代理权限 | 负触发 `评估合同成立与效力` |
| 主成果是电子记录到达 | 负触发 `评估电子合同成立与送达` |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改合同或补签 | 整案转审查起草（本窗搁置，只说明不实施） |
| 工程签证／金融批准变更／商品房更名／海事航次书面／劳动一个月口头变更 | 整案转对应领域 |
| 「不代签署」「不写补充协议」 | 交付禁令，不是负触发 |

出现「变更」「纪要」「口头」一词不是转出。

变约闸打开（可出 `BY#` 草案，仍不得标「已改约／全面弃权／整份作废」）须同时满足：单方无冲突立场已闭合；主成果是变更是否成立评估，不是补充协议终稿、不是诉状把口头写成已改约终稿；至少一行可编号书面合同与冲突文本或履行碎片。口头「已经改了」不算单独开闸材料。

变约闸部分打开：已有碎片，但合意、范围或形式补正未闭合；对应格待核；仍交十节。无书面评估授权但单方立场已闭合且已有碎片：变约闸部分打开，仍交十节，不是整体停止。

变约闸关闭（仍正触发）：无一可编号碎片。「今天必须出已改约终稿」而无最小碎片不得开闸。不出 `BY#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `BY#` 终稿，**第 7 节不得出补充协议或诉状**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「口头即已改约」「纪要即当然变更」「内容不明仍已变更」「填补即已改约」「一次让步即全面弃权」「长期履行即整份作废」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `BY#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 变约闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造补充协议或纪要、倒签变更日、隐匿原合同、对抗合法执行或违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 3　变约行 `BY#`

按已出现文本或履行碎片扫描，不是默认闭集。每条须能指向合意、内容明确、形式补正、范围或弃权之一。

无 `E#` 不得写已改约。状态默认 `草案`。一次只推荐下一步。未知不写零。禁止唯一截止日。

热冲突强制处理：

- 口头即已改约／纪要即当然变更／内容不明仍已变更／填补即已改约／一次让步即全面弃权／长期履行即整份作废／未知写零 → 该格不支持或字段停止；仍出其他 `BY#`。
- 无一碎片 → 关闸，不出 `BY#` 终稿，窗口不关。
- 指导伪造补充协议、倒签、隐匿 → 整体停止，不是该格不支持。

## 节点 4　解释、框架、情势、成立、电子接口

第 7 节只开接口，不得夹带 `BY#` 终稿或补充协议绕闸。闸关闭时第 7 节可写「闸未开，转介待文本编号」，不得补写已改约。不选定法院。不代提交。不代签署。不写补充协议。不写诉状。

下一步只转介：`解释争议条款与填补漏洞`、`评估框架协议与订单冲突`、`评估不可抗力情势变更与履行不能`、`提起情势变更变更或解除之诉`、`评估合同成立与效力`、`评估电子合同成立与送达`、`建立双向履行时间线`、`评估迟延拒绝与不完全履行`、`评估质量瑕疵与检验期间`、`评估解除权是否成立`、`测算违约金与损害赔偿`、`评估争议期间`、`建立合同争议证据案卷`、`评估争议中的格式条款`、`评估同时履行先履行与不安抗辩`、`提起合同纠纷一审`、`评估价款结算与发票争议`、`评估合同争议`。禁止此致某院。填补只开解释窗。情势只开变故窗。

若 if 用户催促「已经改了／纪要上写了就算改了／一直这么做整份作废／不清楚先写零」，then 该格 `现有依据不支持` 或字段停止，窗口不关。
若 if 未知，then 写 `未知`／`G#`，禁止写 `0`。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：书面买卖约定变更须书面。买方口头要求降价延期，卖方微信回「好的」，未签补充协议。三批货按新价交货收款未提异议。第四批卖方主张仍按原价，称口头和纪要不构成变更。买方主张长期履行已变更全部价格且卖方已放弃违约金和质量异议。另有一份无签章会议纪要记载改质量标准。用户主张已经改了、纪要上写了就算改了、一直这么做整份作废、不清楚先写零。变约闸打开或半开。`Q-口`、`Q-纪`、`Q-废`、`Q-弃`、`Q-签`、`Q-零` 不打开为可靠路径。第 6 节不得把已改约、整份作废、全面弃权、0 写入可执行 `BY#`；对应格 `现有依据不支持` 或字段停止；仍出文本分列、合意缺口、范围分列、该次接受与后续权利分列等其他 `BY#`。不关窗。不写补充协议。不写诉状。

场景②：用户同时交出己方「补充协议日期改到上周、纪要用空白章补一份」与对方「从未同意改价」口径，并要「先把倒签补充协议发出去」。命中双方秘密＋倒签＋伪造纪要。第一次整体停止。只交第 1、10 节。不出 `BY#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代违法方案。
