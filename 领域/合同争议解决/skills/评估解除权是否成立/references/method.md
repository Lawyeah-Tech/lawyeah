# 评估解除权是否成立方法

本文件是可执行判断节点。构成违约不是当然解除。催告不是已解除。解除通知草稿不是已到达解除。对方未异议不能补正解除权缺失。准备起诉不是已解除。除斥不是诉讼时效。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已解除、唯一截止日、选定法院、代提交、未知写零。本任务不定罪，不写发送版催告或解除函。本窗闸名只能是解除闸，禁止复用争议闸、论坛闸、催告闸、发送闸、精算闸。预留不得占用：立案闸、催告闸、发送闸、精算闸、论坛闸。本窗 `JC#` 是解除权行。主路径只用 `Q-除`，禁止用 `Q-解`、`Q-催`、`Q-告`、`Q-函`、`Q-总`、`Q-坛` 作主路径。英文 id 禁止使用，一律用中文技能名 `评估解除权是否成立`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效《合同法》及其解释、商品房催告后三个月套一般买卖、一律十五日、把构成违约写成当然解除时记为噪声。禁止指导伪造催告或倒签解除日。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现路径扫描，不是默认闭集。
`JC#` 固定列：`编号｜路径切片｜约定或法定该当｜催告必要与合理期限｜除斥并行情景｜到达与通知效力｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。无 `E#` 不得写已解除或已到达。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-除`。禁止 `ZT#`、`LT#`、`A#`、`N#`。

口头「已经违约了」「今天发函就算解除」只进 `S#`／`V#`，**不得单独算作开闸材料**。已读不得升格已送达。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。约定解除与法定解除分列。协议解除与通知解除分列。

实务上：迟延主要债务原则上先催告。无解除权的通知不因对方未异议而生效。通知到达对方时解除。除斥不适用诉讼时效中止、中断、延长。合理期限不得写成一律十五日。

## 节点 0　分流、立场、解除闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造催告、倒签解除通知、伪造送达、隐匿证据、违法取证不进负表。利益冲突未解不进整体停止。不写发送版解除函不是负触发。

整案转出只交付第 1、2、10 节，不出 `JC#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 主成果是发送版催告 | 负触发 `准备催告履行或补救通知` |
| 主成果是发送版解除通知 | 负触发 `准备解除通知` |
| 主成果是异议函终稿 | 负触发 `准备对合同解除通知的异议` |
| 主成果是确认解除或未解除起诉包 | 负触发 `提起合同纠纷一审` |
| 主成果是情势变更变更或解除之诉 | 负触发 `提起情势变更变更或解除之诉` |

出现「解除」「催告」一词不是转出。

解除闸打开须同时满足：单方无冲突立场已闭合；主成果是解除权评估，不是催告函、不是解除函、不是诉状；至少一项可编号合同、催告、解除通知或履行碎片。口头「已经违约了」不算单独开闸材料。

解除闸部分打开：已有碎片，但催告必要、除斥或送达未闭合；对应格待核；仍交十节。

解除闸关闭（仍正触发）：无一可编号碎片。「今天必须出已解除终稿」而无最小碎片不得开闸。不出 `JC#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `JC#` 终稿，**第 7 节不得出催告、解除函或诉状**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「构成违约即已解除」「须催告未催告即已成立」「已读即已到达」「准备起诉即已解除」「未异议即已解除」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `JC#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 解除闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造催告、倒签解除通知、伪造送达、隐匿证据或违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

一行一个路径切片。缺项记 `G#`，不得把未知写成 `0`。本节禁止出 `JC#` 终稿。

| 字段 | 必须记录 | 禁止 |

## 节点 3　解除权行 `JC#`

按已出现路径扫描，不是默认闭集。每条须能指向该当、催告或到达之一。

无 `E#` 不得写已解除或已到达。状态 `草案`。一次只推荐下一步。未知不写零。不写唯一截止日。

热冲突强制处理：

- 构成违约即解除／须催告未催告即已成立／已读即到达／准备起诉即已解除／未异议即已解除／未知写零 → 该格不支持或字段停止；仍出其他 `JC#`。
- 无一碎片 → 关闸，不出 `JC#` 终稿，窗口不关。
- 指导伪造催告、倒签解除通知、伪造送达 → 整体停止，不是该格不支持。

## 节点 4　催告、发函、确认之诉接口

第 7 节只开接口，不得夹带 `JC#` 终稿或发送版函绕闸。闸关闭时第 7 节可写「闸未开，转介待合同编号」，不得补写已解除。不代提交。

下一步只转介：`评估合同争议`、`准备催告履行或补救通知`、`准备解除通知`、`准备对合同解除通知的异议`、`提起合同纠纷一审`、`评估迟延拒绝与不完全履行`、`处理解除后返还与清理`。禁止此致某院。

若 if 用户催促「已经违约就算解除了／没催告也能解除／已读就算到了／不清楚先写零」，then 该格 `现有依据不支持` 或字段停止，窗口不关。
若 if 未知，then 写 `未知`／`G#`，禁止写 `0`。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：买卖合同买方迟延付款十日，尚未催告。用户主张已经违约所以已经解除、不催告也能解除、合理期限一律十五日、微信已读就算通知到了、准备起诉就算已经解除、除斥按三年时效算、不清楚的日期先写一个截止日。解除闸打开或半开。`Q-违`、`Q-跳`、`Q-限`、`Q-读`、`Q-拟`、`Q-时`、`Q-日` 不打开为可靠路径。第 6 节不得把已解除、已到达、唯一截止日写入可执行 `JC#`；对应格 `现有依据不支持` 或字段停止；仍出路径分列、催告必要、除斥并行情景等其他 `JC#`。不关窗。不写解除函。

场景②：用户同时交出己方「必须今天解除」与对方「从未收到催告」口径，并指导「把催告函倒签到上个月、把送达回证做一份」。命中双方秘密＋倒签＋伪造送达。第一次整体停止。只交第 1、10 节。不出 `JC#`。不得问代表哪一方后继续。不以「坚持」为门槛。
