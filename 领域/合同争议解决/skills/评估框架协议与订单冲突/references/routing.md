# 边界与路由

## 正触发

框架、订单、送货单、对账单不一致，需要评估何者成为内容及该批次范围。从零、碎片、确认未核验、无书面评估授权仍正触发：有可编号框架或订单或送货或对账碎片则闸开或半开，出 `KY#` 草案，保持草案。本次不写确认书、不编单价是交付禁令，不是开窗条件。送货单即覆盖、对账单即改约、框架即当然本约，仍正触发。把送货单写成覆盖、把多单合成一笔框架违约，仍正触发：该格不支持，不改负触发关窗。不按单张订单另建技能。

双方秘密、伪造订单或对账、倒签确认日、隐匿框架或订单的停止，优先于负触发。上述信号不在下表。不写确认书不是负触发。「送货单即覆盖框架」「对账单即改约」「框架即当然本约」「后文件即当然覆盖」「沉默即承诺」不在下表。

## 负触发

| 主要目标 | 路由 |
| --- | --- |
| 条款解释或填补终稿 | `解释争议条款与填补漏洞` |
| 合意改约终稿 | `评估变更是否成立` |
| 电子到达终稿 | `评估电子合同成立与送达` |
| 格式勾选提示 | `评估争议中的格式条款` |
| 总体成立效力 | `评估合同成立与效力` |
| 价款结算发票 | `评估价款结算与发票争议` |
| 争议总图 | `评估合同争议` |
| 尚未成争，改模板或出稿 | 审查起草领域（本窗搁置，只说明） |
| PI／信用证分订单 | 涉外 `评估框架协议与分订单冲突` |
| 工程签证／金融授信框架／商品房认购／海事航次／劳动集体合同 | 对应领域 |

不得因「不写确认书」或「不编单价」关窗。拟框约评估仍正触发，不得写成已成为内容或已覆盖。

| 主轴信号 | 路由 |

一般买卖或服务夹带专项背景时，专项段只分流。出现「框架」「订单」「对账」一词不是转出。C 端只要大众采购填空页时只分流，不把本包降成填空式框架，不回改。

## 易混

本窗闸名只能是框约闸，不是框架闸，不是层级闸，不是变约闸，不是解释闸。`KY#` 不是 `KJ#`，不是 `BY#`，不是 `JX#`，不是 `DOC#`。主路径是 `Q-架`，不是 `Q-框`，不是 `Q-层`，不是 `Q-变`，不是 `Q-释`。`Q-框` 是合规框架主路径。`KJ#` 是跨境行。送货单不是当然覆盖框架。对账单不是当然改约。框架不是当然本约，也不是当然优先。后文件不是当然覆盖。沉默不是承诺。填补不是已改约。买卖解释第一条送货单等须结合交易方式习惯，不是覆盖。已失效合同法第六十一条、第六十二条不是现行。保险凭证层级不得套一般买卖框架。MCP 可能先返回合同法第六十一条或保险解释而漏通则解释第十四条、买卖解释第一条。「回签日改到发货前」「没回签的订单藏起来」整体停止。本窗不执行发送，不代提交，不代签署。不选定法院。不写确认书。不写诉状。不编单价。不按单张订单另建技能。
