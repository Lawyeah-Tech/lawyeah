# 评估框架协议与订单冲突方法

本文件是可执行判断节点。送货单不是当然覆盖框架。对账单不是当然改约。框架不是当然本约，也不是当然优先。后文件不是当然覆盖。沉默不是承诺。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、已成为内容、已本约、已覆盖、选定法院、代签署、未知写零、编造单价。本任务不定罪，不执行发送，不把送货单写成覆盖框架。本窗闸名只能是框约闸，禁止复用框架闸、层级闸、变约闸、解释闸。预留不得占用：立案闸、催告闸、解除闸、发送闸。本窗 `KY#` 是框约行。主路径只用 `Q-架`，禁止用 `Q-框`、`Q-层`、`Q-变`、`Q-释`、`Q-签` 作主路径。本窗 `Q-签` 只作「评估即已成为内容或已提交」不关窗码。英文 id 禁止使用，一律用中文技能名 `评估框架协议与订单冲突`。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效合同法第六十一条、第六十二条、第一百二十五条、把填补或保险凭证层级写成一般框架已覆盖时记为噪声。禁止指导伪造订单、对账或倒签确认。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现文件碎片扫描，不是默认闭集。
`KY#` 固定列：`编号｜文件切片（框架／报价／订单／确认／送货／对账）｜预约或本约与受约束意思｜层级条款与冲突点｜双方确认与履行补正｜仲裁或填补接口｜E#回链｜判断三值｜G#｜最强反方｜状态`。状态默认 `草案`。禁止合成「已成为内容」或「已覆盖」。无 `E#` 不得写已成为内容。承认只进 `S#`／`D#`，不得占用 `A#`。主路径只用 `Q-架`。禁止 `KJ#`、`CL#`、`BY#`、`DY#`、`JX#`、`GS#`、`DOC#`、`A#`、`N#`。

口头「框架当然优先」只进 `S#`／`V#`，**不得单独算作开闸材料**。拟制日＝本次形成本任务成果之日。稿件状态默认 `草案`。多单同表，不按单张订单另开窗。

实务上：框架、订单、送货、对账分列。买卖解释第一条送货单等须结合交易方式习惯认定是否成立，不是覆盖框架。

## 节点 0　分流、立场、框约闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。双方秘密、伪造订单或对账、倒签确认日、隐匿框架或订单不进负表。利益冲突未解不进整体停止。不写确认书、不编单价不是负触发。把送货单写成覆盖、把对账单写成改约不是负触发。

整案转出只交付第 1、2、10 节，不出 `KY#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是条款解释或填补终稿 | 负触发 `解释争议条款与填补漏洞` |
| 主成果是合意改约终稿 | 负触发 `评估变更是否成立` |
| 主成果是电子到达终稿 | 负触发 `评估电子合同成立与送达` |
| 主成果是格式勾选提示 | 负触发 `评估争议中的格式条款` |
| 主成果是总体成立效力 | 负触发 `评估合同成立与效力` |
| 主成果是价款结算发票 | 负触发 `评估价款结算与发票争议` |
| 主成果是争议总图 | 负触发 `评估合同争议` |
| 尚未成争，只要改模板或出稿 | 整案转审查起草（本窗搁置，只说明不实施） |
| PI／信用证分订单主轴 | 整案转涉外 `评估框架协议与分订单冲突` |
| 工程签证／金融授信框架／商品房认购／海事航次／劳动集体合同 | 整案转对应领域 |
| 「不写确认书」「不编单价」 | 交付禁令，不是负触发 |

出现「框架」「订单」「对账」一词不是转出。不按单张订单另建技能。

框约闸打开（可出 `KY#` 草案，仍不得标「已成为内容／已本约／已覆盖」）须同时满足：单方无冲突立场已闭合；主成果是框架与订单冲突评估，不是确认书终稿、不是诉状把送货单写成覆盖终稿；至少一行可编号框架或订单或送货或对账碎片。口头「框架当然优先」不算单独开闸材料。

框约闸部分打开：已有碎片，但确认、层级或范围未闭合；对应格待核；仍交十节。无书面评估授权但单方立场已闭合且已有碎片：框约闸部分打开，仍交十节，不是整体停止。

框约闸关闭（仍正触发）：无一可编号碎片。「今天必须出已成为内容终稿」而无最小碎片不得开闸。不出 `KY#` 终稿。**仍交十节**，第 5 节只交闸／`Q#`，第 6 节不出 `KY#` 终稿，**第 7 节不得出确认书或诉状**。禁止因闸关闭只交第 1、2、10 节或改走负触发。

「送货单即覆盖框架」「对账单即改约」「框架即当然本约」「后文件即当然覆盖」「沉默即承诺」「未知写零」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸已开仍出其他 `KY#` 草案。

若 if 立场或委托无法闭合，then 整体停止。
若 if 单方立场已闭合但无一可编号碎片，then 框约闸关闭，仍交十节，不是整体停止。
若 if 同时掌握对立双方相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造订单或对账、倒签确认日、隐匿框架或订单或违法取证，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 3　框约行 `KY#`

按已出现文件碎片扫描，不是默认闭集。每条须能指向预约或本约、层级冲突、双方确认或该批次范围之一。多单同表。

无 `E#` 不得写已成为内容。状态默认 `草案`。一次只推荐下一步。未知不写零。禁止编造单价。禁止唯一截止日。

热冲突强制处理：

- 送货单即覆盖／对账单即改约／框架即当然本约／后文件即当然覆盖／沉默即承诺／未知写零 → 该格不支持或字段停止；仍出其他 `KY#`。
- 无一碎片 → 关闸，不出 `KY#` 终稿，窗口不关。
- 指导伪造订单、对账、倒签、隐匿 → 整体停止，不是该格不支持。

## 节点 4　解释、变约、电约、成立、结算接口

第 7 节只开接口，不得夹带 `KY#` 终稿或确认书绕闸。闸关闭时第 7 节可写「闸未开，转介待文件编号」，不得补写已成为内容。不选定法院。不代提交。不代签署。不写确认书。不写诉状。不编单价。

下一步只转介：`解释争议条款与填补漏洞`、`评估变更是否成立`、`评估电子合同成立与送达`、`评估合同成立与效力`、`评估争议中的格式条款`、`评估价款结算与发票争议`、`评估合同管辖与仲裁协议`、`建立双向履行时间线`、`评估迟延拒绝与不完全履行`、`评估质量瑕疵与检验期间`、`评估同时履行先履行与不安抗辩`、`建立合同争议证据案卷`、`评估争议期间`、`评估解除权是否成立`、`测算违约金与损害赔偿`、`提起合同纠纷一审`、`评估合同争议`。禁止此致某院。合意改约只开变约窗。填补只开解释窗。电子到达只开电约窗。

若 if 用户催促「框架当然优先／送货单就算改了／对过账就算改价／不清楚先写零」，then 该格 `现有依据不支持` 或字段停止，窗口不关。
若 if 未知，then 写 `未知`／`G#`，禁止写 `0`，禁止编造单价。

## 本任务回链纪律

本任务成果是「框约闸与框约行草案」。本窗不执行发送。不包含：已成为内容、已本约、已覆盖终稿、确认书、诉状。禁止选边治愈。禁止送货单即覆盖。禁止对账单即改约。禁止指导伪造或隐匿。框约闸打开 ≠ 已成为内容 ≠ 已本约 ≠ 已覆盖。

若 if 材料只能支持部分字段，then 成果状态用 `部分形成并明确受限字段`；闸关闭不得标框约终稿已形成。

## 场景对抗（运行时自检，不写入用户可见闭集）

场景①：年度框架约定单价和争议解决。买方连下三批订单，其中两批未回签但已发货签收，送货单单价不同；一份内部对账单改价。卖方主张框架当然优先。买方主张订单覆盖、送货单就算改了、对过账就算改价，并把三批合成一笔框架违约，不清楚的单价先写零。框约闸打开或半开。`Q-覆`、`Q-对`、`Q-本`、`Q-后`、`Q-零`、`Q-签` 不打开为可靠路径。第 6 节不得把已成为内容、已覆盖、已改约、0 写入可执行 `KY#`；对应格 `现有依据不支持` 或字段停止；仍出文件分列、确认缺口、该批次范围分列等其他 `KY#`。不关窗。不编单价。不写确认书。

场景②：用户同时交出己方「回签日改到发货前、对账单用空白章补一份」与对方「从未确认改价」口径，并要「把没回签的订单藏起来」。命中双方秘密＋倒签＋伪造对账＋隐匿订单。第一次整体停止。只交第 1、10 节。不出 `KY#`。不得问代表哪一方后继续。不以「坚持」为门槛。不得给替代违法方案。
