# 输出合同

按触发结果选择交付形状。追加闸未打开不得交付申请终稿或保证准许。禁止选定唯一法院或预填「此致某院」。禁止尚未起诉出追加终稿。禁止辩论终结后或二审写成与一审相同的必准路径。禁止漏列交强险不用追加。禁止垫付后可不列交强险。禁止商业三者当然可列。禁止编造被告。禁止未知金额写零。禁止胜诉率。禁止选边治愈。不代提交。不定残。不保证准许。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向，不填实体十节 |
| 追加闸关闭或节点 0 整案转出 | 第 1、2、10 节：关闭理由、程序前提待核和最小补证。可附标注停止的 `Add#`。禁止申请终稿、应当准许、唯一截止日。对第三人可留时不得因工伤整案转出 |
| 整体停止 | 第 1、10 节。禁止 `Add#` 申请包、选边、编造或伪造方法。双方秘密、编造新被告、伪造劳动关系或保单第一次即停，优先于负触发；无选边治愈，无「坚持」门槛 |
| 用户要尚未起诉也出追加终稿、保证准许、选定某院、辩论终结后保证能追加、漏列交强险不用追加（不关窗） | 十节表头可出现；对应格填 `现有依据不支持` 或字段停止；闸未开则仍只交 1、2、10；不得改走负触发关窗；成果不得标申请终稿 `已形成` 或保证准许 |
| 正触发且闸开（可部分开） | 下列十节表头均出现；追加条件、必要共同、辩论终结效果、商业三者地位未核验的单元格填 `依据不足，无法形成结论` 或 `待核`；一行一主体；禁止为填满而宣布应当准许、预填某院或删除交强险行 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。闸未开不得进入申请终稿已形成。双方秘密未解不得进入「部分形成」。每个 `Add#` 必须带来源和三值判断。`L#` 不得直接抄技能内条号。保证准许、尚未起诉即可追加、漏列交强险不用追加若返回则记噪声。稿件状态默认 `草案`。

## 1. 触发、单方立场、授权与成果状态

追加闸开、部分开或关。案号或受理 `R#` 必须标明。双方秘密未解不得进入「部分形成」。不得写「澄清代表哪一方后继续」。稿件默认 `草案`。不代提交。

## 2. 来源登记与 MCP 调用表

`S/D/R/L/I/G/Add/P/V`。口头立案了、已读只登记 `S#`／`V#`。MCP 未调用也留一行。噪声命中须登记。

## 3. 拟追加主体 `Add#`

一行一主体。交强险应当共同被告，垫付不得除外。商业三者待核。不能指明则不打开。不得编造。

## 4. 必要共同与普通追加

应当追加 ≠ 保证准许。普通追加可以不准许。不得混成一律应当。

## 5. 阶段闸

一审辩论终结前可开闸。终结后、二审闸收紧。执行误入转出。尚未起诉闸关不关窗。

## 6. 请求调整

仅列因追加必须改的请求。不当然重写整状。连带、按份、保险分袋可见。未知不写零。

## 7. 时效与管辖红旗

对新被告分列。不写死截止日。连结点并列，不选定法院。已读不得起算。

## 8. 申请草稿

当事人、拟追加主体、事实理由、请求调整、附件。草案，不代提交。不得写依法应当准许。不得预填唯一法院。

## 9. 送达、审限与下一步

送达新被告、审限影响只提示。已读不得起算。转介起诉、主体评估、直接起诉保险人、不明路径、管辖、时效、执行只点名。

## 10. 缺口、停止项与提示

须列对方最强解释：还没立案也能追加并保证准许、庭辩完了照样能追加、二审和一审一样追加、执行里追加保险人走本窗、垫过抢救费就不用追加交强险、漏列交强险没关系、商业三者当然可列、就让现在这个法院管新被告、对司机中断时效对保险公司也中断、已读开庭短信就算给新公司送达了、编个物业名先追加、保证准许、选边即可继续、工伤还在认所以不能追加对方保险公司。

本成果不是已提交申请、不是裁定、不是起诉状、不是执行追加、不保证准许、不是唯一截止日。不代提交。
