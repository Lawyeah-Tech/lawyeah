# 追加主体方法

本文件是可执行判断节点。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。稿件状态只用 `草案`、`追加闸关闭`、`提交前待核`、`停止`。禁止胜诉率、准许率、唯一必得总额、唯一截止日、选定法院、自行宣布伤残等级、保证准许。未知金额不写零。本任务不代提交。不编造被告。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效《侵权责任法》、已失效《合同法》、把尚未起诉写成可出追加终稿、把保证准许写成应当准许、把辩论终结后写成必能追加、把漏列交强险写成不用追加、把垫付写成可不列、把执行变更追加被执行人写成诉讼追加、把口头或已读写成已送达时记为噪声，不得写入 `L#`。禁止指导编造被告、伪造保单或倒签。

`Add#` 固定列：`编号｜主体类型（交强险保险人／商业三者保险人／用人者／派遣或用工单位／场所／教育机构／直接侵权人／共同侵权人／投保义务人／变更原被告）｜名称可识别性｜列法（必要共同应当追加／交强险应当共同被告／商业三者当事人请求加入待核／普通追加可以不准许／释明追加直接侵权人／不打开／不得编造）｜新主体事实回链｜请求调整（连带／按份／保险限额内分袋；不整状重写除非必要）｜审理阶段（尚未起诉闸关／一审辩论终结前／辩论终结后／二审／执行误入）｜准许状态（草案不保证／闸关闭／现有依据不支持当然准许／待核）｜已赔例外（仅限额内实际赔清且无异议可不列交强险；垫付≠除外）｜对新被告时效红旗（分列／不写截止日／已读不得起算）｜对新被告管辖红旗（连结点并列／不选定）｜送达与审限提示｜状态｜来源回链`。一行一主体。禁止一行打包「保险公司们」。禁止用编造补齐闸。

口头「立案了」、截图、「已读」只进 `S#`／`V#`，不得升格 `R#` 已受理、已送达新被告或期间已起算。

## 节点 0　分流、立场、追加闸与不关窗

整案转出或闸关闭只交付第 1、2、10 节或标注停止的 `Add#`，不得交付申请终稿，不得标法院应当准许。闸部分打开时：仅对名称可识别且列法可回链的主体给出草案，其余行停止或不打开。

| 信号 | 处理 |
| --- | --- |
| 主成果已是诉前完整一审起诉状 | 负触发 `提起人身损害一审`；尚未起诉要「追加」时本窗闸关并转介起诉，窗口不关 |
| 主成果是诉前保险人地位起诉入口 | 负触发 `直接起诉保险公司` |
| 只要主体名单或保险能否进入 | 负触发 `评估责任主体与保险覆盖` |
| 被告侧反诉或抵销 | 负触发 `评估反诉或抵销`；本窗不写反诉状 |
| 执行阶段变更或追加被执行人 | 负触发 `执行人身损害生效文书`／`应对人身损害执行`；本窗不写执行追加 |
| 只要管辖或时效终稿 | 负触发对应专项；本窗只打红旗 |
| 刑附民应否列或另行民事 | 负触发 `评估刑附民与另行起诉` |
| 纯工伤待遇或劳动被申请人追加且无第三人 | 整案转劳动；夹带对第三人追加则本窗正触发，工伤段分流，`Add#` 可留并转介 `评估工伤与第三人侵权竞合` |
| 诊疗过错或医疗鉴定终稿 | 转医疗；对医疗机构的民事追加可留 |
| 海事专门程序 | 转海事 |
| 未成争只要改合同 | 审查起草本窗搁置 |

追加闸打开（可出 `Add#` 与申请草案，仍不代提交、不保证准许）须同时满足：单方无冲突原告立场与授权；主成果是追加或变更申请与新主体最小事实，不是起诉状终稿、不是主体总评估、不是反诉、不是执行追加；已有案号或受理凭证 `R#`；至少一名拟追加主体名称足以与他人相区别，不得用编造补齐；有新主体事实或法定应当追加接口（交强险漏列）。

闸关闭（仍正触发）：尚未起诉、无受理 `R#`；保证准许；选定某院；一审辩论终结后仍要当常规追加交稿；二审写成与一审相同；漏列交强险不用追加；商业三者当然可列或当然不列；垫付后可不列交强险；无新主体事实仍要随意追加；已读起算对新被告期间。闸未开则仍只交 1、2、10 节。

「尚未起诉」「保证准许」「选定法院」「辩论终结后必准」「漏列交强险不用追加」「无新事实仍要追加」**不关窗**。

若 if 使用者与授权或单方立场无法闭合，then 整体停止。
若 if 同时掌握双方秘密，或受害人与拟追加单位、保险人同时交材料争同一份追加稿且未获冲突豁免，then 整体停止，不得选边治愈，也不得改走负触发。
若 if 提出编造被告、伪造劳动关系或保单、倒签入职或出险日、逃逸未知名仍虚构主体、先随便列一个再补，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 1　拟追加主体 `Add#`

**交强险。** 道路交通事故损害赔偿中，承保交强险的保险公司通常**应当**列为共同被告。立案后漏列：本窗正触发核心场景，不是「无新事实」。除外仅当限额内**实际赔偿完毕**且当事人无异议并有赔付凭证。垫付、预付、抢救费垫付、基金垫付 **≠** 除外。用户坚持不追加：该行保留并字段停止，**不得删除**。检索锚点：道交损害赔偿交强险共同被告。条号不是 `L#`。

**商业三者。** 须当事人请求加入，条款与直接请求待核。未核验不得当然列、也不得当然不列。道交解释「请求列为共同被告应予准许」≠ 辩论终结后、二审当然准许，≠ 本窗保证已裁定准许。

**用人者、派遣、场所、教育机构、共同侵权人。** 各转介相应评估接口，本窗只写追加所需最小事实。仅起诉补充义务人须释明追加直接侵权人。不能指明名称：该行不打开，转 `评估侵权人不明路径`，禁止编造。

## 节点 2　必要共同、普通追加与阶段

必须共同进行诉讼的当事人未参加：人民法院应当通知其参加，当事人也可申请。审查后理由不成立裁定驳回。**应当追加 ≠ 保证准许。** 检索锚点：现行民事诉讼法及解释必要共同诉讼条款（2023 修正后常见第一百三十五条、解释第七十三条，须运行时核验）。条号不是 `L#`。

普通追加须申请加审查，不准许是常态风险。不得把必要与普通混成一律应当追加。

**阶段：**
- 一审法庭辩论结束前：常规窗口，仍不保证准许。增加诉讼请求可合并，与追加当事人分列。
- 一审辩论终结后：风险档上升，闸可关，不得标 `提交前待核` 为必然准许。
- 二审：普通追加原则上不打开；必须参加诉讼的当事人一审未参加的，可调解，调解不成发回，字段待核。禁止按一审格式出二审追加终稿。禁止把二审增加独立请求条款当成追加被告依据。上诉包转二审原子。
- 执行：变更、追加被执行人不是本任务。

## 节点 3　请求调整、时效与管辖红旗

因追加必须改的请求另列 `P#`，不当然重写整份起诉状。连带、按份、保险限额内分袋须可见。未知不写零。不定残。

对新被告诉讼时效可能不同。对原被告起诉中断不当然覆盖新被告（连带中断效力待核）。不写唯一截止日。已读不得起算或中断。转 `评估人身损害诉讼时效`。

原受诉法院对新增被告不当然有权。侵权行为地、各被告住所地并列，不选定，不预填「此致某院」。保险人住所地不对未列为当事人的驾驶人生效。转 `评估人身损害管辖`。

## 节点 4　申请草稿、送达与审限

草稿栏目只借范本结构。状态默认 `草案`。闸打开且无停止的 `Add#` 才得标 `提交前待核`。不代提交、不代签署、不写「法院应当准许」。不利事实不删除。

送达新被告、答辩期、审限影响只提示。口头、截图、「已读」不得写成已送达、答辩期已起算或审限已变。不编造唯一审限日。

## 再执行清单

每个节点结束后回写：来源编号、判断状态、最强反方、是否字段停止。不得跳过追加闸直接给应当准许、选定法院或删除交强险行。

若 if 日期、送达或动态规则未核验，then 依赖该规则的期限和法律结论字段停止，不编造唯一截止日。
若 if C 端只要大众准备包，then 只分流不回改。

判断状态只许三值。口头转述、截图和「已读」不得写成已受理、已送达或期限已起算。事故认定书不得单独写成民事终局并据此只追加或不追加。

## 本任务回链纪律

本任务成果是「不代提交的追加或变更申请草案」。必须包含：已立案前提、交强险漏列应当追加、商业三者待核。不包含：起诉状终稿、主体总评估、保险人起诉入口、反诉、执行追加。禁止保证准许。禁止选定法院。禁止编造被告。禁止尚未起诉出追加终稿。禁止选边治愈。

若 if 材料只能支持部分字段，then 成果状态用 `部分形成并明确受限字段`；闸关闭不得标申请终稿已形成。
若 if 相邻专项已打开且用户改要该专项终稿，then 目标停止，交付最小交接。
风险档 A：不可逆追加或编造被告字段必须单独标可逆性。
