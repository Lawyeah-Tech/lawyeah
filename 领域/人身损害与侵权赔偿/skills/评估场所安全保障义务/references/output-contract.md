# 输出合同

按触发结果选择交付形状。禁止损害即过错。禁止把补充改成连带或同一执行顺序。禁止把 2003 年解释第六条当现行。禁止因场所控制监控推定内容有利。禁止选定法院、伤残等级、必得总额。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向，不填实体十节 |
| 节点 0 整案转出（工伤待遇或劳鉴主轴；诊疗过错主轴；海事；未成争改合同） | 第 1、2、10 节。禁止义务违反结论、补充比例、追偿策略、监控内容推定 |
| 整体停止 | 第 1、10 节。禁止安保意见、选边、调取方案。双方秘密、编造监控、破坏现场或违法调取时，整体停止优先于负触发；第一次提出即停，无选边治愈，无「坚持」门槛 |
| 用户要「损害即全责」或「补充改连带」（不关窗） | 十节表头可出现；义务违反格或连带格填 `现有依据不支持` 或字段停止；不得改走负触发关窗；成果不得标 `已形成` |
| 正触发且可评估 | 下列十节表头均出现；义务范围、过错、相应补充、执行顺序、追偿未核验的单元格填 `依据不足，无法形成结论` 或 `待核`；禁止省略后改填全责、连带或必得额 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。双方秘密未解不得进入「部分形成」。每个 `Q#` 必须带判断三值和证明负担方。

## 1. 触发、单方立场、授权与成果状态

场所或活动类型。双方秘密未解不得进入「部分形成」。

## 2. 来源登记与 MCP 调用表

监控、巡检、合同分列。口述已删只登记 `S#`。`L#` 不得直接抄技能内条号。MCP 未调用也留一行。

## 3. 管理人、组织者、出租人分列

物业、商户、主办方、场地出租人一行一主体。私人住宅默认不打开。不替代主体窗终稿。

## 4. 安保义务与第一款过错

禁止损害即过错。湿滑未警示只是候选。主张未尽义务的一方举证。不得写成法定倒置。

## 5. 第三人与相应补充

第一款与第二款分列。不得改写连带，不得补充即全额，不得与第三人同一执行顺序。执行顺序未核验则待核。第三人不明则待核，不得写场所全额。物业抛物条款不得套商场盗窃殴打。

## 6. 追偿接口

承担补充后向第三人追偿。不附追偿状。仅起诉场所则标追加第三人释明接口。

## 7. 监控与易失证据

只转介 `准备监控保存通知`。不办调取。不能因场所控制监控推定内容有利。保存通知不等于法院保全。

## 8. 邻接红旗

教育 1199–1201、施工、物件、承运人 823、打架、自甘风险、过错、不明路径：打开、不打开或待核。

## 9. 下一步

转介发函、保全、测算或起诉。不定伤残。不选定法院。C 端只要大众包则只分流。

## 10. 缺口、停止项与提示

须列对方最强解释（摔了就是全责、旧第六条推定、补充即连带、补充即全额、可与第三人同时执行、监控在商场即内容有利、学校走 1198、工地走 1198、候车厅吞 823、第三人不明则商场全额、各打五十、选边即可继续）与证据缺口。

本成果不是起诉状、不是监控调取、不是伤残意见、不是必得总额、不是邻技能终稿。
