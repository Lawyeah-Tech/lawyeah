# 设计人身案件通知送达

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《侵权责任法》、2003 年人身损害赔偿解释已删除条文或已失效《合同法》当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 任务目标

在明确、无利益冲突的单方立场下，形成人身损害相关通知的送达设计包：设计闸、`E#` 分相对人渠道表（约定渠道、备份渠道、回证、失败升级、到达状态、时效中断接口待核）。诉讼外意思表示到达与诉讼送达分列。不写通知实体内容。不执行发送。不补造回证。不计算唯一截止日。不保证中断时效。不把微信已读、发送成功或口头转述写成已到达。

`depends-on` 为空。索赔正文转 `准备侵权索赔通知`。保存通知正文转 `准备监控保存通知`。中断能否成立转 `评估人身损害诉讼时效`。公证实施转 `准备人身案件公证保全`。已立案后的法院送达不是本任务。

## 工作边界

正触发：发函前需要单独设计送达渠道和到达证据，不写或暂不写通知实体内容。收件人地址不全、约定条款未定位、用户要把已读写成已到达、写死截止日或「今天必须发出」仍正触发：设计闸可关，对应格填 `现有依据不支持` 或字段停止，窗口不关。工伤待遇与对第三人催告送达同时出现：本窗正触发，工伤段分流劳动，第三人催告送达可留。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 只要索赔通知正文或项目表（转 `准备侵权索赔通知`）；
- 只要保存通知正文（转 `准备监控保存通知`）；
- 只要保险理赔申请材料包（转 `准备交强险商业险索赔材料`）；
- 只要公证送达或公证保全实施终稿（转 `准备人身案件公证保全`）；
- 已立案且只要法院诉讼送达策略（由法院实施；本窗不写诉讼送达方案）；
- 只要时效截止日或剩余天数终稿（转 `评估人身损害诉讼时效`）；
- 只要起诉状或应诉（转 `提起人身损害一审`／`应对人身损害一审`）；
- C 端只要大众准备包（只分流）；
- 未成争改合同（审查起草搁置）。

伪造签收、倒签邮戳、补历史回证、双方秘密**不在负触发表**，走整体停止。

## 建立工作坐标

确认：使用者与授权；单方立场；拟收件人（侵权人、用人者、场所、交强险／商业三者保险人分列）；已知地址、邮箱、电话；合同、保单或客运条款中的约定送达；拟发送文书类型（索赔、保存、和解催告等，本窗不写正文）；诉讼外还是已立案诉讼送达；法域。

口头「已经送到」「微信已读就算到了」「后天截止」只登记 `S#`。不得写入到达状态或唯一截止日。

同时掌握双方秘密，或受害人与侵权人、保险人同时交材料争同一份送达方案：`整体停止`，不得以选边治愈，也不得改走负触发去出渠道表。受害人已开口且委托范围就是送达设计、且未掌握对方秘密时，可推定主张方立场。只要同时掌握双方秘密，无例外整体停止。提出伪造签收、倒签邮戳、补造回证、把本稿写成此前已发出：第一次提出即整体停止，不以「坚持」为门槛。

## 来源和判断状态

编号：`S#` 单方陈述；`C#` 约定送达条款；`D#` 地址、回证、报文头；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口；`E#` 送达设计；`V#` 版本。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。到达状态只用 `草案`、`待发送`、`已发送待证明到达`、`已到达`、`停止`。技能正文中的条号是检索锚点，不是已核验 `L#`。本任务默认 `草案` 或 `待发送`，不执行发送。

## 使用 Lawyeah MCP

宿主可调用时：

- `search_law` 核验将被写入 `L#` 的现行规则：诉讼外意思表示到达（对话知道内容、非对话到达；数据电文进入指定系统或相对人知道／应当知道进入其系统）；向义务人提出履行请求且到达才构成中断候选；诉讼电子送达须受送达人同意，不得套到诉讼外否则到达停止；公告送达以穷尽其他方式为前提，不得任意用于诉讼外催告；留置是诉讼送达规则，不得写成诉讼外已留置到达。技能正文条号不是 `L#`。噪声：已失效《侵权责任法》、已读即到达、诉讼电子送达须约定否则诉讼外到达停止、公告或留置任意可用于诉讼外、对保险人到达即中断对侵权人、已读或发送成功起算唯一截止日。不可用则到达规则、中断效力和公告／留置字段停止。
- 已有真实 `regulation_id` 且宿主暴露 `get_law_detail` 时，核验将改变到达、中断或渠道效力的正文再写入 `L#`。不得编造 `regulation_id`。
- `search_practiced` 补已读不等于到达、对保险人到达不当然中断对侵权人、拒绝签收须另证、约定地址变更未通知风险的实务反例。
- `search_case_by_fact` 只比较事实差异与翻转条件，不写成必须已到达或必须未中断。

工具不可用时继续收件人、地址和 `E#` 结构；到达、中断、公告／留置字段停止。不得凭记忆写已读即到达、唯一截止日或诉讼外公告已完成。

## 判断节点

执行顺序和停止条件以 [送达设计方法](references/method.md) 为准。这里只列入口，不代替节点。

### 1. 分流、立场、禁止与不关窗

工伤三段分流，第三人催告送达可留。双方秘密或伪造签收第一次停。错误主张不关窗。已立案法院送达负触发。

### 2. 文书类型与诉讼内外分列

本任务不写正文。索赔、保存、和解催告分属其他原子。诉讼外到达与诉讼电子送达须同意分列，不得互套。

### 3. 收件人、约定渠道与备份渠道

一行一个收件人。约定渠道须定位。变更地址未通知待核。不得共用一个地址冒充全部到达。

### 4. 回证、到达状态与失败升级

已读最高 `已发送待证明到达`。拒绝签收记录经过。公告、留置不得任意建议。本任务不执行发送、不补造回证。

### 5. 时效中断接口与不可逆

分相对人。对保险人到达不当然中断对侵权人。本任务不计算截止日。倒签第一次停。

## 停止与安全

- `整体停止`：立场或授权不明；双方秘密未解；受害人与对方同时交材料争同一份送达方案；提出伪造签收、倒签邮戳、补造回证、把本稿写成此前已发出、威胁或违法取证。整体停止优先于负触发。不以「坚持」为门槛。第一次提出即停。不得选边治愈。
- `字段停止`：约定送达条款效力、到达规则、中断效果、公告或留置条件未核验。用户要把已读写成已到达、写死截止日或今天必须发出则该格停止，窗口不关；闸未开仍不出 `E#` 发送前终稿。
- `目标停止`：主目标变为通知正文、法院诉讼送达实施、公证实施终稿、时效截止日终稿、起诉状或应诉。已读即到达不在目标停止。

禁止指导伪造签收或倒签邮戳。不执行发送。不补造回证。不给胜诉率。不保证中断时效。不选定法院。不计算唯一截止日。
