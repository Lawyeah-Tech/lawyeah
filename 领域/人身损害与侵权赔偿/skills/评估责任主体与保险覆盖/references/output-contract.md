# 输出合同

按触发结果选择交付形状。禁止在缺输入时用情景数字或虚构名称填满栏目。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向 |
| 节点 0 整案转出 | 第 1、2、10 节。不填第 4–9 节实体 |
| 整体停止 | 第 1、10 节。禁止主体表、保险数字、策略。双方秘密或授权不明时，整体停止优先于负触发，不得改走起诉原子完成选边 |
| 正触发 | 下列十节均出现；字段停止的节保留表头，单元格填 `依据不足，无法形成结论` 或 `待核` |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。

## 1. 触发、单方立场、授权与成果状态

必须写明代表哪一方、授权范围、冲突筛查。用户要唯一被告或限额内必得额时，成果状态不得写成已形成。

## 2. 来源登记与 MCP 调用表

`S/D/A/R/C/L/I/G/PTY/INS/V`。MCP 未调用也留一行。`L#` 只登记已核验规则；技能内条号不得直接抄进 `L#`。

## 3. 受害人、法定代理人与已知名称变体

无／限制行为能力受害人必须出现法定代理人行。

## 4. 责任主体表

每个 `PTY#` 含角色假设、关系事实、形态候选、支持不利、判断、转介和待核。不选定唯一义务人。租赁借用必须分列使用人与所有人，不得把所有人写成当然连带。

## 5. 形态候选与追偿接口

补充责任必须可见执行顺序（就直接侵权人财产强制执行后仍不能履行的范围）。禁止在本任务落连带／按份终局。派遣必须分列用工单位与派遣单位。

## 6. 交强险、商业三者与未投保接口

必须可见：交强险是否打开；保险人应当共同被告红旗；有责／无责分项待核；多车多份分列。数字未核验则停止。精神损害优先只保留接口。禁止「限额内必得」。开门杀不得写成保险人可因乘车人身份拒赔。

## 7. 不得列入或依据不足的主体

盗抢案的原车主不因所有权当然列入。登记车主在转让交付后不当然列入。

## 8. 最强反方

包括：不是本车外受害人；工作人员非执行工作任务；场所已尽安保；出借人无过错；乘车人不是被保险人（须用开门杀规则检验，不得直接采信）。

## 9. 风险与下一步

追加、调取保单、转介交通专项、共同侵权、用人者、起诉或保险索赔、弃权审查、救助基金。不写诉状。鉴定闸、先予执行只转介。

## 10. 缺口、停止项与提示

本成果不是保单理赔决定、立案名单终局或交强险分账终稿。
