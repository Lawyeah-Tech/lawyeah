# 评估工伤与第三人侵权竞合

## 任务目标

在明确、无利益冲突的单方立场下，形成“工伤与第三人侵权竞合分账”：民事请求与工伤待遇各自程序入口、医疗费等项目重复禁止、可并行项目待核、交接劳动包条件。不办理工伤认定、劳动能力鉴定或工伤待遇。

`depends-on` 为空。工伤三段整段转劳动。

## 工作边界

正触发：工作中或上下班途中因用人单位以外的第三人导致人身损害，需要比较民事侵权请求与工伤待遇两套成果。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 主成果仅是工伤认定、劳动能力鉴定或工伤待遇测算、且无需第三人分账（转劳动）。用户同时要认定和第三人分账：本窗正触发，认定段转劳动，分账留本窗；
- 无法定工伤统筹关系、纯个人之间劳务（转 `评估提供劳务受害`）；
- 只要向第三人索赔的总体侵权总图且无需分账（转 `评估人身侵权责任`）；
- 只要测算终稿（转 `测算人身损害赔偿`）；
- 诊疗过错主轴（转医疗医药）；
- 海事船舶事故（转海事）。

本任务不代办工伤认定，不出具工伤待遇结论，不给胜诉率，不定残，不选定法院，不编唯一截止日。

## 建立工作坐标

确认：使用者与授权；单方立场；受害人与用人单位关系材料；第三人是否属于用人单位以外；事故是否发生在工作时间工作场所或上下班合理路径；是否已申请工伤认定；民事协商或诉讼状态；医疗费支付方；法域。

同时掌握双方秘密或未解利益冲突：`整体停止`，不得以选边治愈，也不得改走负触发去办工伤或出民事终稿。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 劳动关系或劳务材料；`R#` 工伤认定或事故文书；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口；`Q#` 分账项目；`V#` 版本。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。项目状态只用 `民事可主张`、`工伤入口转劳动`、`禁止双领`、`并行待核`、`无法估计`。技能正文中的条号是检索锚点，不是已核验 `L#`。

## 判断节点

执行顺序和停止条件以 [竞合分账方法](references/method.md) 为准。这里只列入口，不代替节点。

### 1. 用工关系与整案转出

应参加工伤统筹的劳动者：工伤三段转劳动，第三人分账可留。个人劳务负触发一句。同事执行工作任务：竞合默认不打开，先用人者责任。

### 2. 第三人与事故场景

固定第三人是否属于用人单位以外。上下班第三人侵权民事可留，工伤申请仍转劳动。

### 3. 项目分账与重复禁止

医疗费等实际支出禁止双领。残疾赔偿金与一次性伤残补助金、误工费与停工留薪是否并行须核验。

### 4. 程序入口并行

民事起诉与工伤认定可并行，互不等待。禁止写成必须先认工伤才能起诉第三人。期限分列。

### 5. 交接劳动包与输出纪律

交接只含用工事实、事故时间地点、已付清单。不代写工伤申请。不预测伤残等级。

## 停止与安全

- `整体停止`：立场或授权不明；双方秘密未解；用户提出同一张医疗费向工伤基金和第三人全额双领，或隐瞒第三人赔偿以套取工伤基金；伪造劳动关系。整体停止优先于负触发。不以「坚持」为门槛。
- `字段停止`：用工关系性质、第三人身份、已付医疗费来源或现行分账规则未核验。
- `目标停止`：主目标变为工伤认定申请、劳动能力鉴定、工伤待遇测算、侵权总图终稿、测算唯一总额、起诉状或鉴定申请。

禁止指导隐瞒第三人赔偿套取基金。不给胜诉率。
