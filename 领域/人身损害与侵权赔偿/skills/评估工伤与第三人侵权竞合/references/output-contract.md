# 输出合同

按触发结果选择交付形状。禁止写成一律双赔或一律互抵。禁止代办工伤认定。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向，不填实体十节 |
| 节点 0 整案转出（主成果仅工伤三段且无需第三人分账） | 第 1、2、10 节。禁止分账矩阵和待遇测算。劳务受害走负触发一句，不走本行 |
| 整体停止 | 第 1、10 节。禁止双领方案。双方秘密、伪造劳动关系或指导套取基金时，整体停止优先于负触发 |
| 正触发且可分账 | 下列十节表头均出现；未核验的并行项目填 `并行待核`；字段停止的单元格填 `依据不足，无法形成结论` 或 `待核`，禁止省略后改填一律双得 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。每个 `Q#` 必须带项目状态。

## 1. 触发、单方立场、授权与成果状态

写明竞合是否打开及受限字段。双方秘密未解不得进入“部分形成”。

## 2. 来源登记与 MCP 调用表

用工材料、事故文书、已付凭证必须编号。`L#` 不得直接抄技能内条号。

## 3. 用工关系与第三人识别

劳动关系待核时并行情景，不写成已认定工伤。事故认定书与工伤认定决定分列。同事执行任务：竞合默认不打开。

## 4. 两套程序入口

民事与工伤分列，互不等待。禁止写成必须先认工伤才能起诉。期限不混算。

## 5. 逐项分账矩阵

医疗费重复禁止可见；误工与停工留薪分列；残疾赔偿金与一次性伤残补助金分列。金额只作接口或 `并行待核`，禁止本窗填待遇额或民事小计。未知不写零。禁止用劳鉴等级填民事残疾金。

## 6. 已付与追偿接口

基金、用人单位、第三人、医保分列。基金已付从受害人向侵权人主张的该部分扣除，追偿主体是基金，禁止写成第三人责任消灭。

## 7. 交接劳动包最小材料

只交接，不代办，不填待遇表。

## 8. 证据缺口

用工凭证、发票原件、支付方。民事评残与劳鉴分轨。

## 9. 风险与下一步

禁止双领同一票据；可逆性说明。鉴定闸关闭不得转介启动民事评残。

## 10. 缺口、停止项与提示

须列对方最强解释（必须先工伤、一律双得、一律互抵、基金已付则第三人免责、同事即第三人）与证据缺口。

本成果不是工伤认定书、待遇测算或民事唯一总额。
