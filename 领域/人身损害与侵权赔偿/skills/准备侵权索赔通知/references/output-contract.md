# 输出合同

按触发结果选择交付形状。发送闸未打开不得交付发送前终稿。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向 |
| 发送闸关闭或节点 0 整案转出 | 第 1、2、10 节：关闭理由和补证 |
| 整体停止 | 第 1、10 节。禁止正文、金额、催告策略。双方秘密或倒签时，整体停止优先于负触发 |
| 正触发且闸打开 | 下列十节均出现；未知金额单元格不得填零 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。通知状态保持 `草案` 或 `待发送`，除非用户提供送达事实。

## 1. 触发、单方立场、授权与成果状态

发送闸是否打开。

## 2. 来源登记与 MCP 调用表

`S/D/A/R/C/L/I/G/Q/V/E`。MCP 未调用也留一行。`L#` 不得直接抄技能内条号。

## 3. 发送闸与收件人

分列拟收件人及待核。不选定唯一义务人。

## 4. 项目表

未知不写零。禁止双计被扶养人生活费与残疾／死亡赔偿金。未稳定不得写确定伤残金额。

## 5. 发送前通知正文

标注草案／待发送。逐句可回链。禁止倒签、罪名、终局比例、逾期视为同意。

## 6. 到达设计

渠道、回证、失败升级。已读不等于到达。本任务不执行发送。

## 7. 时效中断与不可逆提示

分相对人。发错主体、对保险人到达的效果必须可见。

## 8. 最强异议与应对要点

不认责、主体错误、金额虚高、重复受偿、保险弃权、本车人员除外。

## 9. 风险与下一步

不执行发送。转介精算、鉴定、主体保险、弃权审查或起诉。

## 10. 缺口、停止项与提示

本成果不是对方认责、不是起诉状，不保证中断时效。
