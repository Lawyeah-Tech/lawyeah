# 发函方法

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。通知状态保持 `待发送`，除非用户另行提供送达事实。技能正文中的条号是检索锚点，不是已核验 `L#`。

---

## 节点 0　专项分流与发送闸

**整案转出或负触发**（闸关闭时只交第 1、2、10 节，不出发送前终稿）：

| 信号 | 处理 |
| --- | --- |
| 工伤认定或待遇申请为主成果 | 整案转劳动；对第三人的民事索赔函可留 |
| 医疗损害鉴定申请为主成果 | 整案转医疗 |
| 海事 | 转海事 |
| 只要评估、主体表或精算 | 负触发 |
| 综合提问夹带管辖、金额终稿 | 转 `评估人身侵权责任` |
| 义务人无法指明且用户拒绝列“待补收件人” | 发送闸关闭 |
| 出现一次性了结、权益转让、概括弃权 | 闸可部分打开，但必须红旗并转介 `审查保险一次性了结弃权`；禁止写“先发函再当没签过” |
| 双方秘密或倒签、威胁曝光 | 整体停止 |

发送闸打开条件（同时满足）：

1. 单方主张方立场和授权清楚，无未解双方秘密；
2. 至少一名拟收件人有可回链名称或送达地址线索；
3. 侵害事实与人身损害有材料或可标注为单方陈述的具体事件；
4. 用户确认本次主成果是索赔通知而不是诉状或鉴定。

仅有“先发函压一压”、对方未回复或“还不清楚找谁”：不得打开闸。

---

## 节点 1　收件人与项目

收件人分列行为人、用人者、场所、教育机构、交强险保险人、商业三者保险人，不把未评估的主体写成“依法必须承担”。登记车主在借用场景不得写成当然连带收件人终局，只可列为待核收件人并提示转介 `评估责任主体与保险覆盖`。

对保险人发函须区分交强险与商业三者。不得把本车人员请求写成当然交强险请求。开门杀致第三人：保险人不得以乘车人不是被保险人拒收该请求的抗辩，只作正文注意事项，不写成保险已应当赔付。道路交通事故中交强险保险人可作为收件人（应当共同被告红旗），但本任务不写起诉状。

项目表固定列：`项目｜已支持事实｜金额状态｜来源｜互斥／已付｜是否写入正文`。

- 已核实金额才可写入确定数字；
- 情景金额须标明假设；
- 无法估计写“另行核算／鉴定后主张”，禁止补零；
- 治疗明显未相对稳定：残疾赔偿金、护理依赖、误工截止不得写入确定数字或十级系数；
- 被扶养人生活费不得与残疾／死亡赔偿金写成两笔确定请求相加；
- 精神损害不得编造“依法不少于五万元”；
- 医保、工伤基金已付医疗费：正文提示避免重复主张，细节转测算原子。

事故认定书只作事实叙述附件，不得在正文写成民事终局比例或“依法按全责赔偿”。

---

## 节点 2　正文纪律

正文只包含：当事人与事件中性叙述、已支持损害、请求项目、答复方式和期限（期限未核验则写“请在合理期限内书面答复”并标待核）、保留诉讼和鉴定权利、附件清单。

禁止写入：刑事罪名认定、责任比例终局、保证胜诉、虚假票据金额、倒签日期、对未成年人或无关第三人的隐私、威胁曝光或骚扰、“逾期视为同意赔偿”、伤残等级预测。

逐句回链 `S/D/R/C`。用户坚持写入禁止项：该句停止，必要时整体停止。

---

## 节点 3　到达设计

每次尝试预列：实施人、文本版本、渠道、地址、回证、失败升级。优先书面可核验渠道。电子送达须有约定或对方明确接受，否则不得写成已经到达。微信已读不等于到达。

本任务不执行发送，不补造回证。发送后用户回报送达事实，状态才可改为 `已发送待证明到达` 或 `已到达`。

检索锚点：诉讼时效规定关于书面主张到达的规则。数据电文须到达或应当到达。

---

## 节点 4　时效与不可逆

到达可能构成向**该收件人**主张权利，从而成为对该相对人的时效中断候选。须在成果中明示：

- 未保留回证则中断可能无法证明；
- 发错主体不当然中断对真正义务人的时效；
- 对保险人的到达不当然中断对侵权人的时效；
- 答复期不是除斥。对方沉默不等于认责。不得写“逾期视为同意赔偿”。

拟发送日不得早于实际拟制日期。用户要求倒签：整体停止。
