# 办理和解执行力补强

## 任务目标

在明确、无利益冲突的单方立场下，比较司法确认、调解书、公证赋强路径并列出材料与失败分流。单独和解无执行力必须明示。

`depends-on` 为空。接受用户、律师、机关或其他来源的等价事实、测算和证据清单。

## 工作边界

正触发：和解条件已有或将有协议，用户要补强执行力，主成果是路径比较和材料，而不是再谈条件或普通执行。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 只要和解协议正文；
- 已有生效判决只要执行；
- 破产和解；
- 未成争赋强条款设计（可转公证准备但须成争债权明确）；
- 假装已有执行力去申请执行；

单独和解无执行力必须明示。不保证法院确认或公证处赋强。

## 建立评估坐标

确认：使用者与授权；立场；和解文本；是否已有诉讼或仲裁；双方是否愿意共同申请；债权是否明确无对待给付；法域。

同时掌握双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`S#` 陈述；`D#` 和解文本；`A#` 承认；`R#` 文书；`C#` 条款；`L#` 规则；`I#` 判断；`G#` 缺口；`Q#` 路径比较；`V#` 版本；`E#` 协议签署凭证。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》《担保法》及其解释当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验民诉特别程序司法确认、诉讼调解、仲裁调解、赋强公证条件。工具不可用时继续路径比较；可行性结论字段停止。

## 五个判断节点

执行顺序和停止条件以 [方法](references/method.md) 为准。这里只列入口，不代替节点。

### 节点 1　无执行力明示

单独民事和解协议不能直接作为执行依据。必须写明。

### 节点 2　路径比较

诉中调解书、仲裁调解书、人民调解司法确认、赋强公证。各有管辖、自愿、明确性条件。

### 节点 3　材料

协议、身份、无恶意串通损害第三人声明、担保人是否加入。

### 节点 4　失败分流

法院不予确认、公证拒绝赋强：回到普通诉讼或仲裁。

### 节点 5　担保

未加入补强文书的保证人，执行力通常不及于其。

## 停止与安全

- `整体停止`：立场或授权不明；利益冲突未解；基础主体或文本无法建立；用户坚持伪造流水、隐匿还款、暴力催收、伪造送达或违法取证。
- `字段停止`：法域、日期、文书送达、动态规则未核验。
- `目标停止`：主目标已变为本任务以外的文书或总图。
