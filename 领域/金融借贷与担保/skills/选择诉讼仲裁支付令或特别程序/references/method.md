# 评估方法

判断只用三态。不写完整申请。不得在有实质争议时推荐支付令或特别程序充快车道。

## 节点 0　分流

已决定起诉／仲裁／支付令／特别程序：转对应原子。海事、破产：转出。只要管辖条款：论坛原子。

## 节点 1　互斥表

仲裁条款有效：主位仲裁。支付令由法院发出，与仲裁冲突。特别程序与普通诉讼作为主成果互斥，但特别程序驳回后可诉讼。

## 节点 2　支付令适配

债权人请求债务人给付金钱、有价证券，债权债务关系明确、合法，可申请支付令。对待给付、担保真实性争议、本金交付争议：不支持支付令主位。

## 节点 3　特别程序适配

见实现担保物权原子的条件。有设立、范围、清偿争议：不推荐唯一走特别程序。

## 节点 4　诉讼／仲裁适配

需列保证人、确认合同效力、复杂利息：诉讼或仲裁更适配。成本比较只列项目（受理费、保全、周期不确定性），不编造必胜或必快。

## 节点 5　输出

比较矩阵＋转介。不写申请书。

---

## 判断纪律与 if/then

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然免责、必然全额支持或唯一必得总额。未知金额不写零。

`search_law` 返回已失效《合同法》《担保法》及其解释时记为噪声，不得写入 `L#`。MCP 未安装、无结果或冲突时，不拒绝执行；依赖未核验规则的法律结论、期限或机关路径字段停止。

### 节点执行顺序

1. 先专项分流：一般合同、并购交割、破产申报、未成争审查起草、刑民定罪主轴，命中则整案转出或搁置，不填本任务实体终局。
2. 再固定主体、文本版本、程序文书与送达。口头转述、“已读”、截图不得写成已受理、已送达或期限已起算。
3. 每个请求或抗辩独立建 `Q#`：法律效果、成立条件、支持与不利事实、控制方、最强反方、主备位、互斥。禁止合成一笔“贷款权益”或“担保权益”。
4. 期限分类型：诉讼时效、保证期间、除斥、约定催告期、程序异议期各占一行，禁止混算或输出唯一截止日充作法律意见。
5. 金额分项：本金、利息、罚息、复利、费用、已还。民间借贷 LPR 四倍不得套用金融机构贷款。

### if / then

| 条件 | then |
| --- | --- |
| 立场或授权不明，或同时掌握双方秘密 | 整体停止策略输出，先澄清代表哪一方 |
| 用户坚持伪造流水、隐匿还款、暴力催收、伪造送达或违法取证 | 整体停止，不提供规避方案 |
| 主目标已变为其他原子的文书或总图 | 目标停止，按路由表转介 |
| 关键日期、送达或动态规则未核验 | 字段停止，并列情景，不选对用户最有利的一天 |
| 有效仲裁协议未经排除，用户要求直接起诉 | 不得写应起诉；转论坛或仲裁入口 |
| 破产已受理而用户要个别清偿、执行或申报 | 标红旗，申报转破产领域，本包不做申报 |
| 未成争只要改合同或出稿 | 审查起草本窗搁置，只说明不实施 |
| C 端相邻商品被点名 | 只分流，不回改、不降成大众包 |

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因对方控制而推定材料存在或内容有利。下一步按期限灭失、易失证据、能否改变 `Q#`、可逆性排序。禁止指导伪造、隐匿、威胁或违法取证。
