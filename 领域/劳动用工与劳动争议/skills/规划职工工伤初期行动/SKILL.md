# 规划职工工伤初期行动

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 任务目标

为职工侧形成“工伤初期行动与证据保障方案”，并行管理紧急医疗、事件与工作关联假设、主体和角色、单位申请期、职工侧申请期、机关收件补正受理和决定时钟、送达效力、合法证据和治疗保障。

`depends-on` 为空。接受用户、单位、医院、交警、机关、律师或其他合格来源的等价材料和程序结果，不要求先运行关系识别 Skill。

## 工作边界

事故、突发疾病或职业暴露已发生且主要目标仍是职工侧初期保障时正触发；申请已经提交、机关已经收件或受理不自动终止本任务。只作医学／职业病／伤残／技术结论、只制作可提交认定申请包、鉴定、待遇测算、复工、行政救济、仲裁或第三人赔偿文书均负触发。固定输出 `触发判定：负触发，未启动本任务`，只说明路由和最小输入，不代做相邻成果，不填写成果状态。

本任务不确认构成工伤、责任单位、伤残等级、待遇金额或机关结果，不实际发送、申请或调取。

## 紧急优先与坐标

优先顺序：紧急救治和脱离危险；职业暴露处置；保存医疗事故基础记录并通知适当主体；固定角色、单位和事件事实；建立三组时钟；合法证据及费用保障；再路由正式申请、鉴定、待遇或救济。

法律分析不得延误急救。只记录医疗机构、职业病诊断鉴定、交管或事故调查机关载明内容，不自行诊断或定责。

## 来源、角色和程序状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`R#` 医疗、交管、行政或裁判文书状态；`L#` 运行时已核验规则；`P#` 已读取并准入的等价包；`I#` 条件判断；`G#` 缺口；`V#` 行动方案版本；`E#` 真实通知、提交、收件、补正、受理、决定或送达证据。

角色必须分栏：使用者、受伤职工、法定申请人、代理人、实际提交人、接收机关／人员。一般授权不把代理人变成法定申请人，窗口收件人员不等于决定机关。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。程序状态按 `未提交 → 已提交/待核收件 → 已收件 → 补正中/待受理决定 → 受理或不予受理 → 调查/决定时钟 → 决定作出 → 待送达 → 分对象已送达 → 效力/救济待核`，不得跳步。

## 使用 Lawyeah MCP

宿主实际注册且可调用时，使用 `search_law` 核验认定、申请和期限规则，使用 `search_practiced` 补充多主体与证据方法，特殊事故用 `search_case_by_fact`，明确筛选条件用 `search_case_by_filter`。本候选不声明正式依赖，不假定医院、交警、人社或单位系统取数能力。

调用状态只用 `not-registered`、`permission-denied`、`error`、`no-result`、`partial`、`conflict`、`verified-result`，记录工具、时间、最小查询、请求标识、来源审查、覆盖和恢复条件。动态期限来源不可用时，医疗、事实、角色、证据和状态计划继续，精确截止日字段停止；无结果不证明不存在规则。来源包只在实际读取和准入覆盖内使用。

## 十个判断节点

### 1. 紧急状态与专业边界

记录救治、住院、持续危险、职业暴露和专业意见。存在急救需要时先就近取得合格救治，不等待材料齐全。照片不支持伤残等级或医学结论。

### 2. 事件与工作关联假设

按时间、地点、活动、任务、指令、路线／外出目的、伤害机制、替代解释和来源建时间线，分别列 `可能纳入`、`可能排除`、`信息不足`。工作场所、单位口头承认、无合同或未参保均不能单独定性。详见 [初期方法](references/method.md)。

### 3. 主体与责任候选

列全部招聘、管理、发薪、参保、派遣、外包、转包、挂靠、平台和第三人主体，分别作为沟通对象、材料控制方和责任候选；不由事故或关系单项事实倒推责任。

### 4. 申请资格与代理权限

分别核使用者、职工、近亲属、工会、代理人和实际提交人；死亡、失能或工会场景核身份、关系／组织资格和授权范围。

### 5. 单位申请期及批准延长

记录起算事实、基础期间、单位提交、报请延长、特殊情况、批准机关、批准文书、批准期限、实际提交和逾期风险。报请不等于批准，未核规则或文书不生成新截止日。

### 6. 职工侧申请期及条件化不计算

记录法定申请人、基础起算、基础终点、耽误起止、法定事由候选、非本人原因证据、机关／法院确认、条件化不计算天数、情景截止和实际提交。不得改写为一般“中止／中断”或自行宣布成立。

### 7. 收件、补正与受理

收件只证明收到材料；补正通知不等于拒绝，补正提交不等于受理。分别记录收件凭证、一次性书面补正内容、补正提交、受理／不予受理文书、日期和救济告知。

### 8. 决定期限及中止恢复

只在受理后建立决定时钟，记录适用期间依据、等待的司法／行政结论、中止文书、通知、结论作出、恢复核验和剩余时长。不得把机关决定期中止套到单位或职工申请期。

### 9. 决定、送达与效力

决定作出和送达分开，对职工／近亲属、单位及其他对象逐一记录渠道、凭证和日期。无送达凭证不推定救济期间起算；效力和后续路由按具体文书核验。

### 10. 证据与治疗保障

分类保存医疗、事件、工作关联、主体链、沟通程序、证人、费用和治疗保障。每项写执行人、时点、合法权限、控制方、备份和停止条件。不侵入系统、不诱导证言、不补造排班合同事故或修改医疗记录。申请后仍继续医疗、票据、补正、关系证据和时钟管理。

## 停止与安全

- `整体停止`：法域、使用者／授权或事故基本时空无法建立；用户坚持伪造任务、排班、合同、事故或证言，侵入系统，或要求本任务作医学、技术、交通责任和机关结论。
- `字段停止`：主体链、资格、日期、动态规则或程序文书缺失；不影响紧急医疗和合法保全。
- `目标停止`：主要目标转为正式申请包、鉴定、待遇、救济或第三人文书时负触发。

首次伪造要求立即拒绝并邀请用真实排班、就医和沟通材料重启；明确接受后恢复；坚持时整体停止，不给统一证词技巧。

## 交付

严格按 [输出合同](references/output-contract.md) 固定十四节交付。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`；这只表示初期方案状态，不表示工伤认定。

提交前检查：紧急事项在前；六类角色不混；单位期、职工侧期和机关期不合并；延长未当批准；不计算未擅定；收件未当受理；补正未当拒绝；作出未当送达；不同对象分开；医学技术不越界；证据合法；不保证认定。路由见 [边界](references/routing.md)。
