# 原子 Skill 选择方法

## 一、先识别成果

先问用户这一次要拿到什么可独立验收的成果，而不是只按法律名词匹配：

- 关系和责任主体识别意见；
- 可签署劳动合同；
- 规章制度及民主公示实施包；
- 薪酬工时休假审计；
- 可复核权益测算；
- 单位或劳动者退出方案；
- 单位解除终止实施包；
- 职工工伤初期行动方案；
- 劳动争议总体评估；
- 综合用工合规审计、用工模式比较、招聘审查、入职包、劳动合同审查、续订决策、劳动条件变更；
- 离职结算测算、社保或公积金整改与追缴、社保待遇损失、特殊保护员工行动；
- 绩效改善、场所调查、纪律处分、协商解除、裁员安置、竞业设计／追究／挑战；
- 劳动尽调、员工转移、单位工伤响应与认定申请、职工认定申请、认定调查应对、工伤待遇测算与请求、行政救济分流；
- 在职权利诊断、证据建卷、争议和解、仲裁申请／答辩／庭审、一审起诉／答辩、上诉／二审答辩、单位撤销终局裁决、执行与执行应对。


## 二、再确认上下文

只确认会改变入口的最小信息：

1. 使用者及代理立场；
2. 事项已经发生还是未来安排；
3. 中国大陆工作地和目标时点；
4. 当前程序阶段；
5. 用户已有材料和既有结论；
6. 是否需要文件、测算、行动还是分析意见。

## 三、处理混合请求

一个请求包含多个成果时：

1. 列出每项可独立验收的成果及对应入口；
2. 只问一个问题：`这次要先取得哪一项成果？`；
3. 用户回答前不指定主要 Skill，不暗示先后顺序；
4. 用户只询问是否必须按某顺序调用时，先回答“不必须”，再询问当前要启动哪一项；
5. 用户确认后只启动所选入口，其余保留为独立任务；
6. 只有目标 Skill 明确声明必需结果时才提示依赖，并接受律师、机关、用户材料或其他来源提供的等价成果。

## 四、停止

目标成果、立场或法域不足以区分入口时，只追问一个最能改变选择的问题。用户目标属于相邻领域时，说明劳动专项边界并转到相应领域，不继续代做。
