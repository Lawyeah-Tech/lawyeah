# 识别劳动关系与责任主体

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 任务目标

基于中国大陆已经发生的实际用工，形成一份“主体关系与劳动用工责任主体识别意见”。分别识别：

- 候选劳动关系及期间；
- 劳务、承揽、派遣、外包、自主经营等替代解释；
- 派遣、违法转包、挂靠、关联单位等场景中的特定用工主体责任；
- 用户明确提出且属于本任务所必需的报酬、社保和工伤保险责任主体候选。

`depends-on` 为空。接受用户、律师、机关或其他来源提供的等价材料，不要求先运行其他 Skill。

## 工作边界

处理既有用工事实的主体、关系和责任主体归属初判。

不处理：

- 尚未实施的直营、派遣、外包等未来模式选择；
- 欠付项目或金额计算；
- 是否构成工伤、工伤待遇项目或金额；
- 社保待遇核定或损失赔偿结论；
- 仲裁、诉讼、工伤申请、社保投诉或整改方案；
- 仲裁或诉讼当事人列名、管辖、时效计算、请求项目及顺序；
- 整改通知、证据保全通知、协议或程序文书正文；
- 境外当地劳动法、税务、公司治理、侵权或其他独立专业成果。

若用户目标属于排除事项，不启动本任务，也不填写成果完成状态。固定输出 `触发判定：负触发，未启动本任务`，再说明路由原因和相邻任务所需输入；不继续代做相邻成果，也不建立固定任务顺序。

## 建立分析坐标

先确认：

1. 使用者角色、代理立场和本次问题；
2. 中国大陆实际工作地、目标时点和分段工作期间；
3. 全部自然人及组织主体，不只记录用户点名的单位；
4. 谁招聘、签约、排班、派活、考核、奖惩、决定报酬、支付报酬、缴纳社保、提供场所工具、承担经营风险并决定退出；
5. 合同、工资社保、规则、工作记录、业务链协议及已有机关或裁判文书；
6. 超龄或退休、外籍许可、学生实习、事业身份、平台用工等会改变适用规则的事实。

只追问会改变主体、关系、责任主体或停止状态的最小事实。基础主体、法域和目标时点无法建立时，使用 `因停止条件未形成`，不得用概率措辞填补。

## 信息来源与事实回链

不得把用户陈述或材料表面文字称为“已确认事实”。统一编号：

- `S#`：用户单方陈述，未核验；
- `D#`：材料表面载明，真实性与完整性未核验；
- `A#`：当前材料显示双方一致或对方承认；只表示当前陈述状态，不当然构成程序法上的自认或免证事实；
- `R#`：行政决定、生效裁判等既有认定；
- `I#`：基于前述信息的分析推断；
- `G#`：会影响结论的事实或材料缺口；
- `L#`：运行时取得并完成时效、层级和相关性核验的法律来源。

记录 `A#` 的发生场景、范围、撤回情况及是否属于调解或和解妥协。记录 `R#` 的机构、文书类型、当事人、认定范围、生效、撤销和救济状态。

每个关系或责任主体格必须引用来源编号，列支持事实、相反事实、规则状态和受限字段。详细格式见 [输出合同](references/output-contract.md)。

## 使用 Lawyeah MCP

下列工具只有在宿主实际注册并能调用时才使用；本候选不声明正式工具依赖：

- `search_law`：关系或责任主体判断依赖目标时点、地区或专门现行规则时使用；
- `search_practiced`：多主体、平台、派遣、外包或替代解释复杂时补充实务方法和反例；
- `search_case_by_fact`：用户明确需要地区实践或事实高度特殊时核对类案；
- `search_case_by_filter`：已知法院、年份、案由等精确条件时补充筛选。

只从用户材料和已经编号的信息构造最小查询，不补造事实。先校验结果的法域、层级、时效、相关性和完整性；无结果不等于没有法律依据或不存在关系。

若 `search_law` 未注册、无权限、报错或没有足以核验现行规则的结果：

- 仍可完成主体图、来源清单和事实结构；
- 依赖现行规则的关系或责任字段只能写 `依据不足，无法形成结论`；
- 整体不得使用 `已形成`；
- 不要求用户在对话中提供密钥或令牌，不虚构工具响应。

## 五个判断节点

### 1. 建立主体与候选关系图

先独立核验劳动者和候选用人单位的法定主体资格。主体资格是适格门槛，不与从属性强弱加权；不适格招聘方不能因管理较强而自动成为劳动关系主体，应继续检查实际适格单位或特定用工主体责任。

按主体和时间区间建立劳动关系、劳务或承揽、平台自主经营、派遣、外包、关联单位交替或同时用工等候选解释。“不完全符合确立劳动关系情形”只可作为不构成劳动关系后的权益保障标签，不作为独立关系类型。

### 2. 核对实际履行结构

读取 [关系识别方法](references/relationship-method.md)，逐候选关系检查招聘退出、劳动管理、经济结构、组织归属、工具风险和文件表现。非劳动合同标签不能替代履行审查；除主体资格和专门规则外，不以任何单一从属性事实自动定性。

对每个候选项同时列支持事实、相反事实、替代解释和材料冲突。

### 3. 分开关系与责任主体

只对用户明确提出或主体识别不可缺少的责任建行。每行只能选择以下一个适用与触发状态，不得扩写或自造近义状态：

- `适用且已触发`；
- `适用但尚未触发`；
- `不适用`；
- `依据不足`。

这些状态描述该行写明的精确责任命题，而不是“用户提出了问题”：

- `适用且已触发`：该责任命题所需的触发事件和必要前置决定已有来源支持；
- `适用但尚未触发`：相应规则可能适用，但触发事件或必要前置决定尚未发生；
- `不适用`：有肯定事实或规则排除；
- `依据不足`：不能判断规则是否适用，或不能判断触发事件、前置决定是否存在。

`未询问`、`未提交`、`未测算`、`未知`只表示信息缺失，不能证明事件或前置决定尚未发生。只有肯定来源能够表明相应事件或必要前置决定尚未发生时，才可使用 `适用但尚未触发`；否则使用 `依据不足`。

用户提出问题、事故已经发生或候选识别任务已经启动，不等于精确责任命题 `适用且已触发`。只有规则适用所需的主体资格、业务链或关系结构、责任期间、触发事件和必要前置决定均有来源支持时，才使用该状态；其中任何一项不能判断时使用 `依据不足`。

每一责任行都必须填写判断状态，且只能逐字使用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论` 之一。不得填写 `不进入实质判断`、留空或自造占位值。责任尚未触发但仍需记录时，判断状态通常为 `依据不足，无法形成结论`；只有肯定相反事实或法定前提明确排除该责任命题时，才使用 `现有依据不支持`。

工伤场景必须把“工伤保险责任承担单位候选识别”和“认定工伤后的待遇责任”作为不同命题。事故发生不等于待遇责任已经触发；没有工伤认定时，后者只能是 `适用但尚未触发` 或 `依据不足`。

分别记录工伤认定的申请主体、申请时间、是否受理、是否已有决定及其效力。`劳动者本人未申请`、用户不知道单位、近亲属或工会等其他法定主体是否申请、未提交申请材料或决定书，均不能证明无人申请、未受理或决定不存在；没有肯定来源时使用 `依据不足`。

再分别判断劳动关系及期间、派遣或特定用工主体责任、劳动报酬支付责任主体、社保登记申报缴费义务主体、社保待遇损失专项判断前提，以及工伤保险责任承担单位候选。

不得由劳动关系自动推出全部责任，也不得由工资、工伤保险或其他特定责任反推劳动关系。未发生、未提出的责任不建行，不写成“不支持”。

### 4. 处理证据与当前用途

对每个待证事实标明主张方、基础材料和证据控制方。当事人对自己的具体主张提供证据；单位掌握管理的相关证据应由单位提供，拒不提供的后果由有权机构依程序判断。本任务只提示潜在影响，不把“尚未提交”直接视为相对方主张成立。

唯一关键材料真实性有争议且无替代材料时，只停止受影响字段；不代替机构判断材料真伪、是否构成工伤、医学或技术结论。

### 5. 特殊身份、法域和时间切片

读取 [特殊身份与路由](references/special-routing.md)。先适用特殊身份的专门判断顺序，再进入一般关系因素；不得把专门权益规则的适用事实重复用作普通劳动关系的强结论。只识别专门规则是否改变当前关系或责任主体判断，形成受限字段和路由原因；不完整代做超龄、外籍、实习、事业人事或其他专项成果。

## 停止与安全

- `整体停止`：实际工作对象或基本主体无法识别；基础法域和目标时点无法建立；用户坚持以虚假事实为前提或要求欺骗性成果。
- `字段停止`：某字段的关键地区、期间、身份、许可、触发事件或唯一关键材料缺失或冲突。
- `机关决定边界`：材料真伪、工伤认定、医学或技术结论等只能由有权机构作出。

用户要求伪造、倒签以制造虚假历史、隐藏实际管理、补造记录或统一虚假口径时立即拒绝，并要求保留原始资料、如实陈述。首次拒绝时先停止，不继续输出完整主体图、候选关系或责任矩阵；只说明停止原因，并邀请用户明确同意改为基于真实事实的识别。用户明确同意后，才可另行完成本任务；用户坚持虚假前提时整体停止。安全整体停止后不得在同一答案中继续形成实质关系字段，也不得代拟其他原子任务的完整文件。

不指导以严重侵害他人合法权益、违反法律禁止性规定或严重违背公序良俗的方法取证，不侵入账号、系统或私密空间，不安装违法监听设备。

## 交付与质量检查

严格按 [输出合同](references/output-contract.md) 交付。提交前逐项确认：

- 全部用户问题均有独立适用／触发状态和判断状态；
- `现有依据不支持` 只用于肯定相反事实或法定前提明确不满足；
- 材料缺失、冲突、规则未核验或需机构决定时使用 `依据不足，无法形成结论`；
- 主体、关系和责任没有互相倒推；
- 每项判断有来源编号、支持事实、相反事实、规则状态和受限字段；
- 没有输出金额、胜诉概率、程序步骤、当事人列名或相邻任务正文；
- 没有冒充行政机关、仲裁庭或法院确认关系或责任；
- 开头摘要、标题、表格和最终简答使用同一判断状态；字段为 `依据不足，无法形成结论` 时，只能称“首要候选”或“某候选现有支持较强／较弱”，不得写“更可能是某主体的员工”“更支持劳动关系成立或不成立”“是用人单位”“应当负责”“由某主体承担”或其他更强结论；现行责任规则未核验时始终使用“责任主体候选”；
- 整体完成状态符合已形成字段和停止字段的实际情况。
- 正触发任务的“成果完成状态”必须逐字使用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成` 三者之一，不得改写、缩写或自造近义状态。负触发只输出固定触发判定，不填写成果完成状态。
