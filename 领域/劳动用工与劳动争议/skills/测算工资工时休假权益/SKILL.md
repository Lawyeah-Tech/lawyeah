# 测算工资工时休假权益

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 任务目标

为明确单方立场、特定劳动者和期间形成“工资工时休假权益可复核测算包”：范围与时间线、参数版本、逐期间逐项目公式、应付—已付—合法扣减—差额、证据回链、冲突、情景和补件清单。

`depends-on` 为空。接受用户、律师、会计、机关或其他来源的等价事实和参数材料，不要求先运行其他 Skill。

## 工作边界

正触发于一个明确立场下对特定人员和期间的工资、加班、工时或休假项目进行测算。企业总体抽样审计、离职补偿赔偿、工伤待遇、退出合法性、总体争议请求抗辩、发薪记账和税务申报均负触发。固定输出 `触发判定：负触发，未启动本任务`，只说明原因和相邻目标最小输入，不代做相邻成果，不填写成果完成状态。

## 建立计算坐标

确认：使用者和单方立场；计算对象与关系状态；实际履行地、起止日和目标时点；待算与排除项目；岗位、工资结构、工时制度及批复；排班、实际工作、休假和变更事件；工资表、流水、收据、补发、和解与扣款；合同、集体合同、制度和参数版本。

一次运行不能同时替双方优化。用户希望唯一金额不构成补齐未知事实的授权。

## 来源、事实与计算状态

编号：`S#` 单方陈述；`D#` 材料表面载明；`A#` 当前材料显示一致或承认；`R#` 批复、决定或裁判状态；`L#` 运行时已核验法律来源；`P#` 已读取并准入的等价来源包；`I#` 判断；`G#` 缺口；`F#` 事实时间线版本；`C#` 计算明细；`V#` 工作表版本；`E#` 真实支付或履行动作证据。

每条来源记录提供者、文件／系统、形成日、期间、定位、哈希或稳定链接、真实性与完整性状态、控制方和覆盖字段。材料缺失不证明事件未发生；未知值写 `unknown`，真实零必须有肯定来源。

每个事实的“事实版本”字段只能使用 `劳动者版本`、`单位版本`、`一致版本`、`未决版本`，不得填“合同”“系统”“来源”等其他值；判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`；结果只用 `已核实金额`、`情景金额`、`无法估计`。`情景金额` 仅用于已有足够数值输入、能够代入公式得到可复算数额的命名情景；只有公式、范围、方向或不可替代数值仍未知时必须用 `无法估计`。总额只能由明细聚合。

## 使用 Lawyeah MCP

宿主实际注册且可调用时，使用 `search_law` 核验国家和地方参数，使用 `search_practiced` 核对复杂计算实务，特殊事实需类案时使用 `search_case_by_fact`，用户明确指定地区年份等筛选时使用 `search_case_by_filter`。本候选不声明正式工具依赖，不虚构业务取数或计算 MCP。

实际调用状态只用 `not-registered`、`permission-denied`、`error`、`no-result`、`partial`、`conflict`、`verified-result`，记录工具、时间、最小查询、请求标识、来源审查、覆盖字段和恢复条件。`no-result` 不等于没有地方规则；冲突未关闭时不得选更有利值。工具不可用时，事实时间线、公式结构和已核参数继续，受影响参数及金额字段停止。来源包只有实际读取并完成身份、层级、时效、法域、对象、版本和覆盖核验后才可使用。

## 五个判断节点

### 1. 范围与项目

固定对象、立场、关系状态、履行地、起止日、项目和排除项。主要目标属于企业审计、离职款项、工伤待遇或争议程序时负触发。基础法域、对象或期间不能建立时，只能 `因停止条件未形成`。

### 2. 分段事实时间线

任何会改变公式或规则的工作地、岗位、工资结构、工时制／批复、排班、休假、停工、合同制度或支付变化均开启新 `F#`。排班与实际工作、税前与税后、归属期与支付期分开。冲突来源形成并行版本，不按对某方有利静默选择。详见 [计算方法](references/method.md)。

### 3. 参数效力

每个参数记录名称、数值、用途、地区、适用期间、层级、来源、版本和冲突。标准／综合／不定时工时分别核验；审批机关、岗位、地点、周期和有效期缺失时不采用特殊工时计算。跨年度按各期规则和日历，不用当前参数追溯全部历史。

奖金、提成、津贴、计件、病假、调休和年休假先判断项目性质、条件、基数与期间，再进入公式；不得一律纳入或排除。

### 4. 逐项计算与支付核对

每个 `C#` 固定列项目、期间、事实版本、参数、数量、基数、未舍入公式、应付、逐笔已付匹配、合法扣减、差额、舍入和证据。期间和项目一旦可枚举，必须展开为“期间 × 项目”的独立明细行；例如六个月不得用一行“每月”或一个半年度公式代替六个期间行。无法归属或缺少足够付款证据的款项进“待匹配／争议”，不能计入已付、擅自抵扣或删除；现金、失败转账、冲销和和解款分别核验。

### 5. 证据、敏感性与汇总

对决定性未知量建立保守、中性、高值或其他有业务含义的命名情景，逐字说明假设，不用“最可能”掩盖证据不足。汇总区分已核实、情景和无法估计，不把区间冒充唯一法定金额。每个零值、排除项和扣减都有来源。

## 停止与安全

- `整体停止`：对象、立场、法域或期间无法建立；用户坚持补造、删除、隐匿或篡改考勤、工资、审批、付款等记录，以受污染输入制造结果。
- `字段停止`：支付或出勤冲突、特殊工时批复、地方参数、工资基数、奖金提成条件、累计工龄或休假记录缺失。
- `机关边界`：不冒充仲裁庭、法院或行政机关给出唯一法定金额或必然采纳结论。

首次选择性隐匿要求立即拒绝并保留原始资料；用户明确接受完整对账后恢复，给全部版本和情景；坚持时整体停止，不提供隐藏付款或反取证方法。
