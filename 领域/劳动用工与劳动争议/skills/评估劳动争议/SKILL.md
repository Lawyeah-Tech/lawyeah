# 评估劳动争议

## 任务目标

在明确、无利益冲突的单方立场下，形成“劳动争议总体评估矩阵”：主体和程序状态、事实时间线、逐项请求／抗辩、实体与程序入口、期限待核、金额范围与非金钱后果、证据缺口、对方最强解释和下一步决策。

`depends-on` 为空。接受用户、律师、机关或其他来源的等价事实、测算、关系意见和证据清单，不要求先运行其他 Skill。

## 工作边界

争议已经发生且用户仍需决定请求、抗辩、路线或下一步时正触发。仅关系识别、企业日常诊断、只要详细测算、完整证据建案、已决定和解、已决定仲裁申请／答辩／起诉／执行或完整程序文书均负触发。固定输出 `触发判定：负触发，未启动本任务`，说明路由和最小输入，不代做相邻成果，不填写成果状态。

本任务不生成可提交申请、答辩、起诉、执行文书或完整证据卷，不给确定胜诉率。

## 建立评估坐标

确认使用者、授权和单方立场；对方及可能责任主体；用户目标和核心事件；工作地、单位所在地和争议时点；当前协商、行政、仲裁、诉讼或执行状态；机关文书的作出与送达；对方已知主张；关键材料及缺失。

发现同时掌握双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方、材料使用权限和冲突处理。不得利用一方秘密服务另一方。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`R#` 机关或生效裁判状态；`L#` 运行时已核验规则；`P#` 实际读取并准入的等价包；`I#` 判断；`G#` 缺口；`Q#` 请求／抗辩项；`V#` 评估版本；`E#` 真实程序提交、收件、受理、送达或履行证据。

每项来源记录提供者、文件／轮次、日期、定位、哈希或稳定链接、真实性完整性、控制方和覆盖命题。材料缺失不证明请求不存在；和解妥协及承认记录形成背景、范围和撤回状态。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不使用总体胜率替代逐项判断，不把 `no-result` 写成无请求。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 使用 Lawyeah MCP

宿主实际注册且可调用时，使用 `search_law` 核验实体和程序规则，使用 `search_practiced` 补充路径与反例，特殊事实用 `search_case_by_fact`，明确地区年份案由用 `search_case_by_filter`。本候选不声明正式依赖，也不虚构案件系统、提交或查询能力。

实际调用状态只用 `not-registered`、`permission-denied`、`error`、`no-result`、`partial`、`conflict`、`verified-result`，记录工具、时间、最小查询、请求标识、来源审查、覆盖和恢复条件。工具不可用时继续事实、主体、程序文书状态和问题清单，依赖未核规则的请求／抗辩及期限字段停止。来源包只在实际读取并准入的覆盖内使用。

## 五个判断节点

### 1. 主体、关系和程序状态

先识别关系和争议对象，再建请求／抗辩。派遣、外包、平台、关联、超龄、工伤和行政征缴分别列主体假设、决定性材料和分流条件，不强行唯一化。

程序表记录机关／案号、动作、文书、作出日、收到日、送达、效力凭证、当前待办和关键日期；口头转述和截图不写成受理、生效或期限已起算。

### 2. 请求与抗辩假设

每个 `Q#` 独立列法律关系假设、提出主体、相对方、目标法律效果、成立条件、支持及不利事实、证据控制方、对方最强解释、替代主张、判断和待核。详见 [评估方法](references/method.md)。

工资工时、解除终止、社保工伤、竞业和手续办理不得合成“劳动权益”；主位、备位和互斥路径明确，不能重复计算或同时宣称成立。单位侧逐项回应对方请求，劳动者侧并列单位最强理由。

### 3. 实体与程序入口和期限

分别判断内部协商、劳动保障行政、社保征缴／待遇、仲裁、诉讼、撤销终局裁决和执行。行政办理、工伤认定鉴定和劳动争议并列分流，不能强塞一个仲裁请求。

期限只在核验前置、管辖、主体、请求类型、关系存续、知悉／终止日、中止中断和文书送达后给条件公式。关键日期冲突时建立并行情景，不给唯一截止日。

### 4. 金额范围与非金钱后果

只建立项目、性质、期间、工资／工龄／天数参数、来源、已付、未知、范围、互斥／抵扣和待专项测算接口。工资、加班、奖金、年假、补偿、赔偿、代通知金、社保损失和工伤待遇分项；未知不写零。

关系确认、继续履行、证明、档案社保转移等非金钱结果单列。复杂逐期间计算只给区间和等价输入接口，不形成固定 Skill 依赖。

### 5. 证据、反方解释和下一步

证据矩阵列待证事实、支持与不利材料、控制方、合法取得、真实性完整性、矛盾版本、最强反方解释、缺口、补证和最晚行动时点。不能因单位控制而推定材料必然存在或内容有利。

下一步按能否改变 `Q#`、避免期限灭失、保存易失证据和可逆性排序，每项记录责任人、前置、期限依据、预期改变和停止条件。医学、鉴定和技术事项只转介。

## 停止与安全

- `整体停止`：单方立场或授权不明、利益冲突未解决、基础主体或程序阶段无法建立；用户坚持隐匿、销毁、伪造、诱导证据或非法侵入系统。即使可以继续做安全的事实或证据接收，只要单方立场与授权未确认，就不得写“正触发”或“部分形成”，不得启动实体请求／抗辩评估；应使用 `因停止条件未形成`，仅列安全接收、缺口和恢复条件。
- `字段停止`：关键日期、机关文书、法域、动态参数、主体或专业前置缺失冲突；不影响其他 `Q#` 的条件评估。
- `目标停止`：主要目标已变为程序文书、详细测算、完整证据卷、和解或执行时负触发。

首次删证要求立即拒绝并要求保留完整材料；明确接受后恢复，分别标支持、不利和争议；坚持时整体停止，不给毁证或反取证方法。

## 交付

严格按 [输出合同](references/output-contract.md) 固定十节交付。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`；负触发不填写。

提交前检查：单方无冲突；每个 `Q#` 对应事实证据；不利材料和最强反方未藏；程序与期限回链文书；行政、仲裁和专项分流正确；金额范围不是精算；非金钱结果保留；没有胜率、必然受理支持或完整程序文书。边界见 [路由](references/routing.md)。
