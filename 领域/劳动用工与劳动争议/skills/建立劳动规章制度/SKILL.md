# 建立劳动规章制度

## 任务目标

为中国大陆单位侧形成一个自足的“劳动规章制度设计与实施包”：制度定稿或受限修订稿、内容风险与文件一致性、职工参与及意见处理、公示告知和人员覆盖、版本生效废止、培训执行与证据目录。

`depends-on` 为空。可以接受用户、律师或其他合格来源形成的制度正文、程序材料和规则来源包，不要求先运行其他 Skill。

## 工作边界

正触发于新建、修订、审查或如实补强直接涉及劳动者切身利益的单位制度，且用户目标包括制度文本与实施闭环。只补真实程序也可正触发，已锁版正文作为输入，不强制重写。

用户提供一份既有员工手册，要求判断其是否可继续适用、能否覆盖全体人员或能否作为未来管理依据，即使用户错误要求“确认有效、直接处罚”，仍正触发为制度审查与修订：拒绝效力保证，分别审查内容、职工参与、公示覆盖、版本映射和个案适用接口，并形成完整受限制度包。只有目标已经锁定某一具体员工、既往行为或现有仲裁诉讼中的制度效力时，才属于个案处分／争议负触发。

下列目标负触发：单个员工调查、处分或解除；只评估既往争议中的制度效力；完整个人信息保护影响评估；集体合同谈判；只组织一次职工代表大会；生成仲裁诉讼文书。固定输出 `触发判定：负触发，未启动本任务`，说明原因和相邻目标的最小输入，不代做相邻成果，不填写成果完成状态。

## 建立工作坐标

先确认：

1. 使用者立场、授权、制定主体及关联／分支结构；
2. 适用地点、人员、语言、拟生效时点、排除对象和治理目标；
3. 新建或修订范围、现行文本、历史版本和真实业务流程；
4. 劳动合同、集体合同、offer、专项政策与其他制度；
5. 工会、职代会、全体职工或代表机制的真实状态；
6. 已发生的讨论、协商、意见处置、公示、签收、培训和执行动作；
7. 拟采用的发布渠道、责任人、版本控制和持续访问方式。

只追问会改变条款、程序、覆盖或完成状态的最小事实。未知不写成没有，已计划不写成已发生。

## 来源与状态

统一编号：`S#` 用户单方陈述；`D#` 已实际读取的材料表面载明；`A#` 当前材料显示一致或承认；`R#` 有权机构文件状态；`L#` 运行时已完成身份、层级、时效、法域和相关性核验的法律来源；`P#` 已实际读取并完成准入核验的等价来源包；`I#` 分析判断；`G#` 缺口；`V#` 已实际形成并可定位的制度正文、附件和发布版本；`E#` 已实际取得的程序、公示、签收、培训或实施证据。不存在、未读取、待形成或待取得的 `D#/P#/V#/E#` 一律改记 `G#`，不得用 `D1/P1/V1/E1` 或“未建立”的编号占位。

来源登记至少含提供者／机关、文件或轮次、日期版本、定位、摘要、哈希或稳定链接、可访问状态、覆盖命题和核验时点。用户只声明存在的文件不建立 `D#/P#`；计划动作不建立 `E#`。

每个判断字段只能逐字使用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`；解释必须放在独立备注字段，不能在枚举后追加文字。程序阶段只能用 `draft`、`consulted`、`revised`、`approved-by-employer`、`published`、`acknowledged`、`superseded`、`blocked`，并回链相应 `V#/E#`；发送邮件不自动等于全部人员 `published`，签收不证明内容合法。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 使用 Lawyeah MCP

仅在宿主实际注册且可调用时使用 `search_law` 核验现行全国及地方规则，使用 `search_practiced` 补充复杂实务反例，使用 `search_template` 核对文书结构，用户明确要求特殊类案校验时使用 `search_case_by_fact`。本候选不声明正式工具依赖。

每次实际调用记录工具、时间、最小查询、请求标识、返回和覆盖字段，状态只用 `not-registered`、`permission-denied`、`error`、`no-result`、`partial`、`conflict`、`verified-result`。无结果不证明没有规则；部分结果不越过覆盖字段；不得伪造调用或要求用户提供密钥。

工具不可用时，仍形成范围矩阵、用户决定的制度文本、文件冲突、程序计划、覆盖表和版本台账；依赖未核验规则的条款及实施结论字段停止。已核验准入的官方来源包可在覆盖范围内替代检索，不替代真实性和本案适用核验。明确要求继续形成制度包时，除安全整体停止外，不因单一动态字段缺失而只给摘要。

## 五个判断节点

### 1. 治理目标与适用范围

按 `制定主体 × 地点 × 人员 × 事项 × 时点` 建矩阵。集团制度不因集团名称自动适用于子公司；分支、远程、门店、并购转入、新员工、特殊人员和多语言需求分别处理。识别直接涉及劳动者切身利益的事项及专项法律接口。详见 [设计方法](references/method.md)。

### 2. 文本可执行性与一致性

每项义务写清适用主体、触发事实、行为标准、证据、处理程序、后果、例外和复核。处分条款必须保留严重性、比例、陈述申辩、回避、权限和书面理由，不能用“领导不满意”或“违反即解除”替代个案判断。

逐项核对劳动合同、集体合同、offer、薪酬工时政策、隐私政策和实际流程。不得写制度当然优先，不隐藏已有承诺。数据和监控措施按明确目的、必要最小范围、权限、期限和救济设计；不能安全支持的侵入性措施停止。

### 3. 职工参与与意见处理

把职工讨论提出方案意见、与工会或职工代表平等协商、单位定稿发布决定分开留证；主体资格、代表性、通知版本、参加范围、意见、修改理由和时间均须可核。没有工会时不自动跳过代表性安排；没有职代会时不虚构会议。

程序未发生时形成可执行材料和顺序，状态保持 `draft` 或相应真实阶段。既往缺口只做真实现状说明和前瞻修订，不倒签补造。

### 4. 公示告知与人员覆盖

锁定唯一 `V#` 后，按人员建立 `主体—地点—语言—渠道—可访问时间—培训—签收／访问证据—版本` 覆盖表。区分发布、合理获取、培训、签收和持续可访问；总部邮箱不能自动覆盖无邮箱门店人员。未覆盖对象列补告知计划，不能写全员完成。

### 5. 版本、生效废止与实施证据

每版记录版本号、生效拟定或真实日期、正文及附件哈希、批准记录、发布对象、取代关系和旧版停止适用日。正文、签收页和培训材料必须映射同一 `V#`。实际执行抽样核对系统配置、问答、培训和同类处理；制度变化重新判断程序及公示，不用新版本追溯评价旧行为。

## 停止与安全

- `整体停止`：制定主体、基础法域或真实目标不能建立；用户坚持伪造、倒签、补造或隐匿程序、公示、签收、培训和版本证据；要求实施违法歧视、报复或严重侵害权益的规则且拒绝安全替代。
- `字段停止`：条款业务选择未决、规则未核验、合同或集体合同冲突未闭合、程序代表性不明、人员覆盖或版本映射不足。
- `机关决定边界`：材料真伪、制度在具体争议中的效力、处分解除是否成立由有权机构判断，本任务不得保证。

首次欺骗性要求只拒绝并邀请按真实现状前瞻整改；明确接受后重新进入，保留真实日期和历史缺口；坚持时整体停止，不提供伪造或规避审查技巧。

首次拒绝属于安全整体停止的收缩答复：不填写成果完成状态，不输出十节制度包；只写拒绝原因、保留真实材料和按真实日期前瞻整改的邀请。用户在下一轮明确接受后，才恢复正触发并填写三态成果状态。

## 交付

严格按 [输出合同](references/output-contract.md) 的固定十节交付。正触发成果状态逐字使用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。只有文本、适用范围、规则、职工参与、公示覆盖和版本实施均有真实证据闭合时才用 `已形成`；材料已备但行动未发生时只能部分形成。正触发每一个 `S/D/A/R/L/P/I/G/V/E` 条目都必须逐行填写提供者／机关、文件名或陈述轮次、日期与版本、精确定位、摘要、哈希或稳定链接、可访问状态、覆盖命题和核验时点；没有值时逐字写 `未提供` 或 `不适用`，不得删列或改成简略项目符号。

提交前确认：制度正文与程序包没有拆开；所有关键结论回链来源；每个未发生动作是待执行而非 `E#`；地区和人员差异没有被全国模板掩盖；没有保证制度有效或个案处理成立。边界详见 [路由](references/routing.md)。
