# 实施单位解除终止

## 任务目标

在单位已经唯一选定一个劳动者的单方解除或法定终止路径、不可逆通知尚未执行时，形成“个体解除终止实施包”：路径前提、事实证据、特殊保护、授权审批、员工陈述、工会、受限通知、送达、结算交接、离职后动作和证据卷宗。

`depends-on` 为空。接受用户、律师、调查方、医疗或机关等合格来源的等价路径意见和前置成果，不要求先运行其他 Skill。

## 工作边界

正触发必须有唯一既定路径、明确对象和单位侧授权。路径仍在比较、协商解除、劳动者行动、多人减员、争议答辩、医学鉴定或通知已发后的撤回补救均负触发。固定输出 `触发判定：负触发，未启动本任务`，只说明路由和最小输入，不代做相邻成果，不填写成果状态。

本任务只交付材料和状态，不自行发送、签收、付款、停用账号或修改人事系统。

## 实施总门

确认用人单位、劳动者、工作地、关系合同、唯一路径、决定与签发主体、授权、拟决定日／送达日、构成事实、正反证据、制度版本、员工解释、保护状态、工会、结算参数和送达渠道。路径前提不成立时只停止、补证或退回决策，不在实施稿中静默改换理由。

已经发生的停工停薪、关权限、系统离职、口头书面通知、寄送、收款和交接必须如实登记，不写尚未开始。

## 来源和动作状态

编号：`S#` 单方陈述；`D#` 已实际读取的材料表面；`A#` 当前一致／承认；`R#` 机关、医学鉴定或裁判状态；`L#` 运行时已核验规则；`P#` 已读取并准入的等价包；`I#` 判断；`G#` 缺口；`V#` 已实际形成并可定位的通知和附件唯一版本；`E#` 已实际取得的审批、工会、发送、到达、付款、交接或归档证据。用户只声称存在但未读取的材料仍是 `S#`；不存在、待形成或待取得的 `D#/V#/E#` 一律改记 `G#`，不得预分配编号。

动作状态只用 `未开始`、`草案`、`待授权／审批`、`待工会程序`、`待发送`、`已发送待证明到达`、`已送达`、`结算处理中`、`已结算有凭证`、`已归档`、`停止`。计划、模板、口头确认或检索结果不能推进到已完成。

判断字段只允许逐字使用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`，解释放在独立备注列，不得在枚举后追加其他文字。不利材料和劳动者解释不得省略。

- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 使用 Lawyeah MCP

宿主实际注册且可调用时，使用 `search_law` 核验既定路径、程序和地方规则，使用 `search_practiced` 补充实施错误模式，使用 `search_template` 核对通知及配套文书结构，特殊事实需类案时使用 `search_case_by_fact`。本候选不声明正式依赖，也不虚构发送、送达或支付工具。

调用状态只用 `not-registered`、`permission-denied`、`error`、`no-result`、`partial`、`conflict`、`verified-result`，记录工具、时间、最小查询、请求标识、来源审查、字段覆盖和恢复条件。工具不可用时继续事实证据与材料结构，依赖未核规则的通知字段和不可逆实施停止；`partial` 不越界，合格来源包只在实际读取与准入覆盖内使用。

## 五个判断节点

### 1. 既定路径与权限

区分协商、过失性解除、非过失性解除和法定终止，不混用；把每个构成条件转成字段，以决定作出时已有事实、证据和规则为基准。核验用人单位、决定主体、签发权限、合同续延／无固定期限、目标时点和人员。路径不唯一或授权未知时不制作可发送终稿。

### 2. 事实与证据

逐要件列支持材料、不利材料、劳动者解释、控制方、合法取得、真实性、制度版本、同类处理和可补正动作。主管怀疑不写成事实，通知理由不得超出现有证据。以制度为依据时核内容、民主程序、公示、适用版本、员工覆盖、条款、严重程度和一致性。详见 [实施方法](references/method.md)。

### 3. 特殊保护与程序

筛查职业危害离岗检查、职业病／工伤／劳动能力、医疗期、孕产哺乳、距退休保护、工会任职、合同续延及歧视报复。需要医学、鉴定或机关结果时只接受合格状态，未知即停止受影响路径。

员工陈述申辩、调查处分、绩效前置、内部审批、工会事先通知、意见处理及书面回复分别建状态；没有真实 `E#` 不写完成，也不得补造昨日记录。

### 4. 通知、版本与送达

通知只写已支持的主体、唯一路径、事实、时间、制度／合同条款和规则，逐句回链；不混入协商措辞，不保证有效。锁定唯一 `V#`，正文、附件、签发页和送达件哈希一致，禁止跨版本盖章页。

送达按已确认地址、现场、合同约定和可证明渠道设计主次方案；每次尝试记录实施人、真实时间、内容 `V#`、渠道、签收／拒收／退回和原始凭证。公告、口头转告或电子方式不得类推为当然有效。

### 5. 结算、交接和不可逆动作

工资、补偿／赔偿候选、代通知金、奖金、未休假、社保工伤、竞业和已付款分别列项；金额不足只给公式和参数缺口。另列交接、离职证明、档案社保转移、财物账号、持续义务和归档。

发送、停工停薪、关账号、拒绝工作、付款和系统状态变更均不可逆或高风险；本任务不执行。只有真实证据才能推进动作状态。

## 停止与安全

- `整体停止`：主体、对象、唯一路径、法域或授权无法建立；用户坚持倒签、伪造理由／工会／送达，隐匿不利材料或非法取证；事项实为批量减员、歧视报复或刑事处置。
- `实施停止`：决定性证据、保护、制度、程序、金额或送达渠道不足；可形成受限草案和恢复清单，但不得发送。
- `阶段停止`：通知已发且目标转为撤回、补救或应诉，路由争议或相邻程序。

首次伪造、倒签或补写并不存在的程序记录要求立即安全整体停止，只输出拒绝、保全、后果和按真实日期恢复条件，不继续十二节实施包；明确接受后恢复，保留历史缺口；坚持时整体停止，不给伪造或规避鉴定技巧。

## 交付

严格按 [输出合同](references/output-contract.md) 固定十二节交付。正触发成果状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`；负触发不填写。所有不可逆前提、程序、金额和授权可核且材料达到待发送状态时才用 `已形成`；尚有待执行动作并不等于已送达。

提交前检查：路径与对象唯一；通知理由和证据一致；保护和程序逐项；`V#/E#` 不混；不利材料保留；送达可留痕但未被保证；结算可复算；未发生动作未写完成；不保证员工签收、放弃权利或争议结果。路由见 [边界](references/routing.md)。
