# 审计薪酬工时休假

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是运行本技能的强制依赖。

## 任务目标

为单位侧形成“薪酬工时休假专项审计与整改包”，覆盖审计总体与期间、数据完整性、分层样本、规则—制度—系统—执行穿行、逐人逐期差额、风险与外推限制、整改责任和独立复测。

`depends-on` 为空。接受用户、服务商、会计、律师或其他合格来源提供的等价数据和规则包，不要求先运行其他 Skill。

## 工作边界

正触发于对指定单位、地点、期间和员工总体开展企业专项审计。单个劳动者的最终权益测算、离职款项、发薪操作、税社保专项、争议申请答辩和法定财务鉴证均负触发。固定输出 `触发判定：负触发，未启动本任务`，只说明原因和相邻目标的最小输入，不代做相邻成果，不填写成果完成状态。

## 建立审计坐标

先确认：使用者及授权；被审计实体、地点、期间、事项和总体；人员名册及特殊类别；工时和薪酬分层；数据系统、提取时点与变更链；合同、集体合同、制度和批复版本；样本方法与审计目的；已有投诉、监察、争议或整改动作。

核心数据必须区分应发／实发、税前／税后、归属期／支付期、正常工资／加班工资、原始值／人工调整、零值／缺失值、样本观察／总体推断。未知保持 `unknown`，不得填零。

## 来源、数据与证据状态

统一编号：`S#` 用户陈述；`D#` 业务材料或数据表面值；`A#` 当前材料显示一致或承认；`R#` 批复、决定或裁判状态；`L#` 运行时完成来源核验的法律规则；`P#` 已读取并完成准入的等价来源包；`I#` 审计判断；`G#` 缺口；`T#` 原始数据快照和变换记录；`V#` 审计底稿与报告版本；`E#` 真实整改或复测证据。

每项来源记录必须逐行提供提供者、系统／文件、期间、提取方式、字段定位、哈希或稳定链接、原始或加工状态、访问权限、完整性结果和覆盖命题；缺失字段写 `未提供` 或 `不适用`，不得缩写成一句来源说明。原始数据只有在真实取得并固化后才能编号为 `T#`，且必须同时记录系统／文件、提取时间、查询或筛选条件、字段范围、行数、哈希和访问权限。尚待提取、尚待授权或仅计划固化的数据只能编号为 `G#` 并标记“计划快照”，不得预分配 `T#`。清洗、关联、排除和人工修正保留规则、操作者、时间、输入输出哈希和行数变化。用户自选样本不冒充随机样本。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。金额状态只用 `样本已证实金额`、`合理区间`、`无法估计`、`经统计设计允许外推`。只有形成可复算金额、边界或满足统计外推条件时才使用对应状态；只有差异方向、频次或记录不一致而不能形成金额时，金额状态必须写 `无法估计`，差异另在叙述列说明。

## 使用 Lawyeah MCP

宿主实际注册且可调用时，使用 `search_law` 核验国家和地方规则，使用 `search_practiced` 补充审计与整改方法，特殊事实需要类案时使用 `search_case_by_fact`，用户明确指定筛选条件时使用 `search_case_by_filter`。本候选不声明正式工具依赖，也不虚构工资、考勤或支付数据工具。

每个正触发成果都必须输出固定 MCP 调用表。每次实际调用记录工具、时间、最小查询、请求标识、七态、结果摘要、来源准入、字段覆盖和恢复条件；未调用时也保留一行，按实际情况填写 `not-registered` 等状态，其他缺失字段写 `未提供` 或 `不适用`。状态只用 `not-registered`、`permission-denied`、`error`、`no-result`、`partial`、`conflict`、`verified-result`。无结果不证明无地方规则，部分或冲突结果不得越界。工具不可用时继续数据完整性、样本、流程和公式结构；依赖未核验参数的结论与金额字段停止。合格来源包只在实际读取和准入核验的覆盖范围内替代检索。

## 五个判断节点

### 1. 范围、总体和样本

从 HR、工资、社保、在离职和系统账户数据交叉对账总体；按地点、工时制、薪酬类型、岗位、在离职、特殊人员和异常记录分层。高风险层可全查，其他层说明抽样框、方法、样本量依据、未纳入人群和缺失率。详见 [审计方法](references/method.md)。

法律审计没有可凭空套用的统一样本量。总体或抽样框不明、主动排除异常、样本选择偏差无法评价时，不输出总体合规率或全员精确差额。

### 2. 数据完整性与流程穿行

建立 `法律／地方规则—合同制度—系统配置—排班审批—实际工作—工资结果—支付凭证` 链。既从排班到支付正向穿行，也从异常工资、投诉和人工改数反向追溯。工资表、流水、现金或失败转账冲突时并列，不将工资表表面“已付”升级为实际到账。

### 3. 工资、工时和休假分项测试

先锁定人员、用工地、期间、工时制、工资口径、日历、补休和休假资格，再逐人逐期计算。标准、综合和不定时工时分别处理；合同标签不能替代有效批复。工作日、休息日、法定节假日、补休和不同年度日历不得混用。奖金、提成、津贴、计件和人工调整回链各自规则与实际支付。

参数、公式、舍入、应付、实付、差额和证据强度全部可复算。关键参数未知时给情景区间或 `无法估计`，不得以零补齐。

### 4. 发现、风险与外推

每项发现列事实、相反材料、规则、影响人员期间、金额状态、频率、证据强度、控制根因和最强反方解释。把个体已证实、控制缺陷、样本发生率和允许／禁止外推分栏。不得用平均数掩盖极端加班、负工资、失败支付或受保护人员。

### 5. 整改与复测

整改区分即时止损、扩查、补付或休假安排、制度流程与系统修复、沟通、责任人、批准、期限和复测指标。建议、批准、执行、到账和复测是不同状态；没有真实 `E#` 不写整改完成。补付或改制度不自动消除历史责任。

## 停止与安全

- `整体停止`：主体、授权、期间或总体无法建立；数据被篡改且无法恢复可信快照；用户坚持删除不利数据、制造合规记录、隐匿欠付或报复投诉人员。
- `字段停止`：抽样框、数据链、特殊工时批复、地方参数、工时制、工资基数、支付或休假资格缺失冲突。
- `专业边界`：不冒充行政机关、仲裁庭、法院、统计鉴证或财务审计机构。

首次篡改要求立即拒绝并要求保全原始数据；用户明确同意恢复真实快照后重新进入，记录历史污染和变更；坚持时整体停止，不提供删除痕迹或反取证技巧。
