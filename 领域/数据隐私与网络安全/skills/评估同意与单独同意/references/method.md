# 同意评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变合法性、路径、时限或对外含义的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然免罚、必然合法或唯一处罚金额。未知人数或金额不写零。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

## Q# 矩阵

固定列：`编号｜活动｜同意形态｜知情｜自愿｜明确｜是否须单独同意｜撤回通道｜撤回后能否继续｜最强反方｜判断｜待核`。

## 节点 0　专项分流

先于实体判断。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填本任务实体结论。

| 信号 | 转出 |
| --- | --- |
| 商业秘密、专利商标著作权权利本身 | 知识产权领域 |
| 企业级合规体系、反商业贿赂、舞弊内部调查 | 企业合规领域 |
| 诊疗过错、病历鉴定、药品器械或医疗机构监管本身 | 医疗医药领域 |
| 解除、处分、民主程序等劳动法后果为主 | 劳动领域 |
| 侵犯公民个人信息罪控告或辩护 | 刑事领域 |
| 一般交易合同签前审查起草 | 审查起草领域（本窗搁置，只说明不实施） |

混合信号：本任务主轴可留；专项只作为背景时在缺口标明，不把专项规则硬套进本任务结论。

## 节点 1　争点与分流

- 若 用户要逐项闭合第 13 条七项：则 负触发，转 `评估个人信息处理合法性`
- 若 用户只要对外告知文本：则 负触发，转 `准备隐私政策与告知`
- 若 主张不必同意因合同或人事必要：则 本任务只记录该主张，合法基础终局转合法性原子
- 若 儿童监护人同意：则 本任务只标接口，实体转 `处理不满十四周岁未成年人个人信息`

## 节点 2　知情自愿明确

运行时核验第 14 条及条例第 22 条。

- 若 告知未覆盖该目的、方式或种类：则 知情不支持，同意效力不支持
- 若 预勾选、默认开启或概括“同意全部条款”：则 明确不支持
- 若 拒绝非必要权限即无法使用基本功能：则 自愿不支持，并打开捆绑同意原子接口
- 若 个人已明确拒绝后仍频繁弹窗：则 现有依据不支持该后续同意，条例第 22 条红旗
- 若 目的方式种类已变更但未重新同意：则 原同意不能覆盖变更后处理

禁止：
- 把阅读隐私政策写成已单独同意
- 把登录即同意写成明确同意

## 节点 3　单独同意

- 若 处理敏感个人信息：则 须单独同意（第 29 条），总开关不够
- 若 向其他处理者提供或公开：则 须单独同意，另核法定例外
- 若 向境外提供：则 须告知接收方信息并单独同意（第 39 条），依法可不告知的除外
- 若 同一弹窗并列基本功能与对外提供：则 对外提供的单独同意不成立
- 若 只有一次总勾选覆盖上述场景：则 单独同意判断为现有依据不支持

## 节点 4　撤回

运行时核验第 15、16 条。

- 若 撤回路径明显难于同意路径：则 撤回便利性不支持
- 若 撤回后仍按原同意继续营销或画像：则 继续处理不支持
- 若 主张撤回不影响合同必要处理：则 必须指出哪一项合同义务、哪一类信息确需；写不出则依据不足
- 若 因撤回同意而关闭基本功能，但该处理并非基本功能所必需：则 第 16 条红旗，现有依据不支持该拒绝提供

## 节点 5　效力与转介

- 若 知情自愿明确均支持且无须单独同意：则 普通同意可支持该活动，仍可能要告知
- 若 须单独同意但只有总开关：则 单独同意不支持，处理应停止或补正交互
- 若 同意无效但可能有第 13 条第 2–7 项：则 转合法性原子，本任务不把其他基础写成已成立
- 若 争议主轴是过度收集而非同意形态：则 转最小必要原子
