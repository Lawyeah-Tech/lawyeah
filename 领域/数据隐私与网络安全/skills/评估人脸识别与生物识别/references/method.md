# 人脸与生物识别方法

本文件是可执行判断节点，不是栏目说明书。每个会改变合法性、路径、时限或对外含义的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然免罚、必然合法或唯一处罚金额。未知人数或金额不写零。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

## Q# 矩阵

固定列：`编号｜场景｜是否公共场所｜目的｜单独同意｜替代方案｜显著提示｜原图保存｜判断｜待核`。

## 节点 0　专项分流

先于实体判断。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填本任务实体结论。

| 信号 | 转出 |
| --- | --- |
| 商业秘密、专利商标著作权权利本身 | 知识产权领域 |
| 企业级合规体系、反商业贿赂、舞弊内部调查 | 企业合规领域 |
| 诊疗过错、病历鉴定、药品器械或医疗机构监管本身 | 医疗医药领域 |
| 解除、处分、民主程序等劳动法后果为主 | 劳动领域 |
| 侵犯公民个人信息罪控告或辩护 | 刑事领域 |
| 一般交易合同签前审查起草 | 审查起草领域（本窗搁置，只说明不实施） |

混合信号：本任务主轴可留；专项只作为背景时在缺口标明，不把专项规则硬套进本任务结论。

## 节点 1　分流与禁止

- 若 公安机关依法履职：则 另核法定职权，不按商业核验处理
- 若 用户要规避实名核验或伪造生物特征：则 整体停止
- 若 只要第 28 条认定：则 可先完成本任务场景，认定细节转敏感原子

## 节点 2　场景

- 若 酒店、商场、小区入口以刷脸为唯一通行：则 替代方案缺失红旗
- 若 仅用于支付或高风险核验且有密码替代：则 替代可支持，仍须单独同意
- 若 用于营销识别回头客：则 公共安全目的不支持，须单独同意且通常难成立充分必要

## 节点 3　公共场所

运行时核验第 26 条。

- 若 无显著提示标识：则 第 26 条提示不支持
- 若 采集后用于商业分析且无单独同意：则 目的限制不支持
- 若 目的是否维护公共安全依据不足：则 字段停止，不得自行写成已合法安装

## 节点 4　同意与存储

- 若 无单独同意且无法定例外：则 处理不支持
- 若 长期保存可还原原图而无必要：则 保存不支持
- 若 向物业以外第三方提供人脸：则 打开对外提供与 PIPIA

## 节点 5　输出

- 若 有替代、单独同意、提示和最小保存均支持：则 可在该场景处理
- 若 任一项不支持：则 应停用或改为非生物识别方式

## 金额与规模

已知处理人数、事件波及人数、上一年度营业额只作区间参数。未知不写零。个保法第 66 条处罚上限只标接口，不输出唯一罚款预测。
