# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变合法性、出境、事件报告或整改结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然免罚、必然合法或唯一处罚金额。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

## Q# 矩阵

固定列：`编号｜场景｜处理者角色｜相对方｜法律效果／义务｜成立条件｜支持事实｜不利事实｜控制方｜最强反方｜主备位｜判断｜待核`。

收集、存储、使用、加工、传输、提供、公开、删除分列。同一事实支持多项时分别说明效果。已发布告知不等于合法基础已闭合。

## 节点 0　专项分流

先于实体判断。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填总体评估十节实体结论。

| 信号 | 转出 |
| --- | --- |
| 商标专利著作权确权、商业秘密权利基础与侵权损失 | 知识产权领域 |
| 企业级合规体系、反商业贿赂、舞弊内部调查 | 企业合规领域 |
| 诊疗过错、病历鉴定、药品器械或医疗机构监管本身 | 医疗医药领域 |
| 解除、处分、民主程序等劳动法后果为主 | 劳动领域 |
| 侵犯公民个人信息罪控告或辩护 | 刑事领域 |
| 一般交易合同签前审查起草 | 审查起草领域（本窗搁置，只说明不实施） |

混合信号：数据治理主轴可留本任务；专项只作为背景时在缺口标明，不把专项规则硬套进本任务结论。

## 节点 1　主体、角色和系统范围

1. 固定法律实体、品牌名、App/网站/小程序/SaaS/车端/云账号。冲突并列，不选对用户有利的一版冒充唯一主体。
2. 角色表记录：个人信息处理者、受托人、共同处理者、网络数据处理者、网络运营者、是否自称关基。未被保护工作部门认定时，关基状态标 `依据不足`，不得自行宣布。
3. 系统表记录：主系统、日志、备份、SDK、境外控制台、运维账号。境外只读访问不得直接写成“未出境”，先留出境闸。
4. 同时掌握双方秘密或立场不明：整体停止策略输出。

---

## 节点 2　处理场景与合法性红旗

每个场景先写处理目的，再写种类、来源、是否敏感、保存、合法基础候选。

默认场景簇，不得预先锁定“都有同意”：

- `Q-收` 收集（含 SDK、摄像头、定位）
- `Q-用` 使用与画像、自动化决策
- `Q-委` 委托处理
- `Q-供` 向其他处理者提供
- `Q-公` 公开
- `Q-出` 向境外提供或境外访问
- `Q-存` 保存与删除
- `Q-权` 权利请求通道是否可行使

合法基础只对照个保法第 13 条七项，运行时核验现行文本。第 2–7 项现有依据支持时，不得要求再取得同意作为唯一合法化手段。同意路径必须满足知情、自愿、明确；敏感信息、对外提供、公开、出境另标单独同意接口，不在本任务做专项终局。

禁止：

- 把隐私政策点击写成已取得单独同意；
- 把去标识、哈希、脱敏写成已经匿名化；
- 把“行业惯例”写成第 13 条第 7 项。

## 节点 3　出境、重要数据和关基

本节点只判断红旗和路径接口，不生成申报或备案终稿。

### 3.1 是否构成向境外提供

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 使用境外云 Region 或境外控制台 | 一定未出境 |
| 集团账号可调取境内库 | 仅内部管理故不适用出境规则 |
| 数据先出境再回国 | 回国后当然消灭出境义务 |
| 传输的是“脱敏数据” | 当然不是个人信息或重要数据 |

### 3.2 路径接口

运行时核验《促进和规范数据跨境流动规定》第 3、5、6、8 条及个保法第 38–40 条后再落判断。核验失败则路径字段停止。

- 不含个人信息且不含重要数据：评估免予申报/标准合同/认证的接口。
- 合同履行、跨境人事、紧急情况、低量豁免：逐项核“确需”和“不含重要数据”。
- 自贸区负面清单外：须有清单及备案事实，否则 `依据不足`。
- 数量累计自当年 1 月 1 日起算；未知人数不写零。
- 重要数据：已识别申报但未被告知或公布的，不需要作为重要数据申报出境评估；同时不得写成“已证明不是重要数据”。

关基运营者出境和个人信息境内存储门槛，条号与数量一律运行时核验，不得凭记忆写唯一阈值。

## 节点 4　事件、监管和期限

分别判断：是否已发生或可能发生泄露、篡改、丢失或网络安全事件；是否已向主管部门报告；是否已通知个人；是否已约谈、检查、通报、下架、立案。

- 事件处置与对外报告分账。本任务只标时钟和转介。
- 网络数据安全管理条例第 11 条：立即启动预案、防止危害扩大、按规定报告；对个人、组织造成危害的应及时通知。具体小时数运行时核验，未核验不得写“一律 24 小时”。
- 个保法第 57 条：能有效避免危害的可以不通知个人；部门认为可能造成危害的仍可要求通知。免通知必须有措施与危害判断，不得用公关口径代替。
- 口头“已经报过”或聊天截图不得写成已报告。

---

## 节点 5　证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因供应商控制而推定材料存在或内容有利。

下一步按：事件报告时钟、出境累计可能跨档、日志保留窗口、改变 `Q#`、可逆性排序。发告知、PIPIA 正文、出境申报、事件报告、起诉只写转介和最小交接。

禁止指导伪造同意、补造日志、瞒报或违法取证。

## 金额与规模

已知处理人数、事件波及人数、上一年度营业额只作区间参数。未知不写零。个保法第 66 条处罚上限只标接口，不输出唯一罚款预测。
