# 核心数据方法

本文件是可执行判断节点，不是栏目说明书。每个会改变合法性、路径、时限或对外含义的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率、必然免罚、必然合法或唯一处罚金额。未知人数或金额不写零。

`search_law` 返回已失效《合同法》及其解释时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

## Q# 矩阵

固定列：`编号｜数据｜是否已被确定｜红旗｜更严管理接口｜出境｜停止项｜判断｜待核`。

---

## 节点 0　专项分流

先于实体判断。命中任一项则整案转出，本任务只交付分流理由和最小交接，不填本任务实体结论。

| 信号 | 转出 |
| --- | --- |
| 商业秘密、专利商标著作权权利本身 | 知识产权领域 |
| 企业级合规体系、反商业贿赂、舞弊内部调查 | 企业合规领域 |
| 诊疗过错、病历鉴定、药品器械或医疗机构监管本身 | 医疗医药领域 |
| 解除、处分、民主程序等劳动法后果为主 | 劳动领域 |
| 侵犯公民个人信息罪控告或辩护 | 刑事领域 |
| 一般交易合同签前审查起草 | 审查起草领域（本窗搁置，只说明不实施） |

混合信号：本任务主轴可留；专项只作为背景时在缺口标明，不把专项规则硬套进本任务结论。

## 节点 1　分流

- 若 用户要定罪或报案刑事：则 刑事领域
- 若 出口管制编码或许可：则 涉外／管制
- 若 仅重要数据识别：则 转识别原子

## 节点 2　认定克制

- 若 有权机关已确定为核心数据：则 按核心数据义务评估
- 若 仅有内部猜测：则 只标红旗，认定依据不足
- 若 用户要求对外公告“我们是核心数据运营者”：则 停止该宣布

## 节点 3　义务接口

- 若 已确定或红旗高：则 列更严存储、访问控制、出境禁止或评估接口，条号待核
- 若 拟向境外提供：则 打开出境评估，不得写成可走标准合同了事

## 节点 4　停止项

- 若 用户要降低防护以便业务上线：则 该方案不支持
- 若 事实不足：则 义务范围字段停止

## 节点 5　输出

- 若 红旗与接口已列：则 交付，不定罪
- 若 未被确定：则 结论不得写成已是核心数据

## 金额与规模

已知处理人数、事件波及人数、上一年度营业额只作区间参数。未知不写零。个保法第 66 条处罚上限只标接口，不输出唯一罚款预测。

下一步按期限灭失、易失证据、能否改变 `Q#`、可逆性排序。相邻原子只写转介和最小交接，不代做。禁止指导伪造同意、补造日志、瞒报或违法取证。

## 补强：红旗与停止

- 若 数据描述涉及国家经济命脉行业的生产运行参数但无机关确定：则 只标红旗，不得对外公告核心数据运营者身份。
- 若 拟将疑似核心数据同步至境外研发环境：则 停止该方案美化，打开出境评估并标更严接口。
- 若 用户要求比较“按重要数据还是核心数据处理更省事”：则 不选省事项，分别标接口。
- 若 出口管制编码同时出现：则 本任务只留数据保护红旗，管制许可转涉外。
