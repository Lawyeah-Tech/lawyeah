# 原子 Skill 选择方法

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果，而不是按 App、行业或法条名称匹配：

- 数据与隐私合规总图；
- 特定处理活动合法性；
- 出境路径；
- 隐私政策或告知文本；
- 事件对外报告或个人告知；
- 处理活动记录；
- 事件处置方案；
- 一审起诉包；
- 一审应诉包；
- 损害测算；
- 影响评估记录、同意效力、主体权利或注销、保存删除；
- 敏感、儿童、自动化决策、人脸、监测、定位、营销；
- 委托、共同处理、对外提供、公开、并购转移、供应商、匿名化、SDK；
- 分类分级、重要数据、核心数据、关基、本地化、数据交易；
- 出境安全评估申报、标准合同备案、认证、豁免、远程运维、接收方；
- 等保、网安审查、密评、漏洞披露、云驻留、生成式人工智能数据；
- 事件证据保全、暴露范围测算；
- 约谈检查、行政处罚申辩、合规审计、App 下架、整改报告、向机关提供数据；
- 和解谈判、行为保全、平台或网信投诉；
- 员工信息、健康信息、汽车数据。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权（处理者 / 个人 / 受托人）；
2. 主要成果是评估、发文、建档、事件处置、测算还是程序文书；
3. 是否已发生安全事件、已收到监管文书或起诉状；
4. 是否涉及出境、重要数据或关基；
5. 是否属于知识产权、综合合规、医疗业务监管、劳动程序或刑事主轴。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再发文；
4. 用户确认后只启动所选入口；等价评估、测算或记录可由用户或律师提供。

## 四、停止

立场冲突、专项主轴或一般合同审查起草时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。
