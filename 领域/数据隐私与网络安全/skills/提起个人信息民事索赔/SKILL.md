# 提起个人信息民事索赔

## 任务目标

在明确、无利益冲突的原告立场下，形成不代提交的一审起诉包：起诉状草稿、分项请求、管辖连结点、证据目录和保全红旗。

`depends-on` 为空。

## 工作边界

正触发：个人或近亲属等权利人已决定向人民法院提起个人信息或隐私民事请求。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 只要 C 端投诉材料；
- 名誉诽谤或肖像商业使用为主；
- 公益诉讼由检察院或法定组织提起；
- 用户实为被告；
- 劳动争议或医疗损害主轴。

C 端个人信息侵权投诉只分流，不回改。

## 建立起诉坐标

确认：原告资格；被告处理者；处理行为；已提出的权利请求及答复；拟请求；管辖连结点；是否已有案号。

已有受理凭证时停止生成起诉入口材料。

## 来源和判断状态

编号：`S/D/A/R/C/L/I/G/Q/P#/J#/V/E`。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

`search_law` 核验个保法第 50、69 条、民法典第 995、1032–1039 条、管辖与时效。`search_template` 只借起诉状栏目。

## 五个判断节点

以 [起诉方法](references/method.md) 为准。

### 1. 分流与起诉决定

名誉、肖像、劳动、医疗、公益诉讼整案转出。

### 2. 请求分列

停止处理、删除、更正、赔礼道歉、消除影响、财产损失、精神损害分列。停止侵害等人格请求不适用诉讼时效；金钱请求单独核时效。

### 3. 管辖

被告住所地、侵权行为地分列。材料不足不选定唯一法院。

### 4. 证据与过错推定

第 69 条由处理者证明自己没有过错，但原告仍须证明处理行为、权益与损害事实。违法取证不得列入。

### 5. 起诉状草稿

只交付草案和核验清单，不代提交，不保证受理或胜诉。

## 停止与安全

- `整体停止`：伪造受害事实；立场冲突。
- `字段停止`：管辖、时效、条文未核验。
- `目标停止`：主目标变为投诉或应诉。
