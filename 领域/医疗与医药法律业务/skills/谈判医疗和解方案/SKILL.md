# 谈判医疗和解方案

## 任务目标

在明确、无利益冲突的单方立场下，形成“医疗和解谈判方案”：争点让步表、鉴定前后窗口、底线与交换、弃权范围、后续治疗风险、执行力提示。

`depends-on` 为空。接受用户、律师、医调委或其他来源的等价评估、测算和鉴定。

## 工作边界

正触发：医疗损害或产品／血液争议仍可谈，需要底线和条件，而不是已谈拢的协议正文。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 条件已谈拢，只要可签协议；
- 只要答辩状或起诉状；
- 只要医调委申请书；
- 未成争只要改医疗服务合同（审查起草搁置）；
- 用户要求保证机构赔付或强迫对方签字。

本任务不保证赔付，不替代已签字协议审查，不给胜诉率。

## 建立谈判坐标

确认：使用者与授权；单方立场；相对方决策人；鉴定是否已做；已付费用和后续治疗；是否已立案；对方已知报价；法域。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`R#` 鉴定或文书；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口；`N#` 谈判条件；`V#` 方案版本。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验和解、人民调解效力和司法确认接口。工具不可用时继续让步表；效力结论字段停止。

## 五个判断节点

执行顺序和停止条件以 [谈判方法](references/method.md) 为准。这里只列入口，不代替节点。

### 1. 分流、立场和谈判窗口

鉴定前、鉴定后、立案后窗口分列。强迫或医闹换和解整体停止。

### 2. 争点与让步表

过错、原因力、费用项目、后续治疗、公开道歉、纪律处理分列。不得用放弃鉴定换“承认医疗事故”。

### 3. 底线、交换和弃权

弃权是否覆盖未知后续损害必须明示。概括放弃后续治疗标高风险。

### 4. 执行力

协议、医调委调解、司法确认、公证赋强比较。单独和解无执行力必须明示。

### 5. 破裂预案

转鉴定、起诉或应诉，不在本任务出那些终稿。

## 停止与安全

- `整体停止`：立场不明；用户坚持威胁医务人员或虚假陈述换协议。
- `字段停止`：调解效力规则未核验。
- `目标停止`：主目标变为协议正文、起诉或答辩。

## 交付

严格按 [输出合同](references/output-contract.md) 十节交付。正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。边界见 [路由](references/routing.md)。
