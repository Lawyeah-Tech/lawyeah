# 原子 Skill 选择方法

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果，而不是按科室、术式或药品名称匹配：

- 医疗损害总图；
- 告知同意、急救义务、拒诊转诊、管辖时效、主体链、医美边界、合同侵权竞合、过度医疗、超说明书；
- 病历真实性完整性审查；
- 病历复制或封存、输液输血实物封存、影像病理原始数据、尸检路径；
- 鉴定类型选择、鉴定申请、鉴定异议、专家咨询、调查令；
- 专项测算（不含一般人身标准表）；
- 证据案卷；
- 和解谈判、和解协议草稿、执行力补强、医调委申请或方案评估；
- 一审起诉／应诉、产品责任两造、庭审、上诉／二审、保全、先予执行、执行；
- 机构初期应对、投诉信访、医闹分流、质量安全报告；
- 执业许可与申报、卫健检查处罚、广告、互联网诊疗、抗菌药物、麻精、放射、院感、医废、用血；
- 医师注册、多点会诊、人员处罚、非法行医民行；
- 药械缺陷、召回、GMP／GSP、药监检查处罚、疫苗、集采、推广红旗、试验、伦理、AE 报告、网售处方药；
- 精神障碍收治、传染病报告、孕产双主体、医保拒付或飞检、诊疗隐私行业后果。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权（患方／机构／产品主体）；
2. 患者是否仍需急救；
3. 病历是否已复制或封存、是否已鉴定或已立案；
4. 本次要分析、保全文书、测算、建卷、谈判还是程序文书；
5. 是否属于一般人身侵权、工伤、生活美容、通用合规或数据治理。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再封存或先鉴定再起诉；
4. 用户确认后只启动所选入口；等价评估、病历或鉴定可由用户或律师提供。

## 四、停止

立场冲突、专项主轴或未成争改合同时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。
