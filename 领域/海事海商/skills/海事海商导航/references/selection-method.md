# 原子 Skill 选择方法

当前安装包是。先问这一次要拿到什么可独立验收的成果，而不是按班轮、租船、集装箱或案由名称匹配。

## 一、先识别成果

P0 主干：

- 海事争议总图；
- 海事管辖、专属管辖或仲裁协议判断；
- 货损货差迟延请求或抗辩；
- 扣押船舶申请；
- 应对扣船与担保放船；
- 货损运费滞期或限制后测算；
- 海事证据案卷；
- 和解方案；
- 海事一审起诉包；
- 海事一审应诉包。

P1 专项（已安装，按成果选，不按船种拆）：

- 承运人/实际承运人识别；提单效力与转让；分类型时效；准据法；管辖异议；仲裁协议异议；
- 承运人免责适航；单位责任限制；无单放货；运费留置；多式联运海运段；租约争议；滞期；货代；货损通知；
- 旅客索赔；船员工资伤亡；拖航；港口作业；船舶买卖、建造、抵押、优先权排序、权属；
- 碰撞责任与碰撞测算；油污；救助；共同海损与担保；沉船打捞；责任限制评估、设基金、挑战基金；
- 船舶保险、货物保险、保险索赔材料、代位；航海资料保全、检验申请、鉴定异议；
- 扣船评估、扣货扣燃油、强制令、证据保全申请、放船保函；
- 和解文本、执行力补强；选程序、提起仲裁、庭审、上诉、债权登记、申请拍卖；
- 仲裁应诉、反诉评估与准备、二审答辩、执行与应对执行、撤销裁决、不予执行裁决。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权；
2. 争议是否已经形成，是否已扣船或已立案；
3. 是否已有仲裁条款、租约仲裁、提单 hinterland；
4. 本次要分析、扣船、测算、建卷、谈判还是程序文书；
5. 是否属于一般国际贸易、一般合同、劳动、陆上侵权或工程专项。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再扣船；
4. 用户确认后只启动所选入口；等价评估、测算或证据可由用户或律师提供。

## 四、停止与未安装

立场冲突、国际贸易/一般合同主轴或未成争改租约时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。

保赔会籍、应对海事强制令、刑民交叉专项为 P2，输出 `unavailable`。
