# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变释放、扣留或指令接口结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

释放评估看交易文件条件，不代替银行与托管人之间的监管关系。不得输出银行必须划款。

---

## Q# 释放矩阵

固定列：`编号｜金额｜条件｜索赔通知｜应释放／应扣留｜指令权人｜判断`。

到期自动部分与争议部分分列。

---

## 节点 0　分流

1. 存管合同、备付金 → 金融。
2. 条款设计 → 提存条款原子。

## 节点 1　条件

1. 书面条件逐条。沉默不推定释放。

## 节点 2　扣留

1. 须有合格索赔通知。形式瑕疵标待核。

## 节点 3　指令

1. 共同指令 vs 单方。

## 节点 4　诉讼仲裁

1. 未裁决不得写全部长期冻结，除非条款如此。

## 节点 5　安全

1. 禁止伪造无索赔确认。

---

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 到期了 | 必须全部释放 |
| 有一笔索赔 | 必须全部扣留 |
| 本任务评估 | 银行必须划款 |
| 存管合同审查 | 本任务主成果 |

---

## 条件句

if 银行关系主轴 → 负触发
if 伪造无索赔 → 整体停止
if 条件未满足 → 不得写应释放
if 条款设计主成果 → 负触发

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 不是银行划款命令。 |
| 2 | 存管主轴转金融。 |
| 3 | 到期不自动消灭合格索赔。 |
| 4 | 超额索赔不自动扣留全部。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按伪造、金融边界、条件排序。金融、提存条款、赔偿应对只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。

本成果不是划款指令。
---

## 补充条件句与停止

if 主成果是银行存管、备付金或托管牌照关系 → 负触发，转金融领域。  
if 用户要求伪造无索赔确认以便释放 → 整体停止。  
if 仅因期限届满且存在合格索赔通知 → 不得写必须全部释放。  
if 索赔金额明显小于提存余额 → 不得写必须全部扣留。  
本成果不是对托管人发出的划款命令。
