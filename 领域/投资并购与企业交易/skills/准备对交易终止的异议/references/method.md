# 应对方法

本文件是可执行判断节点，不是栏目说明书。每个会改变异议是否成立或继续交割／索赔分流结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

相对方立场。异议不是自动让终止失效。不写诉状。强制交割 P2 未安装则 `unavailable`。

---

## Q# 异议矩阵

固定列：`编号｜攻击点｜事实｜条款｜判断｜导向（继续交割／索赔／谈判）`。

送达瑕疵、权利瑕疵、催告、不正当阻却、弃权分列。

---

## 节点 0　收到

1. 通知文本、渠道、时间。未收到 → 负触发。

## 节点 1　攻击

1. 逐项对应对方主张，不得只写“我方不同意”。

## 节点 2　继续交割

1. 是否仍可能、对方是否已采取终止后行为。P2 强制交割 unavailable。

## 节点 3　索赔

1. 错误终止的损害赔偿接口，金额不写必得。

## 节点 4　函

1. 待发送。到达设计。

## 节点 5　诉讼

1. 不写诉状。

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 发出异议 | 终止已经无效 |
| 没收到通知 | 本任务主成果 |
| 确认之诉 | 本任务可写诉状 |
| 强制交割 | 本包可终局 |

---

## 条件句

if 尚未收到通知 → 负触发
if 要诉状 → 负触发
if 伪造已满足条件 → 整体停止
if 强制交割主成果 → P2 unavailable

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 异议不自动消灭终止效果。 |
| 2 | 不写确认之诉诉状。 |
| 3 | 强制交割 P2 unavailable。 |
| 4 | 未收到则负触发。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按送达、终止权、诉状边界排序。终止评估、通知、P2、诉讼只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。

函件状态保持待发送。
---

## 补充条件句与停止

if 尚未收到终止通知 → 负触发。  
if 主成果是确认之诉诉状 → 负触发，转合同争议领域。  
if 主成果是强制交割专项 → 输出 `unavailable`。  
if 用户要求把发出异议写成终止已经无效 → 纠正；异议不自动消灭终止效果。  
已读聊天记录不等于送达到达。送达事实不足则效力字段停止。
