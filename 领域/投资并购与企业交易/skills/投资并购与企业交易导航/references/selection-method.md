# 原子 Skill 选择方法

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果，而不是按股权、资产或行业名称匹配：

- 交易路径与监管闸总图（P0）；
- 尽调范围与资料清单、尽调报告（P0）；
- 条款清单或意向书、拘束力分账、排他冻结（P0／P1）；
- 股权收购协议、对方文本审查（P0）；
- 资产协议、认购协议、SHA、R&W、赔偿、提存、TSA、决议、披露表、竞业、增资登记包（P1）；
- 对价测算（P0）与锁箱／交割账、对赌、MAC、交割条件（P1）；
- 交割文件包（P0）与登记、印鉴、资金流向、空档、确认、跟踪（P1）；
- 终止通知（P0）与退出评估、异议、分手费、失败索赔（P1）；
- 投后赔偿评估（P0）与索赔通知、抗辩、业绩成就、行权、随售拖售、交接计划、调价通知、提存释放、投后和解（P1）；
- 国资、上市、外资、安全审查、集中申报红旗、合并分立、挂牌、优先购买、许可、代持清理（P1）。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权（买方／卖方／目标，不得同时策略输出双方）；
2. 交易是否已定路径、已签条款清单、已签 SPA 或已交割；
3. 本次要评估、尽调、出稿、测算、交割还是发终止／索赔通知；
4. 是否出现国资进场、上市、外资、集中申报、融资、劳动安置或跨境主轴。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再出 SPA；
4. 用户确认后只启动所选入口；等价评估、尽调或测算可由用户或律师提供。

## 四、停止

立场冲突、专项主轴或一般合同审查起草时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。
