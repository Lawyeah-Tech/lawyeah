# 起草方法

本文件是可执行判断节点，不是栏目说明书。每个会改变请求范围、批次或清洁团队规则结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

本任务是买方请求和己方资料室使用规则，不是报告，也不是卖方披露控制。劳动、环境、税务专项清单只留转出口。

---

## Q# 请求矩阵

固定列：`编号｜模块｜批次｜必要性｜敏感级｜清洁团队｜特权／个人信息风险｜是否列入`。

公司、资本、重大合同、诉讼、许可、资产负担、关联为默认模块。劳动／环境／税标转出。

---

## 节点 0　分流

1. 卖方建室 → `准备卖方资料室与披露控制`。
2. 只要范围和红旗类别 → `规划法律尽调范围与红旗`。
3. 写报告 → `形成法律尽调报告`。

## 节点 1　清单

1. 与已定路径对齐：资产路径加重权属和合同转让；股权路径加重出资、机关和或有负债。
2. 不得用“请提供贵司全部文件”代替可执行请求。

## 节点 2　批次

1. 第一批：权属、负担、许可、重大诉讼、关联。
2. 第二批：一般合同、历史沿革细节。
3. 敏感定价、客户名单可后置并进清洁团队。

## 节点 3　清洁团队

1. 竞品买方：商务人员与律师／独立顾问分权。
2. 不得把清洁团队当成可以绕过反垄断信息交换限制的工具；集中申报信息交换红旗转竞争法。

## 节点 4　安全

1. 个人信息最小必要。国家秘密、国防科技不得列入请求。
2. 一般 NDA 审查搁置；交易专项保密另项。

## 节点 5　下一步

1. 卖方拒给关键文件：转红旗或报告原子，不在本任务推定清洁或推定违约。

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 买方想快点 | 可以要全部客户合同和定价且不设清洁团队 |
| 卖方还没建室 | 本任务已代替卖方披露控制 |
| 清单已发 | 尽调报告已经完成 |
| 劳动花名册含身份证 | 可以不加限制地要全量人事档案 |

---

## 条件句

if 买方与目标是竞品 → 必须设计清洁团队，否则敏感商业信息字段停止
if 请求包含国家秘密或过量个人信息 → 删除该项或整体停止
if 主成果是报告 → 负触发
if 主成果是卖方建室 → 负触发

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 请求必须分模块分批次，禁止一口价要全部秘密。 |
| 2 | 竞品买方默认考虑清洁团队。 |
| 3 | 劳动／环境／税专项只留接口。 |
| 4 | 不写报告，不代替卖方建室。 |

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按违法请求、竞品隔离、关键权属文件、批次排序。报告、卖方建室、保密协议审查只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。
