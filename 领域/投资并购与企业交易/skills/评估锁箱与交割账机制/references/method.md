# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变机制选择、泄漏定义或保护条款结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

机制选择是法律结构问题。数字工作表由测算原子完成。未知不写零。

---

## P# 机制矩阵

固定列：`编号｜机制｜定价时点｜买方保护｜卖方确定性｜信息依赖｜适用迹象｜判断`。

锁箱、交割账、固定价、混合分列。

---

## 节点 0　分流

1. 测算 → `测算交易对价与调整`。
2. 发出调价通知 → `准备价格调整通知`。

## 节点 1　比较

1. 锁箱适合报表可信、锁箱日至交割短。
2. 交割账适合营运资金波动大。依据不足则并列。

## 节点 2　泄漏

1. 必须穷尽已知类别并留兜底待谈。

## 节点 3　交割账

1. 会计政策锁定、争议解决、时限。

## 节点 4　与 earnout

1. 或有对价是另一机制，不得与锁箱混称。

## 节点 5　安全

1. 已知抽逃不得用锁箱“视为已定价”掩盖。

---

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 选了锁箱 | 价格已经确定且无争议 |
| 本任务比较表 | 测算已经完成 |
| 没有泄漏定义 | 锁箱可以闭合 |
| 交割账 | 必须按买方单方数字 |

---

## 条件句

if 主成果是数字表 → 负触发
if 已知抽逃还要锁死价格 → 整体停止或否决级红旗
if 泄漏未定义 → 锁箱不得标已闭合
if 会计政策冲突 → 交割账字段停止或部分形成

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 不代替数字测算。 |
| 2 | 泄漏定义是锁箱前提。 |
| 3 | 不输出唯一更优机制。 |
| 4 | 抽逃不得掩盖。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按抽逃、泄漏定义、会计口径排序。测算、调价通知、审计只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。

本成果不是测算表。
