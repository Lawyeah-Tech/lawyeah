# 谈判投后和解方案

## 任务目标

在明确、无利益冲突的单方立场下，形成“投后和解谈判方案”：底线、弃权、执行力提示

`depends-on` 为空。接受用户、律师、财务顾问或其他来源的等价事实、估值、清单和文本。本任务不把未核验规则写成已闭合结论。

## 工作边界

正触发：赔偿或对赌仍可谈。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 已谈拢和解协议正文；
- 一般合同和解而无交易投后背景；
- 同时为双方出方案；
- 把谈判纪要写成已和解并已履行；

本任务已谈拢协议正文另项；一般合同和解转争议领域，不给成交率或胜诉率。

## 建立谈判坐标

确认：使用者与授权；单方立场；争议请求；已有通知；可分配资源；授权底线；法域；当前磋商、文本、审批或交割状态；关键材料及缺失。

同时掌握买卖双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`S#` 陈述；`D#` 通知／评估；`C#` 赔偿或对赌；`L#` 已核验规则；`I#` 判断；`Q#` 方案；`V#` 版本

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 使用 Lawyeah MCP

宿主可调用时：`search_practiced` 补和解失败模式；法规核验弃权、公司补偿和执行力；不虚构审批系统、案号或登记回执。

工具不可用时继续按争点出受限方案，协议正文不写终稿；依赖未核验规则的法律结论、期限或机关路径字段停止。

## 五个判断节点

执行顺序和停止条件以 [谈判方法](references/method.md) 为准。这里只列入口，不代替节点。

### 节点 1　分流

已谈拢正文另项。一般和解转争议。强制单方。

### 节点 2　底线

金额区间接口、非金钱（治理、竞业宽限）。未知不写零。

### 节点 3　弃权

必须特定。不得概括放弃未知欺诈或监管责任。

### 节点 4　执行力

公司付款的资本维持、分期、担保接口。转金融只留接口。

### 节点 5　下一步

谈拢后的协议正文标明另项或审查起草搁置边界：交易和解协议可在本领域继续，但本任务不写终稿。

## 停止与安全

- `整体停止`：双方策略；用和解掩盖犯罪或抽逃；概括放弃法定不可弃权事项。
- `字段停止`：公司付款能力、弃权效力未核验。
- `目标停止`：主目标变为已谈拢正文或普通诉讼和解。

## 交付

严格按 [输出合同](references/output-contract.md) 十节交付。正触发状态只用 `已形成、部分形成并明确受限字段、因停止条件未形成`。边界见 [路由](references/routing.md)。
