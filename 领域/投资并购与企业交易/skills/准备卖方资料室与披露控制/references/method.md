# 起草方法

本文件是可执行判断节点，不是栏目说明书。每个会改变资料室结构、权限或保留项结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

卖方披露控制的目标是可追踪、可撤回、可与日后披露函对照，不是把资料室变成“已经全部披露”。隐匿重大不利事实整体停止。

---

## Q# 披露控制矩阵

固定列：`编号｜文件夹｜权限｜脱敏｜保留｜多买方隔离｜与 R&W 对照｜状态`。

开放、受限、清洁团队、不开放分列。不开放必须写入保留清单。

---

## 节点 0　分流

1. 买方 RFI → `准备尽调资料清单与资料室规则`。
2. 披露函 → `准备披露函与披露附件` 或评估原子。
3. 报告 → 买方报告原子。

## 节点 1　结构

1. 与常见尽调模块对齐，便于日后对照。
2. 版本管理：替换文件必须留旧版或变更日志。

## 节点 2　权限

1. 财务、法务、商务分权。
2. 多买方互不可见。竞品不得进未脱敏客户定价区。

## 节点 3　保留与脱敏

1. 保留项列理由：特权、个人信息、进行中谈判、国家安全。
2. 无正当理由的保留标买方红旗风险，不得建议“先不放等签了再说”来掩盖否决级事实。

## 节点 4　与披露函

1. 资料室索引日后可能被主张构成披露。本任务只提示接口，不判断排除效力。

## 节点 5　安全

1. 禁止隐匿。禁止开放国家秘密。禁止把员工身份证无必要投放。

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 文件丢进资料室 | 对应 R&W 已被排除 |
| 有重大诉讼先不放 | 合法的披露控制 |
| 买方规则 | 本任务主成果 |
| 披露函终稿 | 本任务已完成 |

---

## 条件句

if 存在否决级事实且用户要求不放也不登记保留 → 整体停止
if 多买方且未隔离 → 权限方案字段停止或部分形成
if 主成果是披露函 → 负触发
if 未签保密要开放敏感区 → 开放闸不打开

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 保留项必须登记，禁止静默隐匿。 |
| 2 | 资料室投放不等于披露函排除，除非约定如此。 |
| 3 | 多买方和竞品必须隔离。 |
| 4 | 不写披露函，不写买方报告。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按隐匿风险、保密闸、隔离、与披露函对照排序。披露函、买方请求、报告只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。

开放状态保持待开放，直到保密和权限闭合。
