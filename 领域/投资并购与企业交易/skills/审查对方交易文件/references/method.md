# 审查方法

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得只改错别字交差。不得把批注写成对方已接受。失效合同法不得写入 `L#`。

---

## 节点 0　分流

if 无对方文本 → 负触发。  
if 一般买卖合同 → 审查起草搁置。  
if 用户要本任务直接输出一份己方全新 SPA 并丢开对方稿 → 转起草原子。

---

## 节点 1　版本和立场

1. 固定审查方是买方还是卖方。同一赔偿条款在两边的“可接受”阈值不同。
2. 锁定文本哈希或版本号、日期、对照的 TS 和尽调截止日。多份红线并列，不擅自合并。
3. 先标缺失附件：披露函、资产清单、人员清单缺失时，相关 R&W 判断为 `依据不足`。

---

## 节点 2　经济和控制权

逐项对照：
- 对价是否被调整公式、汇率、税务承担掏空；
- 锁箱泄漏定义是否过窄或过宽；
- 或有对价是否由目标公司承担并可能无效／不可履行；
- 交割后是否实际取得名册、印鉴、银行和董事会席位，或只取得登记承诺。

if 文本把名册变更或印鉴交接写成“尽力”且无违约后果 → 至少 `K#` 高级，不得写成可接受。

---

## 节点 3　条件和退出

1. 先决条件是否均由己方单边满足，对方无义务配合。
2. MAC 例外是否把行业普遍变化、疫情、监管全部挖空。
3. 终止权是否仅对方享有；长停权是否无长期。
4. 分手费／定金是否可能构成预约责任或违约金调整问题，金额未核验不写成必得或必给。

条件未满足即自动交割的条款：判断为高风险，建议改为书面确认或交割备忘。

---

## 节点 4　R&W 与赔偿

买方审卖方稿：
- 知识限定扩到“尽合理调查后所知”被改成“实际知悉的自然人点名”且名单过窄 → 高级；
- 披露“所有资料室文件视为已披露”而无索引 → 高级；
- 赔偿上限过低且排除核心权属 → 退出候选。

卖方审买方稿：
- 赔偿无上限、无篮子、生存期过长 → 高级；
- 买方可因轻微违约拒收全部股权 → 高级。

禁止用“市场惯例”代替回链。

---

## 节点 5　合法性与动作

检查：对外转让程序是否按第 84 条和章程；是否要求伪造放弃声明；是否规避国资进场；是否把集中申报写成“双方视为已完成”。违法或规避条款：不提供改写以完成规避，整体停止或删除该条建议。

每条问题只给一个主建议：接受、改写（写改法要点）、退出。不把审查包当作已签署修订。
