# 评估投后赔偿与或有对价请求

## 任务目标

在明确、无利益冲突的单方立场下，形成“投后请求评估矩阵”：请求类型、披露排除、篮子／上限／生存期、对赌互斥、证据缺口和下一步。

`depends-on` 为空。本任务不发出索赔通知，不写诉状，不给胜诉率。

## 工作边界

正触发：交割后出现违反陈述保证、价格调整、或有对价或提存释放争议，单方需要判断能否主张。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 只要发送版索赔或行权通知；
- 尚未交割，只要结构评估或 SPA；
- 已脱离交易完成目标的普通合同诉讼文书（合同争议领域）；
- 只要精算终稿且定性已闭合。

## 建立评估坐标

确认：使用者与授权；单方立场；SPA／SHA／对赌文本；交割日；披露函；已知损失；法域。

同时掌握双方秘密或潜在冲突时，先停止策略输出。

## 来源和判断状态

编号：`S#` 陈述；`D#` 交割后材料；`C#` 赔偿或对赌条款；`L#` 已核验规则；`I#` 判断；`G#` 缺口；`Q#` 请求；`V#` 评估版本。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验赔偿、违约金调整、公司回购与资本维持。工具不可用时继续条款对照，效力与期限字段停止。

## 五个判断节点

执行顺序和停止条件以 [评估方法](references/method.md) 为准。

### 1. 分流和文本版本

交割前争议回结构或审查原子。普通诉讼转合同争议。

### 2. 请求分账

赔偿、价格调整、对赌、提存释放分列，不得合成“投后权益”。

### 3. 排除、期限和限额

披露排除、知识、篮子、上限、生存期。日期冲突建并行情景。

### 4. 对赌与资本维持

义务主体是股东还是目标公司。不得写成当然有效或当然无效。

### 5. 证据和下一步

通知时限红旗。发函、测算、诉讼只转介。

## 停止与安全

- `整体停止`：立场冲突；伪造损失或隐匿披露。
- `字段停止`：生存期、效力未核验。
- `目标停止`：主目标变为发通知或起诉。
