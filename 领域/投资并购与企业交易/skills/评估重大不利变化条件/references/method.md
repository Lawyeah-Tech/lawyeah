# 评估方法

本文件是可执行判断节点，不是栏目说明书。每个会改变MAC 是否支持不交割结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

MAC 成立门槛通常很高。不得把一般业绩波动写成已支持。不发终止通知。不用失效合同法。

---

## Q# MAC 矩阵

固定列：`编号｜事实｜是否落范围｜是否落例外｜量化／持续｜已知或已披露｜判断｜最强反方`。

多项事实分别判断，不得合成“形势不好”。

---

## 节点 0　分流

1. 发通知 → 终止通知原子，须本任务或等价材料支持。
2. 全部 CP → `评估交割条件是否满足`。

## 节点 1　文本

1. 定义、例外、量化标准、谁判断。沉默不编造市场惯例。

## 节点 2　例外

1. 行业整体、宏观、战争、疫情、法律变化常见例外必须逐项套。

## 节点 3　已知

1. 签署时已知或已披露的，通常难再主张，除非条款保留。

## 节点 4　情势变更

1. 无法定 MAC 而想走情势变更：另标接口，不得混成约定 MAC 已成立。

## 节点 5　安全

1. 禁止捏造。

---

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 业绩下滑 | MAC 已成立 |
| 想不买了 | 可以发终止通知 |
| 宏观不好 | 一定构成 MAC |
| 本任务评估 | 交易已经终止 |

---

## 条件句

if 无条款也无具体事实 → 依据不足
if 捏造事实 → 整体停止
if 主成果是发通知 → 负触发，除非仅要评估
if 例外明显命中 → 判断现有依据不支持

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 不发终止通知。 |
| 2 | 例外命中则难以支持。 |
| 3 | 已知或已披露通常削弱主张。 |
| 4 | 不把宏观叙事当成 MAC。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按捏造、例外、量化、与终止通知分工排序。终止通知、交割条件总表只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。

本成果不是终止通知。
