# 起草方法

本文件是可执行判断节点，不是栏目说明书。每个会改变提存结构、释放条件或争议扣留结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

提存／留扣是执行工具。银行存管法律关系转金融。本任务不写必得释放或必得扣留结论。

---

## Q# 释放矩阵

固定列：`编号｜机制｜金额机制｜托管人｜释放触发｜争议扣留｜费用｜状态`。

提存、留扣、抵扣分列，互斥或组合必须可见。

---

## 节点 0　分流

1. 存管银行合同、保证金监管 → 金融。
2. 赔偿范围篮子上限 → 赔偿原子。
3. 释放争议评估 → `评估提存或留扣释放`。

## 节点 1　选择

1. 卖方信用差倾向提存；金额小可用留扣。依据不足则并列。

## 节点 2　释放

1. 不得写“到期一律释放而不管已通知索赔”，除非用户明确且揭示买方风险。

## 节点 3　指令

1. 单方指令释放必须严格限制。

## 节点 4　金融边界

1. 账户开立、反洗钱、托管牌照成主轴 → 转金融。

## 节点 5　安全

1. 禁止与交易无关的资金停留设计。

---

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 有提存条款 | 索赔一定能拿到钱 |
| 银行托管合同 | 本任务主成果 |
| 到期 | 必须释放 |
| 赔偿矩阵未做 | 本任务可代替赔偿设计 |

---

## 条件句

if 金融存管是主成果 → 负触发
if 资金用途脱离交易 → 整体停止
if 赔偿范围完全未定 → 只出结构，金额字段停止
if 评估能否释放是主成果 → 转评估原子

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 银行存管主轴转金融。 |
| 2 | 到期不自动消灭已通知索赔，除非约定并揭示风险。 |
| 3 | 不保证索赔成功。 |
| 4 | 不代替赔偿矩阵。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按洗钱风险、金融主轴、释放与索赔冲突排序。金融、赔偿矩阵、释放评估只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。
