# 起草方法

本文件是可执行判断节点，不是栏目说明书。每个会改变请求项目、通知正文或到达设计结论的节点，必须回链来源编号、规则核验状态、最强反方和停止条件。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出成交率、胜诉率、必然过会、必然交割或唯一必得金额。未知金额不写零。`search_law` 返回已失效《合同法》、2018 年公司法文本或已失效《企业国有产权转让管理暂行办法》时记为噪声，不得写入 `L#`。MCP 效力字段与有权机关公布的施行日冲突时，以施行日为准并记录冲突；无法独立核验施行日则该规则字段停止。

交割失败索赔通知服务交易失败后的返还或违约主张，不是投后 R&W 通知，也不是起诉状。

---

## Q# 请求项目表

固定列：`编号｜类型｜依据｜事实｜金额状态｜互斥｜是否写入通知`。

返还、分手费、损失、费用分列。金额无精算则标待核。

---

## 节点 0　闸

1. 责任基础未评估 → 先走退出或分手费原子。
2. 投后 R&W → 投后通知原子。

## 节点 1　项目

1. 互斥项不得同时写成均已确定应付。

## 节点 2　正文

1. 待发送。禁止倒签。

## 节点 3　到达

1. 渠道、副本、公证接口。

## 节点 4　精算

1. 只留附件接口。

## 节点 5　安全

1. 禁止虚构损失。

---

## 分账禁令

| 已能支持的事实 | 不得写成 |
| --- | --- |
| 通知稿 | 金额已经确定必得 |
| 还没评估责任 | 可以出发送终稿 |
| 起诉状 | 本任务主成果 |
| 投后赔偿 | 本任务主成果 |

---

## 条件句

if 责任基础未闭合 → 不得出终稿
if 虚构损失 → 整体停止
if 主成果是起诉 → 负触发
if 投后 R&W → 负触发

---

## 核验规则

| 序号 | 可执行规则 |
| --- | --- |
| 1 | 评估未闭合不得出终稿。 |
| 2 | 不代替精算或起诉。 |
| 3 | 未知金额不写零。 |
| 4 | 不倒签。 |

---

## 证据、反方和下一步

证据矩阵列待证事实、支持与不利、控制方、合法取得、缺口和最晚时点。不能因相对方未提供材料而推定清洁、已放弃、已批准或已到达。

下一步按发送闸、虚构损失、与投后通知分工排序。精算、起诉、投后通知只写转介。禁止指导抢章、伪造放弃优先购买、阴阳价格、倒签或绕过冻结质押与法定进场。

状态保持待发送。
---

## 补充条件句与停止

if 终止权或责任基础未经评估且材料不能等价支持 → 不得出发送前终稿。  
if 主成果是投后陈述保证赔偿通知 → 负触发。  
if 主成果是起诉状或精算报告 → 负触发或不实施。  
if 金额无依据 → 项目表标待核，不写零，不写必得。  
禁止倒签通知日。发送不等于法院已支持。
