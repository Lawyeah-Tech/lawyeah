# 准备股权或股东变更登记

## 任务目标

在明确、无利益冲突的单方立场下，形成“股权或股东变更登记材料包”：名册请求、登记材料待核、三十日提示

`depends-on` 为空。接受用户、律师、财务顾问或其他来源的等价事实、估值、清单和文本。本任务不把未核验规则写成已闭合结论。

## 工作边界

正触发：交割后需股东名册和登记机关变更材料。

负触发并输出 `触发判定：负触发，未启动本任务`：

- C 端小微变更填空；
- 把当地书式写成已核验全国统一；
- 代提交登记；
- 日常无交易的名称地址变更；

本任务C 端小微变更只分流；当地书式一律待核，不给成交率或胜诉率。

## 建立出稿坐标

确认：使用者与授权；单方立场；交割是否已发生或同日；名册现状；登记机关；增资或老股；法域；当前磋商、文本、审批或交割状态；关键材料及缺失。

同时掌握买卖双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`S#` 陈述；`D#` SPA／名册；`C#` 章程；`L#` 已核验规则；`I#` 判断；`Q#` 文件；`V#` 版本

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验名册记载、变更登记期间和对抗；当地书式待核；不虚构审批系统、案号或登记回执。

工具不可用时继续出名册请求和文件清单，书式字段停止；依赖未核验规则的法律结论、期限或机关路径字段停止。

## 五个判断节点

执行顺序和停止条件以 [起草方法](references/method.md) 为准。这里只列入口，不代替节点。

### 节点 1　分流

C 端小微只分流。日常企业信息变更转公司治理。增资登记交叉可并入增资包原子。

### 节点 2　名册

受让人自记载于名册时起可向公司主张股东权利。公司拒绝则提示可依法起诉，不写诉状。

### 节点 3　登记材料

当地书式待核。不代提交。未经变更登记不得对抗善意相对人。

### 节点 4　三十日提示

变更事项发生之日起依法申请变更登记的期间提示，起算待核。

### 节点 5　状态

待提交。登记完成≠权属无争议。

## 停止与安全

- `整体停止`：立场冲突；伪造名册或倒签记载日。
- `字段停止`：当地书式、期间起算未核验。
- `目标停止`：主目标变为 C 端小微包或代提交。
