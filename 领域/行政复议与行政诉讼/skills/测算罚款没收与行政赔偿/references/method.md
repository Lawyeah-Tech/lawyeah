# 测算方法

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出机关必处或法院必赔的唯一总额。未知不写零。

## 节点 0　分流

税务税额核定、滞纳金按税收征管法的实体计算转税务。征收土地或房屋补偿标准实体转房地产或 C 端征地材料整理。刑事赔偿转刑事。本任务可保留一般处罚罚款和行政赔偿项目接口。

## 节点 1　事件与分项

为同一执法事件分配 `EVT#`。分项：

- 罚款（法定下限、上限、裁量基准、已告知数、已决定数）；
- 没收违法所得、没收非法财物（价值来源必须可回链）；
- 加处罚款或滞纳金（起算、上限，运行时核验）；
- 已缴纳或已执行金额；
- 行政赔偿：人身自由、医疗费、误工、财产直接损失、返还。

已缴金额与拟处金额不得轧差后只报一个数。没收与罚款是否并用必须标互斥或并用依据。

## 节点 2　处罚幅度接口

1. 没有公布的处罚依据，不得把“行业惯例”写成幅度。
2. 裁量基准只是参考，不是必处。
3. 过罚相当、首违不罚、从轻减轻、减轻到幅度以下，分别建接口行，不自动扣减。
4. 决定书数字不是测算终点；仍列法定幅度和争议点。

## 节点 3　行政赔偿

1. 违法确认状态单独一行。未确认违法时赔偿只作为情景，不写成已成立。
2. 人身自由赔偿金按国家上年度职工日平均工资等现行标准，运行时核验年度。未核验则该行 `无法估计`。
3. 财产损失原则上直接损失。可得利益标待核，不得默认计入。
4. 一并请求与单独提起只标路径接口，不写起诉状。

## 节点 4　加处罚款与执行

加处罚款是否以罚款数额为上限等规则必须运行时核验。核验失败则该行停止。不把申请复议写成已停止加处。

## 节点 5　汇总

三列汇总：已核实、情景、无法估计。禁止相加输出唯一必处或必赔总额。用户要“给一个数好谈判”时，给区间和假设，不给伪精确单点。
