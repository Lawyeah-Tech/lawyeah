# 送达方法

判断只用三态。微信已读不等于送达。不写唯一截止日。不编造未收到。

## 节点 0　分流

| 信号 | 处理 |
| --- | --- |
| 送达事实无争议，只要期间计算 | 负触发，转 `assess-time-limits` |
| 只要异议书终稿 | 目标停止，转 `object-to-service-or-announcement` |
| 刑事诉讼文书送达 | 转刑事 |
| 税务文书送达实体规则主导 | 转税务；一般处罚文书送达可留本任务 |

---

## 节点 1　固定对象

1. 文书名称、文号、作出日、送达回证或邮单号码、公告文号。
2. 受送达人身份与签收人身份。他人代收须有授权或同住成年家属等法定情形，未证明则代收效力待核。
3. 地址来源：文书载明、登记住所、许可申请地址、当事人书面确认、执法中口头提供。口头提供须有笔录，否则待核。
4. 当事人主张“从没收到”但材料显示签收：把冲突写入最强反方，不得按主张改写成未送达。

---

## 节点 2　方式合法性

运行时核验处罚法、强制法、复议法、行政诉讼法及司法解释中的送达规则。

| 方式 | 若 | 则 |
| --- | --- | --- |
| 直接送达 | 本人或符合条件的代收人签收 | 到达日为签收日 |
| 留置 | 拒绝签收且有见证人或影像等法定条件 | 条件缺一项则效力待核 |
| 邮寄 | 有妥投或拒收退回记录 | 拒收是否视为送达必须核验后写 |
| 电子 | 受送达人同意或法律另有规定，且到达指定系统 | 仅有已读或表情回复不构成同意 |
| 公告 | 下落不明或其他方式无法送达，并依法公告 | 未穷尽其他方式不得写成合法公告 |

公告期间和起算必须核验。未核验则公告到达日字段停止。

---

## 节点 3　到达证据

1. 支持到达：签收、留置记录、邮单、系统回执、公告载体原件或公证。
2. 削弱到达：地址错误、受送达人当时不在境内且已告知、公告前未尝试直接或邮寄、电子渠道非当事人确认。
3. 不得因当事人后来实际知悉就倒签为合法送达；实际知悉只影响知悉日情景，与送达是否合法分列。
4. 同一文书多种方式冲突：并列，不自动取最早一天。

---

## 节点 4　期限是否起算

| 若 | 则 |
| --- | --- |
| 送达现有依据支持 | 对应期间行可进入 `assess-time-limits` 接口，本任务只给起算日情景 |
| 送达现有依据不支持 | 期限未起算情景；仍列出实际知悉的备选行 |
| 依据不足 | 期限字段停止 |
| 用户要唯一截止日 | 拒绝 |

复议申请期、起诉期、陈述期、听证申请期分列，本任务不混算。

---

## 节点 5　安全

禁止指导伪造未收到的陈述。禁止指导隐匿已签收回证。用户坚持编造未收到：整体停止。需要对外异议时只给最小交接。

## 交付前自检（评估行政文书送达）

完成本任务前逐项打勾。任一未闭合则对应字段停止，不假装已形成结论。

1. 单方立场和授权已固定，利益冲突已排除。
2. 文书名称、文号、作出日与送达日已分列；口头转述和已读未写成已送达。
3. 本技能独立成果（送达方式、到达证据、公告条件、起算情景）已按输出合同各节落盘，未改写成相邻原子终稿。
4. 排除项已检查：微信已读不等于送达；不写唯一截止日。
5. 税务主轴已转税务；劳动仲裁未写成行政诉讼；刑事措施已转刑事。
6. 法律结论与期限仅在规则核验后落判断；未核验则字段停止。
7. 未知金额未写零。未输出胜诉率或必然受理、必然撤销。
8. 禁止动作已明示。未指导伪造、隐匿、威胁或违法取证。
