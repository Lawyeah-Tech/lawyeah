# 原子 Skill 选择方法

## 一、先识别成果

先问这一次要拿到什么可独立验收的成果，而不是按处罚、许可、强制或法条名称匹配：

- 行政行为争议总图；
- 复议或诉讼路径判断；
- 原告资格与被告；
- 受案与复议范围、期限、管辖、送达；
- 处罚、许可、强制、不作为、公开、征收程序、行政协议、附带审查；
- 陈述申辩、听证申请或听证材料、调查应对；
- 复议申请、复议答复、复议听证、履行复议决定；
- 金钱测算、赔偿路径、义务机关申请、单独赔偿诉讼；
- 证据案卷、阅卷、保全、质证、调取、举证期限、公证；
- 协调方案、调解范围、协议文本、执行力补强；
- 请求类型、一审起诉、附带民事、庭审、上诉、追加被告、撤回风险；
- 一审应诉、第三人、二审应对、管辖异议、送达异议；
- 停止执行、保全、应对保全；
- 生效裁判执行、执行应对、非诉执行申请或异议、执行和解；
- 税务、竞争环境、劳动工伤社保专项转出。

劳动仲裁不是行政诉讼。纳税争议实体整案转税务。未安装的再审、检察监督、执行异议之诉、行刑衔接、群体性策略和行政公益诉讼输出 `unavailable`。

## 二、再确认上下文

只确认会改变入口的最小信息：

1. 单方立场与授权（相对人、机关或第三人）；
2. 行政争议是否已经形成；
3. 是否已有告知书、决定书、复议决定或起诉状；
4. 本次要分析、交陈述、申请复议、测算、建卷、谈判还是程序文书；
5. 是否属于刑事强制措施、税务实体、竞争或环境专项实体、劳动工伤社保实体。

## 三、处理混合请求

1. 列出每项可独立验收的成果及对应入口；
2. 只问：`这次要先取得哪一项成果？`；
3. 回答前不指定主要 Skill，不暗示必须先评估再交陈述或复议；
4. 用户确认后只启动所选入口；等价评估、测算或证据可由用户或律师提供。

## 四、停止

立场冲突、专项主轴或未成争只要许可代办时，说明边界并转出，不代做。信息不足时每轮只追问一个最能改变入口的问题。
