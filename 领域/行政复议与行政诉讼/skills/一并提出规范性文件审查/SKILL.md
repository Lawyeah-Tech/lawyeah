# 一并提出规范性文件审查

## 任务目标

在明确、无利益冲突的申请人或原告立场下，形成审查请求、文件层级核验和提出时点。

`depends-on` 为空。接受用户、律师、机关或其他来源的等价事实、测算和证据清单。

## 工作边界

正触发：复议或诉讼中要对所依据的规定提出附带审查。

负触发并输出 `触发判定：负触发，未启动本任务`：

- 单独起诉抽象文件；
- 只要评估能否审查（转评估原子）；
- 审查规章以上立法；

不单独起诉抽象文件。

## 建立审查请求坐标

确认：使用者与授权；具体行政行为；文件名称文号；复议或诉讼阶段；法庭调查是否结束。

同时掌握双方秘密或潜在冲突时，先停止策略输出，澄清代表哪一方。

## 来源和判断状态

编号：`S#` 单方陈述；`D#` 材料表面；`A#` 当前一致／承认；`R#` 决定与文件；`C#` 文件定位；`L#` 运行时已核验规则；`I#` 判断；`G#` 缺口；`Q#` 审查请求；`V#` 稿件版本。

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。

## 律页能力增强

本技能属于律页法律技能家族，并支持 Lawyeah MCP 按需增强。

- 运行环境提供 Lawyeah MCP 时，执行 Agent 根据当前任务按需使用法律法规、法律实务、裁判案例或文书范本检索。
- 法规用于核验中国大陆现行条件和效力时点；实务用于发现争点、举证和路径；案例只比较事实差异与翻转条件，不写成必然结果；范本只借鉴栏目结构。
- 任何结果都要复核法域、效力、时点、地区和与当前事实的差异。不得把已失效《合同法》及其解释当作现行规则。不得把 1989 年行政诉讼法、1996 年行政处罚法或 1999／2017 年行政复议法当作现行文本。
- MCP 未安装、未启用、未暴露、无结果、结果冲突或暂时不可用时，不拒绝执行、不中断主流程。继续使用本技能内置方法和用户材料完成可处理部分；依赖未核验规则的法律结论、期限或机关路径保持停止或待核。
- 不向用户索取密钥、令牌或完整凭证。MCP 是可选增强，不是用户运行技能的强制依赖。

## 使用 Lawyeah MCP

宿主可调用时：`search_law` 核验复议法和行政诉讼法一并提出审查的时点和表述。

工具不可用时继续文件文本、层级和案件阶段登记；依赖未核验规则的法律结论、期限或机关路径字段停止。

## 五个判断节点

执行顺序和停止条件以 [附带审查请求方法](references/method.md) 为准。这里只列入口，不代替节点。

### 节点 1 对象适格

规章以下规定。层级不明则请求稿可写但封面标待核。
### 节点 2 时点

申请复议或起诉时一并提出。补充提出规则核验。
### 节点 3 请求表述

请求对规定进行审查并不作为认定依据，不请求法院废止文件。
### 节点 4 理由

与上位法冲突、增设义务、减损权利，逐条对照。
### 节点 5 禁止单独之诉

不制作以文件为被告的起诉状。

## 停止与安全

- `整体停止`：制作以抽象文件为对象的独立起诉状。
- `字段停止`：层级或提出时点未核验。
- `目标停止`：主目标已变为评估能否审查或抽象诉讼。

## 交付

严格按 [输出合同](references/output-contract.md) 10节交付。正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。边界见 [路由](references/routing.md)。
