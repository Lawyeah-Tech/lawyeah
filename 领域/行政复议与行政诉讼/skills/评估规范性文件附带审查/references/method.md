# 附带审查评估方法

判断只用三态。不审查规章以上。不单独起诉抽象文件。

## 节点 0　分流

| 信号 | 处理 |
| --- | --- |
| 对象是法律、行政法规、地方性法规、规章 | 负触发；说明本任务不审查立法 |
| 没有具体行政行为，只要“告红头文件” | 负触发 |
| 只要一并审查请求书 | 转 `apply-attached-normative-review` |
| 文件是税务规范性文件且税负实体主导 | 转税务 |

---

## 节点 1　层级识别

1. 国务院部门规章、地方政府规章：通常不可由法院作附带合法性审查对象，本任务停止对该文件的审查结论。
2. 其他规范性文件、规定：进入审查对象候选。
3. 文件名称带“办法”“通知”不等于一定是规章或一定不是规章。须核验制定程序和公布形式。无法识别则层级行停止。

---

## 节点 2　适用关系

所审查规定必须是被诉或被申请复议行为的依据。仅因文件“对我们行业不公平”但本案未适用：现有依据不支持附带审查。

---

## 节点 3　时点

复议：申请时一并提出。诉讼：起诉时一并提出；有正当理由可在法庭调查中补充，规则运行时核验。二审新提附带审查通常受限，未核验则该行停止。

---

## 节点 4　效果

法院经审查认为规定不合法的，不作为认定行为合法的依据，并在裁判理由中阐明。移送制定机关等处理权限须核验。不得写成法院将废止该文件或对全国失效。

与上位法冲突、增设义务、减损权利是审查要点，须逐条对照，不得空泛写“违法”。

---

## 节点 5　输出

对象适格、时点、权限、预期效果。不写请求书终稿。不建议单独抽象诉讼。

## 节点补强：层级、适用、时点

1. 对象是法律、法规、规章：停止对该文件的审查结论。
2. 本案未适用该文件：现有依据不支持附带审查。
3. 应在复议申请或起诉时一并提出。二审新提通常受限，未核验则该行停止。
4. 预期效果是不作为本案依据，不是法院废止文件。
5. 用户只要单独告红头文件：负触发。

## 执行闸（必须逐条走过）

判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。不得输出胜诉率。未知金额不写零。不得把 1989 年行政诉讼法、1996 年行政处罚法、1999／2017 年行政复议法或已失效《合同法》当作现行文本。

| 若 | 则 |
| --- | --- |
| 立场或授权不明，或同时掌握双方秘密 | 整体停止策略输出 |
| 税务处理、税额核定、纳税担保、缴清后复议为主轴 | 整案转税务，本任务只交分流 |
| 劳动仲裁申请或对仲裁裁决不服 | 转劳动或民事；劳动仲裁不是行政诉讼 |
| 刑事拘留、搜查、定罪 | 转刑事 |
| 动态规则未核验 | 对应法律结论或期限字段停止 |
| 用户要求伪造、隐匿、威胁或违法取证 | 整体停止 |

`depends-on` 为空。MCP 不可用时不拒跑，继续事实和清单。
