# 输出合同

按触发结果选择交付形状。验收闸未打开不得交付 `P#` 计划终稿或「必然不起诉」。禁止把计划写成已通过。禁止伪造证据或利诱评估。禁止倒签。禁止选边治愈。不执行发送。不代提交。未知不写零。不保证不起诉。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向，不填实体十节 |
| 节点 0 整案转出 | 第 1、2、10 节。不填第 5–9 节 |
| 整体停止 | 第 1、10 节。禁止验收终稿、选边。双方秘密、伪造整改证据、利诱评估人员、走过场、隐瞒未改项、倒签第一次即停，优先于负触发；无选边治愈，无「坚持」门槛 |
| 用户要保证不起诉、法定必然适用、今天必须过验收、计划写成已通过、合规即自首（不关窗） | 十节表头均出现；对应格填 `现有依据不支持` 或字段停止；闸未开则第 6 节不出 `P#` 计划终稿；不得改走负触发关窗；不得标终稿 `已形成` |
| 正触发且闸开 | 十节表头均出现；未核验格填待核；禁止为填满而写已通过、必然不起诉或自首已成立 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。闸未开不得进入验收终稿已形成。双方秘密未解不得进入「部分形成」。每个 `P#`／`Q#` 必须带来源和判断三值。`L#` 不得直接抄技能内条号。材料状态默认 `草案`。第 2 节必须记录合规文件是否核验。

分流理由只放第 1 节。

## 1. 触发、单方立场、授权、验收闸、检察阶段与企业／个人分离

企业立场。自然人辩护不在本窗。验收闸是否打开。双方秘密未解不得进入「部分形成」。不得写「澄清代表哪一方后继续」。不保证不起诉。

## 2. 来源登记与 MCP 调用表

`S/D/A/R/C/L/I/G/N/Q/V/E/P`。必须记录机制文件名称、文号、效力是否核验。口头已过、已读、快递发出只登记 `S#`／`V#`。MCP 未调用也留一行。噪声命中须登记。`E#` 只作验收证据回链。

## 3. 适用条件接口

文件未核验则整段待核，不得写依法应当适用。个人与企业责任分列。无检察程序只开转介。

## 4. 涉案原因与适用事实

业务、决策链、资金、监督失效点。本节禁止出 `P#` 可外传计划正文。禁止无针对性的通用章程。深挖单件根因转根因原子。

## 5. 验收闸与路径矩阵 `Q#`

本节禁止出 `P#` 计划终稿。文件未核验或无一可回链计划／证据则 `Q-验` 关闭，窗口不关。`Q-诉`／`Q-67` 只打红旗或不支持。

## 6. 计划 `P#` 与验收证据对照表

闸未开不得出 `P#` 计划终稿。一行一计划项，`E#` 证据可回链。无证据不得写已通过。禁止「提交本计划后必然不起诉」。状态 `草案`。

## 7. 第三方机制对接与回避

选任、回避、材料清单。未启动只写接口。不得走过场。利害关系未解则该行停止。

## 8. 不得承诺的结果清单与刑事辩护边界

必须列出：必然不起诉、撤销案件、免罚、法定应当适用、自首已成立、选定某检察院。自然人辩护转刑事。本窗不出辩护意见。

## 9. 风险与下一步

每项含可逆性。只转介：`准备合规整改方案`、`形成内部调查报告`、`跟踪整改验收与复发监测`、`准备根因分析与控制补强`、`评估调查后处置路径`、`处理利益冲突与调查回避`、`准备向监管提交材料与特权日志`。禁止发送指令、此致某检察院、已通过验收证明。不代提交。

## 10. 缺口、停止项与提示

须列对方最强解释：交了计划就是不起诉、未核验文件也应当适用、通用合规章程就够、评估可以走过场、合规材料就是自首、快递发出就是已验收、两边材料选边、今天过验收才合法、42 号令就是检察合规。

本成果不是不起诉决定、不是个人辩护、不是普通整改终稿、不是披露发送稿、不是已通过验收证明、不保证从宽。不执行发送。

## 综合提问的强制降级

用户同时问能不能保证不起诉、哪天到期、向哪个检察院交、能不能先把未改的写成已完成时，第 5–8、9 节仍只给接口和转介；伪造或利诱走整体停止，不在本任务完成不起诉预测。
