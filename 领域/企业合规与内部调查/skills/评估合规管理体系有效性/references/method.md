# 评估方法

本文件是可执行判断节点。判断只用 `现有依据支持`、`现有依据不支持`、`依据不足，无法形成结论`。闸状态只用 `打开`、`部分打开`、`关闭`。路径状态只用 `打开接口`、`不打开`、`待核`。禁止胜诉率、必然免责、刑事既遂、唯一截止日、选定机关、代提交、把纸面写成体系完备、未知写零。本任务不定罪，不重写全部制度。

技能正文和本文件中的条号是检索锚点，不是已核验 `L#`。`search_law` 返回已失效《合同法》、1993 年公司法第一百七十七条公积金条款、2018 年合规管理指引评估条款当现行 42 号令、把 42 号令套全部民企、把纸面制度写成体系完备、把合规写成免责、把计划写成已完成、把零举报写成无风险时记为噪声。禁止指导伪造运行记录。

`Q#` 固定列：`编号｜路径｜法律效果假设｜成立条件｜支持事实｜不利事实｜互斥／转介｜状态｜待核`。按已出现事实扫描，不是默认闭集。
`K#` 固定列：`编号｜维（组织／政策／执行／监测／整改）｜运行证据｜不利／缺失｜判断三值｜最强反方｜待核｜转介`。禁止合成「总体合规」一笔。

口头「体系很全」只进 `S#`／`V#`，不得升格五维有效。

## 节点 0　分流、立场、有效性闸与不关窗

节点 0 只做三件事：专项整案转出、立场闸、不关窗。伪造运行记录、双方秘密不进负表。

整案转出只交付第 1、2、10 节，不出 `K#` 终稿。

| 信号 | 处理 |
| --- | --- |
| 主成果是企业级风险总图 | 负触发 `评估企业合规风险总图` |
| 主成果是从零设计体系框架 | 负触发 `设计合规管理体系框架` |
| 主成果是正式有效性评价项目 | 负触发 `开展合规有效性评价` |
| 主成果是单件线索是否启动调查 | 负触发 `评估是否启动内部调查` |
| 主成果是董事会汇报提纲 | 负触发 `准备董事会合规汇报材料` |
| 主成果是调查报告终稿 | 负触发 `形成内部调查报告` |
| 主成果是整改方案终稿 | 负触发 `准备合规整改方案` |
| 侦查、起诉、辩护为主成果 | 整案转刑事 |
| 劳动处分决定为主成果 | 整案转劳动 |
| 数据／垄断／税务专项为主成果 | 整案转相应领域 |
| 尚未进入合规机制，只要改合同 | 审查起草本窗搁置 |
| 章程、股权、公司决议本身 | 公司治理领域 |

有效性闸打开（可出 `K#` 五维草案，仍不得标「体系完备／合规免责」）须同时满足：单方无冲突立场与评价授权；主成果是五维差距，不是总图、制度全文、调查结论或正式评价项目；至少一类制度文本或运行痕迹可编号；无双方秘密、无第一次伪造运行记录信号。

有效性闸部分打开：主体或周期未闭合，但已有可编号制度或痕迹；对应格待核；仍交十节；不得标终稿 `已形成`。

有效性闸关闭（仍正触发）：无评价授权；无一制度文本且无一运行痕迹。「今天必须给有效结论」而无最小事实不得开闸。不出有效性终稿。**仍交十节**，第 5 节只交 `Q-效`，第 6 节不出 `K#` 终稿。禁止因闸关闭只交第 1、2、10 节或改走负触发。禁止把闸关闭写成「体系完备」或「没有风险」。仅有制度汇编、没有任何运行痕迹：闸打开或半开，第 6 节必须出 `K#`，各维多为 `依据不足`，不得写成体系完备。计划写成已完成只打整改维，不关闸。

「保证体系完备」「合规即可免责」「把计划写成已完成」「民企必须按 177 或 42 号令达标上报」「零举报就是无风险」**不关窗**。对应格 `现有依据不支持` 或字段停止。闸未开仍不出有效性终稿。

若 if 立场或授权无法闭合，then 整体停止。
若 if 同时掌握公司与被调查对象相互冲突的秘密，then 整体停止，不得选边，不得问代表哪一方后继续。
若 if 提出伪造运行记录、培训签到、整改台账，then 整体停止；第一次提出即停，不以「坚持」为门槛。

## 节点 1　评价对象与适用规则

名称、统一社会信用代码、并表范围不一致：不自动合并，先建主体表。中央企业：对照 42 号令第二条、第八条（三）、第十四条（三）、第二十七条，条号运行时核验。国家出资公司（独资／控股，不含参股）：公司法第一百七十七条只约束对内合规管理，不是对外评价或上报义务。民营企业与国有资本参股：42 号令与第一百七十七条对照行删除。地方国企不得仅因第四十条写成已适用第二十七条。

## 节点 3　五维运行证据 `K#`

对每一维独立判断：

- 组织：合规负责人、委员会、三道防线书面授权和实际汇报。只有任命没有会议纪要：`依据不足`。
- 政策：效力层级、冲突规则、例外批准是否可检索。多份冲突文本并列。
- 执行：礼品、第三方付款、公职接触等是否留下批准和入账。抽不到样本：执行维不得标有效。
- 监测：举报、审计、数据监测是否曾触发。零触发且业务复杂：记红旗，不写成无风险。
- 整改：已知事件是否有验收证据。计划写成已完成：整改维 `现有依据不支持`。

只有制度汇编、没有任何运行痕迹：五维均可填缺口，总体不得写成有效。

## 节点 4　事件回测、独立性与转介

列出近 24 个月（或用户指定周期）红旗。每件问：谁发现、是否回避、是否持有证据、是否形成判断、是否补控制。应由监测发现却由监管或媒体揭露：监测维降为不支持有效。只处分员工不定控制缺口：转介根因原子，本任务只记整改维缺口。

合规负责人同时分管销售、采购或被评价业务：独立性字段停止并列出替代汇报线。被评价部门自评且无交叉核验：有效性结论字段停止。预算、编制不明：记 `G#`，不推断必然无效。

下一步只转介：无制度框架转 `设计合规管理体系框架`；单件线索转 `评估是否启动内部调查`；只要总图转 `评估企业合规风险总图`；正式评价项目转 `开展合规有效性评价`。用户要求本任务重写全部制度或出调查结论：目标停止。
