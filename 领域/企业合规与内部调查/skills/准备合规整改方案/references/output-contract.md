# 输出合同

按触发结果选择交付形状。整改闸未打开不得交付动作终稿或「已全面整改」。禁止把计划写成已完成。禁止虚假完成证明。禁止倒签验收日。禁止选边治愈。不执行发送。不代提交。未知不写零。不保证免罚。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向，不填实体十节 |
| 节点 0 整案转出 | 第 1、2、10 节。不填第 5–9 节 |
| 整体停止 | 第 1、10 节。禁止 `ACT#` 终稿、选边。双方秘密、虚假完成证明、把尚未实施写入已验证、倒签、指导删除冒充整改第一次即停，优先于负触发；无选边治愈，无「坚持」门槛 |
| 用户要保证已全面整改、今天必须交验收、整改即免罚、民企套 23 条（不关窗） | 十节表头均出现；对应格填 `现有依据不支持` 或字段停止；闸未开则第 6 节不出动作终稿；不得改走负触发关窗；不得标 `已形成` 终稿 |
| 正触发且闸开 | 十节表头均出现；未核验格填待核；禁止为填满而写已验证、已全面整改或已获从轻 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。闸未开不得进入动作终稿已形成。双方秘密未解不得进入「部分形成」。每个 `RC#`／`ACT#`／`Q#` 必须带来源和判断三值。`L#` 不得直接抄技能内条号。方案状态默认 `草案`。

分流理由只放第 1 节。

## 1. 触发、单方立场、授权、整改闸与成果状态

谁要方案。公司立场。整改闸是否打开。双方秘密未解不得进入「部分形成」。不得写「澄清代表哪一方后继续」。不保证免罚。

## 2. 来源登记与 MCP 调用表

`S/D/A/R/C/L/I/G/Q/RC/ACT/V`。口头已改完、已读、快递发出只登记 `S#`／`V#`。MCP 未调用也留一行。噪声命中须登记。

## 3. 触发事件、已认定／待核事实与外部承诺原文

事实与承诺分列。口头不得升格已认定或已验收。未知不写零。

## 4. 根因表 `RC#`

四层必须可被看见。禁止只写员工品德。入账折扣不得当贿赂根因。

## 5. 整改闸与路径矩阵 `Q#`

本节禁止出 `ACT#` 可外传动作终稿。无回链则 `Q-改` 关闭，窗口不关。`Q-检`／`Q-劳`／`Q-刑` 只打红旗。

## 6. 动作表 `ACT#`

闸未开不得出可外传动作终稿。一行一动作，完整固定列。无验收证据不得写已验证。禁止「已全面整改」。状态 `草案`。

## 7. 未闭合项与劳动／数据／竞争／刑事接口

只开接口。处分转劳动。检察第三方转验收原子。跟踪转跟踪原子。本窗不精算、不输出必得总额。

## 8. 外部承诺对照与完成状态词

承诺原文、时点类型、对应动作、现状。不得缩短事实或夸大完成。快递发出不是机关已验收。

## 9. 风险与下一步

每项含可逆性。只转介：`形成内部调查报告`、`准备根因分析与控制补强`、`准备涉案企业合规整改与验收`、`跟踪整改验收与复发监测`、`应对监管检查或突击检查`、`准备主动披露或自查报告`、`评估国企合规管理办法差距`、`评估反商业贿赂风险点`。禁止发送指令、此致某局、已全面整改证明。不代提交。

## 10. 缺口、停止项与提示

须列对方最强解释：计划就是完成、交了方案就应当从轻、民企必须按 23 条报国资委、品德根因就够、当场改正截图就是危害后果已消除、快递已发出就是已验收、两边材料选边、今天交验收才合法。

本成果不是检察验收包、不是调查报告、不是处分决定、不是披露稿、不是已全面整改证明、不保证免罚。不执行发送。

## 综合提问的强制降级

用户同时问改完没有、能不能免罚、哪天到期、向哪个局交、能不能先把未做的写成已完成时，第 5–8、9 节仍只给接口和转介；虚假完成或选边走整体停止，不在本任务完成验收或从轻。
