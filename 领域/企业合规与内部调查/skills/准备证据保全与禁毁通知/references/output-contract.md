# 输出合同

按触发结果选择交付形状。发送闸未打开不得交付待发送终稿或「已保全」。禁止口头备份即已保全。禁止已读即到达。禁止无边界一律禁毁。禁止选定唯一监管机关。禁止倒签。禁止选边治愈。不定罪。不代发送。未知不写零。

## 交付形状

| 状态 | 交付 |
| --- | --- |
| 负触发 | 一句 `触发判定：负触发，未启动本任务` + 路由去向，不填实体十节 |
| 发送闸关闭或节点 0 整案转出 | 第 1、2、10 节：关闭理由、范围待核和最小补证。可附停止的 `Ntc#`。禁止待发送终稿、已保全。持有通知可留时不得因劳动外观整案抹掉 `Ntc#` |
| 整体停止 | 第 1、10 节。禁止 `Ntc#` 策略包、选边、删除或藏匿步骤。双方秘密、指导删除、格式化、藏匿、伪造备份、倒签、打击报复、阻挠检查第一次即停，优先于负触发；无选边治愈，无「坚持」门槛 |
| 用户要先发全员再想范围、口头备份即已保全、已读即到达、无边界一律禁毁、保证已固定、选定某局（不关窗） | 十节表头可出现；对应格填 `现有依据不支持` 或字段停止；闸未开则仍只交 1、2、10；不得改走负触发关窗；不得标待发送终稿 `已形成` |
| 正触发且闸开（可部分开） | 下列十节表头均出现；未核验格待核；禁止为填满而写已保全、已读即到达或指导删除 |

正触发状态只用 `已形成`、`部分形成并明确受限字段`、`因停止条件未形成`。闸未开不得进入待发送终稿已形成。双方秘密未解不得进入「部分形成」。每个 `Ntc#` 必须带来源和三值判断。`L#` 不得直接抄技能内条号。稿件默认 `草案`。通知状态只用 `草案`、`待发送`、`发送闸关闭`、`已发送待证明到达`、`停止`。

## 1. 触发、签发主体、授权与成果状态

发送闸开、部分开或关。单方立场必须标明。双方秘密未解不得进入「部分形成」。不得写「澄清代表哪一方后继续」。不定罪。不代发送。稿件默认 `草案`。

## 2. 来源登记与 MCP 调用表

`S/D/R/C/L/I/G/Ntc/V/E`。口头已经备份、已读只登记 `S#`／`V#`。MCP 未调用也留一行。噪声命中须登记。

## 3. 接收人、系统管理员和回避

被调查人与管理员分列。唯一被调查人不得当唯一接收人。拒绝回避该行停止。

## 4. 保全范围（系统×期间×对象）

一行一类系统。无边界一律禁毁该格不支持。未知不写全公司。

## 5. 发送闸是否打开及理由

缺授权、无线索或无范围则关闭。先发全员再想范围：闸可关，窗口不关。

## 6. 发送前通知正文

持有、禁毁、报告 IT、禁止自行接触证人。不写结论，不指控犯罪，不倒签，不公布举报人。

## 7. 到达设计、回执和失败升级

渠道、回证、失败升级。已读不得填到达。不补造回证。备份任务单独待核。

## 8. 禁止动作与劳动／数据接口

不得授权违法监控。扣手机、停职转劳动。批量通讯录转数据。账户止付另窗。

## 9. 风险、不可逆提示和下一步

每项含可逆性。转介启动闸、案卷、合法收集、检查应对只点名。不写成发送指令。

## 10. 缺口、停止项与提示

须列对方最强解释：IT 口头说已经备份就算保全、微信已读就算送到、先群发全员再补范围、全部资料一律不得删除、倒签到上周、保证证据已固定、此致某局、两边材料选边写、先把电脑格式化再发通知、打折报复接收人。

本成果不是已发送通知、不是已保全、不是调查报告、不是披露稿、不是处分决定、不是发送版。不代发送。不定罪。没有送达事实不得写已保全。
