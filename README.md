# 律页法律技能

这里是律页科技整理的全领域律师专业技能仓库。这个仓库是我们面向中国大陆执业律师、律师助理公开的法律技能库。

把对应文件夹装进电脑端 Agent 后，可以按办案领域或合同类型调用。授权 [Apache License 2.0](LICENSE)。

## 我们是谁

我们做[法律AI工作台](https://www.lawyeah.cn)，把检索、对话、办案材料和团队协作放在同一条工作流里。律师的工作不该被压成一句提示词。

我们提供这些能力：

- **法律检索**：查法律法规、裁判案例、上市公告。可以用案情描述检索，也可以按条件筛选。新法会更新，效力状态能看见。
- **智能问答**：对话前先脱敏，再结合检索做分析。不确定的地方，我们不硬写成结论。
- **智能助理 / 智能分析**：按事项帮你整理事实、争点、依据和文书框架。判断仍由使用的人做。
- **法律资源**：文书范本、项目模板、案例结构化查阅。
- **团队办案**：文档、案件台账、日程和权限放在同一个空间里。

客户、案件和业务敏感信息，我们尽量不让原始内容直接进大模型。对话前脱敏是工作台的默认做法，技能库沿用同一条边界。

这个仓库是我们把办案方法抽出来、做成可安装技能包的地方。

## 为什么做这批技能

通用模型会写、会搜。真正办案时卡住的往往不是文笔，而是：这件事先走哪条路、材料缺什么、该停在哪、不该由邻近技能硬套。

青年律师常见的困难也不是「不会打开数据库」，而是还没形成稳定的任务入口。把材料丢给模型，得到的常常是一段通顺但无法核验的意见。我们把技能写成：先问清立场、阶段和要交的成果，再进入具体原子；查到的法条、案例、范本要能回到来源，而不是停在模型记忆里。

每个包都按真实任务拆。一个原子技能对应一项用户目标、一份可验收成果。入口技能只负责说明边界和分流，不代替办案。相邻领域看起来像同一件事时，我们会写清楚转出，而不是做成「全能助手」。

法域是中国大陆。技能不是法律服务，也不出庭、不出具法律意见。检索结果只供查询参考。

## 怎么安装、怎么用

从 [`领域/`](领域/) 或 [`合同/`](合同/) 取出要用的那个中文目录，整包安装。WorkBuddy 里叫套件，Codex 里叫插件，装的是同一件事。

把该目录（或打成的 zip）拖进对话框，WorkBuddy 输入「把这个技能套件整包安装到本机，不要拆成单个技能。」Codex 把「套件」换成「插件」。装完用 `/` 召唤具体技能。技能多的包，可以先开入口技能。

逐步截图、装到哪里、怎么召唤，见 [技能安装说明](docs/安装.md)。

不要拆成单个技能分发。更新时用同名目录整体替换。

更细的结构说明见 [docs/architecture/repository.md](docs/architecture/repository.md)，领域归属见 [docs/architecture/domain-boundaries.md](docs/architecture/domain-boundaries.md)。

## 律页 MCP

技能自己带方法、边界和成果形状。要核验现行法条、类案、实务或范本时，可以接我们的 [律页 MCP](https://www.lawyeah.cn)。这是可选增强，不是运行技能的前提。没接的时候，按包内方法继续做能做的部分；依赖未核验规则的结论、期限或机关路径应当停止或待核。

MCP 只读。当前公开工具：

| 你要做什么 | 用哪个工具 |
| --- | --- |
| 查法律法规、司法解释、具体法条 | `search_law` |
| 已有 `regulation_id`，要法规详情或正文 | `get_law_detail` |
| 查办案策略、举证、诉讼流程或实务 | `search_practiced` |
| 已有完整案情，找相似案例 | `search_case_by_fact` |
| 按案由、法院、地区、年份等条件筛案例 | `search_case_by_filter` |
| 已有案例 ID 或案号，要详情 | `get_case_detail` |
| 查上市公司公告 | `search_announcement` |
| 查合同、诉讼文书等范本 | `search_template` |
| 已有 `template_id`，要范本正文 | `get_template_detail` |

先选最匹配的一个工具。信息不够就补条件，不要编法规 ID、案例 ID、案号或公司名称。检索结果只供参考，不构成法律意见。

到我们官网申请授权。不要把完整 API Key 写进技能、Issue 或聊天记录。MCP 不可用或权限报错时，检查授权是否过期，或联系所在组织的管理员。
